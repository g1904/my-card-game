# 场景与节点规则

深入配套文档：`.claude/knowledge/standards/godot-scene-conventions.md`。

- **每个场景一个职责。** 一张卡牌、一个敌人、一个屏幕、一个弹窗 —— 各自是自己的场景，按需实例化。
- **可复用的东西通过 `PackedScene` 实例化。** 卡牌、敌人、奖励格和 UI 控件编写一次，在运行时实例化。通过 `[Export]` 或预加载引用 `PackedScene`，绝不在逻辑各处硬编码散落的 `res://` 字符串路径（集中管理场景路径）。
- **场景拥有自己的子节点。** 外部代码通过场景脚本的公开 API / 信号与场景对话，而非伸手进它内部的节点树。
- **稳定的引用。** 使用场景唯一名（`%Node`）、分组（`AddToGroup`/`GetTree().GetNodesInGroup`）或导出的节点引用。避免脆弱的基于索引或路径的遍历。
- **数据不放在场景里。** 视觉/结构性的组合放在 `.tscn` 里；玩法数值与定义放在通过注册表加载的数据资源（`.tres`）里（参见 `data-resource-rules.md`）。一个卡牌场景是一份卡牌资源的*视图*。
- **对竖屏友好的组合。** 用带锚点的 `Container` 节点搭建屏幕，使其在各种宽高比下重新排布（参见 `ui-input-rules.md`）。
- **命名。** 沿用同级场景中已有的命名。新节点取描述性的 PascalCase 名称。
