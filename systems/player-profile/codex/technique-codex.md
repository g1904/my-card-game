# technique-codex

> 功法图鉴 / **TechniqueCodex** —— 图鉴族（见 `_index.md`）中的功法一本：记录玩家**已习得**或**已在敌人身上遭遇过**的功法，按 `CultivationTechniqueData` 的 `Id` 索引，跨轮回持久。

## 意图
> _设计意图，从 handoffs 中提炼。保持更新。_

- **它记录的是「这门功法是什么」，路数与牌表都算。** 一门功法在玩家这一侧是构筑单元（整组入组、按层数整组替换），在敌人那一侧是套牌的来源；图鉴收的是这门功法的完整面貌。
- **敌我共用同一套功法条目，所以这本图鉴天然是双向的。** 你在敌人身上见过的那门功法，就是你有机会习得的那一门——**图鉴知识因此可验证、可迁移**。这也是它值得单独成一本、而不是塞进敌人词条里的理由：同一门功法会出现在多个敌人身上，也会出现在你自己的卡组里，它需要一个与敌人无关的落点。

### 词条构成

| 项 | 来源 |
|---|---|
| 功法名 · 描述（一句路数概括） | `CultivationTechniqueData` 的显示名 / 描述（`LocalizedText`） |
| 稀有度 | `Rarity: RarityTier` |
| 属性（灵根要求） | `RequiredAffinities: Affinity[]`；空数组渲染为「无属性要求」。`MaxCharacterAffinityCount == 1` 时另加「单灵根专属」标注 |
| 风味 / 出处传说 | `CodexFlavor: LocalizedText`，可选；`null` 即不渲染该段、不告警 |
| **逐层卡牌清单** | 该功法每一层是哪几张牌，由呈现层从功法条目的成员卡现算（见下） |

**全部来自条目自身已有的字段**（`CodexFlavor` 是族级共有的那一格），不新增结构化的多项写作规格——与能力 / 道具四本同一条深度口径，理由见 `common-properties.md`。

**属性一行是路数概括的天然一部分，且不泄露卡表**（它讲的是这门功法走哪一路，与「这一层是哪几张牌」无关）。它与「敌方专属」标注同款——**由呈现层从条目字段现场算出，不新增任何存档字段**。词条**不表达「你能不能修」**：那取决于当前角色的灵根，而图鉴是跨轮回的知识面，写进去会让同一条词条在不同轮回下读出不同结论。准入规则见 `systems/character-profile/deck/_index.md`。

### 词条列出该功法的逐层卡牌清单（承重）

**词条给出这门功法每一层是哪几张牌**，与玩家自己持有它时在构筑界面看到的是同一份内容。

- **它是「同一个敌人第二次遇到就该能打赢」的兑现路径（承重）。** 敌人词条②列出他的核心功法，玩家沿「敌人词条 → 功法图鉴 → 逐层卡表」可以把这个敌人的样本卡组反查出来——**这条通道被有意打开**。本作承诺「输了一般是牌组构建或出牌顺序的错」，而敌人行动零事前预告、图鉴战斗中不可查，这条承诺只能靠战前查阅兑现；给玩家路数概括而扣着牌表，归因精度不足以支撑它。
- **对价明写并接受：** 知道卡表的玩家能在战斗中做「他还剩哪些牌」的推算。**这是玩家用一次遭遇（往往是一次失败）换来的东西**——「首遇的信息差即首遇的风险定价」说的是首遇收费，不是一直收费。
- **它有一道天然的界：层数。** 敌人的层数不出现在任何词条里，而层数提升是整组替换（层数不同则牌不同），故反查只能停在「这门功法大致长什么样」，而非逐张精确的本场牌表。
- **两条边界不因此松动：** 图鉴**战斗中一律不可查**（`_index.md` 的族级纪律），且**词条不含动态情报**。推算「他还剩哪些牌」因此只能靠玩家的战中记忆，界面不提供查询。
- **卡表由呈现层从功法条目的成员卡现算，不新增任何存档字段。** 与「敌方专属」标注、`LocationCodex` 的三态同一先例：存档仍只记解锁状态（一列 `CodexEntry(Id)`），文案改版不触发存档迁移。
- **词条与构筑界面因此不再分工遮蔽**，只分工语境：图鉴回答「我见过什么」，构筑界面回答「我手上这门是什么」——两处给的卡表内容相同。

### 两条解锁路径

| 路径 | 触发 | 搭在哪一次已有提交上 |
|---|---|---|
| **习得** | 该功法进入角色卡组（闭关学新 / 商店购入） | 那一次 `LearnTechnique` 提交 |
| **连锁** | 遭遇了套牌含该功法的敌人 | 该战斗事件收口的那一次提交 |

- 两路都是按 `(Kind, Id)` 的幂等收录，**先后无关、重复即空操作**；同一门功法两路都触发过也只有一条条目。展开规则、组装方与零新增提交点的论证见 `common-properties.md`。
- **升阶不产生新条目。** 层数是同一门功法的纵轴，图鉴收的是功法本身——`UpgradeTechnique` 不写图鉴，词条也不表达当前层数。
- **弃置不删条目。** 图鉴只增不删：忘掉一门功法不等于没见过它。

### 敌方专用功法照常收录，标注由呈现层现算

`Pool == Enemy` 的功法玩家永远学不到（施加侧对它的 `LearnTechnique` / `UpgradeTechnique` 是硬拒绝，见 `systems/character-profile/deck/_index.md`），但**遭遇它的敌人时照常收录**，词条与其余功法同形。

- **词条上的「敌方专属」标注由呈现层从 `Pool` 字段现场算出**，与 LocationCodex 的三态由 `LocationMapData` 现算同一先例：**不新增任何存档字段**，存档 / 写入通道 / 校验 / schema 增量全为零。
- **不加这格标注也不会出错**（图鉴本就没有「习得」这种可供性），加它是为了就地答掉玩家必然会问的那一句「这门我怎么学不到」。
- **完成度分母含它**，仍取 `AllIncludingDisabled()` 的功法条目总数，**不加 `Pool` 过滤**：敌方专用功法照样能靠遭遇解锁，不存在无法达成的分母；给分母开第一个过滤例外，代价远大于收益。

### 存档面

存档形态与其余各本完全相同：`PlayerProfile.techniqueCodex` 是一列 `CodexEntry(string Id)`，`Id` = `CultivationTechniqueData.Id`；写入通道 `ProfileChangeSpec.CodexElements`，`Kind = CodexKind.Technique`。词条文案全部挂在内容条目上，**存档只记解锁状态**。字段表与枚举的权威在 `../_index.md` 与 `systems/services/profile-service.md`。

> 条目共有字段与解锁语义见 `common-properties.md`；图鉴族总览见 `_index.md`。

## 决策(-> ADR)
> _已定案的决定链接到 decisions/ADR-####。_

- **功法图鉴收录已习得或已遭遇的功法**，词条 = 功法名 / 描述 / `Rarity` / 属性 / **逐层卡牌清单** + 可选 `CodexFlavor`，不套用敌人的四项写作规格；属性一行与卡表均由呈现层从条目字段现算，不新增存档字段，且词条不表达「当前角色能否修」。
- **词条列出逐层卡牌清单** → `decisions/ADR-0095-technique-codex.md`：「敌人词条 → 功法图鉴 → 逐层卡表」的反查通道是设计目标，层数不进词条是它的天然界。
- **两条解锁路径（习得 · 连锁）皆幂等**；升阶不产生新条目，弃置不删条目。
- **`Pool == Enemy` 的功法照常收录**，「敌方专属」标注由呈现层从 `Pool` 现算，不新增存档字段；**完成度分母含它**，不加 `Pool` 过滤。
