# enemy-codex

> 敌人图鉴 / **EnemyCodex** —— 图鉴族（见 `_index.md`）中的敌人一本，类 Pokédex：记录玩家已遭遇过的敌人信息，跨轮回持久。**遭遇一次即解锁该敌人的全部词条文案。**

## 意图
> _设计意图，从 handoffs 中提炼。保持更新。_

- **敌人图鉴 = 账号级收集。** 类似 Pokédex 的收集面：**追踪玩家已遭遇过的全部敌人及其信息**。它归 **PlayerProfile**（账号级、跨轮回持久），不随轮回清理——因此它是玩家跨轮回积累的**知识资产**，而非角色的轮回内状态。
- **图鉴给「静态知识」，不给「动态情报」（分层纪律）。** 这条分层是图鉴与战斗信息体系共存的前提：

  | 通道 | 回答的问题 | 时点 | 获取途径 |
  |------|-----------|------|----------|
  | **敌人图鉴** | 这个敌人**会做哪些事**（招式池、大致强度、路数与弱点） | **事前** | 跨轮回遭遇积累 |
  | **敌人回合的逐步执行呈现** | 它**这一回合做了什么** | **事中** | 战斗内自动，无需付出 |

  **分工是「事前知识 vs 事中情报」。图鉴再全，也不会告诉玩家本回合的具体选择；逐步呈现再清楚，也只讲已经发生的事。**
  **⚠ 敌人的行动不作任何事前预告**（不设揭示档位，也没有「花代价买情报」的通道），故**本图鉴是事前知识的主通道**——它是玩家在进入战斗前唯一能积累的敌人知识。
- **遭遇即记录，不必击败。** 解锁触发是**遭遇**而非**击败**——**死亡至少换来知识**。这是「失败侧也应有产出」这一取向在图鉴上的落点：一次输掉的战斗仍然把这个敌人写进了图鉴，玩家下次面对它时更有底。
- **它是「靠试错记忆」的制度化。** 越级遭遇的信息劣势不是纯粹的惩罚：玩家每一次遭遇都在向图鉴写入知识，下一次面对同种敌人时更有底。这把原本只存在于玩家脑中的经验变成**有存档、有收集感、有账号级成长**的正经系统。**「遭遇即记」正是这条意图的直接兑现**——不记击败只记遭遇，才让失败也在积累。
- **词条内容 = 五项文案。** 一个敌人的图鉴词条记录：

  | 项 | 内容 |
  |----|------|
  | ① | **人物背景** |
  | ② | **功法简介** |
  | ③ | **运作方式** |
  | ④ | **特点与弱点** |
  | ⑤ | **`EnemyData` 中样本卡组的关键卡牌** |

  **一次遭遇，全文案解锁** —— 逐招式 / 逐项解锁**已否决**。

  > **词条②「功法简介」指向该敌人实际使用的功法条目（`CultivationTechnique`）。** 敌方样本卡组与玩家同源——由**功法 + 层数**展开而来（见 `systems/enemies/` 与 `systems/character-profile/deck/_index.md`），故词条②讲的路数就是玩家有机会习得的那一门功法的路数，**图鉴知识因此可验证、可迁移**。
  > **手写正文只写路数、不写功法名**：功法名的唯一权威是功法条目自身的 `LocalizedText`（多语言 + overlay 可热更），词条里再手抄一份，两份不一致时没有任何机械检查能发现（自然语言 + 多语言，无从定义相等判据）；名字由词条②的**引用字段在呈现层渲染**（可点入功法图鉴），与「展示文案不进图鉴条目、呈现时由 ViewModel 组装」同构。
  > 敌方构筑面另含**游离散牌**一格（不属任何功法），故「图鉴所写即玩家可习得」留有一小块例外——散牌由词条⑤的关键卡牌一并覆盖，**不为它另开词条格**。
- **五项全是描述性文本，这正是分层得以维持的原因。** 词条给的是「他走什么路数、怕什么、常用哪几张牌」，**不是**「他这回合出哪张、精确数值几何」——**因此图鉴再全也不侵蚀越级黑箱**，先前担心的「深度决定它对黑箱的侵蚀程度」这一顾虑由「只写文案、不写数值曲线」化解。
- **词条文案挂在 `EnemyData` 上，存档只记「已遭遇」。** 与「展示文案留在 `Resource` 上、存档态只带 `Id` + 可变状态」一致——**图鉴的存档负担因此接近一个 id 集合**，先前列出的「存档体积」顾虑基本消解。
- **服务归属：profile-service。** 与其余账号级字段一致——图鉴的写入（遭遇 / 击败时的解锁）经 `profile-service.ProfileManager.TryApply(spec)`，与轮回内变更落在同一事务体系内。见 `systems/services/profile-service.md`。

- **五项的写作规格。**

  | 项 | 长度 | 写作口径 | 视角 |
  |----|------|---------|------|
  | ① **人物背景** | 2–3 句 / **40–80 字** | 他是谁、从哪来、为何在此。**叙事性，可有情绪** | 第三人称 |
  | ② **功法简介** | 1 句 / **25–50 字** | **只写一句概括其路数、不写功法名**（「以快打慢，不留后手」）——名字由引用字段渲染 | 第三人称 |
  | ③ **运作方式** | 2–3 句 / **50–90 字** | **机制性但不带数字**（「前期蓄势，越到后半越难缠」） | 可用第二人称 |
  | ④ **特点与弱点** | 2 句 / **30–60 字** | **一条特点 + 一条可行动的弱点** | 提示性 |
  | ⑤ **关键卡牌** | **3 张**卡名 + 每张一句（≤ 20 字） | 见下 | — |

  - **排版：每项一段连续文本，不分行、不用项目符号**——竖屏阅读连续短段优于碎片列表（列表在窄屏产生大量换行与留白）。**总长 150–280 字，一屏读完不需滚动。**
  - **三条口径纪律（承重）：**
    1. **禁止出现任何具体数值**——伤害、道念、`ManaCost`、概率、回合数一律不写，可用定性词（「大量」「偶尔」「代价高昂」）。**「不含阿拉伯数字」是「图鉴不侵蚀越级黑箱」这句话唯一可被审阅执行的形式**，作为内容评审的硬检查项。**但它是形式检查不是语义检查**（作者仍可写「大约十二点」绕过），只是一道低成本的第一关，不替代人工评审。**检查对象只是挂在 `EnemyData` 上的手写文案**——词条②的功法引用字段、以及由它在呈现层渲染出的功法名不纳入本检查（功法名是内容命名，受功法条目自身的命名规范约束）。
    2. **禁止「本回合」类动态措辞**——图鉴给静态知识，不给动态情报。
    3. **④ 的弱点必须可行动**——玩家读完要知道**该改什么打法**（「他吃不消连续的高费单发」可行动；「他很强」不是）。否则这一项是废话，也辜负了「死亡至少换来知识」的设计意图。
  - **写作规格是可观的成本**（每个敌人 150–280 字 × 5 项结构化文案，且要过「无数字」的审阅）。**缓解：给一份模板 + 两三个范例词条放进内容制作流程**，让作者照着填——上述长度区间正是为此而设。
- **词条②挂一个「主功法」引用字段：单个功法 `Id`、必填。** 正文仍是挂在 `EnemyData` 上的**手写 `LocalizedText`**，**不**由功法条目自动生成——自动灌入的功法正文会带进阿拉伯数字，破掉「不含阿拉伯数字」这道硬检查。
  - **只带 `Id`，不带 `TechniqueTier`**：词条正文绝不写等级，而层数本身就是一个数字面。
  - 加载校验：`Id` 解析不到 → `PushError`（带模板 `Id` + 功法 `Id`）；**主功法须 ∈ 该敌人的功法列表** → 否则 `PushError`（与 `KeyCardIds` 的「须 ∈ 样本卡组」同款）。字段面见 `systems/enemies/`。
  - 被引用功法 `ContentEnabled == false` **不阻断词条渲染**——禁用是产出侧的取池过滤，不是解析失败。
  - 一个敌人通常持多门功法，词条只给主功法这一个入口；其余功法玩家仍可从功法图鉴列表里找到。这是**一屏纪律优先**下被接受的取舍（与「总长 150–280 字」「关键卡 3 张」是同一条纪律的三面）。
- **关键卡牌列 3 张，由 `EnemyData.KeyCardIds` 显式标注，不做自动挑选。** 样本卡组通常十余张，3 张 ≈ 玩家能记住的上限且足够勾勒路数（2 张不足以表达「路数」，5 张变成背卡表）。
  - **为何不自动挑选**（例如按出现次数 / 最高费用）：自动挑出的往往是**最平庸的低费填充牌**；关键卡是**叙事与教学的选择**（「这三张能让玩家理解他的路数」），属内容作者职责、不是统计问题；**词条文案挂模板且是静态的**，自动挑选会随功法条目的改版而漂移，与词条的静态性不一致；显式字段还可被 overlay 热更单独修正。
  - 加载校验：每个 id 必须存在于该模板的样本卡组（功法展开产物 ∪ 游离散牌）内 → 否则 `PushError`（带模板 `Id` + 卡牌 `Id`）；数量 > 3 或 < 2 → `PushError`；数量 = 0 但词条已启用 → `PushError`。
  - **这 3 张必在玩家实际遭遇的牌里**——层数是模板上的固定值，展开在加载期即唯一确定，物化路径不再改写卡组，故上面那条加载校验就是完整保证，没有需要在物化期再检一遍的窗口。图鉴是**唯一的事前信息来源**，对不上即失去意义。见 `systems/enemies/`。
- **慷慨度维持 3 张关键卡，不给样本卡组完整列表（承重）。** 本图鉴是事前知识的主通道，「是否该给得更多」因此是一个真实的问题；结论是**先不动机制**，三条理由：
  1. **完整卡组列表把词条从「事前知识」推向「事中情报」。** 知道全表的玩家可在战斗中做「他还剩哪些牌」的推算——那是读牌堆，属事中情报，而「事前知识 vs 事中情报」这条分层是图鉴与战斗信息体系共存的**前提**，不是可微调的旋钮。3 张只勾勒路数，不支持这种推算。
  2. **它与两条既有结论同时相抵。** 「关键卡 3 张（5 张变成背卡表）」与「总长 150–280 字、一屏读完不需滚动」是同一件事的两面；整副卡组的卡名 + 说明必然突破一屏，而卡组规模不设硬限，词条长度会随内容编排无上界地涨——进而逼出分页或分档解锁，而分档解锁本身已被否决。
  3. **慷慨度上调有一个更便宜、可回退的旋钮：**③「运作方式」与 ④「特点与弱点」的写作厚度。④ 本就被要求「必须可行动」；若实测知识不足，先把 ③④ 写厚——**纯内容侧调整、零机制成本、可逐条回退**，远早于动机制。
  - **退让阶梯（属实测调整，不是重新裁决）：** 加厚 ③④ → 把 `KeyCardIds` 的**数量上界**由 3 放宽到 5（加载校验的 `> 3 → PushError` 改为 `> 5 → PushError`，**下界 2 不动**；纯数据改动，词条仍在一屏内）→ **再之后**才考虑全表。给出这条阶梯，是为了让「慷慨度不够」将来有一条不必重开分层裁决的出路。
  - **已知代价照录：** 首次面对陌生敌人的信息劣势维持现有水平，而该水平尚未经实测检验。
- **词条正文绝不写等级（承重）。** 词条挂模板、跨轮回持久，而同一模板会以 5 个不同等级出场——把实例信息写进词条就是用一份会变的东西污染静态知识面。**本次遭遇实例的境界与层级由呈现层单独给出**，不进词条正文；落点与措辞见 `ux/screen-flow.md`。
- **战斗中不可查阅。** 与整族同一条纪律（见 `_index.md`）：本图鉴只在非战斗界面可读，**开打之后没有任何查阅入口**，立绘的点按语义因此完全归战斗自身（选目标）。
  - **它读起来的时刻是战斗前确认页**：已解锁的敌人在进场前把词条摆在玩家面前，未解锁的什么也不给。见 `ux/screen-flow.md`。
- **解锁写在该战斗事件的收口，首遇本场读不到。** 这不是让图鉴分担一份遮蔽，而是把「知识」和「用知识」在时间上分开：**第一次撞上他时你就是不知道他是谁，这份劣势即首遇的风险定价**；这一场换来的词条，在下一次进场前兑现。「一次遭遇，全文案解锁」不受影响——解锁仍是一次性的全量写入，只是落在收口那一次提交上（触发表见 `common-properties.md`）。
- **收录他，同时收录他所用的全部功法。** 敌人的构筑面就是功法引用，故词条②指向的那门功法与他套牌里的其余功法一并进入功法图鉴，玩家可从这里点进去读。展开规则见 `common-properties.md`，功法本见 `technique-codex.md`。

> 条目共有字段与解锁语义见 `common-properties.md`；图鉴族总览见 `_index.md`。

## 决策(-> ADR)
> _已定案的决定链接到 decisions/ADR-####。_

- **五项写作规格（长度 / 口径 / 不含阿拉伯数字）；关键卡牌列 3 张由 `EnemyData.KeyCardIds` 显式标注；词条正文绝不写等级，实例信息由呈现层单独给出**。
- **敌人图鉴为账号级收集，归 PlayerProfile；与敌人回合的逐步执行呈现按「事前知识 vs 事中情报」分层；它是事前知识的主通道**。
- **战斗中不可查阅**；已解锁词条的呈现时刻是**战斗前确认页**。
- **解锁触发 = 遭遇即记录（不必击败），写在该战斗事件的收口**——本场读不到，下一次进场前兑现。
- **收录一个敌人即连锁收录其套牌所含的全部功法**（→ `technique-codex.md`）。
- **词条②指向该敌人实际使用的功法条目**：挂一个单数、必填的「主功法」引用字段（只带 `Id`，悬空或不在该敌人功法列表内 → `PushError`）；**手写正文只写路数、不写功法名**，名字由引用字段在呈现层渲染。
- **慷慨度维持「关键卡 3 张、不给样本卡组完整列表」**；上调走「加厚 ③④ 写作 → `KeyCardIds` 上界 3 放宽至 5（下界 2 不动）→ 才考虑全表」这条**退让阶梯**，属实测调整，不重开「事前知识 vs 事中情报」的分层裁决。
