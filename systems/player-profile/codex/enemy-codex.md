# enemy-codex

> 敌人图鉴 / **EnemyCodex** —— 图鉴族（见 `_index.md`）中的敌人一本，类 Pokédex：记录玩家已遭遇过的敌人信息，跨轮回持久。**遭遇一次即解锁该敌人的全部词条文案。**

## 意图
> _设计意图，从 handoffs 中提炼。保持更新。_

- **敌人图鉴 = 账号级收集。** 类似 Pokédex 的收集面：**追踪玩家已遭遇过的全部敌人及其信息**。它归 **PlayerProfile**（账号级、跨轮回持久），不随轮回清理——因此它是玩家跨轮回积累的**知识资产**，而非角色的轮回内状态。
- **图鉴给「静态知识」，不给「动态情报」（分层纪律）。** 这条分层是图鉴与战斗信息体系共存的前提：

  | 通道 | 回答的问题 | 时点 | 获取途径 |
  |------|-----------|------|----------|
  | **敌人图鉴** | 这个敌人**会做哪些事**（招式与行为模式、路数与弱点） | **事前** | 跨轮回遭遇积累 |
  | **敌人回合的逐步执行呈现** | 它**这一回合做了什么** | **事中** | 战斗内自动，无需付出 |

  **分工是「事前知识 vs 事中情报」。图鉴再全，也不会告诉玩家本回合的具体选择；逐步呈现再清楚，也只讲已经发生的事。**
  **⚠ 敌人的行动不作任何事前预告**（不设揭示档位，也没有「花代价买情报」的通道），故**本图鉴是事前知识的主通道**——它是玩家在进入战斗前唯一能积累的敌人知识。
- **它是「可预测性的唯一载体」，深度因此写到招式与行为模式级（承重）。** 本作承诺「输了一般是牌组构建或出牌顺序的错，同一个敌人**第二次遇到就该能打赢**」；而敌人行动零事前预告、图鉴战斗中一律不可查，这条承诺**只能靠战前查阅 + 战中记忆兑现**，没有别的通道。故词条必须写清**他会出哪几路牌、什么节奏、何时发力**，而不是只给一段定性印象。
  - **只给定性描述被否决：** 归因精度不足以支撑「第二次就该打赢」，那条承诺会退化为一句空话。
  - **靠玩家自己记被否决：** 跨轮回的间隔太长，记忆不是可依赖的载体。
  - **它对敌人 AI 构成一条硬约束：AI 必须是可描述的固定行为模式，而非自由决策。** 现有 AI（1-ply 加权效用评分 + 确定性 argmax、全流程零随机、零记忆，见 `systems/enemies/_index.md`）满足它；此后那些性质是**本条的义务**——给 AI 掷骰或加私有记忆即推翻本条。
  - **代价明写并接受：** 敌人条目的内容量显著上升，且首遇之外的信息劣势被大幅削平。这是为「主要可归因于决策」付的对价。
- **遭遇即记录，不必击败。** 解锁触发是**遭遇**而非**击败**——**死亡至少换来知识**。这是「失败侧也应有产出」这一取向在图鉴上的落点：一次输掉的战斗仍然把这个敌人写进了图鉴，玩家下次面对它时更有底。
- **它是「靠试错记忆」的制度化。** 越级遭遇的信息劣势不是纯粹的惩罚：玩家每一次遭遇都在向图鉴写入知识，下一次面对同种敌人时更有底。这把原本只存在于玩家脑中的经验变成**有存档、有收集感、有账号级成长**的正经系统。**「遭遇即记」正是这条意图的直接兑现**——不记击败只记遭遇，才让失败也在积累。
- **词条内容 = 四项。** 一个敌人的图鉴词条记录：

  | 项 | 内容 |
  |----|------|
  | ① | **人物背景** |
  | ② | **核心功法**（引用列表 + 一段路数概括） |
  | ③ | **运作方式** |
  | ④ | **特点与弱点** |

  **一次遭遇，全文案解锁** —— 逐招式 / 逐项解锁**已否决**。

  > **词条②「核心功法」列出该敌人实际使用的核心功法条目（`CultivationTechnique`），多门、不含层数。** 敌方样本卡组与玩家同源——由**功法 + 层数**展开而来（见 `systems/enemies/` 与 `systems/character-profile/deck/_index.md`），故词条②列的就是玩家有机会习得的那几门功法，**图鉴知识因此可验证、可迁移**。玩家可**点入功法图鉴自行展开**其逐层卡表（见 `technique-codex.md`）。
  > **手写正文只写路数、不写功法名**：功法名的唯一权威是功法条目自身的 `LocalizedText`（多语言 + overlay 可热更），词条里再手抄一份，两份不一致时没有任何机械检查能发现（自然语言 + 多语言，无从定义相等判据）；名字由词条②的**引用字段在呈现层渲染**，与「展示文案不进图鉴条目、呈现时由 ViewModel 组装」同构。
  > **不含层数**：层数是实例信息也是一个数字面，词条正文与引用字段都不带它。这也给反查留了一道天然的界——见下方「反查是设计目标」。
  > 敌方构筑面另含**游离散牌**一格（不属任何功法），故「图鉴所写即玩家可习得」留有一小块例外——散牌由词条③④ 的行为模式描述覆盖，**不为它另开词条格**。
- **四项全是描述性文本（词条②的功法名由引用字段渲染）。** 词条给的是「他走什么路数、什么节奏、怕什么」，**不是**「他这回合出哪张」——**「事前知识 vs 事中情报」这条分层一字不动**，深度加大改变的是事前那一侧有多厚，不是分层本身。
- **词条文案挂在 `EnemyData` 上，存档只记「已遭遇」。** 与「展示文案留在 `Resource` 上、存档态只带 `Id` + 可变状态」一致——**图鉴的存档负担因此接近一个 id 集合**，先前列出的「存档体积」顾虑基本消解。
- **服务归属：profile-service。** 与其余账号级字段一致——图鉴的写入（遭遇 / 击败时的解锁）经 `profile-service.ProfileManager.TryApply(spec)`，与轮回内变更落在同一事务体系内。见 `systems/services/profile-service.md`。

- **四项的写作规格。**

  | 项 | 长度 | 写作口径 | 视角 |
  |----|------|---------|------|
  | ① **人物背景** | 2–3 句 / **40–80 字** | 他是谁、从哪来、为何在此。**叙事性，可有情绪** | 第三人称 |
  | ② **核心功法** | 引用列表 + 1–2 句 / **25–60 字** | **只概括其路数、不写功法名**（「以快打慢，不留后手」）——名字由引用字段渲染；多门时概括它们**合起来**的路数 | 第三人称 |
  | ③ **运作方式** | **写到行为模式级**，**不设字数上限** | **会出哪几路牌、什么节奏、何时发力、优先打什么**（「开局连铺两三张低费阵法，中段起把攒下的势一次砸出来；你的场面一旦厚起来他会转去拆」）。**机制性但不带数字** | 可用第二人称 |
  | ④ **特点与弱点** | **≥ 2 句**，**不设字数上限** | **一条特点 + 一条以上可行动的弱点**；弱点要具体到「该改什么打法」 | 提示性 |

  - **排版：每项一段连续文本，不分行、不用项目符号**——竖屏阅读连续短段优于碎片列表（列表在窄屏产生大量换行与留白）。
  - **词条页允许纵向滚动，不设总长上限。** 「一屏读完不需滚动」这条排版纪律**为深度让路**：③④ 要写到行为模式级，而「会出什么牌、什么节奏」写不进两三句。保留的只有「每项一段连续文本」这条可读性要求，与全库其余滚动面（结果区、闭关面板、Exchange 屏）同款处理。
  - **词条②的引用列表不设条数上限**：它列的是「核心」而非全部，条数由内容作者按该敌人的构筑面定。
  - **三条口径纪律（承重）：**
    1. **禁止出现任何具体数值**——伤害、道念、`ManaCost`、概率、回合数一律不写，可用定性词（「大量」「偶尔」「代价高昂」）。**「不含阿拉伯数字」是「词条只给行为模式、不给数值曲线」这句话唯一可被审阅执行的形式**，作为内容评审的硬检查项。**但它是形式检查不是语义检查**（作者仍可写「大约十二点」绕过），只是一道低成本的第一关，不替代人工评审。**检查对象只是挂在 `EnemyData` 上的手写文案**——词条②的功法引用字段、以及由它在呈现层渲染出的功法名不纳入本检查（功法名是内容命名，受功法条目自身的命名规范约束）。
    2. **禁止「本回合」类动态措辞**——图鉴给静态知识，不给动态情报。**这条是深度加大之后唯一没有松动的边界**：写「他中段会把攒下的势砸出来」合规，写「他这回合会出那张」不合规。
    3. **④ 的弱点必须可行动**——玩家读完要知道**该改什么打法**（「他吃不消连续的高费单发」可行动；「他很强」不是）。否则这一项是废话，也辜负了「死亡至少换来知识」的设计意图。
  - **写作规格是可观的成本**（每个敌人四项结构化文案，③④ 写到行为模式级、且要过「无数字」的审阅）。**缓解：给一份模板 + 两三个范例词条放进内容制作流程**，让作者照着填。
- **词条②挂一个「核心功法」引用字段：功法 `Id` 列表、非空。** 正文仍是挂在 `EnemyData` 上的**手写 `LocalizedText`**，**不**由功法条目自动生成——自动灌入的功法正文会带进阿拉伯数字，破掉「不含阿拉伯数字」这道硬检查。
  - **只带 `Id`，不带 `TechniqueTier`**：词条正文绝不写等级，而层数本身就是一个数字面。
  - 加载校验：任一 `Id` 解析不到 → `PushError`（带模板 `Id` + 功法 `Id`）；**每一门须 ∈ 该敌人的功法列表** → 否则 `PushError`；**列表为空但词条已启用** → `PushError`。字段面见 `systems/enemies/`。
  - 被引用功法 `ContentEnabled == false` **不阻断词条渲染**——禁用是产出侧的取池过滤，不是解析失败。
  - **它是玩家点入功法图鉴的入口**，因此列的是「核心」而非「唯一」：一个敌人的路数往往由几门功法合成，只给一门会让玩家读到半张脸。
- **反查是设计目标，不是漏洞（承重）。** 玩家沿「敌人词条② → 功法图鉴 → 该功法逐层卡表」可以**把这个敌人的样本卡组反查出来**。这条通道**被有意打开**，因为它正是「同一个敌人第二次遇到就该能打赢」最强的兑现形式，也是「信息本身就是元进程奖励」（支柱 9）第一次有了强制的落地形态。
  - **对价明写：** 知道卡表的玩家能在战斗中做「他还剩哪些牌」的推算。这不再被当作越界——**它是玩家用一次失败换来的东西**，而「首遇的信息差即首遇的风险定价」说的是首遇收费，不是一直收费。
  - **它有一道天然的界：层数。** 敌人的层数不出现在任何词条里，而层数提升是整组替换（层数不同则牌不同），故反查只能停在「这门功法大致长什么样」，而非逐张精确的本场牌表。这道界不是补丁——它是「词条正文绝不写等级」这条既有纪律的副产物。
  - **没有松动的两条：** 图鉴**战斗中一律不可查**（深度加大不开任何战斗内查询入口，见 `_index.md`），以及**词条不含动态情报**。「读牌堆」这件事因此只能靠玩家的战中记忆完成，不能靠界面查询。
  - **`EnemyData.KeyCardIds` 不再是图鉴的数据源。** 该字段保留，但职能收窄为**仅供敌人 AI 使用**（`KeyCardBias` 权重项的数据源，见 `systems/enemies/_index.md`）——它告诉 AI「这几张是这个敌人的打法重心」，不再对玩家呈现为一个词条格。词条侧的「关键卡列 3 张」整格撤销：核心功法列表 + 可反查的卡表已经把它的职能整条吸收。
- **词条正文绝不写等级（承重）。** 词条挂模板、跨轮回持久，而同一模板会以 5 个不同等级出场——把实例信息写进词条就是用一份会变的东西污染静态知识面。**本次遭遇实例的境界与层级由呈现层单独给出**，不进词条正文；落点与措辞见 `ux/screen-flow.md`。
- **战斗中不可查阅。** 与整族同一条纪律（见 `_index.md`）：本图鉴只在非战斗界面可读，**开打之后没有任何查阅入口**，立绘的点按语义因此完全归战斗自身（选目标）。
  - **它读起来的时刻是战斗前确认页**：已解锁的敌人在进场前把词条摆在玩家面前，未解锁的什么也不给。见 `ux/screen-flow.md`。
- **解锁写在该战斗事件的收口，首遇本场读不到。** 这不是让图鉴分担一份遮蔽，而是把「知识」和「用知识」在时间上分开：**第一次撞上他时你就是不知道他是谁，这份劣势即首遇的风险定价**；这一场换来的词条，在下一次进场前兑现。「一次遭遇，全文案解锁」不受影响——解锁仍是一次性的全量写入，只是落在收口那一次提交上（触发表见 `common-properties.md`）。
- **收录他，同时收录他所用的全部功法。** 敌人的构筑面就是功法引用，故词条②列出的那几门与他套牌里的其余功法一并进入功法图鉴，玩家可从这里点进去读**其逐层卡表**。展开规则见 `common-properties.md`，功法本见 `technique-codex.md`。

> 条目共有字段与解锁语义见 `common-properties.md`；图鉴族总览见 `_index.md`。

## 决策(-> ADR)
> _已定案的决定链接到 decisions/ADR-####。_

- **词条 = 四项**（人物背景 · 核心功法 · 运作方式 · 特点与弱点）；**③④ 写到招式与行为模式级、不设字数上限、词条页允许纵向滚动**；三条口径纪律（不含阿拉伯数字 / 无动态措辞 / 弱点可行动）不变；**词条正文绝不写等级**，实例信息由呈现层单独给出。
- **词条②「核心功法」= 功法 `Id` 非空列表**（多门、不含层数），手写正文只写路数不写功法名；它是点入功法图鉴的入口。
- **「敌人词条 → 功法图鉴 → 逐层卡表」的反查通道是设计目标**（兑现「第二次遇到就该能打赢」），层数不进词条是它的天然界；**图鉴战斗中一律不可查** 与 **词条不含动态情报** 两条不松动。
- **`EnemyData.KeyCardIds` 保留但仅供敌人 AI 使用**（`KeyCardBias` 的数据源），不再是图鉴词条的数据源；词条侧「关键卡列 3 张」整格撤销。
- **敌人图鉴为账号级收集，归 PlayerProfile；与敌人回合的逐步执行呈现按「事前知识 vs 事中情报」分层；它是事前知识的主通道**。
- **战斗中不可查阅**；已解锁词条的呈现时刻是**战斗前确认页**。
- **解锁触发 = 遭遇即记录（不必击败），写在该战斗事件的收口**——本场读不到，下一次进场前兑现。
- **收录一个敌人即连锁收录其套牌所含的全部功法**（→ `technique-codex.md`）。
- **本图鉴是可预测性的唯一载体**：它对敌人 AI 构成一条硬约束——AI 必须是可描述的固定行为模式，而非自由决策。
