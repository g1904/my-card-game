## flags 请求处理路径

`GET /v1/content/flags` 的单次请求成本是：取规则集 → 跑纯函数分桶 → 得出 `disabledIds` → 对该账号的应答做一次签名。下面各节定这条路径上的进程内形态。

### 三份缓存的分工（承重）

该路径上有**三份互不相干的缓存**，混用任意两份都会破坏一条已定纪律，故先一次列清：

| 缓存 | 键 | 值 | 位置 | 生命周期 |
|---|---|---|---|---|
| 规则集缓存 | `flagsVersion` | 规则集记录（不可变） | **进程内** | 永不失效，LRU 回收 |
| 当前版本读取缓存 | —（单值） | `flagsVersionHighWater` | 进程内 | TTL 5 秒 |
| 应答签名结果缓存 | `(flagsVersion, accountId)` | `sig` | 进程内 | LRU 回收 |

- **规则集缓存必须是进程内、不得落 Redis。** 「本实例能兑现的最大版本」的整个取数面是**本实例**已装载的最大键；Redis 是跨实例共享的，放进去就没有「本实例能兑现什么」这个概念，头的下发算式里 `min()` 的右操作数当场失去指称对象。这同时是 `_index.md`「Redis 只承担限流计数器、不持有任何权威状态」在本域的具体落点。
- **当前版本读取缓存与 `operations/environments.md` 配置三层里那个约 30 秒的 `config_knob` 进程内缓存是两份东西，不得混用**——flags 的当前版本不是配置。TTL 初值与它在传播窗口 T 中的预算见 `operations/content-delivery-ops.md`。
- **签名结果缓存的键含 `accountId`，但它不是被否决的那种「按账号解析结果缓存」**：缓存的是 `sig` 而非 `disabledIds`。契约要求同一 `(flagsVersion, 账号)` 的 `disabledIds` 恒定，不要求 `sig` 逐字节恒定；键含版本使该硬约束同样结构性满足。

### 规则集缓存

键 = `flagsVersion`，值是不可变的规则集记录 ⇒ **这个缓存永不需要失效逻辑**：版本提升后旧条目自然不可达，LRU 回收即可，且它使「缓存键必须含 `flagsVersion`」这条硬约束成为结构上不可能违反的事。冷启动与新版本首波用**请求合并（single-flight）**收敛回源：同一 `flagsVersion` 的并发装载只发生一次存储读取。

**不引入按账号的解析结果缓存**；一旦被读数触发而引入，键**必须**是 `(flagsVersion, accountId)`。触发判据是读数与运维阈值（端点处理时延与 CPU 占比，且须已确认瓶颈在分桶计算而非存储读取），取值见 `operations/content-delivery-ops.md`「数值初值一览」。

### 版本预热：装载的触发面

**装载必须有一个请求无关的触发。** 实例侧的当前版本读取缓存每次刷新发现高水位更大时，**主动装载该版本的规则集**；装载成功之后，本实例可兑现的最大版本才随之抬高（头因此永不领先于本实例能兑现的规则集）。成本 = 实例数 × 每次发布一次回源。

纯请求驱动的懒加载在这条路径上自锁：

```
实例未装载新版本 → 它下发的头不涨 → 客户端等值不拉 → 该实例收不到 flags GET → 永不装载
```

集群内每个实例都懒加载时，一次 `publish` 可能对全体设备永不生效，而传播窗口 T 的探针（实例间 gauge 极差 ≠ 0 且持续超 T）**发现不了**——极差为 0，全体一致地卡在旧版本。「全体一致地落后」的告警断言见 `operations/observability.md`。

### 应答的构造：一次快照引用

一次请求**先取定一个规则集缓存条目的引用**，此后应答的全部取值——`disabledIds` 的分桶计算输入 · 应答体的 `flagsVersion` · 签名缓存的键 · 签名覆盖的字节——**一律从这一个引用派生**，请求处理路径上不再第二次读取高水位或缓存。

它把「应答体的 `flagsVersion` 绝不取自高水位」从一条要靠实现者记住的纪律变成结构上不可能违反的手法——高水位就在手边、取错极自然，而取错的后果是同版本不同结果，客户端只比版本号、**没有任何手段发现**。这与 `profile-store.md` 纪律 2「回声校验读的是本事务内已加锁的当前值」是同一手法的两个实例：先取定一个快照，其后全部取值同源。

### `X-Flags-Version` 的下发值

下发值 = `min(高水位, 本实例当前能兑现的最大规则集版本)`。偏斜是不对称的：头落后于本实例可兑现的版本时，客户端等值 / 更小即不拉，只是晚一拍、零告警零上报；头领先时客户端拉回后整批丢弃并产生一次误告警，而那条上报通道存在的目的是发现灰度分桶串号、中间层缓存旧应答这类真事故。**要堵的是「头领先于体」，不是「窗口太大」。**

### 「本实例可兑现的最大版本」的取数面

即规则集缓存中已装载的最大键——零新增机制、零新增存储、零报文改动。同一个数同时是传播窗口 T 的探针所暴露的那个 gauge 的取数面（`operations/observability.md`）。

### 应答签名的结果缓存

应答按账号计算并逐账号签名，走与 manifest 同一密钥体系。签名结果按 `(flagsVersion, accountId)` 缓存，**缓存的是 `sig` 而非 `disabledIds`**；请求量量级与该端点的容量口径见 `operations/content-delivery-ops.md`。

### 回源失败的降级

single-flight 回源失败时的处置由头的不对称性直接给出：

- **本实例已装载过更旧的版本** → **用它兑现应答**，应答体与头都是那个更旧的版本号，**不返回错误**。这正是这套设计要覆盖的情形：头落后在客户端侧零告警、零上报，只是晚一拍。
- **本实例一个版本都没装载**（冷启动首个请求且回源失败）→ **返回错误应答，绝不以空 `disabledIds` 兑现**。空集合语义上是「什么都没关」，会让秒关静默失效，且客户端会把它当作一批合法的 flags 持久化下来作降级值。
- **失败不写负缓存**——一次瞬时存储故障会被缓存住，把秒级抖动放大成 TTL 级失效。
- 错误应答用**兜底码 `server.unavailable`**（`class: Retryable`），**不给这个失败面专属码**——客户端在本端点上的处置与一般断线降级逐字相同、玩家面为空，而「区分零装载与一般不可达」所需的事实就在服务端进程内，打点即可。判据见 `contracts/envelope.md` §6「台账的承重项」；该失败面的可见性由 `operations/observability.md` 的零装载失败计数器承担。

### 规则集缓存的容量上限

键不可变 ⇒ 无失效逻辑，只需一个 LRU 容量上限。稳态下同时可达的版本只有 1–2 个（当前版本 + 刚发布尚在传播的那个），故上限取 **8**（数量级余量，规则集体积极小——一批 `Id` 集合 + 分桶规则）。**待实测校准**；它是进程内容量常数、不构成运营旋钮，不进运维文档的旋钮表。

## 四条实现纪律

写错任一条都会在正常账号上产生故障，而不是在边角情形上。

1. **规则集缓存留在进程内。** 把它挪进 Redis 会让「本实例能兑现的最大版本」失去指称对象，头的下发算式随之失效。
2. **一次请求只取定一次快照引用**，应答体版本号、分桶输入、签名键与签名字节全部由它派生，路径上不再第二次读高水位。
3. **装载有请求无关的触发**，否则懒加载与「头永不领先」合成自锁，且探针发现不了。
4. **回源失败时宁可用旧版本或报错，绝不下发空 `disabledIds`、绝不写负缓存。**

## 服务端保证

阈值一律参数化，落定后可直接转为验收用例；与 `account.md` 的 N / S / C 组同体例。

| # | 输入 | 期望 |
|---|---|---|
| F1 | 同一 `flagsVersion` 的两次装载并发到达 | 只发生一次存储读取（single-flight） |
| F2 | 版本提升后再读旧 `flagsVersion` 的缓存条目 | 仍可读到且内容逐字不变（键不可变 ⇒ 无失效逻辑） |
| F3 | 高水位 > 本实例可兑现的最大版本 | 应答体的 `flagsVersion` 恒等于本次实际用于分桶的那条记录的键，即取后者 |
| F4 | 任一应答 | `X-Flags-Version` 恒 ≤ 本实例已装载的最大键，且恒 ≤ 高水位 |
| F5 | 某实例上无任何 flags GET 到达，其间发生一次 `publish` | 该实例下发的头在当前版本读取缓存的一个 TTL + 装载耗时内抬高到新版本 |
| F6 | 回源失败，本实例已装载旧版本 | 以旧版本兑现，应答体与头同为旧版本号，**不返回错误** |
| F7 | 回源失败，本实例零装载 | 返回 `Retryable` 类错误，**应答体不含 `disabledIds`** |
| F8 | 连续两次请求同一 `(flagsVersion, accountId)` | 分桶结果逐字相同（分桶是 `(accountId, 规则集版本)` 的纯函数） |
