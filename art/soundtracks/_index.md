**生成工具：倾向 Suno，尚未定案。** Midjourney 不产音频，故音频侧需要另一个工具；当前倾向 **Suno**，但**未拍板**——写 audio guide 时可**暂按 Suno 的形态组织 prompt**，但**不要把工具专属的参数语法写死进模板**，换工具时 prompt 正文应仍可复用。待答条目见 `../../open-questions/deferred-content.md`。

## 资产类目

| 类目 | 用在哪 | 关键约束 |
|------|--------|----------|
| **主题曲 / 主菜单** | 启动与主菜单 | 一次定调，玩家第一耳朵听到的就是全作基调；**最先编写**。 |
| **战斗 BGM** | 战斗事件（含 Practice / Finale） | 对局需要**可循环**且不易听腻。**常规战斗与 Finale 各一份 guide**：共享动机、配器密度分档，常规低位压迫、全配器爆发只留给 Finale。 |
| **事件 / 探索 BGM** | 五类修行事件的非战斗形态 | 抉择氛围为主，不抢文本注意力。 |
| **篇章氛围** | 三个篇章（炼气→筑基 / 筑基→金丹 / 金丹→元婴） | 随境界推进而变化，承担进程感：**越走越空旷孤高**（织体 / 混响 / 音区三参数拉梯度，见 `audio-direction.md`）。 |
| **UI 音效** | 出牌、抽牌、结算、按钮、翻页 | **短、可重复听**——出牌音会在一局内响几十次；材质取古物实材质，须过「几十次重复可听」校验。 |
| **反馈音效** | 道念增减、被削减、胜负结算、寿元告警 | 与视觉反馈同拍；**寿元跌破低位播一次性低调提示音**（不循环、不常驻、不震动，形态见 `../../ux/screen-flow.md`）。 |

> 类目可增。

**guide 编写顺序：BGM 类目在前（主题曲最先）→ 音效类目在后。** 听觉的 grimdark 身份由 BGM 承载，先立氛围、一次定调；音效的方向已在 `audio-direction.md` 锁定以免日后漂移，后置的只是打磨深度与预算。

## 移动端约束

- **多数玩家静音游玩。** 音频必须是**增益**而非承载信息的唯一通道——任何靠声音传达的东西都要有视觉等价物（与 `.claude/rules/ui-input-rules.md` 的「无仅悬停可供性」同源的纪律）。
- **混音基准是耳机聆听**，不为外放场景打磨——外放缺失低频层是被接受的听感代价，且因上一条纪律不构成信息缺失。权威在 `audio-direction.md`「动态与混音」。
- **包体与内存：** 移动端优先；BGM 时长与码率需与包体预算权衡（预算未定）。
- **可循环**：BGM 须无缝循环，对局时长不定。
