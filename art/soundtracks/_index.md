# 音频（Soundtracks）—— 索引

一切音频资产的方向、参考与生成指导。流水线与视觉相同：vision + 参考 → AI 写 audio guide → 投喂生成工具。

**生成工具：倾向 Suno，尚未定案。** Midjourney 不产音频，故音频侧需要另一个工具；当前倾向 **Suno**，但**未拍板**——写 audio guide 时可**暂按 Suno 的形态组织 prompt**，但**不要把工具专属的参数语法写死进模板**，换工具时 prompt 正文应仍可复用。待答条目见 `../../open-questions/deferred-content.md`。

## 资产类目

| 类目 | 用在哪 | 关键约束 |
|------|--------|----------|
| **主题曲 / 主菜单** | 启动与主菜单 | 一次定调，玩家第一耳朵听到的就是全作基调。 |
| **战斗 BGM** | 战斗事件（含 Practice / Finale） | 固定 10 回合的对局需要**可循环**且不易听腻；Finale 应有区别于常规 Combat 的强度。 |
| **事件 / 探索 BGM** | 九类修行事件的非战斗形态 | 抉择氛围为主，不抢文本注意力。 |
| **篇章氛围** | 三个篇章（炼气→筑基 / 筑基→金丹 / 金丹→元婴） | 随境界推进而变化，承担进程感。 |
| **UI 音效** | 出牌、抽牌、结算、按钮、翻页 | **短、可重复听**——出牌音会在一局内响几十次。 |
| **反馈音效** | 道念增减、被削减、胜负结算、寿元告警 | 与视觉反馈同拍；寿元告警是否伴音尚未定（见搁置清单）。 |

> 类目可增。

## 移动端约束

- **多数玩家静音游玩。** 音频必须是**增益**而非承载信息的唯一通道——任何靠声音传达的东西都要有视觉等价物（与 `.claude/rules/ui-input-rules.md` 的「无仅悬停可供性」同源的纪律）。
- **包体与内存：** 移动端优先；BGM 时长与码率需与包体预算权衡（预算未定）。
- **可循环**：BGM 须无缝循环，对局时长不定。
