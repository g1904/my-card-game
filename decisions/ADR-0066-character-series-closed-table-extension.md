# ADR-0066 — `/entitlement/characterSeries` 进后端写入字段封闭表（该表成文以来的第一次扩表）

- **状态：** Accepted
- **日期：** 2026-09-11
- **来源：** handoffs/2026-09-12-premium-character-series-unlock.md

## 背景

`profile-sync.md` §5 的**后端写入字段封闭表**自成文起就带一道护栏：规则的措辞是「后端只读，**除表内 N 项外**」——例外式而非列举式，任何扩表提案须显式引用该护栏并逐条论证，不得静默加行。角色系列解锁的真值产生在验票事务里，客户端没有任何本地通道能派生它；不进表，解锁就没有通道到达客户端。这构成该表成文以来的**第一次扩表请求**，必须按护栏的规格处理。

## 决策

**后端写入字段封闭表由 4 行扩为 5 行，新增 `/entitlement/characterSeries`**（写入时机 = 验票通过且 `kind == CharacterSeries` 时尾部追加一个元素）；**透明字段白名单同加一行**。两张表**正交、非二选一**：前者答「谁写」，后者答「后端看不看得懂」，而后端写入者必然对后端透明。

按护栏逐条论证：**判据 ①（真值只可能在服务端产生）成立** —— 客户端写入即等于客户端有权发货，那条路径已由 `purchase.md` §2 与 `ADR-0007` 关死；**判据 ②（客户端无其他通道取到它）成立** —— 本 path 没有兑现段，没有客户端掷骰、没有可由本地事实派生的值、没有第二个字段能承载它。

**「写入时机」列不被触碰** —— 本行落在既有的「验票」时机下，建号 / `bind`·`unbind` 两个时机一字不动。**§5c 的适用面恒等式自动覆盖新 path**，不需要第二次决定；`entitlement` 本就是两个受约束顶层键之一 ⇒ **「受约束的顶层键恰有两个」一字不改**。回声比较口径取**有序逐元素**（同 `identities`），成立前提是后端恒在尾部追加、客户端原样回声。

→ `contracts/profile-sync.md` §5 · §5c

## 理由

- **护栏本身写明它是「一道需要论证才能通过的门」，不是禁止扩表** —— 两条「够格进表」判据同时满足即通过，而本 path 与表内 `bundleGrantOrdinal` **同所有权、同写入时机**，与三条既有反例（`nickname` · `/statistics` · `bundleRedeemedOrdinal`，真值均在客户端）逐条不同。
- **§5c 的恒等式（受回声校验约束的 path 集合 ≡ 写入表行集合）使扩表无需加强护栏**：写入表加一行，该路径自动进入回声约束，不需要第二份清单。这正是当初否决「另立一张受约束 path 清单」的收益兑现。
- **两表正交** —— 透明性与所有权不同轴；后端写入的字段不可能对后端不透明。
- **有序逐元素而非集合相等**：后端恒尾部追加、客户端不改写 / 不去重 / 不归一化 ⇒ 有序天然成立；另开一种无序比较语义只会在口径表上多一种读法，为零收益付一次歧义。

## 备选方案

- **不进封闭表，另开一条解锁下发通道 / 端点** — 本 path 没有其他通道能让解锁到达客户端；新开通道等于为一个字段造一条并行的下行面。
- **只加透明白名单、不加写入表** — 那等于承认客户端有权写它，与 `ADR-0007` 的写入权威分配正面相悖。
- **另立一张「受回声校验约束的 path」清单** — 已由 §5c 恒等式明确否决：它与写入表必然漂移，且漂移形态恰是「进了写入表却没进回声表」。
- **`characterSeries` 取无序集合比较口径** — 多一种读法、零收益。

## 后果

- `contracts/profile-sync.md` §5 封闭表五行、§5b 透明白名单加行、§5c 的「当前的具体面」表加行；**护栏措辞与「受约束的顶层键恰有两个」一字不改**。
- 该 path 自此受 §5c 回声校验约束：客户端提交不等的值 ⇒ 整批拒绝 `sync.conflict` + 风控事件。
- **连带刚性首次真实行使**（`envelope.md` §8）：向受约束顶层键内的对象追加字段，须两侧同批落笔 —— 客户端对该 path 持强类型 record，往返会静默丢掉不认识的字段，下一次回声当场失败。**条文不改**，此处只记它被行使了一次。
- 触发 `schemaVersion` bump 与矩阵登记（`ADR-0024` 的既有流程，矩阵行落 `operations/version-matrix.md`）。
- 跨边界后果：客户端须对该 path **原样回声、不改写 / 不去重 / 不归一化**，且元素字段面由客户端定义、本库不复述 → `game-design-documents/systems/player-profile/_index.md`、`game-design-documents/handoffs/2026-09-12-premium-character-series-unlock.md`。
- 如实记下的代价：护栏此后会被引为「扩过一次表」的先例 —— 两条判据的逐条检验因此不可省略。
