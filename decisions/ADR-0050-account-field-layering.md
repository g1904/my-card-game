# ADR-0050 — 账号级字段分规则层 / 统计计数层；元素键分野是它的投影，由启动期词缀断言把守

- **状态：** Accepted
- **日期：** 2026-08-09
- **来源：** handoffs/2026-08-09d-field-layering-merge-criterion-and-ordinal-naming.md, handoffs/2026-08-19-costkey-statkey-registry.md, handoffs/2026-08-22-purchase-count-statkey.md

## 背景

`PlayerProfile` 上同时有两类数：一类被判定 / 闸门 / 幂等键读取（例如「第几次通关」决定礼包发放序号），一类只被 UI 读来展示（例如「累计通关次数」）。两者若混装，同步口径就无从确定——严格同步太贵，宽松同步会让幂等键失准。

## 决策

账号级字段分两层：

- **规则字段层** — 被任何判定 / 闸门 / 幂等键读取。严格同步、后端可复算。
- **统计计数层** — 只被 UI 读来展示。宽松同步。

**依赖方向单向**：规则层**可以**被统计 / UI 层读取展示；统计计数层**绝不可**被任何规则读取。

**合并判据**：语义 + 同步口径 + 篡改后果三者全同才可合并。

**命名硬约定（可机械检查）**：后缀 `Ordinal` ⇒ 规则层；`Total` 前缀 / `Count` 后缀 ⇒ 统计层，且统计层**禁用 `Ordinal` 后缀**。

这条分野在元素键上的投影：**`CostKey`（进 `Elements`）与 `StatKey`（进 `Stats`）**，判据是「**这个数会被规则 / 闸门 / 幂等键读吗**」。由一条**启动期词缀断言**把守（`StatKey` 成员必带 `Total` 前缀或 `Count` 后缀）。

分层表 → `systems/player-profile/_index.md`；断言 → `systems/services/profile-service.md`。

## 理由

同步口径不是字段的装饰，而是它的**类型**：一个会被幂等键读的数，宽松同步一次就可能重复发放。把它写进命名规则并加一条开机可失败的检查，是把纪律停在阶梯第 4 级（→ `ADR-0013`）。

两个枚举的成员由对两张字段表**反向穷举**得出，闭合判据是双向满射——不是「列举想得到的资源」。

## 备选方案

- **统计侧照常设 `TotalFinaleWins`、靠注释说明它不是规则层** — 否决：注释不可机械检查。
- **通关按篇章计** — 否决：改变幂等键语义。
- **把 `FinaleWinOrdinal` 移进统计容器另立幂等键** — 否决：幂等键就是规则层的定义特征。
- **改用复合幂等键 `Hash64(AccountSeed, chapterId, characterId)`** — 否决：不可读、排障困难。
- **加读档交叉校验补救混装** — 否决：补救不如不混装。

## 后果

- 「不为购买次数设 `StatKey` 成员」这类判断由本判据机械得出，不需要逐次讨论。
- `CostKey` 成员数长到 30+ 则重议这条分野——退让位已写下。
- 后端的 `/entitlement/bundleRedeemedOrdinal` 只读行与不变式建立在规则层语义上。
