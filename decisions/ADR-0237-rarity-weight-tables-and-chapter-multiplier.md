# ADR-0237 — 奖励稀有度权重 = 三张优势档表 × 篇章乘数 `m(c)` 共九行；配三条加载期校验

- **状态：** Accepted
- **日期：** 2026-09-09
- **来源：** handoffs/2026-09-09d-combat-rarity-and-reward-scale.md · answer-logs/log-combat-rarity-and-reward-scale.md

## 背景

战后可选奖励按内容定义上的 `Rarity : RarityTier` 加权抽取，但权重从来没有取值。同时，「每个池五档全非空」一旦成立（→ `ADR-0238`），**篇章对稀有度的影响就归零**——因为混合池上某档的抽中概率只由权重决定。篇章维必须另找落点，否则三章拿到的东西一样好。

## 决策

**权重 ∝ `1, r_eff, r_eff², r_eff³, r_eff⁴`（相邻档递减比），归一到 100 后取整。** 三张表由优势档 `Tier { Narrow, Solid, Crushing }` 选定，篇章差异落成 **`r` 的篇章乘数 `m(c)`**：

```
r_eff(Tier, c) = r(Tier) × m(c)
r(Narrow) = 0.42   r(Solid) = 0.52   r(Crushing) = 0.70
m(ch1) = 1.00      m(ch2) = 1.15     m(ch3) = 1.30
```

九行权重表 → `systems/balance.md`。

**三张奖励表与授予表同住一份 `ISingletonContent`（暂名 `RarityWeightsData`）；权重表一律住 `systems/balance.md`、不落 `DrawPool<T>`。**

**加载期校验三条：** ① 任一格权重 ≤ 0 → `PushError`（带篇章 + 优势档 + 档号）；② **随机占优逐篇章各验一次**，违反 → `PushError`；③ 任一 `(Tier, c)` 组合的 `r_eff ≥ 1` → `PushError`。

## 理由

- **篇章乘数是一层追加的旋钮、不改动三个 `r`**：`m(ch1) = 1.00` ⇒ ch1 一列就是三个 `r` 直接生成的那三行，形状与取值解耦。
- **`r` 不共用授予池的 0.6**：授予池取 0.6 是因为账号级法则的**获取次数极少**（残卷个位数、礼包 1 次），过陡会让高档事实上不可达；战后奖励的获取次数高两个数量级，这条约束不成立 ⇒ 基准档可以更陡。
- **`Crushing` 取 0.70 而非更高**，使碾压档在 ch1 仍以 Tier1–Tier2 为主：「碾压才有高稀有度」这条激励已被 `±2` 赋级带从规则层压制，把碾压做成「几乎必出高档」会把它重新放大。
- **`r_eff < 1` 是硬上界**：越界则分布单调上升、Tier5 成为最常见的一档，与稀有度语义正面相抵。当前最大值 `0.70 × 1.30 = 0.91`。
- 与授予表同住一份资源，是因为奖励表之间存在**随机占优这条跨表不变式**，按平衡资源的三问判据「有跨字段不变式 ⇒ 必须同住一份」不容拆开。

## 备选方案

- **用池的档幅上下界表达篇章与档位差异** — 否决（用户裁决）：与「每池五档全非空」不兼容。
- **按 `combatTier` 再分一维权重表** — 否决：权重表的分表维度是「按用途」，`combatTier` 是「由哪条路径给出」，加这一维与分表判据同形相抵。
- **沿用授予池的 `r = 0.6`** — 否决：两侧获取次数差两个数量级，约束前提不成立。

## 后果

- **稀有度分布完全由这九行给出**；池只决定「抽中某一档时拿到的是哪一族的哪几条」（→ `ADR-0238`）。
- **同一篇章内的随机占优仍成立**（同章内 `r_eff` 沿 `Narrow → Solid → Crushing` 单调增），加载期断言的形状不变，只是要逐篇章各验一次。
- Tier5 的量级回代 ≈ **2.1 次 / 轮回**（三章平均权重 ≈4.7% / 7% / 9.3%，≈30 候选槽 / 轮回），与「值得记住、但会真的遇到」的既有量级同档。
- 九行表与 `m(c)` 的**实测校准**留作待答项：样本出来后按同一条式子重算，**改的是数不是形状**。
