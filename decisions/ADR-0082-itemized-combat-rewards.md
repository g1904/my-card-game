# ADR-0082 — 战后奖励改为逐项领取 / 跳过（不再是三选一）；领取进度成为决策点 D6

- **状态：** Accepted
- **日期：** 2026-08-23
- **来源：** handoffs/2026-08-23g-hidden-stat-combat-boundary-event-backdrop-and-itemized-rewards.md

## 背景

战后奖励原设计是**三选一**：给三项候选，玩家挑一项。理由之一是「奖励数量恒定使 UI 布局稳定」。

但三选一与本作的其他选择面重复（事件批次也是择一），且它强制玩家在不需要任何一项时仍要拿一项。

## 决策

战后 / 事件奖励面板改为 **Slay the Spire 式逐项列出、逐项领取或跳过**——**不是三选一**。数量仍为 3、面板长度恒为 3，**到手数 0–3 由玩家定**。

**领取进度因此确立为决策点**：战斗侧决策点清单由 D0–D6 扩为 **D0–D7**（`D6` = 一次领取 / 跳过，原战斗收口顺延 `D7`），中途状态落 `activeCombat.reward`。

规则与决策点表 → `systems/services/combat-service.md`；面板呈现 → `ux/combat-ux.md`。

## 理由

逐项领取让「我不需要这个」成为可表达的选择，而三选一强迫玩家在三个都不想要时仍拿一个——那不是取舍，是形式。

「奖励数量恒定使 UI 布局稳定」这条理由**已失效并删除**：逐项面板的长度仍是 3，布局照样稳定。

领取进度必须是决策点，因为**领取那一刻有新状态产生**（`reward.picks[i].state` 由 `Pending` 转定）——这正是决策点的判据（→ `ADR-0036`）。

## 备选方案

- **保留三选一** — 推翻：强迫领取，且与事件批次的择一重复。
- **另设「放弃全部候选」通道** — 推翻为不必要：逐项跳过天然包含它。
- **置换 / 禁用面板随之改动** — 否决：它本就是逐槽接受 / 拒绝，同构，无需动。

## 后果

- 本条**推翻三条既有定案**：不设「放弃全部」通道 · 「固定 3 项候选」的择一语义 · 「战后奖励选择不是决策点」。
- `activeCombat.reward` 是新的中途状态，随 `activeCombat` 落存档。
- 失败时无奖励面板，六条失败代价不变（→ `ADR-0076`）。
