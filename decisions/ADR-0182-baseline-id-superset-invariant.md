# ADR-0182 — 随包基线条目永不删除：`Id` 集合单调不减，退役 = 禁用或掏空，归档步机械核对超集

- **状态：** Accepted
- **日期：** 2026-09-06
- **来源：** handoffs/2026-09-06-baseline-superset-and-pack-proof.md · answer-logs/log-baseline-superset-and-pack-proof.md

## 背景

overlay 侧早已定死「只改不增」，防的是 overlay 引入基线里不存在的 `Id`。但**发版通道**上的反方向从未表态：客户端发新版时能不能把一个随包基线条目**删掉**。这个口子不堵，会精确重演同一个事故——只是换了通道与方向。

## 决策

**客户端发版对随包基线只增不删——跨发版的基线 `Id` 集合单调不减；更高版本基线恒为更低版本基线的 `Id` 层超集。**

**精确表述（承重）：超集只在 `Id` 集合层面成立**；字段值与 `ContentEnabled` 取值**不承诺**跨版本不变——发版可以自由改值，这正是退役路径的载体。**改名 = 删 + 增，同样禁止。剧本类型不开删除例外。**

**退役路径按类型三分，全部落在「只改不删」内：** 抽取池成员 → 基线里置 `ContentEnabled = false`；结构性查表类型（含一切 `ISingletonContent`）→ **没有退役一说**，只能演进字段值；合规级移除 → **掏空而非删除**（字段值改中性、`Artwork` 置空并同版删除其贴图资产、`ContentEnabled = false`；命中恒启用类型时只掏空、不置 false）。

**机械闸落在基线快照归档步：** 每次发版归档时枚举新快照的 `Id` 全集，与**按 semver 版本序取的上一份已归档快照**比对，出现「上一版有、本版无」的 `Id` → **非零退出，归档与发版闸失败**，报出缺失清单。

逐类型退役形态表、semver 取基准的理由与包体代价 → `systems/services/content-service.md`「内容发版纪律」。

## 理由

- **删一个条目 = 升级即废档**：云端权威档里躺着被删条目的持有实例，玩家升级客户端后拉档 → `Get(id)` → `PushError` + 抛。本库「存档引用未知内容的风险从根上消失、无需任何兼容规则」这句话的前提正是**已发布的 `Id` 永远可解析**；允许删除就得为发版通道发明一整套本库明确庆幸不需要的兼容规则。
- **另两条独立支撑**：图鉴完成度分母走 `AllIncludingDisabled()`，删条目让全体玩家的分母跳变；结构类型（地域图顶点、剧本节点、档位表行）删一条即结构空洞，而图的稳定性是对玩家的隐性承诺。
- **闸取第 3 级（机械阻断）**：删条目的症状是「能上线、线上不可见」——要到老档玩家升级后才炸，现场已丢（`ADR-0013` 的选级判据）。
- **只比上一版即可**：超集关系传递，逐版通过则全链成立。**按 semver 而非归档时间序取基准**——老版本线补丁（1.1.5 晚于 1.2.0 归档）按时间序会误拿 1.2.0 当基准而误报缺失。

## 备选方案

- **为剧本类型开删除例外** — 否决：剧本条目理论上可删（不被存档引用、key points 悬空已有降级处置），但开例外会把超集不变式从全称命题降为**带类型白名单的命题**，发版闸与对侧回链都要跟着带条件，换来的只是 KB 级文本的包体。
- **合规移除时真删条目** — 否决：`Id` 壳留存才能让存档解析不断；掏空已能回收全部实质包体（贴图）。
- **打包闸只跑最新基线** — 否决：不健全且方向反了。存在性判据在 **`Id` 最少的最旧在架基线**上最严，只跑最新恰好漏掉闸要防的事；且合并校验含值敏感断言，`Id` 层超集不能使任何单基线运行覆盖其余。

## 后果

- **包体单调增长**，但代价有界：不删条目 ≠ 不删资产——退役条目的贴图可从包内移除，`.tres` 文本壳是 KB 级。
- **与「不预埋空壳 `Id`」不冲突**：那条否决的是**从未发布过**的假条目（校验放不宽 + 审核灰区），退役条目是曾经完整发布过、已被禁用不进池的真条目，校验不放宽。
- **快照形态须「可枚举 `Id` 集」**成为一条硬要求（归本库自决那一项）。
- **对侧的回链锚点**：`backend-design-documents/operations/content-delivery-ops.md` C6 的打包闸基线口径前提句以本条为锚。
- **`ADR-0141` 的客户端义务不被弱化**——打包闸仍逐基线各跑，产包证明仍按被跑的每个基线逐份产出。
