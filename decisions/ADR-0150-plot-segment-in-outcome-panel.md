# ADR-0150 — 剧本分支触发于 `eventEnd` 提交之后，呈现落在事件结算面板内的「剧本段」

- **状态：** Accepted
- **日期：** 2026-09-02
- **来源：** handoffs/2026-09-02-plot-branch-choice-ui.md

## 背景

剧本树的数据挂点已定（`decisions/ADR-0015-plot-tree-data-shape.md`）。悬着的是呈现侧三问：**何时** · **哪一屏** · 以及剧本正文落哪里（至今无明文）。事件事务纪律（中间态永不需要持久化、取消点与存档点永远重合）把可选位置压得极窄。

## 决策

- **触发点 = `eventEnd` 那一次 `TryApply` 提交完成之后**：该 arc 的 key point 已停在分支节点上 → 结算面板呈现该节点的正文与分支 → 玩家点选 → `ChooseBranch` 一次 `TryApply` → 面板收起。**分支呈现在 arc 抵达该节点的同一次结算面板上，不延后一次收口。**
- **屏 = 事件结算面板内追加一段「剧本段」= 正文（可空）+ 分支（可空）。有分支时分支按钮取代「继续」**（零额外点击）；无分支时正文 + 既有「继续」。**纯叙事节点与分支节点共用同一落点，不另开剧本层屏。**
- **纵向堆叠全宽按钮**，每条一行、承载 `BranchLabel` 全文不截断，满足触控目标尺寸下限、落在拇指可达区与安全区内；不复用横滑区语汇；正文过长时面板内纵向滚动；零 hover 通道。
- **不做二次确认、无跳过、无默认选中、无超时自动选**；未选完退出 = arc 停在该节点，下次收口照常再呈现，该等待时刻**不是新的存档点**。
- **分支段不带「这是一次剧情抉择」的显式标识**，与结算面板其余部分同一视觉层级。
- **一次收口至多呈现一条 arc 的分支**，固定优先序 `Tier` 序 `Story → Chapter → SideChapter → SideStory`，同 `Tier` 按 `ArcId` 字典序。与跨档叙事同屏时**跨档叙事行在上、剧本段在下**。**终态时不呈现分支**。
- **`ChooseBranch` 那一次写入 = 批次层的一次独立即时提交**，不新增存档点清单条目；不触发 `RefreshAfterEvent`、照跑终态判定（恒为 no-op）、不计软阻塞闸门。

逐条排布与优先序 → `ux/screen-flow.md`、`systems/services/plot-manager.md`。

## 理由

- **触发点不是取舍，是被既定纪律逼出的唯一位置**：落在 `eventEnd` 组装之内，等于在提交之前引入一个可退出点 ⇒ 需持久化中间态，与「中间态永不需要持久化」「取消点与存档点永远重合」正面冲突（`decisions/ADR-0020-event-transaction-discipline.md`、`decisions/ADR-0036-decision-point-saves.md`）；落在事件推进之外的独立时机，等于给剧本层开第二个出口。延后一次收口只会让分支正文与产生它的那个事件脱节。
- **屏有先例**：跨档叙事已确立「由状态转换触发的定性文案播在事件结算面板内，不是独立弹层」；剧本分支是同族的东西，没有理由为它选一个已被明确否决过的形态。
- **不加显式标识**：承重的「隐藏剧本层 + 调制才是显影通道」是本作的核心路径；标识会把刻意隐藏的剧本层在 UI 上显形一次，而「一时不确定」由按钮文案本身自然消解。
- **确定性是硬要求**（同一存档恢复后必须问同一条），字典序是零成本的确定性来源；这同时填上 `TryResolvePlot` 单数产出在多条 `Active` arc 下取哪一条的空白。
- **不触发 `RefreshAfterEvent` 成立且必须**：重算会消耗 `map` 子流，并开出「用一次分支选择刷新这一批事件」的通道。

## 备选方案

- **把分支插进 `eventEnd` 五步组装之内** — 否决：在提交前引入可退出点 ⇒ 需持久化中间态，与两条事务纪律正面冲突。
- **另设独立触发时机** — 否决：给剧本层开第二个出口。
- **延到下一次收口再呈现** — 否决：分支正文与产生它的事件脱节。
- **另开一层全屏剧本层屏** — 否决：与「叙事是点缀不是载体」相抵；跨档叙事已否决过同形态。
- **只把分支节点的正文落结算面板、纯叙事节点另裁** — 否决：分支必然需要正文作语境，两者分落两处则一次选择要跨两个呈现面。
- **复用横滑区语汇** — 否决：横滑是 eventOptions 与角色选择的语言，复用会让两个层级的操作读成同一件事。

## 后果

- **存档 schema 零改动、零迁移、零新增存档点**；不把分支选择记进 key point 的已走路径数组（判据「重算不出来且有消费方」当前无消费方）。
- 面板框架文案走 `EVENT_` / `event.csv`；`Body` 与 `BranchLabel` 一个字都不进 `res://text/`——内容层 `LocalizedText`（`decisions/ADR-0084-no-baked-in-translatable-text.md`）。
- 相关文档因此这么写：`ux/screen-flow.md`（结算面板内「剧本段」的排布、按钮语汇、优先序与同屏叠放）· `systems/services/plot-manager.md`（触发点、arc 优先序、`ChooseBranch` 写入定位）。
- 「一次 `eventEnd`，每条 arc 至多前进一个节点」重述为「一次 `eventEnd` **之内**至多前进一个节点」：行为零改动，只把作用域写明。
- 待定项：`content/plot-arc/` · `content/plot-node/` 类型档案尚未开张，可见 / 不可见判据须写进它们的字段核对清单。
