# ADR-0096 — 收录一个敌人即收录其全部功法词条；`eventEnd` 入账口径只收窄到两本

- **状态：** Accepted
- **日期：** 2026-08-25
- **来源：** handoffs/2026-08-25-info-economy-and-codex-expansion.md

## 背景

`TechniqueCodex` 立起后（→ `ADR-0095`），它的解锁触发要定。逐门功法单独解锁意味着玩家要在战斗中「见到这门功法被打出来」才算——而敌人未必把每门功法都用上。

同时，若把「只有 `eventEnd` 入账」定为全族通则，就要为出生地、自带绑定神通、Exchange 购买三处各开例外。

## 决策

**连锁解锁：收录一个敌人即收录他所用的全部功法。** `EnemyCodex` 收录一个敌人时，按**该敌人的功法引用列表**同时把全部功法收录进 `TechniqueCodex`。展开组装方 = **`CodexManager`**，写入仍经 `ProfileManager` 单点提交、**零新增提交点**。

**入账判据是遭遇而非胜利**——战败 / 中途终局同样入账。

**「只有 `eventEnd` 入账」只约束 `EnemyCodex` 与 `TechniqueCodex`**，其余各本触发表原样不动。

`Pool == Enemy` 的功法**照常收录**，完成度分母含它；「敌方专属」是**呈现层现算标注**，不新增存档字段。

→ `systems/player-profile/codex/_index.md` 与 `codex/common-properties.md`。

## 理由

敌人的构筑面**就是**功法引用（→ `ADR-0090`），故「见过这个敌人」与「见过这几门功法」是**同一次接触**——不是两件需要分别达成的事。

`eventEnd` 口径只收窄两本而非全族：全族改口径需为出生地 / 自带绑定神通（落在「轮回创建」提交上）与 Exchange 购买（逐笔即时提交）**三处各开例外**，把一张可机械核对的触发表变成三条例外规则。

遭遇即入账（不要求胜利）与七本共用的触发内核一致：**接触即记，不要求你从中获益**。

## 备选方案

- **全族改 `eventEnd` 入账** — 否决：需三处例外，触发表失去可机械核对性。
- **按本次遭遇实例实际使用的功法展开** — 改写：其理由（`OverridesDeck` 会解锁错的东西）已随字段删除而失效，且层数逐条固定 ⇒ 实例功法集**恒等于**模板引用列表。
- **由 `ProfileManager` 自动派生展开** — 否决：展开是图鉴域的知识，归 `CodexManager`。

## 后果

- 零新增提交点：连锁解锁在既有的 `eventEnd` 提交内一次写完。
- 完成度分母含敌方专属功法，玩家可能永远无法「持有」它们——这是有意的，图鉴记的是见过而非拥有。
- 敌人图鉴词条②因此有了真实去处（功法词条入口），在战斗前确认页兑现（→ `ADR-0094`）。
