# ADR-0268 — 账号级法则获取速率写成 `balance.md` 上的派生表：「老账号全开」的现实分母是 `x ≈ 9–12`，不是池被取尽

- **状态：** Accepted
- **日期：** 2026-09-10
- **来源：** handoffs/2026-09-10-player-power-acquisition-and-balance.md · answer-logs/log-player-power-acquisition-and-balance.md

## 背景

「老账号全开的战斗内法则合计 ≤ 25%」这条参考闸缺一个**分母**：按什么口径算「老账号全开」。按「池被取尽」算会得到一个远高于任何真实账号的上界，让这条闸在评审时失去意义。本次不提出任何新机械闸，改为补一个可算的分母。

## 决策

由残卷分档表（**六档 + 首胜硬置行**）与「一篇章一个 Finale」算出的**派生量**落 `systems/balance.md`——**不是第四张配置表、不落任何字段、不得被当作独立锚引用**。

三条读法：

1. **现实分母是 `x ≈ 9–12`，不是「池被取尽」。** `x ≥ 15` 是**渐近线而非可达点**。校准 ≤ 25% 时按 `x ≈ 12` + 礼包所得 + 成就 90% 档所得取分母。累计里程碑写在表上。
2. **两个方向相反的偏差同时存在**：分母取完整轮回而多数轮回中途身死 ⇒ 真实速率**更低**；表把 `0 → 3` 档整体写成由三次首胜占满、未计入 `0 < x < 3` 档常规掷骰 ⇒ 在该档上估算**偏慢**。
3. **旋钮位置与调整方向已在权威处给出**（下调阈值、表结构不变），本表只是它的量化底稿。

→ `systems/balance.md`「账号级法则获取速率」。

## 理由

`systems/balance.md`：难度曲线按「老账号全开」校准而非「新账号裸奔」，因为战斗内法则**不可被针对且跨轮回单调累积**。这条校准要成立就必须有分母，而「池被取尽」这个分母对应约 74 次完整通关——它不是一个需要被校准的用户群。

两条偏差必须**一起写**，否则这张派生表会被当成单向上界引用。

落派生量而非配置表：它由残卷分档表机械推出，写成第四张表即制造第二权威，与本库「平衡资源按三问判据逐份切」（`decisions/ADR-0074-balance-resource-is-the-only-config-layer.md`）同源。

## 备选方案

- **补一个代理指标给 ≤ 25% 做机械校验** — 否决：两个百分比落纪律阶梯**第 4 级（零保证）**，「不为它补代理指标」已由 `decisions/ADR-0244-single-strength-gate-baseline-momentum.md` 定为纪律。
- **把速率写成第四张平衡配置表** — 否决：它是派生量，独立成表即第二权威。
- **按「池被取尽」取分母** — 否决：对应约 74 次完整通关，不是需要被校准的用户群。

## 后果

- 约束「≤ 25%」这条参考闸的读法：它在 `x ≈ 12` + 礼包 + 成就所得的分母上评审，不在取尽池上评审。
- **派生表待实测校准**：它建立在「生效概率取该档 `[Base, Cap]` 中值」这一个假设上，且分母取完整轮回。
- **成就组数尚未定** ⇒ `AchievementReward` 渠道的法则供给量未知，当前只能给出残卷 + 礼包两条的量。归内容阶段，本表其余部分不受它阻塞。
