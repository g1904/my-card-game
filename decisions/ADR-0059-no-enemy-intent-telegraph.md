# ADR-0059 — 敌人的行动不作任何事前预告；可读性改由六条既有通道分工承担

- **状态：** Accepted
- **日期：** 2026-08-15
- **来源：** handoffs/2026-08-15d-intent-removal-lifespan-cost-visibility-and-design-audit.md

## 背景

意图预告（敌人头顶显示「下回合将攻击 12 点」）是同类作品的标准做法，本作也曾设计过完整的一族：三档揭示 · `IntentCategory` 必填字段 · 快照语义 · 偏差解释 UX · 花代价换情报的探查通道。

它的代价逐渐显形：每个敌人内容条目多一个必填字段；快照语义要回答「预告后局面变了怎么办」；偏差解释要一整套 UX；而探查通道与「信息靠遭遇获得」这条取向正面冲突。

## 决策

**敌人的行动不作任何事前预告（承重）。** 本作**不设任何形式的意图预告**——不设揭示档位、不设行动类别标注与内容侧的对应必填字段、不生成回合级行动描述、不设「花代价换情报」的探查通道。

敌人回合的可读性改由**六条通道分工承担**：事中逐步执行反馈 · 敌人图鉴 · 战场 · 埋伏计数 · 敌人精确等级 · 道念对比。

权威 → `systems/adventure-event/combat/_index.md`；实现侧的连带 → `systems/services/combat-service.md`；呈现 → `ux/combat-ux.md`。

## 理由

六条通道**已经存在**，且它们分工覆盖了预告本来要解决的问题：事中反馈解决「刚才发生了什么」，图鉴解决「这个敌人会做什么」（事前，靠遭遇积累），道念对比解决「我现在是优是劣」。预告是第七条，且是唯一一条需要内容侧逐条目维护的。

**这条不要靠加一层预告去「改善可读性」**：玩家的可读通道另有其人。

## 备选方案

- **保留意图但只砍数值，恒定只给类别** — 否决：`IntentCategory` 必填字段的内容成本原样保留。
- **另设极简替代（敌人本回合将打出 N 张牌 / 手牌数可见）** — 否决：仍是预告，只是精度更低。
- **以显式状态标记（蓄力 / 凝聚 / 破绽）替代** — 否决：换了个名字的预告，且要一套新的状态词表。
- **只砍篇章分档、保留三档揭示** — 否决：分档本身就是内容成本的来源。

## 后果

- 本条**推翻 07-30b / 08-02c / 08-04b / 08-06d 四份 handoff 的整个意图族**。
- 三处承重论据被改挂：精确标注敌人等级 · 境界名展示 · `EncounterScopes` 共享池——它们原本以「配合意图预告」为理由，现各自独立成立。
- 敌人图鉴因此成为事前知识的主通道，其可查时机成为承重设计（→ `ADR-0094`）。
- 与「信息靠遭遇获得」这条支柱互为支撑（→ `ADR-0093`）。
