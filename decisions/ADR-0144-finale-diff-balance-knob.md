# ADR-0144 — 天劫的指派等级改为平衡资源上的旋钮 `FinaleDiff`

- **状态：** Accepted
- **日期：** 2026-09-05
- **来源：** handoffs/2026-09-05-finale-level-config.md

## 背景

`systems/balance.md` 自陈「校准 Finale 难度只有三条替代手段」，其中手段 ① 是「天劫的赋级带位置（`±2` 带内的权重偏移）」——而同一份文件另一处写「Finale 不掷骰（天劫是指派）」。**不掷骰就没有权重可偏移**：手段 ① 是一条死手段，实际可用只剩两条（定制卡组强度、`TurnLimit`），后者一动还要连带重估「12 回合是给 build 表达自己的窗口」那条论据。Finale 既是全作压迫顶点、又是篇章推进的唯一闸门，却是三档里校准余地最小的一档。

## 决策

**在 `EnemyLevelingData` 的既有行类型 `EnemyLevelRange` 上增一格 `FinaleDiff : int`，取代硬编码的 `+1`；物化 Finale 时以 `角色等级 + FinaleDiff` 得出天劫等级。存储形态是相对 `diff`，不是绝对等级。**

- 三章初值恒 `+1`，推导出的天劫等级仍是 14 / 18 / 22 —— **行为零变化、玩家侧零可感知、平衡侧零重算：装上旋钮，不拧它**；
- **取值域由加载期校验锁死**（三条新增校验，均 `PushError` + 抛，带篇章号与取值）：`1 <= FinaleDiff <= Upper`（**下界写常量 `1`、刻意不读 `Lower`**，上界读同一行的 `Upper`、不写字面量）· `该篇章末级 + FinaleDiff <= 22`（全局序上界）· 缺值 / 未赋值（读作 `0`）即违规；
- **通道不变**：Finale 本就是指派、不掷骰；`FinaleDiff` 不是传给赋级函数的区间覆盖参数，而是这条既有指派通道自己的取值来源；
- **Finale 的等级差自此是平衡面独占的旋钮**：`balance.md`「绝境感永远不由等级差表达」与 `combat/_index.md`「推论 ②」两句的作用域收窄为「**剧本 / 内容侧**不得用等级差表达 Finale 的特殊性」。

字段形态、三条校验与实际档位 → `systems/balance.md`；指派旁路 → `systems/services/future-event-service.md`。

## 理由

- **落点是推演不是选择**：平衡资源是本库唯一配置层（`decisions/ADR-0074-balance-resource-is-the-only-config-layer.md`），且 `FinaleDiff` 与同行 `Upper` 之间有跨字段不变式，按「有跨字段不变式的同住一份」判据不容拆成第二份资源。
- **相对形态而非绝对等级**：同行其余字段本就定义为「相对 `diff` 的闭区间 + 逐档权重」，塞一个绝对值是同页两义；绝对形态的校验须外借住在境界枚举里的「篇章末级」常量，而本库已否决跨文件不变式。相对形态下校验退化为纯本地断言。
- **下界恒 1**：`FinaleDiff = 0` 意味着天劫不越阶，「渡劫 = 突破到下一境界」的叙事随之破裂；**天劫必然越阶是承重的**，故下界与带的 `Lower` 无关——跟着 `Lower` 走会让一次带宽调整顺手把不越阶的天劫放进来。
- **作用域收窄不是网开一面**：依据是 `decisions/ADR-0077-encounter-tighten-increments.md` 的理由原话「Finale 是篇章的能力检查点，**它的难度必须由平衡面独占决定**；允许剧本加压等于让某些剧本线不可通关」。平衡资源正是「平衡面」，而被撞两句的上下文都指向剧本 / 内容侧。
- **`decisions/ADR-0044-enemy-leveling-band.md` 一字不动**：其「赋级函数不接受任何区间覆盖参数」逐字成立——旁路只绕过掷骰，不绕过带。
- **承重前提须写出**：角色进入 Finale 时**恒在本境界末级**，校验按「本境界末级」而非「角色当前等级」算，正因二者在 Finale 时刻恒相等。

## 备选方案

- **保持硬编码 `+1`** — 否决：手段 ① 永远是死手段，Finale 的校准余地只剩两条且互相牵连。
- **字段取绝对等级 `FinaleLevel`（14 / 18 / 22）** — 否决：与同行字段的相对语义构成同页两义，且校验须外借跨文件常量。
- **取值域取 `[末级 − 2, 末级 + 2]`** — 否决：下半段（天劫等级 ≤ 角色等级）与「天劫必然越阶」「渡劫 = 突破到下一境界」正面相抵。
- **扩成完整的绝对递增阶梯**（篇章内增设必经节点、等级出 `±2` 带、新增篇章计数器） — 本次不做：它需要订正 `decisions/ADR-0044-enemy-leveling-band.md`、重述 `decisions/ADR-0018-momentum-scoring-model.md` 的护栏、bump 存档 schema、新增内容条目并放宽 `eventPriority` 抬升判据；它解决的问题是否真实存在须由 ch1 可运行后的实测回答。本决策是它的严格子集，不构成阻碍。

## 后果

- **实际档位如实写下：ch1 `[14,15]` · ch2 `[18,19]` · ch3 `[22,22]`**。上界受 `Upper = +2` 与全局序 22 双重截断，**`FinaleDiff` 在第三篇章只有一个合法取值、旋钮不可拧**；ch3 的 Finale 校准仍只能走定制卡组强度与 `TurnLimit`。为 ch3 争取余量需要放宽 `±2` 带本身，那是一次要有实测数据支撑的独立决策。
- 明确不需要的：`CharacterProfile` 新字段 / 存档 schema bump · 存档迁移 · 新内容条目 · `eventPriority` 抬升清单变更 · 平衡数值重算 · `terminology.md` 登记（`FinaleDiff` 是代码标识符，非领域术语）。
- 因此必须这么写的文档：`systems/balance.md`（字段与代码块 · 档位表 · 三条新增校验 · 手段 ① 改述为「调本篇章的 `FinaleDiff`」·「绝境感不由等级差表达」的作用域收窄）· `systems/adventure-event/combat/_index.md`（赋级约束 · 推论 ① / ② · 退让位清单）· `systems/services/future-event-service.md`（赋级合法区间一节与十步管线伪码的赋级行）。
