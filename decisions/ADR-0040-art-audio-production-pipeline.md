# ADR-0040 — 美术 / 音频走三段流水线；设计库只承载 vision 与 guide，不承载生成产物

- **状态：** Accepted
- **日期：** 2026-08-04
- **来源：** handoffs/2026-08-04-art-audio-library-scaffold.md

## 背景

美术与音频资产需要一条可重复的产出路径，而本项目的资产将主要由生成工具产出。问题是：这条路径的哪几段归设计库、哪几段归代码库？若不定，二进制产物会漂进设计库，而 prompt 文本会漂进代码库。

## 决策

美术 / 音频资产走**三段流水线**：① 人给 vision + 参考 → ② AI 写 art / audio guide（结构化 prompt） → ③ 投喂生成工具。

**设计库承载 ① 与 ②**（vision 文本、参考素材登记、guide 文本）；**不承载 ③ 的产物**——二进制归 `game-feature-branch/`。

**动画不走这条流水线**（范围与技术载体待咨询专业人士后确定）。

分区结构与资产类目表 → `art/_index.md`。

## 理由

切分判据是「这份东西改动时，谁需要评审它」：vision 与 guide 是设计意图，改动要人看；二进制是产物，改动只需重新生成。把产物放进设计库会让每次重新生成都变成一次设计库提交，且 git 里堆满不可 diff 的大文件。

动画被排除是因为它的制作方式（逐帧 / 骨骼 / 程序化）尚无判断依据，把它塞进一条为静态资产设计的流水线是过早承诺。

## 备选方案

- **动画与 visuals / soundtracks 三分区并列** — 否决：归入 `visuals/` 之内，因为它尚不构成一条独立的流水线。
- **二进制入设计库** — 否决：见理由。

## 后果

- `art/` 下只有文本；任何 `.png` / `.wav` 出现在设计库都是违规。
- 音频生成工具**倾向 Suno 但未拍板**，且**工具专属语法不得写死进 guide 模板**——模板须保持工具中立。
- guide 是 prompt 的权威形态，条目产出后回填登记表，不回写 guide。
