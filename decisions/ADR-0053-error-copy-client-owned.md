# ADR-0053 — 玩家可见错误文案由客户端持有，键由后端 `code` 机械变换而来；后端 `message` 永不进弹窗

- **状态：** Accepted
- **日期：** 2026-08-12
- **来源：** handoffs/2026-08-12-error-copy-and-update-prompts.md

## 背景

后端会返回结构化错误（`code` + `message`）。最省事的做法是把 `message` 直接显示给玩家——但那意味着玩家可见文案的权威在后端，改一句话要发后端、且它不经过任何本地化通道。

## 决策

**玩家可见文案由客户端 UI 层持有**，键 = 后端 `code`，载体 = 翻译键。**后端 `message` 永不进玩家可见弹窗**（只进日志与客服溯源）。

**`code` → 翻译键是机械规则，不是第二张手写表**：`ERR_` 前缀 + `code` 全大写 + `.` 换 `_`。

三种终局态收敛为**一个阻塞屏 + 数据驱动的变体表**。

分区表、审计与变体表 → `ux/error-and-blocking-ux.md`。

## 理由

机械变换消灭了「维护一张 code → 文案对照表」这件事：新增一个 `code`，客户端只需补一行翻译，不需要改任何映射代码，也不可能出现「表里漏了一条」。手写表则必然漂移，且漏项的症状是玩家看到一个原始 code。

一个阻塞屏三变体而非三个屏，是因为三者的结构完全一致（一句说明 + 一个动作），差别只在文案与按钮——那是数据不是结构。

## 备选方案

- **服务返回已本地化串** — 否决（三条理由）：本地化权威跑到后端、无法随客户端语言切换、后端要知道客户端语言。
- **手写 `code → 文案` 对照表** — 否决：必然漏项，漏项即暴露原始 code。
- **迁移失败时提示重装 / 回退到云端上一个可用版本** — 否决：前者丢进度，后者与「绝不回退」冲突（→ `ADR-0032`）。

## 后果

- **推翻 07-27b 的「`OpResult.Detail` 携带面向玩家的原因串」**——`Detail` 只进日志。
- `ERR_*` 键**不得手写**，否则会与日后新增的后端 `code` 撞键；这条已写进 `.claude/rules/ui-input-rules.md`。
- 后端每新增一个 `code`，客户端就欠一行翻译；覆盖率由启动期审计报出（→ `ADR-0056`）。
