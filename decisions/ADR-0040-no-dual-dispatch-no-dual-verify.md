# ADR-0040 — 禁并发双发、同码转备用至多一次、禁双验

- **状态：** Accepted
- **日期：** 2026-09-06
- **来源：** handoffs/2026-09-06-external-provider-selection-dr.md · answer-logs/log-external-provider-selection-dr.md

## 背景

短信有两家供应商、实名核验按次计费。「同时发两家提高送达率」「同时验两家取一致结论」是很自然的直觉写法，但两者各自会带来重复计费与更坏的正确性后果。冗余度本身已由 `ADR-0039` 定，这里定的是**同一次请求能产生几次外部调用**。

## 决策

- **禁止并发双发**：同一个验证码不得同时发给两家。
- **允许「同码转备用」一次，且只在首家未返回受理 id 时**；若首家已返回 `providerMessageId`（已受理），不转备用。**一次 `challenge` 请求至多产生两次外部调用。**
- **禁止双验（实名核验）**：不得两家同时验一次。

见 `operations/external-providers.md`「灾备与切换」。

## 理由

并发双发双倍计费，且玩家收到两条一模一样的短信；其可用性收益仅覆盖「主供受理后静默不送达」这一小类失败，不值。

转备用之所以安全，关键性质是**验证码由本方生成**，因此重发同一个码是幂等的；这与 `ADR-0038` A4「适配层内不做应用层重试」不冲突——转备用是**换目标**，不是重试同一目标。

双验的问题不止于计费：两家结论不一致时**没有任何仲裁规则**，而这是一个直接决定「这个人是不是未成年」的判定。**一个没有仲裁规则的双源比单源更坏。**

## 备选方案

- 并发双发同一验证码到两家 — 双倍计费 + 玩家收到重复短信，顺序转备用已覆盖其余全部失败面。
- 两家实名核验并行、取一致结论 — 双倍计费，且结论不一致时无仲裁规则。

## 后果

- `resendAfterSeconds` 与验证码有效期由本方决定（码由本方生成），不受供应商形态影响。
- 实名核验的可用性只能靠单供的 SLA 与人工切换，这是被接受的代价。
- 一次 `challenge` 的外部调用次数上界为 2，可写成验收断言。
