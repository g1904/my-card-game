# ADR-0032 — 断线降级的总原则：绝不回退存档点；本地存档点与云端 push 解耦

- **状态：** Accepted
- **日期：** 2026-07-27
- **来源：** handoffs/2026-07-27-content-gating-offline-resilience-and-rng-persistence.md

## 背景

本作是强制在线、云端权威（→ `ADR-0003`）。但「云端权威」如果被直接实现成「以云端状态覆盖本地」，断线重连时就会把玩家刚打完的一场战斗抹掉——那不是解决冲突，那是丢进度。需要一条把两者分开的原则。

## 决策

**总原则：绝不回退存档点。** 「云端权威」解决的是**冲突**，不是**丢进度**。

据此把本地存档点与网络 push **解耦**：存档点到达时本地立即原子写入，push 走 5 秒防抖 + 两道缓冲闸门异步进行。网络不可用不阻塞玩法推进，也不使已到达的存档点失效。

完整的 push 调度、退避阶梯、`revision` CAS 与 `pushId` 幂等 → `systems/services/sync-service.md`。

## 理由

存档点是玩家已付出的时间的唯一凭证。任何会抹掉它的机制，代价都由玩家承担而收益归实现方（少写一段合并逻辑）。而冲突本身是稀有事件，为它设计的机制不应改变常态路径的语义。

解耦还有一个结构收益：本地写入是同步可验的（原子写 + 校验），网络写入是异步不可靠的，两者的失败语义完全不同，混在一起会得到一个既不能保证落盘也不能保证上行的中间态。

## 备选方案

- **断线时回退到上一个存档点** — 否决：抹掉玩家已完成的进度。
- **字节级断点续传** — 否决：负载本就小，续传机制的复杂度远超收益。
- **静默合并 / 字段级三路合并** — 否决：会产生玩家无从解释的中间状态。

## 后果

- `sync-service` 的失败语义一律是「延后重试」，从不是「回滚本地」。
- 存档点的定义（在哪些时刻落盘）因此成为承重设计，见 `ADR-0036`。
- 本地 `user://` 缓存的原子写只有一处实现（共享静态工具），→ `systems/services/account-service.md`。
