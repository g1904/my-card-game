# ADR-0062 — 内部运营工具面不属于契约面，`/internal/` 永不进端点全集表

- **状态：** Accepted
- **日期：** 2026-09-09
- **来源：** handoffs/2026-09-09-internal-ops-tools-and-operator-identity.md · answer-logs/log-internal-ops-tools.md

## 背景

内部运营工具面要开六个端点（昵称复核台三条 · 风控工单三条）。本库此前的端点只有一类——跨客户端边界的契约端点，它们全部登记在 `contracts/envelope.md` §3 的端点全集表里，而该表是**机检断言③的输入**（端点集 ⇔ 六份契约正文，双向）。新端点是否进这张表，必须先定。

## 决策

内部端点**不属于契约面**：路径前缀 **`/internal/`，不带 `/v1/`**，**不进 `envelope.md` §3 端点全集表、不进 `openapi.yaml`、不进 §6 错误码台账**；§3 表下只留一句非规范性说明（表本身不加行，守 P-3）。

内部端点**一律必带凭据，无例外**——§4a 无鉴权例外的判据主语是「玩家」，内部面不够格。

**复用序列化惯例，不复用契约机制**：JSON / lowerCamelCase / RFC 3339 `…AtUtc` / 不下发 `null` / 忽略未知字段 / 照带 `X-Request-Id` 照旧，但**不引入 `code` / `class` / `detail` 三段与错误码台账**。部署形态为**同一制品、同一进程、独立监听**，**仅 VPC 内可达（经堡垒机 / VPN）**。端点最小集与判定语义见 `operations/internal-tools.md`。

## 理由

- **判据是机检而非风格**：内部端点在六份客户端契约正文中永不出现 ⇒ 一旦登进 §3 表，断言③当场红灯。
- 客户端与后端唯一的耦合点是协议，`contracts/` 是它的单一事实来源；内部面不跨这条边界 ⇒ 契约的稳定性承诺（`/v1/` 主版本、并存两版）对它无意义——它与后端同一制品同批发布。
- `code` 的存在理由是「客户端据它分处置路径」，而内部面的读者是人 ⇒ 三段错误体与台账在此纯属成本。
- 不拆第四个部署单元：处置动作必须与 `account` 域写入同事务，拆进程即跨进程写同一张表，白白多一个故障域，且与「三处环境跑同一个 artifact」相抵。

## 备选方案

- **把内部端点登进 §3 端点全集表并写进 `openapi.yaml`** — 直接触发机检断言③红灯，且把不跨边界的面绑上契约的版本承诺。
- **扩写 §4a 无鉴权例外以容纳内部面** — 该判据的主语是玩家，扩写会削弱一条已成立的判据；内部面必带凭据本就无需例外。
- **内部面拆成独立部署单元** — 处置须与 `account` 域同事务，跨进程即多一个故障域。

## 后果

- `contracts/envelope.md` §3 表下的非规范性说明是这条决策在契约侧的唯一痕迹；**契约报文零改动**（不新增 `code`、`code` 全量枚举不变、§6 台账不增不减）。
- `operations/internal-tools.md` 承载端点最小集、认证形态与可见字段范围；`operations/deployment.md` 的「首次面向公众发行之前」清单承载接入通道与工具面的过闸。
- 内部端点不入 spec ⇒ 「契约变更的完成判据」六条与三条机检断言对它不适用，它的正确性由 `operations/internal-tools.md` 的服务端保证 I1–I10 承担。
- 客户端零影响：不跨边界、无 counterpart、`game-design-documents/` 侧无需同步。
