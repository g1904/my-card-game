# ADR-0055 — 第三方昵称审核首版不启用，且写死唯一启用触发条件

- **状态：** Accepted
- **日期：** 2026-09-07
- **来源：** handoffs/2026-09-07-compliance-launch-tiering.md · answer-logs/log-compliance-launch-tiering.md

## 背景

昵称判定链第④级（第三方内容审核适配器）此前是一个**悬而未决的默认**：`operations/moderation.md` 给出「首版不启用 · 透传恒放行」的形态，同句却自陈「是否启用取决于合规能力的上线分级」。这个未裁决的占位横切三份文档的验收面，且没有触发条件的留位会变成没有人会再想起来的空位。

## 决策

**判定链第④级首版不启用，实现为透传恒放行**（`ADR-0044` 的「不可达一律先接受」出口）。形态由「悬而未决的默认」升为**有触发器的默认**：

> **触发启用的唯一条件：渠道过审点名要求接入第三方内容审核能力。**

触发时以真实人工判定样本标定 `rejectThreshold` / `reviewThreshold`（服务商 × 环境维度），并登记进 `operations/moderation.md` 的数值初值表。**首版不定值**——形态与阈值位置已落笔，取值待触发后标定。

## 理由

依据链五条全部来自库内既有文本：

1. 昵称在本作**没有任何玩家间可见性**（`contracts/auth.md` §8）⇒ 残留风险面只剩合规抽查；
2. 抽查面已由本地词表两档分级 + T1/T2/T3 存量扫描 + 三档处置阶梯完整承接——**第④级是增强，不是承重**；
3. 启用需要一对以真实人工判定样本标定的阈值，首版无样本 ⇒ 启用即等于上一对未标定阈值，其误拒会以 `SensitiveWord` 误告玩家违规（`systems/account.md` N9 明令避免）；
4. 启用的边际成本明确且非零：一家服务商过 H1–H4 选型判据 · 一份独立审计线的凭据轮换（`ADR-0041`）· 同步路径上的玩家等待预算 · 一条要监控的曲线；
5. **后置成本 ≈ 0**，由 `ADR-0044`（待复核 / 不可达与未启用同出口）· `ADR-0038`（换 / 不接服务商是适配层内部的事）· `ADR-0015`（未知 `reasonKey` 回落一级键）三条共同担保——不改报文、不新增 `code`、不要求客户端发版。

## 备选方案

- **首版即启用** — 无标定样本，等于上一对拍脑袋阈值，误拒直接落到玩家身上。
- **留一个不带触发条件的开放留位**（改动前的形态）— 没有触发条件的留位无人会再想起来，且它作为「未裁决的占位」持续横切三处验收面。

## 后果

- `operations/moderation.md` 的适配器一节写明不启用理由与唯一触发条件；数值初值表该行填「**不定值**」并指回触发条件。
- `operations/external-providers.md` 的逐能力冗余度表把第三方昵称审核记为 **0（首版不启用）**，其阈值不进该文件的旋钮表。
- `vision/scope.md` 的 In scope 写明「第三方昵称审核适配器留位不启用」。
- 判定链第④级的性质由「未裁决的占位」变为「已裁决的未启用能力」；**是否据此收缩 `contracts/auth.md` / `systems/account.md` / `operations/moderation.md` 三处的 derive 排除面，由 `/assess-derive-readiness` 的下一次全量评估判定**，本决策不代判。
- 契约面零改动、报文零改动、客户端零承接项。
