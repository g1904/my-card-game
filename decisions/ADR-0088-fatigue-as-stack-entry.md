# ADR-0088 — 疲劳改为入栈的一等条目：可被监听、可被响应、可被削减至 0

- **状态：** Accepted
- **日期：** 2026-08-25
- **来源：** handoffs/2026-08-25-combat-presentation-and-action-result.md

## 背景

疲劳（抽牌堆空时每抽一张 −1 道念，→ `ADR-0052`）最初实现为**抽牌流程内的一次直接扣减**：不入栈、不产生结果对象。理由是它必须一定发生——若可被抹掉，对局可能永不终止。

但直接扣减使它无法被监听（没有效果能响应「对手疲劳了」），也在战报里无处可挂。

## 决策

**疲劳以一条栈条目结算，与触发式异能同形且完全一等**——**可被监听、可被响应、可被削减至 0**。

疲劳**不产生 `ActionResult`**（它不是玩家动作），但**照常广播一条 `CombatFeedEntry`**。

对局终止性由既有 **`EncounterSpec.TurnLimit` 封顶**承接，**不新增机制**。

→ `systems/services/combat-service.md`。

## 理由

**削减量走求值管线，不需要为疲劳开第二条通道。** 疲劳的扣减量与其余数值同经求值管线聚合得出（`ModifierTarget.FatigueAmount`），故「免疫下一次疲劳」写成一条 `ForTurns(1)` 的战场条目 + 一条把扣减量削到 0 的静止式修正即可，**零新增结构**。

**削减至 0 不会让对局不终止：回合上限是双方合计的硬护栏。** 削减疲劳只改变**失血曲线**，不改变**终止性**——`TurnLimit` 到了就是到了。**疲劳因此不需要「不可削减」这条特权**，而特权本身是要付代价的：它让疲劳成为规则体系里唯一一个不遵守栈语义的东西。

一等化的收益具体：应对疲劳的牌成为可设计的对象，战报里疲劳有条目，触发式异能可以监听它。

## 备选方案

- **疲劳不入栈、是抽牌流程内的直接扣减** — 否决：不可监听、战报无处挂。
- **疲劳量不可被任何效果削减** — 否决：`TurnLimit` 已封顶，削减只改失血曲线不改终止性。
- **为栈开第二个可寻址面**（恢复 `TargetKind.StackEntry`，或另立一套栈筛选结构，使栈上那条疲劳条目本身可被反制掉）— 否决：`EntryFilter` 是目标与作用域**共用的单一筛选结构**（`ADR-0062`），另立一套必然与它各自漂移；而反制类效果要有意义，玩家得在对手回合有响应窗口，那撞上「不借交互与优先权」（`ADR-0039`）。两条纪律同向指出不该给栈开第二个可寻址面，而它要买的那个例子（免疫下一次疲劳）已由求值管线免费覆盖。

## 后果

- **存档 schema 一格不加**：多的只是栈条目 `kind` 枚举的一个取值。
- `systems/adventure-event/combat/_index.md` 的规则层措辞仍读作「直接扣减」，规则权威在 `combat-service.md`——两处的口径差异应在下一次触及该文件时抹平。
- 疲劳规则本身（不重洗、每抽 −1 道念、扣减量为全局常量）不变。
