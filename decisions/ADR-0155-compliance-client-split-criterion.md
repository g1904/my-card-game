# ADR-0155 — 合规域的客户端切分判据：流程归 `ComplianceManager`，说明失败归发起屏

- **状态：** Accepted
- **日期：** 2026-09-03
- **来源：** handoffs/2026-09-03-compliance-client-surface.md

## 背景

后端合规域的六个端点与七条 `code` 已在对侧落笔完毕，边界这一侧要接住四件事：实名、防沉迷、账号注销、数据导出。客户端需要一个新部件承载它们，但**覆盖面若不先划清，`ComplianceManager` 会长成一个什么都往里塞的口袋**——一旦它开始「读年龄」「比时钟」「算时段」，客户端就有了一套本地合规判定，而合规的强制力本就在后端；两套判定不一致时，玩家会遇到本地拦住而服务端放行（或反之）。

同时，七条 `code` 的呈现该落哪里也没有答案；随手让它们落阻塞屏，就会造出第三处由 `code` 触发的硬阻塞。

## 决策

**合规域客户端切分判据一句话：凡需要「一段流程」（多于一次请求、或需要持有一个流程内凭据）的归 `ComplianceManager`；凡只是「把一次失败说清楚」的归发起它的那一屏。**

- **`ComplianceManager` 不做任何判定**——不读年龄、不比时钟、不算时段。四件明确不归它的事：任何判定 · 会话中途下线（`AuthManager` 既有路径）· 昵称合法性判定与提交 · 拦截错误的措辞选择。它的职责行写作「流程编排 + 呈现驱动」。
- 流程凭据**只在内存、绝不落盘、绝不出 API 面**；随凭据下发的过期时刻**读取即丢弃**，过期的唯一发现方式是拿去用一次。
- **一屏也不进阻塞屏**：四条拦截码落登录屏就地呈现 + 各一个主动作，三条端点码落发起它的那一屏内联呈现。
- 合规态查询**调用点唯一（`ComplianceManager`），排在会话到手之后、`SyncService.InitializeAsync` 之前**；失败按「可选缺失」降级。

覆盖面表、逐项落屏与失败映射 → `systems/services/account-service.md`；呈现与阻塞判据 → `ux/error-and-blocking-ux.md`。

## 理由

- **「一段流程」是唯一非任意的分界**：需要持有流程内凭据、跨多次请求的东西必须有一个进程内持有者；只需要把一次失败说清楚的东西，把它挪出发起屏只会让措辞与上下文分家。
- **不做判定 = 强制力留在后端**：客户端不做任何本地合规拦截，后端侧的兜底是存量扫描与复核通道。把强制改名升级成启动阻塞则需改写「阻塞点穷举」那条承重不变式，代价远高于收益。
- **七条 `code` 逐条核过阻塞屏变体表的两条准入判据（由已知 `code` 触发 **且** 玩家没有任何自愈路径），七条全部卡在后一条上**——准入若在此松动就会造出第三处由 `code` 触发的硬阻塞。
- **status 的调用时点不写作「`signin` 成功之后」**：静默续期那条路径根本不走 `signin`，照那个措辞写会让续期玩家永不取 status。落点复用 flags 刷新的先例（需鉴权 + 失败不阻塞）。
- **凭据不落盘**：落盘就造出一个「过期了还在生效」的本地状态，且它需要一份自己的失效口径——而那个口径恰恰是客户端不该自己判的（设备时钟不可信）。

## 备选方案

- **让合规拦截落阻塞屏变体表** — 否决：七条全部不满足「玩家没有任何自愈路径」这条准入，松动即造出第三处由 `code` 触发的硬阻塞。
- **把强制改名升级为启动硬阻塞** — 否决：需改写阻塞点穷举那条承重不变式；维持 fail-open，边界明写（见 `decisions/ADR-0138-nickname-change-is-flow-gate.md`）。
- **流程凭据落 `user://cache/`** — 否决：落盘后唯一正确的读法仍是「拿去试一次，失败就回登录屏」，与不落盘完全等价。
- **在 `systems/architecture.md` 开一张逐 `code` 表** — 否决：本库从无逐 `code` 表（只有 `class` 默认路径表），开一张只有合规三条的半张表会制造一份天生残缺、且与对侧台账重复的第二权威。

## 后果

- **总账零增量**：不新增硬阻塞 · 不动阻塞屏变体表 · 不增 `OpError` 成员（三条端点码全映 `OpError.Compliance`）· 不 bump 存档 schema · 不新增 `user://` 文件 · 不新开翻译分区 · 对后端零新增义务。
- **`ERR_*` 键全由 `code` 机械变换得出**，本库仍不持有任何 `reasonKey` 清单；逐 `code` 的跨边界台账权威在 `backend-design-documents/contracts/envelope.md`。
- 注销 / 导出落 PlayerProfile 屏（就地二段确认、冷静期提醒只在本屏内、主菜单零增量）；实名是登录流程内新增的一屏。
- 受约束的文档：`systems/services/account-service.md`（切分判据 · 覆盖面表 · 失败映射 · status 调用点）· `ux/error-and-blocking-ux.md`（七条的呈现形态）· `ux/screen-flow.md`（实名屏 + 落屏排布）· `systems/services/sync-service.md`（status 失败归入三条不变式③ 的第二形状）。
