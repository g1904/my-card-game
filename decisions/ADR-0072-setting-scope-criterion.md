# ADR-0072 — 设置项的账号级 / 设备本地切分判据 = 这一项的正确取值是否取决于这台机器

- **状态：** Accepted
- **日期：** 2026-08-19
- **来源：** handoffs/2026-08-19-game-setting-schema.md

## 背景

设置项有两个可能的归属：跟着账号走（换台手机也保留）或跟着设备走。音量该跟哪边？语言呢？没有判据时，每一项都要单独讨论，且讨论的结论不可复用到下一项。

## 决策

**一句话判据：这一项的正确取值是否取决于「这台机器」。** 取决于 → **设备本地**；纯粹是玩家的偏好、换台手机也应当跟着走 → **账号级**。

配套两条：**拿不准时归设备本地**；**一项设置只能落一侧**（不两侧各存一份）。

逐项归属、`SettingChanges` 通道与 `SettingFields` 配表 → `systems/player-profile/game-setting.md`。

## 理由

判据本身就是一个可自检的反问（「换台手机，这个值还对吗」），任何人对任何新设置项都能得出同一个答案。

**拿不准归设备本地**是因为两侧成本不对称：错判为设备本地的症状是「换手机要重设一次」（轻微、可自愈）；错判为账号级的症状是「一台机器的正确设置被同步到另一台不适用的机器」（例如把平板的字号同步到手机），而玩家无从理解为何自己没改过的设置变了。

一项只落一侧：两侧各存一份**正是「设置屏会长出两个开关」要防的形态**。

## 备选方案

- **两侧各存一份，按场景取用** — 否决：设置屏会长出两个开关。
- **一律账号级（同步一切）** — 否决：设备相关项被跨机同步，玩家无从理解。

## 后果

- 账号级四项（三条音量轨 `int [0,100]` + `FastCombatAnimation` `bool`）+ 设备本地一项（`locale`）。
- 三条音量轨默认值是**待实测初值**（相对关系有依据），不阻塞结构。
- 新增设置项时，先跑一遍反问，答案即落点。
