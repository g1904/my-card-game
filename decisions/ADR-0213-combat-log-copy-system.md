# ADR-0213 — 战报文案体系：飘字管量与归属、战报管事实与例外；省略来源名绝不省略增量

- **状态：** Accepted
- **日期：** 2026-09-08
- **来源：** handoffs/2026-09-08-combat-ui-elements.md · answer-logs/log-combat-ui-elements.md

## 背景

战报的两条硬要求——截断量必须被说明、目标落空必须被说明——在「单行 · 永不换行 · ≈ 屏高 6%」的约束下尚无任何可执行的表达形态。

## 决策

**分工判据：不读也不会错过的归飘字，不读就读不懂的归战报。**飘字 = 量与归属，取实际量，不表达因果与例外；战报 = 事实与例外，取标称 / 实际一对，不设延迟。

**收起态单行 = 结构化槽位 `[归属方] [动作动词] [来源名] · [增量]`。**

**省略顺序是一条规则：优先省略来源名，绝不省略增量。**

**截断与落空在单行内以符号标记表达**（非数字 · 单字宽 · 两枚互不相似 · 与飘字 `+N` / `−N` 不同源）；括注只在展开态，**不做说明浮层**。

**翻译键随 `CombatFeedKind` 成员机械对应，来源名不进翻译键**（`ux/error-and-blocking-ux.md`）。

## 理由

`ux/combat-ux.md`：实际量为 0 时飘字本就没有数字可飘——「削减被下限 0 全部吃掉」与「目标落空」在飘字上都表现为「什么也没有」，**而那正是两条硬要求要说明的那件事**。

省略顺序的依据：**增量是玩家推不出来的那一半**，来源名在展开态可查。

## 备选方案

- **收起态只写动作不写结果** — 否决：那把「第 3 回合我的道念为什么少了 3」这个战报存在的唯一理由整个推给展开态，**而玩家不会主动开日志**。
- **说明浮层** — 否决：无 hover 通道，且弹提示在连锁中是噪音。

## 后果

- 约束「单行 · 永不换行」下被省略的必须是括注而非增量。
- 放弃了收起态承载完整括注；**与飘字的冗余是刻意接受的**。
- 是 `decisions/ADR-0086-lifo-resolution-and-combat-log.md` 的文案体系补齐——那条定两视图 / 不上提为 `eventLog` / 不进存档，未定文案。
- 字段面权威（`Declared` / `Actual` / `FizzledSlots`）仍在 `systems/services/combat-service.md`。
