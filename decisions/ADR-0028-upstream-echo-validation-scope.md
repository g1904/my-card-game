# ADR-0028 — 上行整键回声校验升为通则；受约束顶层键由写入表机械导出

- **状态：** Accepted
- **日期：** 2026-08-22
- **来源：** handoffs/2026-08-22-echo-validation-scope-client-half.md

## 背景

上行 diff 的语义是「顶层键出现即整键替换」⇒ 客户端只要改动某顶层键内**自己写的那一半**，就必然把**后端写入的那一半**一并提交上去。`entitlement`（兑现时提交 `bundleGrantOrdinal`）此前已按特例定过；`accountInfo` 是同形的第二处，且它由**改昵称**触发——是每次都走一遍的常规路径，不是异常路径。两件事因此悬着：① 缺一份「哪些键受约束」的封闭登记，逐键临时判必然漏，而漏掉的那一处正是客户端可静默改写后端权威字段的口子；② 客户端侧**没有任何一处**在发出之前检查过这些值，全靠「组装代码恰好没碰它们」这条隐含假设。

## 决策

**把「上行时后端写入的字段只能原样回声」由 `entitlement` 一处特例升为通则。**

- **受约束顶层键由机械导出规则给出，不另建清单：** 某顶层键受约束 ⟺ 后端写入字段封闭表中存在一条以该键开头的 path ⇒ **当前恰为 `accountInfo` · `entitlement`**。日后写入表加一行，该键**自动**进入回声约束，不需要第二次决定。本库只在 `systems/player-profile/_index.md` 字段表的写入通道列登记「顶层键」这一层，逐条 path 回链后端契约、一字不复述。
- **组装规则：回声值的唯一来源是最近一次 pull 的权威快照**（`ProfileService` 内存态）。永不自行赋值、永不由本地历史推算、永不沿用上一次 push 的值、**不另存缓存文件**。`ProfileChangeSpec` 对这些路径不提供写入通道（无对应列 / `AllowedOps` 为空）。
- **回声路径不参与读档钳制、缺省补齐与格式归一化。** 缺失 → 该顶层键本次不进 diff + `PushError` + 触发一次 pull；越界 / 不合法 → 同上，**不钳制**；需归一化 → **不归一化**，按原值提交。客户端自己写的那一半照常钳制。
- **push 前自检落在 `ProfileSyncManager` 组装出口一处：** 不同 → 用快照值强制改写 + `PushError`（带 path / 快照值 / 组装值）+ **本批照常发出**。缺失分支不在此处理（组装期已剔键）。
- **新刚性：向受约束顶层键内的对象追加字段 = 两侧同批落笔的变更**，不适用「后端加字段零配合」。
- 连带订正：`BundleGrantOrdinal` 的读档 `< 0` 处置由「`PushWarning` + 钳制到 0」改为「`PushError` + 不进 diff + 触发 pull，不钳制」；「老档缺字段以默认值补齐」的口径在库内两处（`account-info.md` · `player-profile/_index.md`）一并松动为分路式。

六条落笔逐条与处置表 → `systems/services/sync-service.md`；校验规则、逐条 path、比较口径与拒绝语义的权威在 `backend-design-documents/contracts/profile-sync.md`。

## 理由

- **一条路径够格进后端写入表 ⟺ 它的真值只可能在服务端产生、客户端无其他通道取到它 ⟺ 客户端提交的任何值都只能是回声。** 机械导出不是巧合，是同一件事的两面；另建第二份清单则两份必然各自漂移，而漂移形态（某条路径进了写入表却没进回声清单）正是这条纪律要关掉的口子。
- **回声路径上做钳制 / 补默认 / 归一化会丢玩家进度。** 客户端拿一个自己造出来的值去回声 ⇒ 整批拒绝 ⇒ 按 `Conflict` 丢弃本地缓冲 ⇒ 丢进度，而症状完全指不向触发它的那次操作（「改一次昵称丢一场战斗」）。
- **把纪律抬进类型系统**：`ProfileChangeSpec` 不给写入通道，使「客户端改写后端字段」在跨服务代码里根本写不出来（可执行化阶梯第 1 级），与 `deviceId` 私有化同款手法。
- **自检不替代后端校验，它防的是客户端自己的 bug**——那才是这条路径上概率最高的失败源。且客户端无法从一次 `sync.conflict` 分辨「多设备」与「我改写了后端字段」（同码同处置），可观测性只能由本地自检承担。
- **「客户端侧不新增任何分支」约束的是收到 `Conflict` 之后，自检发生在发出之前**，两者不在同一层——本条不新增 `OpError` 取值、不新增 `SyncState` 值、不新增错误码映射行。
- **断言收敛到一处**，与「请求头组装与应答头解析收敛到 `src/Core/` 的一处」同构；让唯一出口同时承担缺失与不等两种处置会把它变成分叉点。

## 备选方案

- **维持 `entitlement` 单例、逐键临时判** — 必然漏，漏掉的那处就是静默改写后端权威字段的口子。
- **手工维护一份「受约束键」清单** — 与写入表两份各自漂移。
- **为回声值另存一份本地缓存** — 即第二权威，且它与快照的不一致无任何机制能发现。
- **自检失败即中止本批** — 正确值就在手边，玩家不该为一次客户端 bug 付出停滞或丢进度的代价。
- **把改昵称的失败窗口做成 UI 表现** — 需要一个翻译键与一行错误码映射，而本条明确不新增映射行。

## 后果

- **零 schema 影响、零迁移**：不增删任何字段，只改组装路径与读档处置；`sync-service.md` 的 bump 清单与老档补默认值列表不含 `accountInfo` 任何字段。
- **`AccountId` 须点明「不在后端写入封闭表内、不受回声约束」**——它写入方是后端却不在表内，读者按「后端写的都受约束」会导出一份多一行的错误清单。
- **本条与 `decisions/ADR-0003-online-cloud-authority.md` 同向并加强它**；`decisions/ADR-0023-premium-entitlement-and-redemption.md` 只讲「谁有权推进序号」与「客户端置位当场失败」，不含读档钳制与补默认值口径，不受影响。
- **⚠ 成对采纳尚未完成。** 后端契约半（`backend-design-documents/contracts/profile-sync.md` §5c 的受约束 path 恒等式、非整数路径的比较口径表；`contracts/envelope.md` §8 的指路句）**仍待落笔**，承接项已落 `backend-design-documents/open-questions/01-contracts.md`。在此之前 `contracts/profile-sync.md` §5c 明写的「`/accountInfo` 的比较口径尚未落笔 ⇒ 不得按字节相等实现」仍然有效；**客户端侧的「不得再加工」纪律在任何一种口径下都成立**，故本条不阻塞、也不预设口径。
- 与 `.claude/rules/state-save-rules.md` 相容：把回声路径的缺失从「静默补默认」抬为「`PushError` + 显式重取」，是该规则「缺失字段必须以清晰的错误 / 迁移处理」的更严实现。
