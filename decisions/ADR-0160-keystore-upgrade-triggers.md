# ADR-0160 — 平台密钥库升级：五条可机械判定的触发条件，且升级不引入平台分支

- **状态：** Accepted
- **日期：** 2026-09-02
- **来源：** handoffs/2026-09-02-platform-keystore-upgrade-triggers.md · answer-logs/log-platform-keystore-upgrade.md

## 背景

refresh token 明文落 `user://`，平台密钥库（Android Keystore / iOS Keychain）被记为**后置评估项**（`ADR-0080`）。但「后置」当时没有兑现物：**只写「日后评估」而不给可判定的触发条件，等于没有评估**——那种留口不会在某天被想起来，只会在下一次「看看还有什么没做」时被再次记为后置。

同时悬着第二个问题：四端（Android / iOS / 桌面 / Web）的凭据存储能力差异极大（Web 根本没有等价机制），升级是否必然把这条差异抬到 API 面上、制造一族平台分支。

## 决策

**一、升级触发条件穷举五条 T1–T5，每条都是可机械判定的事件。** 判据取两条轴——「明文的依据是否仍成立」与「升级的边际成本是否已被别的事付掉」。命中任一条 ⇒ 该评估从后置项转为**必须在当次同批裁决的工作项**：**裁决可以是「仍不升级」，但必须给出结论，不得再记为后置。** 配**四条明确不构成触发**的写法（「有空了」· root 设备占比统计 · 竞品做了 · 「安全总是好的」）。

**二、升级不引入平台分支。** 明文实现**不被移除**，它是四端共同的**缺省**；移动双端在插件可用时替换。判据是「**这一端有没有可用的凭据存储实现**」的**运行期一次探测**，不是「我在哪个平台」——因此服务 API 面、`Session`、六条失效路径、三条读写失败处置一格不动，**也不碰条件编译清单**。

**三、现在不预留 `ICredentialStore` 之类的抽象。**

四端能力矩阵、T1–T5 全表、四条非触发与「升级真发生时的落地形态」五条 → `systems/services/account-service.md`「refresh token 的持有与失效」。

## 理由

- **五条覆盖的是真正的分界线，不是时间点**：T1（后端 `auth.md` §4 的 rotation 与「窗口外重放即吊销全部会话」被改写）直接抽掉明文的全部辩护——它一动就不是「再评估」，是必须重做决定；T3（首次为移动端引入任何自有原生插件）把成本侧的否决理由消掉，因为当前成本的大头正是「为这一件事单独建一个插件工程」；T4 **不设阈值、>0 即触发**——已登记的残余风险实际发生了，本身就证伪了「风险被接受」这一判断。
- **能力差异不落在 API 面上，落在一处实现内**：落盘点已收敛为 `AuthManager` 私有的一处且无公开取值方法，升级 = 换掉这一处的读写实现。这与 `BackendSelector` 的「唯一选择点 + 换实现而非插 `if`」是同一条纪律的第二次应用。
- **Web / 桌面不是「降级分支」，而是同一个默认实现**——两端的升级收益是**零**而非「小」（桌面是威胁模型使然，Web 是机制缺失），为它们写分支买不到任何东西。
- **不预留抽象**：落盘点只有一处、只有一个实现、API 面已隔离，此刻抽接口正命中 `systems/architecture.md` 的抽象反判据；替换成本已经是最低的。

## 备选方案

- **在客户端自行加密后落明文文件** — 否决：密钥必须与密文同处一个可读位置，安全性提升为零，代价是一层假保障——**比明文更糟，因为它会让人以为已经处理过了**。
- **Web 端禁止持久化凭据、每次启动重登** — 否决：为它单开一条登录流即制造平台分支，且把一条可自愈的存储清空路径升级成常态摩擦。
- **T3 写成「必须升级」而非「必须给出结论」** — 否决：密钥库只消掉三条残余风险中的备份提取一条半，硬绑会把收益未变的事塞进最重的一批里。
- **把本条写进后端 `open-questions/cross-boundary.md`** — 否决：它不是待答问题而是已成立的下游依赖事实，写进待答清单会成为永不答结的僵尸条目。

## 后果

- **`ADR-0080` 后果段自陈的那条欠账就此闭合**——「后置」的兑现物（四端能力矩阵 · 五条触发 + 四条非触发 · 不引入平台分支）全部成文。
- **对侧留下反向登记**：`backend-design-documents/contracts/auth.md` §4 记一条「本节任一条被改写、削弱或取消 ⇒ 须同批触发客户端侧重评」，只回链不复述。
- **矩阵中三项平台能力事实带 `[待核实]`**（Godot 4.7 有无内置安全存储绑定 · Web 导出 `user://` 的持久化后端 · Android Keystore 密钥失效的具体异常），并入 `game-feature-branch/` 首次生成 `.csproj` 后的那一次实测批次 → `open-questions/05-service-contracts.md`。它们是事实待查，不影响本决定的形状。
- **升级真发生时存档 schema 零影响**（存的还是同一份 JSON 串），迁移 = 一次性搬迁；`AtomicJsonFile` 的调用方名单届时少一处，`systems/architecture.md` 那份写入方清单须在搬迁同批复核。
- 受约束的文档：`systems/services/account-service.md` · `decisions/ADR-0080-refresh-token-client-custody.md` · `backend-design-documents/contracts/auth.md`。
