# ADR-0153 — 单条神通的战斗内强度上沿：`baseMomentum` 比例刻度，不设合计总闸

- **状态：** Accepted
- **日期：** 2026-09-03
- **来源：** handoffs/2026-09-03-character-power-mechanics.md

## 背景

神通（`CharacterPower`）与法则（`PlayerPower`）同为 `CardType.Power` 入场，`systems/balance.md` 里已有一条法则的战斗内上沿（净贡献 / `baseMomentum` ≤ 10%，外加一道合计总闸）。问题是：这套约束**该不该覆盖神通**。

若照搬，神通就成了 build 三件套（卡组 / 法宝 / 神通）里最不值得关注的那一件——用一档为「跨轮回单调累积」设的约束去框一个每局从零起的东西。若什么都不写，神通就是全库唯一一族**没有强度上界**的战斗内内容，而它恰恰没有任何节流阀（见 `decisions/ADR-0152-cross-carrier-boundary-criterion.md`）。

## 决策

**单条神通的战斗内强度上沿取 `baseMomentum` 比例刻度：单条神通的道念净贡献 / 本方 `baseMomentum` ≤ X%，X 显著高于法则的 10%。X 属【待内容】，随第一批条目与 ch1 平衡打磨定出。**

**不设合计总闸。** 一局内的持有量由内容侧的获取频次承担。

刻度、逐条依据与前置依赖住 `systems/balance.md`「神通的战斗内强度刻度」；定性面在 `systems/character-profile/power/_index.md` 留回链。

## 理由

- **取同一把刻度、不同的一档值**：`baseMomentum` 是既定的战斗强度主刻度，神通与法则因此可并排比较；另立一把刻度会让两族的强度无法互相对账。
- **法则「轻度提升」这个定位的三条成因，神通一条都不成立**——它跨轮回单调累积 / 不可被针对 / 须按老账号全开校准，而神通随轮回清理、可被禁用或置换、每局从零起。
- **合计总闸正是为那三条不成立的前提而设的**：再压一道合计闸，只是把一个不存在的失控路径写进文档。
- **「先定形状、后定数值」是承重纪律**：只留一行占位与 `systems/balance.md` 现有「留待校准」项的通行形态相抵——那些项无一是纯占位，每一条都写明刻度与前置依赖。

## 备选方案

- **神通沿用法则的 10% 上沿与合计总闸** — 否决：用为「累积且不可被针对」设的档位去框一个不累积、可被针对的东西，会让神通在 build 三件套里成为最不值得关注的一件。
- **`balance.md` 只留一行占位、不给刻度** — 否决：与「先定形状、后定数值」相抵；不给刻度则内容侧无从判断「一条神通多强算过」。
- **给神通另立一把独立刻度** — 否决：两族即失去可并排比较的公共分母。

## 后果

- **法则那条「ch1 前段只能是纯信息 / 便利类、道念贡献为 0」不适用于神通**（起手绑定神通本就是 ch1 第一分钟就在手里的东西），须在 `systems/balance.md` 明写例外。
- **「不得随对局延长而累积」照搬且更硬**——神通没有任何配额闸；可机械化的那一半落成加载期 `PushWarning`，见 `systems/character-profile/power/_index.md`。
- **X 的定案被三格互相咬合的定量项阻塞**（一次轮回预期获得几条 · 单条相对同 `ManaCost` 法术的效果量系数 · 各 `RarityTier` 档的条目数），均需 starter deck 与功法条目规模先落地才有分母 → `open-questions.md`。
- 受约束的文档：`systems/balance.md`（刻度本体 + 不设总闸 + 前置依赖）· `systems/character-profile/power/_index.md`（定性面 + 回链）。
