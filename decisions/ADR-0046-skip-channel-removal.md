# ADR-0046 — 跳过通道整体移除：一批 eventOptions 只有一次操作——择一进入

- **状态：** Accepted
- **日期：** 2026-08-06
- **来源：** handoffs/2026-08-06c-skip-channel-removal-priority-two-tier-and-location-codex-edges.md

## 背景

07-25b 引入、07-26 与 08-05b 逐步充实了一整条跳过设计：`skipCost`（跳过要付的代价）、`ifMandatory`（这批能不能被跳过）、`TryRefill`（跳过后补充新批次），外加两条产出侧保证。它给玩家一条「都不喜欢就都不选」的出口。

问题是这条出口把每一批的决策从「选哪个」变成「选哪个或者不选」，而后者在绝大多数情形下有一个显然最优解（付得起就跳过烂批次），使批次内的权衡失去意义。

## 决策

**跳过通道整体移除。** 删除 `skipCost` / `ifMandatory` / `TryRefill` 三个字段与配套机制。

**一批 eventOptions 只有一次操作：择一进入。没有跳过通道（承重）。**

批次形态与物化字段 → `systems/adventure-event/common-properties.md`。

## 理由

保留跳过就必须给它定价，而定价一旦偏低就是恒定最优解、偏高就从不使用——中间没有稳定区间。移除它使每一批都成为真实的取舍：三个都不理想时，你仍然要选一个。

这也是「明知是死路仍然走」这条承重取向的前提（→ `ADR-0031`）：有跳过通道时，玩家永远可以花钱绕开死路。

## 备选方案

- **保留 `skipCost` 的降级形态（免费跳过 / 每篇章限次）** — 否决：免费即恒定最优；限次是又一个待平衡的数，且需新存档字段。

## 后果

- 三个字段与 `TryRefill` 整条机制作废；`eventPriority` 成为选择约束的**唯一**一条轴（→ `ADR-0047`）。
- 死局兜底改由 Travel 承担（→ `ADR-0043`），因为不再有「跳过」这条逃生口。
- 候选短缺的处置因此只能是「给几条算几条」的降级，不能是「这批作废重来」（→ `ADR-0073`）。
