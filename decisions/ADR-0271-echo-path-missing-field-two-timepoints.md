# ADR-0271 — 回声路径「老档缺字段」分两个时点处置：迁移时点写空列表，迁移之后的读档时点即真异常

- **状态：** Accepted
- **日期：** 2026-09-12
- **来源：** handoffs/2026-09-12-premium-character-series-unlock.md · answer-logs/log-premium-character-series-unlock.md

## 背景

回声路径有一条通则：**不参与读档钳制、缺省补齐与格式归一化** —— 客户端一旦替云端造值，回声比对就会在正常账号上稳定失败。但一次真实 `schemaVersion` bump 的迁移器**必须**给新字段一个初始值，否则搬运出来的档是残缺的。两条纪律看上去正面相撞，而 `Cosmetic` 与 `CharacterSeries` 两格都会撞上它。

## 决策

**「老档缺字段」拆成两个时点，口径不同：**

- **迁移时点**（一次真实 bump 的迁移器）：**写入空列表**。迁移是结构搬运，不是「客户端造一个值去回声」。
- **迁移之后的读档时点**：该格缺失即**真异常**，按回声路径的必需缺失处置（`PushError` + 该顶层键本次不进 diff + 触发一次 pull），**不补默认值**。

首次 pull 立即带回权威值 ⇒ **空列表的存活期以一次往返计**。

**本条对 `Cosmetic` 与 `CharacterSeries` 两格逐字同款适用**，不逐付费点各推演一遍。

口径原文与落位见 `systems/player-profile/_index.md`（**本 ADR 不复述**）。

## 理由

`systems/player-profile/_index.md`：两个时点的性质本就不同 —— 迁移器跑在**已知的结构变更**上下文里，它知道这一格刚被引入、云端也刚开始写它；而迁移之后的读档没有这层上下文，缺失只可能来自损坏或版本错配，此时补一个默认值等于用一个伪造值去参与回声比对。

空列表的存活期以一次往返计，是这条切分成立的关键：迁移写下的那个值**不是权威值，也不打算是** —— 它只需活到首次 pull。

## 备选方案

- **迁移时点也不补值、直接走必需缺失处置** — 否决：迁移器的产物会是一份结构残缺的档，且每次启动都触发一轮 `PushError` + pull。
- **读档时点也补空列表** — 否决：客户端替云端造值，回声比对将在损坏档上静默"修复"而掩盖真实故障。
- **逐付费点各推演一遍** — 否决：同一条形态问题重复裁决，两份口径必然漂移。

## 后果

- 该口径是 `systems/services/profile-schema-versions.md` v2 行「迁移器写入空列表 / 迁移之后按回声路径必需缺失处置」那一格的依据。
- 日后任何新增的受回声约束的顶层键内字段，**直接套用本条**，不再单独出题。
- 与 `decisions/ADR-0028-upstream-echo-validation-scope.md` 的整键回声通则并行不悖：本条只切「缺字段」这一情形的时点，不动回声比对本身的范围。
