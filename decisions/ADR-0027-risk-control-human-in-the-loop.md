# ADR-0027 — 风控自动处置止步于观察与工单，并配全局熔断

- **状态：** Accepted
- **日期：** 2026-09-03
- **来源：** `handoffs/2026-09-03-nickname-moderation-and-risk-control.md` · `answer-logs/log-nickname-moderation-and-risk-control.md`

## 背景

`ADR-0005` 定了「复算不一致仅记账不拒绝」，`ADR-0008` 定了「回声不等即整批拒绝」——两者都会持续产出风控事件。事件有了，就要回答两件事：这套东西是不是第四个后端服务，以及自动化能走到哪一步（自动封禁 vs 生成工单）。

## 决策

**风控取轻量档：事件产出在 `account` / `profile-store` 内部旁路，绝不在同步热路径上裁决；自动化止步于「观察」与「生成工单」，`restricted` / `banned` 一律需人工确认；并配一条全局熔断。**

- **全局熔断（承重）**：同一 `appVersion` / `contentVersion` 分组内，`RollMismatch` 触发率 > **1%** 账号，或 `EchoRejected` > **0.5%** 账号 ⇒ **一律判为我方实现缺陷，立即暂停该分组的一切自动处置并告警。**
- **一张统一事件字段表**同时装下回声校验与越界记账两组已具名字段，不另立两套；`expected` / `actual` 一律字符串序列化。
- **复算不一致率与「本地领先」两条线上探针由本事件流聚合得出，不另建第二条采集路径。**
- 阈值表、数值初值与分档 → `operations/moderation.md`；产出点 → `systems/account.md` · `contracts/profile-sync.md` §5c §7a。

## 理由

**`status` 变更连带吊销全部会话——一次误判 = 一次强制下线，撞 pillar #4。** 且全局熔断的存在本身就意味着**必须有人在回路里**判断「这是作弊还是我方 bug」（`operations/moderation.md`）。

**1% 这个数是从游戏形态推出来的，不是凭感觉取的**：单人游戏、无玩家间交互、作弊收益是「每篇章至多一次的低价值掉落」——真实作弊渗透率不可能达到 1%，故 1% 是「这是 bug」的强信号，不是「这是作弊潮」。`EchoRejected` 取更低的 0.5%，因为它的误报**当场丢玩家进度**。熔断防的正是最坏那一类事故：后端复算差一位或客户端一次发版 bug ⇒ 大批正常玩家被限制。

**两条采集路径必然漂移，而漂移时没有任何机制会报错**——故探针复用同一条事件流。

`expected` / `actual` 走字符串是因为它们可能是 `ulong`：用原生 JSON 数值类型会在超 `2^53` 时**静默丢低位**（`envelope.md` §2 同一条判据）。

## 备选方案

- **建独立风控服务（第四个后端服务）** — 与轻量档的收益不成比例；事件产出本就在两个既有服务内部，旁路即可。
- **自动封禁** — 一次我方实现缺陷会被放大为全量误封，而 `status` 变更连带强制下线。
- **回声校验与越界记账各立一套事件表** — 一张统一字段表已装下两组已具名字段。
- **`expected` / `actual` 用原生 JSON 数值类型** — `ulong` 超 `2^53` 时静默丢低位。
- **为复算不一致率另建第二条采集路径** — 两条路径必然漂移，且漂移时无任何机制会报错。
- **不设熔断，只靠阈值分档** — 阈值分档判的是单账号，判不出「整批玩家同时异常」这一类我方缺陷。

## 后果

- **人必须在回路里**：`restricted` / `banned` 永远需要人工确认，运营流程因此有一条不可省的人工环节。这是被接受的运营成本。
- 风控**不进同步热路径**：push 的应答不等待事件落盘 ⇒ `profile-sync.md` §5c / §7a 的风控事件只影响可观测性，**不改任何报文面**。
- 熔断按 `appVersion` / `contentVersion` 分组 ⇒ 部署侧必须能按这两个维度切分事件流 → `operations/observability.md`。
- 阈值（1% / 0.5% / 各档累计窗口）全部**待实测校准，落后端配置**，改值不发版；它们是旋钮，不是本决策的承重部分。
- **`pushId` 去重命中率不是风控事件**（弱网下去重命中是常态），透明路径缺失告警同理走告警台账——两者都不进事件流。
- 本条与 `ADR-0005` 同源但不同域：那条定「不一致不拒绝」，本条定「不一致之后由谁拍板」。
