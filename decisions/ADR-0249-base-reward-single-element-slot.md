# ADR-0249 — `BaseReward` 的默认 element 面 = 灵石一格，其余恒空

- **状态：** Accepted
- **日期：** 2026-09-09
- **来源：** handoffs/2026-09-09f-event-reward-and-hidden-stat-orchestration.md

## 背景

`BaseReward`（战斗必得的那一半奖励）的三档相对分量已定，但「除灵石之外还给多少别的 element」一直挂着，读起来像一个待填的数字。

## 决策

**`BaseReward` 的默认 element 面 = 灵石一格；其余 element 恒空。** 这不是一个待填的数字，是**结构上没有第二格**。

**唯一的例外是少数条目的额外惩罚**——它是 `Spoils` 内的负向 `ChangeElement`，属**逐条目编排**，不是档位默认值。

→ `systems/balance.md`。

## 理由

逐条排除，每一条都由既有定案给出：

- **仙玉**走稀有事件通道，不是战斗产出（→ `ADR-0134`）；
- **经验**在模板侧有独立的书写位，再装一份即与「物化后可出现的 key ≠ 模板可声明的 key」相抵；
- **回寿**只走 outcome 侧的三条通道（→ `ADR-0066`）；
- **`ManaLimit`** 量值恒 1，由 outcome 侧展开；
- **四族内容**走 `RewardPoolId`（→ `ADR-0241`）。

## 备选方案

- **给 `BaseReward` 开第二个默认 element 格** — 否决：每一个候选 key 都已有自己的通道，第二格只会制造双通道。

## 后果

- 「`BaseReward` 其余 element 的量」这条待答项**永久关闭**，不再是取值缺口。
- 逐条目的额外惩罚仍可写，但它落 `Spoils` 的负向 `ChangeElement`，**不得被读成档位默认值**。
- `BaseReward` 的三档相对分量（`0.5 / 1.0 / 2.0 × S(c)`）**不重估**——它被「篇章缩放落在给多少、不落定价表」与「货币产出与定价表是同一次反推的三个输出」两条同时钉住，动它要连带重算定价表与双币经济曲线。
