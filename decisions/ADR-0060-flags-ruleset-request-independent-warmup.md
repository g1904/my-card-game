# ADR-0060 — flags 规则集的装载必须有请求无关的触发

- **状态：** Accepted
- **日期：** 2026-09-08
- **来源：** handoffs/2026-09-08-flags-service-internal-doc-home.md · answer-logs/log-flags-service-internal-doc-home.md

## 背景

`ADR-0047` 把 `X-Flags-Version` 钉成 `min(高水位, 本实例可兑现的最大版本)`（头永不领先），而客户端对该头「等值不拉」。若实例侧的规则集装载纯粹由请求驱动（懒加载），两条纪律合成一个自锁：

```
实例未装载新版本 → 它下发的头不涨 → 客户端不拉 flags → 该实例收不到 flags GET → 永不装载
```

集群内每个实例都懒加载时，一次 `publish` 可能**对全体设备永不生效**；而传播窗口 T 的探针（实例间 gauge 极差 ≠ 0 且持续超 T）**发现不了**——极差恒为 0，全体一致地卡在旧版本。

## 决策

**装载必须有一个请求无关的触发**：实例侧的当前版本读取缓存每次刷新（TTL 5 秒）发现高水位更大时，**主动装载该版本的规则集**；装载成功之后，本实例可兑现的最大版本才随之抬高。

配套的观测缺口同批堵上：`operations/observability.md` 增一条断言——**`高水位 − 本实例可兑现的最大版本` 持续 > T 即告警**，取数面仍是既有那个 gauge，零新增机制。

形态见 `systems/content-delivery.md`「版本预热：装载的触发面」。

## 理由

- 「头永不领先」（`ADR-0047`）与客户端「等值不拉」都不打算放弃，自锁只能从装载触发面这一侧解开。
- 预热**不破坏**「头永不领先」：抬高本实例可兑现版本的动作发生在装载**成功之后**，顺序与该纪律同向。
- 成本 = 实例数 × 每次发布一次回源，可忽略。
- 现有告警只看实例间极差，看不见「全体一致地落后」——那正是缺少请求无关触发时的**唯一**表现形态，因此这条断言与预热必须同批落笔，否则该失败面零信号。

## 备选方案

- **纯请求驱动的懒加载**（改动前的读法）— 与「头永不领先」合成自锁，且极差探针发现不了。
- **放宽「头永不领先」，让头直接跟随高水位** — 会让客户端拉到本实例尚不能兑现的版本，正是 `ADR-0047` 要堵的误报方向。
- **只加告警、不加预热触发** — 把一个结构性必然发生的自锁降级成靠人值守发现。

## 后果

- `systems/content-delivery.md` 的服务内部纪律含「装载有请求无关的触发」一条；`operations/observability.md` 多一条告警断言（与既有极差探针互补）。
- **契约面零改动**：`contracts/content-manifest.md` 不动、报文不动、`flagsSchema` 不提升；`ADR-0047` / `ADR-0009` 的决策本体一字不动。
- 客户端承接义务：零。
