# ADR-0016 — 隐藏属性档位模型：一张档位表统一三个消费方，叙事挂档位不挂事件

- **状态：** Accepted
- **日期：** 2026-08-12
- **来源：** handoffs/2026-08-12d-hidden-stat-bands-and-crossing-narrative.md

## 背景

两个隐藏属性（道心 / 煞气）此前有两套彼此独立的说法：「达阈值触发剧情线」与「跨档给定性叙事反馈」。同时数值必须保持隐藏——玩家该学到方向与因果，学不到精确数值，否则可以做电子表格式优化。落地时要回答：档分几档、叙事挂在哪、档位存不存。

## 决策

**① 一套档位模型统一三个消费方。** 「跨过一个隐藏档位」与「达阈值触发剧情线」**是同一件事**：剧情线触发 = 跨入某个带 `PlotTriggerId` 的档。一张表同时回答 eventOptions 调制（用全部档，**这是档位表存在的首要理由**）· 剧情线触发（2 档）· 跨档叙事文案（2 档）。

**② 档数与取值域：道心 5 档（`[0,100]`，起始 50，带符号档号 −2…+2）· 煞气 4 档（`[0,100]`，起始 0）**，共 9 档。**`BandIndex` 的方向定义 = 离常态的距离**，故触发规则对两个属性、两条臂一致：`|newBand| > |oldBand|` 才播，反向静默。

**②b 本模型的管辖对象只有道心与煞气。寿元不在其内**——它是一条**明文资源**：余量、`selectCost` 与回寿数字一律恒精确展示，没有档、没有 band 字段、不触发任何 `PlotTriggerId`。语义与呈现的权威在 `systems/character-profile/life-span.md`。

**③ 跨档叙事文案挂档位、不挂事件；走内容层；只挂极值档**（全库有文案的档共 2 个：道心 `+2` · 煞气 `3`；道心下臂 `−2` 是明写例外）。每档 2–3 条候选、等概率随机取一、随机源不带种子。

**④ 档位是内容条目 `HiddenStatBandData : Resource`，恒启用；阈值 / δ / 文案可线上改，档数不可线上增减。**

**⑤ 每档带回滞 δ**（退出阈值 = 进入阈值向常态方向放宽 δ；初值：道心 / 煞气 = 4），代价是**必须持久化当前所处档**（`CharacterProfile.Status` 上的两个 band 字段）。

档位表逐行取值、加载期校验表与三个消费方的完整口径见 `systems/services/plot-manager.md`。

## 理由

- **一张表三个消费方，不需要三套判定**——两套说法本就是同一件事的两种措辞。
- **9 档的分辨率有真实消费者**：调制的作用面是全覆盖的（五类事件无一例外都可能推拉隐藏属性），故这个分辨率是真实的，不是先于内容而定的空结构。**档多 ≠ 文案多**——玩家感知「这条线在动」主要来自摆在面前的事件变了，而不是一句旁白；砍中间档等于砍掉调制的分辨率，是拿主业去迁就点缀。
- **挂事件是组合爆炸**（一章 30 事件 × 2 属性 × 2 方向 = 120 条），内容侧不可维护；且挂事件会泄露「事件 → 属性」的精确映射，与「学到方向与因果、学不到精确数值」的边界擦得太近。**这两条各自已经足以定案，不依赖任何先例**（同类落点另有一例：Finale 的渡劫身死文案同样挂在状态转换上）。
- **只挂极值档**：本作是卡牌构筑游戏不是视觉小说，叙事是点缀不是载体；因果的主要载体是事件文案本身，中间档的旁白是重复信息，只会稀释极值那一条的分量；且**题材常识已经填上中间档**——道心低了会入魔、煞气高了会反噬，这些不需要本作教。
- **取值域有界**：无界属性的档位只能靠不断加新档追赶，而档位是内容条目、overlay 只改不增 ⇒ 加档必须发版。有界 + 顶档吸收溢出，使档数在整条内容生命周期里是常量。
- **档号取「离常态的距离」而非「数值大小」**：否则「下行不播」会字面废掉道心下臂的跨档（心魔滋生本身就是数值下降触发的），而它与上臂在「离常态」这条轴上同向；如此不必为任何一臂开特例、不必加方向字段。
- **回滞不可省**：没有它，一个在阈值上反复 ±3 震荡的道心值会把「稀缺才有分量」直接毁掉。回滞与「下行不播」各管一半——后者挡「上去又下来又上去」里的下来那一次，前者挡在同一条阈值线上反复上行。
- **档位条目恒启用**：它是被**查表读取**的结构，不是抽取池成员；关掉一档会在档位表上造出空洞、触发假跨档，`BandIndex` 连续性校验随之失去意义。

## 备选方案

- **剧情线阈值与叙事档位各设一套** — 否决：同一件事的两套判定。
- **叙事文案挂在触发它的事件上** — 否决：组合爆炸 + 泄露精确映射。
- **为「文案太少」而减档** — 否决：砍中间档 = 砍调制分辨率；解耦后两者各调各的。**这条禁令的射程是「不得为文案密度 / 调制手感而减档」**——某个属性**整体退出隐藏属性体系**而带来的档数减少不在此列，那不是拿档数当旋钮，而是管辖对象少了一个。
- **隐藏属性取无界值域** — 否决：加档必须发版。
- **两个方向各排一套无符号档号 + 一个方向字段** — 否决：多一层映射，且给「方向字段与档号不一致」这种坏状态留位置。

## 后果

- 新增存档结构**仅一处**：`CharacterProfile.Status` 上的两个 band 字段（回滞的代价）。
- 长出一条可机械检查的内容纪律：**只有极值档允许配 `NarrativeIds`**，其余档配了 → 加载期 `PushWarning`；**文案正文含属性名 / 阿拉伯数字 / 档位序号 → `PushWarning`**（「不给数字」纪律的机械形态）。
- **overlay 改阈值后的对齐**：热更后首次 `eventEnd` 若存档 band 与新阈值算出的档不符 → 直接对齐、不播叙事、`PushWarning` 留痕，否则一次数值热更会给全体在线玩家批量假跨档。
- 明写的取舍：**中间档的跨越对玩家完全无提示**——调制才是隐藏属性的主要显影通道，旁白只是极值时刻的一次强调。日后若嫌闷，退让顺序为煞气 Band 2 → 道心 `+1` → 道心下臂，**每一步只是加内容条目，结构 / 字段 / schema 全不动；档数永远不是该动的旋钮**。**跨档叙事是里程碑不是计时器**——它只在玩家把某条线推到极端时响一次，日常的「这条线在动」由调制承担。
- 影响文档：`systems/services/plot-manager.md`（权威）· `systems/character-profile/_index.md`（两个 band 字段）· `systems/balance.md`（`HiddenStatGrade` 映射值）· `ux/screen-flow.md`（跨档叙事的呈现形态）。
