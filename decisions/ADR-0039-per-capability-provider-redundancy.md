# ADR-0039 — 供应商冗余度逐能力判定：只有短信双供，且只有短信有自动切换

- **状态：** Accepted
- **日期：** 2026-09-06
- **来源：** handoffs/2026-09-06-external-provider-selection-dr.md · answer-logs/log-external-provider-selection-dr.md

## 背景

四类外接能力都可能停摆。一刀切上双供会为每一类都付出一份凭据轮换、一次模板报备与一条要监控的曲线；一刀切单供则会在某一类停摆时让一半玩家完全进不来。

## 决策

冗余度按「**这个能力停摆，玩家会怎样**」逐能力判定，不一刀切。首版：**短信 2 家 · 邮件 0 家 · 实名核验 1 家 · 昵称审核 0 家**；**自动降级与回切只对短信**（滑动窗口失败率或连续失败触发降级，主供探测达标且冷却满足后回切）。

**明确拒绝不计入降级触发判据**；**备用供应商必须持续保持「可用」而非「可接入」**。

判据表、切换阈值与可观测性增量见 `operations/external-providers.md`；旋钮登记见 `operations/environments.md`。

## 理由

短信是唯一「外部停摆 = 一半玩家完全进不来」的能力：`Phone` 渠道玩家全体无法登录，且他们**无法改走 `WeChat`**——那会建出第二个账号，而 `contracts/auth.md` §1a 明禁隐式账号合并（`ADR-0010`）。

把明确拒绝计进触发判据，一批脏号码就能触发一次假降级。备用家若只是「可接入」，降级当天才会发现它的模板报备已过期。

## 备选方案

- 首版只接一家短信、靠人工快速切换 — 无人值守时段等于停摆数小时，而后果是该渠道玩家全体无法登录且无替代登录路径。
- 首版即为 `Email` 选型并接入 — 该渠道首版返回 `auth.channel_rejected`、零调用面；接入即产生一份要轮换的凭据、一次模板报备与一条要监控的曲线，全是负债。
- 四类一律双供 — 为零调用面或低后果的能力付同样的常驻成本。

## 后果

- 只有短信这一条路径存在自动切换逻辑与回切冷却，其余三类的故障处置是人工。
- 服务商选型本身不在设计库内点名——那是商业决定；本库只写判据与冗余度。
- 「禁止并发双发 / 禁止双验」是另一条轴上的约束，见 `ADR-0040`。
