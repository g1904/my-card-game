# ADR-0258 — 多灵根角色走免费轨道；卡池区分 = 复合功法 + 数量上限双机制组合

- **状态：** Accepted
- **日期：** 2026-09-10
- **来源：** handoffs/2026-09-10-character-series-identity-and-monetization.md · answer-logs/log-character-technique-identity.md

## 背景

首批五角全是单灵根，`Affinities` 长度恒为 1。多灵根角色一旦引入，宽池角色**只有加法没有减法**——它能修的功法是单灵根角色的超集，辨识度与强度对齐两侧都会出问题。而辨识度体系要从现在起为它预留编排空间，就必须**现在**知道区分模式。

## 决策

**多灵根角色是确定项：后续版本引入、走免费轨道**，首批估计十个（五行恰有 `C(5,2) = 10` 种双灵根组合）。

**卡池区分取双机制组合**，两条机制均已在 `CanLearn` 判定式内，**零新字段、零新机制**：

- **`RequiredAffinities` 多元素 = 复合功法** —— 只有同时持两灵根的角色能修，承担双灵根角色的**独占亮点**（组合）。
- **`MaxCharacterAffinityCount` = 数量上限** —— 承担单灵根角色的**专属补偿**（深度）。

**上限语义即现行判定式**：上限 2 的功法单、双灵根皆可修（属性要求照常须满足）；上限 1 的功法双灵根不可修。

**双灵根批的内容义务 = 两类专属内容同批对铺**（单灵根专属功法 + 复合功法）；对铺量待实测。
→ `systems/character-profile/_index.md`「灵根」· `systems/character-profile/deck/_index.md`「灵根修习准入」。

## 理由

`systems/character-profile/deck/_index.md`：只用数量上限这一条，宽池角色**只有减法没有加法**——它拿不到任何别人拿不到的东西，「池更宽」在体验上读作「没有专属」。复合功法补的正是这一半：宽池角色有自己修得、别人修不得的独占亮点。

走免费轨道：它是玩法复杂度的向上展开面，而 `decisions/ADR-0255-paid-character-series-track.md` 明写付费卖的是新玩法——把第一批复杂度展开也做成付费会让「付费 = 更深玩法」与「免费档是可通关基准」之间的边界模糊。

## 备选方案

- **只用数量上限梯度** — 否决：宽池角色只有减法没有加法。
- **留到引入时再定** — 否决：预留编排空间需要现在就知道模式，否则首批功法的编排会把宽池角色的位置写死。
- **多灵根批走付费轨道** — 否决：见理由段。

## 后果

- `MaxCharacterAffinityCount = 1` 的单灵根专属功法**首批可以为空**（五角全单灵根，不需要对冲）。
- 多灵根角色的强度对齐自此是「两类专属内容对铺」的**编排题**，不是单一强度公式。
- 加载期校验 8 / 9（`MaxCharacterAffinityCount` 负值 / 小于 `RequiredAffinities.Length`）承接本条的结构面，见 `systems/character-profile/_index.md`。
- 引入多灵根角色**零结构变更**：`Affinities` 本就是数组，「长度恰为 1」是内容编排口径而非字段约束。
