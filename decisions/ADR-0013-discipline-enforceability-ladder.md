# ADR-0013 — 纪律的可执行化：四级阶梯 + 两条选级判据

- **状态：** Accepted
- **日期：** 2026-08-09
- **来源：** handoffs/2026-08-09e-discipline-enforceability.md

## 背景

本库积累了大量以「必须 / 一律 / 绝不」写下的工程纪律。三条待答项本是同一个问题的三个实例：*正确的写法要作者主动记得，错误的写法既不报错也不显眼*。逐条讨论「这条约定怎么强制」会给形状相同的问题推出互不一致的答案。

## 决策

**一条约定该做到哪一级，取决于违反它的代价——不取决于它写得多醒目。**

| 级 | 手段 | 违反时 | 成本 |
|----|------|--------|------|
| **1 · 写不出来** | 类型 / 可见性 / 命名——错误的写法在语言层不存在或不合法 | 不可能发生 | 设计期一次性 |
| **2 · 编译不过** | `[Obsolete(error: true)]`、`#if` 条件编译、分析器 | 编译期报错 | 低～中 |
| **3 · 大声失败** | 启动期断言、切屏 / 退出期审计（一律 `#if DEBUG`） | 开发期 `PushError` | 低，但只在开发期生效 |
| **4 · 评审清单** | 文档条款 + 人工评审 | 靠人 | 零成本、零保证 |

**两条选级判据：**

- **能上线且线上不可见 → 必须做到第 1 或第 2 级。** 判据是「这条纪律被违反后，测试期能不能被发现」。违反后游戏照常运行、错误只在真实玩家身上显形的，**第 3 级不够**。
- **只在开发期显形、且违反后会累积 → 第 3 级足够**，不必付第 1 / 2 级的成本。

**通用补注 —— 内容侧纪律的等价第 2 级 = 发布管线跑同一份校验。** 第 1 / 2 级手段全部作用于 C# 代码，而有一类纪律的检查对象是 **`.tres` 的引用图**，客户端侧的天花板是第 3 级。其等价物是：把同一份校验放进内容的打包 / 发布管线，**不通过即不产包**；成立的前提是校验**内嵌在打包工具本身**（产包的唯一路径），否则退化为第 4 级。客户端启动期的 `PushError` 保留为兜底，处理手工塞进 `user://overlay/` 这类非发布路径。

阶梯、判据与四处应用的形态见 `systems/architecture.md`「纪律的可执行化」。

## 理由

- 本判据是把本库**已有的三处实践**（`internal sealed` manager、`Async` 后缀、两条唯一入口）归纳成的显式阶梯，不是新造的规则；有了它，日后遇到「这条约定怎么强制」直接套用，不必逐条重新讨论。
- **「能上线且线上不可见」这一档的症状恰恰是「一切正常」**，故断言（第 3 级）不够——断言只在跑到那一步时生效。
- **写成通用补注而非逐条例外**：`.tres` 的引用图不止剧本一处，逐条写例外只会把同一条论证重复五遍。

## 备选方案

- **Roslyn 分析器** — 否决：单独项目要维护、随 Godot 生成的 `.csproj` 走易被覆盖、无 CI 前提下只在本机构建生效；`[Obsolete(error: true)]` 拿到同一份编译期保证，成本低几个数量级。
- **把「上线且不可见」类纪律只做到第 3 级** — 否决：见上方理由第二条。
- **给内容侧纪律逐条写例外，而不是一条通用补注** — 否决：同一论证重复五遍。

## 后果

- 四处应用被逐一定级：**离线后端不得发到线上 → 第 1 级**（`BackendSelector` + `OfflineXxxBackend` 整类 `#if DEBUG`）· **抽取必走 `AllEnabled()` → 第 1 / 2 级**（删除中性名 `All()`、过渡期 `[Obsolete(error: true)]`、第二阶段前升为 `DrawPool<T>`）· **EventBus 订阅必退订 → 第 3 级**（`#if DEBUG` 切屏审计）· **overlay 新增剧本条目不得引用新的非剧本 `Id` → 第 3 级 + 发布侧等价第 2 级**（`newIds` 双闸 + 打包工具跑同一份 `LoadAll()`）。
- 它是后续每一次新纪律落地的选级依据，`systems/services/*.md` 与 `ux/` 的多条检查形态直接引用它。
- 影响文档：`systems/architecture.md`（权威）· `systems/services/content-service.md` · `systems/services/plot-manager.md` · `systems/viewmodel.md` · `ux/error-and-blocking-ux.md` · `system-overview.md` 第四节。
