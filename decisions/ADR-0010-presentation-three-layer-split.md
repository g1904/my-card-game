# ADR-0010 — 展示层三层切分：Data / 运行时·存档 / ViewModel

- **状态：** Accepted
- **日期：** 2026-07-25
- **来源：** handoffs/2026-07-25b-event-cost-fields-capability-flags-and-service-hierarchy.md · handoffs/2026-08-19-architecture-structural-residuals.md · answer-logs/log-0725c.md

## 背景

前端需要的描述字段（显示名、动态描述、随 capability flag 变化的可见性）该放在哪一层？最直接的做法是给核心「类」另建一套「充血」的并行展示类——那会制造两份需同步的真值，且展示文本一旦进入存档，文案改版就会触发存档迁移。

## 决策

**不为「充血模型」另建并行展示类，按生命周期切分三层：**

1. **静态展示文本留在数据资源上。** `XxxData : Resource`（`.tres`）除 `Id` 与玩法数值外**直接携带**显示名 / 描述 / 图标。
2. **运行时 / 存档态只带 `Id` + 可变状态**，不复制展示文本。
3. **组合展示走 UI 层轻量 ViewModel。** 动态描述由展示层按需组装 `Data + 运行时状态 → ViewModel`，只存在于呈现期，**不落存档、不进云端负载**。

**ViewModel 因此是架构中的一个显式层**，位于 services / 核心「类」与屏幕场景之间，是「服务 → 屏幕」的数据形态契约；它单向依赖，**服务的 API 面永不返回 ViewModel**。

三层的定义段在 `systems/architecture.md`「展示层契约」；第三层的完整契约（依赖方向、组装源三件套、重组装触发面、只读消费纪律、缓存归属、永不渲染清单）在 `systems/viewmodel.md`。

## 理由

- **另建并行展示类只会制造两份需同步的真值**——而静态展示文本落在 `.tres` 上本就是既有约定（显示字符串与 `Id` 分离、可本地化，见 `.claude/rules/data-resource-rules.md`）。
- **存档与上行负载保持轻量可版本化**：文案变更不触发存档迁移。
- **服务一旦返回屏幕形态的对象，服务层就被绑死在某一屏的布局上**，换一屏要改服务。
- **ViewModel 是这批横切纪律的最小公共祖先**：它们的消费面横跨内容层、事件层、战斗层、同步层与错误呈现层，没有任何单一既有文档能容纳全部；且它服务于全部屏 × 全部服务，不属任何单屏。
- **权威在结构一侧**（依赖方向、生命周期、只读性、缓存归属、重组装时机），没有一条在回答「怎么说」，故归 `systems/` 而非 `ux/`。

## 备选方案

- **另建一套并行的充血展示类** — 否决：两份需同步的真值。
- **把展示文本复制进运行时 / 存档态** — 否决：存档变胖，且文案改版触发存档迁移。
- **让服务直接返回屏幕形态对象** — 否决：服务被绑死在布局上。
- **ViewModel 的纪律留在 `architecture.md` 的一节里** — 否决：那一节已被 API 契约总则占满，落地纪律进不去；且横切面无处容纳。
- **把 ViewModel 归 `ux/`** — 否决：`ux/` 已自我限定为「怎么说、说在哪、说几次」。

## 后果

- 约束了 `LocalizedText.Get()` 的缓存归属：**解析结果只能缓存在 ViewModel 上，绝不写回 `XxxData`**（后者是 ContentRegistry 里的共享只读单例，写回即污染注册表）。
- 引出一条承重纪律：**切语言后 ViewModel 必须重组装**——内容层的 `LocalizedText` 不经 `TranslationServer`，漏掉它的症状是「切语言后卡面文字不变」，属「能上线且线上不可见」那一档。
- 使「UI 代码里拿到的恒是 `Id` 与翻译键」成立，从而「赋给 `.Text` 的字面量含 CJK」可以被直接判为违规（文案审计的前提）。
- 闭合了架构体检的第 8 处缺口（UI 与服务间无契约层）。
- 影响文档：`systems/viewmodel.md`（固化主落点）· `systems/architecture.md`「展示层契约」· `systems/common-properties.md` · `program-overview.md` · `ux/_index.md`。
