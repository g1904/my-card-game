# ADR-0008 — 后端写入路径在上行侧只接受回声，不等即整批拒绝

- **状态：** Accepted
- **日期：** 2026-08-22（§5c 本体）· 2026-08-23（适用面恒等式与比较口径）
- **来源：** `handoffs/2026-08-22-entitlement-echo-and-receipt-idempotency.md` · `handoffs/2026-08-23c-echo-validation-scope.md` · `answer-logs/log-echo-validation-scope.md`

## 背景

`playerDiff` 的合并语义是**顶层键粒度的浅合并**（`contracts/profile-sync.md` §3a）：客户端提交某个顶层键即整键替换，键内属**后端写入字段表**的路径随之被客户端提交的值覆盖。那张表挡住的是「谁有权 `+1`」，挡不住**覆写**——客户端提交它 pull 时的旧序号，云端就被回退，而序号回退比不推进更糟。

`revision` CAS 不是这条的防线：它问的是「你的基线对不对」，不问「你有没有权改这个字段」。没有一个报文层的执行点，后端写入字段表就只是一句纪律。

## 决策

**凡 `playerDiff` 含某个顶层键，键内属后端写入字段表的每条路径，客户端提交的值只能是回声（与当前云端值相等）——不等即整批拒绝**，回 `sync.conflict`、`detail` 给 `{ cloudRevision, field }`，并打一条风控事件。

同批固化的三条承重条款：

- **适用面是一条恒等式，不是第二份清单：受回声校验约束的 JSON path 集合 ≡ 后端写入字段表的行集合。** 写入表加一行即自动进入约束；写入表封闭 ⇒ 约束面结构性封闭。**判据是所有权，不是透明性**——客户端有权写的路径一律不受本节约束，越界走 §7a 的「记账 + 风控、不拒绝」。
- **比较口径为类型感知的语义相等**，不是原始字节相等：整数按数值、定长 hex 按逐字、RFC 3339 时间串**按时刻**、对象数组**有序逐元素**递归。
- **连带刚性：向受约束顶层键内的对象追加字段 = 两侧同批落笔的变更**，它是 `contracts/envelope.md` §8「客户端加字段零配合」的例外。

判定顺序、拒绝面、当前受约束的四条 path 与栈中立的验收断言 → `contracts/profile-sync.md` §5c。

## 理由

浅合并按顶层键 ⇒ 封闭的后端写入表若无报文层执行点即形同虚设，而 CAS 问基线不问所有权（§5c）。受约束的是客户端**根本无权写**的路径，正常客户端在这些路径上永远只会提交回声，故零误报、拒绝是安全的。

恒等式而非第二份清单：另立一张「受约束 path」表与写入表必然漂移，漂移形态恰恰是「进了写入表却没进回声表」——正是这条要关掉的口子。

比较口径必须类型感知：误判的代价是**在正常账号上丢玩家进度**。按字面 / 按字节比较等于要求两侧序列化器逐字一致，是一条无人声明、无处校验、一次库升级即静默破坏的隐含契约，破坏时的症状是「所有玩家改昵称都丢一次进度」。

## 备选方案

- **只靠 `revision` CAS 挡覆写** — CAS 问基线不问所有权；写成常量的客户端 bug 在基线正确时被原样接受。
- **字段级挑拣（忽略越权路径、接受其余）** — 要求后端在顶层键内部做字段级合并，动摇 §3a「不递归、不逐元素合并」的分段。
- **按顶层键统一处置** — 会把 `bundleRedeemedOrdinal` 的越界从「记账」升为「丢进度」，与 §7a 正面冲突。
- **为回声校验新增专用错误码** — 客户端处置与 Conflict 完全一致；可观测性由风控事件承担。
- **另立一张「受回声校验约束的 path」清单** — 与写入表必然漂移。
- **把 `bundleRedeemedOrdinal` 提为另一个顶层键以避开整键替换** — 绕开一处表现，`/accountInfo` 仍是同一形状；需要的是通则而非搬家。
- **按原始字节相等 / `createdAtUtc` 按字面逐字相等** — 把序列化器实现细节抬成契约。
- **`identities` 按集合相等** — 更宽松但无收益，只会掩盖客户端的重排 bug。
- **用 JSON Schema 表达回声约束** — schema 说不出「等于当前云端值」。
- **回声校验放在 CAS 之前** — 无收益且更贵：CAS 失败时本就整批拒绝。

## 后果

- `contracts/profile-sync.md` §5 的后端写入字段表**同时成为回声约束面**：扩表即扩约束，扩表仍是破坏性契约变更、须两侧同批评审。
- `contracts/envelope.md` §8 须保留一句指路：受约束顶层键内追加字段是该节「客户端加字段零配合」的例外。
- `openapi.yaml` / `schemas/*.json` 落笔时须在对应 schema 处留注释指向 §5c——schema 表达不了这条约束，强行表达会退化为把这些 path 标成必填。
- 风控事件的字段与处置阈值归 `open-questions/02-account-compliance.md` / `06-platform-stack.md`，落 `operations/`；契约层只声明「必须上报、不在热路径裁决」。
- 客户端侧对位（回声值取自最近一次 pull 的权威快照、回声路径不参与钳制 / 补默认 / 归一化、push 前自检）权威在 `game-design-documents/systems/services/sync-service.md`，本库不复述。上游裁决见 `game-design-documents/decisions/ADR-0023-premium-entitlement-and-redemption.md`。
