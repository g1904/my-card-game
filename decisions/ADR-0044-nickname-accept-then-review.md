# ADR-0044 — 昵称判定取四级短路，复核级与不可达一律先接受

- **状态：** Accepted
- **日期：** 2026-09-03
- **来源：** handoffs/2026-09-03-nickname-moderation-and-risk-control.md · answer-logs/log-nickname-moderation-and-risk-control.md

## 背景

昵称要过形态校验、频次闸、敏感词表与（可选的）第三方审核适配器四道。词表有「复核级」这一档，第三方适配器则可能判「待复核」或干脆不可达。这三种情形都不是明确拒绝，端点却必须当场给一个应答。

## 决策

昵称判定是**四级短路**：形态 → 频次 → 词表 → 第三方审核适配器 → 接受，第一个失败级决定 `reasonKey`。

词表命中「复核级」与适配器判「待复核 / 不可达」**一律先接受**（`204`）并入复核队列——端点**不返回「待审」态**，`reasonKey` 表**不加第四个取值**。

判定链见 `contracts/auth.md` §8；服务内部形态与断言见 `systems/account.md`；复核队列与词表分级见 `operations/moderation.md`；适配器档位映射见 `operations/external-providers.md`。

## 理由

返回「待审」会把一个长时状态机塞回 auth 域，而 `contracts/compliance.md` §1 的分域判据正是以相反的纪律把合规域拆出去的——auth 域只做即时判定。

适配器不可达时若返回 `SensitiveWord`，等于把外部抖动伪装成明确拒绝，玩家会以为自己的昵称违规（与「渠道不可达 ≠ 明确拒绝」同源）。

短路顺序不能颠倒：既超长又含敏感词时应答必须唯一，否则验收断言有歧义；且把唯一有外部成本的一级放最后，被频次闸挡住的刷子不产生任何外部调用。

## 备选方案

- 给 `reasonKey` 表加第四值「待审」 — 端点从即时判定变成长时状态机，与合规域的分域纪律相抵。
- 适配器不可达时返回 `SensitiveWord` — 把外部抖动伪装成明确拒绝。
- 颠倒短路顺序 — 应答不唯一，且刷子会产生外部调用成本。
- 词表设第三档「放行」 — 放行是补集，不是一档。

## 后果

- 复核队列与存量扫描是同一条处置通道的两个入口，不是两套机制。
- 「先接受」是 `ADR-0026`（处置只落 `status` 侧）与存量扫描三触发源成立的前提——没有它，扫描通道与 `nicknameChangeRequired` 标记都失去对象。
- 第三方昵称审核是 `ADR-0038` 的结构性例外：它的归一目标是判定链的档位，不是 `code`。
