# ADR-0095 — 新增 `TechniqueCodex`；词条不列卡牌清单

- **状态：** Accepted
- **日期：** 2026-08-25
- **来源：** handoffs/2026-08-25-info-economy-and-codex-expansion.md

## 背景

功法成为卡组构筑单位（→ `ADR-0054`）、敌方套牌也由功法展开（→ `ADR-0090`）之后，功法成了玩家最需要了解、也最常遭遇的一类内容——而它此前没有图鉴。

新本一旦立起，词条深度就要定：列不列出这门功法每层有哪些卡？

## 决策

新增 **`TechniqueCodex`**（标识符 `TechniqueCodex` / `CodexKind.Technique` 枚举末位 / 存档字段 `techniqueCodex`）。条目按 `CultivationTechnique` 的 `Id` 索引，账号级跨轮回持久，静态文案，只记解锁状态。

**词条不列卡牌清单**——词条 = 功法名 / 描述 / `Rarity` / 路数概括 + 可选 `CodexFlavor`。卡牌列表**只在玩家自己持有该功法时**由卡组 / 构筑界面提供。

→ `systems/player-profile/codex/_index.md` 与 `codex/technique-codex.md`。

## 理由

**不列卡表的理由承重**：玩家可从敌人词条②（指向真实功法）→ 功法图鉴**反查出敌人的完整卡组**，这实质绕过了「慷慨度维持 3 张关键卡、不给样本卡组完整列表」这条既定分寸，把词条从**事前知识**推向**事中情报**——而事中情报正是被整条移除的东西（→ `ADR-0059`）。

自己持有时可看全表则没有这个问题：那是你自己的牌。

## 备选方案

- **词条列出每层卡表** — 否决：见理由，开出敌人卡组反查通道。
- **用序数命名「第六本 / 第七本」** — 否决：一律**去序数化**而非改数字——序数下次扩员会再次失真。

## 后果

- 词条深度分野因此成形：**能力 / 道具 / 功法类**只用内容条目自身已有的字段 + 一段可选的 `CodexFlavor`。
- `LocationCodex` 与 `TechniqueCodex` 的加入是这条分野的两次验证。
- 图鉴清单表的措辞一律去序数化，扩员时只加行不改数（→ `ADR-0037`）。
