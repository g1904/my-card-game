# ADR-0095 — 新增 `TechniqueCodex`；词条列出逐层卡牌清单

- **状态：** Accepted
- **日期：** 2026-09-11
- **来源：** handoffs/2026-09-11-failure-and-punishment-identity.md · handoffs/2026-08-25-info-economy-and-codex-expansion.md

## 背景

功法成为卡组构筑单位（→ `ADR-0054`）、敌方套牌也由功法展开（→ `ADR-0090`）之后，功法成了玩家最需要了解、也最常遭遇的一类内容——而它此前没有图鉴。

新本一旦立起，词条深度就要定：列不列出这门功法每层有哪些卡？这个问题的答案由**归因承诺**裁定——本作要求「输了一般是牌组构建或出牌顺序的错，同一个敌人第二次遇到就该能打赢」，而敌人行动零事前预告、图鉴战斗中一律不可查，这条承诺只能靠战前查阅兑现。

## 决策

新增 **`TechniqueCodex`**（标识符 `TechniqueCodex` / `CodexKind.Technique` 枚举末位 / 存档字段 `techniqueCodex`）。条目按 `CultivationTechnique` 的 `Id` 索引，账号级跨轮回持久，静态文案，只记解锁状态。

**词条列出该功法逐层的卡牌清单**——词条 = 功法名 / 描述 / `Rarity` / 属性 / **逐层卡表** + 可选 `CodexFlavor`。卡表由呈现层从功法条目的成员卡现算，**不新增任何存档字段**。

**「敌人词条② → 功法图鉴 → 逐层卡表」的反查通道因此是设计目标，不是漏洞。**

→ `systems/player-profile/codex/_index.md` 与 `codex/technique-codex.md`。

## 理由

- **它是归因承诺唯一可行的兑现方式。** 给路数概括而扣着牌表，归因精度不足以支撑「第二次就该打赢」，那条承诺会退化成一句空话。信息本身就是元进程奖励（支柱 9）在此第一次有了强制的落地形态。
- **对价是玩家用一次遭遇换来的。** 知道卡表的玩家能在战斗中推算「他还剩哪些牌」；「首遇的信息差即首遇的风险定价」说的是**首遇**收费，不是一直收费。
- **反查有一道天然的界：层数不进任何词条。** 层数提升是整组替换（层数不同则牌不同），故反查停在「这门功法大致长什么样」，而非逐张精确的本场牌表。
- **两条边界不松动**：图鉴**战斗中一律不可查**、词条**不含动态情报**。推算只能靠玩家的战中记忆，界面不提供查询入口。

## 备选方案

- **词条只到路数为止，卡表只在玩家自己持有该功法时由构筑界面给出** — 否决：归因精度不足，且它与敌人本「只给定性描述」是同一条不足的两面。
- **只列卡名、不列效果与数值** — 否决：会引入第三种词条形态（本人持有 / 仅遭遇两档），而逐档解锁本身已被否决（`ADR-0037` 族线）。
- **用序数命名「第六本 / 第七本」** — 否决：一律**去序数化**而非改数字——序数下次扩员会再次失真。

## 后果

- **敌人本的词条随之定形为四项**（人物背景 · **核心功法引用列表**，多门、不含层数 · 运作方式 · 特点与弱点）；`EnemyData.KeyCardIds` 的职能是**仅供敌人 AI 的 `KeyCardBias`**，不对玩家呈现为词条格。见 `codex/enemy-codex.md`。
- **敌人本的一屏纪律让路**：③④ 写到行为模式级、不设字数上限，词条页允许纵向滚动。
- 词条深度分野因此成形：**能力 / 道具类**只用内容条目自身已有的字段 + 一段可选的 `CodexFlavor`；**功法本另加一份由条目现算的卡表**。
- `LocationCodex` 与 `TechniqueCodex` 的加入仍是「一族而不是一个」这条设计的两次验证。
- 图鉴清单表的措辞一律去序数化，扩员时只加行不改数（→ `ADR-0037`）。
- **它对敌人 AI 构成一条硬约束**：AI 必须是可描述的固定行为模式。现有形态（1-ply 确定性 argmax、零随机、零记忆，→ `ADR-0113`）满足它，此后那些性质是本决策的义务。
