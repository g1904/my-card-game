# ADR-0005 — 防作弊边界：可复算 `roll`、不复算阈值；不一致仅记账不拒绝

- **状态：** Accepted
- **日期：** 2026-08-14
- **来源：** `handoffs/2026-08-14-profile-sync-contract.md` · `handoffs/2026-08-12-grant-source-code-contract.md` · `answer-logs/log-profile-sync-contract.md`

## 背景

「后端可离线复算账号级掷骰」这句已定案语义，落到实处时拆成性质完全不同的两件事：算出 `roll`，与判定是否命中。后者需要生效概率 `clamp(accumulated, Base(x), Cap(x))`，而 `Base` / `Cap` 是按 `(x, chapter)` 分档的**内容数值表**，随 overlay 热更且不冻结 `contentVersion`。同时还有一个处置问题：复算对不上时，后端该不该拒绝这次上行。

## 决策

**能复算的只有 `roll`，不复算阈值；复算不一致仅记账 + 上报风控，不拒绝、不改写。**

- 后端由 `(accountSeed, PowerFragment, finaleWinOrdinal)` 自算 `roll'` 并与客户端上报的 `lastRoll` 逐位比对。
- **明确否决后端持有分档表并全量验算命中。**
- 客户端每次 Finale 胜利上报两个中间值（`lastRoll` · `lastEffectiveChance`），后端做三条校验：① `roll'` 逐位相符 ② **单向蕴含**——未命中却新增法则 ⇒ 异常，反向不判 ③ 结构不变式（序号恰 `+1`、区间、单调）。
- 不一致 → **接受写入** + 打结构化风控事件 + 交风控按累计频次处置；**不拒绝上行、不以后端值改写 profile**。
- 三条承重的客户端写入约定（停摆时也掷骰并落 `lastRoll` · 首胜写 `10000` · 校验 ② 只能单向）与校验细则 → `contracts/profile-sync.md` §7 §7a。

## 理由

- **不复算阈值**：把随 overlay 热更的平衡表复制到后端 = 第二份真值 + 必然漂移，与 pillar #1（云端不重跑玩法）、pillar #5（改数值不需要发版）同时相悖；后端还缺一个输入——「这次 Finale 是哪一篇章」，补它又要再加一条透明路径。
- **不拒绝**：拒绝即 `sync.conflict`，而客户端按既定语义会**丢弃本地缓冲**——一次误报（时钟、并发、任一侧实现差一位）当场变成一次玩家进度丢失，违反「绝不回退存档点」与 pillar #4。而复算对象是**每篇章至多一次**的低价值掉落，用进度丢失去防它，比例失衡。
- **不改写**：会让客户端与云端的 Profile 在客户端不知情时分叉（客户端并不重新 pull），且与「未知 `sourceCode` 记录原值、不改写」正面冲突。
- 形状与「验签失败 → 拒绝 + 上报一次」一致：**异常必须可见，但不在同步热路径上做裁决。** → `contracts/profile-sync.md` §7a。

## 备选方案

- **后端持有残卷分档表并全量验算命中** — 第二份真值 + 必然漂移，且缺「本次是哪一篇章」这个输入。
- **复算不一致 → 拒绝上行** — 一次误报 = 一次玩家进度丢失。
- **复算不一致 → 以后端值改写 profile** — 两侧 Profile 在客户端不知情时分叉。
- **校验 ② 保持双向等价** — 被两条既定客户端规则证伪（首胜 100%、候选池取尽后静默停摆），在正常账号上误报。
- **客户端再上报一个「本次结局」字段以保住双向等价** — 多一条透明路径即多一条路径稳定性约束，而该字段同样不可验真。
- **在 profile 里存掷骰历史列表供离线核对** — 随账号年龄单调增长，正是 `pastEvent` 已被立护栏防范的那种形态。

## 后果

- **「后端要不要持有平衡表」有了永久答案：不持有。** 任何要求后端验算命中的提案，等于要求推翻 pillar #1 / #5。
- 代价如实记下：`lastEffectiveChance` 后端无法验真，「篡改客户端把生效概率写成 10000」这条路仍通——它被校验 ③ 与风控接住，不被复算接住。
- 风控事件的字段与处置阈值属运营形态，归 `02-account-compliance.md` / `06-platform-stack.md`，落 `operations/`；契约层只声明「必须上报、不在热路径裁决」。
- 复算所需的输入全部落在 `contracts/profile-sync.md` §5 的透明白名单内，**其 JSON path 是契约的一部分**：移动或重命名 = 破坏性契约变更，须 bump `schemaVersion` 并两侧同批改。
- 购买域的兑现段**沿用同一条处置**，不单开更严的规则 → `contracts/purchase.md` §5。
- 复算所依赖的随机源见 ADR-0006。
