# ADR-0149 — 阵法上启动式异能的 UI 宿主 = 战场条目自身

- **状态：** Accepted
- **日期：** 2026-09-02
- **来源：** handoffs/2026-09-02-enchantment-activated-ability-host.md

## 背景

`ActivateAbility(entryId, abilityId, targets)` 按**战场条目 id** 寻址、与 UI 宿主无关（`decisions/ADR-0114-activate-ability-service-contract.md`）。但呈现侧此前只定了 `Power` 那一半（图标条 → 长按弹层 → 弹层内的启动键），**阵法条目在战场区内没有启动入口**——没有宿主就没有玩家可发起的路径，服务算好的那一格在阵法上永无消费者，「留场 + 每回合花 mana 启动」整类内容在客户端写不出来。竖屏战场区空间已很挤，任何新增常驻部件都要与竖屏分区取舍正面冲突。

## 决策

**宿主 = 己方战场区里那个阵法条目本身，不新开任何区、不新增常驻部件。**

- **交互链 = 长按条目 → bottom sheet →「详情 + 启动」合一**，与 `Power` 那一半逐字同构；启动键必须在弹层内、不直接挂在条目上。
- **启动区 = 逐行列表**，每行逐字映射服务算好的 `AbilityAvailability` 一格；呈现层不重演窗口 / mana / 配额三条规则。`Accepted == false` 时 UI 只回到原态、不提示。动词取「启动」不取「使用」。
- **可发现性 = 条目上的静态启动可供性标记，与 `Power` 侧共用同一套**（两态：有启动式异能 / 此刻至少一条可启动）；具体形状归竖屏分区专场。
- **需目标时：弹层先收起** → 该异能目标槽位按 `slotIndex` 顺序一次收齐 → 调用 `ActivateAbility`；合法目标集合大小为 1 时自动选定。
- **己方面朝下条目（埋伏）照常有启动入口**；**对手侧条目不渲染任何标记或启动区**。
- **禁用规格与 `Power` 弹层 / 随身抽屉完全同规格**：敌人回合 / 结算中 / 选目标态下标记置灰、详情弹层入口整体禁用，**弹层是否只读不影响该判定**。

逐条呈现规格 → `ux/combat-ux.md`；字段面权威 → `systems/services/combat-service.md`。

## 理由

- 服务按 `entryId` 寻址、`ActivatableAbilities` 逐条目填充 ⇒ **数据本就是逐条目的**，宿主与它同构时零映射成本；另立集中入口等于在 UI 侧再建一份「异能 → 载体条目」的对应关系。
- `Power` 的宿主就是它在战场上的呈现物；二者同为战场条目、同一条 API，阵法另找宿主会让同一个动作有两条心智路径。
- **零新增区、零新增常驻部件**是本方案不与竖屏分区取舍冲突的唯一形态。
- **启动键落弹层**：竖屏战场条目塞不下满足最小触控目标尺寸的按钮；而启动扣 mana、占掉行动阶段一个动作位、不可撤销、不做二次确认，弹层这一步正是唯一的误触门槛。
- **长按而非点按**：既有判据「详情入口的手势按对象是否可拖拽分化」一字不改（`decisions/ADR-0085-gesture-split-tap-versus-longpress.md`）。
- **禁用理由是半屏弹层争屏幕 + 启动键争语义**，与内容是否只读无关；需目标时收起弹层，因为「选目标态期间栈层必然在场且豁免压暗」「合法目标不被压暗」是承重。
- **对侧不渲染**：既无消费者（对侧列表恒为空、敌人启动走 EnemyManager 内部路径），又是一条信息泄漏面。

## 备选方案

- **单开「启动式异能条」集中入口** — 否决：新增常驻区与竖屏分区取舍冲突，且要在 UI 侧另建一份「异能 → 条目」对应关系。
- **把阵法启动并进随身抽屉** — 否决：随身是按 `UsableScene` 筛出的**道具**视图，阵法不是道具；`Use` 与 `Activate` 在契约面已是两条路径。
- **启动键直接挂在战场条目上** — 否决：竖屏条目尺寸达不到最小触控目标；且会失去唯一的误触门槛。
- **敌人回合 / 结算中允许弹层以纯只读打开** — 否决：禁用理由是半屏弹层争屏幕，与只读无关。被接受的代价见后果。

## 后果

- **零服务契约改动、零 schema 改动、零存档迁移**；新增的只有呈现层部件：启动可供性标记（两态）· 弹层内的启动区一节 · `COMBAT_` 分区的拒绝原因文案键（由 `ActionRejection` 成员机械映射，不占 `ERR_` 前缀）· 启动键与「启动」动词的文案键。**不新增**区、常驻挂件、手势、控件类型、服务方法、存档字段。
- **明写接受的代价**：敌人回合与结算中无法查阅战场阵法的规则文字；该段可读性由飘字与战报因果树承担。
- 相关文档因此这么写：`ux/combat-ux.md`（阵法条目的宿主 / 交互链 / 启动区 / 可发现性 / 禁用规格）。本条不重排战斗屏分区、不为它规定屏面积配额。
- 待定项归竖屏分区专场：启动可供性标记的具体形状 · 卡牌详情页的内容清单与排布 · 己方埋伏是逐条渲染还是折叠成一格（无论何种形状都必须有启动入口）。
