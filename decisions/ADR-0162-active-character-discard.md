# ADR-0162 — 主动放弃角色：入口落主菜单篇章行，就地二段确认，只对 `ongoing` 开放

- **状态：** Accepted
- **日期：** 2026-09-06
- **来源：** handoffs/2026-09-06-active-discard-entry.md · answer-logs/log-character-discard-entry.md

## 背景

篇章推进是一道闸：一个 `ongoing` 角色占着它所在篇章的位置。玩家如果决定不再推进某个角色，此前**没有任何通道**能把它终结——闸就一直占着，而 `DefeatCharacter` 只在系统判定失败时由服务内部调用。

## 决策

**唯一发起入口 = 主菜单「切换篇章」面上、该篇章那一行 `ongoing` 角色旁的次级动作**；不新增屏、不新增主菜单入口，**轮回内不设第二个入口**。

**就地二段确认，无冷静期、无撤销通道**；弃置键恒可用、不置灰。

**只对 `ongoing` 角色开放**：`completed` 的可挑战角色不提供该动作，**不新增 `completed → defeated` 转移**，状态机一格不动。**被接受的代价：已通关角色档没有任何清理通道。**

**`DefeatCharacter` 签名扩为 `(DefeatReason reason, string characterId)`**——不加重载、不加可空默认值，并进「服务方法不收 `character` 参数」通则的**显式例外表**。

**面向玩家的中文 UI 文案一律写「放弃」，不写「弃置」**（后者留给功法侧），登记进 `terminology.md`。

逐屏措辞、`MENU_DISCARD_*` 键族与剩余次数取值时点 → `ux/screen-flow.md`；状态机与记账口径 → `systems/services/life-cycle-service.md`。

## 理由

- **入口挂在闸旁**：玩家想放弃的时刻，恰是他看着「切换篇章」面发现自己被这一行挡住的时刻——入口与动机同屏，不需要记住它在哪。
- **冷静期在这里自相矛盾**：冷静期内角色仍是 `ongoing` ⇒ 闸仍占着 ⇒ 功能在整个冷静期内**什么都没做成**。
- **`ongoing` 限定不动状态机**：`completed → ongoing` 已是合法转移、只有 `defeated` 是吸收态；开放 `completed` 弃置要新增一条转移并回答「已通关的存档能不能被销毁」，那是另一个问题。
- **显式收 `characterId`**：主菜单侧要弃置的不是当前 active 角色；「先把目标角色设为 active 再调用」等于为一次销毁做一整套水合。
- **术语分工**：功法侧「弃置」已固定，角色侧沿用会让同一个词指两件后果差异极大的事。

## 备选方案

- **轮回内再设一个入口** — 否决：等价于「取消到最近决策点 → `Immediate` flush → 弃置」的同一条链，且全库无暂停屏、设置屏语义不承载；代价（多一次退出）如实写下。
- **允许弃置 `completed` 角色** — 否决（用户裁决）：明知 ch3 通关档会堆积仍选此项，理由是不为清理需求新增一条状态机转移。
- **冷静期 / 撤销通道** — 否决：见上，功能全程什么都没做成。
- **滑动删除 / 长按菜单** — 否决：隐藏可供性，且与角色选择、eventOptions 的横滑语汇撞层。
- **主菜单侧先把目标角色设为 active 再调用** — 否决：为一次销毁做完整水合。

## 后果

- **`DefeatReason` 增一员 `Discarded`**，走与系统判定失败**同一条**记账与拆解链路（`ADR-0148` 的轮回结束屏据 `DefeatReason` 查表取文案，本项自动落位）。
- **`RetriesLeft == 0` 时走新增的第三条文案键**——放弃即该角色终结，没有可回退的重试。
- **剩余次数读数取「记账之后」的值**，避免二段确认页与结束屏两处读数不一致。
- 受约束的文档：`ux/screen-flow.md`（篇章切换面 + 二段确认 + 键族）· `systems/services/life-cycle-service.md`（方法签名 + 例外表 + `ongoing` 限定）· `terminology.md`（「放弃」条）· `program-overview.md`（签名同步）· `decisions/ADR-0148-cycle-end-screen.md`。
