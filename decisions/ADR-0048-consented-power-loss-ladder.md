# ADR-0048 — 法则不会被强制剥夺：只有自愿置换能真正移除；三级严重度阶梯

- **状态：** Accepted
- **日期：** 2026-08-06
- **来源：** handoffs/2026-08-06b-asymmetric-ch1-band-consented-power-loss-and-chapter-retry-shape.md, handoffs/2026-08-10c-ability-disable-replacement-and-player-statistics.md

## 背景

「失去法则」是元进程失败侧的一类事件设计。但法则是**账号级**积累物——玩家可能为一个法则跑了十几个轮回。若某个事件能强制剥夺它，玩家的长期投入会被一次随机遭遇抹掉，而这与法则作为积累线的定位直接冲突。

## 决策

**法则（`PlayerPower`）不会被强制剥夺：只有玩家自愿的「置换」能真正从账号移除**，其余事件一律降级为**「本轮回禁用」**。

禁用集合落 **`CharacterProfile.disabledAbility`**——与 `pastEvent` / `chapterRetry` / `activeCombat` 平级的新字段，**不落 `Status` 内**。

战斗内的 `IgnoresProtection` 只作用于本场。三者构成**三级严重度阶梯：本场移除 < 本轮回禁用 < 账号移除（仅置换、需自愿）**。

形态与判据 → `systems/player-profile/player-power/_index.md`；存档字段 → `systems/character-profile/_index.md`。

## 理由

自愿是这条设计的全部重量：置换是玩家主动做出的取舍（用一个换另一个），而剥夺是加诸于他的损失。前者是策略，后者是惩罚——而本作的惩罚已经由寿元与角色终结承担，不需要再叠一层作用于账号层的。

三级阶梯让「失去」这个词在三个层次上各有确定含义，事件设计因此可以选择强度而不必每次重新发明语义。

## 备选方案

- **真的允许永久剥夺** — 否决（08-06b 三候选之一）：抹掉跨轮回投入，与法则的积累线定位冲突。
- **禁用集合落 `Status` 内** — 否决：`Status` 是具名子类，集合型 build 状态与它平级。
- **禁用 = 入场后立即移除** — 否决：那就是剥夺，只是换了个说法。
- **允许能力 element 出现在 `selectCost`** — 否决（08-10c 推翻 08-06b 的旧措辞「置换作为选择成本似乎合理」）。
- **置换 = 一条 `Replace` element** — 否决：置换是两条 element（移除 + 授予）的事务，不是一个新算子。

## 后果

- `disabledAbility` 是轮回级字段，轮回结束即消失——禁用永不跨轮回。
- 事件设计里「失去法则」一律读作「本轮回禁用」，除非该事件明确走置换面板。
- 置换候选池为空时的处置由三道闸承担，**不降级到相邻稀有度**。
