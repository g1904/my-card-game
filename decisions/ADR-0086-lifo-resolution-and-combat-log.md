# ADR-0086 — 结算呈现 = 逐层 LIFO 弹栈 + 短暂强调；战报 `combatLog` 是同一份数据的两个视图，不上提为 `eventLog`

- **状态：** Accepted
- **日期：** 2026-08-25
- **来源：** handoffs/2026-08-25-combat-presentation-and-action-result.md

## 背景

一次出牌可能触发一长串结算。两种呈现方式：把结果冲刷进一条滚动播报，或逐层演出。同时，玩家需要能回看刚才发生了什么——此前设想的「结算 ticker」与「stackHistory」是两个部件。

## 决策

**结算呈现 = 逐层弹栈 + 短暂强调，不做滚动播报流（承重）。** 逐层 LIFO 弹出栈上卡牌 / 效果、每弹一层做一次短暂视觉强调、弹完即落账。**「不可暂停」读作「无玩家侧的暂停 / 跳过控件」。**

**战报 `combatLog`：收起态与展开态是同一份数据的两个视图（承重）**，竖屏**净增 0 个区**。条目粒度 = 结算事件，保留本场全部条目不设上限，**不进战斗存档**。展开态在**选目标态禁用**（判据 = 是否与决策面争抢屏幕或语义）。

**明确不上提为跨事件类型的 `eventLog`（边界）。**

**一句话纪律：一个权威、两种寿命——事件内的过程态是纯呈现层、不落存档（战报）；事件间的账目归 `PastEventEntry`、落存档。**

节奏参数为双方回合通用，但**「单个回合演出总时长 ≤ 4 s」这条硬上界只约束敌人回合**。

→ `ux/combat-ux.md`。

## 理由

逐层演出让**因果可见**：玩家看得到「这张牌触发了那个异能」。滚动播报把因果压平成一串文本，而本作的栈深靠触发撑起（→ `ADR-0039`），因果正是要看的东西。

4 s 上界只约束敌人回合，是因为它的论证针对**完全无交互的整段观看**；对称适用会在栈深大时撞天花板、只剩跳步一条出路，与「逐步可见是硬要求」相抵。

不上提为 `eventLog` 有三条独立理由：制造第二权威 · 非战斗事件没有时间轴 · 非战斗事件里唯一值得记的恰好必须隐藏。

## 备选方案

- **滚动播报流** — 否决：压平因果。
- **展开态在选目标态随时可开** — 否决：判据由「有无可供性」改为「是否与决策面争抢屏幕或语义」——原判据漏了遮挡维度，而展开态是半屏。
- **上提为跨事件类型的 `eventLog`** — 否决：三条独立理由，见上。
- **命名为 `eventLog`** — 否决：本作已有三个 "event"（`EventBus` / `AdventureEvent` / `PastEventEntry`）。
- **4 s 上界对称适用于双方回合** — 否决：栈深大时只剩跳步。

## 后果

- 战报不进战斗存档，**退出重进丢失**，代价明写接受。
- 战报的数据源是统一呈现事件流（→ `ADR-0087`）。
- 三个消费者（飘字 / 收起态 / 展开态）读同一条流，不各自组装。
