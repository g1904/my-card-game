# ADR-0119 — 牌可经 `MoveCard` 回到抽牌堆顶 / 底：新增 `InsertPosition { Top, Bottom }`，插入位不掷随机

- **状态：** Accepted
- **日期：** 2026-08-27
- **来源：** handoffs/2026-08-27-card-pool-and-reshuffle.md · handoffs/2026-08-27-ability-primitive-grammar.md

## 背景

抽牌堆不重洗（`ADR-0052`）意味着牌打出即离开抽牌堆、永不回流。但「把这张牌放回牌堆顶」是卡牌游戏里一类基本的战术表达，此前在本作里完全写不出来。问题是：开这个口会不会把被否决的「规则性弃牌堆回流重洗」换个写法放回来。

## 决策

**开口，但形态限定为 `MoveCard` 的目的地扩展，不是新增一条重洗规则。**

`To : CardZone` 保持四值 + **独立一格 `InsertPosition { Top, Bottom }`**（仅目的地为抽牌堆时有意义）——顶 / 底是同一个区的两个插入位、不是两个区，存档仍只记抽牌堆的一条 `Id` 序列。

**首批只开确定性的顶 / 底两位，不开随机位。**

护栏落在**载体消耗性**上（法术天然一次性 · 道具须有限充能 · 启动式异能有 `ManaCost` / 配额两格闸 · 静止式在结构上装不下原子操作），外加「`Count` 必须有限、『整堆 / 全部』形态硬禁」。

校验由「`From == To` → `PushError`」放宽为「**且 `To != DrawPile`**」⇒ **抽牌堆内重排（把堆顶废牌压到堆底）可写。**

触发式载体携带回堆效果**不加配额、不加任何新校验**。

字段形态与两条正面纪律 → `systems/character-profile/deck/_index.md`。

## 理由

**不开随机位是这条开口的承重界线**：随机位才使抽牌堆重新成为战斗中途的随机消耗点；顶 / 底对玩家可读、可规划，且不消耗随机。

**「整堆 / 全部」形态硬禁**——那正是被否决的规则性重洗换个写法。有限次、消耗性的一次性效果不落在 `ADR-0052` 那条理由的射程内：它否决的是**规则性、无限次**的弃牌堆回流重洗。

**触发式不加配额**：与疲劳那条同源——`TurnLimit` 是终止性的硬护栏；同批已推翻「启动式必须有有限性闸」，无限组合是被接受的设计面（`ADR-0114`）。而既有校验「配额只对启动侧成立」与「触发式须有配额」两条永不可能同时通过，必须择一。

**允许抽牌堆内重排**：`From == To` 的一般禁令是防空操作，但在抽牌堆上它不是空操作——把堆顶废牌压到堆底是一次真实的牌序改动。

## 备选方案

- **开随机插入位** — 否决：使抽牌堆重新成为战斗中途的随机消耗点。
- **新增一条独立的「回堆」原语** — 否决：它就是 `MoveCard` 的一个目的地，另立原语会让「牌在区间流转」有两个入口。
- **把「抽牌堆顶」「抽牌堆底」做成 `CardZone` 的两个新值** — 否决：它们是同一个区的两个插入位，拆成两个区会让存档的区序列定义分叉。
- **要求携带该效果的触发式异能须有配额** — 否决：与既有校验「配额只对启动侧成立」永不可能同时通过。
- **维持 `ADR-0052` 的封闭、完全不开口** — 否决：存疑的是无限回流，不是这类效果的存在。

## 后果

- `systems/character-profile/deck/_index.md` 是形态的权威；`systems/services/combat-service.md` 的「抽牌堆不重洗」推论 ④ 与前瞻注记同批改写。
- `deck/_index.md` 内「闭集流转 `⇄`」（对）与「只减不增」（错）的自相矛盾就此收掉——**改的是后者**。
- `ADR-0052` 只在**后果**补一条边界说明，决策 / 理由 / 备选三节不动。
- `ADR-0041` 的读档校验（三区 `Id` 序列并集 = `instances` 全集）不受影响：回堆是闭集内的区间搬运。**无存档 schema 变更、无迁移。**
- `MoveCardEffect` 的 `From` 可取对手抽牌堆，使「削减对手抽牌堆」结构上成立——这触发了「疲劳扣减是否进 `EncounterSpec` 覆写组」的重开判据，已登记为一条新的待答项。
