# ADR-0099 — 战斗内持有物面板按「可操作 / 只读」分两层，不按数据归属分

- **状态：** Accepted
- **日期：** 2026-08-26
- **来源：** handoffs/2026-08-26-storage-pack-two-layer-view-and-combat-holdings.md

## 背景

战斗中玩家身上有四种持有物：法宝 / 古宝（道具类，可用）与神通 / 法则（能力类，多为被动）。它们分属两个持久层（轮回级 / 账号级），直觉切分是按数据归属分两组。

但按归属分组会把「能点的」和「不能点的」混在同一组里——玩家点了半天发现有些点不动。

## 决策

**战斗内持有物面板按「可操作 / 只读」分两层**，**而不是按数据归属分**：

- **可操作层** = 随身道具角标 + 底部抽屉。按 `UsableScene` 筛 + 一条禁用过滤；抽屉内**同时呈现两级**并带 `AbilityScope` 标识，可直接使用。
- **只读层** = 神通 / 法则。不列被禁用者；**长按**升起弹层查看详情；启动式 `Power` 的**启动键落在该弹层内**；图标条本体纯只读。`PowerData.Abilities` **不按启动式 / 被动式收窄**——区分在呈现层。

弹层与随身抽屉**同规格禁用**（敌人回合 / 结算中 / 选目标态）。

**功法与货币不进战斗 HUD。**

→ `ux/combat-ux.md`。

## 理由

玩家在战斗中问的问题是「我现在能做什么」，不是「这东西存在哪一层」。按可操作性分组直接回答那个问题；`AbilityScope` 标识保留了归属信息，但它是标注不是分组轴。

只读层用**长按**而非点按：既有手势判据（可拖拽用点按、不可拖拽用长按，→ `ADR-0085`）已被标为承重，只读层不可拖拽 ⇒ 长按。

同规格禁用：启动键**争语义**、半屏弹层**争屏幕**，两种争抢都各自构成禁用理由。

## 备选方案

- **按数据归属（轮回级 / 账号级）分两组** — 否决：把能点的和不能点的混在一起。
- **只读层用点按查看详情** — 推翻：违反既有承重手势判据。
- **为弹层另立一套禁用规格** — 否决：两种争抢都成立，规格应与抽屉相同。

## 后果

- **未裁定项**：只读层的形状（角标 vs 常驻一排小图标）归已排期的竖屏分区专场。
- `PowerData.Abilities` 不按启动式 / 被动式收窄，意味着两者共用同一字段、区分在呈现层。**这条只针对启动 / 被动这一根轴**：沿另一根轴（`UsableScene` × 异能档）该字段仍受一条加载期校验约束——纯战斗外条目不得挂触发式异能，因为战斗外没有任何广播点，见 `../systems/character-profile/power/_index.md`。
- 神通 / 法则在这一层以技能条目呈现，不用卡面（→ `ADR-0083`）。
