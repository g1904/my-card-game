# ADR-0090 — 敌方套牌由「功法 + 层数」展开，敌我同源构筑；层数逐条固定，赋级只动 `baseMomentum`

- **状态：** Accepted
- **日期：** 2026-08-25
- **来源：** handoffs/2026-08-25-enemy-deck-from-techniques-and-ai.md

## 背景

`EnemyData` 的构筑面原是一个**直接卡牌列表**。这使敌人的牌与玩家可习得的功法体系完全脱钩：敌人打出的牌玩家在图鉴里查不到出处，而「见过这个敌人」也不构成对任何功法的了解。

同时，赋级（`±2` 带）如何作用于敌人套牌尚未定：是让层数随赋级浮动，还是只动数值？

## 决策

**敌方构筑面 = 功法引用列表 `TechniqueRef[]`（`TechniqueId` + `Tier`）+ 游离散牌 `Id` 列表**；样本卡组 = 功法展开产物 ∪ 散牌。敌我**共用同一 `CultivationTechniqueData` 类型与同一注册表**。战斗内照旧**不感知功法**。

**层数在 `EnemyData` 上逐条编排为固定值，随赋级只动 `baseMomentum`**——`EnemyLevelRange` 与层数**不建立机械对应关系**。

**「赋级对齐 / 风味替换」的样本卡组物化改写整条取消，`OverridesDeck` 字段删除**；敌方定制性改由 `Pool == Enemy` 的敌方专用功法承担。产出缩放与玩家同因，**不设敌方专属隐藏乘区**。

条目之间的层数散布立**内容编排护栏**（篇章基准档 ± 1 档，落 `/audit-content` 只报告不阻断）。

→ `systems/enemies/_index.md` 与 `enemies/common-properties.md`。

## 理由

同源构筑让敌人图鉴的词条②从风味文案升级为**指向真实功法条目**——见过这个敌人就见过这几门功法（→ `ADR-0096`）。这是「信息靠遭遇获得」这条支柱的一次兑现（→ `ADR-0093`）。

层数不随赋级浮动，是因为**层数是严格升级、按定义就是第二条强度曲线**：`±2` 赋级带之所以能充当难度刻度，前提正是「赋级只动一条曲线」（→ `ADR-0044`）——层数浮动会在等级标注之外再开一条不可见的强度轴，那条刻度当场失效。

保留散牌一格：纯功法列表与玩家侧「卡组 = 功法展开的牌 ∪ 游离散牌」**不同构**（→ `ADR-0054`），且会让卡组规模只能按「功法数 × 每层卡数」整组增减，废掉「卡组规模是一条疲劳编排旋钮」（→ `ADR-0052`）。

## 备选方案

- **直接卡牌列表** — 推翻：与功法体系脱钩，图鉴无出处可指。
- **纯功法列表、不留散牌一格** — 否决：与玩家侧不同构，且废掉卡组规模旋钮。
- **层数随赋级浮动、作为敌方强度的唯一表达面** — 推翻：第二条强度曲线。
- **保留一条作用于展开产物的二次改写** — 否决：会同时保留两条强度旋钮。

## 后果

- **被接受的代价正面写下**：散牌不属任何功法，「敌人卡组 = 玩家可习得内容」留有一小块例外。
- `KeyCardIds` 与「不得含 `Pool == Character`」的校验基准取展开后的并集。
- `OverridesDeck` 已从全库删除；原稿「其语义不受影响」被细化为「语义没变，但已指向空集合」。
