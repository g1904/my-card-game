# ADR-0041 — 本作不存在凭空生成的牌：一场战斗内的卡牌集合是闭集

- **状态：** Accepted
- **日期：** 2026-08-05
- **来源：** handoffs/2026-08-05-level-band-stack-save-and-token-free-deck.md

## 背景

「加入手牌」类效果在同类作品里通常靠 token（运行时新造的卡牌实体）实现。token 会引入一整套配套问题：它算不算卡组的一部分、离开战场后去哪、存档怎么表示、图鉴收不收录。

## 决策

**本作不存在凭空生成的牌（全局硬约束 · 承重）。** 「加入手牌」类效果的牌**一律来自既有的区**（抽牌堆 / 弃牌堆 / 卡组）——**没有 token、没有运行时新造的卡牌实体**。

推论：**一场战斗内的卡牌集合是闭集**。

三区的 `Id` 序列与 `instances` 全集的关系、读档校验 → `systems/services/combat-service.md`；卡组构成 → `systems/character-profile/deck/_index.md`。

## 理由

闭集使战斗存档可以只存「三区各有哪些 `Id`」，不需要为运行时新造的实体设计序列化。它同时让一条读档断言成为可能：**三区 `Id` 序列的并集 ≠ `instances` 全集即为损坏**——有 token 就写不出这条断言，因为并集本就该随时增长。

## 备选方案

- **借入 MTG 的 token 概念，`CardType` 增第七类** — 否决：连带引入放逐区、token 存档表示与图鉴收录三个新问题，而效果设计不依赖它。

## 后果

- 读档校验 ④（三区并集 = `instances` 全集）以本条为唯一依据；推翻本条即作废该断言。
- `CardType` 停在五类（→ `ADR-0019`），不为 token 预留。
- 「加入手牌」类效果的设计空间因此收窄为「从哪个区取、取哪张」，这是有意的收窄。
