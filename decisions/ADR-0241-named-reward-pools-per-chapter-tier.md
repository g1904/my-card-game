# ADR-0241 — 奖励池 = 篇章 × `combatTier` 九个具名成员清单；厚薄轴就是换池

- **状态：** Accepted
- **日期：** 2026-09-09
- **来源：** handoffs/2026-09-09f-event-reward-and-hidden-stat-orchestration.md · handoffs/2026-09-09d-combat-rarity-and-reward-scale.md

## 背景

Combat 三档（`Practice` / `Standard` / `Finale`）的奖励厚薄要有差别，但既有结构里能表达差别的地方不止一处：换池、换稀有度权重表、换抽数。选错会引入第二条机制轴。

同时，「池」到底是什么载体一直空着：一组过滤器，还是一份成员清单。

## 决策

**一、厚薄轴 = 换池，不换权重表、不换抽数。** 三档共用同一条生成路径，差异只在 `RewardPoolId` 与优势档 `Tier` 两格。

**二、池的编排维度 = 篇章 × `combatTier`，共九个具名池**，id 形态 `reward.<chN>.<tier>`（`reward.ch1.practice` · `reward.ch1.standard` · `reward.ch1.finale` · ……），与既有点分小写内容 id 同构。

**三、池是一份逐条编排的具名成员清单（`.tres` 编排面），不是一组过滤器；同一个内容条目可以同时属于多个池。**

**四、期望价值 `V` 是可复算的书写口径、不进 `.tres`：**

```
V(池, 篇章, 优势档) = Σ_i w_i × BasePrice(RarityTier_i) × k(族_i) / Σ_i w_i
每场战斗的可选奖励期望厚度 = 挂池率 × 候选数量 3 × V(池)
```

→ `systems/balance.md` · `systems/services/combat-service.md`。

## 理由

- **换池正是既有结构唯一已经预留的档位差异旋钮**；`Practice` 档对神通的整族排除（→ `ADR-0169`）与它是同一条轴上的两个刻度（族排除 = 池成分的极端形态），故不引入第二条机制。
- **换权重被否**：权重表的分表维度是「按用途」，`combatTier` 是「由哪条路径给出」而非「什么用途」，加这一维与分表判据同形相抵。
- **成员清单被选中有两条硬理由**：`EncounterSpec` 携带的是一个 `string` id，而**过滤器组装不出 id**；且取池不足的加载期断言（→ `ADR-0073` 闸一）要求池在加载期是**可数出条数的确定集合**。
- 一条目可属多池，使首批**全库约 48 条内容即可铺满九个池**（→ `ADR-0242`）。

## 备选方案

- **换稀有度权重表（按 `combatTier` 再分一维）** — 否决：与权重表的分表判据同形相抵。
- **换抽数（`Practice` 抽 2 / `Finale` 抽 4）** — 否决：与「候选数量恒 3」冲突，并牵动战后奖励屏布局。
- **池 = 一组过滤器** — 否决：组装不出 id，且加载期数不出条数。

## 后果

- **三档厚薄由三个承担者表达**：① 挂池率（`Finale` 恒挂 · `Standard` 约三成 · `Practice` 偏低）② 同一档位上池里放什么条目（族构成与价位构成）③ `Practice` 池的神通族整族排除。
- **厚度比的目标形状**与基础奖励灵石量的三档偏置同向（`Practice` 薄 · `Standard` 基准 · `Finale` 显著厚）；`Finale` 因「每章一次 + 恒挂池」比灵石那一半更厚，是被接受的取向。
- **三档 V 的具体数值待内容铺开后按上式核算**——池成员与权重表两侧都还只有初值时给出精确比值，只会得到一个不可复算的数字。
- 措辞纪律：`Practice` 池须写成条件口径（「`Practice` 档条目**若**挂池，取该篇章的 `practice` 池」），不得写成「`Practice` 档的战斗从这个池抽」——挂不挂池是另一条轴（→ `ADR-0240`）。
