# ADR-0027 — `LocationCodex` 的显影粒度 = 顶点级解锁，连边是呈现层派生

- **状态：** Accepted
- **日期：** 2026-08-22
- **来源：** handoffs/2026-08-22-locationcodex-edge-granularity.md

## 背景

六本图鉴中 `LocationCodex` 是唯一一本以**图**为对象的：它既要记地域顶点，又要「记连边」。而「记连边」的粒度一直只写着「本库现按顶点级理解，待确认」——两种读法（去过 A 即显影 A 的全部邻接 · 只记玩家真正走过的那条边）在存档形态上完全不同，且它同时决定两条已宣告的设计目标（跨轮回重建整张图 · 提前两步规划路线）能否兑现。粒度不定，图鉴屏与 `locationCodex` 的存档表达都写不下去。

## 决策

**显影粒度取顶点级解锁：去过 A 即显影 A 在 `locationMap` 上的全部邻接（含玩家从未去过的地名）；连边不进存档，由呈现层从单份 `LocationMapData` 现算。**

- 存档侧 `locationCodex` 仍是**顶点 `Id` 的集合**，一条 `CodexEntry(Id = LocationData.Id)` 对应一个去过的地域。**存档 / 契约 / 校验 / 迁移增量全为零。**
- 呈现三态：**已解锁**（`Id ∈ locationCodex`，名字 + 完整词条）· **边缘**（不在集合内、但在某条至少一端已解锁的边上，只给真实地名 + 灰态 + 词条锁着）· **不可见**（顶点与边都不画）。
- **显影半径固定 1 跳，不设旋钮。**
- 呈现层派生取图走 `AllIncludingDisabled()`，纯读、可在图鉴屏打开时缓存、不进 `_Process` 热路径；`Frontier` 顶点的 `LocationData` 解析不到 → `PushWarning` + 跳过（可选缺失）。
- **完成度只计已解锁顶点**，边缘顶点不计、边不计。

派生式、三态表与触控 / 翻译键要求 → `systems/player-profile/codex/_index.md`；`locationCodex` 的存档形态 → `systems/player-profile/codex/common-properties.md`。

## 理由

- **裁决依据是「零存档增量」对「为一本图鉴破族级约束」，不是手感取舍。** 「只记走过的边」要让存档表达**边**这个对象，三条出路各破一条承重约束：把 `Id` 编成复合键要为一条「必需缺失」级校验单开例外、并让体积护栏对这一本恒常误报；把边升格为一等内容条目要改写「单份 `LocationMapData` 持无向边集」的载体形态、补一批加载期校验，且顶点仍需另记 ⇒ 一本图鉴装两类对象；在 `CodexEntry` 上加一格邻接表则该格对其余五本恒为空，正是「不落成单表 + `Kind` 字段」判据所拒绝的形态。
- **它是两条已宣告设计目标的分水岭。** 顶点级下重建全图只需玩家的已访顶点构成图的一个**顶点覆盖**；边级则要求踩遍每一条边，而 Travel 非常驻可选项、另有 20% 档把玩家随机推走 ⇒ 有限轮回内边覆盖近乎不可完成。「提前两步规划路线」尤其直接：提前两步的信息就是「B 又通向哪里」，边级下要走过 B→C 才有，而那时已不需要它。
- **「提前看见地名」不是泄露。** 地名之外什么都不给——事件类型倾向 / 敌人池 / `EventCountLimit` 全部锁在词条里。看见名字只带来「那边还有路」，不带来「那边有什么」。
- **半径 1 跳恰好等于「提前两步规划路线」所需的信息量**；半径 2 会让图在两三次轮回内基本发完。半径是约束面参数，与 80 / 20 不可被剧本调制同理由。
- **边的显影随顶点自动成立**：无向图下一条边只要任一端已解锁即画出，不需要为边单独记状态。

## 备选方案

- **边级粒度（只显影走过的边）** — 见理由第一、二条：要么破族级约束，要么使两条设计目标落空。
- **边缘顶点显示「地名 + 出度」或「？」占位** — 出度会泄露结构信息、占位符则连「那边还有路」这点导航价值都不给。
- **显影半径 2 / 做成可调旋钮** — 半径 2 使全图两三轮回内发完；开成旋钮则把一个约束面参数误置为可调数值。

## 后果

- **落地面一格不动**：`CodexEntry` 字段面 / `CodexUnlock` / `CodexKind` / `ProfileChangeSpec` 列 / 触发点 / `ProfileManager` 校验行 / 存档 schema 版本 / 后端配合**增量全为零**，全部改动落在呈现层的一段只读派生与一条口径明文。加载期校验不新增：已有的出度 ≤ 5 / 出度 ≥ 1 / 连通 / 无自环重复边四条恰好也是本方案渲染正确性的前提。
- **代价明写**：玩家记住的不只是去过的顶点，还有它们 1 跳邻域的地名 ⇒ **改连边所清空的账号级资产比边级粒度更大**。这与「`locationMap` 的稳定性是对玩家的隐性承诺」是同一条纪律，只是量级更明确。
- **边缘态只给名字，把词条深度与本条解耦**——`LocationCodex` 的其余词条深度（风物文案 / 事件类型倾向 / 敌人清单 / `EventCountLimit`）可独立裁决，仍开放。
- **两项呈现层细节仍标 `[采纳推荐 — 待复核]`**（边缘顶点的显示程度 · 半径不设旋钮），已按推荐落笔、留在 `open-questions/02-event-options.md`。两项均为纯呈现层、可逆、不影响存档，复核结果不动本 ADR 的主结论。
- **`LocationCodex` 的呈现形态不同于其余五本**（一张逐步显影的图 vs 列表 / 网格），六本图鉴的入口与浏览形态归图鉴呈现专场（`ux/screen-flow.md`）。
