# ADR-0206 — 回合进度与道念差是邻接两行，绝不合成「还追得回来吗」的复合指示

- **状态：** Accepted
- **日期：** 2026-09-08
- **来源：** handoffs/2026-09-08-combat-portrait-layout.md · answer-logs/log-combat-portrait-layout.md

## 背景

回合进度与道念差在版面上空间邻接，把两者合成一个综合「追分可行性」指示是自然的排版冲动。

## 决策

**回合进度 = `TurnLimit` 个小格的一排点，格数由 `EncounterSpec.TurnLimit` 驱动、绝不写死 10**；当前格着色即回合归属方，另给对应一端头像一圈呼吸描边作冗余编码。

**它与道念差是空间邻接的两行，绝不合成一个「还追得回来吗」的复合指示。**

## 理由

`ux/combat-ux.md` 两条：① 这样一个指示需要一个每回合期望产出模型才算得出，**而该模型的输入在 `systems/balance.md` 中明标为待实测校准的标定假设、不得作为承重依据**；② **它会替玩家算掉那本账**——「我落后 8 点、还剩 2 个回合」这本玩家自己算的账正是紧张感来源。

## 备选方案

- **合成一个复合指示** — 否决：两条理由如上。

## 后果

- 约束 UI 不得引入任何依赖期望产出模型的读数。
- 放弃了一屏内的「胜率 / 追分可行性」提示。
- 与 `decisions/ADR-0177-no-finale-distance-foresight.md` 同调而对象不同：那条管轮回尺度的前瞻，本条管战斗内的前瞻。
