# ADR-0264 — barter 的两格护栏：对价按档差 `产出物 RarityTier ≤ 支付物 RarityTier + 1`，条数 ≤ 1 条 / 店

- **状态：** Accepted
- **日期：** 2026-09-10
- **来源：** handoffs/2026-09-10-item-family-supply-guardrails.md · answer-logs/log-item-family-supply-guardrails.md

## 背景

以物易物（barter）此前**一个护栏都没有**：它不读定价表、不带折扣、不经取池、不计入槽位总数上界，加载期也不设条数上界。这意味着内容侧可以写出「付一件 Tier1 法宝换一件 Tier5 古宝」的格子，也可以在一家店里塞满 barter 格。

## 决策

补两格**编排口径**护栏，两格均为 `/audit-content` 汇总、**只报告不阻断**，**都不落加载期硬校验**：

- **对价按档差核算：`产出物的 RarityTier ≤ 支付物的 RarityTier + 1`。**
- **条数 ≤ 1 条 / 店。**

「不进闸 ① 核算 · 不计入槽位总数上界 · 加载期不设条数上界」三条**原样保留**，改写的只是「不另设 barter 条数上界」那一句的理由。
→ `systems/adventure-event/exchange/common-properties.md`。

## 理由

**档差口径而非价值比**（`systems/adventure-event/exchange/common-properties.md`）：barter 的支付面硬校验为法宝一族 ⇒ 分母恒为灵石，而产出物可以落在收仙玉的格上——写成「基准价之比」那个比值**就是一个灵石 ↔ 仙玉的兑换率**，而「售出侧同币回收、因而不产生事实汇率」这条纪律由结构闭合，不得由一个书写口径给它开缺口。档差另有两个好处：两个枚举值机械可比、玩家也读得出「至多换高一档」；族系数变动时它自动跟随。

**≤ 1 条 / 店**：barter **不可逆地损失一件具体法宝、须就地二段确认**，一店多格会把这个仪式感稀释成清单。

**两格都不落硬校验**：它们是编排口径而不是不变式——「贵人相赠」是合理例外。这与 `SellRatePercent <= PackSellRatePercent` 落硬校验的差别在于：那一条的坏形态没有任何合理解释，这一条有。

## 备选方案

- **价值比公式（`BasePrice` 相除 ≤ 2.0）** — 否决：给「不产生事实汇率」开书写口径级缺口；且 ≤ 2.0 在族系数下并不等于「一档跃升」（付 Tier2 法宝换同档古宝即 2.5 > 2.0，换高两档散牌只 3.0）。
- **不设条数上界** — 否决：一店多格稀释二段确认的仪式感。
- **两格落加载期硬校验** — 否决：会把合理例外一并挡住。

## 后果

- **已知代价（被接受）：** 同档跨族的价值差（法宝 → 古宝在基准价上是 ×2.5）**不被这条口径看住**，由「≤ 1 条 / 店」与就地二段确认承担。
- `decisions/ADR-0126-exchange-barter-payment.md` 的支付侧形态与 `Holds(...)` 前置拒绝不受影响，本条只补编排层护栏。
