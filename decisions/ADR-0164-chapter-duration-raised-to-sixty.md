# ADR-0164 — 篇章目标时长上移至三章均值约 60 分钟，整链沿 λ 层重算

- **状态：** Accepted
- **日期：** 2026-09-06
- **来源：** handoffs/2026-09-06-chapter-duration-rescale.md · answer-logs/log-chapter-duration-rescale.md

## 背景

篇章目标时长原定 30–40 / 35–45 / 45–55 分钟，产品承诺写成「移动端一个时段」。按该口径反推出的事件数偏少，而一个篇章要装下五类事件、构筑推进与一场 Finale——每类事件出现次数被压到「玩家还没建立起对它的预期，篇章就结束了」。时长是这条链的**唯一自由端**：事件数、λ、21 格定价表、经验曲线、`S(c)` 全部由它反推。

## 决策

**篇章目标时长上移为 45–55 / 50–60 / 60–70 分钟（`T_c` = 55 / 58 / 68），三章均值 ≈60 分钟。**

**整链沿「时长 → 事件数 → λ → 21 格定价表」重算**，重算发生在 **λ 层**（λ = 15 / 17 / 44），不字面缩放已取整的格子。连带 `S(c)` 与经验阈值曲线同批下调，以保住「25 格商店定价表不设篇章维」这条既定纪律。

**产品承诺改写为「一个长时段，中途可随时存档退出续玩」**，并**如实写下代价：通勤 / 碎片时间不再是目标场景**——单次坐完一个篇章需要约一小时。

逐格取值、八项反推输入与两个待实测校准的标定假设 → `systems/balance.md`。

## 理由

- **时长是反推链的唯一自由端**，改它才能同时松开事件数与每类事件的出现次数；改下游任何一格都只是局部补丁。
- **重算必须发生在 λ 层**——`ADR-0156` 已明令否决「把已取整的格子字面放大」：那会让 ch1 → ch2 的变化率一位不改，量纲改动买的唯一东西（分辨率）当场落空。
- **承诺改写是时长上移的直接后果**，不是可选项：把一小时的体验继续宣称为「一个通勤时段」，会让 `vision/scope.md` 与实际数值互相矛盾。
- **`S(c)` 与经验曲线下调而非给定价表加篇章维**：加维会让服务侧从「只读当前篇章那一行」变成为分章写分支，撞既有的三处约束。

## 备选方案

- **字面缩放 21 格定价表** — 否决：`ADR-0156` 明令否决的备选，重算必须在 λ 层。
- **保留 `C1 ≳ 140` 那句** — 否决：经用户裁决承认为算错，按八项输入自洽重算为 `C1 ≳ 83`（≈ ch1 预算 8%）。
- **同批上调篇章重试上限** — 否决：上限是次数不是时长，不改，只记一个实测复核点。

## 后果

- **`vision/scope.md` 的目标场景收窄**——碎片时间退出目标场景，换来每类事件出现次数足以建立预期。
- **21 格定价表、事件数（114 = 35 / 36 / 43）、经验曲线（79 / 247 / 391）、`S(c)`（10 / 23 / 39）全部为本次重算的输出**，改时长即须整链重跑，不得只改一处。
- **两个标定假设（熟练玩家败率 · `E[道念差]`）仍标「待实测校准，不是设计结论」**，不得引为承重依据。
- **数值副本失真须同批清理**：`terminology.md` 与 `systems/adventure-event/common-properties.md` 仍留旧区间（30–40 / 35–45 / 45–55），权威在 `systems/balance.md`。
- 受约束的文档：`systems/balance.md` · `vision/scope.md` · `systems/game-progression.md` · `systems/player-profile/player-power/_index.md` · `decisions/ADR-0156-lifespan-cost-proportional-to-time.md`。
