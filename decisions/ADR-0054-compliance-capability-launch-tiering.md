# ADR-0054 — 合规四项能力全部首版必备，可后置判据 = 是否需要对存量账号追溯

- **状态：** Accepted
- **日期：** 2026-09-07
- **来源：** handoffs/2026-09-07-compliance-launch-tiering.md · answer-logs/log-compliance-launch-tiering.md

## 背景

合规域的形态已全部落笔（`contracts/compliance.md` 六端点 · `operations/compliance-ops.md` 全套执行形态），但「首版必须具备哪几项合规能力」一直未分级。它不动任何契约报文，卡的是 `operations/deployment.md` 的上线前置清单与 `vision/scope.md` 的 In scope 能否写实。分档必须有判据，不能按「重要程度」这种直觉。

## 决策

按**驱动力**分三档（T0 法规硬下限 · T1 渠道过闸下限 · T2 可后置增强项），并把「能否落 T2」收敛为一条判据：

> **后置之后再补，是否需要对存量账号做一次追溯动作？需要 → 不得后置。**

分级结论：**实名核验（T0）· 防沉迷时段（T0）· 账号注销（T1）· 数据导出（T0）四项全部首版必备，不分档**；可后置的是各项的**增强项**，不是能力本身。

`operations/deployment.md` 的上线前置清单据此**拆成两份**：实名 + 防沉迷追加进「首个真实账号建号之前」（过闸断言写成**可验证的运行时事实**，不是「已完成开发」）；注销 + 导出落新增的第二份「首次面向公众发行之前」，与域名备案 / 国内发行资质同批推进。两份的未就绪处置相同：**推迟上线，不降级放行**。

首版发行形态定为**中国大陆正式发行**（iOS / Android 国内渠道 + 微信）。

## 理由

- **判据不是新造的**：`operations/deployment.md` 的发布前置清单四项用的就是这一条（「首批真实账号落地的那一刻，『线上无真实账号数据』这个前提永久失效」），而 `operations/compliance-ops.md` 已用同一判据把年度日历录入**排除在**那份清单之外。正反两个用例都已在库内，本次只是复用到合规域。
- **实名**是防沉迷的唯一数据源（`contracts/compliance.md` §7），不上实名防沉迷在结构上不成立；后置会积累一批未实名存量账号，启用之日 `compliance.realname_required` 对全体同时成立，是一次全量拦截潮——而拦截只在 `signin`、求值顺序写死（`ADR-0037`）、**没有任何灰度旋钮**。
- **防沉迷**不与实名拆档：实名一旦在线，服务端就已经知道某账号未成年，知情而不限制的合规敞口**大于**两项都不上；它也是四项里唯一会在会话中途生效的能力。
- **注销**的理由由 `contracts/compliance.md` §1 直接给出（PIPL 删除权 + 商店审核查「App 内可注销」）；且后置有不可逆连带——墓碑行的存在使「`account_id` 存在」不再等价于「账号可用」，越晚做需要回头改的读路径越多。
- **拆成两份而非同一份内分两节**：现清单的成立前提被文档自己写死为「四项共用同一个不可逆时刻」，注销 / 导出不共用它，同一份内分节会稀释那句承重前提。

## 备选方案

- **注销 / 导出后置到上线后补** — 违反同一条判据的第二半（渠道过闸下限），且注销的墓碑语义越晚做改动面越大。
- **按「重要程度」分档** — 无判据，每次讨论都要从头吵一遍。
- **在同一份前置清单内分两节** — 稀释该清单「四项共用同一个不可逆时刻」的承重前提。

## 后果

- `operations/deployment.md` 由一份前置清单变为两份，各自的过闸断言须是可验证的运行时事实；未就绪一律推迟上线（沿用 `ADR-0042` 对微信资质的处置）。
- `vision/scope.md` 的 In scope 据此写实四项能力全部在首版范围内。
- `systems/account.md`「合规域的服务端保证」补一组时段判定保证 P1–P5（对 `operations/compliance-ops.md` 既有形态的机械对位，无新形态）——防沉迷既判 T0，这个空洞会在 derive 时立刻显形。
- **契约面零改动、存档 schema 零改动、跨库零承接项。** 本决策只定时点，一个形态字段都不动——这正是 `operations/compliance-ops.md`「形态与上线时点是两件事」预设的用法。
- 遗留一条**挂账项**（须以真实过审要求核实，不是设计待答）：实名核验是否另需对接主管部门的实名认证系统。本库对该接入的沉默是尚未核实的空白，**不是「已确认无此义务」**。登记在 `open-questions/02-account-compliance.md`。
