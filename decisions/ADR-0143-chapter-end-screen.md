# ADR-0143 — 新增 `ChapterEndScreen`：一屏三变体，ch3 变体即元婴通关证书

- **状态：** Accepted
- **日期：** 2026-09-05
- **来源：** handoffs/2026-09-05-chapter-end-screen.md

## 背景

一次轮回走到尽头有两条出口。失败侧（`defeated` 三因）已有 `CycleEndScreen`；**成功侧（`completed`）全库无明文**。而元婴界面——整轮回通关的终局展示面——只定了三句：它是一块类似通关证书的终局界面、它是寿元 `+5000` 这次最终更新的读者、统计区落两个数；字段与形态未定。成功侧不定，`/derive-requirements` 无从写验收标准，元婴界面也无处落。

## 决策

**新增 `ChapterEndScreen`，一屏三变体，变体轴取 `chapter`（1 / 2 / 3），ch3 变体即元婴通关证书。轮回收尾族因此是两屏，`CycleEndScreen` 一格不动。**

- 形态：一屏全屏（安全区内）· 不进屏幕栈 · 无返回 · 非弹层；触发 = `CompleteChapter()` 提交完成之后；
- **唯一主按钮「返回主菜单」**，出口不放「继续下一篇章」；
- 三变体差异恰是四格（标题键 · 定性文案条目 · 解锁行有无 · 统计区有无），出路 / 布局骨架 / 主按钮 / 结果三行全同；
- 数据源 = `CompleteChapter` 内组装的只读值摘要 **`ChapterEndSummary`**，与 `DefeatCharacter` 的摘要逐条同纪律（只含值类型 + 内容 `Id` + 文案条目 `Id`，不持 `CharacterProfile` 引用，不落存档、不进 `PlayerProfile`）；
- **时点两条硬要求**：在境界寿元增量施加**之后**（本屏正是 `+5000` 这次最终更新的读者），且在 `TeardownCycle()` 与任何角色数据处置**之前**组装；
- 翻译键走 `CYCLE_` 分区扩容，不新开 `CHAPTER_`；
- **零新增存档字段、零新增存档点、零 schema bump、后端零配合。**

逐格变体表与呈现清单 → `ux/screen-flow.md`、`systems/services/life-cycle-service.md`。

## 理由

- **不是一屏五变体。** 拿 `CycleEndScreen` 自己写下的收敛门槛去量，成功侧与失败侧的差异不止两格，且其中两处是**互相否定的承重纪律**——失败侧「本屏不呈现本轮回的账号级收获」vs 元婴**必须**有统计区；同一张变体表内同时写「零呈现」与「必须呈现」，读者无从判断哪条是该表的纪律。另两处：剩余重试行在成功侧没有可显示的事实（通关不消耗重试次数）；演出口径相反。
- **不是三屏。** 元婴就是 ch3 的 `CompleteChapter()`——同方法、同状态、同收尾链、同一套触控与安全区约束；三份等价布局各自维护必然漂移成三种观感。元婴独有的东西恰好可表达为变体表里的两格开关。
- **出口不放「继续下一篇章」**：逐字复用 `decisions/ADR-0148-cycle-end-screen.md` 否掉「再试一次」的理由——主菜单是既定唯一开局入口，三道闸全挂在「开始新轮回」上，第二个开局入口要么复制三道闸（必然漂移）要么绕过它们。附带理由：`completed` 后起手是读档续章，而「哪个角色、哪个篇章」的选择面本就在主菜单侧。
- **变体轴取 `chapter` 而非「是不是最后一章」**：前者是摘要里本就有的一格、可机械判定；后者要在呈现层再写一次「3 是最后一章」的常量。
- **`CYCLE_` 扩容不新开分区**：分区划的是界面，轮回结束屏与篇章结束屏是同一界面族（同一收尾链、同一骨架、共用结果行标签与主按钮）；单开一个 CSV 收益为零，代价是标签与主按钮要么跨文件引用要么复制两份。

## 备选方案

- **把成功侧并进 `CycleEndScreen`，做成一屏五变体** — 否决：差异超出该屏自陈的收敛门槛，且会让同一张表同时写下两条互相否定的纪律。
- **元婴另立第三屏** — 否决：与 ch1 / ch2 同方法同链路，三份等价布局必然漂移。
- **通关证书做独立回看入口** — 否决：两个账号级数字在玩家档案屏常驻可读即为回看通道；独立回看要新增账号级字段、新增屏、新增 `user://` 文件。
- **统计区展示更深的账号级数据** — 否决：只用已定字段，据此零新增字段、零 schema bump 成立，`PlayerStatistics` 首批清单不成为硬前置。

## 后果

- 「通关」二字口径分离：ch1 / ch2 变体一律用「突破」，「通关」只留给 ch3 变体与统计区——状态机的 `completed` 是**篇章**通关，统计侧的「通关」是完成整个轮回，本屏是唯一同时呈现两者的界面。
- 允许一次入场演出，但复用既有语汇（标题淡入 + 一次短音效 + 全屏任意触点即跳过 + 无震动）；演出只覆盖标题与定性文案入场，结果行 / 解锁行 / 统计区不做逐行动画。
- 本屏商业化零入口零文字、残卷零呈现、成就零呈现（结算在主按钮之后才跑）、图鉴零呈现、常驻同步指示可见。
- **`completed` 是否清理角色数据本次不裁定**——摘要时点写成「在 `TeardownCycle()` 与任何角色数据处置之前」，该要求在两种读法下都成立；库内两处措辞的矛盾另立待答项跟踪。
- 因此必须这么写的文档：`ux/screen-flow.md`（屏形态 · 三变体表 · 数据源）· `systems/services/life-cycle-service.md`（`ChapterEndSummary` 与时点两条硬要求）· `systems/services/plot-manager.md`（解锁行取篇章名的既有键复用）· `ux/error-and-blocking-ux.md`（本屏不新增任何阻塞面）。
