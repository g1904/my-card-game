# ADR-0074 — 凡可调数值一律住平衡资源 `.tres`；本库不存在「服务配置」这一层

- **状态：** Accepted
- **日期：** 2026-08-22
- **来源：** handoffs/2026-08-22-band-boundary-config-placement.md

## 背景

赋级带边界 `(−2, +2)` 要住在哪？三个候选：服务上的 `[Export]` 字段（Godot 检视器可调）、并入 `CombatRulesData`、或单开一份平衡资源。

这个问题的一般形式是：本作有没有「服务配置」这一层——即那些不算内容、但又需要可调的数值。

## 决策

**「服务配置」这一层在本库不存在：凡可调数值一律住平衡资源 `.tres`。**

赋级带边界与带内分布权重表**同住一份平衡资源 `EnemyLevelingData`**（三章各一行 `EnemyLevelRange`）。

**不设 `GlobalBalanceData` 兜底大表**：平衡资源按**三问判据**（① 消费者是谁 ② 覆写纪律是什么 ③ 有没有跨字段不变式）逐份切——纪律相反 ⇒ 必须分开；有跨字段不变式 ⇒ 必须同住一份。**准入边界：消费点早于 `LoadAll()` 的旋钮不进注册表**（写死为常量并如实标注「不可线上调」）。

平衡资源的注册与取用 → `ADR-0030`；三问判据全文与逐份落点 → `systems/balance.md`。

## 理由

`[Export]` 服务配置有三条独立的致命问题：**绕开 overlay 热更**（改值要发版）、**绕开启动期强校验**（合并后全量校验只看内容层）、**制造第二种「可调数值住哪」的答案**（此后每个数值都要先问它属于哪一类）。

边界与权重**同住一份**：它们之间有跨字段不变式（权重表的定义域就是边界区间）。分放两份时不变式破了就**静默错位**——权重表在一个不存在的区间上分布。

并入 `CombatRulesData` 被否是因为消费者不同（赋级发生在事件生成期，不在战斗内）且**覆写纪律相反**。

## 备选方案

- **`[Export]` 服务配置字段** — 否决：三条独立问题，见理由。
- **并入 `CombatRulesData`** — 否决：消费者不同、覆写纪律相反。
- **边界与权重分放两份** — 否决：跨字段不变式破了即静默错位。

## 后果

- 平衡资源经 `Content.Single<T>()` 取，调用方不写 `Id` 字面量（→ `ADR-0030`）。
- 平衡资源**切成几份**的三问判据（消费者 / 覆写纪律 / 跨字段不变式）与「不设兜底大表」已落在 `systems/balance.md`「不设 `GlobalBalanceData` 兜底大表」一节（2026-08-28 补齐），该处是判据的权威落点。
- 代价如实记下：短期内会出现若干份字段很少的小资源，且每份都要各自命名；这个代价被接受。
- 新增可调数值时不必问「住哪一层」，只问「归哪一份平衡资源」。
