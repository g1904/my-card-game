# ADR-0055 — 角色是有身份的内容条目 `CharacterData`，不是程序化生成的空白人

- **状态：** Accepted
- **日期：** 2026-08-12
- **来源：** handoffs/2026-08-12f-cultivation-technique-deck-building.md

## 背景

roguelike 的角色可以是「一个空白起点 + 随机初始配置」，也可以是「一份有身份的模板」。前者省内容、后者给辨识度。本作既然把构筑单位抬到功法这一层（→ `ADR-0054`），起手配置就不再是「几张随机牌」，而是「你是谁」。

## 决策

**角色是有身份的模板，不是程序化生成的空白人（承重）。** 角色升格为内容条目 **`CharacterData`**，**每个角色自带一个神通（`CharacterPower`）与两门绑定功法**。

绑定功法**可弃置**——绑定说的是起手带着，不是永久锁定。

字段面与存档关系 → `systems/character-profile/_index.md`。

## 理由

有身份的模板让每一局有一个可辨认的起点，玩家的选择从「随机拿到了什么」变成「这次我玩谁」。它同时给了内容层一个自然的扩展面：新角色 = 一份新 `.tres` + 一个神通 + 两门功法，可加性成立。

「可弃置」是必需的：不可弃置就意味着卡组里永远有两门你可能不想要的功法，把身份从起点变成了枷锁。

## 备选方案

- **程序化生成的空白人 + 随机初始配置** — 否决：无辨识度，且与功法级构筑颗粒度不匹配。
- **至少保留一门绑定功法不可弃置** — 否决（08-12f）：见理由。

## 后果

- 角色模板池的形态（池规模 / 是否账号级解锁 / 能否重抽或指定）**仍是未决项**，它改写元进程压力模型。
- `CharacterData` 进入 `content/` 的类型登记表，条目按内容流水线产出。
- `CharacterProfile.id` 由客户端在轮回创建时生成 GUID，不用 `characterDataId` 作键——同一个模板可以开多个轮回。
