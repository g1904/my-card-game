# ADR-0045 — 寿元只跟踪 `lifeSpan` 单值：无上限字段、无上限截断

- **状态：** Accepted
- **日期：** 2026-08-06
- **来源：** handoffs/2026-08-06d-combat-open-questions-mass-closure.md

## 背景

承接失败惩罚与寿命流逝的那条资源线，最初按常规做法设计为「当前值 + 上限值」两格。但本作里境界突破要抬高它，而「抬高上限再回满」与「直接加一笔」在玩家可见行为上完全一致，只是前者多一个字段和一处截断逻辑。

## 决策

**上限字段的概念整体删除。** 角色只跟踪 **`lifeSpan` 单值**——无上限字段、无上限截断。

境界突破是**给 `lifeSpan` 加一笔**（炼气起始 100 / 抵达筑基 +100 / 金丹 +300 / 元婴 +500），而非抬高上限。

预算取值 → `systems/balance.md`；字段、两个扣减来源与终态 → `systems/character-profile/life-span.md`。

## 理由

上限字段的唯一用途是截断回复，而本作的回复来源稀少且都是定量给予——截断从不触发。一个从不触发的机制是纯负债：它要被存档、被同步、被校验。**加上界另有一笔更贵的代价**：它会引出「补满时用丹浪费」这一整类挫败感，而玩家把余量堆得很高是他自己攒来的容错、攒它要花事件位。

**mana 有上限字段而寿元没有，这处非对称必须连同理由写清**：mana 是**每回合重置的节奏资源**（上限即每回合可用量，是核心旋钮），寿元是**跨事件、跨篇章累积的容错资源**（没有「每回合回满」这回事）。不写清理由，日后极易被当作不一致而「顺手统一」，把寿元也拆成 `currentLifeSpan / lifeSpanLimit` 两字段。两列逐格的对照见 `systems/character-profile/life-span.md`。

## 备选方案

- **为寿元加一个上限字段以与 mana 对称** — 预先驳回：见理由，两者的资源性质不同，对称是假的。
- **境界突破抬高上限并回满** — 否决：与「加一笔」行为等价，多一个字段与一处截断。

## 后果

- 寿元归 0 = 角色终结，是 `DefeatReason` 之一。
- 回复幅度与来源分布留待统计校准，本 ADR 不定取值。
- 存档 schema 少一格；`ResourceElements` 表中 `LifeSpan` 行的 `Max` 列因此不设上界。
