# ADR-0139 — 未成年账号剩余可游玩时长：客户端只呈现不判定，阈值落数据资源

- **状态：** Accepted
- **日期：** 2026-09-05
- **来源：** handoffs/2026-09-05-backend-batch-client-obligations.md

## 背景

后端合规批量评审要求客户端呈现未成年账号的剩余可游玩时长。后端**刻意下发相对量而非绝对时刻**，正是为了免除客户端做本地时钟比较——本地时钟不可信，一旦客户端拿它做「还能不能玩」的判定，就等于把合规裁决权交给一个可被改的设备时钟。同时本库已有一条既定纪律「注销冷静期在主菜单零增量」，而本项要在主菜单加一处常驻指示，两者看起来相抵，须给出判据。提醒阈值是典型的待实测数值，硬编码即绕过唯一的配置层。

## 决策

**剩余可游玩时长在客户端是纯呈现：两级提醒 + 主菜单一处常驻指示，客户端不做任何「能否继续游玩」的判定。两级提醒阈值落数据资源、以秒计，初值 1800 / 600。**

- 数据源单点 = 合规 status 里的那一个相对量字段（仅未成年账号下发）；
- 阈值字段以**秒**计，与下发量同量纲、不做换算；初值 `1800` / `600`（30 分钟 / 10 分钟），待实测校准；
- 常驻指示**复用主菜单顶部同步指示同一条带的形态**，不新增第二处常驻 UI；**战斗内至多常驻指示、不弹窗打断**；
- 到点仍由既有的会话失效路径接住，客户端侧的倒计时永不决定能否继续游玩。

逐条呈现规则 → `systems/services/account-service.md`、`ux/screen-flow.md`。

## 理由

- **「呈现用的倒计时不属判定」须就地澄清。** 这条写在 `account-service.md`「四件不归它的事」旁——不写出来，「不比时钟」会被读成「不许显示」，而那正是本项要做的事。
- **阈值属可调数值。** 可调数值一律落数据资源，是本库既定纪律（`decisions/ADR-0074-balance-resource-is-the-only-config-layer.md`）；以秒存是为了与下发字段同量纲，消灭一处换算即消灭一类偏差。
- **与「注销冷静期主菜单零增量」不矛盾**：那是同一条判据的两侧——注销由玩家主动发起、心智明确，无须提示；剩余时长是玩家**不知情**的状态，不提示即等于突然被踢。
- **复用同步指示条带**是为了不让主菜单出现第二处常驻 UI 语汇。

## 备选方案

- **客户端按下发的绝对时刻做本地判定** — 否决：后端下发相对量正是为免除本地时钟比较；本地判定把合规裁决权交给可改的设备时钟。
- **阈值硬编码在呈现逻辑里** — 否决：绕过唯一配置层，一次实测校准就要发一次版。
- **战斗内弹窗提醒** — 否决：打断进行中的战斗，与本库「不打断进行中的事件」一致。

## 后果

- 零新增屏、零新增阻塞点、零存档 schema 改动；增量为数据资源上的两个阈值字段 + 主菜单一处常驻指示。
- 客户端不承担任何到点断流的责任，该责任完整留在后端的会话失效路径上。
- 因此必须这么写的文档：`systems/services/account-service.md`（数据源单点 · 阈值形态与初值 ·「倒计时不属判定」的就地澄清）· `ux/screen-flow.md`（主菜单常驻指示的位置与复用形态）。
