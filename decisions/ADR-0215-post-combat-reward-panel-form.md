# ADR-0215 — 战后奖励面板 = 全屏一屏纵向堆叠，绝不横滑；已处置项两键移除而非置灰

- **状态：** Accepted
- **日期：** 2026-09-08
- **来源：** handoffs/2026-09-08-combat-ui-elements.md · answer-logs/log-combat-ui-elements.md

## 背景

`decisions/ADR-0082-itemized-combat-rewards.md` 定了「逐项领取 / 跳过、不是三选一」的规则，但面板形态从未落地。

## 决策

**战后奖励面板 = 战斗流程内的全屏一屏**（不进屏幕栈、无返回键），三段（结果 / 强制 / 可选）+ 底部全宽主按钮。

**强制段必须展示。**强制 / 可选靠「有没有按钮」这个**结构差**区分，不靠颜色 / 图标。

**竖屏排布 = 纵向堆叠全宽行，绝不横滑。**

已处置项**就地置灰保留**（逐格映射 `picks`），**但两个按钮移除而不是置灰**，另以非文字状态标记表达终态。主按钮在仍有 `Pending` 时置灰并给一行说明。**与事件结算面板两屏顺接、不合并。**

## 理由

`ux/combat-ux.md`：**横滑正是「择一」的语汇**，而「三项各自独立可领、不是三选一」恰是这块的承重语义——用错语汇即在视觉上否定它。

强制段必须展示的依据：**失败侧的额外惩罚正是以负向条目包在 reward 内** ⇒ 不展示等于让惩罚静默发生。

两键移除的依据：灰态纪律要求灰格继续接收触控并给一条说明，而此处已成事实、**没有任何说明可给**，留灰键只会诱导点击。

## 备选方案

- **横滑排布** — 否决：语汇冲突。
- **已处置项两键置灰** — 否决：无说明可给。
- **与事件结算面板合并为一屏** — 否决：会让「计算归战斗、施加归生命周期」的分工在 UI 上糊掉。

## 后果

- 约束面板逐格映射 `picks`、不渲染空槽、不移入「已领区」；放弃了已处置行的控件位。
- 由此在 `ux/error-and-blocking-ux.md` 的灰态判据表补出一条边界：**暂时不可用 → 置灰并保留触控；已成事实、永不恢复 → 移除控件**。这是 `decisions/ADR-0142-grayed-state-is-visual-only.md` 的边界补齐，不是推翻。
