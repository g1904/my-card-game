# ADR-0029 — 时段规则集走不可变版本化发布，时区是规则集的一员

- **状态：** Accepted
- **日期：** 2026-09-06
- **来源：** handoffs/2026-09-06-trusted-server-clock.md · answer-logs/log-trusted-server-clock.md

## 决策

未成年时段规则做成结构化规则集 `playtime_ruleset`（时区 + 星期集合 + 时段区间 + 每日时长 + 日历），**逐条复用昵称词表的不可变版本化发布形态**（`operations/moderation.md`）。时区以 **IANA 名**写进规则集本身，既不是代码常量、也不落 `config_knob`。镜像内置 tzdata，并以**启动自检**解析规则集的时区名，解析失败即拒绝启动。生效时刻只有一个：**判定时读当前最高版本**，不做预约生效。

承重列与判定形态见 `operations/compliance-ops.md`「时区与时段规则集」；启动断言见 `operations/deployment.md`。

## 背景

时段规则不是一个可以就地改的开关：存量审计必须能回答「这一次拦截是按哪一版规则做的」。而规则里含时区、星期集合、时段区间等彼此耦合的项——任何把其中一项单独抽出去的形态，都会造出「改了一半」的中间态。

## 理由

- 把时区单独放进旋钮表会造出「时区改了但时段没改」的**半版本态**；同处规则集则一次发布即整体切换。
- 规则集与词表同量级，永久保留成本近似为零，而发布通道 / 留痕字段 / 回滚语义**全部已存在** ⇒ 零新增机制。
- 用 IANA 名而非固定偏移，今天等价，但任何带夏令时的扩展都不必改形状，成本为零。

## 备选方案

- 时区落 `config_knob` 单值旋钮 — 造出「时区改了但时段没改」的半版本态。
- 用固定偏移 `+08:00` — 今天等价，但扩展时要改形状。
- 支持预约生效 — 会引入一个自己也要判时刻的调度器，而运营在发布动作上择时的成本为零。

## 后果

- 时段规则的每一次变更都产生一个新版本号，存量审计因此可回答「按哪一版判的」。
- tzdata 成为启动前置：镜像必须内置，且解析失败是拒绝启动而非降级。
- 与 `ADR-0009`（flags 规则集不可变版本化）同构但对象不同，两条各自可被单独推翻。
- 日历作为规则集的一员随之受同一发布通道约束 → `ADR-0030`。
