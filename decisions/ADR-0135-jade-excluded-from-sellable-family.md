# ADR-0135 — 仙玉一格都不落可售出族，净产出敞口结构性关闭

- **状态：** Accepted
- **日期：** 2026-09-05
- **来源：** handoffs/2026-09-05-currency-acquisition-and-pricing.md

## 背景

定价表的每一格给出一个 `(Currency, BasePrice)`，币种与「族 × 稀有度」绑死。而**可售出 ⟺ `ExchangeGoodsKind == CharacterItem`** 是代码级常量判据，售出所得 = 同币回收、且回收价有 `Clamp >= 1` 下限。

三者叠加出一个泄漏：只要有一格 `CharacterItem` 收仙玉，任何**免费掉落**的仙玉计价法宝卖出即净产出仙玉。量级上这尤其要紧——仙玉的预期收入只有个位数（`J(c) ≈ 2 / 3 / 5`），而 3 枚定价 × 40% = 1.2 → **1**，一件就稳产 1 枚，占一章收入的 20–50%。这个量级上「统计校准把关」不可靠。

## 决策

**定价表的 `CharacterItem` 行五档全部收灵石；仙玉一格都不落该族。**

- 由此「售出产仙玉」在结构上不可能发生：不需要任何新机制、不需要统计盯防、不需要额外判断。
- 仙玉的唯一**主动**获取通道仍是稀有 AdventureEvent 产出（每章 1–2 次、单次 1 / 2 / 4 枚，频次载体为既有的 `SelectionWeightGrades.Rare` 档）；售出与储物袋随售是**同币回流**，不新增获取渠道。
- **代价如实写下：从此编排不出「以仙玉计价的法宝」**，包括补天丹类顶级消耗品——它们只能以灵石计价。

逐格币种分布、`J(c)` / `J_cum(c)` 与仙玉基准价的递进曲线 → `systems/balance.md`「货币产出与定价」；获取通道 → `systems/character-profile/currency.md`。

## 理由

- **结构性关闭优于统计盯防。** 在个位数收入 + `Clamp >= 1` 下限的量级上，任何依赖「事后统计校准」的把关都会漏；而把敞口关在币种分布这一格里，成本是零——定价表本就要逐格填币种。
- **它不引入任何新机制**：既有的两条判据（币种由格决定、可售出 ⟺ `CharacterItem`）交出的结果就是禁止，无需新增字段或校验。
- **「售出所得 = 同币回收，因而不产生事实汇率」这条既有结论随之闭合**（`systems/balance.md`）：币种在同一格上 ⇒ 卖出所得恒与买入同币，「灵石与仙玉完全不可兑换」由结构保证。

## 备选方案

- **允许仙玉落在 `CharacterItem` 行，靠内容审校与统计校准防泄漏** — 否决：在个位数量级上不可靠，且要长期承担一项盯防义务。用户在 2026-09-05 的评审中裁决取本方案。
- **给随售 / 收购加一条「仙玉计价商品不可售出」的特判** — 否决：需要新增一条判据，而它与「可售出 ⟺ `Kind == CharacterItem`」这条代码级常量判据并列，等于把一个已闭合的判据拆成两个。

## 后果

- 定价表 `CharacterItem` 行**永久全灵石**；仙玉只落在其余四族的高档位 → `systems/balance.md`、`systems/adventure-event/exchange/_index.md`。
- **永远编排不出以仙玉计价的法宝**（含顶级消耗品）。这是在「币种与族 × 稀有度绑死」这条既有代价（`decisions/ADR-0089-two-tier-currency.md`）之上再收一格。
- 储物袋随售（`PackSellRatePercent`）与商店收购（`SellRatePercent`）两条通道**都不可能产出仙玉** → `systems/character-profile/item/_index.md`。
- 仙玉的稀缺性表达由「稀有 AdventureEvent 出现频次」独家承载；调它只有一个旋钮。
