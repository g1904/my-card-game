# ADR-0031 — 寿元是按境界递增的预算、按事件成本递减；归 0 即角色终结

- **状态：** Accepted
- **日期：** 2026-07-25
- **来源：** handoffs/2026-07-25-lifespan-service-refactor-and-legacy-cleanup.md, handoffs/2026-07-25b-event-cost-fields-capability-flags-and-service-hierarchy.md, handoffs/2026-08-01-momentum-scoring-lifespan-tuning-and-failure-payoff.md

## 背景

轮回需要一个**贯穿全程、不可回避**的压力源，用来给「继续推进还是止步」这个决策定价。早期表述是「寿元增长到阈值触发大限将至」——一个递增计数器 + 一条阈值线。这个方向有两个问题：阈值线本身成了第二个平衡旋钮，且「还剩多少」对玩家不可直读。

## 决策

寿元是一个**递减的隐藏计数器**：按境界递增地授予预算（炼气起始 100 → 抵达筑基 +100 → 抵达金丹 +300 → 抵达元婴 +500），按事件的 `lifeSpanCost` 递减，**归 0 即角色终结**（`defeated`）。剩余寿元**跨篇章结转**。

**预算表固定不动，`lifeSpanCost` 是控制篇章时长的主旋钮。** 要改变一个篇章有多长，改事件定价，不改预算。

逐格取值与定价表 → `systems/balance.md`；终态与 `DefeatReason` → `systems/services/life-cycle-service.md`。

## 理由

递减预算把「还能走多远」变成一个玩家可直读的数，而递增计数器需要玩家自己去减。更承重的是**旋钮分工**：预算固定 ⇒ 篇章时长只有一个可调面（事件定价），调错了也只影响节奏、不影响境界结构；预算可调 ⇒ 时长由两条曲线相乘决定，二者互相掩盖。

跨篇章结转是「省着走能换来后面更宽裕」这条策略成立的前提；不结转则每篇章末尾的余量一律浪费，玩家的最优解退化为「把余量花光」。

## 备选方案

- **递增计数器 + 大限阈值** — 否决：阈值线是第二个平衡旋钮，且剩余量对玩家不可直读。
- **每篇章重置寿元、不结转** — 否决：使篇章末的余量恒为浪费，取消了「节省」这条策略。
- **`selectCost` 塌缩为单一 `int`** — 否决（08-15c）：成本侧不止寿元一种资源。
- **逐条目手写定价** — 否决（08-15c）：定价表是平衡面，逐条目手写会让时长旋钮散落在内容里。

## 后果

- 篇章时长的调参入口唯一：`systems/balance.md` 的 `lifeSpanCost` 定价表。预算四格不参与调参。
- 寿元是隐藏属性，其展示受档位表约束（→ `ADR-0016`）；精确扣减量只在 Band 2 展示。
- 寿元归 0 是四种 `DefeatReason` 之一，与 Finale 失败并列（→ `ADR-0025`）。
- 成本侧的 `LifeSpan` 取值域因此收紧为非负（回复只走产出侧，→ `ADR-0066`）。
