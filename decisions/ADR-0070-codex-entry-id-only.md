# ADR-0070 — `CodexEntry` 首批只有一格 `Id`；计数与首次解锁元数据全部不落

- **状态：** Accepted
- **日期：** 2026-08-19
- **来源：** handoffs/2026-08-19-codex-entry-schema.md

## 背景

图鉴条目的存档形态有很多可选字段：遭遇次数、败于其手次数、首次解锁日期 / 境界 / 篇章。它们都能让图鉴页面更丰富。

## 决策

`CodexEntry` 首批**只有一格 `Id`**：

```csharp
public readonly record struct CodexEntry(string Id);
```

计数字段与首次解锁元数据**全部不落**。

字段面与失败语义 → `systems/player-profile/codex/common-properties.md`。

## 理由

计数字段会把**规则字段层与统计计数层混装在同一个结构里**（→ `ADR-0050`）——图鉴条目本身是规则层（解锁状态决定呈现），而计数是统计层。混装后同步口径无从确定。

三项首次解锁元数据各有独立否决理由：日期靠**不可信的客户端时钟**；境界与「词条正文不写等级」的既定纪律冲突；篇章对玩家**无信息量**（三章共用一张图，见 `ADR-0042`）。

## 备选方案

- **加遭遇次数 / 败于其手次数** — 否决：混装规则层与统计层。
- **加首次解锁日期** — 否决：客户端时钟不可信。
- **加首次解锁境界** — 否决：与「词条正文不写等级」冲突。
- **加首次解锁篇章** — 否决：对玩家无信息量。

## 后果

- **代价明写：逐条目的计数因此不可得**，图鉴页面不能显示「遭遇 7 次 / 败于其手 2 次」。
- 完成度分母由内容侧条目数现算，不落存档。
- 「敌方专属」这类标注一律是呈现层现算，不新增存档字段（→ `ADR-0096`）。
