# ADR-0056 — 语言分两层承载：UI 文案走翻译键、内容文案走 `LocalizedText`；语言封顶二值，未翻译即留空

- **状态：** Accepted
- **日期：** 2026-08-13
- **来源：** handoffs/2026-08-13-translation-key-rollout-and-content-localization.md, handoffs/2026-08-12-error-copy-and-update-prompts.md, handoffs/2026-08-19-translation-english-placeholder.md

## 背景

本作有两类文案，热更权限完全不同：**UI 文案**（按钮、标签、叙事框架）随包发布，改它要发版；**内容文案**（卡牌名、事件正文、图鉴词条）经 overlay 热更，改它不发版。若用同一个载体，要么内容文案失去热更，要么 UI 文案被塞进内容层。

## 决策

**两层不同载体、不同热更权限，但共用同一个语言开关**：

- **UI 文案** → `res://text/` 翻译键（随包，发版才改）。**全库不新增任何 UI 文案字面量。**
- **内容文案** → 条目内嵌的 **`LocalizedText`**（overlay 可热更）。

**语言范围封顶为 `zh` / `en` 二值，不带地区码。** 中文是默认语言与优先制作的一列。

**未翻译的形态 = `en` 单元格留空，不写任何哨兵值**；回落靠引擎 `internationalization/locale/fallback = "zh"`，**调用点零分支**。

分区表、键命名与三条启动期审计 → `ux/error-and-blocking-ux.md`；`LocalizedText` 形态 → `systems/common-properties.md`。

## 理由

两层的分界线就是热更边界，这是唯一一条自然的切分——按「是不是叙事文本」切会立刻遇到「叙事框架是 UI、叙事正文是内容」这种同一屏内的混合。

`en` 留空而非写哨兵：哨兵的形态**一定会漂移**（`TODO` / `[EN]` / `???` 混用），且它相对空单元格**没有任何信息增量**——空就是未翻译。而不设回落时，英文 locale 下每一条未翻译文案都会显示成**大写英文键**，比显示中文更糟。

## 备选方案

- **每语言一套 `Id`** — 否决：`Id` 是稳定键，绑定语言即毁掉它。
- **内容文案塞进 `res://text/`** — 否决：内容文案失去 overlay 热更。
- **每语言一个 `[Export]` 字段** — 否决：把语言数焊进 C# 类，加一门语言就要改类并发版。
- **`TODO` 一类哨兵值** — 否决：形态必漂移且无信息增量。
- **`en` 列复制 `zh` 原文 / 写键名本身 / 机翻初稿** — 均否决：都会让「未翻译」不可检测。
- **按语言分包 / 设 `zh_TW` 分列** — 否决：二值封顶。
- **先用 C# 常量表、待全局 i18n 决策时再迁** — 否决（08-12）：晚迁没有任何收益。

## 后果

- `LocalizedText.Get()` **只读、绝不把解析结果写回条目**——写回会污染 ContentRegistry 里的共享只读单例。
- 语言覆盖率审计以「空单元格 = 未翻译」为唯一判据，可机械统计。
- 这条与 `ADR-0053`（错误文案键机械变换）共用同一套翻译键基建。
