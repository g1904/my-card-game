# ADR-0083 — 卡面 = 全幅插画，唯一文字是 `manaCost`；`Power` 战斗内以技能条目呈现，卡面形态只用于图鉴 / 详情 / 选择面

- **状态：** Accepted
- **日期：** 2026-08-25
- **来源：** handoffs/2026-08-25-combat-presentation-and-action-result.md, handoffs/2026-08-26-storage-pack-two-layer-view-and-combat-holdings.md

## 背景

竖屏手机上的手牌区很小。传统卡面（插画 + 卡名 + 规则文字框）在这个尺寸下三样都读不清，且规则文字要随语言变化重新排版。

另一侧，神通 / 法则（`Power`）此前也按卡牌呈现，但它们不被打出、永不入栈、不产生弃牌堆流量——卡面上的类型角标对它们是空转。

## 决策

**卡面是全幅插画（full art）（承重）。** 卡牌为整图，**卡面上的文字信息只有 `manaCost`**——无规则文字、无卡名。规则描述、卡名、关键字名与定义、`Power` 的明示内容一律后置到**点按升起的详情页**。

呈现哲学一句话：**卡面极简，信息后置到详情页与战报。**

**非文字的 UI 叠加保留并因此升格**：五类卡牌仍靠**卡框色 + 类型角标**区分（**适用于会以卡面出现的类型**），在 full art 下它们是卡面上唯一的非 `manaCost` 呈现元素。

**神通 / 法则的呈现气质是技能感，不是卡牌感**：战斗内 `Power` **一律以技能条目呈现**；**卡面形态只用于图鉴 / 详情卡 / 奖励与置换选择面**。

**缩略可辨**由「看得出画的是什么」加强为**跨卡之间彼此可区分**（剪影 / 主色 / 构图有别）。

→ `ux/combat-ux.md`（权威）；美术侧 → `art/visuals/art-direction.md`、`art/_index.md`。

## 理由

小尺寸下只能读一个数，那就只放一个数。规则文字后置到详情页不损失信息——玩家需要细读时点一下，而不需要时手牌区是干净的。

跨卡可区分是 full art 的直接推论：**没有卡名可读时，插画就是唯一的识别通道**，一手牌里两张长得像就读不开。

`Power` 用技能条目：它不被打出、永不入栈、不产生弃牌堆流量 ⇒ 卡面类型标识对它本就是空转；而奖励 / 图鉴面需与其他族并排，保留卡面成本最低。

## 备选方案

- **保留卡面文字（卡名 / 规则描述）** — 否决：小尺寸下读不清，且随语言重排版。三条既有的「卡面带文字」要求判定为**换载体不换要求**（关键字定义移入详情页 · 多目标槽位类别交给选目标态指令条 · `Power` 改详情页明示）。
- **`Power` 沿用卡面形态** — 否决：类型标识对它空转。

## 后果

- 本条**收窄了 `ADR-0019`「五类靠卡框色 + 类型角标区分」的适用面**——该表述现只适用于会以卡面出现的类型。
- 卡框色与类型角标是呈现层 UI、与插画分开生成（UI 需要可九宫格拉伸）。
- 插画内不得烧入承载可翻译语义的文字（→ `ADR-0084`）。
