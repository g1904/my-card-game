# ③ 逐类型 AdventureEvent 机制（焦点 · 各开一次专门 session）

> 本分片属 `../open-questions.md` 的当前焦点区。逐类型 AdventureEvent 的机制将**各开一次专门 session**（五类各一场），不在一次 handoff 里做完 —— 见 `systems/adventure-event/_index.md`。

- **各类型的结算 / 机制细化。** 五类分类法已定（`decisions/ADR-0002` 五值枚举 + Combat 的 `combatTier` 三档）。**Combat 已开过多场专场**（07-30b 参战方结构 / mana / 存档，08-15d 意图机制整条移除，08-06d 三档遭遇参数，08-09b Finale 档的残卷与重试，08-17e 全部 Finale 均为天劫战 + 三档与隐藏属性的交互口径）；**五类至此全部收口**（**Exchange 已收口**：仍走 `GenericEventResolver` · 交易逐笔即时提交 · 库存物化时经 `Shop` 子流掷定并落存档 · 定价走「商品族 × 稀有度」统一表 + 两条折扣通道 · 售出面仅 `CharacterItem` 一族且为代码级常量判据 · 刷新机制落地但首批内容默认关闭 · NPC / 势力为风味层不建数据模型 · 支付侧二选一（一条货币 element 或一件点名的轮回级法宝，barter 定值不经池、不参与刷新，白送漏洞以门面 `Holds` 前置拒绝堵死）。**Travel 已收口**：常规出场走 location 类型修正 · 80/20 为全局常量不可调制 · 代价走定价表且 > 0 · 不设途中遭遇 · 换图后无特殊规则。**Research 已收口**：构筑面板 = 复数决策槽 · 五类操作闭合 · 产出面 = 卡组 + `manaLimit` · 候选物化时掷定走 `RngStream.Reward` · 不另收资源代价。**Explore 已收口**：真身分布 = 条目池组成 × 既有加权抽取、三处数据类不加字段 · 取池期附加「真身须同样 enabled」一条过滤 · 揭示 = `eventStart` 内一次 `with` 派生且 resolver 按真身选取 · 遮罩卡与其余选项完全同构、揭示走全屏转场层 · 不给任何部分线索）。→ `systems/adventure-event/<type>/`。
