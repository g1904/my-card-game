# ② eventOptions 生成流程（焦点）

> 本分片属 `../open-questions.md` 的当前焦点区。

- **生成 / 加权规则与叠加顺序（08-05b 收窄 · 08-15c 再收窄）。** **location 层的形态已答定**（事件类型概率修正 + 敌人模板池 + `eventCountLimit`）、**每批数量已答定**（常态 3、区间 1–5）、**重算依据已答定**（依角色整体历程重算、重度依赖 `pastEvent`、不承接上一批）；仍待定：类型修正的**运算形态**（乘性 / 加性 / 白名单 + 权重，能否修正到 0）、月圆之夜式策划与随机权重的配比、**location 框定 / AdventurePlot 调制 / seeded RNG 的叠加顺序**，以及**批次规模区间两端由什么驱动**（何时收到 1、何时放到 5——location？篇章？剧本？隐藏属性？）。→ `systems/services/future-event-service.md`、`systems/adventure-event/common-properties.md`、`systems/game-progression.md`。
- **五类之间的配比，以及 Combat 内 `combatTier` 三档的配比（08-15c 新增）。** 一段修行历程中五类事件的分布权重、由 location 与 AdventurePlot 如何调制未定；**Combat 内部另有一层**——每篇章一个 `Finale` 已定，`Practice` 与 `Standard` 的比例未定。→ `systems/adventure-event/_index.md`、`systems/balance.md`。
- **Explore 揭示池的权重（08-15c 新增）。** 真身取值域已答定（Combat / Travel / Exchange，不含 Research、不嵌套自身）；三者的出现权重、是否随 location / 篇章 / 剧本调制未定。→ `systems/adventure-event/explore/_index.md`。
- **遮罩下的 `selectCost` 呈现（08-15c 新增）。** `selectCost` 必须如实展示（让玩家算得出「这一步可能是最后一步」），但 Explore 的真身隐藏——展示的是 Explore 条目自己的成本还是真身的？两者若不一致会泄漏信息。→ `systems/adventure-event/explore/_index.md`、`systems/adventure-event/common-properties.md`。
- **Travel 的常规出场概率，以及 80 / 20 是否可被剧本调制（08-15c 新增）。** **候选呈现规则已答定**（80% 列全部邻接 / 20% seeded 随机一个；常规与闸门一律适用；Explore 揭示出的必为随机）；仍待定：非闸门时**出场概率由什么给出**（location 的类型概率修正？固定值？）、以及 **80 / 20 比例是全局常量还是可由 PlotManager 推拉**。→ `systems/adventure-event/travel/_index.md`、`systems/services/future-event-service.md`。
- **location 与 `locationMap` 的数据载体（08-05b 收窄）。** 字段与图的存在形态已定（**连通关系由全局不变的 `locationMap` 承载**），载体未定：`LocationData : Resource` + `.tres`？枚举 + 资源两件套？`locationMap` 是单份邻接表资源还是各 location 持边？是否受 `AllEnabled()` 与 overlay 管辖。→ `systems/game-progression.md`、`systems/adventure-event/travel/`。
- **`LocationCodex`「记连边」的显影粒度（08-06c 收窄 · 承重）。** **记连边已定案**（跨轮回重建整张 `locationMap` 是设计目标）；仍待定：去过 A 之后列出的是 **A 的全部邻接（含从未去过的地名）** 还是**只记已走过的那几条边**？前者才支持「提前两步规划路线」，后者纯回溯。**本库现按前者理解，待确认。** 其余词条深度（风物文案 / 事件类型倾向 / 敌人清单 / 配额）与它不同于其余五本的呈现形态亦未定。→ `systems/player-profile/codex/_index.md`。
- **`eventCountLimit` 能否被剧本调制（08-05b 收窄）。** **计数口径已定案**（只计选择进入并结算的，Travel 不计入）；配额本身能否被 PlotManager 推拉未定。→ `systems/game-progression.md`。
- **寿元打穿后怎么办（08-06c 新增 · 08-15c 收窄 · 承重）。** `selectCost` 无条件施加，且**成本侧现已只剩 `lifeSpanCost` 一项**（其余资源不进成本侧，已答定）——于是这一问收窄为纯寿元问题：寿元归 0 = `defeated` 已定，**支付使寿元变为负数时如何钳制**（截断到 0？允许为负？）仍未定，它直接决定 `ProfileManager.TryApply` 施加负值时的规则。→ `systems/services/profile-service.md`。
- **「余额不足即拒」还剩哪些消费点（08-06c 新增 · 08-15c 收窄）。** 事件推进路径已不需要它，成本侧也只剩寿元；**只剩 Exchange 内的商店购买这一个可能的消费点**。若它也不需要，`CanAfford` / `AdvanceResult.CostRejected` / `MissingElement` 可整体删除。→ `systems/adventure-event/exchange/_index.md`、`systems/services/profile-service.md`。
- **`Priority = 1` 依什么条件抬升（08-06c 收窄）。** **取值域两档、置位方唯一（future-event-service，PlotManager 不可改）已定案**；仍待定：依什么条件抬升（配额闸门与开局构筑事件之外还有哪些）、同批多个 `1` 档是否需额外收窄规则、以及字段是否从 `int` 退化为 `bool`。→ `systems/services/future-event-service.md`。
- **`EventOption` 的完整物化字段清单（08-06c 减为七字段 · 08-09c 再收窄 · 08-15c 新增一项）。** 骨架七字段已定（`InstanceId` / `EventId` / `EventType` / `Priority` / `SelectCost` / `IsRevealed` / `RevealedEventId`）。仍待定：还有哪些数值可被情境改写？outcome 权重是否在物化时固化？**`lifeSpanCost` 是固定值还是可带区间 / 公式？** **`combatTier` 除 `EncounterSpec` 外是否也要出现在 `EventOption` / `PastEventEntry` 上？**（`EncounterSpec` 上已定为 `Tier` 字段；但呈现层要在选择区区分「切磋 / 遭遇 / 渡劫」、履历要读出「这一步是不是渡劫」，二者是否够用现有的 `EventId` 溯源）（**「风味文案是否也物化」已答结：不物化、跟随模板** ⇒ 剩余分叉不含任何文本类字段。）→ `systems/services/future-event-service.md`、`systems/adventure-event/common-properties.md`。
- **物化后敌人实例的类型形态（08-09c 新增）。** `EnemyInstance` 是嵌在 `EventOption` 上还是只记引用？战斗类痕迹需要它才能定稿。**不阻塞 `pastEvent` 的最小面已定**：至少存 `EnemyTemplateId` + 物化赋级 `Level`。→ `systems/services/future-event-service.md`、`systems/enemies/`。
