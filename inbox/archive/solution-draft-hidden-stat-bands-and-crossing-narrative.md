# 方案草稿 — 隐藏属性的档位模型与跨档叙事

> **裁决状态（2026-08-12）：五项已由用户全部裁决**，见文末「已裁决」。正文各处已按裁决改写为定稿形态。唯一的张力项（内容层 overlay vs 翻译键）经确认**不冲突**，判据已写入「与既有决策的张力」小节。可直接喂 `/analyze-new-ideas`。
>
> **两处连带改写**：
> - **裁决 ③「下行不播叙事」重定义了档号方向**（否则寿元既定的 30% 提示会被字面废掉）——见 §3 的「档号方向」条。
> - **裁决 ⑤「只有极值档播文案」把档位与文案彻底解耦**：档位表继续做 eventOptions 的**调制粒度**（多档有意义），文案则收窄到**每个属性最外的一档**。全库有文案的档由 7 降为 **4**，密度降至 **≈ 6–10 条 / 轮回**。见 §3 与 §6。

## 问题

08-01 定案「**当某个隐藏属性跨过一个隐藏档位时，给一条定性的叙事描述**」，并定死了落点（`ResolveOutcome` → `eventEnd`，无新结构）与意图（给方向与因果、不给数字）。但**档位本身从未被定义**：

- **道心 / 煞气连取值域都没有**（是否有界？起始值？），更没有档数与阈值；寿元只有 30% / 10% 两个百分比，且**没写「百分比的分母是什么」**——而「剩余寿元跨篇章结转」使得预算不是常量。
- **文案侧四个子问题全悬着**：挂档位还是挂事件？走不走内容层？播在结算面板一行还是独立弹层？同一次结算多个属性同时跨档怎么办？

两条互为前提：没有档位就没有触发点，没有触发点文案无处挂。因此本草稿把两条**一起答**。

顺带闭合的第三件事：`plot-manager.md` 既定「隐藏属性达**阈值**时触发对应剧情线」（煞气反噬 / 大限将至），这套「阈值」与跨档的「档位」此前是**两套并行的说法**——本方案把它们收敛为**同一个档位模型**。

## 建议方案

### 1. 三个隐藏属性共用**一套档位模型**，档位是内容条目

`[既有推演]`

既定文本里有两套说法——「跨过一个隐藏**档位**」（08-01）与「达**阈值**时触发对应剧情线」（07-23）。建议明确它们是**同一件事**：剧情线触发 = 跨入某个带 `PlotTriggerId` 的档。收益是单一真相：一张档位表同时回答「什么时候播叙事」「什么时候起剧情线」「寿元什么时候转红字」「eventOptions 该怎么调制」，不需要四套判定。

**档位有四个消费方，它们各取所需、密度互不绑定（裁决 ⑤ 后成为承重）：**

| 消费方 | 用到几档 | 说明 |
|---|---|---|
| **eventOptions 调制**（PlotManager 的主业） | **全部档** | 档位是调制的粒度：煞气 1 档与 2 档就该抽出不同风味的事件池。**这是档位表存在的首要理由。** |
| **剧情线触发** | 带 `PlotTriggerId` 的档（当前 2 个） | 煞气反噬 / 心魔滋生 |
| **跨档叙事文案** | **只有极值档（4 个）** | 裁决 ⑤ —— 见 §6 |
| **寿元红字标注** | 寿元 Band 2 | 既定 |

**关键的解耦：档多 ≠ 文案多。** 玩家感知到的「这条线在动」主要来自**摆在他面前的事件变了**（调制），而不是来自一句旁白。这正是裁决 ⑤ 的依据，也是本作作为 deck building game 而非 visual novel 的直接体现。

推论：`PlotManager.OnHiddenStatThreshold(CharacterProfile, HiddenStat)` 与事件 `PlotThresholdReached(CharacterId, Stat, int Threshold)` 的 `Threshold` 参数建议**改名为 `BandIndex`**——它传的从来不是那个阈值数值，而是「跨进了第几档」。

### 2. 取值域：道心 / 煞气 = `[0, 100]` 有界整数

`[已裁决 ①]`

- **道心 faith：`[0, 100]`，轮回起始 `50`，双向推拉。** 它是「状态」（心境澄明 ↔ 心魔渐生），事件两个方向都推得动。
- **煞气 malefic qi：`[0, 100]`，轮回起始 `0`，以上行为主、可被净化类事件下拉。** 它是「累积物」，既定的「累积到阈值触发煞气反噬」直接对应最高档。
- **有界的理由**：无界属性的「档位」只能靠不断加新档追赶，而档位是内容条目、**overlay 只改不增**（见 §6）⇒ 加档必须发版。有界 + 顶档吸收溢出，使档数在整条内容生命周期里是常量。
- 钳制规则：施加后截断到 `[0, 100]`，**不构成终态**（与寿元不同）——这同时是「哪些资源允许被打穿」那条待答项在隐藏属性这一半上的答案。
- 寿元不套用本条：它已有既定的预算模型（起始 100 / +100 / +300 / +500，归 0 = `defeated`）。

### 3. 档位表（定稿）

`[已裁决 ②]`（档数 5 / 4）+ `[既有推演]`（寿元两档）

**档号方向（承重 · 由裁决 ③ 逼出的定义）：`BandIndex` 越高 = 越远离常态，而不是「数值越大」。** 裁决 ③ 定「下行不播叙事」，若把「下行」读成「数值下降」，寿元的既定 30% 提示（它本身就是数值下降触发的）会被字面废掉。因此把三个属性的档号统一定义为「离常态的距离」，于是**触发规则对三属性完全一致：只在 `BandIndex` 增大时播，减小时静默**——不需要方向字段，也不需要为寿元开特例。

**道心 faith —— 5 档，阈值 20 / 40 / 60 / 80**（数值序，档号非单调）

| Band | 区间 | 语义（内部命名，不对玩家可见） | 文案 |
|---|---|---|---|
| **+2** | **80–100** | **道心通明 —— 极值档** | **✅ 唯一有文案的档** |
| +1 | 60–79 | 心念澄澈 | 静默（裁决 ⑤） |
| **0** | **40–59** | **常态（轮回起点 50 落于此档中心）** | 静默 |
| −1 | 20–39 | 心绪浮动 | 静默（裁决 ③） |
| −2 | 0–19 | 心魔滋生 —— 带 `PlotTriggerId` | 静默（裁决 ③ · 下臂极值不例外） |

> **道心是唯一的双臂属性**，故它的档号是「常态 0 + 上下各两级」。落地上用**带符号档号** `-2 / -1 / 0 / +1 / +2`（`sbyte`），触发判据取 `|newBand| > |oldBand|`；这比「两个方向各排一套无符号档号」少一层映射，也让「远离常态」直接就是绝对值变大。
>
> **道心下臂极值 `-2` 不配文案**：裁决 ③（下行不播）优先于裁决 ⑤（极值播），两者叠加的结果是「**上行的极值才播**」。`-2` 的存在感由 `PlotTriggerId`（心魔滋生剧情线）与调制承担。

**煞气 malefic qi —— 4 档，阈值 25 / 50 / 75**（单臂，档号即数值序）

| Band | 区间 | 语义 | 文案 |
|---|---|---|---|
| **3** | **75–100** | **煞气反噬 —— 极值档，带 `PlotTriggerId`（既定剧情线）** | **✅ 唯一有文案的档** |
| 2 | 50–74 | 煞气缠身 | 静默（裁决 ⑤） |
| 1 | 25–49 | 煞气初显 | 静默（裁决 ⑤） |
| **0** | **0–24** | **常态（轮回起点 0）** | 静默 |

**寿元 lifeSpan —— 3 档，阈值 30% / 10%**（单臂，**档号与数值反向**）

| Band | 区间 | 语义 | 文案 |
|---|---|---|---|
| **2** | **< 10%** | **红字数值倒数**开始（既定） | **✅ 有**（既定，两档皆为极值侧） |
| **1** | **10% – 30%** | **定性叙事提示**开始（既定） | **✅ 有**（既定） |
| **0** | **> 30%** | **常态，无提示** | 静默 |

**寿元是唯一有两个文案档的属性**，且这两档是**既定案**（08-01 的两段式告警），不受裁决 ⑤ 收窄。这正好落成用户要的频次序：**寿元 > 道心 / 煞气**——寿元的两条几乎每章必播（它单调递减），道心 / 煞气的一条则是「打到极端才有」。

**有文案的档一共 4 个**：道心 `+2` · 煞气 `3` · 寿元 `1` · 寿元 `2`。

- **档数仍取 5 / 4，不随文案收窄而减**：档位的首要消费方是 **eventOptions 调制**（§1 表），煞气 1 档与 2 档就该抽出不同风味的事件池；把中间档砍掉等于砍掉调制的分辨率，是拿主业去迁就点缀。
- **`PlotTriggerId` 只挂两档**（道心 `-2` / 煞气 3）—— 既定只点名了「煞气反噬」与「大限将至」两条线；剧情线目录未定，字段留空即可，**不臆造第三条线**。**道心 `-2`「心魔滋生」无叙事文案但 `PlotTriggerId` 照常触发**——剧情线靠 eventOptions 调制显影，不依赖旁白句，两者本就是档位表上的两个独立字段。

### 4. 百分比的分母 = **本篇章起始可用预算**（承重澄清）

`[既有推演]`

「剩余寿元跨篇章结转 ⇒ 下一篇章预算 = 该章增量 + 上一章剩余」使得寿元没有一个固定分母。若拿「本章增量」（100 / 100 / 300）作分母，省着花的玩家在第二篇章一开局就可能超过 100%，30% 阈值的含义随之漂移。

建议：**ChapterManager 在篇章边界把「结转后的可用预算」冻结为 `CharacterProfile.Status.ChapterLifeSpanBudget`**，百分比一律以它为分母。它是既有篇章边界职责的一个赋值，**不新增存档点、不新增流程**。

推论：`ChapterLifeSpanBudget` 是新增存档字段（见「后果」）。它同时给了「寿元还剩多少比例」一个**可显示、可复算**的口径，供 EventOption 界面的静态标注读取。

### 5. 回滞（hysteresis）：每档带**进入阈值**与**退出阈值**

`[通行做法]`

没有回滞，一个在阈值上反复 ±3 震荡的道心值会把「稀缺才有分量」直接毁掉——同一条文案连播五次。这是所有带阈值叙事反馈的系统（RPG 好感度、Reigns 类仪表、成就进度）的标准处理。

- 进入阈值 = 上表的区间边界；**退出阈值 = 进入阈值 − δ**（δ 一律向**常态方向**放宽，故道心下臂的退出阈值是 `EnterValue + δ`——用「向常态方向」表述而非「减」，才对双臂属性成立）。
- δ 初值：**道心 / 煞气 = 4**（≈ 档宽的 20%）· **寿元 = 3 个百分点**。
- 代价（明写）：**档位不再是当前值的纯函数** ⇒ 必须持久化「当前所处档」，见 §7 的 `HiddenStatBands`。这是本方案唯一真正新增的存档结构。

### 6. 文案归属：**挂档位、不挂事件；走内容层**（其中一半已由既有决策答定）

`[既有推演]`

`content-service.md` 第 38 / 185 行**已经明写**「状态转换触发的定性文案（隐藏属性跨档叙事、Finale 补白）」是**被存档引用类的内容条目、有稳定 `Id`、需启动期校验、overlay 只改不增**。因此待答项里的「是否也走内容层」实际上**已经答了，只是没回填 `plot-manager.md`**——本条只是把它取回来。

真正需要提案的是**挂在哪**：

- **挂档位定义**（每档一组固定候选文案），**不随触发它的事件而变**。三条理由：① 08-10b 的同类先例（Finale 补白）就是挂在**状态转换**上、与触发它的事件无关；② 挂事件是 `事件数 × 属性数 × 档数 × 方向` 的组合爆炸，一章 30 个事件 × 3 属性 × 2 方向 = 180 条文案，**内容侧不可维护**；③ 挂事件会让文案泄露事件与属性的精确映射（「做这件事 → 播这句话」），与「学到方向与因果、学不到精确数值」的边界擦得太近。
- **每档 2–3 条候选，等概率随机取一**（沿用 08-10b）。**随机源不带种子**——同 08-10b 的推论：只影响呈现、不产生任何玩法结果，故不占 `SeedManager` 子流。
- **只有一组文案，没有「上行组 / 下行组」之分**（`[已裁决 ③]`）。裁决定「下行不播」，配合 §3 的档号方向定义，触发面收敛为「**跨入一个 `|BandIndex|` 更大的档**」这一种情形，故每档只需要一组文案；**回到离常态更近的档一律静默**。原提案的 `NarrativeDownIds` 字段整个删除——留空的字段会持续引诱内容侧去填。
- **只有极值档配文案**（`[已裁决 ⑤]`）。**道心 / 煞气各只有最外一档播；寿元保持既定的两档。**

  | 属性 | 有文案的档 | 一轮回可播次数 |
  |---|---|---|
  | 寿元 | Band 1（30%）· Band 2（10%） | **≈ 4–6**（每章至多 2，且几乎必然发生） |
  | 煞气 | Band 3（75+） | **≈ 1–2** |
  | 道心 | Band `+2`（80+） | **≈ 1–2** |

  **三条依据：**
  - **体裁定位。** 本作是 deck building / turn-based card combat game，**不是 visual novel**。叙事是点缀不是载体；「多写几句」与「少写几句」存疑时一律取少。
  - **因果的主要载体是事件文案本身。** 玩家从内容侧（这个事件在描述什么、他选了什么）就能推断抉择的影响——一个「屠戮山门」的选项不需要旁白告诉他煞气涨了。中间档的旁白是**重复信息**，只会稀释极值那一条的分量。
  - **档位与文案解耦后频次可以各调各的**（§1 表）：档位密度服务调制分辨率，文案密度服务「稀缺才有分量」。用中间档的静默换极值档的重量，是本条的全部意思。
  - **可机械检查的形态**：`|BandIndex| == 该属性的最大档号` 才允许配 `NarrativeIds`，其余档配了 → 加载期 `PushWarning`（见 §7②）。**这条纪律取代了原提案的 `NarrativeSilent` 布尔字段**——静默成了默认与常态，不再需要一个字段去声明它。
- **常态档（道心 / 煞气 / 寿元的 Band 0）恒无文案**：没有任何跨入它的路径是「远离常态」。
- **退让位（不是待答项）**：日后若实测觉得太闷，按顺序放宽——① 给煞气 Band 2 补一条 → ② 给道心 `+1` 补一条 → ③ 才考虑道心下臂。**每一步都只是加内容条目，结构 / 字段 / schema 全不动。**
- 若「非境界突破的寿元增长途径」日后答为「有」，寿元回升 = 档号减小 = 静默，同样不改结构。

### 7. 具体形态（可 derive 的落地面）

**① 内容条目类型 `HiddenStatBandData : Resource`**（进 ContentRegistry，有自己的仓储）

```csharp
[GlobalClass]
public partial class HiddenStatBandData : Resource
{
    [Export] public string     Id            { get; set; }  // "plot.band.faith.2"
    [Export] public HiddenStat Stat          { get; set; }  // Faith | MaleficQi | LifeSpan
    [Export] public int        BandIndex     { get; set; }  // 带符号：0 = 常态，|值| 越大越远离常态
    [Export] public int        EnterValue    { get; set; }  // 该档朝常态一侧的边界；LifeSpan 以百分点书写
    [Export] public int        Hysteresis    { get; set; }  // δ，退出阈值 = EnterValue 向常态方向放宽 δ
    [Export] public string[]   NarrativeIds  { get; set; }  // 跨入本档的候选文案；只有极值档允许非空
    [Export] public string     PlotTriggerId { get; set; }  // 可空：跨入即起剧情线
    [Export] public bool       ContentEnabled { get; set; } = true;
}
```

- **文案正文单独成条目**（复用 Finale 补白已经要用的那个定性文案类型），本类只持 `Id` 数组——与「快照 / 结构里不存字符串正文」的既有分层一致，也让文案与档位可各自热更。
- `HiddenStat` 是新枚举 `{ Faith, MaleficQi, LifeSpan }`——`plot-manager.md` 的 API 表里**已在用这个类型名**，本方案只是给它定值。
- **`BandIndex` 取带符号 `int`（存档侧落 `sbyte`）**：只有道心用得到负值，煞气 / 寿元恒为 `0..3` / `0..2`。判据统一为 `|new| > |old|` ⇒ 播。

**② 加载期校验（`data-resource-rules.md` 的「坏数据在启动时大声失败」）**

| 违规 | 处置 |
|---|---|
| 某 `HiddenStat` 的 `BandIndex` 不连续 / 有重复 / 缺常态档 `0` | `PushError` + 抛（`Stat` + 缺失的 index） |
| `EnterValue` 沿档号方向非单调，或 `δ` 使两档的进出区间交叠 | `PushError`（带两档 `Id`） |
| `NarrativeIds` 指向不存在的文案条目 | `PushError`（带悬空 `Id`）——它不是剧本 key point，不适用悬空降级 |
| **非极值档配了 `NarrativeIds`**（`\|BandIndex\| != 该 `Stat` 的最大档号`） | `PushWarning` 逐条列出 —— **裁决 ⑤ 的可机械检查形态**；静默是默认，不需要字段声明 |
| 某 `Stat` 的极值档 `NarrativeIds` 为空 | `PushWarning`（漏配。**道心下臂 `-2` 是明写例外**，见 §3） |
| **文案正文含属性名 / 阿拉伯数字 / 档位序号** | `PushWarning` + 逐条列出 —— 这是「不给数字」纪律的可机械检查形态，同 `IgnoresProtection` 的清单式软检查 |

**③ `CharacterProfile.Status` 新增字段**

```csharp
// 当前所处档（回滞使档位不是当前值的纯函数，必须持久化）
sbyte FaithBand;             // 索引 HiddenStatBandData.BandIndex；带符号，双臂
sbyte MaleficQiBand;
sbyte LifeSpanBand;
int  ChapterLifeSpanBudget;  // 本篇章起始可用预算 = 本章增量 + 上章结转；篇章边界赋值
```

三个 band 建议落成**三个具名字段**而非字典 —— 与 `chapterRetry` 的「篇章数是固定的游戏结构，不用字典 / 索引数组」同款判据（属性清单虽仍待答，但增删属性本就要动 schema）。

**④ 结算流程内的挂点（无新阶段）**

```
eventEnd 阶段
  → 合并 ResolveOutcome + lifeSpanCost + 隐藏属性推拉为一次 TryApply   ← 既有
  → 【新增：纯函数比对】对三个属性各算一次 newBand（读 Status 前值 + AppliedChange + 回滞）
       newBand != 存档 band  → 更新 Status 上的 band 字段（并入同一次 TryApply 的 spec，不另开事务）
       且 |newBand| > |oldBand| → 记一条跨档叙事；反向（回到离常态更近的档）只更新字段、不播
  → life-cycle-service 以 `with` 复制把 BandNarrativeIds 附加到 ResolveOutcome
  → 记入 pastEvent → 终态判定 ② → 广播 → 存档点                        ← 既有
```

- **`ResolveOutcome` 增加一个字段** `IReadOnlyList<string> BandNarrativeIds`（**resolver 侧恒填空**，只由 life-cycle-service 在 `TryApply` 之后填）。这保住「resolver 只描述结果、不自行写档」的既有边界。
- **不进 `PastEventEntry`**：跨档可由 `AppliedChange` + 前值重放得出，按 08-09c 判据「重算得出来的不存」⇒ 快照不加字段。（`LifeSpanAfter` 那条例外**不得据此扩大**。）
- **band 字段的写入并入 `eventEnd` 那一次 `TryApply`**，故「一个事件 = 一次事务 = 一个存档点」原样成立。

**⑤ 呈现（`ux/screen-flow.md`）**

- **播在事件结算面板内，一档一行**——不是独立弹层。独立弹层 = 新结构（违 08-01 的「无新结构」）+ 在最频繁的操作上多一次点击（违 combat-ux 的既定纪律）。
- **多属性同时跨档 → 全部逐条陈列，固定优先序：寿元 → 煞气 → 道心。不合并、不截断、不排队。** 属性只有三个，最坏情形三行；截断会丢掉玩家唯一能看见的信号，合并成一句则需要一套「两两组合文案」（又一次组合爆炸）。优先序取「离终局最近的先说」。
  - **裁决 ⑤ 后这几乎不会发生**（同一次结算里两个属性同时跨到各自极值档）。规则照样写明——**它便宜（一个排序 + 一次遍历）且不写就是个空洞**；但内容侧不必为它做任何准备。
- **视觉与其他结算行区分**：斜体 / 弱化色、**无图标、无数字、无属性名**；不做入场动画强调（与寿元告警「静态标注、不做跳动」同调）。
- **寿元 30% 与其他属性跨档 = 同一形态**（它本就是「跨进 Band 1」）；**10% 的红字倒数不是叙事，而是选择界面的常驻静态标注**——跨进 Band 2 时**同时**播一条叙事并开启红字标注。这澄清了一处此前容易被读成矛盾的地方：两段告警是「一条叙事 + 一个常驻标注」的叠加，不是两种叙事形态。

**⑥ 推拉幅度的量纲（初值，用于让阈值可被校准）**

沿用 `ExperienceGrade` 范式：内容侧不落裸数字，写枚举档，平衡表映射数值。

```
HiddenStatGrade { None 0 | Minor 2 | Standard 5 | Major 10 }
```

反推口径（对齐 `balance.md` 的「供给 / 需求比」写法，**它是验收项，不是死数字**）：

```
目标：每个属性每篇章跨档（含往返）2–4 次
道心档宽 20 ⇒ 一章净行程 40–80 点
一章 ≈ 30 个事件，设其中约一半推拉道心（15 次）
⇒ 平均单次净幅度 ≈ 3–5 点  ⇒ Standard = 5 落在区间内 ✓
煞气档宽 25 ⇒ 一章净行程 50–100 点，同一组档位取值下同样落区间内 ✓
```

**全轮回叙事条数（按裁决 ③ + ⑤ 重估 · 定稿）：**

| 属性 | 有文案的档 | 一轮回可播次数 |
|---|---|---|
| 寿元 | Band 1 · Band 2（× 3 篇章） | ≈ 4–6（每章至多 2，几乎必然发生） |
| 煞气 | Band 3（75+） | ≈ 1–2 |
| 道心 | Band `+2`（80+） | ≈ 1–2 |
| **合计** | **4 档** | **≈ 6–10 条 / 轮回** |

一轮回约 86–102 个事件 ⇒ **约每 9–17 个事件一条**。三次修订的收敛轨迹：

| 口径 | 有文案的档 | 条数 / 轮回 | 文案总量 |
|---|---|---|---|
| 初稿（双向、每档都播） | 20 | 18–36 | 40–60 条 |
| 裁决 ③ 后（下行不播） | 7 | 11–19 | 14–21 条 |
| **裁决 ⑤ 后（仅极值档）· 定稿** | **4** | **6–10** | **8–12 条** |

- **频次序符合设计意图**：寿元（每章必来，是压力计时器）> 煞气 / 道心（打到极端才有，是里程碑）。
- **若实测觉得太闷**，放宽顺序见 §6 的退让位；**`HiddenStatGrade` 的映射值仍是第一旋钮**（它同时也在改调制的推进速度，比加文案更贴近「让这条线动起来」的真实诉求）。
- **档数不因此改变**：它服务的是 eventOptions 调制的分辨率（§1 表），与文案密度已解耦。

## 备选方案（已考虑并否决）

- **文案随触发事件变化**（同一跨档在不同事件下措辞不同）—— 否决：`事件 × 属性 × 档 × 方向` 组合爆炸；且泄露事件↔属性映射。**局部保留的可能**：日后确需时，可在少数标志性事件上加一条**覆盖 Id**，不改本结构。
- **不做回滞，只靠「只在远离常态方向播」去防重复** —— 否决：裁决 ③ 后两者看似重叠，其实各管一半。方向规则挡的是「上去又下来又上去」里的**下来那一次**，回滞挡的是**在同一条阈值线上反复上行**（62 → 58 → 63 会连播两次同一档文案）。去掉回滞，震荡型的道心推拉仍会把文案播成噪音。
- **把「下行不播」实现为「数值下降时不播」** —— 否决：**会把既定的寿元 30% / 10% 提示整条废掉**（寿元的告警本身就是数值下降触发的）。这正是 §3 把档号方向定义为「离常态的距离」的原因。
- **每个跨档都播一条**（初稿形态） —— 否决（裁决 ⑤）：中间档的旁白是**重复信息**，玩家从事件文案本身已能推断抉择的影响；每档都播只会稀释极值那一条的分量，且把一个 deck building game 的结算面板做成 visual novel 的对白框。
- **为收窄文案而把档数砍到 3 / 2** —— 否决：档位的首要消费方是 **eventOptions 调制**，砍档 = 砍调制分辨率。**正确的做法是解耦而不是同时砍**：档位密度与文案密度各服务各的目标（§1 表）。
- **保留 `NarrativeSilent` 布尔来声明「本档有意静默」** —— 否决（裁决 ⑤ 后）：静默成了**默认与常态**（12 档里 8 档静默），为常态设一个必须显式置位的字段是反向的负担；改用「只有极值档允许配文案」这条可机械检查的规则，省一个字段。
- **无界属性 + 无限追加档位** —— 否决：与「overlay 只改不增」正面冲突，加档必须发版，反而更僵。
- **多属性同跨时合并为一句** —— 否决：需要两两 / 三三组合文案，是被否决的组合爆炸的另一种形态。
- **独立小弹层呈现** —— 否决：新结构 + 在最高频操作上加模态，两条既定纪律各违一条。
- **band 存成字典 `Dictionary<HiddenStat, sbyte>`** —— 否决：属性清单虽待答，但增删属性本就要动 schema，字典只换来一层查找与一处可空。
- **道心用两套无符号档号（上臂 0..2 / 下臂 0..2 + 一个方向字段）** —— 否决：带符号档号让「远离常态」直接就是 `|BandIndex|` 变大，判据是一行；两套档号则需要在每个比对点先取方向再比大小，且给了「方向字段与档号不一致」这种坏状态一个存在的机会。

## 与既有决策的张力

**无。** 唯一的疑似冲突（08-12 定「**全库 UI 文案统一走 `TranslationServer` 翻译键**，翻译资源随包、不走 overlay」vs 本方案的跨档叙事走**内容层 overlay**）经确认**不构成冲突**：两条纪律作用于**不同的文本层**，判据是「谁是内容、谁是界面」。

| | UI 文案 → 翻译键（随包） | 内容文案 → 内容层（overlay） |
|---|---|---|
| 有稳定 `Id`、被别的条目按 `Id` 引用 | ❌ 键由 `code` 机械变换而来 | ✅ |
| 进 ContentRegistry / 参与 `AllEnabled()` | ❌ `system-overview.md` 明写「`text/` **不是内容层**」 | ✅ 且参与启动期强校验 |
| 被存档引用 ⇒ 受「只改不增」约束 | ❌ | ✅ |
| 需线上可改而不发版 | ❌ 改按钮文字本就该跟版本走 | ✅ `content-service.md` 第 30 行的既定收益 |

三条支撑：

1. **08-12 的原话就限定了范围**——「全库 **UI** 文案统一走翻译键」，落点是 `ux/error-and-blocking-ux.md`，讨论对象是错误串、阻塞屏、同步指示、更新横幅；它从未涉及卡面描述、事件正文、风味文案这一层。
2. **跨档叙事归内容层不是本方案新提的**——`content-service.md` 第 38 / 185 行**已逐字点名**「状态转换触发的定性文案（隐藏属性跨档叙事、Finale 补白）」属「被存档引用 / 只改不增」类。本方案只是把它取回 `plot-manager.md`。
3. **互换载体两头都坏**：叙事塞进 `res://text/` → 失去 `Id`、失去启动期校验、档位定义无从引用它、也失去热更；UI 文案塞进 overlay → 按 `system-overview.md` 原话「把一条被刻意限窄的热更通道撑宽」，而 UI 文案根本不需要这项能力。

**唯一真正的交叉点（诚实标注，本方案不越界）：内容条目自己的多语言。** 跨档叙事日后要出英文版时，走的是**内容条目内的多语言表达**，不是 `text/` 翻译表——这一层尚无定案（英文列目前全是占位符），属既有待答项「翻译键的铺开节奏」的邻域。

**建议的落笔动作**：把上表那句判据显式化，落 `ux/_index.md` 那条横向纪律的注记位。**不推翻任何一侧、不改任何既有决策。**
