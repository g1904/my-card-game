# 定案草稿 — 储物袋与战斗内持有物面板

> 原始想法记于 2026-08-23，经 2026-08-24 设计讨论逐条裁决定案，2026-08-25 批量 interview 修正四项——其中「储物袋 9 格上限」被整条推翻。

## 定案

### 1. 储物袋的宝可梦式交互
`[用户拍板]` 法宝与古宝同为储物袋中的可使用道具（类比背包里的精灵球）：非战斗阶段可随时打开查看，并可**直接选择售出**换取基础货币灵石（`spiritStone`，见 `draft-0823d`）。

### 1b. 储物袋 = 跨两层的呈现视图；取消格数上限（08-25 裁定）
- **储物袋是一个跨两个持久层的呈现视图**：轮回级法宝（`CharacterProfile.magicPack`，`List<CharacterItem>`）与账号级古宝（`PlayerProfile` 持有的 `PlayerItem`）**同时呈现**，条目上带 `AbilityScope { Character, Player }` 标识来源——与战斗内道具区已定的「同时呈现两级、条目带 Scope 标识」同形，元界面沿用同一形状。
- **推翻 9 格上限，改用可下滑视图。** 原「9 格上限与堆叠 / 筛选规则全部挂在 `magicPack` 上」整条失效；「9 格是轮回级构筑取舍位」这条设计意图随之作废。界面改为可纵向下滑的列表 / 网格，容量不设硬上限。
- **连带作废的两条在办待答项**（是**作废**而非答定）：「满袋再获得一件如何处理（拒收 / 强制择一丢弃 / 奖励侧过滤）」与「满袋时能否购买道具」——满袋情形不再存在。`PROFILE_MAGICPACK_FULL` 这个文案键随之失去用途。
- **顺手收口一处既有漂移**（先于本草稿存在）：`player-item/_index.md` 说古宝「存于储物袋」，而 `item/_index.md` 与 `ux/screen-flow.md` 把储物袋定义为纯 `CharacterItem` 容器，三份文档口径不一致。按本条统一为「储物袋是跨两层的呈现视图，`magicPack` 只是它的轮回级那一半」。

### 2. 出售规则：只有法宝可售，古宝不可售
`[用户拍板]` **法宝（轮回级）可在储物袋随时售出**；**古宝（账号级）不可售出**——古宝的唯一退出通道仍是既有的「置换」机制。理由：允许卖古宝 = 用账号级资产兑换轮回级货币，会使「开局清仓换经济」成为最优解，并与「避免第二套账号级经济」的既有取向相抵。

这是既有定案的重申与延伸——既有已明写「古宝恒不可售出，售出面仅对轮回级的法宝开放，且这是一条代码级常量判据」。本次的真新增只是把它延伸到储物袋随售面。**随售的准入判据直接复用那条代码级常量**（可售出 ⟺ `ExchangeGoodsKind == CharacterItem`），不新写第二条族白名单。

### 3. 储物袋随售的回收率低于 Exchange 内出售
`[用户拍板 · 08-25 修正数值处理]` 随售的回收率应**显著低于**在 Exchange 事件内出售，保住「跑一趟商店」的规划价值。

**只定「两档 + 相对关系」，绝对数值留给内容扩充后的统计校准**——不写死 50% / 80%。
- 原稿建议的 80%（Exchange 档）与既有明写的「30–50%」相抵，而绝对数字在货币获取渠道答定前无法反推（获取渠道今天仍是空白）。本次真正的新增是「**两档**」这个结构，不是数字。
- **理由须改写：** 既有把回收率论证为「摩擦保住储物袋 9 格的取舍感」，而 9 格已按 1b 取消 ⇒ 该论据失效。回收率的存续理由改为本条自陈的那一条——**保住「跑一趟商店」的规划价值**（随售是便利，商店是更优解）。
- **随售率的落点：** 全局平衡资源单值（`PackSellRatePercent`）。Exchange 的条目侧字段 `SellEnabled` / `SellRatePercent` **原样保留**——它们存在的理由是「让『只卖不收』的商店可编排」，属内容编排面；随售没有编排主体，天然是全局单值。两者折算基准同为「族 × 稀有度」定价表的**基准价**，不取 `ListPrice`（随售场合没有 `ListPrice`）。
- 售出机制自此有**两条通道**：Exchange 只拥有商店内那一条，随售那条的权威落 `systems/character-profile/item/`。

**随售的痕迹：** 新增 `Source.PackSell`（合法子集表对 `(Item, Character)` 的 `Remove` 开 ✅）。不复用 `Source.ExchangeSell`——`Source` 的既定职责是「这件东西怎么来的 / 怎么没的」，复用会让「购买次数」这类统计永远算不准；且随售发生在事件之外、**没有 `PastEventEntry` 可挂**，`Source` 是它唯一的痕迹载体，复用会让这条痕迹指向一个不存在的事件。不新开 `PastEventEntry` 通道，也不为「售出次数」设 `StatKey`（沿用交易侧零统计的既定判据）。售出即时提交，沿用既有路径，不新增存档点类型。

### 4. 战斗内持有物面板：按「可操作 / 只读」分两层
`[用户拍板]` 法宝 / 古宝 / 神通 / 法则需要战斗内可查看或使用的交互面；分层如下：
- **可操作层 —— 随身道具角标**：点按升起底部抽屉，展示按 `UsableScene` 筛出的本场可用道具（法宝 + 古宝，同时呈现两级、带 `AbilityScope` 标识），可直接使用。这一层已全文成文（角标收起 + 底部抽屉 + 横向滚动一行 + 灰显长按给原因 + 敌人回合置灰），本稿为纯沿用。「本场可用道具」的派生规则 = 按 `UsableScene` 筛 + 一条禁用过滤。
- **只读层 —— 神通 / 法则**：点按查看详情，本身不承载操作。只读层不列被禁用的神通 / 法则（它们根本不入场）。
- **启动式 `Power` 的启动入口放一个额外的弹出界面**（08-25 裁定）。只读层保持纯只读，而 `PowerData.Abilities` 的取值域**不收窄**（静止式 / 启动式 / 触发式皆可，至少一个）——既有明写「这条分界只用来决定禁用应当在哪一层截断，不收窄 `Abilities` 的取值域」，且已为启动费预留口径。`ux/combat-ux.md` 原写的「带启动式异能的 `Power` 需要一个可点击的启动入口」改为指向该弹出界面。
- **功法与货币不进战斗 HUD**：功法在组装时已展开为卡牌（战斗内不感知功法，既有定案），货币在战斗内无用途。仙玉与灵石的非战斗查看归**储物袋**（`draft-0823d` 已定仙玉为轮回级，落点为单一的储物袋，不再写「储物袋 / 元界面」）。
- **战斗内的卡组构成查询不在本稿收口**：原稿称它「走『抽牌堆剩余』一类既有信息面」，但「抽牌堆剩余张数是否常驻」本身仍是待决项，且「剩余张数」≠「卡组构成」。本稿只记方向——不为它单开面板，复用抽牌堆信息面——形态留待 UX 专场。

**只读层的形状（角标 vs 常驻一排小图标）不在本稿裁定。** 原稿称沿用「己方战场区边缘两个角标、分居两侧」，但既有原话是：随身为**角标（收起）**，神通 / 法则为**贴边缘的一排小图标（常驻）**——把只读层也改成收起式角标是形状变更而非沿用。该形状与已排期的「竖屏分区专场」高度重叠（既有明写「不在逐次 handoff 中零敲碎打」），故本稿只定**分层原则**，形状留给那场专场。

### 5. 神通 / 法则的呈现气质：技能感而非卡牌感
`[用户拍板]` 参照三国杀武将技能——被动常驻、身份绑定、少而精。UI 上神通 / 法则**不应长得像手牌**，应长得像武将技能栏 / 技能列表；与其 `CardType.Power`（开局入场、受保护、不可针对）的机制定位一致。

**卡面形态的适用面：** 战斗内 `Power` 一律以技能条目呈现（图标 + 名 + 一行效果），**卡面形态只用于图鉴 / 详情卡 / 奖励与置换选择面**。依据：`Power` 明写「不被打出、永不入栈、不产生弃牌堆流量」⇒ 它在战斗内从不以一张牌的姿态出现，卡面类型标识对它本就是空转；而奖励 / 图鉴面需要与其他族并排，保留卡面成本最低。既有「五类卡牌靠卡框色 + 类型角标区分」那句须加限定「适用于会以卡面出现的类型」。

## 后果
- `systems/character-profile/item/_index.md`：储物袋改为跨两层的呈现视图、**取消格数上限**、改可下滑；售出通道由一条扩为两条，随售那条的权威落本处；两档回收率的结构与相对关系；删除满袋相关的待决项与代价陈述。
- `systems/player-profile/player-item/_index.md`：「古宝恒不可售」延伸到随售面；改写「存于储物袋」为精确措辞。
- `systems/adventure-event/exchange/_index.md`：售出小节明写两条通道、Exchange 只拥有商店内那一条；回收率表述按第 3 条改写；新增 `Source.PackSell`；归属判据表补一行。
- `systems/balance.md`：回收率由一个数值格拆为两格（商店档 / 随售档 + 相对关系约束），登记 `PackSellRatePercent`；删除以「9 格取舍感」为由的论证。
- `ux/screen-flow.md`：储物袋面板改可下滑、列两级并带 Scope 标识；详情卡片加「售出」键（含回收价预览与确认形态，走本地业务提示分区的普通键，不占 `ERR_` 前缀）；入口沿用角色状态条上的「袋」图标。
- `ux/combat-ux.md`：可操作 / 只读两层的命名与结构；启动式 `Power` 的启动入口改指额外弹出界面；卡面类型标识的适用面加限定；神通 / 法则的技能栏式呈现气质成文。

## 与既有决策的张力
- **原稿自评「无张力」不成立。** 08-25 查出四条与既有定案的正面冲突并逐条裁决：回收率数值（30–50% vs 80%）、启动式 `Power` 的入口、古宝与储物袋的层归属（并暴露一处既有漂移）、货币定名。
- **9 格上限被推翻**是本轮最大的连带改动：它同时是「回收率」与「满袋处置」两条既有论证的基石，两者都需重写（前者换理由、后者整条作废）。
