# 方案草稿 — `EncounterTighten` 三格牌流量的六个界常量取值

## 问题

`systems/balance.md`「剧本收紧（`EncounterTighten`）的十个界常量」表里，五格遭遇参数各配一个**内容侧上界**（加载期 `PushWarning`，挡明显的编排失误）与一条**物化期硬界**（`Clamp` 钳制 + `PushWarning`，硬性削平坏数据）。回合数与胜负门槛两格的四个数已落（`MaxTurnLimitTighten = 2` / `MinTurnLimit = 6` · `MaxWinMarginTighten = 1` / `MaxWinMargin = 2`）；**三格牌流量的六格仍写着「待内容扩充后的统计校准」**：

| 格 | 内容侧上界 | 物化期硬界 |
|---|---|---|
| 起手抽牌数 | `MaxInitialDrawTighten` | `MinInitialDraw` |
| 每回合抽牌数 | `MaxDrawPerTurnTighten` | `MinDrawPerTurn` |
| 手牌上限 | `MaxHandLimitTighten` | `MinHandLimit` |

**它卡住了什么。** 没有下界，一条剧本条目写 `DrawPerTurnDelta = -2` 即可把每回合抽牌压到 `0`，遭遇从第 2 回合起完全断供；没有上界，加载期挡不住明显的编排失误。结构、算子、施加式、校验落位全部已定，**只欠六个数字**。

**阻塞已解除。** `balance.md` 当初把取值推迟的理由是「这三格的基准值（4 / 2 / 7）本身仍待校准」；基准值现已校准并维持（见 `open-questions/01-combat.md` 该条与 `handoffs/2026-09-07-combat-scale-baseline.md`），前置不复存在。

## 约束（来自既有设计）

**基准值（`CombatRulesData`，三章统一，敌我同值）** — `systems/balance.md`「战斗规则的卡牌侧数值」：

| 项 | 值 | 既有依据（原文要点） |
|---|---|---|
| 起手抽牌 `InitialDraw` | **4** | 「4 张 × 2 费 = 8 > `manaLimit` 5 ⇒ 首回合至多打 2 张」——刻意略低于 mana 基线，开局有一拍蓄势 |
| 每回合抽牌 `DrawPerTurn` | **2** | 一场流入 `4 + 5×2 = 14` 张，三个候选里唯一让 mana 线与牌线大致等长的取值 |
| 手牌上限 `HandLimit` | **7** | 「起手 4 → 第 2 回合 8 > 7」，是一条会真实咬合的紧约束；稳态手牌 4，连续两个回合出牌不足才撞 7 |
| 首回合是否抽 | **抽**（无例外） | 三步结构对每个回合一视同仁 |

**硬性约束（先于取值成立）** — `systems/balance.md`「三格牌流量的六个常量各自不可省」：
- `MinDrawPerTurn >= 1`（否则牌流量断供）
- `MinHandLimit >= MinInitialDraw`（否则起手即撞上限）

**机制形态** — `systems/services/plot-manager.md` + `systems/services/future-event-service.md` + `decisions/ADR-0077`：
- `EncounterTighten` 是**增量不是绝对覆写**；三格牌流量的 delta 恒 `<= 0`（加载期方向违规 → `PushError`）。
- 多条 `Active` arc（同时最多四条）**逐格取 `min`**，不是相加 ⇒ **合并后的 delta 幅度永不超过单条 arc 的最大幅度**。这一条很重要：它意味着内容侧上界基本上就决定了最坏情形，物化期硬界主要是防 overlay 坏数据。
- 施加式 `Clamp(v + Delta, Min*, v)`，`v` = 施加前值 ⇒ **永不放宽**，即便方向校验被绕过。
- `Tier == Finale` **整档豁免**（跳过整个 `Tighten`）⇒ 本组常量只对 `Practice` / `Standard` 有效。
- 界常量同住 `CombatRulesData`，**是取值不是结构 ⇒ 可 overlay 线上改**，`Tighten` 不落存档 ⇒ 零 schema 改动。
- 内容侧上界的语义 = **delta 绝对值超出即 `PushWarning`**（`plot-manager.md` 校验表末行），不是拒绝加载。

**已有的两格先例（同一张表，本方案沿用其推导语言）** — `systems/balance.md`：
- `MaxTurnLimitTighten = 2`：`Standard` `10 → 8` 正是 `Practice` 的既有回合数，「是一个已被论证过的可玩长度；再深一档就没有参照系了」。
- `MinTurnLimit = 6`：「双方合计 6 = 各 3 个回合……低于此即退化为纯起跑线检定」。
⇒ **两个数各自的判据是「落到哪个值会让战斗退化」，不是某个统一比例。** 本方案照此逐格推。

**呈现侧的连带** — `ux/combat-ux.md` + `decisions/ADR-0214`：
- 撞手牌上限**不丢牌**：第 8 张从抽牌堆抬起一半后**退回抽牌堆**。⇒ 压低 `HandLimit` 的代价是**少抽一张**（条件性的牌流收紧），不是销毁一张。
- 见底预警阈值 = `DrawPerTurn × 2`，是派生量、随收紧自动跟随。

## 建议方案

### ① 每回合抽牌数：`MaxDrawPerTurnTighten = 1` · `MinDrawPerTurn = 1`

`[既有推演]` **这一格的两个数由既有约束唯一确定，不含裁量。**

- 基准 `DrawPerTurn = 2`，硬约束 `MinDrawPerTurn >= 1` ⇒ 下界只能取 `1` 或 `2`。
- 取 `2`（= 基准）会让这一格成为**死结构**：任何 delta 都被钳回基准，格位永不生效。这与 `ADR-0077`「五格是封闭的：新增一格必须先回答『更紧在这一格上是什么方向』」的立格判据相抵（能表达方向却永远不生效，等于疲劳量那一格被挡掉的镜像失败），且会让 `MinDrawPerTurn >= 1` 这条明写的硬约束变成空文。⇒ **`MinDrawPerTurn = 1`**。
- 下界既为 `1`，唯一有效的 delta 就是 `-1`；写 `-2` 必被钳回 `1`，纯属编排失误 ⇒ **`MaxDrawPerTurnTighten = 1`**（正是「挡明显的编排失误」这条职责）。

**代价如实写下：这一格单格 −1 是五格中杀伤最大的一格。** `Standard`（双方合计 10 回合 = 己方 5 个回合）下总流入从 `4 + 5×2 = 14` 降到 `4 + 5×1 = 9`，**−36%**；对比 `MaxTurnLimitTighten` 的 `10 → 8` 只有 −20%。这不是失误，是「基准只有 2」的算术后果——一格整数在小基数上天然是粗粒度旋钮。编排口径见下方「后果」。

### ② 起手抽牌数：`MaxInitialDrawTighten = 1` · `MinInitialDraw = 3`

`[既有推演]` 下界由 `InitialDraw = 4` 的既有依据反推。

`balance.md` 给 4 的依据是一条可复算的不等式：**起手张数 × 平均费用 > `manaLimit`**（`4 × 2 = 8 > 5`），语义是「首回合几乎必然打不满 mana——开局有一拍蓄势」。逐值代入（ch1 平均费用 2 / `manaLimit` 5）：

| `InitialDraw` | 起手可支付量 | 与 `manaLimit` 5 的关系 | 判定 |
|---|---|---|---|
| 4（基准） | 8 | `>` | 蓄势一拍，不浪费 mana |
| **3** | 6 | `>` | **该性质仍成立**——仍是「打不满」而非「打不出」，是一次真实但不破坏结构的加压 |
| 2 | 4 | `<` | 首回合 mana **必然浪费**，开局从「蓄势」翻转为「无牌可打」 |

⇒ **`MinInitialDraw = 3`**：它是保住那条既有依据的最低值，判据形态与 `MinTurnLimit = 6`（「低于此即退化为纯起跑线检定」）同构。
⇒ **`MaxInitialDrawTighten = 1`**：下界 3、基准 4，`-2` 必被钳回，上界取 1 才挡得住那个编排失误。

（三章一致性复核：费用曲线随境界上移为 2 / 3 / 4，`manaLimit` 同步上移 ⇒ `3 × 3 = 9` 对 ch2、`3 × 4 = 12` 对 ch3 均维持 `>` 关系。该性质不随篇章翻转。）

### ③ 手牌上限 —— **本格已作废（2026-09-11 · 批量评审裁决）**

> **→ 已裁决（2026-09-11 · 批量评审）：手牌上限恒为 7、不可被剧本改动，整格移出 `EncounterTighten` 结构。**
> `MaxHandLimitTighten` 与 `MinHandLimit` **两个常量取消**（不是取 0，是不存在）；`EncounterSpec` 不再有手牌上限的收紧字段，剧本写了也无处可落。手牌上限 7 降为一个**普通的全局平衡常量**。
> ⇒ 本草稿的落地面由「三格六常量」收敛为**两格四常量**（起手抽牌数 · 每回合抽牌数）。
> ⇒ **须改写 `decisions/ADR-0077`**（Tighten 五格增量 → 四格）与 `systems/balance.md` 十常量表（十格 → 八格）。这是一次对既有结构的推翻，按根约定「决策可被推翻，以最新用户意图为准」处置。
>
> 以下原推演**仅作存档**，其结论不再采纳：

`[既有推演]` 判据取「**玩家在做出第一个决策之前不应因上限而少抽牌**」。

开局到第一个决策点之间必然入手的张数 = `InitialDraw + DrawPerTurn = 4 + 2 = 6`（首回合照常抽，无例外）。逐值代入：

| `HandLimit` | 开局入手 6 张时 | 判定 |
|---|---|---|
| 7（基准） | 6 ≤ 7，余 1 | 不咬 |
| **6** | 6 = 6，**恰好装下** | 不咬；稳态手牌 4 之上只要**跳过一个回合**就撞（基准下需连续两回合）⇒ 真实加压 |
| 5 | 6 > 5，**第一个决策之前就少抽 1 张** | 玩家在还没打出任何一张牌时已经吃了一次不可避免的损失 |

⇒ **`MinHandLimit = 6`**、**`MaxHandLimitTighten = 1`**（同上，`-2` 必被钳回 6）。

这一格顺带确立一条可机械核对的不变式：**`MinHandLimit >= 基准 InitialDraw + 基准 DrawPerTurn`**（6 ≥ 4 + 2）。它比明写的硬约束 `MinHandLimit >= MinInitialDraw`（6 ≥ 3）更强、且蕴含它 ⇒ 两条同时成立，无需取舍。

**最坏情形的牌流账（复合收紧：三格同时拧到底）：**

| 档 | 己方回合数 | 基准总流入 | 最紧总流入 | 降幅 |
|---|---|---|---|---|
| `Standard` | 5 | `4 + 5×2 = 14` | `3 + 5×1 = 8` | **−43%** |
| `Practice` | 4 | `4 + 4×2 = 12` | `3 + 4×1 = 7` | **−42%** |
| `Finale` | — | — | **整档豁免，不受影响** | — |

**它们是待实测校准的初值。** 校准输入与 `balance.md` 本表其余初值同源：卡牌产 / 削道念的量纲基准、starter deck 的实际平均费用。**若实测把基准 4 / 2 / 7 改掉，本组六个数须按上面三条判据（mana 不等式 · 开局入手量 · 下界非死结构）同式重算**，而不是按比例缩放。

## 后果

- **文档影响面只有一份：** `systems/balance.md` 的十常量表六格填数，另其下「取值推迟到统计校准的理由」一条须改写（前置已解除，理由不再成立）。
- **`systems/services/plot-manager.md` / `future-event-service.md` / `combat-service.md` 无需改动**——三处均只回链取值、不复述数字（明写的纪律）。
- **零结构改动、零存档 schema 改动、零迁移**：`EncounterTighten` 不进 `EncounterSpec`、不落存档。
- **加载期校验从此真正生效**：`plot-manager.md` 校验表末行「任一 delta 绝对值超出该格的内容侧上界常量 → `PushWarning`」此前因常量空缺无法执行，填数后立即可跑。
- **呈现侧无需改动但语义跟随**：见底预警阈值 `DrawPerTurn × 2` 在最紧遭遇里 = **2 张**（预警窗口减半）；手牌上限格 `n/7` 显示 `n/6`——两者都已明写「不写死」，形态不变。
- **编排口径（建议，不落成结构）：一条 arc 不宜同时拧两格以上的牌流量。** 复合最紧是 −43%，单格 `DrawPerTurnDelta = -1` 已是 −36%。这条只作编排指导写进 `balance.md` 的行内说明；**不建议为它新开一道「总量闸」**（那是新结构，超出本条「只欠数字」的范围，且 `min` 合并算子已保证幅度不会被多条 arc 叠加放大）。
- **已接受的代价：三格的可调幅度都只有一档（各 2 个合法值）。** 剧本在牌流量上的表达力因此很粗；这是基准值本身小（4 / 2 / 7）的算术后果，要更细的粒度只能先抬基准，那是另一个问题。

## 备选方案（已考虑并否决）

- **`MinDrawPerTurn = 2`（等于基准，格位变死结构）** — 否决：任何 delta 都被钳回基准，`DrawPerTurnDelta` 永不生效；与 `ADR-0077`「五格是封闭的、每格须能表达『更紧』」相抵，也让明写的硬约束 `MinDrawPerTurn >= 1` 变成空文。
- **`MinInitialDraw = 2`** — 否决：`2 × 平均费用 2 = 4 < manaLimit 5`，首回合 mana 必然浪费，把「略低于 mana 基线、有一拍蓄势」的设计意图翻转为「开局打不出」。
- **上界取 2 而下界不变（如 `MaxInitialDrawTighten = 2` / `MinInitialDraw = 3`）** — 否决：`-2` 必被物化期钳回，内容侧上界的唯一职责是「挡明显的编排失误」，写成 2 恰好挡不住那个失误，等于自废该格。
- **界常量随 `EncounterSpec` 覆写后的基准按比例动态计算** — 否决：常量住 `CombatRulesData` 是定值，动态界会让加载期校验依赖遭遇上下文（加载期够不着任何一场具体遭遇），且与已定的两格（`MaxTurnLimitTighten` 对三档同值）语言不一致。
- **三格共用一道「总量闸」（限制复合收紧幅度）** — 否决：新增结构，超出本条范围（结构已定、只欠数字）；`min` 合并算子已排除多 arc 叠加，剩下的单条 arc 复合收紧由编排口径承接。
- **逐 `combatTier` 分档给界常量** — 否决：`Finale` 整档豁免，只剩 `Practice` / `Standard` 两档，而两档的牌流量基准完全相同（4 / 2 / 7 三章三档统一）⇒ 分档得到的是两个必然同值的格子（与疲劳量被否决分档同一条判据）。

## 与既有决策的张力

**一处轻张力，建议直接改写而非留张力：** `systems/balance.md` 在该表下明写「**取值推迟到统计校准的理由：** 这三格的基准值（4 / 2 / 7）本身仍待校准，为它们的可压幅度先写数字只会制造两轮返工」。本方案正是「先写数字」。

- 松动理由：该句的前提已经消失——基准 4 / 2 / 7 已校准并维持（`open-questions/01-combat.md` 明记「该阻塞已解除」）。
- 松动代价：零。返工风险原本来自基准漂移；基准既定，本方案的三条判据又是**跟着基准走的式子**（mana 不等式 · 开局入手量 · 非死结构），基准真改时按同式重算即可，与本库「反推输入格被实测改写时按同式自动重算」的既有处置同款。
- **不松动时的替代方案**：六格继续留空，`plot-manager.md` 的上界校验一行继续无法执行，且任何含 `Tighten` 的剧本 arc 都不可 blueprint。⇒ 建议改写该句为「取值为初值，随基准值同式重算」。

`ADR-0044`（赋级带）/ `ADR-0052`、`ADR-0088`（疲劳）**均无冲突**：本方案不动方向约束、不动豁免闸，且收紧牌流与疲劳压力同向减轻。

**一处结构性张力（评审中新生，已裁决）：`ADR-0077` 须改写。**
