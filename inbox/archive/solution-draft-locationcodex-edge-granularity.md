# 方案草稿 — `LocationCodex` 连边显影粒度

## 问题

**「记连边」本身已定案**（08-06c）：去过一个地域就记下它通向哪些地域，玩家因此能在多次轮回中把整张 `locationMap` 重建出来——这是设计目标，不是要规避的泄露。

仍悬着的是**粒度**：

- **选项 A（本库现按此理解）** —— 去过 A 就显影 **A 在 `locationMap` 上的全部邻接**，包含玩家从未去过的 B（B 的地名因此被提前看见）。
- **选项 B** —— 只记**玩家实际走过的那几条边**（走过 A→B 才记 A—B）。纯回溯，更保守。

这条被标为**承重**，因为它同时决定三件事：① 「提前两步规划路线」这个已宣称的设计目标能不能兑现；② `locationCodex` 的**存档形态**（本方案认为这才是真正的裁决依据）；③ 图鉴族「六本形状相同、差别只在收录对象」这条族存在理由是否被破。

**范围：** 本草稿只答粒度这一条，并把它对 `CodexEntry` 存档形态的影响写清。**词条深度**（风物文案 / 事件类型倾向 / 敌人清单 / `EventCountLimit`）与**它不同于其余五本的呈现形态**（一张逐步显影的图 vs 列表 / 网格）是另一条待答项，只在 `## 前置依赖` 中点到，不在此展开。

## 约束（来自既有设计）

**存档形态侧（本条的硬边界）**

- **`CodexEntry` 首批只有一格 `Id`**（`public readonly record struct CodexEntry(string Id);`）。计数字段与首次解锁元数据两组候选全部不落，三条依据已成文。→ `systems/player-profile/codex/common-properties.md`
- **条目按对象的稳定 `Id` 索引**，与全库「稳定 `Id` 是一切引用的键」一致；**绝不用显示名、索引或复合键**。→ 同上
- **`LocationCodex` 的连边不落存档**——存档形态仍是 id 集合。这句已明写在 `systems/player-profile/_index.md`（`CodexEntry` 小节）与 `codex/_index.md` 推论 ③。
- **写入通道唯一：`ProfileChangeSpec.CodexElements`，元素 `CodexUnlock(CodexKind Kind, string Id)`，零 `Op`、恒不经 modifier pipeline。** `CodexKind` 是**六值**枚举（`Enemy` / `CharacterPower` / `PlayerPower` / `CharacterItem` / `PlayerItem` / `Location`）。→ `systems/services/profile-service.md`
- **`CodexUnlock.Id` 经 `ContentRegistry` 解析不到 → `PushError` + 整批拒绝**（必需缺失；悬空 `Id` 写进 Profile 会污染存档）。→ 同上
- **图鉴不落成 `Dictionary<CodexKind, …>`，也不落成单表 + `Kind` 字段**——六本各占一个具名字段。→ `systems/player-profile/_index.md`
- **体积护栏：** 任一本图鉴的条目数 **>** 该内容类型经 `AllIncludingDisabled()` 得到的**条目总数** → `PushWarning`；**图鉴统计的分母走 `AllIncludingDisabled()`**。→ `systems/services/sync-service.md`

**触发与族形状侧**

- **六本共用一条触发内核：接触即记，不要求你从中获益**；LocationCodex 那一行是**抵达**（`CurrentLocationId` 被置值那一刻），由 life-cycle-service 组装，搭在 Travel 结算 / 轮回创建**已经存在**的那一次提交上。**零新增提交点是最强的工程依据。** → `codex/common-properties.md`
- **「六本形状相同、语义相同、存档形态相同——差别只在收录对象」是这一族存在的理由**；文中并明写「LocationCodex 的加入是这条设计的验证：一个全新的收录对象只需加一行，不需要任何新机制」。→ `codex/_index.md`
- **08-06c 的原话是「去过 A 就记下 A 及 A 的连边」**——触发主体是**顶点**，不是边。→ `handoffs/2026-08-06c-…`

**地图与路由侧**

- **`locationMap` = 一张全局不变的连通图**，三章共用；载体是**单份 `LocationMapData`**，持一个无向边集（`LocationEdgeData[] Edges`，A–B 只写一条），**不由各 location 持边**。`LocationData` 与 `LocationMapData` 恒启用（`ContentEnabled == false` → 加载期 `PushError`，解析走 `AllIncludingDisabled()`）。→ `systems/game-progression.md`
- **加载期校验已封住图的形状：** 出度 `> 5` → `PushError`（闸门批次规模 = 出度，批次区间上限 5）；出度 `== 0` → `PushError`；图不连通 → `PushError`；自环 / 重复边 / 悬空 `Id` → `PushError`。→ 同上
- **出度 ≤ 5 的副作用是正面的：它让 `LocationCodex` 的连边词条在竖屏上一屏可读。** → `systems/game-progression.md`、`travel/_index.md`
- **Travel 候选走 80 / 20 掷定**：80% 列出全部邻接、20% seeded 随机取一个；**该掷定对常规出场与配额闸门一律适用**，且 **80 / 20 是全局常量、不可被剧本调制**——其**依据 ②（承重）正是**「`LocationCodex` 记连边 ⇒ 提前两步规划路线是跨轮回知识的变现通道，剧本若能悄悄拉高随机档，这份积累会在玩家不知情时失效」。→ `travel/_index.md`
- **Travel 不是常驻可选项**，常规批里出不出场不保证；20% 档下玩家无从选择去哪。→ 同上
- **改连边等于清空一份账号级 `LocationCodex` 资产**——`locationMap` 的稳定性已从设计选择升格为**对玩家的隐性承诺**。→ `codex/_index.md`、`game-progression.md`

**元进程侧**

- **地理方位感已宣告落地**：「玩家因此能跨轮回重建整张 `locationMap` 并在 Travel 闸门处**提前两步规划路线**」；仍待定的只剩进度感那一半。→ `open-questions/06-meta-progression.md`

## 建议方案

### 一、粒度取 **A：去过 A 即显影 A 的全部邻接**（顶点级解锁 + 连边在呈现层从 `LocationMapData` 派生）

`[既有推演]`

**这不是两个玩法手感的取舍，是「零存档增量」与「为一本图鉴破三条族级约束」的取舍。** 分三层论证。

**① A 与现行存档形态严丝合缝，零新增。**

A 下 `locationCodex` 仍是**顶点 id 的集合**：一条 `CodexEntry(Id = LocationData.Id)` 对应一个去过的地域。连边**完全不进存档**——它由呈现层从常驻内存的单份 `LocationMapData` 现算。逐条核对：

| 已定约束 | A 是否成立 |
|---|---|
| `CodexEntry(string Id)` 一格 | ✅ 不加格 |
| `Id` 是对象的稳定 `Id` | ✅ 就是 `LocationData.Id` |
| `CodexUnlock.Id` 须经 `ContentRegistry` 解析 | ✅ 解析到 `LocationData` |
| 六值 `CodexKind`，`Location` 一值一本 | ✅ 收录对象仍是 location |
| 触发 = 抵达，搭已有提交 | ✅ 零新增提交点 |
| 体积护栏（条目数 ≤ location 总数） | ✅ 上界恒成立 |
| 完成度分母走 `AllIncludingDisabled()` | ✅ 分母 = location 条目总数 |
| 「连边不落存档」（已明写） | ✅ 逐字兑现 |
| 六本形状相同、差别只在收录对象 | ✅ 不破 |

**A 需要的全部改动 = 呈现层一段派生逻辑 + 一条口径明文，存档 / 契约 / 校验 / 迁移面净增为零。**

**② B 无法在现行存档形态下表达，三条子路各自破一条承重约束。**

B 的语义是「已走过的**边**」——存档必须表达**边**这个对象，而 `CodexEntry` 只有一格 `Id`，且那一格必须解析回一个 `ContentRegistry` 条目。三条出路：

- **B1 — `Id` 编码成 `"location.a>location.b"`。**
  撞 **`CodexUnlock.Id` 解析不到 → `PushError` + 整批拒绝**（复合键在 `ContentRegistry` 里没有对象），必须让这条**必需缺失**级校验**按 `Kind` 分叉**、为 LocationCodex 单开例外——而这条校验的存在理由正是「悬空 `Id` 写进 Profile 会污染存档」。
  撞 **「条目按对象的稳定 `Id` 索引，绝不用显示名或索引作键」**：`"A>B"` 是一个由两个 `Id` 拼出的复合键，全库无第二处先例。
  撞 **体积护栏**：边数可以大于 location 数（连通图出度 ≤ 5 时边数上界 ≈ 2.5 × 顶点数），护栏对这一本恒常误报，等于把它关掉。
  撞 **完成度分母**：「已解锁 X / 共 Y」的 Y 要从 `AllIncludingDisabled()` 改取 `LocationMapData.Edges.Length`，六本统一的分母口径破一个特例。
  撞 **「连边不落存档」**这句已明写的结论。

- **B2 — 把 `LocationEdgeData` 升格为一等内容条目**（给它 `Id`、进 `ContentRegistry` 建仓储）。
  它把 `game-progression.md` 已定的载体形态（**单份** `LocationMapData` 持无向边集，选它正是因为「连通性校验需要全图视角」）改写成「边是散条目」，加载期校验表要补一批（边 `Id` 唯一性、悬空、与图的一致性），`content/` 要开一个新的内容类型档案。
  **并且它解决不了顶点**：玩家「到过 A」这一态仍需被记，否则完成度、词条解锁、「我去过哪」全部落空 ⇒ LocationCodex 变成顶点条目与边条目**两类混装**的一本，或需要第七本图鉴。这是六本一族里最贵的破例。

- **B3 — 在 `CodexEntry` 上加一格 `IReadOnlyList<string> KnownEdgeTo`。**
  撞 **`CodexEntry` 首批不加格的第二条依据**（层混装）——更直接的是：这一格对**其余五本恒为空**，正是「不落成单表 + `Kind` 字段」判据所拒绝的形态（每个消费点先按 `Kind` 分叉）。六本共用一个 record 的前提是它们形状相同。
  撞 **「存档只记解锁状态、连边随图静态给出」**：连边从静态内容变成账号级可变状态，图鉴的存档负担从「接近一个 id 集合」变成一份邻接表。

**三条子路没有一条是便宜的；A 则一处不动。这就是本条的裁决依据。**

**③ B 在玩法上还使已定案落空——不只是「更保守」。**

- **B 兑现不了「跨轮回重建整张图」这条已定案。** A 下重建全图只需玩家的已访顶点集构成图的一个**顶点覆盖**（每条边至少一端去过）；B 下要求**踩遍每一条边**，而 Travel 是**非常驻可选项**、还有 **20% 档把玩家随机推走**——在有限轮回内边覆盖近乎不可完成。08-06c 的定案（「跨轮回重建整张 `locationMap` 是设计目标」）在 B 下事实上是空头支票。
- **B 兑现不了「提前两步规划路线」。** 提前两步的信息 = 「B 又通向哪里」；B 下这条信息只有**已经走过 B→C** 才有，而那时你已经不需要它了。`open-questions/06-meta-progression.md` 已宣告地理方位感落地、`travel/_index.md` 把它写成 80/20 不可调制的**承重依据 ②**——两处都建立在 A 上。取 B 需同时改写这两处。
- **B 改的是触发内核，不只是词条内容。** 六本的共同内核是**接触即记**（遭遇 / 抵达 / 进入持有列表）；B 的触发是「走过一条边」，比接触更重，且**主体从顶点变成边**。08-06c 的原话是「去过 A 就记下 A 及 A 的连边」——B 把它改写成「走过 A→B 就记 A—B」。六本无法再用同一句话表述触发，正是「为何是一族而不是一个」要避免的形态。
- **A 「提前看见地名」不是泄露，是既定设计。** 「知识 = 力量」「玩家的世界地图是在多次轮回中一格一格拼出来的」都已成文；且**地名之外什么都不给**（见下方二），未去过的地域仍是一个只有名字的灰点——它的事件类型倾向、敌人池、`EventCountLimit` 全部锁着。**看见名字只带来「那边还有路」，不带来「那边有什么」。**

### 二、呈现三态：已解锁 / 边缘 / 不可见，显影半径固定 1 跳

`[既有推演]` + `[取向选择]`（显示到什么程度那一格：**已裁决取 A1**，2026-08-22；见 `## 仍需用户决定`）

A 若不加口径，会被误读成「已解锁顶点的邻接也可以再展开它们的邻接」——那等于直接发全图。故明写**显影半径 = 1 跳**，并给三态：

| 态 | 判据 | 显示 |
|---|---|---|
| **已解锁**（Known） | `Id ∈ locationCodex` | 名字 + 完整词条（词条含什么归词条深度那条待答项） |
| **边缘**（Frontier） | 不在 `locationCodex`，但在某条**至少一端已解锁**的边上 | **只有名字**，灰态；词条锁着；点按提示「尚未到过」 |
| **不可见** | 其余 | 完全不画（顶点与边都不画） |

- **半径固定 1 跳、不设旋钮。** 半径 2 = 提前三步 ⇒ 图在两三次轮回内就基本发完，「一格一格拼出来」这条体验消失；半径 0 = 退化成不记连边，与已定案相抵。**1 跳恰好等于「提前两步规划路线」所需的信息量**——闸门给你若干个 B，你知道每个 B 又通向哪里（那些 C 是边缘态，只有名字）。
- **边的显影随顶点自动成立**：一条边只要**任一端**已解锁就画出来（无向图，A 记 A 的邻接 ⇒ 从 B 侧看这条边也已知）。不需要为边单独记状态。
- **完成度只计已解锁顶点**（分母 = `AllIncludingDisabled()` 的 location 条目数），**边缘顶点不计、边不计**——保住六本统一的完成度口径。

### 三、词条深度与图形呈现不在本条内答

`[既有推演]`

「边缘顶点只显示名字」这一格已经把**词条深度**与本条解耦：无论词条最终写风物文案还是敌人清单，边缘态一律不渲染词条正文。**这使词条深度可以在本条定案之后独立裁决，两者不互锁。**

同理，「这张图在竖屏上长什么样」（节点图 / 分层列表 / 可缩放画布）整条归图鉴呈现专场；本条只承诺**出度 ≤ 5 使一屏可读**这条已有依据仍然成立。

## 具体形态（可 derive 的落地面）

**存档 schema —— 一格不动（这是本方案的全部要点）**

```csharp
// systems/player-profile/_index.md 第 11 行，不变
locationCodex : IReadOnlyList<CodexEntry>
public readonly record struct CodexEntry(string Id);   // Id == LocationData.Id
```

| 面 | 本方案的增量 |
|---|---|
| `CodexEntry` 字段面 | **零**（不加格） |
| `CodexUnlock` / `CodexKind` | **零**（仍是 `(Location, LocationData.Id)`） |
| `ProfileChangeSpec` 列 | **零** |
| 触发点 / 提交点 | **零**（抵达时那一次已有提交） |
| `ProfileManager` 校验行 | **零**（现有四行逐条成立，见上表） |
| 存档 schema 版本 bump | **零**（无字段变化 ⇒ 无迁移） |
| 后端配合 | **零**（Codex 六键本就不进透明路径白名单） |
| 呈现层 | 一段只读派生（下） |

**呈现层派生（ViewModel，只读，不写存档、不进 `ContentRegistry`）**

```
Known    = { e.Id : e ∈ playerProfile.locationCodex }
VisibleE = { edge ∈ LocationMapData.Edges : edge.FromId ∈ Known || edge.ToId ∈ Known }
Frontier = { 端点 x : x ∈ VisibleE 的某端 && x ∉ Known }
渲染顶点 = Known（完整） ∪ Frontier（仅名字，灰）
渲染边   = VisibleE
```

- **取图走 `AllIncludingDisabled()`**（`LocationData` / `LocationMapData` 恒启用，flags 第三层对它们不生效），与 `travel/common-properties.md` 的邻接取法同一条口径。
- **`Frontier` 顶点的 `LocationData` 解析不到 → `PushWarning` + 跳过该顶点**（可选缺失：图鉴少画一个灰点不阻断浏览）。**读档侧对 `locationCodex` 中悬空 `Id` 的处置沿用图鉴既有口径**（`PushWarning` + 保留条目，与写入侧的 `PushError` 读写不对称，见 `profile-service.md`）——本方案不新增失败语义。
- **纯读、可缓存于图鉴屏打开时**；`locationMap` 一次轮回内视为不变，不进 `_Process` 热路径。

**UI 文案**：三态的标签（「尚未到过」等）一律走 `res://text/` 翻译键，不写字面量；边缘顶点必须有**触控等价的**查看反馈（点按提示，无 hover-only 可供性）。

**加载期校验**：不新增。已有的出度 ≤ 5 / 出度 ≥ 1 / 连通 / 无自环重复边四条，恰好也是本方案渲染正确性的前提（出度 ≤ 5 ⇒ 单个顶点的邻接一屏可读；连通 ⇒ 图鉴最终可被拼全）。
