# 方案 — 英文占位符形态与覆盖率审计的可判条件

## 问题

「全库 UI 文案走翻译键、中文为默认与优先制作列、**英文列全部预设占位符**」已定案（`ux/error-and-blocking-ux.md`「翻译资源」）。但**「占位符」到底长什么样**从未陈述：取键名本身、取 `TODO`、还是取机翻初稿。

这不是一个措辞问题，是**唯一带行为面的一条**：`ErrorText.AuditTranslations()` 要报英文覆盖率（内容层一侧的同形审计已定为报 `en: 12 / 840 条目已翻译`）。若占位符是一个**非空字符串**，而审计的判据只是「这一行有没有值」，则英文覆盖率**恒读作 100%**，审计等于失效——而它失效时**没有任何症状**（中文玩家完全看不出差别，做英文版时才整片暴露），正是 `ux/error-and-blocking-ux.md` 自己给「能上线且线上不可见」定的那一档。

范围（08-13 缩范围后）：内容层 `LocalizedText` 一侧**已答定**为「缺 `en` 键即未翻译」，本方案对它**不作任何改动**，只把 CSV 一侧对齐到同一条判据，并补上两侧共用的运行时回落与审计口径。

## 约束（来自既有设计）

- **locale 封闭二值 `zh` / `en`，CSV 列 = `key, zh, en` 两列封顶，`zh` 为默认与优先制作列。** —— `ux/error-and-blocking-ux.md`「语言开关只有一个」。
- **内容层一侧已答定：`en` 的占位形态 = 该 locale 干脆没有这个键**（`Entries` 只有 `zh`），由静默回落承接；覆盖率审计**不需要第二套「什么算占位符」的识别规则**。 —— `systems/services/content-service.md`「内容文本的语言校验与覆盖率审计」。
- **非默认语言缺失 = 可选缺失 ⇒ 读取侧静默回落、不逐次警告**，改由合并后一次性审计报缺失数 + 覆盖率 + 前 N 个 `Id`。逐次警告会刷屏并淹掉真告警（占位符阶段每一条都会命中）。 —— 同上。
- **默认语言缺失 = 必需缺失 ⇒ `PushError`**（内容层还带 `throw`）。 —— 同上；对上 `.claude/rules/null-check-rules.md` 的两种失败语义。
- **能机械变换的绝不建第二张手写表。** —— `code → ERR_*`、`code + reasonKey → 二级键`、「繁体走简繁转换而非再开一列」三处已连续兑现同一条。
- **`ERR_` 分区保留给 `code` 的机械像，人不得手写。** —— 同文件禁令。
- **告警要落在能被看见的地方；纪律的可执行化取第 2 级（一次审计）。** —— 同文件「UI 文案字面量审计」；CJK 字符判据在本作**特别可靠**（键恒为 ASCII 大写，内容文案不经 UI 代码传递）。
- **不另开构建期工具链**，本机验证走 Godot 编辑器运行。 —— `.claude/rules/environment-rules.md`。
- **本地化打磨在 MVP 范围外**（现在做键与结构，不产出英文文案）。 —— `vision/scope.md`。

## 建议方案

### 1. 占位形态：`en` 单元格**留空**——与内容层「缺 `en` 键」是同一条判据的两次兑现

`[既有推演]`

CSV 一行未翻译时写成 `KEY,"中文文案",`（`en` 列为空单元格），**不写任何哨兵值**。

- 这与内容层已答定的「`Entries` 只有 `zh` 键」在语义上**逐字同构**：两层载体不同（CSV 行 vs 字典键），但「未翻译」的判据都是**该 locale 下没有可用值**，而不是「该 locale 下有一个约定好的特殊值」。内容层为此写下的理由原样适用：**覆盖率审计因此不需要第二套「什么算占位符」的识别规则**。
- 它同时落在「能机械变换的绝不建第二张手写表」内：任何非空占位符都是**人手写下的第二份约定**，而约定一旦要人遵守就会被违反（漏写、写错大小写、写成 `TODO:` 带冒号），且违反的后果正是覆盖率虚高。
- 附带收益：`git diff` 上「这一批英文补上了」表现为空单元格被填上，可读性最好；反之若占位符是键名，diff 里满屏是键名到英文的替换，与「新增一行」难以区分。

**连带纪律（必须一并写下，否则本形态会被绕过）：**

- **`en` 列绝不复制 `zh` 原文。** 这是覆盖率恒读 100% 的最容易发生的路径（复制粘贴整列），且英文玩家看到中文、**零症状**。可机械检查，见子项 3 的伪翻译告警。
- **`en` 列绝不写键名本身。** 理由见「备选方案」。

### 2. 运行时回落：靠 `TranslationServer` 的 fallback locale，不在调用点写分支

`[既有推演]` + `[通行做法]`

- Godot 的 `tr()` 在缺键 / 空值时**原样返回键本身**（这一点 `ux/error-and-blocking-ux.md` 已写明，正是 `ErrorText` 要包一层的原因）。占位形态取「空」之后，若不设回落，英文 locale 下**每一条 UI 文案都会显示成大写英文键**——这比显示中文更糟。
- 建议在 `project.godot` 增设 **`internationalization/locale/fallback = "zh"`**（与既定的「默认 locale `zh`」同处、同批落在 `FR-ux-translation-foundation` 的第二件事里）。此后 `en` 下缺值 → 引擎自动回落 `zh` 串，**调用点零分支**。
  - 这让 UI 层与内容层的运行时行为**完全一致**：`LocalizedText.Get()` 缺 `en` → 静默回落 `zh`；`tr()` 缺 `en` → 静默回落 `zh`。两层不同载体、共用同一个语言开关，理应也共用同一条回落语义。
  - 「调用点零分支」正是既定的「归一在启动期做一次，此后 CSV 与 `LocalizedText` 两层各自零分支」那条的延续。
- **不留痕（不逐次警告）**，与内容层同理同据：占位符阶段每一条 UI 文案在 `en` 下都会命中回落，逐次 `PushWarning` = 每帧刷屏并淹掉真告警。留痕责任**全部**交给子项 3 的一次性覆盖率审计。

> ⚠ **一处必须同时订正的现有措辞**，否则占位符阶段会被刷屏：`ErrorText.For` 现定为「一级键缺条目才 `PushWarning`」。此处的「缺条目」必须明确为**「`errors.csv` 里根本没有这一行」（按默认语言 `zh` 列判）**，而**不是**「当前 locale 解析不出值」。若按后者判，英文 locale 下每一个 `code` 都会报一次 `missing translation`——那恰恰是「真告警被噪音淹掉」的复现。

### 3. `AuditTranslations()` 的判定规则：三条判据，数据源统一为翻译对象的消息表

`[既有推演]`

在既有的正向（已知 `code` 缺条目）+ 反向（`ERR_*` 前缀匹配）之上，加**第三条：覆盖率**。三条判据：

| 判据 | 条件 | 处置 |
|---|---|---|
| **未翻译** | 键不在 `en` 的消息表中 **或** 其值为空 / 全空白 | 计入未翻译，**不逐条告警** |
| **伪翻译** | `en` 的值**含 CJK 字符** | **不计入已翻译分子** + 单列一条 `PushWarning` 列出前 N 个键 |
| **已翻译** | 其余（非空、无 CJK） | 计入分子 |

- **「缺键 **或** 空值」是刻意的双判据，不是冗余。** Godot 的 CSV 导入器对空单元格是「跳过该键」还是「写入空串」属落地细节（与 `auto_translate_mode` 同属一次 `.csproj` 生成后的实测项）。两种行为下本判据**结论完全相同**，因此本方案**不依赖那次实测**，也不被它阻塞——与既有「两种情况下键的形态、分区表、两条审计完全相同」是同一种写法。
- **伪翻译判据复用 CJK 检测**，与既定的「UI 文案字面量审计」是同一条判据的第二次使用。文档已论证 CJK 判据在本作特别可靠（键恒为 ASCII 大写）。它挡住的正是子项 1 那条连带纪律（`en` 列复制了中文原文）——这是覆盖率虚高的最后一条路径，且**同样零症状**。
- **数据源建议统一为 `TranslationServer.GetTranslationObject(locale)` 的消息表，而非读 `res://text/*.csv` 源文件。** 见「与既有决策的张力」——现有反向审计写的是「扫 `errors.csv`」，而 `.csv` 是导入源文件、**不随导出包分发**（包内只有 `.translation`）。改用消息表后三条判据在编辑器与导出包内同样成立，且省掉一个 CSV 解析器。
- **输出形态与内容层的覆盖率审计对齐**：一条 `GD.PushWarning`，按分区分行 + 一行合计，例：
  ```
  [ErrorText-AuditTranslations] en coverage: 0 / 41 (errors) · 3 / 18 (common) · … · total 3 / 612
  [ErrorText-AuditTranslations] suspected untranslated-but-filled (CJK in en): COMMON_OK, LOGIN_TITLE, …
  ```
  「英文版做到哪一步了」因此是一个能一眼读到的数——与内容层 `en: 12 / 840 条目已翻译` 逐字同构。
- **覆盖率审计覆盖全部 `res://text/*.csv` 分区**，不止 `errors.csv`（正向 / 反向两条仍只针对 `ERR_` 分区，那两条的判据本就依赖处置表的 `code` 全集）。

### 4. 闸门：只加一条启动期告警级闸，不加编译期闸，不加硬失败

`[取向选择]`（推荐项见下）+ `[既有推演]`（不加编译期闸这一半）

- **不加编译期 / 构建期闸门。** `.claude/rules/environment-rules.md` 明确本机验证走 Godot 编辑器、不假定额外工具在 PATH 上；`ux/error-and-blocking-ux.md` 已为同一问题给出过结论（「故不另开构建期工具链」）。这一半属 `[既有推演]`，不需用户裁决。
- **`en` 缺失一律不阻塞**：它是可选缺失，回落完全可用，且**当前设计状态下 100% 的条目都缺 `en`**——任何硬闸门会让游戏直接起不来。
- **`zh` 列为空 → 启动期 `PushError`**（附键名与所属分区文件）。这与内容层「默认语言缺失 → `PushError`」同档：一条没有中文的 UI 键会让中文玩家看到一个大写英文键。**已定案：不 `throw`**，只 `PushError`；该不对称的理由须落笔，见「用户裁决」B。
- **不加 `OS.HasFeature("editor")` 守卫**：改用消息表数据源后三条判据在导出包内同样成立，且与内容层覆盖率审计（未加守卫）保持同形。CJK 字面量审计需要守卫是因为它扫的是 `.tscn` / `.cs` 源文件——那是**数据源差异导致的差异**，不是两套纪律。

### 5. 审计的落点：新增一个同处调用的静态审计入口

`[取向选择]`（推荐项见下）

覆盖率审计要扫**全部分区**，而 `ErrorText` 是错误文案的门面（`For` / `ToTranslationKey` 都只服务 `ERR_` 分区）。把「扫全库分区」塞进 `ErrorText.AuditTranslations()` 与该类的职责不符——这与文档已用过的判据同源：**按「它服务于谁」定位，而不是按「谁先用到它」**（`ErrorText` 不放 `src/Core/` 用的正是这一条）。**已定案：新增独立入口 `TranslationAudit.AuditCoverage()`**，见「用户裁决」A。

## 具体形态（可 derive 的落地面）

**CSV 行形态**（`res://text/<partition>.csv`，列 `key, zh, en`）：

| 状态 | 行 | 审计判定 |
|---|---|---|
| 未翻译（默认状态） | `COMMON_CONFIRM,"确定",` | 未翻译，计入分母 |
| 已翻译 | `COMMON_CONFIRM,"确定","Confirm"` | 已翻译，计入分子 |
| **伪翻译（禁止）** | `COMMON_CONFIRM,"确定","确定"` | CJK 命中 → `PushWarning`，**不计入分子** |
| **默认语言缺失（坏数据）** | `COMMON_CONFIRM,,"Confirm"` | `PushError` + 键名 + 分区文件 |

**`project.godot` 增设一项**（落在 `FR-ux-translation-foundation` 的第二件事内）：

```
internationalization/locale/fallback = "zh"
```

**审计签名**（落点已定案为独立入口 `TranslationAudit`，见「用户裁决」A）：

```csharp
/// 全 res://text/ 分区的 en 覆盖率审计。数据源 = TranslationServer.GetTranslationObject(locale)
/// 的消息表（非 .csv 源文件——.csv 不随导出包分发）。
/// 未翻译 := 键不在 en 消息表中，或其值为空 / 全空白。
/// 伪翻译 := en 值含 CJK 字符 → 不计入分子，单列一条 PushWarning。
/// zh 值缺失 / 空 → PushError（键 + 所属分区）。
/// 输出：按分区一行 + 合计一行，单条 GD.PushWarning。
public static void AuditCoverage();
```

**对既有 `ErrorText` 代码块的两处订正：**

1. `For` 的文档注释「一级键缺条目才 `PushWarning`」→ 明确为「**一级键在默认语言 `zh` 下无条目**才 `PushWarning`」。
2. `AuditTranslations` 的注释里「反向 —— 扫 `errors.csv`」→ 「反向 —— 扫 `ERR_` 分区的**消息表**」。

## 备选方案（已考虑并否决）

- **占位符取键名本身（`COMMON_CONFIRM,"确定","COMMON_CONFIRM"`）** —— 否决。① 它是第 1 列的**机械像**，手写一份即「能机械变换的绝不建第二张手写表」的正面违反，且写错一个字符就变成一条无人察觉的假翻译；② 引擎在缺值时**本就返回键名**，显式写一遍是纯冗余劳动（全库每一行都要写）；③ 覆盖率审计被迫加一条「值 == 键」的识别规则——正是内容层明确要避免的「第二套什么算占位符的识别规则」；④ 一旦该识别规则漏判，玩家直接看到 `ERR_AUTH_SESSION_REVOKED`。
- **占位符取 `TODO` / `[TODO] 中文原文`** —— 否决。同样是手写哨兵（第二张表），且形态一定会漂移（`TODO` / `TODO:` / `todo` / 带原文）；审计要维护一套哨兵识别规则；漏判时玩家看到 `TODO`。它相对空单元格**没有任何信息增量**——「哪些没翻」由覆盖率审计报，不需要写在每一行里。
- **占位符取机翻初稿** —— 否决。① 它把覆盖率**恒读作 100%**，正是本问题要防的那件事，且机翻与人工翻译在值的形态上**不可机械区分**（要区分就得再加一列状态，两列封顶被打破）；② 产出英文文案属本地化打磨，`vision/scope.md` 已明确在 MVP 范围外；③ 若日后确要机翻打底，它应作为一次**批量填值 + 单独的质量状态跟踪**来做，而不是靠「占位符的形态」承载——那会让占位符字段兼两个身份，与「`OpResult.Detail` 不兼两个身份」同一条。
- **`en` 列复制 `zh` 原文** —— 否决且需主动防。覆盖率 100%、英文玩家看到中文、**零症状**；由 CJK 伪翻译告警挡住。
- **不设 fallback locale，在 `tr()` 外再包一层 `UiText.Get(key)` 自己回落** —— 否决。引擎已提供该能力，包一层等于把一条零成本的引擎配置换成一个全库必须遵守的调用纪律（且它挡不住 `.tscn` 里直接写 `text = "KEY"` 的自动翻译路径）。与「否决先用 C# 常量表再迁」同源：**多出的那层没有收益**。
- **把覆盖率做成 EditorScript 手动跑** —— 否决，理由与文档已写下的一致：**脱离启动链就没人会记得跑。**

## 与既有决策的张力

**一条，且它是本方案顺带发现的一个既有缺陷，需用户确认订正：**

`ux/error-and-blocking-ux.md` 现把反向审计写成「**扫 `errors.csv`**」。但 `.csv` 是 Godot 的**导入源文件，不随导出包分发**（包内只有 `.translation`）——这与该文档自己为 CJK 字面量审计写下的理由**逐字同构**（「导出包里 `.tscn` 已编译为 `.scn`、`.cs` 不随包分发，源文件扫描在发布版中无从执行」）。故现状下反向审计要么必须加 `OS.HasFeature("editor")` 守卫、要么在发布版静默失效。

- **建议的松动方式：** 把三条审计的数据源统一改为 `TranslationServer.GetTranslationObject(locale)` 的**消息表**。反向审计要的「`errors.csv` 里有哪些 `ERR_*` 行」在消息表里同样拿得到（`ERR_` 分区的键全集），判据（前缀匹配）**一字不改**，且不再需要守卫、不再需要 CSV 解析器。
- **不松动时的替代：** 反向审计与覆盖率审计双双加 `OS.HasFeature("editor")` 守卫，接受「发布版无审计」。代价是覆盖率这个数只能在开发机上看到——但英文覆盖率本就是开发期指标，此替代**可接受**，只是白留一个 CSV 解析器。
- 无论取哪个，**本方案的占位形态与三条判据都不受影响**。

## 前置依赖

- **无阻塞性前置。** 本方案刻意做成**不依赖** `auto_translate_mode` / CSV 导入器空单元格行为的那次实测（子项 3 的双判据即为此设计）。
- **弱依赖（不阻塞定稿）：** 各 `ERR_*` 与四条兜底文案的**逐条中文措辞**仍待文案定稿——那是填 `zh` 列的内容，与本方案定的 `en` 列形态互不牵动。

## 用户裁决（2026-08-19 · 全部定案）

**三项取向全部按本方案的推荐定案（各取选项 1），逐条无保留采纳。** 本方案自此为**定案方案**，`## 建议方案` 与 `## 具体形态` 各节即最终形态，可直接喂给 `/analyze-new-ideas` 提炼。

| # | 取向 | 定案 | 承重理由（保留） |
|---|---|---|---|
| A | 覆盖率审计的落点与命名 | **新增 UI 层静态入口 `TranslationAudit.AuditCoverage()`**，与 `ErrorText.AuditTranslations()`、CJK 字面量审计**同处启动期依次调用**（三处，调用顺序须在 `FR-ux-translation-foundation` 里明写） | 「按它服务于谁定位」正是文档为 `ErrorText` 不放 `src/Core/` 写下的那一条判据，此处不宜自我例外；且覆盖率审计与错误码处置表**零耦合**（不读 `code` 全集）。塞进 `ErrorText` 会让它从「错误文案门面」膨胀为「全库翻译门面」 |
| B | `zh` 列为空时是否 `throw` | **只 `PushError`（键名 + 分区文件），不 `throw`** | 与内容层的「`PushError` + `throw`」**刻意不对称，且该不对称须在文档里写明理由**：内容层 `throw` 是因为坏内容会进抽取池、被存档引用、把错误扩散到不可逆处；缺一条 UI 文案只影响**一屏的一处显示**，回落后仍是一个可操作的界面。这正是 `null-check-rules.md` 两种失败语义的分界 |
| C | 伪翻译（`en` 含 CJK）的处置档 | **`PushWarning` + 不计入覆盖率分子** | 它与「`en` 缺失」本质是同一件事（这一条没翻），只是表现形态更隐蔽；处置档理应相同，差别只在「多说一句」。用 `PushError` 会在同一维度上给出两种严厉度，且纯符号 / 数字类条目存在误报可能 |

**落笔时必须一并写下的两句：** ① B 项那条**不对称的理由**（否则后来者会把 UI 层与内容层读成矛盾）；② A 项三处启动期审计的**调用顺序**。
