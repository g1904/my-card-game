# 方案草稿 — 打包闸简化的采纳条件与爆炸半径闸优化路径的读数面（后端半）

> 本份只写归后端的那一半：**C6 简化的采纳条件**与 **A4' 优化路径的读数面 / 采纳触发 / 同批落地协议**。内容发版纪律（能否删条目、退役路径、发版闸）与产包证明的字段形态**全部归对侧**，见 front matter 的 `counterpart`，本文一律回链不复述。

## 问题

C6 现取安全默认（兼容矩阵内每个在架基线各跑一遍），并记录了「若客户端确立超集纪律，可简化为只跑最新」。A4' 记录了一条尚未采纳的优化路径（阈值按类型池规模缩放），其数据依赖（产包证明供池规模数）须与客户端同批落地。对侧现已在 `counterpart` 中提案确立超集纪律并预写计数字段形态——本库这一半须回答：简化采不采、优化路径何时采、怎么读数。

## 约束（来自既有设计）

- 打包闸校验规则的权威在客户端，本库不复述、不复制实现——发布侧只做产物认证核对（C1，`operations/content-delivery-ops.md`）。
- 后端不区分内容类别、`disabledIds` 只是一串 `Id`（A4'，契约逐字要求；`contracts/content-manifest.md`）。
- 并存在架版本数是个位数，逐基线成本可忽略（C6 自注）。
- 客户端条目 `Id` 恒为 `<内容类型前缀>.<slug>` 两段式（权威：`game-design-documents/content/_index.md`「条目 `Id` 约定」）。

## 建议方案

### 1. C6：**不采纳任何单基线简化，改写前提句**

`[既有推演]`（对闸判据的逻辑推演，与 `counterpart` 建议 4 同一条推演的本库落笔）

对侧推演确认：即便超集纪律成立，「只跑最新」也**不健全，且方向反了**——存在性判据在 `Id` 最少的**最旧**在架基线上最严（overlay 触到新版本才有的 `Id`，对老基线即非法新增）；而「只跑最旧」同样漏值敏感断言（合并校验的结果依赖各基线自身字段值）。结论：**逐基线各跑一遍维持为长期形态**，成本已注明可忽略，本来就无需省。

**改写 C6 的前提句**：删去「它需要『更高版本基线是更低版本基线的超集』这个本库不裁决且不必然成立的前提」，改为——超集纪律已由客户端确立并由发版快照归档闸机械保证（回链 `counterpart` 采纳后的落点，`game-design-documents/systems/services/content-service.md`）；但该简化经推演不成立（存在性判据最严处在最旧基线 + 值敏感断言依赖各基线取值），**故不采纳，且此项不再是待优化项**。

### 2. A4' 优化路径的读数面（采纳时的形态，现在定死）

`[通行做法]`（数据由产权方 emit、策略由闸的持有方裁决的标准分工；具体数值为待校准初值）

| 项 | 形态 |
|---|---|
| 数据来源 | 产包证明的 `entryCountsByType`（字段形态归客户端，见 `counterpart` 建议 5，本库只读数字） |
| 分组 | 对 `disabledIds` 逐条取**首个 `.` 之前的前缀**做纯字符串分组——语法操作，不解析内容、不识别语义，与「后端不区分内容类别」相容（读的是 `Id` 的既定语法，不是内容） |
| 池规模口径 | 同前缀计数在**兼容矩阵内全部在架基线中取最小值**（分母取小 = 阈值取严 = 保守） |
| 阈值合成 | 确认参数在「新增解析规模 > 20 **且** > 5% × 该前缀池规模」时才要求（等效阈值 = max(20, 5% × 池)）——对小池维持绝对 20，对大池放宽摩擦 |
| 兜底 | 前缀不在计数表（未知前缀 / 计数缺失 / 证明过旧）→ 该组按绝对阈值 20 单独判，不放行 |
| 数据时效 | 用最近一次内容发布的证明计数；flags 发布不重取（池规模变化以内容发版为节拍，慢于 flags） |

### 3. 采纳触发判据（现在定死，触发前一字不动）

`[通行做法]`（friction 驱动的运维旋钮升级，初值待实测校准）

- **触发信号（满足其一）**：① 一个季度内 ≥ 2 次**合法**批量关闭被迫携带显式确认参数（绝对 20 已成日常摩擦）；② 任一 flags 适用前缀的最小在架池规模 > **400**（此时 5% > 20，缩放开始有意义——400 = 20 / 5% 的直接推导）。
- **触发者 = 本库运维**（闸与摩擦都在本库可见处），触发后提起同批落地，不由客户端侧猜测时机。

### 4. 同批落地协议

`[既有推演]`（跨库纪律「对称落笔、单侧采纳即两侧不一致」的直接应用）

采纳日一批改两库：客户端开启 `entryCountsByType` 的 emit（形态已预写，见 `counterpart`）；本库把 A4' 的「优化路径」段改写为已采纳规则 + 上表读数面；步 ⓪ 的「证明自洽」核对顺带扩展到计数项（非负整数 · 前缀符合两段式语法）。**任一侧未落，另一侧不启用。**

## 具体形态（可 derive 的落地面）

`operations/content-delivery-ops.md`：C6 行的前提句按建议 1 改写；A4' 行的「优化路径」句改写为「已定形态、未采纳」并附建议 2 / 3 两张表（或回链本草稿提炼后的落点）。数值初值一览表追加两行：池规模缩放触发（季度 ≥ 2 次摩擦 / 最小池 > 400）· 池规模口径（矩阵内最小值）。

## 后果

- C6 从「留着一个不成立的优化想头」变为定案，兼容矩阵扫描是长期形态——`deployment.md` 的基线快照可达性要求因此是永久义务而非过渡态。
- A4' 的采纳从「将来再整体设计」压缩为「翻一个双侧开关」。
- 本库零新增契约面、零新增报文——计数活在发布侧产包证明里，不下发客户端、不进 flags 应答。

## 备选方案（已考虑并否决）

- **采纳「只跑最旧在架基线」**（超集下存在性判据的健全简化）— 否决：仍漏值敏感断言，且省下的只是个位数次数的运行——为一个不完整的简化引入「哪个基线才算最旧」的边界维护，净亏。
- **现在就采纳 A4' 优化路径** — 否决：A4' 自注「不为一个初值旋钮提前付这笔账」仍成立；当前内容规模远未到 400 池，绝对 20 尚无摩擦证据。
- **后端持有内容类型 → 池规模的自维护表** — 否决：制造对侧内容集的第二副本，与「只读数字不解析内容文件」的既有立场直接相抵。

## 与既有决策的张力

- 本方案**改写 C6 与 A4' 的记载句**是其目的本身，不与任何 ADR 冲突；唯一被订正的是「超集成立 → 可只跑最新」这句经推演不成立的优化前提（`handoffs/2026-09-03-content-delivery-ops.md` 亦有同句，落笔时以主题文档为准更新，handoff 按活文档纪律同批订正或由回链承载）。
  → 已裁决（2026-09-06 · 批量评审）：采纳推演——「只跑最新」不成立，逐基线各跑定为长期形态；C6 前提句、本库 09-03 handoff 同句与对侧 `ADR-0141` 后果句按本草稿建议订正，随 `/analyze-new-ideas` 落笔。

## 前置依赖

- **与 `counterpart` 成对采纳**：C6 前提句的改写以对侧「超集纪律 + 发版归档闸」的落笔为回链锚点；建议 2 的读数面以对侧 `entryCountsByType` 的 dormant 形态为数据契约。单侧采纳即两侧不一致。
- A4' 优化路径本体维持未采纳；本方案只定其采纳条件与形态，不构成采纳。

## 仍需用户决定

- 无。三个数值（20 维持既有初值、5%、400 与「季度 ≥ 2 次」）均为待实测校准的初值，按 A4' 既有惯例登记于数值初值一览，不构成取向。
