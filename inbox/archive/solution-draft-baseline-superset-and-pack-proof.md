# 方案草稿 — 基线内容超集纪律与产包证明条目计数（客户端半）

> 本份只写归客户端的那一半：**内容发版纪律**（能否删除随包条目、退役路径、发版闸）与**产包证明的字段形态**。打包闸简化的采纳条件、爆炸半径闸优化路径的读数面与采纳触发归对侧，见 front matter 的 `counterpart`，本文不复述。

## 问题

两条 2026-09-05 登记的跨边界待承接项，紧耦合、须一起答：

1. **更高版本客户端的随包基线内容集，是否恒为更低版本基线的超集？** 即「客户端发版能否删除随包内容条目」这条本库尚未定的内容纪律。对侧（`backend-design-documents/operations/content-delivery-ops.md` C6）现取安全默认（兼容矩阵内每个在架基线各跑一遍打包闸），并记录了「超集成立则可简化为只跑最新」这个前提。
2. **产包证明是否增设「按类型的条目计数」一格。** 对侧 A4' 的一条尚未采纳的优化路径需要它（爆炸半径闸阈值按类型池规模缩放，池规模由发布侧产包证明供数、对侧只读数字不解析内容文件），且对侧自注该项须与客户端同批落地。ADR-0141 本次已明确不纳入。

## 约束（来自既有设计）

- **强制在线 · 云端权威**：存档跨客户端版本更新迁移（玩家升级 App，云端档原样拉回）→ `decisions/ADR-0003-online-cloud-authority.md`、`vision/scope.md`。
- **读取侧不过滤 + `Get(id)` 缺失即 `PushError` + 抛**：「存档引用未知内容」的风险被设计为**从根上消失、无需任何兼容规则** → `systems/services/content-service.md`「热更范围」、`decisions/ADR-0007-local-content-layer-and-overlay.md`。
- **`ContentEnabled` 永久禁用机制已存在**：关闭一个条目只让它不再被新抽到，存档引用照常解析；结构性查表类型（`PlotNodeData` / `LocationData` / `HiddenStatBandData` / 一切 `ISingletonContent`）恒启用，禁用即启动期 `PushError` → 同上「放量开关」节。
- **合并后强校验含值敏感断言**（`BandIndex` 连续性、交叉引用不悬空、`Rarity` 必填、单例条数、`zh` 必填——disabled 条目照常参与）→ 同上。
- **发版基线快照按在架版本归档、发布侧可达；打包工具不自持在架版本清单** → `decisions/ADR-0141-overlay-packer-proof-and-baseline-snapshot.md`。
- **图鉴 / 账号级资产钉在内容 `Id` 上**：图鉴统计走 `AllIncludingDisabled()`；改地域图连边 = 清空账号级 `LocationCodex` 资产 → `systems/services/content-service.md`、`decisions/ADR-0042-location-flat-set-and-single-map.md`。
- **纪律的可执行化阶梯**：能上线且线上不可见的纪律必须落到机械闸 → `decisions/ADR-0013-discipline-enforceability-ladder.md`。

## 建议方案

### 1. 内容发版纪律：随包基线条目**永不删除**（Id 超集不变式成立）

`[既有推演]`（来源：ADR-0003 + content-service「读取侧不过滤」+「无需任何兼容规则」）

删除一个随包条目会精确重演 overlay「只改不增」纪律要防的那个事故，只是换了通道与方向：云端权威档里躺着 `card.foo` 的持有实例，玩家把客户端从 1.1 升到删掉它的 1.2，拉档 → `Get("card.foo")` → `PushError` + 抛 → **升级即废档**。整个内容架构的承重句「存档引用未知内容的风险从根上消失，无需任何兼容规则」是以「已发布的 `Id` 永远可解析」为前提的；允许删除就得为发版通道发明一整套本库明确庆幸不需要的兼容规则。另两条独立支撑：图鉴统计走 `AllIncludingDisabled()`，删条目会让全体玩家的图鉴分母跳变；结构类型（地域图顶点、剧本节点、档位表行）删一条即结构空洞，本库已把「图的稳定性」写为对玩家的隐性承诺。

**故纪律定为：客户端发版对随包基线只增不删——跨发版的基线 `Id` 集合单调不减。** 推论：更高版本基线恒为更低版本基线的 **`Id` 层超集**。**精确表述（承重）：超集只在 `Id` 集合层面成立；字段值与 `ContentEnabled` 取值不承诺跨版本不变**（发版本就可以自由改值，这正是退役路径的载体）。

- **改名 = 删 + 增，同样禁止**——与既有的「`Id` 稳定唯一、成员名与 code 冻结、永不复用」纪律同构（`systems/common-properties.md`）。
- **剧本类型不开删除例外。** `[通行做法]` overlay 例外（剧本可新增）的判据是「不被存档引用」，key points 悬空已有降级处置，故剧本条目理论上可删；但为它开例外会把超集不变式从全称命题降为带类型白名单的命题，发版闸与对侧回链都要跟着带条件，换来的只是省下 KB 级文本的包体——不值。统一不删，废弃 arc 用 `ContentEnabled = false` 退役（arc 参与放量，禁 arc 合法）。

### 2. 退役路径：按类型三分，全部落在「只改不删」内

`[既有推演]`（`ContentEnabled` 三层机制与结构类型恒启用规则的直接应用）

| 类型 | 退役形态 |
|---|---|
| 抽取池成员（卡 / 事件 / 敌人 / 法则 / 神通 / 古宝 / 法宝 / 功法 / `PlotArcData` / 文案候选） | 基线里置 `ContentEnabled = false`（永久禁用）。条目留存、`Get(id)` 照常解析、不再被新抽到 |
| 结构性查表类型（`PlotNodeData` / `LocationData` / `HiddenStatBandData` / `ISingletonContent`） | **没有退役一说**——恒启用且删除即结构空洞；只能演进字段值 |
| 合规级移除（法务 / 商店审核要求某条内容消失） | **掏空而非删除**：字段值改为中性内容（`zh` 文本须留非空的中性句——空串会触发强校验）、`Artwork` 置空并**在同版删除其不再被引用的贴图资产**（回收包体）、`ContentEnabled = false`。`Id` 壳留存，存档解析不断 |

- **包体代价有界**：不删条目 ≠ 不删资产。退役条目的 `Artwork` 可置空（可空是常态，占位回落已有），其贴图从包内移除是合法的——`.tres` 文本壳是 KB 级，长期累积可忽略。这与「不预埋空壳 `Id`」不冲突：那条否决的是**从未发布过**的假条目（校验放不宽 + 审核灰区），退役条目是曾经完整发布过、且已被禁用不进池的真条目。

### 3. 机械闸：发版快照归档步比对上一版 `Id` 集

`[既有推演]`（ADR-0013 选级判据：删条目「能上线、线上不可见」——症状在老档玩家升级后才炸；ADR-0141 已备好基线快照基础设施）

- **落点 = 基线快照归档步**（每次客户端发版归档快照时）：枚举新快照的 `Id` 全集，与**上一份已归档快照**比对；出现「上一版有、本版无」的 `Id` → **非零退出，归档与发版闸失败**，报出缺失 `Id` 清单。
- 只比上一版即可——超集关系传递，逐版通过则全链成立。
- 顺带把「快照形态须可枚举 `Id` 集」立为快照形态（归本库自决那一项）的一条硬要求。
- 这道闸使超集不变式对对侧成为**被机械保证的事实**而非口头纪律——对侧 C6 前提句的改写以此为回链锚点（改写本体在 `counterpart`）。

### 4. 超集成立 ≠ 打包闸可以只跑最新（对既有记载的一处订正）

`[既有推演]`（对 C6 判据的逻辑推演；本条结论的对侧落笔在 `counterpart`，此处只写客户端立场）

推演发现：**「只跑最新」这个记录在案的简化方向反了，即便超集成立也不健全。** 打包闸的存在性判据（「overlay 触到的 `Id` 必须存在于基线」「新增剧本条目的非剧本引用必须存在于基线」）在 **`Id` 最少的那个基线**（兼容矩阵内最旧的在架版本）上最严：overlay 若改了一个 1.2 新增、1.1 没有的条目，对 1.1 玩家它就是非法新增 `Id`——只跑 1.2 基线恰好漏掉闸要防的那件事。且合并校验含值敏感断言（`BandIndex` 连续性等），其结果依赖各基线自身的字段值，超集（`Id` 层）不能使任何单基线运行覆盖其余。**客户端立场：超集纪律成立，但不因此弱化任何客户端义务——产包证明仍按被跑的每个基线逐份产出，逐基线各跑一遍维持不变**（对侧已注成本可忽略）。

### 5. 产包证明「按类型条目计数」：维持不增设，但**现在预写形态**

`[既有推演]`（ADR-0141 备选已裁「本次不纳入」；对侧 A4' 自注「不为一个初值旋钮提前付这笔账」——两侧现状一致，不翻案）
`[通行做法]`（预写 dormant 形态：跨侧同批变更最贵的是协调成本，本项目已两次踩过「第二半经常不会发生」；形态先定死，采纳日退化为机械开关）

- **本次不 emit、不进字段集**——一个无人消费的字段就是无人校验的字段，先发出去只会静默腐坏。
- **但形态现在写进 `content-service.md` 的产包证明节**，作明确标注「已设计、未启用；启用与对侧 A4' 优化路径同批」的附注：

| 项 | 形态 |
|---|---|
| 字段名 | `entryCountsByType` |
| 键 | 内容条目 `Id` 的**首段前缀**（`content/_index.md` 的 `<内容类型>.` 段，如 `card` / `player_power`）——对侧按同一前缀对 `disabledIds` 做纯字符串分组，不解析内容 |
| 值 | 该基线 + 本次 overlay **合并后 `ContentEnabled == true`** 的条目数（= 抽取池口径） |
| 覆盖面 | 仅 flags 适用类型（结构性恒启用类型不 emit——flags 对其本就不生效，emit 了对侧也不该用） |
| 基数 | **按被跑的基线逐份**，与证明中「基线 `appVersion`」同层级落；具体嵌套在采纳批内与证明结构一并定 |

- 计数由打包工具在既有的逐基线 `LoadAll()` 运行里顺手产出，零新增校验路径。
- 采纳触发判据与后端读数面（min 口径、未知前缀兜底、阈值合成）归对侧，见 `counterpart`——本库不复述。

## 具体形态（可 derive 的落地面）

`systems/services/content-service.md` 新增「内容发版纪律（基线 `Id` 超集不变式）」小节，内容 = 上方 1–3 的纪律句、退役三分表、归档步比对闸；产包证明节追加第 5 项的 dormant 字段附注。ADR 候选一条：**「随包基线条目永不删除；退役 = 永久禁用 + 掏空，发版快照归档步机械核对 `Id` 超集」**（归 `/write-adr`）。

## 后果

- `systems/services/content-service.md`：新增发版纪律节 + 产包证明附注。
- `decisions/ADR-0141` 后果节的「若日后确认超集…可简化为只跑最新」一句需订正（超集已确立，但该简化经推演不成立——见建议 4）。
- 对侧 `operations/content-delivery-ops.md` C6 / A4' 的改写见 `counterpart`。
- 无存档影响、不 bump schema、无报文改动；发版闸是构建期工具行为，不触运行时。

## 备选方案（已考虑并否决）

- **允许删除 + 为发版通道立存档兼容规则**（未知 `Id` 静默剔除 / 迁移表）— 否决：重新引入整个架构明确宣布「从根上消失」的那类风险，且云端权威下「静默剔除」实质是客户端擅改权威档。
- **剧本类型开删除例外** — 否决：超集不变式降为带白名单命题，闸与回链复杂化，收益 KB 级（见建议 1）。
- **现在就 emit `entryCountsByType`** — 否决：无消费者的字段静默腐坏；两侧既有裁决（ADR-0141 备选、A4' 自注）均为「不提前付账」。
- **连形态也不预写，触发时再整体设计** — 否决：跨侧同批变更的协调成本是本项目已验证的高危项（cross-boundary.md 序言），形态预写把采纳日的工作量压到机械开关。

## 与既有决策的张力

- **ADR-0141 后果节与对侧 C6 记载的「超集成立 → 可只跑最新」前提句，经推演不成立**（方向相反 + 值敏感断言，见建议 4）。这不与任何决策本体冲突——两侧都取了安全默认、未采纳该简化；张力只在一句记录在案的优化前提上，两侧各自订正各自那句（本库 ADR-0141、对侧 C6），由用户在评审本草稿时一并裁决订正。
  → 已裁决（2026-09-06 · 批量评审）：采纳推演——该简化不成立，逐基线各跑定为长期形态；三处既有落笔（本库 `ADR-0141` 后果句 · 对侧 C6 前提句 · 对侧 `handoffs/2026-09-03-content-delivery-ops.md` 同句）按本草稿建议订正，随 `/analyze-new-ideas` 落笔。
