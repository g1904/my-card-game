# 方案 — 「失去能力」四支的频次预算配平

## 问题

`systems/player-profile/player-power/_index.md:100` 定的上层口径是：**「这次可能失去法则」的事件应约占全部 AdventureEvent（五类）的 1%**，分子当时是三支。此后两侧同时变动：

- **分子由三支变四支**：神通（`CharacterPower`）侧的置换 / 禁用挤进同一份预算、不另立一套（`systems/character-profile/power/_index.md:50`）。
- **分子的第一支被显式上调**：`IgnoresProtection` 的目标频次由 1% 上调至 5%（战斗类遭遇为分母，`balance.md:674-678`）。
- **分母两度漂移**：先由 86–102 下修至 ≈83，又随时长重标定升至 **114**（战斗类遭遇 23 → **≈37**）。

算术后果是 `player-power/_index.md:104` 已如实记下的那条张力：**单 `IgnoresProtection` 一支就已超出上层总额**。本稿把它算清并配平。

## 分母口径（定案值）

- **一轮回事件总数 = 114**（35 / 36 / 43，rescale 稿 ③，替换 `balance.md:586` 的 25 / 26 / 32）。该分母是五类 AdventureEvent 全体、**含 Travel**（`player-power/_index.md:100` 明写「全部 AdventureEvent（五类）」；Travel 不占 `eventCountLimit` 配额但玩家确实经历）。
- **一轮回战斗类遭遇 ≈ 37**（常规 34.4 + 3 个 Finale，rescale 稿 ③，替换 `balance.md:678` 的 23）。

## 约束（来自既有设计）

- **`IgnoresProtection` 的两条硬准入 R1 / R2 与「值得记住、但会真的遇到」的量级定性不动**（`balance.md:674-681`）；目标频次已随分母上移由 5% 定案下调至 **3%**（3% × 37 = 1.11 次/轮回，保住「一轮回约 1 次」的既有量级——正确的收紧位置是这一格，而不是压三支持久支）。
- **四支共用一份预算，神通侧不另立一套**（`character-profile/power/_index.md:50`、`player-power/_index.md:104`）。
- **两个口径都不可机械校验**，落在内容编排与抽取权重侧，代码只留 `PushWarning`（`player-power/_index.md:101`）。**本稿不引入任何新字段、新校验、新状态位。**
- **失去恰三种形态，构成严重度阶梯**：`本场移除 < 本轮回禁用 < 账号移除（仅置换、需自愿）`（`character-profile/power/_index.md:47`）。`IgnoresProtection` = 本场移除、**不写 Profile**（`profile-service.md:40`）。
- **同意与否是第二条轴**：置换 `AllowDecline = true`（先看后决、拒绝零代价、拿回同 `Rarity` 等价物，是正向决策点）；禁用 `AllowDecline = false`（只告知、无选择）。
- **神通是轮回级、随轮回清理**（`balance.md:650`）；法则是账号级、跨轮回单调累积。
- **频次的唯一旋钮是内容侧出现权重 + 条目数**：`SelectionWeightGrades`（`Rare 12 / Uncommon 40 / Common 100`）；`balance.md:346` 的先例明写「不加字段、不加校验」。
- **不加精算装置**（`balance.md:680`：「规则密度与它买到的收益密度失配」）。
- **`IgnoresProtection` 无轮回内次数上限、`CycleState` 不设任何相关状态位（定案）**——`balance.md:679-680` 与 `player-power/_index.md:103` 的两文档矛盾裁给前者；后者那段本就是对 `balance.md` 的复述（自己写着「见 `systems/balance.md`」），判为复述侧失真，按「回链而非复述」纪律改为回链。

## 方案

### 1. 上层口径的**书写形态**由「占全部事件的百分比」改为「每完整轮回的期望次数」

`[既有推演]`

百分比口径在本项目已经**三次被分母漂移静默重定价**（86–102 → 83 → 114），而没有任何设计意图要求目标变严或变松。这不是四舍五入问题，是口径选错了刻度：内容编排关心的是「玩家一局撞上几次」，不是「占事件池百分之几」。本库已自己得出过这个结论——`player-power/_index.md:103` 对 `IgnoresProtection` 写过「这个数字比百分比直观得多，是内容编排时唯一需要记住的口径」。把同一句话提升为四支通用的书写口径：

- 上层口径改写为：**「一次完整轮回中，玩家撞上『可能失去能力』场合的期望次数」**。
- 百分比仍可作为换算副本写在括号里，但不再是承重表述；分母变动时只需重算括号里的数，目标值本身不动。

**本次重标定就是这条口径的实证**：分母从 83 涨到 114，三支持久支的绝对次数一格未动，只有括号里的百分比换算跟着重算。

### 2. 把 `IgnoresProtection` 从上层分子中移出，单独持有自己的口径；上层口径由三支持久支持有

`[既有推演]`

现状是两个口径嵌套：`IgnoresProtection` 既有自己的分母（战斗类遭遇）与目标，又同时被计入上层的「全部事件的 1%」。嵌套正是超支的成因。解除嵌套有三条依据：

1. **它不写 Profile**（`profile-service.md:40`），玩家没有失去任何持久的东西——本场结束即恢复。上层口径保护的是「构筑投入会不会被拿走」这条心理契约，而它根本不触碰。
2. **分母不同**（战斗类遭遇 vs 全五类事件）。子集百分比嵌进全集百分比，意味着战斗占比一变内层目标就被静默重定价——本次重标定实证了这一点：战斗遭遇的分母涨 61%、事件分母涨 37%，**涨幅不同**，嵌套不解除即产生一次静默重定价。
3. **控制旋钮不同**。`IgnoresProtection` 由载体编排控制（R1 仅挂 boss 档载体 · R2 绝不挂玩家可主动获取的内容），三支持久支落在内容编排与抽取权重侧，两者不共享任何一个可调的数。

> **这不违反「不另立一套」。** 那条纪律针对的是神通侧——本稿把神通留在上层口径内。被移出的 `IgnoresProtection` 的独立口径本来就已存在且更详尽（`balance.md:674-681`），本稿只是删掉重复计账的那一层。

### 3. 三支持久支之间按「持久度 × 是否经玩家同意」两条轴分配

`[既有推演]`

- **轴一 · 持久度**（严重度阶梯）：账号级永久（法则置换）> 账号级条目被禁一段（法则禁用）> 轮回级（神通两类，随轮回清理、篇章边界自动恢复 `ThisChapter` 档）。
- **轴二 · 是否经玩家同意**：置换是正向决策点；禁用是无同意的施加。伤害「构筑投入」契约的是后者。

⇒ 频次与「持久度 × 无同意」反相关：轮回级的可以最常见；无同意的必须最稀有。顺序：**神通（置换+禁用）> 法则置换 > 法则禁用**。

### 4. 目标频次（定案 · 各支均不收窄）

| 支 | 目标频次（次 / 完整轮回） | 换算副本（分母 114 事件） | 口径归属 |
|---|---|---|---|
| 战斗内 `IgnoresProtection` | **≈1.11**（= 3% × 37 场战斗类遭遇） | ——（它的口径是战斗分母，不用事件百分比） | 自持，`balance.md:674` |
| 神通（`CharacterPower`）置换 + 禁用合计 | **≈0.5**（内部置换 : 禁用 ≈ 2 : 1，即 ≈0.35 / ≈0.15） | ≈0.44% | 上层口径内 |
| 法则（`PlayerPower`）置换型 | **≈0.3** | ≈0.26% | 上层口径内 |
| 法则（`PlayerPower`）禁用型 | **≈0.2** | ≈0.18% | 上层口径内 |
| **上层口径 = 持久三支合计** | **≈1.0** | **≈0.88%** | **新的承重表述** |
| 四支合计（导出量 · 非闸门） | ≈2.11 | —— | 只作叙事密度 sanity check |

**推导（旧口径基准 → 新分配，每一步可复算）：**

```
旧口径下的实际分配（反推，用于确认「各支不收窄」的基准）：
  旧分母：事件 ≈94（86–102 中位）· 战斗 ≈33（30–36 中位）
  旧上层预算 = 1% × 94                         ≈ 0.94 次 / 轮回
  旧 IgnoresProtection = 1% × 33               ≈ 0.33 次 / 轮回
  余给置换型 + 禁用型 = 0.94 − 0.33            ≈ 0.61 → 两支各 ≈ 0.3
  ✓ 与既有推论 ④「两支各自落在一个篇章遇上一次或更少」吻合

新口径：
  IgnoresProtection = 3% × 37 场                = 1.11 次 / 轮回
  法则置换 0.3 + 法则禁用 0.2 + 神通 0.5        = 1.00 次 / 轮回（新上层口径）
  ├ 法则置换 0.3：与旧值持平，不收窄
  ├ 法则禁用 0.2：唯一被下调的一格，理由是轴二
  │  （无同意的施加最伤构筑契约，让出的 0.1 转给同等严重度但有同意的置换侧）
  └ 神通 0.5   ：新增第四支的份额，取 > 法则两支之和的一半，理由是轴一
  四支合计 = 1.11 + 1.00                        ≈ 2.11 次 / 轮回
```

**为什么必须上调上层合计而不能收窄（这一步是推演，不是取向）：** 若坚持四支合计 ≈ 旧的 1% 总额，`IgnoresProtection` 一支（1.11）已超总额，其余三支份额为负——唯一的收窄解是三条机制在整个游戏里一次都不出现。而它们各有已定案的完整落地面（`AbilityChangeSlots` 决策点 · 结算面板「失去 A · 得到 B」· 候选预算存档 · `GrantPoolManager.TryPickReplacement` · `disabledAbility` 三档时长与灰态可见性 · `CharacterPowerCodex`），且置换被明写为正向决策点。为一个从不发生的决策点保留整套机制，与本库「不为不存在的失控路径写规则」的纪律直接相悖。

**总量档位的取向依据（≈1.0 而非更低 / 更高）：** 它是唯一不收窄任何既有支的档位；法则两支合计 0.5 次/轮回 = 每两轮回一次，保住「跨篇章尺度的稀有事件」这条既定定性；更低（≈0.83）会让法则禁用的整套落地面几乎不可见（每 7 个轮回一次），更高（≈1.5）与既定定性拉扯。

### 5. 可调旋钮位置（数值不硬编码，全部落内容侧）

`[既有推演]` 不新增任何字段或校验：

| 支 | 旋钮 | 位置 |
|---|---|---|
| `IgnoresProtection` | 带该效果的 boss 档载体条目数（R1 限定）+ 载体在其池内的出现权重 | `EnemyData` 条目侧；准入规则 `balance.md:679` |
| 法则 / 神通 置换型 · 禁用型 | ① 带 `AbilityChangeSlots` 的 `AdventureEventData` 条目数；② 各条目的 `SelectionWeight` 档 | `content/` 条目侧；权重表 `balance.md` 的 `SelectionWeightGrades` |
| 全局微调 | `PlotModulation.TypeWeights` / `EventWeights` 的 arc 系数（已有，不为本条新增） | `future-event-service.md:167` 的 ⑦ 条目抽取 |

- `Rare` 档已是最低档，故 0.2–0.5 次/轮回量级的主旋钮实际是**条目数**（典型为每支 1–2 条 `Rare` 档条目）。
- 精确的「几条 `Rare` 条目 = 几次/轮回」换算需要各类型池的条目规模（归内容阶段）；本稿只给目标频次与旋钮位置。全部数字为待实测校准的初值。

## 后果

- **玩家体感**：一次完整轮回中「能力可能被动」的场合约 2.1 次——约 1.1 次是战斗内的临时失效（本场结束即恢复），约 1 次是真正触及持有列表的（其中多数是玩家可拒绝的置换）。「我的法则会不会被拆」仍是跨篇章尺度的稀有事件，推论 ④ 的定性结论不变。
- **不产生任何代码 / 存档影响**：无新字段、无 `CycleState` 位、无新校验；`ProfileChangeSpec` / `AbilityChangeSlot` / `disabledAbility` 形态一律不动。
- **对内容阶段的影响**：ch1 编排时须为每支准备 1–2 条 `Rare` 档 `AdventureEventData`（精确条目数待池规模定），并在 ch1 数值标杆专场回归校准。
- **可 grep 性提升**：口径从百分比改为绝对次数后，下次分母变动不再静默重定价目标值——这是本方案最实的一处收益，且已被本次分母漂移（83 → 114）当场验证。

## 备选方案（已考虑并否决）

- **各支相应收窄，保持四支合计 ≈ 旧总额** — 否决：算术上不可行——`IgnoresProtection` 一支已超总额，其余三支份额为负，唯一解是三条已完整设计的机制一次都不出现。
- **保守档（持久三支合计 ≈0.83）/ 宽松档（≈1.5）** — 否决：前者让法则禁用降到每 7 个轮回一次、整套落地面几乎不可见；后者逼近「构筑投入不稳」的体感边界，与「跨篇章尺度的稀有事件」拉扯。
- **`IgnoresProtection` 保 5%（1.85 次/轮回）** — 否决：「一轮回约 1 次」的既有量级变成约 2 次，与措辞拉扯；3% 保量级、改一个数、不推翻任何论证。下调回 1–2% 亦否决——那会回到「几乎从不发生」，正是当初上调要解决的问题。
- **为四支加轮回级配额 / 加载期核对表** — 否决：`balance.md:680` 已明令此类精算装置失配；口径结构上不可机械校验。
- **给神通侧另立一份独立预算** — 否决：`character-profile/power/_index.md:50` 明写不另立；神通与法则的失去在玩家侧是同一类体验，分两本账会让内容作者同时对两个目标编排。
- **按「每篇章 X 次」表述** — 否决：三章事件数不等且 ch1 可无限重试，按篇章表述会让 ch1 的实际频次随重试次数放大；轮回是本库既有的频次分母。

## 与既有决策的张力
