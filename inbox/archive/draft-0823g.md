# 定案草稿 — 杂项

> 原始想法记于 2026-08-23，经 2026-08-24 设计讨论确认，2026-08-25 批量 interview 修正三条。三条彼此独立，合并成稿只为归档整洁。
> **原稿自评「与既有决策的张力：无」不成立**——校验查出第 3 条抵触三条已定案、第 1 条措辞过宽且落点选错。

## 定案

### 1. 隐藏属性不进战斗资源面
`[用户拍板 · 08-25 收窄措辞]` 隐藏属性（道心 / 煞气 / 寿元）与战斗资源（mana / 道念）**不设直接的读写通道**：隐藏属性驱动事件层（PlotManager 调制 eventOptions），战斗层只认 mana 与道念。

**措辞必须收窄——原稿「无直接耦合 / 不设直接读写通道」按字面会否掉三条已定案的通道：**
- PlotManager 依隐藏属性**调制事件选项的参数**；
- 事件 outcome 求值时**读取**隐藏属性；
- `eventEnd` 时对 `HiddenStatGrade` 的推拉。
另有两处例外须一并写明（原稿漏了）：**`lifeTotal` 与寿元的成本侧**本就与战斗层有交互。
正确表述取自既有原话即可推出：**隐藏属性不作为战斗内的资源或结算输入，战斗层不读写它；两者的交互全部发生在事件层**。

**落点纠偏：本条的权威不放 `systems/scoring.md`。** 该文件全文零处提及隐藏属性，写进去会造第二权威。权威句落 `systems/services/plot-manager.md`；`adventure-event/combat/_index.md` 呼应并删掉那条同题待决项；`systems/scoring.md` 只在「归属与协作」表加一行回链。

### 2. 事件背景板：按地域区分，后期按事件类型细化
`[用户拍板]` 地点不同，event 的背景板不同。**前期**同一地域的所有事件共用同一张背景板；**后期**再考虑按 event 类型（Combat / Exchange / Research / Explore / Travel）定制。

**与既有资产类目的关系：并存，不替代。** `art/visuals/` 新增一行「**事件背景板**」类目（按地域，前期每地域一张）；既有的「事件插图」类目行（绑定五类事件、描述为「数量最大的类目」）**保留并注明前期不产出**。两者资产量级差一个数量级，合为一行会让排期失真。

### 3. 奖励面板：逐项列出、逐项领取 / 跳过
`[用户拍板 · 08-25 确认推翻三条既有定案]` 战后 / 事件奖励面板的交互参照 Slay the Spire：逐项列出、**逐项领取 / 跳过**。

**被推翻的既有侧（须一并改写）：**
- `systems/services/combat-service.md`「**不设『放弃全部候选』通道**」（原理由：放弃会重新制造一个玩家心理上的决策点，与低压定位相悖）；
- 同处「**固定 3 项候选，不受道念差影响**」的**择一**语义；
- 同处「**战后奖励选择明确不是决策点**」；
- `ux/combat-ux.md`「可选部分由玩家……择一」。

**必须一并定义的连带（原稿未交代）：**
- **部分领取后的战斗存档结构。** 当前 `picks` 在胜负判定后一次性抽定并落存档，择一即收口；改为逐项领取后，「已领哪几项 / 还剩哪几项」成为一段中途状态，需要落存档才能在挂起态恢复后接着领。
- 战后奖励重新成为一个**决策点**，须核对 `life-cycle-service` 的决策点与存档点清单。
- 「碾压才有高稀有度会诱导刷弱敌」这条既有推论的受限依据（`±2` 带封住碾压深度）不受影响，但「奖励数量恒定使 UI 布局稳定」的理由随逐项领取失效。
- 与既有「置换候选面板与战后奖励面板同构」的定案吻合这一点仍成立——但同构的**对象**变了，置换面板是否也随之改为逐项领取需要一次核对。
