# 定案草稿 — 信息经济与图鉴

> 原始想法记于 2026-08-23，经 2026-08-24 设计讨论逐条裁决定案，2026-08-25 批量 interview 补齐五项口径。

## 定案

### 1. 正面原则：信息只能靠遭遇获得，不能靠资源获得
`[用户拍板]` 「不留花代价买信息的通道」升级为正面设计原则，用于裁决未来一整类提案（占卜类事件、侦察类法宝、付费情报等一律不做）。与既有的「敌人行动不作事前预告」「地域图对玩家不可见、靠 LocationCodex 逐格显影」同属一套信息哲学：**信息本身是元进程奖励**。

**射程（08-25 裁定）= 外部情报**（关于敌人 / 未来 / 世界的知识），**不含**关于玩家自己的牌堆 / 手牌的便利类效果。
- 保留 `systems/balance.md` 与 `player-power/_index.md` 的「允许 ✅：信息 / 便利类（每场一次重排手牌 / 查看牌堆顶；道念净贡献为 0）」列表，只删掉两处「日后若开一条『花代价买信息』的通道，它落在这一类」的尾句。
- `systems/character-profile/deck/_index.md` 的「信息类效果」整节改写为「自身牌序 / 手牌的便利类效果」的花费纪律（mana 为主 + 古宝 `Charges`，明确排除弃牌），删除「买信息通道」框架。
- 依据：原则的动机是「关于世界的知识只能靠遭遇积累」；查看自己的牌堆顶不产生任何关于世界的知识。

**落点：** 写进 `vision/pillars.md` 作为一条正面原则（该文件现有条目均为题材与体验层，无信息哲学的承载位），并记为 **ADR 候选**——立档归 `/write-adr`，本次不建 ADR、不动 `decisions/_index.md`。

### 2. 图鉴在战斗中一律不可查看
`[用户拍板 · 08-25 确认推翻既有定案]` 全部图鉴（地域 / 敌人 / 功法 / 古宝 / 法宝 / 神通 / 法则）在战斗中锁死，只在非战斗界面可查。战前准备的仪式感与首遇的信息差风险由此成立。

**被推翻的既有侧：** `ux/combat-ux.md`「图鉴是事前知识的主通道，故战斗内的查阅入口尤其重要；战斗内可直接查阅（点按敌人立绘 → 半屏 bottom sheet，结算 / 选目标态禁用）」与 `enemy-codex.md` 的决策行「战斗内可读全部五项」。既有侧的论证是「词条不含动态情报 ⇒ 战斗内可读**不改变**信息分层」（说明可以开，不是必须开），而本条给出的是更强的正面取向。
**连带处置：**
- **动态页眉「本次遭遇：筑基后期」迁至战斗前确认页**（见第 6 条），不再随战斗内查阅出现。
- 「点按敌人立绘 = 开图鉴」的语义条整条作废（选目标态中立绘点按语义被该态独占那半句随之失去对照对象）。

### 3. 新增第七本图鉴 `TechniqueCodex`（功法图鉴）
`[用户拍板]` 图鉴族由六本扩为**七本**，新增功法图鉴，条目按 `CultivationTechnique` 的 `Id` 索引，形态与既有六本一致（账号级、跨轮回持久、静态文案、存档只记解锁状态）。

**词条深度（08-25 裁定）：不列卡牌清单。** 词条 = 功法名 / 描述 / `Rarity` / 路数概括 + 可选 `CodexFlavor`，即四本能力 · 道具类的既有深度口径；卡牌列表只在**玩家自己持有该功法时**由卡组 / 构筑界面提供，不进图鉴。
- 理由：敌人套牌已定为功法 + 层数，而功法条目的既有字段就含「每层一份卡牌 `Id` 列表」。若词条列出卡表，玩家可从敌人图鉴词条② → 功法图鉴 → **反查出敌人完整卡组**，实质绕过 `enemy-codex.md` 的承重裁决「慷慨度维持 3 张关键卡，不给样本卡组完整列表」（理由：完整卡组列表把词条从事前知识推向事中情报，那是读牌堆）。
- 本裁定同时满足「敌我共用一套功法条目、知识可验证可迁移」与「图鉴不侵蚀越级黑箱」。

**标识符：** `TechniqueCodex` / `CodexKind.Technique` / 存档字段 `techniqueCodex`（随草稿措辞，且随三处短名先例 `TechniqueEntry.TechniqueId` / `TechniqueTier` / `DeckChangeOp.LearnTechnique`）。成员名随存档冻结，需在第一批存档写下前定稿。

**存档面增量：** `PlayerProfile` 增第 16 个字段 `techniqueCodex`；`CodexKind` 六值 → 七值；`PlayerProfileDiff` 由六个顶层 Codex 键增为七个；bump `schemaVersion`（当前无线上存档 ⇒ 空迁移）。不进透明路径白名单，后端零配合。

### 4. 连锁解锁：解锁敌人 = 解锁其全部功法词条
`[用户拍板]` `EnemyCodex` 收录一个敌人时，**同时收录该敌人套牌所含的全部功法进 `TechniqueCodex`**（敌人构筑面为功法引用，见 `draft-0823b`）。玩家自己习得功法当然也解锁对应词条。

**展开依据（08-25 标准默认）：按本次遭遇实例实际使用的功法展开**，不按模板——与「遭遇即记 = 你实实在在接触过的东西」这条族内承重口径一致，也避免 `OverridesDeck` 条目下解锁错的东西。
**机制上零新增：** `CodexElements` 的语义是按 `(Kind, Id)` 的幂等收录、零 `Op`、重复收录是幂等空操作 ⇒ 一次敌人收录展开为 1 条 `(Enemy, enemyId)` + N 条 `(Technique, techniqueId)` 完全合法。展开的组装方是 **`CodexManager`**（触发采集与去重归它），写入仍组装 `CodexElements` 经 `ProfileManager` 单点提交，不由 `ProfileManager` 自动派生。零新增提交点仍成立。
玩家自己习得的触发口径沿用「进入持有列表」，搭在 `DeckElements` 的 `LearnTechnique` 那次提交上。

### 5. 入账时点与判据
`[用户拍板 · 08-25 收窄射程]` 判据是**遭遇**而非胜利——战败 / 中途终局同样入账（沿用「遭遇即记录，不必击败」的既有定案）。

**射程收窄：** 「只有 event 结束后（`eventEnd`）入账」这一条**只约束 `EnemyCodex` 与新的 `TechniqueCodex`**（`EnemyCodex` 由「战斗开始」改为该战斗事件的 `eventEnd`），其余五本的触发表原样不动。
- 理由：既有触发表的承重结论是「零新增提交点，六行全部搭在一次已经存在的提交上」，而**出生地与自带绑定神通落在「轮回创建」那一次提交上**——那不是任何事件的 `eventEnd`；Exchange 的购买则是逐笔即时提交、明令不攒到 `eventEnd`。全族改 `eventEnd` 需为三处各开例外，把一张可机械核对的触发表变成三条例外规则。
- 收窄后「零新增提交点」不破（`eventEnd` 是既有提交），且它**正是第 6 条能成立的前提**——本场遭遇不当场解锁，才有「上次输给它，这次进场前能看到它的底牌」。

### 6. 战斗前确认页展示已解锁的敌人图鉴摘要
`[用户拍板 · 08-25 裁定真做确认动作，推翻一条承重纪律]` 进入 Combat 事件、开打之前设一个确认页：**若该敌人已在 `EnemyCodex` 解锁，则显示其图鉴摘要**（含关键功法词条入口）；未解锁则摘要区不出现。这不违反「战斗中不可查」（尚未开打），并给图鉴解锁一个明确的回报时刻。首遇的信息差即首遇的风险定价。

**页面现状：** `ux/` 中此页面尚不存在；最接近的承载是 `screen-flow.md` 流程图里一格无规格的「战斗前展示」（它已承担敌人等级的精确标注）。本次为它补齐规格：页面名 / 载体 / 展示内容 / 触控与安全区 / 翻译键 / 动态页眉（承接第 2 条）/ 已解锁敌人摘要区。

**确认动作（08-25 裁定）：带一个「进入战斗」按钮。**
- **被推翻的既有侧：** `ux/screen-flow.md` 的表格行「确认 | 无（不设『确定进入』按钮）」及其承重理由「成本已支付、规则层不可回退，一个只能点『确定』的按钮是纯粹的额外操作，而这是全游戏最高频的操作路径（与『不在最高频操作上加模态』同一条纪律）」。
- **必须一并处理的连带：** 该按钮构成一个新的事件内决策点，牵动 `systems/services/life-cycle-service.md` 的决策点与存档点清单，以及 `systems/services/sync-service.md`「D0 不参与闸门判定，『进入战斗前』只是既有 `Immediate` flush 点」这条已定案。
- **边界（按最小解读，落笔时若与本意不符请纠正）：** 只新增一次**确认**操作，**不**新增可退出通道——「成本已支付、规则层不可回退」这一半仍然成立，玩家在此页不能返回地图。
- 摘要内容 = 敌人图鉴词条全文（五项）+ 功法词条入口。词条本就设计为 150–280 字一屏读完，再切一层摘要是多一套写作规格。
- 「未解锁则不显示任何情报」**不覆盖敌人等级标注**——等级是实例信息，不是图鉴词条内容。落笔写成「图鉴摘要区不出现」。

## 后果
- `systems/player-profile/codex/`：图鉴族清单 6 → 7；`CodexElements` 的 `(Kind, Id)` 值域新增功法一族；连锁解锁规则成文；`EnemyCodex` 触发时点改 `eventEnd`；整族战斗中不可查。
- `systems/player-profile/_index.md` · `profile-service.md` · `sync-service.md`：字段表 15 → 16 行、`CodexKind` 七值、`PlayerProfileDiff` 七个顶层键、bump `schemaVersion`。
- `ux/combat-ux.md`：删除战斗内图鉴入口与立绘点按语义条。
- `ux/screen-flow.md`：新增「战斗前确认页」小节（含确认按钮、摘要区、动态页眉）；确认表格行与「不设确定进入按钮」的承重理由按第 6 条改写。
- `systems/services/life-cycle-service.md` · `sync-service.md`：决策点清单与 D0 语义按第 6 条更新。
- `terminology.md`：`Codex` 条目「共六个」改七个 + 新增「功法图鉴」词条；`LocationCodex` 的「第六本」序数中性化。
- `vision/pillars.md`：新增第 1 条的正面原则（ADR 候选）。
- `systems/balance.md` · `player-power/_index.md` · `deck/_index.md` · `combat/_index.md`：按第 1 条的射程处理「买信息通道」占位。
- **对侧库承接项：** `backend-design-documents/contracts/profile-sync.md` 的「六个 Codex —— 无后端规则用途」随扩员失真，改为不带计数的措辞「全部 Codex 顶层键」（从根上消除下次扩员再漂移），并回链客户端 codex 文档。不复述客户端的图鉴设计。

## 与既有决策的张力
- 第 2 条推翻「战斗内可读全部五项」的决策行，第 6 条推翻「不设确定进入按钮」的承重纪律——两条均已由用户明确裁定推翻，按根约定「决策可被推翻」执行。
- 第 3 条的词条深度裁定保住了 `enemy-codex.md` 的慷慨度承重裁决，无残留张力。
