# 方案草稿 — 各篇章 `lifeSpanCost` 分档表

## 问题

定价表的**形态已完全定死**（ADR-0109）：行 = `eventType` 五类、Combat 一行再按 `combatTier` 三档细分，列 = ch1 / ch2 / ch3，每格一个非负整数定值，不设区间不设公式。**仍待定的只有 21 个格子填什么。**

它悬着的原因不是缺主意，而是**反推口径本身是三元联立**：`lifeSpanCost` 定「每个事件多贵」，`eventCountLimit` 定「一共能做几个」，`lossPerMomentum` × 失败频次定「另有多少预算被战斗失败吃掉」——三者吃同一份寿元预算，各调各的会互相抵消（`systems/balance.md`「`eventCountLimit` = 篇章节奏的第二个旋钮」、`decisions/ADR-0031` 后果第一条）。而目标时长在 08-01b 被上调为 30–40 / 35–45 / 45–55 分钟后，先前设想的定价水平整体失效。

它卡住的下游：`experiencePoint` 阈值曲线的验收（「按标准路线走能在预算内升满」）、回寿三档的绝对点数、`lossPerMomentum` 的 ch2 / ch3 系数、`eventCountLimit` 的内容制作取值——四项全部等这张表。

## 约束（来自既有设计）

**硬结构（不得触碰）**

- **每格是非负整数定值**，不带区间、不带公式；变异位恰三个且无一新增（定价表分格 · 条目级偏移 / 更小的覆盖值 · `ModifierKey.LifeSpanCost`）→ `decisions/ADR-0109-lifespan-cost-fixed-value.md`。
- **预算四格是形式量、不是调参旋钮**：100 / +100 / +300 / +500 固定不动，篇章时长只由事件定价调 → `decisions/ADR-0031-lifespan-budget-countdown.md`。
- **剩余寿元跨篇章结转**（ch2 可用预算 = 100 + ch1 剩余）→ 同上。
- **成本侧 `LifeSpan` 恒非负**，回复只走 outcome 侧 → `decisions/ADR-0066-lifespan-gain-outcome-side-only.md`。
- **无上限字段、无上限截断** → `decisions/ADR-0045-life-span-single-value.md`、`decisions/ADR-0127-life-merged-into-lifespan.md`。

**已定的相对关系（本方案必须满足，逐条已校验）**

1. **Research 行最高** —— `systems/game-progression.md`「Research 闭关 `Major`（`lifeSpanCost` 最高）」。
2. **Travel 行 > 0，且 = 常规事件基准的 1/3 ~ 1/2** —— 定价为 0 即开出零成本事件池 reroll，`systems/balance.md`、`systems/adventure-event/travel/_index.md`。
3. **Combat 三档按 8 / 10 / 12 回合分别给值** —— 三个回合数意味着战斗时长本就有三档。
4. **Explore 自成一行、该行不得由真身推导、且禁用条目级覆盖** —— 否则成本数字构成真身指纹，`systems/adventure-event/explore/_index.md`。
5. **逐篇章上调**（ch1 基准 / ch2 略微上调 / ch3 相应上调）—— `systems/balance.md` 定价表取向列。
6. **单次定价绝对值偏低、一章事件总数偏多** —— 30–40 / 35–45 / 45–55 分钟反推的必然。
7. 开局强制构筑的 Research 条目取 `lifeSpanCost = 0` 的条目级覆盖 —— `systems/adventure-event/research/_index.md`。

**已有的定量估算（本方案发现它们互相超定，见「与既有决策的张力」）**

- 事件数 ch1 26–30 / ch2 28–34 / ch3 32–38；混合均值 ≈ 1.3–1.5 分钟 / 事件；战斗类 ≈ 3–4 分钟、非战斗类 30–90 秒、战斗类约占 1/3（`systems/balance.md` 经验阈值一条）。
- 一章约 9–13 场战斗，一轮回约 30–36 场；一轮回约 86–102 个事件。
- 最坏开局落差 9 / 23 / 35；`lossPerMomentum` ch1 = 1 锁定；形状锚 = 一次带内最坏落差的失败恒落本章可用预算的 8%–12%。
- 回寿三档 = 本章预算的 5% / 10% / 20%。
- 每篇章恰一个 Finale，且它以 `eventPriority = 1` 收窄整批（玩家没有替代选项）。
- 批次数 = 玩家实际结算的事件数（1:1，一批择一、无跳过通道）；Travel 占一个批次但不占 `eventCountLimit` 配额。

## 建议方案

### 子项 1 · 反推的核心恒等式：定价 = 耗时 × 单位时间寿元价 λ

`[既有推演]`

`lifeSpanCost` 在本库里**只有一个职责**——控制篇章时长（`ADR-0031`：「要改变一个篇章有多长，改事件定价」）。由此直接得出定价的形状：

> **`lifeSpanCost(type, chapter) = round( t(type) × λ(chapter) )`**
> 其中 `t(type)` = 该事件类型的玩家实际耗时（分钟），`λ(chapter)` = 该篇章的单位时间寿元价（点 / 分钟）。

**为什么必须正比于耗时，而不能按"风险"或"收益"定价：** 若某类事件时间贵而寿元便宜，它的单位时间价就低于其他类型 ⇒ 最优策略是**尽量只选它**，篇章时长随之爆表，而定价表存在的唯一理由（旋钮精度）当场失效。这与本库反复否决的那类「可电子表格化优化」是同一个漏洞，也正是 Travel 那一格必须 > 0 的同一条论据的一般化形式。**耗时正比是唯一不产生套利的定价形状。**

已定的三条相对关系全部是这条恒等式的推论，不是独立约束：Research 最高 ⟸ 闭关是耗时最长的一类；Travel 最低 ⟸ 结算是毫秒级纯内存计算、零事件内决策点；Combat 三档分别给值 ⟸ 8 / 10 / 12 回合是三个不同的 `t`。**这是本恒等式最强的证据：它把三条各自论证过的既定纪律统一为一条式子。**

### 子项 2 · λ 的反推式（把三个旋钮联立起来）

`[既有推演]`

一个篇章的寿元收支恒等式：

```
本章可用预算  B_c = 篇章增量_c + 上章结转 C_{c-1}
本章事件支出  S_c = Σ_events lifeSpanCost = λ_c × T_c        （T_c = 目标时长，分钟）
本章失败扣减  F_c = 常规战斗场数 × 败率 × E[道念差] × lossPerMomentum_c
本章回寿产出  R_c = Σ 回寿事件的产出量
结转到下章    C_c = B_c + R_c − F_c − S_c        （须 ≥ 0）

⇒  λ_c = ( B_c + R_c − F_c − C_c ) / T_c
```

**这是可执行的：** 一旦 `E[道念差]`（被卡牌道念量纲阻塞）与目标结转 `C_c` 定下，λ 三格立刻解出，21 个格子随之由子项 1 的乘法给出。**在那之前，把它们保留为符号即可，不必先编数字**——下方给出的是代入一组明写假设后的初值。

**副产品 · `lossPerMomentum` 的 ch2 / ch3 由形状锚直接解出**（该条的定案权归它自己那条待答项，此处只给算术）：

| 篇章 | 最坏开局落差 | 本章可用预算 | 8–12% 对应点数 | ⇒ 系数区间 | 建议取 |
|---|---|---|---|---|---|
| ch1 | 9 | 100 | 8–12 | — | **1**（已锁定，9% ✓） |
| ch2 | 23 | ≈ 111 | 8.9–13.3 | 0.39–0.58 | **1 / 2 点**（→ 10.4% ✓） |
| ch3 | 35 | ≈ 310 | 24.8–37.2 | 0.71–1.06 | **1**（→ 11.3% ✓） |

- **写法沿用 `rewardPerMomentum` 表的分数记法**（该表 ch2 已写作「1 / 2 点」），不引入浮点。
- **非单调（1 → 1/2 → 1）不是错误**，是 ch3 预算跳 3 倍而落差只跳 1.5 倍的算术结果。它值得在落笔时明写一句，否则会被后人当作笔误"顺手统一"。

### 子项 3 · 耗时表 `t(type)`：推导用的标定台账，不落任何数据字段

`[通行做法]` + `[既有推演]`

**形态先说清：`t(type)` 不是运行期字段，不进 `.tres`、不进任何 `Resource`。** 它是定价表旁边的一张**标定台账**（住 `systems/balance.md`，与「越级追分的形状锚点」同档），作用是让 21 个格子的取值有可复算的来源，而不是 21 个孤立的经验数字。重定价时改 λ 或改 `t`，表自动重算——这正是「改一张表即可全局调时长」的完整兑现。

| 事件类型 | `t`（分钟 · 初值） | 依据 |
|---|---|---|
| `Combat` / `Practice`（8 回合） | **2.0** | 定长回合 ⇒ 时长可预测；己方 4 个回合 |
| `Combat` / `Standard`（10 回合） | **2.5** | 己方 5 个回合；`balance.md` 明写它是反推的稳定输入 |
| `Combat` / `Finale`（12 回合） | **3.0** | 己方 6 个回合 |
| `Research` 闭关 | **2.8** | **本作最慢的一类决策**：每槽三选一、须读完三条完整内容描述并权衡对整副卡组的影响；移动端上长考时间超过机械出牌。多槽条目更长 |
| `Explore` 探索秘境 | **1.6** | 期望值，见下 |
| `Exchange` 交易 | **1.0** | 多步但每步轻（浏览 → 买若干件 → 离开），步数由玩家自定 |
| `Travel` 前往某处 | **0.4** | 零事件内决策点、结算为毫秒级纯内存计算；耗时只有一次转场 |

**`Explore` 的 `t` 按真身分布的期望值标定（并非"由真身推导"，两者必须分清）：**

```
t(Explore) = 揭示转场 0.1
           + 0.5 × t(Combat 加权 2.25)      ← 真身占比初值 Combat : Exchange : Travel ≈ 5 : 3 : 2
           + 0.3 × t(Exchange 1.0)
           + 0.2 × t(Travel 0.4)
           = 0.1 + 1.125 + 0.30 + 0.08 ≈ 1.6
```

- **与 explore 的两条承重纪律不冲突。** 那两条禁的是**运行期按这一个 Explore 实例的真身取价**（会构成指纹）与**条目级覆盖**（第二种指纹）。本处是**设计期用整个 Explore 条目池的真身分布期望值来标定那一行的唯一定值**——产出的仍是一个与任何具体真身无关的常数，展示侧零泄漏面。**这一条区分必须写进设计库**，否则日后会有人拿 explore 的纪律来否掉这个标定方法，而它是这一行唯一有依据的定法。
- Combat 加权只按 `Practice : Standard = 1 : 1` 计，**不含 Finale**——Finale 不绑 location、以 `eventPriority = 1` 出场收窄整批，不可能作为 Explore 的真身。

### 子项 5 · 结转不是奖励，是 ch2 的必要预算（承重发现）

`[既有推演]`

**ch2 的名义预算 +100 对 35–45 分钟，比 ch1 的 100 对 30–40 分钟更宽松。** 若不计结转：

```
λ_1 = 100 / 39 = 2.56      λ_2 = 100 / 40 = 2.50      λ_3 = 300 / 50 = 6.00
```

**λ_2 < λ_1 —— ch2 反而应当比 ch1 更便宜**，与既定的「ch2 略微上调」直接相反。既有文档只论证过 ch3（「300 点预算对 45–55 分钟，单价仍显著高于 ch1」），**ch2 那一格从未经过算术检验，是一个直觉**。

「ch2 上调」要成立，唯一的通道是**结转**：`λ_2 = (100 + C1) / T_2 > λ_1 = (100 + R1 − F1 − C1) / T_1`。解出 **C1 ≳ 14**，即 ch1 须留下约 15% 的预算。

**三条推论应当一并写进设计库：**

1. **跨篇章结转从"省着花有回报"升级为"ch2 的预算构成"。** 一个把 ch1 花到只剩 0–3 点的玩家，在 ch2 面对的是一份**结构性偏紧**的预算——这是被接受的失败面（与「寿元耗尽而等级未满 → `defeated`」同一条），但必须是**有意的**，不能是没算过的。
2. **`lifeSpanCost` 定价表的标定必须给出一个目标结转量 `C_c`**，它是这张表的第 22 个隐含参数。建议随表一并落进 `balance.md`。
3. **ch3 的 λ 是 ch2 的约 2.5 倍**，这不是取向而是既定预算表（+300）与既定时长表（45–55 分钟）的算术必然。落笔时须明写，否则会被当成定价失控。

### 子项 6 · 条目级偏移 / 覆盖值的建议幅度

`[通行做法]`

既定形态：内容条目默认不填取表值，需要时标偏移或**更小的**覆盖值。建议幅度 **≈ ±15%**：

| 篇章 | 建议偏移幅度 | 落地 |
|---|---|---|
| ch1 / ch2 | **±1** | 单位太粗，多数条目不填 |

- 落点是 `/audit-content` 的一项汇总（只报告不阻断），**不进加载期校验**——它是编排口径不是数据合法性，与「负向 `OnFailureRules` 占比 ≤ 10%」同款处理。
- **`Explore` 行禁用覆盖（既定）；开局强制构筑的 Research 条目取覆盖值 `0`**——后者按既定要求在定价表下方登记一笔。

## 具体形态（可 derive 的落地面）

**写入 `systems/balance.md`（`lifeSpanCost` 那一条之下），三块：**

1. **定价表 21 格**（子项 4 的表），标注「待实测校准的初值」。
2. **耗时标定台账 `t(type)` 7 行 + Explore 的期望式**（子项 3），标注「不是运行期字段，是定价表的推导来源」。
3. **λ 反推式与其 8 个输入参数**（子项 2 + 子项 4 的假设表），连同 `C_c` 目标结转与 ch1 收支校验。

**数据侧零结构增量。** 定价表本身尚未定名载体；按 `balance.md` 的平衡资源三问判据，它的消费者是 future-event-service 的物化阶段、不接受任何覆写参数 ⇒ 与 `EnemyLevelingData` 同族，宜**独立成一份 `ISingletonContent`**（暂名 `LifeSpanCostTableData`，逐篇章各一行、行内七格），**不并入 `CombatRulesData`**（后者可被 `EncounterSpec` 覆写，覆写纪律相反）。

**建议的加载期校验（三条，全部带定位上下文）：**

| 违规 | 语义 | 处置 |
|---|---|---|
| 任一格 < 0 | 成本侧 `LifeSpan` 恒非负（`ADR-0066`） | `PushError` + 篇章 + 行名 |
| 某章 `Travel` 格 == 0 | 开出零成本事件池 reroll | `PushError` + 篇章 |
| 某章 `Travel` 格 > `Exchange` 格 × 1/2，或 < × 1/3 | 违反既定相对关系 | `PushWarning` + 篇章与两个值 |

> `Research ≥ Combat/Standard` 一条**建议只作 `/audit-content` 汇总，不进加载期校验**——它依赖上方那条收窄解读，而收窄解读尚待用户确认。

## 备选方案（已考虑并否决）

- **按"风险 / 收益"定价（战斗贵、交易便宜，与耗时无关）** — 否决：产生单位时间价套利，玩家专挑单位时间价低的类型即可无限拉长篇章，定价表的旋钮精度当场失效。
- **逐条目手写定价，不设表** — 否决：`ADR-0031` 已否（时长旋钮会散落进内容）。
- **给定价表加区间列（每次掷一个）** — 否决：`ADR-0109` 已否（把算术反推变成期望值 + 方差）。
- **把「ch2 上调」实现为提高 ch2 预算增量（+100 → +150）** — 否决：`ADR-0031` 明定预算四格不参与调参。
- **接受 ch2 定价 ≤ ch1，放弃「逐篇章上调」这条取向** — 保留为取向 ② 的选项 B，不在此处单方面否决。
- **在 ch1 / ch2 引入 0.5 点粒度（`lifeSpanCost` 改为定点数）** — 否决：与「非负**整数**定值」的既定形态冲突，且会让 `selectCost` 的恒精确展示出现小数，玩家心算账本变复杂。要提高分辨率应改量纲而非改类型（取向 ①）。

## 与既有决策的张力

### ① 三组既有定量估算互相超定，无法同时满足（须放松其一）

`systems/balance.md` 同处给出的三组数字彼此矛盾：

```
战斗类 3–4 分钟 × 占比 1/3  +  非战斗 30–90 秒 × 2/3   ⇒  混合均值 ≈ 1.83 分钟 / 事件
                                                          （而同处写的是 1.3–1.5）
1.83 × 28 个事件 = 51 分钟                                （而 ch1 目标是 30–40 分钟）
```

**任意两条成立则第三条必不成立。** 本方案选择放松**耗时估值**这一条（它是三条里唯一从未被任何论证支撑的纯占位数），把战斗类下修为 **2.0 / 2.5 / 3.0**（按 8 / 10 / 12 回合）、非战斗上修为 **0.4 ~ 2.8**（Research 与 Exchange 的差距远大于"30–90 秒"这个区间所能表达的）。连带混合均值上修至 **≈ 1.57**、ch1 事件数下修至 **≈ 25**（略低于既有的 26–30）。

**为什么选它：** 另两条的下游承重更重——事件数是经验阈值曲线的直接输入（ch1 合计 79 由它推出），目标时长是 08-01b 刚刚改写过的用户意图。**代价必须明写：** 经验的供给 / 需求比须按 25 个事件重算（既有目标 1.15–1.20）；若重算后不达标，收口方向按 `game-progression.md` 既定的「提高 ch1 阈值 + 降低覆盖率，不动炼气 13 层」。

### ② 100 点量级的整数定价，分辨率不足以表达 ch1 → ch2 的「略微上调」

`λ_1 = 2.3 → λ_2 = 2.5`（+9%），但整数取整后：

| 行 | ch1 | ch2 | 实际变化 |
|---|---|---|---|
| Practice | 5 | 5 | **0%** |
| Standard | 6 | 6 | **0%** |
| Exchange | 2 | 3 | **+50%** |
| Travel | 1 | 1 | **0%** |

**7 行里 4 行完全没动，1 行跳了 50%。** 逐格取整误差累积到篇章总支出的 ±10%——与旋钮本身的调节幅度同量级，等于旋钮在 ch1 / ch2 上**几乎失灵**。ch3 因单价 3–19 而分辨率良好，**问题只在前两章**。

根因是量纲：100 点预算 ÷ 约 25 个事件 = 单价 2–7 点，整数粒度即 14%–50%。这条张力**不是本方案引入的**，它内生于「预算 100 + 整数定价 + 事件数偏多」这三条既定设定的交集，先前之所以没暴露，是因为目标时长上调（08-01b）之前的设想是更少的事件、更高的单价。→ 取向 ①。

### ③ 「ch2 略微上调」这条既定取向没有算术支撑

见子项 5：不计结转时 `λ_2 < λ_1`。既有文档只论证了 ch3。**这不是文档错误，是一条从未被检验的直觉**；本方案给出的化解（依赖 C1 ≈ 15 的结转）是可行的，但它把「结转」从策略奖励改写成了 ch2 的**必要预算构成**——这一层语义变化须由用户确认，故列为取向 ②。

## 前置依赖

**真阻塞（这些定下前，λ 的 `F_c` 项与整张表只能是初值）**

- **卡牌的道念产 / 削量纲基准未定** → 直接阻塞 `E[道念差]`（本方案取 5 / 12 / 18，为最坏落差的一半，是纯假设）。**它同时阻塞 `lossPerMomentum` ch2 / ch3 的最终定案**——本方案给出的 1 / (1/2) / 1 只满足形状锚，一旦典型道念差的实际分布偏离"最坏值的一半"，三格须重解。
- **熟练玩家的战斗败率未定**（本方案取 20%）。这是整份反推里**最需要实测、也最容易大幅偏离**的一格：败率翻倍即 `F_c` 翻倍，ch1 的 λ 要下调 6%。它没有任何既有依据可推，只能靠可玩版本实测。
- **`lossPerMomentum` 的 ch2 / ch3 系数未定案**（ch1 = 1 已定）。本方案由形状锚解出候选值，但**定案权归 `open-questions` 里它自己那一条**——两条须同批采纳，否则 `F_2` / `F_3` 悬空。
- **回寿三档的绝对点数须在新量纲下重估**。本方案按既定的 5% / 10% / 20% 折算为 ch1 5 / 10 / 20、ch2 ≈ 6 / 11 / 22、ch3 ≈ 16 / 31 / 62 代入 `R_c`；**这只是代入用的换算，不构成对那条待答项的裁决**。回寿事件的**每章次数**（本方案假设 2 次）同样未定，它直接进 `R_c`。

**不阻塞本题（须与派单口径澄清的一条）**

- **两种货币（灵石 / 仙玉）的获取渠道与掉落权重未定** —— 它是**商店定价表**（「商品族 × 稀有度」）的阻塞项，`balance.md` 明写「定价表的绝对数字被两种货币的获取渠道阻塞」指的是那一张。**寿元定价表与货币不共享任何量纲**（寿元既不能买也不能卖），故本题不受它阻塞。如实记下以免被当作遗漏。

**下游等待本表（本方案一旦采纳即可解除）**

- `eventCountLimit` 的内容制作取值（本方案给出 ch1 反推产出：4–5 个 location × 容量 4–5）。
- 经验阈值曲线的「供给 / 需求比」验收（须按修正后的事件数重算）。
- 「即使发生 N 次典型失败，按标准路线走仍能在预算内升满」这条验收项的 N（本方案的 `F_c` 假设即隐含 N ≈ 1.2 / 1.4 / 1.4）。

## 仍需用户决定

### 取向 ① · 是否把寿元预算量纲整体放大 10 倍，以换取 ch1 / ch2 的定价分辨率

**背景：** 张力 ② —— 100 点预算下单价只有 2–7 点，整数粒度使 7 行里 4 行在 ch1 → ch2 之间完全无法体现「略微上调」，逐格取整误差达篇章总支出的 ±10%。

| 选项 | 做法 | 后果 |
|---|---|---|
| **A（推荐）** | 预算四格 ×10：**1000 / +1000 / +3000 / +5000**；定价表随之 ×10（Practice ch1 = 46、Travel ch1 = 9…） | 分辨率提升一个数量级，`λ` 的每一次微调都能落到表上；**结构零改动**（仍是非负整数单值、无上限、无截断）；改动面 = `balance.md` 预算一行 + `life-span.md` 预算一行 + 回寿三档换算 + `ADR-0031` / `ADR-0045` 的数字。修仙题材里「寿元 1000」比「寿元 100」更自然。**代价：** 触及两份 ADR 里写死的数字（虽然两份的**结论**都不依赖具体数值） |
| **B** | 维持 100 量级，接受 ch1 / ch2 多格同值 | 零改动；但「逐篇章上调」在前两章事实上只能由 Exchange / Finale / Research 三格承载，其余四格三章齐平，旋钮在 ch1 / ch2 半失灵 |
| **C** | 维持 100 量级，改用更少的事件 + 更高的单价 | 分辨率随单价上升而改善；但**直接违反 08-01b 的用户意图**（目标时长上调后事件总数应当变多） |

**推荐 A，理由：** 分辨率不足是可以被一次性消除的量纲问题，B 是在长期 workaround 它，而 C 与刚刚改写过的用户意图正面冲突。A 的改动全部落在「数字」而非「结构」上——两份 ADR 的**决策本体**（递减预算 / 单值无上限）与本次改动无关。**若选 A，本草稿全部 21 格与耗时台账原样 ×10 即可，方法与校验一字不改。**

→ **已裁决（2026-09-03 · 批量评审）：选项 A —— 寿元预算四格改为 1000 / +1000 / +3000 / +5000，21 格定价表与相关标定值按本稿自陈原样 ×10，方法与校验一字不改。** 提炼时须同批订正 `ADR-0031` / `ADR-0045` 中写死的数字（两份的决策本体不受影响）与回寿三档的换算值。

### 取向 ② · 寿元压力曲线的形状：ch2 与 ch3 各要多紧

**背景：** 张力 ③ + 子项 5 —— 「ch2 略微上调」只有依赖 ≈ 15 点的结转才成立，这把结转从策略奖励改写为 ch2 的必要预算；而 ch3 的 λ 是 ch2 的约 2.5 倍已是算术必然，问题只在**要不要在此之上再加压**。

| 选项 | ch2 | ch3 | 后果 |
|---|---|---|---|
| **A（推荐）** | 依赖结转维持「略微上调」（λ ≈ 2.5，目标结转 C1 ≈ 15） | 算术中性（λ ≈ 6.3，C2 目标 10，C3 = 0） | 三章压力平滑递增；ch1 挥霍者在 ch2 面对结构性偏紧的预算——**是有意的失败面**。须在设计库明写「结转是 ch2 的预算构成」 |
| **B** | 承认 ch2 ≈ ch1（λ ≈ 2.3），修正「略微上调」这条取向 | 同 A | 最诚实：不为一条未经检验的直觉引入对结转的依赖；ch1 挥霍者不被隐性惩罚。代价 = 改写 `balance.md` 定价表的取向列 |
| **C** | 同 A | **ch3 再上浮 15–20%**（λ ≈ 7.3），压低 C3 至负容错边缘 | 终章明显更紧，300 点预算须精打细算，「渡劫前的窒息感」由资源侧承担一部分。代价 = 与「绝境感只能由卡组 / item / power / 遭遇参数四个旋钮表达，永远不由等级差表达」那条纪律**不冲突**（它管的是等级差），但确实新增了第五条表达通道，须确认这是想要的 |

**推荐 A，理由：** 它同时保住了 08-01b 的时长意图与既定的「逐篇章上调」取向，且把代价（对结转的依赖）显式写进设计库而非留作暗账。C 的诉求（终章更紧）在本作已有更贴切的承载面——Finale 的二重压迫与卡级失败面；用寿元定价再压一次，会与「一次惨败真的会滚雪球」这条既有正反馈叠成两层，风险是 ch3 的失败螺旋过陡而玩家读不出原因。B 是安全的保守解，若用户认为「不应让 ch1 的花法隐性决定 ch2 难度」，B 优于 A。

→ **已裁决（2026-09-03 · 批量评审）：选项 A —— ch2 依赖结转维持「略微上调」（λ ≈ 2.5，目标结转 C1 ≈ 15，量纲 ×10 后 ≈ 150）· ch3 算术中性（λ ≈ 6.3）。** 「结转是 ch2 的必要预算构成」须随提炼在设计库明写，不留作暗账。
