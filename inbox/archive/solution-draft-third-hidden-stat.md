# 方案草稿 — 是否还有第三项隐藏属性

## 问题

`open-questions/04-hidden-attributes-plot.md:9` 那条待答项已被两轮收窄，剩下三项残留，本草稿只答其中第一项：

> 仍待定：**是否还有第三项隐藏属性**、逐条目的映射、每条剧情线的具体内容。

围绕隐藏属性的**一切结构**都已定案 —— 取值域 `[0,100]`、档位表（道心 5 档 / 煞气 4 档 = 9 档）、阈值、回滞 δ、跨档叙事形态、推拉的允许面（五类事件全开、`HiddenStatGrants` 是可选字段，不填 = 不推）、战斗层边界（ADR-0081）、方向格 `HiddenStatDirection`（ADR-0129）、内容类型 `HiddenStatBandData`、存档字段、加载期校验表。**唯独「一共几项」这个数没有被明写为定稿**，于是它以待答项的形态挂着，并让同条目下的另两项（逐条目映射、剧情线内容）在名义上仍被「清单未定」阻塞。

它卡住的东西是**内容扩充的起跑线**：属性数决定 `HiddenStatGrade` 的统计校准要标定几条曲线（`systems/balance.md` 的反推口径是**逐属性一行**），也决定逐条目 `HiddenStatGrants` 编排面的宽度。

**这条待答项从未被推演过。** 2026-08-12d 的档位草稿把它记为「不阻塞」（原文：「档位模型对属性数不敏感；新增属性 = 加一个 `HiddenStat` 枚举值 + 一个 band 字段 + 一批档位条目」），此后再未有人对它求过值。

## 建议方案

### 1. 结论：不加第三项，并把「两项」写成定稿

`[既有推演]`（推荐强度：高）

**建议把隐藏属性清单定稿为道心 / 煞气两项，并关闭这条待答项。** 四条依据，按强度排序：

1. **它正面撞上一条愿景级约束（最强）。** C1 + C2 不是「代价大」，而是**范围界定**：本作的求生张力明确只有寿元一条压力线，「支撑 Reigns 式平衡张力的完整属性模型」被写进 `scope.md` 的「范围之外」，而 `character-profile/_index.md:89` 明确该条指的就是「`faith` / `bloodlust` 一类运行时可推拉的资源条」。**再加一条隐藏属性 = 正面走进 scope 的排除项。** `vision/references.md:16` 那句 Reigns「每次抉择同时拨动多个仪表」是全库唯一能被读成「想要更多轴」的原句，已被 C1 / C2 双重收窄。
2. **唯一被正式提出过的候选已被逐条驳回（C7）。** 「社交 / 阵营 / 关系」是第三轴最大的候选来源，它已被 `PlotArcData.ExclusiveGroup` + `PlotKeyPoint.State` + `pastEvent` 三件既有设施吸收，判词是「代价与收益完全不成比例」。这份否决活在主题文档里，不是历史记录。
3. **找不到任何一个需要它来填的设计缺口（见 §3）。**
4. **加一项的边际成本已被逐条清点，落在 14 处（见 §2）**，其中两处不是「加一行」而是「改写一段已定的论证 / 一处只能表达两值的展开式」。

**零成本项（已泛化，加属性不动一格）：** `HiddenStatGrade` 映射表（行数不随属性增长）· `HiddenStatDirection` · `HiddenStatGrant` 三格本身 · `AdventureEventData.HiddenStatGrants` 数组格 · `common-properties.md` 校验 7 / 8 · `HiddenStatBandData` 的六行加载期校验（全部按 `Stat` 分组）· EventBus `PlotThresholdReached` · `CapabilityFlag.RevealHiddenStats` · `PlotModulation` 六字段。

**B. 内容与标定面（两格「大」，是这笔账真正贵的地方）**

- **逐条目编排 +50%，落在一个尚未开工的工作量上。** 逐条目 `HiddenStatGrants` 映射当前**一条都没写**。把一个未开工工作量放大 50%，代价不是「多干一半」，而是**把这条待答项的完成时间推后**，而它正卡着 `HiddenStatGrade` 三个映射值的定案。
- **标定难度是超线性的。** C11 的验收带是**逐属性**的，而三条曲线**共享同一批事件条目** ⇒ 调整任一条目的 `Grade` 会同时移动多条曲线，必然出现「压住 A 就顶出 B」的循环。`balance.md` 已明写这条反推链「是脆的」（同款风险在经验阈值处也点了名）；再加一维等于在一条已知脆的链上再挂一个约束。

**C. 与既有两项的正交性 —— 也是收益侧为什么是空的**

道心是**双臂状态轴**（心境澄明 ↔ 心魔渐生），煞气是**单臂累积物**：两种形态已被占满。而第三项**不新增任何调制表达力** —— `PlotModulation` 的六字段是 arc 的权力面，与属性数无关；它只新增一个**触发源**。而触发源不是当前瓶颈：C12 摆着两条剧情线、零条内容、并发上限 2。**在既有两条剧情线一条内容都没写之前，加第三条触发轴是给一个空结构再开一格。**

### 3. 有没有一个真实存在的设计缺口需要第三项来填？

`[既有推演]` —— **全库扫描后：没有。** 四个方向逐一核过：

- **「后果无处承载」的事件类型 —— 无。** 五类共有的产出格是 `ExperienceGrade` · `FailureRatio` · `HiddenStatGrants` · `OnResolvedRules` / `OnFailureRules`；载体覆盖资源 element / 能力 element / 卡组 element / `PlotElements` / `TraceElements`。**2026-08-17 已做过一次专门的「载体缺口」体检**（`answer-logs/log-element-carrier-gaps.md`），四项缺口全部答结，**结论里没有留下任何「后果无载体」的残留**。五类各自 `_index.md` 的待决问题里也没有一条是「载体缺失」，剩的全是取值 / 配比 / 权重。
  - Explore 侧「线索 / 情报」类后果没有载体是**结构性禁止**（`explore/_index.md`「不给任何部分线索」· `deck/_index.md`「关于敌人 / 未来 / 世界的外部情报不存在任何以资源换取的通道」），是有意的，不是缺口。
- **关键词扫描 —— 全库无任何文档在指望一个尚不存在的属性。** 「声望 / 名声 / 业力 / 气运 / 机缘 / karma / reputation / luck / fortune」的**唯一命中**是一张业障卡的 id（`affliction.karma`），与属性轴无关；「因果」的全部命中都是「因果链 / 因果树」（战报可读性），不是修仙意义上的因果值；「宗门 / 师门 / 好感 / 势力」的命中全部集中在 C7 那段**已定案否决**里。
- **愿景 / 系统文档对属性维度的期望 —— 反向（C1 / C2）。** `game-progression.md` 全文只有一处提隐藏属性（转述调制），无维度期望；`future-event-service.md` 只以「调制输入 / 结算输入 / 两个 element key」出现。
- **「正邪二元之外的第三维」的诉求 —— 无。** 角色差异化的第三维已由**静态灵根**承担（`CharacterData` 上的静态分类维度，明写「不产生任何运行时状态、不进 `CharacterProfile`」）；卡牌侧明确拒绝加分类维度，判据 C14「**没有规则后果的分类维度本库连概念占位都不给**」可直接套到本题。

### 4. 「关闭」而不是「留一个加法式扩展口」

`[既有推演]`（推荐强度：高）

**建议关闭这条待答项，而不是把它降级为长期待答 / 预留扩展口。** 「扩展口」在本题上是个空概念：

- **结构上本来就是开的。** `HiddenStat` 是枚举、档位是内容条目、`Status` 字段可增 —— 加一项属性从来不需要今天预留什么。**留不留扩展口不改变任何一行结构**，留下的只是 04 分片里一条永远不动的条目。
- **预留占位是被明确禁止的形态。** 留一个占位枚举成员 / 预留 band 字段，正是 C13 那条纪律要禁的东西（两个先例）；且占位成员会立刻污染 `ResourceElements` 表与「每 `Stat` 须有常态档」那行校验。
- **正确形态 = 关闭 + 留一条准入判据**，与 C13 的「不预留结构，但留下路标」逐字同款。
- **时机上现在最便宜：** `content/hidden-stat-band/` **尚未开张**，「9」这个数还没有被写进任何条目台账。在类型档案开张前定稿，是**零改写成本**；开张后再定，就要改一份已冻结的台账数字。

### 5. 四问准入判据（本方案的正面产物）

`[既有推演]` —— 四条全部由既有否决理由与寿元先例反向提炼，不引入新概念：

> **任何「新增一项隐藏属性」的提案须逐条通过下列四问，一条不成立即不加。**
>
> **① 它落在 scope 之内吗？** `vision/scope.md` 把「支撑 Reigns 式平衡张力的完整属性模型」列为范围之外，`pillars.md` 明写「**压力线是一条**」。新增一条运行时可推拉的隐藏资源条**默认落在排除项内**，提案须先说明它为何不是那个被排除的东西。
>
> **② 不可替代 —— 它的因果能不能由道心或煞气任一表达？** 能 → 不加。两条轴已覆盖「状态」（双臂）与「累积物」（单臂）两种形态。语义重叠的第三条轴会让内容编排随手互相替代，两条曲线一起漂，而 C11 的逐属性验收带发现不了这种漂移。
>
> **③ 必须连续，且必须隐藏 ——**
> - **不连续 → 不加**，正确载体是 `PlotArcData` + `PlotKeyPoint.State`。判据来自 C7：「**好感度本质上就是一条 arc 的进度**，只是用离散节点而非连续数值表达」。「与某人 / 某势力的关系」「某条支线走到哪」「某个秘密是否被发现」「师门态度」全部落在这一侧。
> - **需要给玩家精确数值（哪怕只在一档）→ 不加，做成明文资源。** 这是**寿元先例**的正面提炼（C8）：寿元退出体系的直接触发因素就是「它需要被精确规划，而定性告警撑不住规划」。
>
> **④ 消费方是调制 —— 它要驱动 eventOptions 调制，还是只想多一句旁白？** 只为旁白 → 不加。**档位表存在的首要理由是调制分辨率**（C9）；只为叙事而设的属性会造出一张没有首要消费方的档位表，而「文案密度」的正确旋钮是 `HiddenStatGrade` 的映射值与退让位顺序（ADR-0016 后果段已排好序），不是属性数。

> **举证责任在提案侧：** 第三项必须能给 eventOptions 调制带来一条**道心 / 煞气都表达不了的**新维度，而不只是新增一条叙事线。
