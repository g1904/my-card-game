# 方案草稿 — 胜侧 `rewardPerMomentum[experiencePoint]` 是否计入经验供给账

## 问题

`systems/balance.md` 的胜侧单价表（支路 A · 强制奖励线性加成）给出 `experiencePoint` 的逐章单价 **1 / 点 · 1 / 2 点 · 1 / 4 点**，式子是：

```
element 量 = baseReward 中该 element 的量 + 道念差 × rewardPerMomentum[element]
```

而同一份文件里的经验供需对账 **`G_c` = 92 / 290 / 460** 只累加了 `ExperienceGrade` 档位产出（ch1：Finale `Minor` 2 + Practice ×5 `Standard` 20 + Standard ×5 `Major` 30 + Research ×4 `Major` 24 + Explore ×4 `Standard` 16），**一分道念差加成都没算**。同一个术语（供给）在两处指两个不同的量。

它卡住的东西写在 `open-questions.md`：**凡引用「供给 / 需求 ≈ 1.15–1.20」三章比值或「失败容错量 N 的反推台账」的 FR，一律推迟到本条答定之后。** 答定后须同批重算这两处台账。

推演过程中还挖出一件比原问题更承重的事：**`1.15–1.20` 这条带被同时施加在两个相差约 6% 的量上（全胜供给比与扣掉 `N = 2` 后的供给比），二者在算术上不可能同时落带。** A3 当前三章全部 ✗（1.09 / 1.10 / 1.12）的根因不是数值没校准，是口径撞了。本方案把它一并处理——不先答它，就没有判据决定该计入多少。

## 约束（来自既有设计）

- **胜侧线性加成不设上限截断，平局给 0 加成**（`systems/balance.md` 支路 A）；负侧 `lossPerMomentum` 同样不设截断。
- **失败代价 ⑤「失去胜利侧的全部奖励厚度」已是定案**：失败时线性加厚归零、只发 `baseReward`（`systems/adventure-event/combat/_index.md` 六条代价表）。⇒ 若经验吃这条加成，一次失败少拿的就不止「档位折半」那一笔。
- **灵石侧已经把同一项计进了账**：`I(c) = Σ BaseReward 灵石 + Σ 道念差 × rewardPerMomentum[SpiritStone][c] + Σ 事件 outcome 灵石`（`systems/balance.md` 货币产出小节）。两条账对同一个式子取了相反口径。
- **`BaseReward` 的默认 element 面 = 灵石一格，其余恒空**，理由是「经验有模板侧独立的 `ExperienceGrade` + `FailureRatio` 书写位，`BaseReward` 再装一份即与『物化后可出现的 key ≠ 模板可声明的 key』相抵」。⇒ 该句本身承认 **`experiencePoint` 可以在物化后出现、只是模板不可声明它**，与「经验吃线性加成」相容。
- **单价表的列集是刻意的**：`ADR-0089-two-tier-currency.md` 明确否决过「给单价表加仙玉列」。⇒ `experiencePoint` 列的存在是一次决策，不是遗留。
- **单价逐篇章下调是必需的**（否则奖励通胀被绑死在 `baseMomentum` 的百倍曲线上）。
- **不引入浮点**：分数记法沿用「1 / K 点」形态（`lossPerMomentum` 条明写）。
- **收口方向已定**：供需比偏离时「**调这条曲线或调构成，不是提高阈值**」（`experiencePoint` 小节）。
- **单次给予量 ≤ 该境界的最小阈值**（ch1 即 ≤ 6，`Major` 给予 6 恰好达界）——该断言的**对象是 `ExperienceGrade` 映射值**（加载期断言），不是含道念加成的运行期总量。
- `E[道念差]` = **5 / 12 / 18**、败率 20% 是两个 ⚠ 待实测标定格，**不得引为承重依据**；本方案的一切算术沿用同一格，不另立第二套假设。
- **`N = 2` 三章统一已定案**（`log-failure-spiral-tolerance.md`），本方案不得威胁它。

## 建议方案

### 子项 1 — 正面认账：这是账目缺口，不是设计选择

`[既有推演]`

**建议裁定「应当计入」**，三条依据各自独立成立：

1. **同一式子的两条账取了相反口径。** 灵石侧 `I(c)` 计入，经验侧 `G_c` 不计——没有任何一处文档给出过这个差别的理由。
2. **失败代价 ⑤ 已定案「胜侧加厚归零」。** 若经验不吃加成，⑤ 在经验一列上就是空的；而问题条目正是把它称作「失败少拿的第三笔代价」。
3. **单价表有 `experiencePoint` 一列且逐章给了值。** 不计入等于让一列已定案的数据在账上不存在。

**但「计入」不等于「按现价计入」**——见子项 2 的算术。

### 子项 2 — 按现价计入会把供给账打飞，这是本条最重要的算术

`[既有推演]`

记 **`p_c` = 一场胜局的道念差经验加成** = `E[道念差]_c × 单价_c`；战斗场数取 **11 / 11.9 / 14.0**（ch1 用 35 批次参考构成的显式 Combat 行 5 + 5 + 1；ch2 / ch3 用权重外推的 10.9 + 1 与 13.0 + 1）。`G_c` 是**全胜口径**（阈值曲线按全胜标定）。

| | ch1 | ch2 | ch3 |
|---|---|---|---|
| `E[道念差]` | 5 | 12 | 18 |
| 现行单价 | 1 / 点 | 1 / 2 点 | 1 / 4 点 |
| **`p_c`（现价）** | **5** | **6** | **4.5** |
| 战斗场数 `n_c` | 11 | 11.9 | 14.0 |
| 加成总量 `n × p` | **55** | **71.4** | **63** |
| 原 `G_c` | 92 | 290 | 460 |
| **计入后 `G_c′`** | **147** | **361** | **523** |
| 需求 `D_c` | 79 | 247 | 391 |
| **全胜供给比 `G′/D`** | **1.86** | **1.46** | **1.34** |

**ch1 的加成量 55 相当于原供给 92 的 60%**——一个从未入账的项，体量超过全部 Research + Explore 产出之和。目标带是 1.15–1.20。

失败代价侧同步变化（一次典型失败的经验损失 `X_c` = 档位折半损失 + **整笔胜侧加成**，因为 ⑤ 明写加厚归零）：

| | ch1 | ch2 | ch3 |
|---|---|---|---|
| 原 `X_c`（`Major − floor(Major×50%)`） | 3 | 9 | 12 |
| **计入后 `X_c′` = 原 + `p_c`** | **8** | **15** | **16.5** |

代回 A1–A3（`N = 2`）：

| 断言 | ch1 | ch2 | ch3 | 结论 |
|---|---|---|---|---|
| A1 寿元不破产 | 165 | 178 | 125 | 不受影响 ✓ |
| A2 `G′ − 2X′ ≥ D` | 131 ≥ 79 | 331 ≥ 247 | 490 ≥ 391 | ✓ |
| **A3 `(G′ − 2X′)/D`** | **1.66** | **1.34** | **1.25** | **✗ 三章全部超上沿** |
| 经验侧 N 上界 `(G′−D)/X′` | 8.50 | 7.63 | 8.00 | 原 4.33 / 4.78 / 5.75 |

**⇒ `N = 2` 不受威胁**（寿元侧软口径 5.30 / 4.97 / **2.69** 全程封顶，`min` 仍取 2.69 ⇒ 2）。**但有一句既有表述作废：「ch1 由经验侧封顶（4.33 < 5.30）」不再成立**——计入后三章一律由寿元侧独占封顶，经验侧退出竞争。

**A3 从「略低于下沿 −5%」翻到「远高于上沿 +38%」。按现价计入不是把偏紧补上，是矫枉过正五倍有余。**

### 子项 3 — 根因：`1.15–1.20` 这条带被施加在两个不同的量上

`[既有推演]`

- `experiencePoint` 小节：「供给 / 需求 ≈ **1.15–1.20**」，当前 **1.16 / 1.17 / 1.18** —— 分子是**全胜** `G_c`。
- N 反推台账 A3：「**1.15** ≤ `(G_c − 2X_c)/D_c` ≤ **1.20** + ε」，当前 **1.09 / 1.10 / 1.12** —— 分子是**扣掉两次典型失败后**的供给。

两个量相差 `2X_c/D_c` ≈ 7.6% / 7.3% / 6.1%。**同一条带不可能同时容下相差 6–8% 的两个量**——A3 三章全 ✗ 是这条口径撞车的直接后果，不是数值没调好。当前记录的处置（「归实测校准」）无论怎么实测都不可能同时满足两条。

**⇒ 必须先裁定这条带管辖哪一个量**，再决定 `experiencePoint` 单价取多少。这是本条的前提题，见 `## 仍需用户决定` Q1。

**带的取值一旦确定管辖对象，`p_c` 的可行窗口就是纯算术：**

| 若带管辖 | ch1 `p` 窗口 | ch2 `p` 窗口 | ch3 `p` 窗口 | 含义 |
|---|---|---|---|---|
| **扣 N 后的比**（A3 口径） | **0.54 ~ 0.98** | **1.22 ~ 2.47** | **1.14 ~ 2.77** | 需要 `p > 0` ⇒ **必须计入，且须大幅下调单价** |
| **全胜比**（现状口径） | ≤ 0.25 | ≤ 0.54 | ≤ 0.66 | `p` 近似为 0 ⇒ **等价于不计入** |

（窗口解法：ch1 `(86 + 9p)/79 ∈ [1.15, 1.20]`；ch2 `(272 + 9.9p)/247`；ch3 `(436 + 12p)/391`。）

**这张表就是本条的全部张力**：A3 口径要求带内 `p > 0`（即「不计入」正是 A3 三章不达标的直接原因之一），全胜口径则要求 `p ≈ 0`（即「删列」才是诚实答案）。两条路各自自洽，无法折中。

### 子项 4 — 推荐路线：带管辖 A3 口径 ⇒ 计入 + 单价下调至 `1 / 5 · 1 / 8 · 1 / 12`

`[既有推演]`（数值为初值 · 待实测校准）

在 Q1 答「带管辖扣 N 后的比」的前提下，取每个窗口的中位附近、并让 K 保持整数与逐章递增：

| 篇章 | 现行单价 | **建议单价** | `K`（每 K 点道念差 +1 经验） | `p_c = floor(E/K)` |
|---|---|---|---|---|
| ch1 炼气 | 1 / 点 | **1 / 5 点** | 5 | **1** |
| ch2 筑基 | 1 / 2 点 | **1 / 8 点** | 8 | **1.5** |
| ch3 金丹 | 1 / 4 点 | **1 / 12 点** | 12 | **1.5** |

代回全账：

| | ch1 | ch2 | ch3 |
|---|---|---|---|
| 加成总量 `n × p` | 11 | 17.9 | 21 |
| **`G_c′`** | **103** | **308** | **481** |
| **`X_c′`** | **4** | **10.5** | **13.5** |
| 全胜比 `G′/D`（导出量） | 1.30 | 1.25 | 1.23 |
| A1 | ✓（不受影响） | ✓ | ✓ |
| A2 `G′ − 2X′ ≥ D` | 95 ≥ 79 ✓ | 287 ≥ 247 ✓ | 454 ≥ 391 ✓ |
| **A3 `(G′ − 2X′)/D`** | **1.203** | **1.161** | **1.161** |
| 经验侧 N 上界 | 6.00 | 5.80 | 6.67 |
| **`N_c`（软 · min）** | 5.30 | 4.97 | **2.69** |

- **A3 三章首次全部落带**（ch1 1.203 落在「1.20 + ε」的 ε 上，见 Q2）。这是「归实测校准」那笔欠账的一条可落地收口，且它属于**调构成 / 调曲线**，不是提高阈值——与既定收口方向一致。
- **`N = 2` 原样成立**，三章一律由寿元侧封顶，ch3 仍是最薄的一章（2.69）。
- **单价逐章下调的形状保住**（K 递增 5 → 8 → 12），与「吸收 `baseMomentum` 百倍量纲膨胀」同向。
- **对败率不敏感**：`G_c` 是全胜口径，本方案不引入败率这一格。⚠ 依赖只剩 `E[道念差]` 一格。

### 子项 5 — 单价的存储形态统一为整数 `MomentumPerUnit`

`[通行做法]`

现行表里三章分别写作「1 / 点」「1 / 2 点」「1 / 4 点」，是同一件事的分数记法。建议在平衡资源里落成**每 (篇章 × element) 一个正整数 `K`**：

```
element 加成量 = floor(道念差 / MomentumPerUnit[element][chapter])
```

- 灵石列 `K` = **1 / 2 / 4**（与现值等价，零改动）；经验列 `K` = **5 / 8 / 12**（本方案）。
- **`floor` 语义必须明写**，否则「四舍五入还是截断」会在文档与实现处各取一半——与 21 格定价表「半值一律四舍五入向上，不写死方向文档与实现会各取一半」同款处置。
- **不引入浮点**，与既有纪律一致；**不设上限截断**，与胜负两侧的既定表述一致；**平局给 0 加成**不变。
- 呈现侧：奖励结算屏本就要求**显式陈列算式**，`floor(道念差 / K)` 是一次除法，玩家读得出因果。

### 子项 6 — 补一条可机械校验的断言，替下「≤ 最小阈值」在运行期的空白

`[既有推演]`

既有断言「单次给予量 ≤ 该境界的最小阈值」作用在 `ExperienceGrade` **映射值**上（加载期），管不到含道念加成的运行期总量。计入后建议在表侧核对清单补一条（与 A1–A3 同档，**不进 `.tres`、不进加载期校验**——它含 ⚠ 标定格）：

```
A4   Major 映射值 + E[道念差]_c × 单价_c  <  2 × 该境界最小阈值
```

- 本方案取值下：ch1 `6 + 1 = 7 < 12` ✓ · ch2 `18 + 1.5 = 19.5 < 138` ✓ · ch3 `24 + 1.5 = 25.5 < 216` ✓。
- **按现价则 ch1 为 `6 + 5 = 11 < 12`，只余 1 点余量**——这是「现价过高」的第三条独立证据（前两条：A3 超上沿 38%、加成量占原供给 60%）。

## 具体形态（可 derive 的落地面）

**① 胜侧单价表改写后的形态**（住 `systems/balance.md`，落 `.tres` 为平衡资源）：

| 篇章 | 角色 `baseMomentum` 量级 | `SpiritStone` 单价 | `experiencePoint` 单价 |
|---|---|---|---|
| ch1 炼气 | 1–15 | 1 / 点（K = 1） | **1 / 5 点（K = 5）** |
| ch2 筑基 | 20–32 | 1 / 2 点（K = 2） | **1 / 8 点（K = 8）** |
| ch3 金丹 | 45–75 | 1 / 4 点（K = 4） | **1 / 12 点（K = 12）** |

`K` 为正整数、逐章不下降；`K == 0` 无意义 ⇒ 加载期 `PushError`（带篇章与 element 名）。

**② `experiencePoint` 供需对账小节的重算值**（书写口径，不进任何 `Resource`）：

**③ N 反推台账的改动面**（`systems/balance.md`「失败容错量 N 的反推台账」）：

- **「ch1 由经验侧封顶（4.33 < 5.30）」整句作废**，改为「三章一律由寿元侧封顶（5.30 / 4.97 / 2.69）；经验侧上界 6.00 / 5.80 / 6.67 全程宽松」。ch3 由寿元侧独占封顶那句不变。
- A3 当前状态由「三章均略低于下沿（1.09 / 1.10 / 1.12）✗」改为「**1.203 / 1.161 / 1.161 ✓（首次三章全部落带）**」；同时删去「归实测校准」的挂账。

- **`N = 2，三章统一` 的定案与三条依据一字不改**；依据①的三个数字由 4.33 / 4.78 / 2.69 改为 5.30 / 4.97 / 2.69。

**④ 回链面**（本方案不写这两处，只登记须同改）：`systems/game-progression.md` 的验收项（「即使发生 2 次典型失败仍能升满」措辞不变，引用的台账值变）· `systems/adventure-event/combat/_index.md` 六条代价表的 ④ 与 ⑤——计入后两行在**经验**这一列上同时有量，须补一句「④ 是档位侧、⑤ 是道念差侧，两笔不重叠」。

## 后果

- **解除阻塞。** `open-questions.md` 明写「凡引用这两处台账的 FR 一律推迟到本条答定之后」——本条答定 + 两处台账重算即解锁那一批 FR 的 derive。
- **`.tres` / schema 零改动。** 单价表本就是既有平衡资源的一格，改的是取值与存储记法（分数 → 整数 `K`）；`G_c` / `X_c` / A1–A4 全是书写口径与标定台账，**不进任何 `Resource`、不进存档**，无迁移。
- **玩家侧可感知变化很小。** ch1 一场典型胜局多拿 1 点经验（约为 `Standard` 档 4 点的 1/4），碾压局多拿 2–3 点；越级挑战因此在经验侧也有回报，与「道念差是双向刻度」同向。
- **A3 从欠账变为通过**，表侧核对清单首次三条全过；代价是全胜供给比上移到 1.23–1.30 并被重新定性为**导出量**（见 Q1 的反方论据）。
- **失败的代价确实变重了一点**：ch1 一次典型失败的经验损失由 3 升到 4（占本章阈值合计 5.1%，原 3.8%）。容错量 `N = 2` 不受影响。
- **两条账的口径统一**：灵石与经验此后用同一个「胜场数 × `E[道念差]`」分母（前提是 `I(ch1) ≈ 127` 那格先对上，见「越界发现」）。

## 备选方案（已考虑并否决）

- **按现价（1 / 1 / 2 / 4）原样计入，超出部分靠提高阈值曲线吸收** — 否决：`experiencePoint` 小节明写「收口方向是继续调这条曲线或调构成，**不是提高阈值**」。且要吸收 ch1 的 +38% 需把阈值合计从 79 抬到 ≈114，等于推翻一条刚定案的曲线。
- **给经验侧的线性加成加一个上限截断（如封顶 2 点）** — 否决：胜负两侧均明写「不设上限截断」（`lossPerMomentum` 条：「截断会让『一次惨败』失去分量，正确的旋钮是系数本身」）。同一条理由对称适用于胜侧。
- **只让部分 `combatTier` 吃加成（如 Finale 吃、Practice 不吃）** — 否决：单价表只有篇章一维；按 `combatTier` 分档与 `lossPerMomentum`「三档共用同一系数，一个篇章之内玩家的心算账本只有一本」正面相抵。
- **把 `Explore` 真身为 Combat 的那部分也计进加成** — 本方案**不计**：`G_c` 当前把 `Explore` 计成扁平的 `Standard` 档（ch1 ×4 = 16），供给侧不区分真身；加成侧单独区分会造成两半口径不一致。ch1 影响量约 2 场 × `p` = 2 点（≈2%），保守不计并明写。真身构成表补齐后可一并复核。
- **`K` 取 ch1 = 6（窗口正中）** — 否决：`floor(5 / 6) = 0`，典型胜局的结算屏会显示「道念差加成 +0」，而结算屏被要求显式陈列算式。`K = 5` 使典型胜局稳定 +1，代价是 A3 落在 1.203（见 Q2）。

## 与既有决策的张力

1. **与「供给 / 需求 ≈ 1.15–1.20」的现有读数 1.16 / 1.17 / 1.18 冲突（承重）。** 推荐路线下全胜比升到 1.23 / 1.25 / 1.30，那三个数必须改写、并注明**带不管辖它**。松动的代价：全胜路线的经验冗余由 16–18% 升到 23–30%，「玩家提前满级、后半章经验奖励变废纸」这条风险在**全胜玩家**身上确实上升（满级后经验直接丢弃，`log-0830.md`）。不松动的替代方案 = 删列（Q1 选项 b），已在 Q1 中并列。
2. **与「单次给予量 ≤ 该境界最小阈值」的意图张力（不与其字面冲突）。** 该断言的对象是映射值，运行期总量不受它约束；但其意图（产出可细碎而连续、一次事件不跳两级）在含加成后需要一条新的可校验形式 ⇒ 子项 6 的 A4。按现价则 ch1 只余 1 点余量，按本方案余 5 点。
3. **与 `BaseReward` 「element 面 = 灵石一格、其余恒空」的表述需要一句澄清。** 计入后 `Spoils` 在物化后会出现一格 `experiencePoint`（其 `baseReward` 分量恒 0、只有道念差加成）。这与该条的论证**不冲突**——它本就是「物化后可出现的 key ≠ 模板可声明的 key」的字面情形——但须在该条补一句，否则会被读成矛盾。
4. **A3 的带值若维持 1.15–1.20 不变**（Q1 选 a），则 09-06 刚定案的 A3 只改状态不改形式；**若选 b**，A3 的带须重写为一条独立下界，等于在定案四天后改写它的形式。这是 Q1 两条路各自的代价，须由用户裁决。

## 前置依赖

- **`E[道念差]` = 5 / 12 / 18 是 ⚠ 待实测标定格。** 本方案的 `p_c` 与 `K` 全部由它派生 ⇒ 该格一改，`K` 须按同一条式子重算（改的是数，不是形状）。`open-questions/01-combat.md` 另有一条在办：**「`E[道念差]` ch3 的 35% 偏高」**——若 `E_3` 下调，`K_3 = 12` 须同步下调（`p_3` 须保持在 1.14 ~ 2.77 的窗口内）。**这两条应当一并裁决或明确先后。**
- **ch2 / ch3 的逐类型事件构成表尚未补齐。** `G_2` / `G_3` = 290 / 460 与战斗场数 11.9 / 14.0 同为按权重外推；构成表落定后本方案的 ch2 / ch3 两列须整列重算。ch1 的一列基于 35 批次参考构成，是三章中唯一可复算的。
- **`E[floor(d / K)] ≠ floor(E[d] / K)`。** 本方案用点估计代入，与整份台账的既有做法一致；实测拿到道念差分布后须按分布重算期望，届时 `K` 可能移动一档。明写以免被当成精确值。
- **`lossPerMomentum` ch2 / ch3 仍是候选值**（5 / 10）。它只影响寿元侧封顶值，不影响本方案的经验侧算术；但 `N` 的 `min` 取自寿元侧 ⇒ 它一改，`N` 由反推式自动重算（既定处置，不需重开口径）。

## 仍需用户决定

### Q1（前提题 · 必须先答）「供给 / 需求 ≈ 1.15–1.20」这条带，管辖哪一个量？

→ **已裁决（2026-09-10 · 批量评审）：(a) 带管辖「扣 N 后的比」（A3 口径）。** 全胜比降级为导出量；`G_c` 须计入道念差加成，全胜比三个数 1.16 / 1.17 / 1.18 改写为 1.30 / 1.25 / 1.23 并注明带不管它。用户已一并权衡并接受反方论据（全胜路线经验冗余 23–30%）。

**背景（自包含）：** `systems/balance.md` 里有两处用同一条带 `1.15–1.20` 卡经验供给，但分子是两个不同的量——一个是**全胜路线**的供给 `G_c`（当前 1.16 / 1.17 / 1.18，落带），一个是**扣掉 2 次典型失败后**的供给 `G_c − 2X_c`（验收断言 A3，当前 1.09 / 1.10 / 1.12，三章全部低于下沿）。两者相差 6–8%，**算术上不可能同时落在同一条带里**。A3 三章全 ✗ 的根因是这个，不是数值没校准。这一题决定下一题（Q2）的答案。

| 选项 | 含义 | 后果 |
|---|---|---|
| **(a) 带管辖「扣 N 后的比」（A3 口径）** | 全胜比降级为导出量，带不管它 | 需要 `p > 0` ⇒ **必须计入道念差加成，且单价须下调约 5 倍**；A3 三章首次全部落带（1.20 / 1.16 / 1.16）；全胜比上移到 1.30 / 1.25 / 1.23 并须改写那三个数 |
| **(b) 带管辖「全胜比」（现状口径）** | A3 的带须重写为一条独立、更低的下界（如 `≥ 1.05`） | 要求 `p ≈ 0` ⇒ **等价于经验不吃道念差加成**（Q2 只能选删列）；1.16 / 1.17 / 1.18 三个数原样保留；代价是 09-06 刚定案的 A3 在四天后被改写形式 |
| **(c) 两个量都要落带** | — | **算术上不可能**，仅列出以说明不是遗漏 |

**推荐 (a)。** 三条理由：① 带的两条边界（「更高则玩家提前满级、后半章奖励变废纸」「更低则跳过几个事件就卡在 12 级进不了 Finale」）**描述的都是实际游玩路线的失衡**，而全胜是上界情形、不是典型路线；② A3 是写进表侧核对清单的**机械可校验断言**，比一句书写口径更承重，让带跟着断言走更稳；③ 它是唯一能把「A3 偏紧、归实测校准」那笔欠账真正收掉的路线。
**反方论据（须一并权衡）：** 选 (a) 后全胜路线的经验冗余达 23–30%，而满级后经验直接丢弃——熟练玩家在篇章后半段会更早看到经验奖励变废纸。若你认为这一条比 A3 的通过更要紧，应选 (b)。

### Q2（依赖 Q1）`experiencePoint` 的胜侧单价取什么？

→ **已按标准默认采纳（2026-09-10 · 批量评审 · 未占 interview）：(A′) 计入 + 单价下调到 `K = 5 / 8 / 12`。** Q1 裁定 (a) 后本题被算术唯一锁定——(A) 按现价得 A3 = 1.66 / 1.34 / 1.25 超上沿，(B) 删列得 A3 停在 1.09 / 1.10 / 1.12 低于下沿，二者与 (a) 均不自洽。次级取值 `K = 5` vs `K = 6` 同样不构成取向：`K = 6` 使 ch1 典型胜局在结算屏显示「+0」，而结算屏**已定案要求显式陈列算式** ⇒ 取 `K = 5`，接受 ch1 落在 1.203 的那个 ε。若你不同意这一默认，直接改本行即可（其余数字按同式重算）。

**背景（自包含）：** 「胜侧单价」= 战斗胜利时，除固定奖励外按**道念差**（角色道念 − 敌人道念）额外给予的量，现行表给 `experiencePoint` 的三章取值是「每 1 点道念差 +1 经验 / 每 2 点 +1 / 每 4 点 +1」。按现价计入供给账会让 ch1 的经验供给多出 60%。

| 选项 | 形态 | 后果 |
|---|---|---|
| **(A′) 计入 + 单价下调到 `1 / 5 点 · 1 / 8 点 · 1 / 12 点`** | 存储改整数 `K = 5 / 8 / 12`，量 = `floor(道念差 / K)` | A3 = 1.203 / 1.161 / 1.161 ✓；`G_c` = 103 / 308 / 481；`N = 2` 不变；ch1 典型胜局 +1 经验。**仅在 Q1 选 (a) 时可行** |
| **(A) 按现价（1 / 2 / 4）计入** | 表不动，只重算台账 | A3 = 1.66 / 1.34 / 1.25 ✗（超上沿 38% / 12% / 4%）；全胜比 1.86 / 1.46 / 1.34；须同时推翻阈值曲线或供需带。**不推荐** |
| **(B) 删掉 `experiencePoint` 列（或置 0），正面裁定「经验不吃道念差线性加成」** | 单价表只剩灵石一列 | 所有既有数字（`G_c` 92 / 290 / 460、`X_c` 3 / 9 / 12、全胜比 1.16–1.18）原样不动；须在失败代价表 ⑤ 补一句「经验不在加厚范围内」；代价 = 删掉一列已定案数据，且 `ADR-0089` 曾以「列集是刻意的」否决过增列。**Q1 选 (b) 时这是唯一自洽答案** |

**推荐 (A′)（配合 Q1 选 (a)）。** 理由：它同时解决三件事——账目口径与灵石侧对齐、失败代价 ⑤ 在经验一列上落到实处、A3 首次三章通过；且它属于「调构成」，与既定收口方向（不提高阈值）一致。`K = 5` 的唯一瑕疵是 ch1 落在 1.203、吃掉「1.20 + ε」的 ε；换 `K = 6` 可得 1.184，但典型胜局的结算屏会显示「+0」，而结算屏要求显式陈列算式——**建议接受 ε，取 `K = 5`**；若你更看重带的严格性，改 `K = 6` 即可，其余数字按同式重算。
