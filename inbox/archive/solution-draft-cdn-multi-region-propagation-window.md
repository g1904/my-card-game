# 方案草稿 — CDN 多区域一致性的消解，与传播窗口 T 的重定义与取值

## 问题

`open-questions/04-content-delivery.md` 余下的唯一待答条目由两半组成：

1. **CDN 侧的三问** —— `contentRoot` 按区域下发这条自由度是否启用（它被刻意排除在被签名的 manifest 之外，正是为留出它）· 多区域间 `contentVersion` 是否必须同步推进 · 区域间发布的时序差如何处置。
2. **一个具体的数值缺口** —— flags 的传播窗口 **T**。契约已写死条款「新批次须在窗口 T 内在全部区域可见」，窗口内客户端观测到更小版本是**已知良性态**；但 T 一直只是个符号，`operations/content-delivery-ops.md`（「flags 读路径的拓扑自由度」）、`decisions/ADR-0009` 末段、`systems/_index.md`（`content-delivery.md` 尚未建立的两项欠账之一）都在引用它。

它卡住的是三处：`systems/content-delivery.md` 无法开写 · `ADR-0009` 的末段悬着 · T 缺值使「传播时延而非独立计数」这个口径无法被核对（一个没有数值的 SLO 无法判定是否违反）。

**本草稿的核心主张是：第 1 半已被上游决策消解，不是一个仍然开放的问题；而第 2 半的 T 需要先被重新定义，才谈得上取值。**

## 建议方案

### 1. CDN 侧的「多区域一致性」问题已被上游消解 —— 结论是否定的

`[既有推演]`

K1 把服务侧钉死为**单区域部署**。对内容分发面逐条推演，「多区域」在本项目里**不存在**：

| 三问之一 | 结论 | 推演 |
|---|---|---|
| `contentRoot` 按区域下发是否启用 | **不启用**（自由度保留，不撤销） | 单区域 ⇒ 只有一个内容源站、一个 `contentRoot` 值。CDN 的边缘节点不是「区域」——它们回源到同一个源站、由同一份 manifest 定义内容，**边缘之间不存在需要协调的独立版本**。启用区域化下发要先有「两套内容源」，而那只在海外独立部署时出现，届时它是**另一套部署的另一个 `contentRoot`**，不是同一套的多区域 |
| 多区域间 `contentVersion` 是否必须同步推进 | **问题消解**（无「多区域」可同步） | `contentVersion` 由**单一发布动作**分配（`content-delivery-ops.md` 步②与「`contentVersion` 的分配形态」），单调高水位落主存储。只有一条序列、一个分配点，「同步推进」没有对象 |
| 区域间发布的时序差如何处置 | **降格为边缘缓存传播**，已被既有条款覆盖，只欠一条 CDN 能力要求（见建议 6） | K7 的发布顺序 + 内容寻址 + 两类 TTL 已经把它处理完：blob 先推且 URL 不可变 ⇒ 任何边缘一旦读到新 manifest，其列出的 blob 必然可回源取到；manifest `no-cache` ⇒ 边缘不会长期停在旧版本 |

**海外扩展时的形态一并写清（否定「日后必然要回来重开这条」）：** 那是**两套独立部署**，各自独立的 `accountId` 空间、独立的 `contentRoot`、**独立的 `contentVersion` / `flagsVersion` 序列**，且**不要求两套同步推进**——两套之间没有共享账号、没有共享存档、没有跨部署的客户端路由，同步推进既无收益也无兑现手段。这与 K1 的「独立部署 + 独立 `accountId` 空间」同向，不是新决定。

**`contentRoot` 的自由度不撤销、也不改一个字。** 它现在的真实用途已经明确写在 `content-delivery-ops.md` 的 CDN 能力要求里：**域名 / 厂商切换**。「为多区域托管留出自由度」这句措辞建议在提炼时改写为「为域名切换与日后独立部署留出自由度」——它的成本本就为零（不进签名范围），保留它不需要任何理由，但让它继续指向一个已被消解的场景会误导实现方去建区域路由。

### 2. T 必须先被重定义 —— 它不是「跨区域」窗口，而是「跨实例」窗口

`[既有推演]`

条款原文是「新批次须在窗口 T 内在**全部区域**可见」。建议 1 一旦成立，「全部区域」就没有指称对象，条款会变成空条款——但**它要防的失效模式并没有消失，只是换了主体**：

单区域下仍有**多个应用实例**（托管容器，K1 的部署形态）。`X-Flags-Version` 搭任意应答的车下发，一个设备在一次会话内会打到多个实例；实例各自持有的「当前 `flagsVersion`」不会在 `publish` 事务提交的同一瞬间全部更新（版本读取的进程内缓存、连接池、K3 那条日后可能被用上的副本自由度）。**这就是 T 的真实主体。**

**建议把条款措辞由「在全部区域可见」改为「在全部对外服务的实例上可见」**，语义与既有条款完全一致（K4 的单一全局序列原样成立、良性态口径原样成立），只是把主体换成一个在本项目里真实存在的东西。这条改写同时让 K3 那条被保留的自由度继续有效——它日后若被用上（flags 读移出写入区），副本滞后天然落进同一个 T 的预算里，不需要第二个窗口。

### 3. 承重：偏斜是**不对称**的，纪律不是「把 T 压小」而是「头永不领先」

`[既有推演]` · **本草稿最承重的一条**

把 K8 的客户端处置逐条对上「头（`X-Flags-Version`）与体（flags 应答的 `flagsVersion`）来自不同实例」的两个方向：

| 偏斜方向 | 客户端行为 | 代价 |
|---|---|---|
| **头落后**（头 41、本实例已能兑现 42） | 等值 / 更小 → **不拉**；`PushWarning` 只在「更小于内存值」时触发，而内存值来自上一次成功应用 ⇒ 常态下只是**晚一拍拉取** | 只有延迟，**零告警、零上报** |
| **头领先**（头 42、flags GET 落到仍在 41 的实例） | 拉了一次，拉回 41 ≤ 内存值或 < 头观测值 ⇒ **整批丢弃 + `PushWarning` + 按会话上报一次**；且触发「有实质推进才允许尾随」的封顶判据 | 一次**误告警 + 一次上报**，而这条上报通道存在的目的是发现**灰度分桶串号 / 中间层缓存旧应答**这类真事故 |

**推论：真正要堵的不是「T 太大」，而是「头领先于体」。** 它是唯一会产生误报的方向，而误报会稀释一条**只可能在线上发生**的事故信号（K8 逐字写了这条上报「必须」存在的理由）。故建议三条服务端纪律：

- **D1 · 应答体的 `flagsVersion` 取自它实际使用的那条规则集记录，绝不取自高水位。** 「按高水位标号、按手上能读到的规则集算 `disabledIds`」会直接违反 K5（同版本不同结果），且客户端无任何手段发现。这条是 K5 的实现侧直接推论，写下来是因为高水位就在手边、取错极自然。
- **D2 · `X-Flags-Version` 头下发的值 = `min(高水位, 本实例当前能兑现的最大规则集版本)`。** 即**头永不领先于本实例能兑现的规则集**。单实例内的「头领先」由此**结构性不可能**；跨实例只剩「头落后」，而那一栏零告警。
- **D3 · 「实例能兑现的最大规则集版本」由 A6 的规则集缓存自然给出。** A6 已定「缓存对象是规则集本身、键 = `flagsVersion`、值不可变、永不需要失效逻辑」；D2 要的那个数就是该实例已装载的最大键。**零新增机制、零新增存储、零报文改动。**

采纳 D1–D3 后，T 从一条「必须压得足够小否则出误报」的硬约束，降级为一条**纯延迟 SLO**：超了只是秒关慢一点，不产生任何错误行为、不产生任何误报。这正是它该有的分量。

### 4. T 的数值：初值 **60 秒**

`[通行做法]` · 平衡数值的规矩：初值 + 推导 + 旋钮位置，**待实测校准**

**上界从两侧夹出来：**

- **上侧（不能更大）** —— 契约已承诺秒关的端到端延迟是**分钟级**（K9）。端到端 = T（新号在全部实例可见）+ 该玩家下一次上行（稳态 ≈ 60 秒）+ 一次 flags GET。取 T = 60 秒 ⇒ 端到端上界 ≈ 2 分钟，仍是分钟级；取 T = 5 分钟则端到端逼近 6 分钟，「分钟级」这句承诺开始名不副实，而秒关要止的是线上事故。
- **下侧（不必更小）** —— 采纳 D2 后偏斜不再产生误报，把 T 压到秒级换不到任何正确性收益，只会把一条本可宽松的 SLO 变成频繁告警的噪音源。

**预算分解（T 由三项组成，各自是可调旋钮）：**

| 分项 | 初值 | 说明 |
|---|---|---|
| 实例侧「当前 `flagsVersion`」的读取缓存 TTL | **5 秒** | 主导项。**注意它不是 `config_knob` 的那个 30 秒进程内缓存**（`operations/environments.md` 配置三层）——那是配置旋钮的缓存，flags 当前版本不是配置。两者不得混用同一份缓存 |
| 副本滞后预算 | **10 秒**（当前实际为 0） | K2 下 flags 读走写入区 ⇒ 现值 0。预留这一格是为 K3 那条自由度：日后 flags 读移出写入区时，不必重开 T |
| 余量（实例滚动、连接池、冷启动首波 single-flight） | 其余 | A6 的 single-flight 已覆盖新版本首波回源 |

**T 本身不是 `config_knob`**——它是一条 SLO（判定用的阈值），不是运行时行为的输入。**进 `config_knob` 表的是上面两个分项**（版本读取缓存 TTL、副本滞后预算），按 `environments.md` 的第三层「改值不发版」落位；T 随之进 `content-delivery-ops.md` 的「数值初值一览」表。

**校准信号：** 建议 5 的探针 p99 稳定低于 T 的三分之一 ⇒ 可考虑收紧 T；p99 反复触顶 ⇒ 先查缓存 TTL 与实例滚动策略，而不是抬高 T。

### 5. T 需要一条探针，否则它是纸面 SLO

`[通行做法]`

一条**零契约面、零新增埋点**的形态：

- 每个实例把「本实例当前能兑现的最大规则集版本」（即 D2 用的那个数）作为一个 **gauge** 暴露；
- 告警断言：`max(gauge) - min(gauge) != 0` 且**持续超过 T** ⇒ 告警。稳态下它恒为 0，一次 `publish` 后短暂非零是正常的；
- 与 `observability.md` 已有的五条契约语义探针并列，落「数据面」一档，不新增契约字段、不新增客户端义务。

**为什么不用「publish 提交时刻 → 首次出现新号的时刻」做主指标：** 那要求把发布动作的时间戳与请求侧的观测关联起来，跨两个数据源；而 gauge 的极差直接就是 T 的定义本身，且在**没有发布**的时候也持续有效（能发现「某个实例卡在旧版本再也不更新」这个更阴的故障，它不会被任何一次发布触发）。

### 6. 顺带堵一个 CDN 侧的真实残留：blob 的 **404 负缓存**

`[通行做法]`

建议 1 判定区域时序差已被覆盖，但推演中浮出**一个尚未被任何条款堵住的边缘行为**，它与「区域」无关、与「内容寻址 + `immutable` 长缓存」这个组合有关：

> 若某个边缘节点在 blob 推上去**之前**曾对同一个 `<contentRoot>/blobs/<hash>` 收到过请求并缓存了 404，则在负缓存 TTL 内，命中该边缘的客户端会**稳定拿不到一个 manifest 已经列出的文件**。客户端的表现是逐文件下载失败 → 事务不提交 → 跳过本次更新（不崩、不坏档），但症状与网络不好难以区分，且**只影响命中该边缘的那部分玩家**——与「④ 自验」要防的那类静默失效同型。

建议在 `content-delivery-ops.md` 的「对 CDN 的能力要求」补两条（**属于运维形态，不动契约**）：

- **`/blobs/*` 路径关闭负缓存，或负缓存 TTL ≤ 数秒。**
- **步⑤「确认 blob 可读」的探针走 CDN 域（与玩家同一条路径），不直连源站。** 直连源站验的是「源站有没有」，而 A 组第 3 条要保证的是「manifest 可被读到时其文件必须已可下载」——可下载指的是**玩家侧**可下载。

现有发布顺序（先 blob 后 manifest）本身不产生负缓存：客户端只请求 manifest 列出的 hash，而 manifest 尚未发布。**风险来自发布流水线之外的探测**（人工排查、监控探针、扫描器）。故这是一条低概率但**高定位成本**的项，用一行 CDN 配置换掉它是划算的。

## 备选方案（已考虑并否决）

- **保留「多区域」措辞、只填一个 T 的数字。** 否决：条款主体（「全部区域」）在单区域部署下没有指称对象，一条无法判定是否被违反的 SLO 等于没有 SLO；而真实的失效主体（多实例）会因此**一直没有被任何条款覆盖**。
- **把 T 压到秒级（如 5 秒）而不引入 D2。** 否决：靠压窗口去减少误报是概率手段，压不到零；且它把一条本可宽松的 SLO 变成频繁告警源。D2 是结构性手段、成本为零（那个数已经在 A6 的缓存里）。
- **启用 `contentRoot` 按区域下发，先把机制建起来备用。** 否决：单区域下没有第二个 `contentRoot` 值可下发；建一套无输入的区域路由是纯负债，且会在海外独立部署真的到来时被发现形态不对（那时是两套部署，不是一套的多区域）。
- **按区域独立的 `flagsVersion` 序列 · 跨区读。** 已在 `handoffs/2026-08-23b-flags-version-monotonic.md` 否决（前者须下发区域标识、泄漏区域概念给客户端；后者使某区域故障即全球 flags 不可用），本草稿不重开。
- **用「publish 时刻 → 首次出现新号」做 T 的主探针。** 否决：跨两个数据源，且在无发布期间失效，发现不了「某实例永久卡在旧版本」。
- **撤销 `contentRoot` 不进签名范围这条自由度**（既然不用区域化下发）。否决：它的现役用途是域名 / 厂商切换（`content-delivery-ops.md` 的 CDN 能力要求已在依赖它），撤销要重签历史 manifest 才能换域名——`ADR-0001` 的备选方案栏已逐字否决过。
