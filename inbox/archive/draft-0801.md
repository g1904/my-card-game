## 一、评审背景：当前循环（评审时读到的样子）

```
登录 → 主菜单（择已解锁篇章）
  └─ 篇章循环：
       future-event-service 物化一批 eventOptions（location 框定 + AdventurePlot 调制 + seeded RNG）
         → 横向滑动菜单择一（受 eventPriority 封锁、ifMandatory 封锁跳过）
         → TryApply(selectCost | skipCost)
         → resolver 结算（Combat / Practice / Finale 走战斗；其余六类走 GenericEventResolver）
         → 合并 outcome + lifeSpanCost + 隐藏属性推拉为一次 TryApply → 记 pastEvent → 自动存档
         → 重算下一批
       ...直到 Finale 突破 → 篇章边界存档 → 下一篇章
```

评审结论：架构骨架（一事件 = 一事务 = 一存档点、模板 → `EventOption` 物化、两级 service ⊃ manager）是扎实的；问题集中在**玩法闭环的空洞**与**几处互相打架的定案**。

评审提出的七个结构性问题（严重度递减）：

1. **寿元预算 ↔ 时段形态不匹配。** `lifeSpanCost` 基准 1 + 炼气寿元 100 → 第一篇章约 100 个事件（2–5 小时），与「一个篇章 = 一个移动端时段」冲突；且各篇章密度失衡（炼气 13 级 / 100 寿元 ≈ 7.7 事件每级，筑基 4 级 / 100 ≈ 25，金丹 4 级 / 300 = 75），第三篇章「最长 + 只有 1 次重试」。→ 见裁决 ①。
2. **跳过通道无经济学闭环。** 跳过通常不扣寿元 + 单项补位 → 可无限 reroll 刷事件。→ 见裁决 ②（前提被推翻）。
3. **战斗内节奏张力为空。** `mana.md` 自陈节奏须由「卡牌效果 / 状态层数 / 敌人行为」承担，但状态系统空白、`scoring.md` 整份空、CardData 字段未定 —— 三根支柱一根未立。→ 见裁决 ③（由「道念」承接）。
4. **`manaLimit` 可降 ↔ 卡牌费用空间锁死**（高费卡可能变死牌）。→ 见裁决 ④（前提不成立）。
5. **信息全遮蔽的叠加效应。** 隐藏属性 + Mystery + 越级黑箱 + 物化随机四层叠加，抉择可能退化为盲选；Reigns 的张力来自**可见**仪表。→ 见裁决 ⑤（批准）。
6. **无俯瞰地图 + 无预告 = 缺中长期规划感。**（本次未裁决，留待后续。）
7. **元进程只有奖励、没有「失败也推进」。** 第一篇章无限重试 = 死亡零成本亦零推进。→ 见裁决 ⑦。

## 二、逐条裁决（用户意图 · 权威）

### ① 寿元与 `lifeSpanCost` —— 目标时长驱动的分档

- **`lifeSpanCost` 用正数表示消耗（已定案）**（不是 -1）；**当前的 1 是占位值**，不是设计意图。
  - **与 `ProfileChangeSpec` 带符号约定的协调（已定案）：** `systems/adventure-event/common-properties.md` 现载「代码形态 = `ProfileChangeSpec`，`ChangeElement.BaseValue` **带符号**：负 = 消耗，正 = 产出」——该约定**不变**。`lifeSpanCost` 是**内容侧作者标注的正数量值（magnitude）**，在 **future-event-service 物化组装 `selectCost` / `skipCost` 时取负**填入 `ChangeElement.BaseValue`。即：**内容作者写正数，spec 里仍是负数**，两条约定各自成立、互不推翻。
    - 落点：`systems/adventure-event/common-properties.md`（`lifeSpanCost` 条目 + 成本类型代码形态段）、`systems/services/future-event-service.md`（物化阶段的取负规则）、`systems/balance.md`（分档表用正数书写）。
- **目标游玩时长（愿景）：**

  | 篇章 | 寿元增量 | 目标时长 | `lifeSpanCost` 取向 |
  |------|---------|---------|---------------------|
  | 第一篇章 炼气→筑基 | 起始 100 | **15–30 分钟** | 基准档 |
  | 第二篇章 筑基→金丹 | +100（**外加第一篇章结转的剩余寿元**） | **15–30 分钟** | **略微上调**（例：闭关耗时更长） |
  | 第三篇章 金丹→元婴 | +300（远多于前两章） | **20–40 分钟** | **相应大幅上调**，以把时长压回区间 |

- 要点：**寿元预算不变，靠调 `lifeSpanCost` 来控时长**——预算增量是叙事 / 阶梯的形式量，事件定价才是时长旋钮。
- **剩余寿元跨篇章结转**（第二篇章的可用预算 = +100 + 第一篇章剩余），即「省着花」有跨篇章回报。
- 事件之间 `lifeSpanCost` 有差异（如 **闭关 Research 比常规事件耗时更长**）；具体分档表待定。

### ② 跳过通道 —— 前提修正，配额 / 递增成本不需要

- **跳过只对「可选」事件开放**：可选的剧情事件、可选的增益事件等。**不是所有事件都能跳过**。因此「无限 reroll」的前提不成立 —— **不需要每批跳过配额，也不需要递增 `skipCost`**。
- **跳过留痕（跳过什么类型的事件反向影响 AdventurePlot / 隐藏属性）是好主意**，且 `pastEvent` 已经跟踪跳过痕迹。但它**属于内容设计而非系统设计**，留待将来的**剧情与卡牌设计**阶段考虑。

### ③ 战斗节奏提案 —— **驳回**；新愿景：道念 = 胜负判据

- 「气机 / 状态层数造节奏」的提案**驳回**：同样属于将来的剧情与卡牌设计范畴。
- **新愿景（重要，改写战斗模型）：**
  - **momentum = 道念**，是**计分（scoring）用的胜利点数（victory point）**。
  - **战斗胜负不再由「life 归零」判定，而是由「道念高者胜」判定。**
  - **战斗 / 修炼失败 → 角色在战斗结束时损失 life，损失量由「角色道念 − 敌人道念」的差值决定。**
  - **战斗过程中 life 不直接参与，焦点全在道念。**
- **连锁改写（已定案，随本条一并生效）：**
  - **`systems/scoring.md` 的答案就是道念。** 该文档当前整份为空——计分模型不再悬空：**计分 = 道念（momentum），且道念即战斗胜负判据**，不是独立于战斗之外的另一层。需按此重写 `scoring.md`，并与 `adventure-event/combat/` 交叉引用。
  - **`life` 重定位。** life **不再是战斗内的血量资源**，而是「**战斗外的耐久 / 失败惩罚承受量**」——只在战斗**结算时**按道念差被扣减，战斗**过程中不参与**。`systems/character-profile/life.md` 需按此重写。
  - **「life + mana 双资源战斗模型」的表述被推翻。** `systems/adventure-event/combat/_index.md`、`systems/character-profile/life.md`、`mana.md`、`systems/balance.md` 中「参考 MTG / Hearthstone 的 life + mana 双资源」「胜负 = life 归零」一类表述**全部需要重写**为：**战斗内资源 = mana（出牌）+ 道念（计分与胜负）；life 在战斗外承接失败惩罚**。炼气基线 life 10/10、mana 5/5 的数值本身不受影响。
  - 相应地，`systems/services/combat-service.md` 的胜负判定、`CombatSnapshot` / `PlayResult` 字段需含道念；`ux/combat-ux.md` 的战斗屏幕需以道念为主视觉（双方道念对比），life 退居次要。
- 仍未定（后续 session）：战斗的**终止条件**（回合上限？道念阈值？敌人卡组耗尽？）、**道念的产出途径**（哪些卡 / 行为产道念）、道念差 → life 损失的**换算公式**。

### ④ `manaLimit` 下界护栏 + 死牌转化 —— 不需要

- **`manaLimit` 下降是非常罕见的情形**，不值得为它专门设计下界护栏与死牌转化规则。

### ⑤ 隐藏属性的定性反馈 —— **批准**

- 保留数值隐藏，但**跨档时给一条定性的叙事描述**（不给数字）：

  ```
  道心 ↑ 跨档：  「你于静室枯坐三日，心念澄明。」
  煞气 ↑ 跨档：  「你的指节泛起一层洗不去的暗红。」
  寿元 进入 30%：「鬓角新添的白发，你已数不清是第几根。」
  ```

- 只在**跨档**时触发（隐藏属性分若干隐藏档位），不是每次结算都播 —— 保持稀缺感。
- 玩家学到**方向与因果**，学不到**精确数值**，无法做电子表格式优化 —— 这正是 Reigns 式张力的来源。
- 复用已有的 `ResolveOutcome` → `eventEnd` 阶段，无新结构。
- **寿元告警改为两段式：30% 起给定性叙事提示，10% 起给红字数值倒数**（现行只有 10% 红字，对 100 点预算而言太晚，来不及做战略调整）。呈现位置仍为 EventOption 选择界面的静态标注。

### ⑥ 等级成长与危险度标注

- **等级成长 = event reward**：由 AdventureEvent 的产出给予，**不只绑定 Combat / Practice**，且**不只有胜利才给**（失败同样可能有等级产出）。
- **危险度标注：Combat / Practice / Finale 不做模糊的危险度档位（「同阶 / 略高 / 越阶 / 无从揣度」被否决），而是在 eventOptions 上精确标注敌人的等级。**
  - 推论：`ux/combat-ux.md` 的待决项「等级差本身是否对玩家可见」由此答定 —— **敌人等级精确可见**；玩家可自行与自身等级比对，从而理解意图为何被遮蔽。
  - 推论：「越级挑战」因此成为玩家**可主动选择**的风险 / 回报维度（信息可见 → 抉择成立）。

### ⑦ 失败侧的产出

- **EnemyCodex 遭遇即记录**（不必击败才记）—— 死亡至少换来知识；这同时是 `open-questions.md` 中「敌人图鉴解锁粒度」的一个答案。
- **道统残卷改写：不发放账号级货币，而是提高「下一次轮回获得新 PlayerPower」的概率；一旦获得新 PlayerPower 即重置该概率。**
  - 即：失败累积的是**一个递增的掉落概率**，而非可支配的货币；避免引入第二套账号级经济。
  - 待定：概率的累积粒度（每次失败 +X%？按抵达深度加权？）、上限、与 seed 公平性的关系。
