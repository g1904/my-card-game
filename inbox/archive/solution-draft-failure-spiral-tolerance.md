# 方案 — 失败螺旋的容错量 N 与「典型失败」口径

## 问题

`systems/game-progression.md:56` 的验收项要求「验证即使发生 N 次典型失败，按标准路线走仍能在预算内升满」，`systems/character-profile/life-span.md:24` 用「若干次典型失败」。两处都没有定义：① 「典型失败」是哪一档遭遇、道念差多少、用哪一章的 `lossPerMomentum`；② N 是多少、三章是否同值；③ 验收断言长什么样（本作的验证方式是在 Godot 编辑器里运行游戏观察，一条不可当场核对的断言等于没有验收项）。

**螺旋本身不是待答项。** `decisions/ADR-0127-life-merged-into-lifespan.md:29` 已把「一次战斗失败同时压缩『还能失败几次』与『本章还能做几个事件』」定为被接受的设计取向。本稿只做标定，不动机制。

## 方案

### 一、「典型失败」的口径（五格全部锁死）

`[既有推演]`

| 格 | 取值 | 依据 |
|---|---|---|
| **遭遇档** | `Combat` / `Standard`（10 回合） | `balance.md:193`「一场 `Standard` 遭遇是时长反推的稳定输入」；`Practice` 的轻量化由 `TurnLimit` 8 / `WinMargin` 0 / `ExperienceGrade` 偏置承担，不是典型；`Finale` 失败不进螺旋 |
| **赋级 `diff`** | 按带内分布权重的众数 **`diff = 0`** | `balance.md:38`（40%）与 `:42`「众数恒为 `diff = 0`」 |
| **道念差** | `E[道念差]` = **5 / 12 / 18** | `balance.md:234`。不另立第二套假设——螺旋标定与 λ 反推必须共用同一格 |
| **系数** | 该章 `lossPerMomentum` = **10 / 5 / 10** | `balance.md:466–470` |
| **经验档** | 该场若胜为 `Major`，失败得 `floor(Major × 50%)` | `game-progression.md:50`、`balance.md:596–597` |

**分布口径：N 次失败均匀散布在本章常规事件段，不集中在末段。** `[通行做法]` 集中在末段更狠，但「末段」不是可标定的位置——事件序列由 future-event-service 逐批重算，篇章内没有可寻址的进度刻度（`game-progression.md:59`）。均匀散布是唯一可复算的假设。

**一次典型失败的两笔代价（逐章）：**

| | ch1 | ch2 | ch3 |
|---|---|---|---|
| **① 寿元扣减** `L_c` = `E[道念差] × lossPerMomentum` | 5 × 10 = **50** | 12 × 5 = **60** | 18 × 10 = **180** |
| 占本章可用预算 | 50 / 1000 = **5.0%** | 60 / 1160 = **5.2%** | 180 / 3169 = **5.7%** |
| **② 经验损失** `X_c` = `Major − floor(Major × 50%)` | 6 − 3 = **3** | 18 − 9 = **9** | 24 − 12 = **12** |
| 占本章阈值合计 | 3.8% | 3.6% | 3.1% |

`[既有推演]` **副产品（第二条形状锚）：一次典型失败恒占本章预算 ≈ 5%，恰是回寿小档。** 既定形状锚是「一次带内最坏落差的失败恒落本章预算 8%–12%」（`balance.md:474`）；「典型 ≈ 最坏的一半」（`:234`）⇒ 典型失败恒落 ≈5%，与回寿三档的小档（5%，`:266`）同量级。这不是巧合，是两格取值的算术后果，值得写进 `balance.md`。

### 二、N 的反推式

`[既有推演]` 沿用 `balance.md:214` 的 λ 反推式记法，把 N 显式加进去：

```
寿元侧    Surplus_c(N) = B_c + R_c − S_c − N × L_c  ≥  C_c^min
经验侧    Supply_c(N)  = G_c − N × X_c              ≥  D_c

  N_c = min( (B_c + R_c − S_c − C_c^min) / L_c ,  (G_c − D_c) / X_c )   向下取整
```

**结转目标 `C_c` 在容错验收里算软目标（定案）**：验收只要求 `Surplus_c(N) ≥ 0`（`C_c^min = 0`），结转不足由 ch2 的偏紧预算自行承担——`balance.md:112` 明写「结构性偏紧的预算……是有意的失败面」；容错量的定义本就是「输了还能不能走完这一章」，把下一章的舒适度写进本章的及格线，等于用一条软目标去卡一条硬验收。**硬结转口径（`C_c^min` = 150 / 100 / 0）的对照值一并写进台账**，供日后收紧时直接取用。

### 三、逐章代入

| | ch1 | ch2 | ch3 |
|---|---|---|---|
| `B_c + R_c` | 1100 | 1276 | 3486 |
| 盈余 = `B + R − S` | **265** | **298** | **485** |
| 寿元侧（软，`C^min = 0`） | 265 / 50 = **5.30** | 298 / 60 = **4.97** | 485 / 180 = **2.69** |
| 寿元侧（硬，`C^min` = 150 / 100 / 0） | **2.30** | **3.30** | **2.69** |
| 经验侧 `(G − D) / X` | (92−79)/3 = **4.33** | (290−247)/9 = **4.78** | (460−391)/12 = **5.75** |
| ⇒ **N_c（软）** | **4.33** | **4.78** | **2.69** |
| ⇒ **N_c（硬 · 对照）** | 2.30 | 3.30 | 2.69 |

`[既有推演]` **承重结论 ①：ch3 的容错量由寿元侧独占决定（2.69 ≪ 5.75）；ch1 由经验侧封顶（4.33 < 5.30）；ch2 两侧几乎持平（经验 4.78 · 寿元 4.97），封顶侧对标定噪声敏感、不作承重表述。** 量纲直觉不变：ch1 一章升 12 级、经验账排得满；ch3 只升 3 级、经验远超需求，咬合的是寿元。

`[既有推演]` **承重结论 ②：ch3 是全轮回容错最薄的一章（N = 2.69），而它恰是重试上限为 1 的那一章**（`game-progression.md:17`）。螺旋咬得最狠的地方正是玩家最输不起的地方。这是算术必然（ch3 预算跳 3 倍而 `L_3` 跳 3 倍），不是配置失误，作为已知代价明写并登记为实测复核点；**不为它加旋钮**——N = 2 之外 ch3 仍余约 125 点寿元 ≈ 1 个完整事件的余量，且「ch3 最凶、重试只有 1 次」与既定叙事同向。

### 四、取 **N = 2，三章统一**（定案）

三条依据：

1. **三章的算术上界（软口径）是 4.33 / 4.78 / 2.69**，向下取整的统一取值即 min ⇒ 2；三章全部舒适成立（最紧的 ch3 仍余 0.69 × 180 ≈ 125 点寿元）。
2. **硬软两种结转口径给出同一个 N = 2**（硬口径 2.30 / 3.30 / 2.69 同样全部 ≥ 2）——裁决口径之争不影响取值。
3. **与「三章统一」的既有纪律同向**——赋级带 `±2`、`FinaleDiff` 三章恒 `+1`、批次规模三章共用一行皆如此。分章的容错量需要一个分章的理由，当前没有。

**N = 2 落在哪里：** **不进 `.tres`、不进任何 `Resource`。** 它与 `t(type)` 耗时台账、越级追分形状锚同档——是标定台账 / 验收口径，不是运行期读取的字段。以「失败容错量 N 的反推台账」小节落在 `systems/balance.md` 的 λ 反推式之后。

### 五、可验证的验收断言

`[通行做法]` 断言分两层：一层可在电子表格里当场算、一层可在编辑器里一次通关核对。

**A. 表侧（每次调三个旋钮后重算，直接扩充 `balance.md:601` 已要求的「供给 / 需求校验表」，加 `N × L_c` 与 `N × X_c` 两列）**

```
对 c ∈ {1, 2, 3}：
  A1  B_c + R_c − S_c − 2 × L_c        ≥ 0          寿元不破产
  A2  G_c − 2 × X_c                    ≥ D_c        经验仍够升满
  A3  1.15 ≤ (G_c − 2 × X_c) / D_c     ≤ 1.20 + ε   供给不因加了 N 而跌出既定区间
```

当前状态：A1 全过（165 / 178 / 125）✓ · A2 全过（86 ≥ 79 · 272 ≥ 247 · 436 ≥ 391）✓ · **A3 三章均略低于下沿（1.09 / 1.10 / 1.12）✗——已知的、被记录在案的偏紧**：阈值曲线按全胜 1.16–1.18 标定，扣掉两次失败必然跌破 1.15。收口方向仍是 `balance.md:599` 写明的「调曲线或调构成，不是提高阈值」，归实测校准。

**B. 编辑器侧（一次通关即可核对，不需要任何测试工具）**

```
以固定 CycleSeed 走 ch1 的参考构成路线，故意在第 10 与第 24 个事件位上的
两场 Combat/Standard 遭遇判负（各落后约 5 点道念）；
抵达 Finale 出现条件判定点时，读角色状态条：
    ① level == 13（炼气十三层，即本境界末级）
    ② lifeSpan > 0
    ③ Finale 选项以 eventPriority = 1 出场（即出现条件已满足）
三条同时成立 = 该章的 N = 2 验收通过。ch2 / ch3 同形，末级取 17 / 21。
```

三个读数全部已在既有 UI 上恒精确可见（等级与经验条常驻角色状态条，`game-progression.md:57`；寿元明文常驻，`life-span.md:34`）。**不要求任何新增的调试面板或读数。**

## 后果

- 三份活文档的措辞收紧（`balance.md` / `game-progression.md` / `life-span.md`），无结构改动、无迁移。
- `balance.md:601` 的「供给 / 需求校验表」多两列（`N × L_c` 与 `N × X_c`）——既有缓解措施的扩充，不是新负担。
- **ch3 的容错量 2.69 被显式记录**为一条已知代价与实测复核点。
- 若日后 `lossPerMomentum` ch2 / ch3、`E[道念差]` 或败率任一格被实测改写，**N 由反推式自动重算**，不需要重新讨论口径。

## 备选方案（已考虑并否决）

- **结转按硬约束验收** — 否决为主口径（保留为台账对照值）：`balance.md:112` 明写偏紧预算是有意的失败面；且新分母下硬口径同样得 N = 2，此项之争已无实际后果。
- **N 逐章取不同值** — 否决：分章需要一个分章的理由，当前只有「算术上界不同」，而库内同类旋钮（赋级带、`FinaleDiff`、批次规模）一律三章统一、把可逆性留在数据侧。且 N = 2 在三章都舒适成立。
- **把 N 做成 `.tres` 上的平衡字段** — 否决：运行期无任何消费者；`balance.md:188` 已明写这类量不进 `Resource`。
- **给失败扣减加「连败递减」阻尼** — 否决：`ADR-0018` 已否决上限截断（「截断会让一次惨败失去分量」），连败递减是同一类补丁，且引入一个必须存档的连败计数器；`ADR-0127:29` 已把螺旋定为取向。
- **把「典型失败」定义为 `Practice` 档** — 否决：低风险档会系统性低估容错需求；`balance.md:193` 已把 `Standard` 指定为反推的稳定输入。
- **N 以「占常规战斗场数的百分比」表达** — 否决：验收断言最终要落成「故意输掉 k 场」这个整数动作，百分比徒增换算。
- **为 ch3 多排一次回寿（`R_3` 3 次小档）或把 ch3 `lossPerMomentum` 下调至 5** — 否决：都是为一个算术结果加旋钮；前者要重算 λ₃ 与 ch3 整列定价，后者当场破 8%–12% 形状锚。新分母下 ch3 余量已达约 1 个完整事件，动机也已消失。

## 与既有决策的张力

**① 与 `balance.md:240` 的引用禁令。** 该行明写败率 20% 与 `E[道念差]`「不得被引用为任何设计的承重依据」，而 `L_c` 正是由这两格算出。**化解（不需要松动禁令）：本方案的承重产物是口径与反推式，`N = 2` 是该式在当前输入下的输出**，不是独立成立的设计结论——落笔时把这句话写进台账，与 λ 反推式「21 格可复算」的处理完全同款（那 21 格同样建立在这两格之上）。

**② 与「结转是 ch2 的必要预算构成」（`balance.md:243`）的读法分歧已消解。** 该行与 `:112`「偏紧预算是有意的失败面」对结转是硬是软给出相反读法；已裁定按软目标验收，且新分母下两种口径同得 N = 2，分歧不再有数值后果。`:243` 的「`C1 ≳ 140`」算式本身不自洽（自洽重算为 ≳ 83），归 rescale 稿前置依赖 3 处理。

## 前置依赖

1. **`lossPerMomentum` ch2 / ch3 仍是候选值**（三处口径直读核对：取值完全一致，均为 ch2 = 5 / ch3 = 10，分歧只在状态措辞——`life-span.md:54`「定案待反推」应对齐为「定案待『典型道念差的实际分布』实测」，见矛盾收口稿条目 ③）。**敏感度：若 ch2 定案改判为 10**，`L_2` = 120 ⇒ 寿元侧（软）298 / 120 = 2.48 ⇒ N₂ = 2.48，**N = 2 仍成立**（硬口径 1.65 会破，但主口径已定软目标）。
2. **ch2 / ch3 没有直读的参考构成**——`S_c` / `G_c` 两组取自 rescale 稿按权重外推的构成，构成落定后两章的 N 须重算。
3. **胜侧 `rewardPerMomentum[experiencePoint]` 是否计入供给账未答定**（`balance.md:450` 给出 ch1 单价 1 / 点，而 `G_c` 只算了档位产出）。计入则经验侧的 N 全部上移 ⇒ 当前经验侧的 N 偏保守；它同时是「失败少拿的第三笔代价」，本方案未计入。
4. **回寿量三档的绝对点数未定案**（`balance.md:818`）。`R_c` 取自 λ 反推式的假设（每章 2 次小档）；回寿次数一变，盈余随之变。
