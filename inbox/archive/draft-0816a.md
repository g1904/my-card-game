# 收口批次一 — 删「已定案」戳

## 为什么

活文档里「已定案」出现 **659 次**。

活文档的每一句**默认就是当前定案**——这是根约定「活文档只保留最新设计（重写替换，不留考古）」的直接推论。给定案句加「已定案」戳，等于给所有句子加同一个标记，**信息量为零**；而它挤占的是句首最值钱的位置，读者每一条都要先跳过它才读到设计本身。

更实际的代价：戳一旦泛滥，**真正需要区分的「暂定 / 软标准 / 待验证」反而看不出来了**——读者无法从「有戳 / 无戳」判断确定性，因为无戳的也是定案。

## 范围

**只改活文档**：`vision/` · `systems/` · `art/` · `ux/` · `content/` · `decisions/` · `requirements/`。

**不碰过程档案**：`handoffs/` · `inbox/` · `answer-logs/` · `open-questions/` · `open-questions.md`。那里的「已定案」是**记录当时状态**，是正当的。

## 定位

```bash
cd game-design-documents
grep -rn "已定案" --include="*.md" vision systems art ux content decisions requirements
```

## 三种处置

### ① 孤立的戳 → 直接删（预计占绝大多数）

戳只是给一句定案陈述加标记，删掉不损失任何信息。

```
✗ **战斗是定长的：固定 10 个回合（已定案）。**
✓ **战斗是定长的：固定 10 个回合。**

✗ **道念的运行态骨架（已定案）。**
✓ **道念的运行态骨架。**

✗ 唯一选择点 `BackendSelector`（已定案）
✓ 唯一选择点 `BackendSelector`
```

括号里**只有**「已定案」→ 连括号一起删。删完检查标点是否还通顺（`（已定案）。` → `。`，不要留下 `。。` 或悬空的 `·`）。

### ② 戳 + 过程坐标 → 本批只删戳，坐标留给批次二

```
当前：**`OpResult.Detail` 是诊断串（已定案 · 08-12 · 推翻 07-27b 的「面向玩家的原因串」）。**
本批：**`OpResult.Detail` 是诊断串（08-12 · 推翻 07-27b 的「面向玩家的原因串」）。**
批次二再处理成：**`OpResult.Detail` 是诊断串**（并把「为什么不是面向玩家的原因串」这条承重理由改写保留）。
```

**不要在本批顺手做批次二的活。** 那需要逐条判断「否决理由是否承重」，与本批的机械替换混在一起会让 diff 无法复核。

### ③ 并置了非定案项 → 反转标注对象

同一处**并列**着确定项与不确定项时，戳是有用的——但应该标**不确定的那个**，不是给确定的加戳。

```
✗ 手牌上限 7（已定案）· `itemPowerRatio` 0.35（已定案）· 法则强度上沿 25%（软标准）
✓ 手牌上限 7 · `itemPowerRatio` 0.35 · 法则强度上沿 25%（暂定，内容评审参考值）
```

保留 / 补上的标注词用现成的：`暂定` · `软标准` · `待验证` · `⟨待定⟩` · `待用户确认`。**不要发明新词。**

## 一并处理的近亲

同批扫掉这几个等价空戳（判据相同：活文档默认即当前定案）：

```bash
grep -rn "（已确认）\|（确定）\|（已拍板）\|（已裁决）\|已敲定" --include="*.md" vision systems art ux content decisions requirements
```

**但保留** `已定案的准确措辞`、`已定案的一张表` 这类——那里「已定案」是**修饰后面的名词**（在说「这张表是定下来的版本」），不是给句子盖戳。判据：删掉后句子是否还通顺、语义是否不变。不变 ⇒ 删；变了 ⇒ 留。

## 验收

```bash
# 活文档中应归零（除上面说的"修饰名词"用法，逐个确认过的可豁免）
grep -rc "已定案" --include="*.md" vision systems art ux content decisions requirements | grep -v ":0"

# 过程档案不应被动过
git diff --stat -- handoffs/ inbox/ answer-logs/ open-questions/ open-questions.md   # 应为空
```

人工复核：随机抽 5 处改动，确认删戳后句子仍通顺、语义未变。

## 不要做

- **不改任何设计取值。** 本批是纯文本清理；发现数值可疑 → 记下来单独报告，不就地改。
- **不重排小节、不合并段落、不润色行文。** diff 应当只有删除，几乎没有新增。
- **不动 `Source:` 行**（那是批次二的事）。
- **不碰 `open-questions.md`**（那是批次三）。
