# 方案草稿 — 疲劳扣减是否进 `EncounterSpec` 覆写组

## 问题

`systems/balance.md` 的战斗规则数值表把 `FatiguePerDraw`（每张 1 点道念）定为**全局常量、刻意不进 `EncounterSpec` 覆写组**，并给了三条理由与三条重开判据。判据 ① 是「出现真的削减对手抽牌堆的内容条目」。

`ADR-0115` 的八原语落定后，`MoveCardEffect` 的 `From : CardZone` 可取 `DrawPile`，`EffectScope.Side` 可取 `Opponent` ⇒ **「削减对手抽牌堆」在结构上已可写**。`open-questions/01-combat.md`（08-27）据此认为判据 ① 触发，要求**重估那三条理由是否仍成立**；该条明写「本次不答定、未改任何数值」。

卡住的是：这一格开不开，决定 `EncounterSpec` 覆写组是四格还是五格、`EncounterTighten` 是五格还是六格（`ADR-0077` 明写五格封闭、新增一格须先回答「更紧在这一格上是什么方向」），以及内容侧「疲劳流」是否成为一条被承认的构筑方向。

## 约束（来自既有设计）

- **`FatiguePerDraw` = 全局常量，住 `CombatRulesData`**（`ISingletonContent`，经 `Content.Single<T>()` 取）→ `systems/balance.md`。
- **`EncounterSpec` 覆写组 = `InitialDraw` / `DrawPerTurn` / `HandLimit` / `EnemyManaLimit` 四格**，`null` = 取 `CombatRulesData` 默认值；形状权威在 `systems/services/combat-service.md`，取值权威在 `systems/balance.md`。
- **`EncounterTighten` = 五格带方向约束的增量**，字段面止于五格，准入判据两条连用，其中 ② 是「**该格上必须存在一个全序 + 一个单调难度方向**」；`Tier == Finale` 整档豁免 → `ADR-0077` · `systems/services/plot-manager.md`。`ADR-0077` 的备选方案里已明确否决过「加入疲劳量」。
- **疲劳量本身已可被内容侧调节**：`ModifierTarget.FatigueAmount`（`StaticModifierData` 五项之一）经求值管线聚合，`EffectScope.Side` 可取 `Opponent`；「免疫 / 削减疲劳」是它的立项样板 → `ADR-0088` · `systems/character-profile/deck/common-properties.md`。
- **对局终止性由 `EncounterSpec.TurnLimit` 独立封顶**，疲劳被削减到 0 也不影响终止 → `ADR-0088`。
- **一方一场的牌流入上界 = `InitialDraw` + `TurnLimit/2 × DrawPerTurn`**（`Standard` 档 4 + 5×2 = 14）；疲劳总量的天花板由这条抽牌预算决定，不由卡组规模决定 → `systems/balance.md`。
- **`ModifierTarget` 不收 `HandLimit` / `ManaLimit` / `TurnLimit`**，理由是「战斗内的静止式修正去改轮回级 / 物化期定稿的量会跨越已定的层级边界」→ `common-properties.md`。这条层级判据在本题上反向同样适用。
- **内容层现状：`game-design-documents/content/` 下零个内容条目**（只有两份模板与登记表），故不存在任何已签核的削堆条目。

## 建议方案

### 一、三条理由逐条重估（核心动作）

#### 理由 ① 触发窗口由卡组规模决定、不由档位决定 —— `[既有推演]` **仍成立（且被新事实加强）**

原文的承重点不是「只有卡组规模能决定触发窗口」，而是「**档位决定不了它**」——`Practice` 回合更短反而使疲劳更难触发，调这一格买不到覆写组想买的那个东西（更宽容的 `Practice`）。

削堆结构可写只是**再添一个内容侧的决定因素**（卡组规模、削堆条目），仍然**不是档位侧的**。理由 ① 因此不但没被削弱，反而更强：现在有两条内容侧通道决定触发窗口，档位侧仍是零条。

> 连带的一处反向咬合值得写进正文：`EncounterTighten.DrawPerTurnDelta` / `InitialDrawDelta` 恒 `<= 0`，**收紧牌流量的同时是在减轻疲劳压力**（抽得少 ⇒ 空堆后触发次数少）。若 `FatiguePerDraw` 也进 `Tighten`，一条 arc 就能同时朝两个方向拧同一条压力线，其净效果对内容作者不可预测。这是理由 ① 在增量形态下的具体化。

#### 理由 ② payoff 面很窄 —— `[既有推演]` **仍成立（该「新事实」本就写在这条理由里）**

`balance.md` 的原文逐字是：「`MoveCard` **虽能把对手抽牌堆的牌搬进别的区（闭集内流转，`From` 可取抽牌堆）**，但那是逐条内容、有限次、受载体消耗性约束的效果，撑不起一条需要用档位旋钮调节的『疲劳流』构筑方向」。

**⇒ 「结构上可写削堆」不是新事实**：写下理由 ② 时它已经成立、并已被计价。重开判据 ① 要的是「**出现真的削减对手抽牌堆的内容条目**」——是**已签核的条目**，不是**结构可写性**。而 `content/` 目前零条目、starter deck 未设计、关键字与次类型清单为空，判据 ① 在字面上**尚未触发**。

理由 ② 的实质护栏也未松动：载体消耗性纪律（法术结算即进弃牌堆 · 道具须有限充能 · 启动式异能有配额闸 · 静止式在结构上装不下原子操作，`ADR-0052` 边界条）使削堆恒为**有限次**，`MoveCardEffect.Count` 逐条有限且加载期 `>= 1` 校验。

#### 理由 ③ 量纲撑不起一条路线 —— `[既有推演]` **部分失效（结论不变，论据须改写）**

原论据是「即便对手从第 1 回合起就空堆，5 回合疲劳总量也只有 −10 上限」。削堆可写后，**「从第 1 回合起就空堆」从纯假想变成了内容侧真能逼近的状态**，故这句反证的修辞前提确实弱了——它原本靠「这种极端不会发生」取信。

但**天花板本身一格没动**：疲劳总量 ≤ 空堆后的剩余抽牌次数 ≤ `InitialDraw + TurnLimit/2 × DrawPerTurn`，这个上界由抽牌预算封死，而抽牌预算**已经在覆写组与 `Tighten` 里各有三格可调**。削堆只能让实际值更快逼近这个既有上界，**不能抬高上界**。

⇒ 建议把理由 ③ 从「极端不会发生」改写为「**上界由抽牌预算封死，而抽牌预算已被覆写组三格覆盖**」——同一个结论，换一条不依赖「极端不会发生」的论据。这是本次重估唯一需要改动 `balance.md` 正文的地方。

### 二、一条新的、独立于三条理由的否决论据 —— `[既有推演]`

即便三条理由全部失效，`FatiguePerDraw` 仍**过不了 `EncounterTighten` 的准入判据 ②**（全序 + **单调难度方向**）：

- **疲劳是对称规则，作用于「抽牌方」而非「玩家」。** 抬高 `FatiguePerDraw` 同时打双方，谁先空堆谁先挨打；先空堆的是**卡组更小的一方**。玩家侧卡组由构筑决定、敌人侧由 `EnemyData` 逐条编排 ⇒ **同一个正向 delta 对某些构筑是加压、对另一些是送礼**。难度方向不单调，「更紧」在这一格上没有定义。
- 这与 `ADR-0077` 否决 `Enemy` / `Tier` / `FirstSide` 三格**同一条判据、同一个失败模式**，只是失败在「单调」而非「全序」上。
- 顺带修正一处措辞：`ADR-0052` / `ADR-0077` 写的否决理由是「**无覆写基准可拧**」，这话在 `FatiguePerDraw` 已是 `CombatRulesData` 上一个具名常量之后**读起来是错的**（基准明明存在）。建议把两处的理由改写为「**方向不单调 + 层级边界**」，与本节口径一致。

### 三、建议结论：维持不进覆写组，且不新增 `Tighten` 第六格 —— `[既有推演]`

- `FatiguePerDraw` **保持为 `CombatRulesData` 全局常量**；`EncounterSpec` 覆写组**仍是四格**、`EncounterTighten` **仍是五格**（`ADR-0077` 的封闭性不被打开）。
- 本次**不改任何数值**（`FatiguePerDraw = 1` 不动）。

### 四、「遭遇级疲劳压力」并不缺旋钮：写明三条既有承接通道 —— `[既有推演]`

重开判据 ② 是「某个遭遇档需要显式调节疲劳压力」。建议在 `balance.md` 正文写明：这个需求**已有三条通道承接**，故它不构成开覆写格的理由。

| 想要的效果 | 既有通道 | 权威 |
|---|---|---|
| 让这一场更早 / 更晚触发疲劳 | 敌人侧 `EnemyData` 的卡组规模编排（规模即触发时点） | `ADR-0052` · `systems/enemies/` |
| 让这一场的疲劳更痛 / 免疫 | 内容侧 `StaticModifierData{ What = FatigueAmount, Scope.Side = Self\|Opponent }`，经求值管线聚合 | `ADR-0088` · `deck/common-properties.md` |
| 改变疲劳总量的天花板 | 覆写组的 `InitialDraw` / `DrawPerTurn`（连同 `Tighten` 的两格增量） | `combat-service.md` · `plot-manager.md` |

第二条尤其关键：它**已经是一个逐遭遇可编排的疲劳旋钮**（挂在敌人的卡 / `Power` 产出的战场条目上），只是承载面在**内容层**而非**遭遇参数层**——这正是本作既定的分工（难度差走 `baseMomentum` + 逐条编排的卡组，不走规则分叉，见 `balance.md`「接受敌人侧不做规则层差异化」）。

### 五、重开判据 ① 的措辞收紧 —— `[既有推演]`

现措辞「出现真的削减对手抽牌堆的内容条目」在**结构可写**与**条目已签核**之间留了歧义，本次重开正是被这处歧义触发的。建议改写为两句：

> ① **出现 `Pool` 覆盖敌人侧、以削减对手抽牌堆为主要效果的、已签核（`ready`）的内容条目，且其在同一抽取池内的密度足以让一方在 `TurnLimit` 的前 40% 内空堆。**
> （**结构可写性不构成触发**——`MoveCardEffect.From` 可取 `DrawPile` 自 `ADR-0115` 起即成立，理由 ② 已在此前提上写就。）

「前 40%」是一条**待实测的触发线占位**（`Standard` 档 = 前 4 个回合），旋钮位置与其余待校准初值同处：`systems/balance.md` 的战斗规则数值区，与「一张牌该产多少道念」同批校准。**不建议现在填死这个百分比**，它同样被那条量纲基准阻塞。

### 六、条件性预案：万一日后真要开这一格，它应该长什么样 —— `[通行做法]`

**本节不是本次建议，是给未来那次决策省一轮推演。** 若判据 ①（收紧后）或 ③ 真的触发：

- 形态取 **`EncounterSpec` 覆写组第五格 `int? FatiguePerDraw`**（`null` = 取 `CombatRulesData` 默认），**不取 `EncounterTighten` 第六格**——覆写组是「这一场就是这个值」，不承担方向语义，绕开了准入判据 ②；`Tighten` 那一格无论如何都过不了单调性。
- 取值域 `[0, FatiguePerDrawMax]`，越界 → 物化期钳制 + `PushWarning`（与 `Tighten` 越界那行同款严厉度）；`0` 是**合法值**（= 本场无疲劳），它与 `ADR-0088`「可被削减至 0」自洽，终止性仍由 `TurnLimit` 独立保证。
- `FatiguePerDrawMax` 是内容侧上界常量，住 `systems/balance.md` 的界常量组（与 `EncounterTighten` 六个界常量同批），**初值待实测**。
- 代价照记：每个消费点多一次 `?? ` 合并、「哪些字段可被 `EncounterSpec` 覆写」的记忆清单长一格、存档 `EncounterSpec` 多一格（`sealed record` 加一个可空 int，schema 需过一次版本）。

## 后果

- **本方案被采纳 ⇒ 该待答条目可从 `open-questions/01-combat.md` 移出**（重估已完成、结论为维持现状 + 判据收紧），不留待「内容扩充后的统计校准」那一批——收紧后的判据 ① 会在 starter deck / 敌人池成型时自然复查一次。
- `EncounterTighten` 的五格封闭性（`ADR-0077` 后果条「新增一格必须先回答『更紧在这一格上是什么方向』」）经此获得**一次实证**：疲劳量正是回答不了那个问题的第一个候选。建议把这一条写进 `balance.md` 而非 ADR，避免动 `Accepted` 的 ADR 正文（措辞纠正除外，见上表第 7 行）。
- 若取向项 A 选「限定只能下调」，`common-properties.md` 的加载期校验表需**加一行**（`What == FatigueAmount` 且 `Amount > 0`（`Additive`）/ `> 10000`（`Multiplicative`）→ `PushError`），这是本方案唯一可能产生的新校验。
- 不影响任何 UX 待答项；`open-questions/01-combat.md`「呈现的残留」里「疲劳扣减与被对手削减如何在飘字上区分」独立成立，本方案既不解决也不加重它。

## 备选方案（已考虑并否决）

- **`FatiguePerDraw` 进 `EncounterSpec` 覆写组（第五格）** — 否决：四条理由（触发窗口非档位决定 · payoff 面窄 · 上界已被抽牌预算三格覆盖 · 方向不单调）无一失效，且判据 ① 字面尚未触发（`content/` 零条目）。形态已写进第六节备查。
- **`EncounterTighten` 第六格 `FatiguePerDrawDelta`** — 否决：过不了准入判据 ②（无单调难度方向），且与既有两格牌流量 delta 反向咬合，净效果对内容作者不可预测。
- **给疲劳单开一个「敌人侧专用」的不对称覆写**（只抬敌人的疲劳量） — 否决：直接违反 `balance.md`「敌人侧不做规则层差异化」这条已接受的取舍，且它是玩家看不见的最不可读的一条旋钮。
- **恢复重洗以规避整个问题** — 否决：`ADR-0052` 已推翻（有重洗则疲劳永不可达）。
- **等到 starter deck 设计完再重估** — 否决：本条重开的触发物是**结构可写性**，那是一个此刻就能判定真假的命题（且答案是「它不是新事实」）；把它挂到统计校准那一批会让判据 ① 的歧义原样留到下一次。

## 与既有决策的张力

- **与 `ADR-0052` / `ADR-0077` 的张力仅在措辞层，不在结论层。** 两处都写「疲劳量无覆写基准可拧」，而 `FatiguePerDraw` 现已是 `CombatRulesData` 上的具名常量 ⇒ 基准存在，那句论据读起来是错的。本方案**不推翻两个 ADR 的决定**（结论完全一致），只建议把论据换成「方向不单调 + 层级边界」。**改 `Accepted` ADR 的正文须由用户点头**，且落笔归 `/analyze-new-ideas`；本草稿只提出。
- **与 `ADR-0088` 无张力。** 该 ADR 已把「疲劳量可被内容侧削减至 0」定死，本方案第四节把它正面认领为「遭遇级疲劳旋钮」，是对它的引用而非松动。

## 前置依赖

- **取向项 A（`FatigueAmount` 修正是否允许上调）若选「限定只能下调」**，其加载期校验行的落笔须与 `ADR-0115` 的校验表格式对齐；该表的权威在 `deck/common-properties.md`，本草稿不代写。

## 仍需用户决定

1. **内容侧 `ModifierTarget.FatigueAmount` 的修正是否允许「上调」（把对手的疲劳量拧大），还是限定为只能下调 / 免疫？**
   - 现状：`StaticModifierData.Amount` 是带符号 `int`，**结构上双向可写**；但 `common-properties.md` 给它立项的样板只写了「免疫 / 削减疲劳」一个方向，**方向约束从未被明写**。这是本题真正剩下的取向——它等价于问「**疲劳流（削堆 + 加重疲劳）是否是一条被承认的构筑方向**」。
