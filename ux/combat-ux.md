# combat-ux

> 战斗手感:出牌/拖拽/指定目标、节奏。**主视觉 = 双方道念对比**;**敌人意图按等级差三档呈现**(见下)。

## 意图

- **道念是战斗屏幕的主视觉(已定案)。** 胜负判据是**道念(momentum)高者胜**(见 `systems/scoring.md`),因此战斗屏幕的视觉重心是**双方道念的对比**——玩家任何时刻都应一眼看出「我现在领先还是落后、差多少」。**lifeTotal 退居次要**:它在战斗过程中不变化,只在结算时按道念差被扣减,故不需要战斗内的常驻血条式强调。具体形态(对比条 / 双数值 / 天平隐喻)待战斗 UX 专场。Source: `handoffs/2026-08-01-momentum-scoring-lifespan-tuning-and-failure-payoff.md`。
- **战斗是定长的 10 个回合,故进度可视(已定案的连带)。** 双方各 5 个回合、打满即比大小——**「还剩几回合」是一个必须呈现的信息**:它把「我落后 8 点、还剩 2 个回合」变成玩家可算的账,是限时积分对抗的紧张感来源。**起始道念按等级给**,故战斗一开场就可能呈现出一段明显的落差。呈现形态(回合计数器 / 进度条 / 双方轮次指示)待战斗 UX 专场。Source: `handoffs/2026-08-01b-abstraction-levels-combat-numbers-codex-family-and-monetization.md`。
- **敌人等级精确可见(已定案 · 答结「等级差是否可见」)。** 玩家**能**看到敌人的等级——**在 eventOptions 上就已精确标注**(见 `systems/services/future-event-service.md`),而非模糊的危险度档位(「同阶 / 略高 / 越阶 / 无从揣度」一类标签**否决**)。玩家自行与自身等级比对,由此**理解意图为何被遮蔽**;「越级挑战」也因此成为可主动选择的风险 / 回报维度。Source: 同上。
- **敌人意图三档呈现(已定案)。** 呈现档位由**全局等级序**上的「敌人 − 角色」等级差决定,**默认给完整意图,越级才降级**:

  | 情形（`diff` = 敌人全局等级 − 角色全局等级） | 呈现 |
  |---|---|
  | **越阶**（敌人境界更高） | **完全不呈现**,且**没有任何替代线索** —— 不论 `diff` 多小 |
  | 同阶 · 第一篇章、`diff ≤ −2` | **完整意图**:类别符号 + 综合数值 |
  | 同阶 · 第一篇章、`−1 ≤ diff ≤ +1` | **仅类别**:攻击 / 防御 / 增益 / 特殊——符号或剪影,**不带数值** |
  | 同阶 · 第一篇章、`diff ≥ +2` | **完全不呈现** |
  | 同阶 · 第二 / 第三篇章、`diff ≤ −1` | **完整意图** |
  | 同阶 · 第二 / 第三篇章、`diff = 0` | **仅类别** |
  | 同阶 · 第二 / 第三篇章、`diff ≥ +1` | **完全不呈现** |

  **「越阶 = 黑箱」是一道硬门**——它让境界鸿沟在呈现上成为一条明确界线,而不只是数值差的连续衰减;玩家在 eventOptions 上已看到敌人的精确等级,故这一遮蔽**有可解释的因**。**呈现层只认档位,不认档位的来源**:「这次为什么是完整意图」是规则层的事,不上浮到 UI——这与「越阶黑箱不给任何替代线索」是同一种克制,**硬门不自我声明**。服务侧与全局等级序见 `systems/services/combat-service.md`、`systems/game-progression.md`。Source: `handoffs/2026-08-02c-intent-threshold-inversion-and-aggregate-intent.md` + `handoffs/2026-08-06d-combat-open-questions-mass-closure.md`。
- **第二档「仅类别」是 ch1 的常态呈现,但这条判断只在 ch1 成立(已定案 · 承重 · 须重估)。** ch1 的第二档覆盖 `−1 ~ +1` 三格,是玩家看得最多的一档;**但 ch2 · ch3 的第二档收窄为 `diff = 0` 单一取值**,而黑箱门下移到 `+1` 后**约五分之二的同阶遭遇完全无信息**(再叠加境界末两级的越阶)。
  - **推论 ①:第二档视觉语言的承重级别按篇章重估** —— 它在 ch1 是核心可读性来源,在后两章退为窄档;**后两章的可读性压力全部转嫁给图鉴、卡面文本与道念主视觉**,沿既定纪律**不做意图侧补偿**。
  - **推论 ②:「碾压」重定义为「压到带内下界」**(ch1 `diff = −2` / ch2 · ch3 `−1`),完整意图仍是奖励而非基础信息,呈现上可以做得更「给」。**⚠ 已知风险:ch1 的 `diff = −2` 在炼气段只意味着领先 2 点 `baseMomentum`,玩家未必读得出「我碾压了所以拿到数值」这层因果**——属实测校准项。
  - **推论 ③:探查(probe)的入口值得在战斗屏留位置**。
  - **推论 ④:同级对局缺少可算的账是设计意图,不是缺口**——不为此另做补偿。
  - **推论 ⑤:轮回最初两级(角色全局等级 1 · 2)因带被截断而恒为「仅类别」**,这是开局的自然状态,不是死档。
  Source: 同上。
- **意图类别 = 四个符号,主类别并行陈列(已定案)。** 枚举为 `Offense / Defense / Buff / Special`(攻击 / 防御 / 增益 / 特殊),**贡献占比 ≥ 20% 的类别才进摘要**——这条阈值就是把符号数从最多 4 个压到通常 1~2 个的旋钮(竖屏窄边容不下四个)。
  - **完整档的数值只有一个数字位,靠符号区分**:主类别含 `Offense` → 显示**对玩家道念的预估净削减量**,负号(`−12`);不含 `Offense`(纯增益 / 防御回合)→ 显示**敌人道念的预估净增量**,正号(`+9`)。**不并列两个数。**
  - **埋伏与静止式异能不进意图区**(它们仍参与数值计算,只是不作为类别陈列)——埋伏标记必须与意图区**分开呈现**,否则玩家会把它当成本回合意图的一部分。
  Source: `handoffs/2026-08-06d-combat-open-questions-mass-closure.md`。
- **意图是回合级的综合描述,不是逐张预告(已定案 · 08-02c)。** 一个回合对手可以打出多张牌,故呈现的是**本回合的汇总**:**数值 = 计算后合并的最终结果**(一个结果值,例:削减 12),**类别 = 主类别并行陈列**(跨类别的一回合并列显示各主类别,不压缩成单一类别、不归入「特殊」),**不列张数、不做逐张分解**。**推论 ①:意图不是一串图标而是一条摘要**——不采用 Slay the Spire 式「一个敌人一个意图图标」的逐动作映射,也不排出牌序列;但**并行陈列意味着一条摘要里可能有 2~4 个类别符号**,布局须容得下(竖屏窄边尤其吃紧)。**推论 ②:呈现的数值是声明量,可能与实际结算不符**(下限 0 的饱和减法 + 触发入栈),UI 须容得下"意图说 12、实际掉 8"而不显得像 bug。Source: 同上。
- **意图只在玩家回合呈现,内容是敌人的下一个回合(已定案 · 08-02c)。** 敌人回合内**不呈现意图**——那时它正在出牌,呈现的是出牌本身。**推论 ①:意图是玩家回合内的常驻信息**,随回合归属切换而出现 / 消失,不是逐次出牌的飘字。**推论 ②:它是玩家出牌决策的依据**(「我该防多少 / 追多少」),故与道念对比、剩余回合数同属决策面板一组,应就近呈现。**推论 ③:敌人回合内意图区收起(已定案)** —— 该区域在敌方回合清空内容;**容器保留固定高度、内容整体清空,且该槽位在敌人回合复用为结算日志 ticker**(见下方「意图区收起后的布局」一节 —— 它明确修订了原先「不换成其他指示」那一句)。**布局必须扛得住这块区域的出现 / 消失**,竖屏下绝不能因此让道念对比、手牌区整体跳位。Source: 同上。
- **意图即快照:公布后不重算,但不保证与执行一致(已定案 · 08-02c 立、08-04b 修正措辞 · 承重)。** 玩家在行动阶段做什么都不改写已公布的意图,**屏上的意图数字在整个玩家回合内不跳动**;但**敌人回合的实际执行按执行时的真实局面求值**,与快照可能有偏差。**推论 ①:UI 无需表达"意图已变更"这一状态**(没有重算就没有刷新动画 / 变更高亮)。**推论 ②(唯一的新增呈现硬要求):意图的呈现语气必须是「预估」而非「契约」** —— 措辞不给保证(不用「将会」这类断言式表述),完整意图档的综合数值宜有「预估」的视觉提示。**推论 ③:偏差发生时必须可解释** —— **敌人回合的执行过程需有逐步可见的反馈**(每一步的飘字 / 结算日志),否则玩家会把偏差读成 bug。**这是快照语义能被玩家接受的前提**,也是本条对呈现层唯一新增的硬要求。**推论 ④:呈现风险集中在完整意图档** —— 「仅类别」档(常态档)本就无数值,偏差在那一档几乎不可感知。Source: 同上 + `handoffs/2026-08-04b-mtg-loanwords-card-types-and-intent-snapshot.md`。
- **战斗屏再多两个可读对象:本场可用道具区与神通 / 法则条(已定案 · 08-04b)。** 卡牌不再只有一个来源区,呈现层要跟着补:
  - **本场可用道具区** —— 竖屏空间紧张且它不像手牌那样每回合变化,**建议默认收起为一个角标(显示可用道具数),点开为抽屉式面板**,不值得常驻占位。**措辞上不要在战斗语境里称它为「储物袋」**:储物袋是角色的容器(含大量战斗外道具),战斗里出现的只是它的一个筛选视图;**敌人没有储物袋却同样有道具**,也证明这两个概念必须分开。
  - **神通 / 法则条** —— 贴在己方战场区边缘的一排小图标。`Power` 因不可交互,**视觉权重应低于常规永久物**;**但带启动式异能的 `Power` 例外**,它需要一个可点击的启动入口。**详情须长按查看** —— `ui-input-rules.md` 禁止 hover-only 可供性。
  - **埋伏标记（08-05 由条件项升为必做项）** —— 对手场上「有一张埋伏」的指示(**只给计数,不给内容**);这是本作第一处**双向对称**的信息规则,玩家与 AI 读到的是同一层信息。**埋伏已定案进入敌人卡池**,故这块指示是必做的;且**埋伏不计入意图**,它在**玩家回合**触发而意图只描述敌人**自己回合**的行动——**呈现上二者必须分开**,埋伏标记不能挂进意图区,否则玩家会把它当作本回合意图的一部分。
  - **卡面须呈现类型标识** —— 五类卡牌(法术 / 阵法 / 道具 / 神通·法则 / 业障)靠**卡框色 + 类型角标**区分,**不用纯文字**:竖屏卡面横向空间紧,且「法术 / 法宝」等相邻中文名共用字根,只靠文字读不开。

  Source: `handoffs/2026-08-04b-mtg-loanwords-card-types-and-intent-snapshot.md`。
- **不做「敌人状态可读」的补偿(已否决)。** 「以蓄力 / 凝聚 / 破绽等显式状态标记替代意图」的方案**明确否决**:大幅越级就是彻底的信息黑箱,不给替代线索。Source: 同上。
- **探查(probe)是玩家主动买信息的通道。** 与被动的意图档位相对:玩家**付出代价换取当回合敌人意图**。方向与定名已成,**呈现形态(按钮 / 手势 / 常驻入口)与花费形式归卡牌与技能内容的横向扩展阶段,本阶段搁置**。「能力 / 道具授予窥视意图」即探查能力的授予形式。Source: 同上。
- **敌人图鉴给静态知识,不给动态情报。** 账号级敌人图鉴(`systems/player-profile/codex/`)记录「这个敌人**会做哪些事**」;它**不揭示本回合的具体意图**,因此不架空越级时的信息黑箱。**战斗内可直接查阅**(点按敌人立绘 → 半屏 bottom sheet,结算 / 选目标态禁用),见下。Source: 同上。
- **战后奖励面板是战斗流程的一屏(已定案 · 新增)。** 「获取奖励」属于战斗流程本身,故战斗结束后**在战斗流程内**呈现奖励:**强制部分自动计入**(无需玩家操作,例:`experiencePoint`),**可选部分由玩家从若干候选中择一**——形态**参照 Slay the Spire** 的战后奖励面板。**推论:这是战斗 UX 至今未有的一屏**,且它在返回结果之前,不是事件收口后的另一步。**奖励预先算定,选择不是决策点**——退出重进得到同一组选项,故 UI 不必表达"已存档"。具体形态(候选项呈现、强制项的提示方式、竖屏布局)待战斗 UX 专场。Source: `handoffs/2026-08-02-momentum-conversion-reward-structure-and-mtg-stack.md`。
- **回合不是交互式的:stack 保留、交互与优先权移除(已定案 · 承重 · 08-02b 收窄)。** 卡牌入栈后按 LIFO 结算,但**没有响应窗口、没有优先权传递**——**"我打完换你打"的简单交替成立**,理由是交互 / 优先权**拉长时长、决策点过多、复杂度高而深度收益小**。**推论 ①:不需要"轮到你响应"这套交互**(何时提示 / 如何 pass / 自动 pass / 超时),竖屏触控上最吃紧的那一环由此消失。**推论 ②:栈仍必须进入呈现层**——虽然玩家不再为"是否响应"读栈,但**触发式能力也入栈**,故栈深可以大于 1(见 `systems/character-profile/deck/`);玩家要看懂"现在有哪些东西在等待结算、以什么顺序",否则触发连锁不可读。**推论 ③:敌人的出牌仍要呈现**(敌人也持有卡组),但只在敌方回合内呈现,不再穿插进玩家回合。Source: `handoffs/2026-08-02b-stack-without-interaction-and-three-step-turn.md`。
- **回合的三步结构给了 UX 一条明确的时间轴(已定案 · 08-02b)。** **开始阶段**(归属方 mana 恢复至 `manaLimit` → 触发「回合开始时」→ 抽牌)→ **行动阶段**(唯一出牌阶段)→ **结束阶段**(触发「回合结束时」→ 清理回合内状态)。**三步是回合归属方的流程,双方不同时走。** **推论 ①:每回合有三个可被呈现的节拍**——mana 刷满、抽牌、以及结束阶段的触发 / 状态消散,动画节奏可依此编排,不必自创分段。**推论 ②:手牌上限需要在 UI 上可读**——上限是**任何时刻都不得超过**的硬约束(**没有弃牌机制**),故玩家必须能随时看出"我还能拿几张";满手时抽牌的表现要能被看见(见待决问题)。**推论 ③:"轮到谁"是一个必须常驻的指示**,它现在是回合归属权的唯一表达。具体形态待战斗 UX 专场。Source: 同上。
- **结算会在中途停下来问「指谁」(已定案 · 08-05 · 承重)。** 触发式异能在栈上若需要选择目标,**那次目标选择是玩家的一次真实输入,也是一个决策点**(见 `systems/services/combat-service.md`)。**推论 ①:结算动画不能是一段不可打断的过场**——它必须能在中途停住、进入一个可交互的选目标态,再继续弹栈。**推论 ②:选目标态需要明确的进入 / 退出信号**,否则玩家会以为战斗卡住了(尤其在连锁触发中,停顿点可能出现在玩家没有预期的时刻)。**推论 ③:这不是「响应窗口」,呈现上必须区分**——玩家此刻不是在决定"要不要插手",而是在补全一个已经在结算中的效果的参数;措辞与视觉都不该暗示这是一次可放弃的机会。**推论 ④:这一步会落存档**,而 UI **不必**为此表达"已存档"(与战后奖励面板同理)。Source: `handoffs/2026-08-05-level-band-stack-save-and-token-free-deck.md`。
- **战斗屏多了一个区:战场(battlefield)(已定案 · 08-03 · 承重)。** 场上**正在生效**的卡牌 / 持续状态 / 等待中的触发器落在 battlefield 上,与**栈**(等待结算的队列)是**两个不同的区**。**推论 ①:竖屏要容下三块**——战场 / 栈 / 手牌,再加上道念对比、回合计数与意图区,窄高屏的分区压力显著上升(具体排布待战斗 UX 专场)。**推论 ②:玩家须能区分"已经在生效"与"正在等待结算"**——二者混成一片就读不懂触发连锁。**推论 ③:回合内状态的消散有了可视对象**——结束阶段清理的是战场上标记为回合内的条目,动画有了明确的落点。Source: `handoffs/2026-08-03-battlefield-stack-hand-limit-and-power-item-naming.md`。
- **满手时抽牌的表现:牌抽不进(规则已定 · 08-03)。** 满手时抽牌**抽不进**(牌留在抽牌堆、本次抽牌无事发生),「加入手牌」类效果同理落空——**规则已定,剩下的只是表现形式**。**推论 ①:需要一个"没抽进"的可见反馈**,否则玩家会以为抽牌漏了或界面卡了;**推论 ②:手牌上限本身要常驻可读**(「我还能拿几张」),否则满手是个突然出现的意外;**推论 ③:不会有牌被弃掉或销毁的画面**——上限是纯上界,不产生弃牌堆流量,视觉上不该出现"牌被丢掉"的动作。Source: 同上。
- **道念差是玩家可直接换算的账(已定案的连带)。** 失败时 `lifeTotal` 的扣减量**就是道念差**(1:1),故战斗屏上的「我落后 8 点」同时就是「输了要掉 8 点 lifeTotal」——**这条 1:1 关系让主视觉的价值大增**:玩家不需要额外的教学就能读懂风险,也让「道念差是否显式呈现」这个问题的答案更倾向于「显式呈现」。Source: 同上。
- **回合数不是固定的 10(已定案的连带)。** 10 回合是 **Combat 档的标准值**;Practice / Finale 可改写回合数与胜负条件。**推论:「还剩几回合」的呈现必须由本场遭遇的配置驱动**,不能把 10 写死进 UI。Source: 同上。
- **敌人等级的展示措辞(已定案)。** **面向玩家一律用「境界名 + 层级」,全局序 1–22 不出现在任何 UI 上**(例:「筑基中期」「炼气十三层」)。
  - **理由(最强的一条):境界名让「越阶」自动可见** —— 越阶是意图黑箱的硬门,「筑基巅峰 vs 金丹初期」一眼就是跨境界,「17 vs 18」看不出来。既定要求玩家「理解意图为何被遮蔽」,**境界名让这个因果无需教学即可读出,全局序做不到**;全局序是内部比较刻度,不是玩家词汇。
  - **`EventOption` 的战斗类卡片上并列显示双方等级**(`我 · 筑基中期 ⟶ 敌 · 筑基后期`)——把比对成本降到零,而不是要求玩家记忆。
  - **战斗屏内敌人区常驻一行敌人境界名,但不并列玩家自身等级、不常驻**(玩家知道自己是谁;竖屏空间已是本作压力最大处),需要时在角色面板查看。
  - **不做方向标记**:`↑` / `=` / `↓` 一类由两个等级机械导出的符号**一律不加**——它同时把「日后被扩成三色 / 加文字 → 滑向模糊危险度档位」的风险从根上掐掉。任何主观危险度词汇(「略强」「凶险」「无从揣度」)照旧被否决。
  - **已知代价**:境界名不利于表达带内细微差(ch2 · ch3 只有四个层级名,`diff = ±1` 就是相邻两个词,玩家读得出差一档但读不出「差一档意味着 `baseMomentum` 差多少」),且比对成本回到玩家自己身上——**接受**,这正是「精确标注、不做主观解读」的直接体感。
  Source: `handoffs/2026-08-06d-combat-open-questions-mass-closure.md`。
- **选目标态的呈现形态(已定案)。**
  - **规则层先削掉一半的进入次数:合法目标集合大小为 1 时自动选定,不进入该态、不产生决策点、不落存档。** 这条**一并缓解三个问题**(连锁打断次数 / 决策点密度 / 操作疲劳),是本节最有价值的一条,**且它是规则层的、不只是呈现层的**。(合法目标为 0 时按既定的效果落空规则处理,同样不进入。)
  - **进入信号** = 全屏低透明度**暗幕**(≈45%)0.15 s 淡入,压暗一切非决策必需元素;**道念对比条与栈区豁免不压暗**——前者是判断「该指谁」的依据,后者是「队列里还剩什么」的唯一来源。**暗幕因此是「压暗除决策必需信息外的一切」,不是字面的全屏。**
  - **来源指示**:栈上的该条目**上浮 + 放大 1.1× + 描边**,一条引导线连向指令条——**连锁中玩家必须知道「是谁在问」**,否则第三次弹出时完全失去上下文。**指令条位置绝对固定**(屏幕中部偏上,道念对比条与栈之间),每次进入同一位置、同一套视觉:**节奏可预期 = 不迷失**。
  - **合法目标**不被压暗 + **描边呼吸动画**(1.2 s 周期,静态描边在小屏易被忽略);**非法目标随暗幕压暗、点击无反馈**——压暗即答案,**不做「点非法目标弹提示」**(连锁中反复弹提示是噪音)。退出总时长 ≤ 0.4 s。
  - **指向手势 = 单点即确认**,不用拖拽连线:拖拽要求精确的起点落位与长路径,而起点(栈条目)在屏幕中上部、终点可能在顶部敌方区或底部手牌,**竖屏单手拇指跨不过去**;连锁中可能连续进入 2–4 次,**任何多余的操作都要乘以次数**。**也不做二次确认**——误触代价用「目标足够大 + 呼吸描边足够醒目」化解,而不是用二次确认换(那把每次操作翻倍)。**误触不做保护**(与「玩家主动退出静默处理」的手感取向同向);**已知代价**:一次误触在连锁中可能改变结算结果,且该步已落存档、退出重进也回到误触之后。**退让位**:若实测误触率高,退到「点选 + 确认键」,且只在合法目标 ≥ 4 个时启用。
  - **连锁中不迷失的四条**:① **连锁进度可见** —— 指令条第二行常驻 **`还有 N 项待结算`**(= 栈深,**永远可算**;不用「还有 N 项待选」——后者要求预知后续条目是否需要目标,而那依赖前面的结算结果,未必可精确预知)。**这是把「不可预期的停顿」变成「有限的、可数的停顿」,是四条里最关键的一项。** ② 位置绝对固定。③ **连续两次之间不完全淡出暗幕**(只交叉淡变来源高亮与文案,0.2 s)——避免全屏明暗闪烁,同时让「这是一段连续结算」在视觉上成立。④ **栈区保持可见且不被压暗**。
  - **措辞与「响应窗口」严格区分(三条禁令)**:文案用「选择一个目标」「指定」,**不用**「是否响应 / 跳过 / pass / 等待你的回应」;控件上**无取消键、无跳过键、无「不使用」**;**无倒计时、无超时自动选**(倒计时暗示「不选也会过去」,与「不可放弃」矛盾)。
  - **硬要求:选目标态必须自解释。** 玩家可能退出后隔几小时回来,正对着一个「请选择目标」的界面——呈现层必须交代**是哪张牌 / 哪个异能在要求选目标、它要做什么**,**不能依赖玩家的短期记忆**。恢复语义(回到该选择点、栈原样挂起、不允许反悔)见 `systems/services/combat-service.md`。
  - **道具使用后若需目标,直接进入这同一套形态,不另做一套。**
  Source: `handoffs/2026-08-06d-combat-open-questions-mass-closure.md`。
- **快照与执行偏差的呈现形态(已定案)。**
  - **「预估」的视觉提示 = `≈` 前置 + 数值下方短虚线底纹**。`≈` 一个字符、跨文化通用、零本地化成本、竖屏最省空间;虚线提供**非文字的第二重冗余**(小屏 / 低视力 / 色觉差异下 `≈` 可能读不清,虚线是形状线索、不依赖颜色)。括注「(预估)」**否决**(竖屏窄边放不下且要本地化);整体淡化**否决**(与「不可用 / 已失效」的通用语义冲突,会被误读)。**首次出现完整意图档时给一条一次性教学提示**(「意图是预估,实战可能有出入」),此后不再打扰。
  - **逐步反馈 = 飘字为主 + 一条日志 ticker 为辅,两者都要**:飘字**注意力跟随对象**(敌人打出牌 → 牌面飞出 + 道念条上 `+5`;玩家侧被削减 → `−3`),不需要阅读但转瞬即逝;ticker 可回看。**ticker 默认显示最近一行**,点按展开本回合完整日志(半屏,可上滑)——**藏在按钮后等于取消了「偏差必须可解释」这条硬要求**(玩家不会主动开日志)。**一条 ticker 同时解决「栈与战场的连锁可读性」那条待答。**
  - **偏差时的对照标记(最关键的一项)**:实际结算值与已公布意图值不一致时,在**最终道念结算那一步**给出——飘字 `≈12 → 8`(划掉预估值,给出实际值)、ticker `预估 ≈12,实际 8(你的「明镜台」减免 4)`。**把偏差本身变成一次明确的说明,而不是让玩家自己对账**:光有「逐步可见」还不够,玩家还得能把那些步骤加总回意图数字。**这是「偏差不做处理」这条定案能被玩家接受的实际前提。** 它对服务层的要求是:**意图声明值与实际结算值都要拿得到且能配对**(由 `PlayResult.MomentumDelta` 的 `Declared` / `Actual` 承载)。
  - **节奏**:单个敌人回合演出**总时长 ≤ 4 s**(一场合计 ≤ 20 s;若每回合演出 8 秒,一场就是 40 秒纯观看,在 30–40 分钟篇章预算下不可接受)· 单步节拍 **0.35–0.5 s** · **超过 4 步后压到 0.2 s** 并**合并同来源、同类型、同符号的连续增量**(跨来源不合并——跨来源正是玩家需要区分的)· 点按屏幕任意处 **3× 加速**(**只能加速不能跳过**,「逐步可见」是硬要求)· 永久快速演出为设置项(默认关,开启后基线节拍 0.2 s)。
  - **偏差对照那一步额外停 0.4 s,且加速对这一步无效**——**偏差是唯一必须被看到的时刻**,让它成为演出中唯一不可跳过的节拍,是把「可解释性」这条硬要求钉死的最小代价。已知代价:快速演出的玩家会在偏差处感到「卡了一下」,有意接受。

- **意图区收起后的布局:固定预留高度 + 敌人回合复用为结算日志 ticker(已定案 · 承重 · 修订既有措辞)。**
  - **先化解一处表面矛盾**:「不留占位、不换成其他指示」与「布局必须扛得住这块区域的出现 / 消失」并不冲突,**只要区分「占位符」与「预留高度」**——**容器保留固定高度,内容整体清空**:视觉上该区域是**空的**(没有占位符、灰框、「敌方行动中」字样),但容器高度不变、邻居不移动。工程形态 = `custom_minimum_size.y` 固定的 `Control`,收起时其**子节点**整体淡出,**容器本身不参与布局变化 ⇒ 动画不触发 `Container` 重排**。
