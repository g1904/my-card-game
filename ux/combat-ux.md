# combat-ux

> 战斗手感:出牌/拖拽/指定目标、节奏。**主视觉 = 双方道念对比**;**敌人的行动不作事前预告**,可读性由敌人回合的逐步执行呈现承担(见下)。

## 意图

- **道念是战斗屏幕的主视觉。** 胜负判据是**道念(momentum)高者胜**(见 `systems/scoring.md`),因此战斗屏幕的视觉重心是**双方道念的对比**——玩家任何时刻都应一眼看出「我现在领先还是落后、差多少」。**寿元不进战斗屏**:它在战斗过程中既不被读也不被写,只在收口时刻按道念差被扣减,故不做战斗内的常驻血条式强调。形态 = **横贯屏幕的一条对峙条**(单条双向、中点为分界),两端各挂头像与数值,详见下方「竖屏分区」。
- **道念显示位:双方各随其头像（承重）。** 道念对比条横贯屏幕,**双方的头像与数值分居其两端**——对比条与头像位不互斥,两者同时成立,合称**双方道念位**。**玩家侧因此有一个头像位**(战斗屏此前只写了敌人立绘):它只作道念的锚点,**不承担任何图鉴入口**,也不并列玩家自身等级。本文件中以「道念对比条」为基准的布局纪律,凡涉及压暗豁免与压缩顺序处,指的都是这一整组。
- **战斗是定长的 10 个回合,故进度可视。** 双方各 5 个回合、打满即比大小——**「还剩几回合」是一个必须呈现的信息**:它把「我落后 8 点、还剩 2 个回合」变成玩家可算的账,是限时积分对抗的紧张感来源。**起始道念按等级给**,故战斗一开场就可能呈现出一段明显的落差。呈现形态 = **`TurnLimit` 个小格的一排点 + 并列文字「第 `TurnIndex` / `TurnLimit` 回合」**,详见下方「竖屏分区」。
- **敌人等级精确可见(答结「等级差是否可见」)。** 玩家**能**看到敌人的等级——**在 eventOptions 上就已精确标注**(见 `systems/services/future-event-service.md`),而非模糊的危险度档位(「同阶 / 略高 / 越阶 / 无从揣度」一类标签**否决**)。**承重理由:看到等级即看到起跑线**——等级 → `baseMomentum` → 开局领先 / 落后量,故标注的等级**就是这场遭遇的难度刻度**;「越级挑战」也因此成为可主动选择的风险 / 回报维度。
- **敌人的行动不作任何事前预告（承重）。** **意图区、三档呈现、类别符号体系、综合数值、「预估」视觉提示与偏差对照,全部从战斗屏移除。** 玩家在自己回合看不到敌人下一回合要做什么;可读性改由**事中呈现**承担(见下一条)。规则侧权威见 `systems/adventure-event/combat/_index.md`「敌人回合的可读性」。
  - **推论 ①:战斗屏少一个区**,释放约屏高 8%,且**少一个随回合归属切换而出现 / 消失的区域**——一场约 20 次的收起 / 展开动画整条消失,布局跳位的风险源随之减少一个。
  - **推论 ②:玩家回合的决策面收敛为「道念对比 + 剩余回合数 + 战场 + 埋伏计数」**。「我落后 8 点、还剩 2 个回合」这本账仍然可算,只是账里没有「它下回合要打 12」这一项。
  - **推论 ③:探查(probe)的入口不再需要在战斗屏留位置**。
  - **已知代价(明写接受):** 本作已移除交互与优先权,故敌人回合对玩家而言是**信息与交互双零**的一段观看。这正是下一条把逐步呈现升为硬要求的原因。
- **敌人回合的逐步执行呈现是硬要求（承重）。** **敌人回合是玩家获取动态情报的唯一时刻**——看不清就完全不可读:
  - **飘字为主 + 战报为辅,两者都要**:飘字**注意力跟随对象**(敌人打出牌 → 牌面飞出 + 道念条上 `+5`;玩家侧被削减 → `−3`),不需要阅读但转瞬即逝;战报可回看。**战报的收起态必须常驻可见**——藏在按钮后等于取消这条硬要求(玩家不会主动开日志)。形态见下「战报」条。
  - **截断量必须被说明**:一次结算的效果标称量与实际量不等时(道念下限 0 的饱和减法),战报给出「削减 8(对方仅剩 5,溢出 3 未结转)」。数据由呈现事件流每条自带的 `Declared` / `Actual` 一对承载——**`Declared` 是效果的标称量、`Actual` 是实际生效量**,契约见 `systems/services/combat-service.md`。
  - **目标落空(fizzle)必须被说明**:结算时逐槽位重检,已选定的目标可能已被拆掉。**部分槽位落空 → 战报写明是哪一半没生效;全部槽位落空 → 战报明写「目标已不存在」**,而不是让玩家看到一张牌打出去后什么也没发生。规则侧见 `systems/services/combat-service.md`。
- **结算呈现 = 逐层弹栈 + 短暂强调,不做滚动播报流（承重）。** 结算时先显示栈上的卡牌 / 效果,再**逐层 LIFO 弹出**,每弹一层做一次短暂的视觉强调,弹完即落账——因果顺序因此保持可见,而不是把一串结果冲刷进一条滚动播报里。
  - **「不可暂停」读作「无玩家侧的暂停 / 跳过控件」。** 结算中途停下来问「指谁」是规则层的停顿 + 玩家的一次真实输入(见下「结算会在中途停下来问『指谁』」),不是暂停;演出可以在那里挂起、再继续弹栈。
- **结算演出的节奏(双方回合通用)。** 单步节拍 **0.35–0.5 s** · **超过 4 步后压到 0.2 s** 并**合并同来源、同类型、同符号的连续增量**(跨来源不合并——跨来源正是玩家需要区分的)· 点按屏幕任意处 **3× 加速**(**只能加速不能跳过**,「逐步可见」是硬要求)· 永久快速演出为设置项(默认关,开启后基线节拍 0.2 s)。**演出中没有不可跳过的节拍**——不设「某一步额外停顿且加速无效」一类的强制停留,加速手势在任何一步都生效。
  - **总时长的硬上界只约束敌人回合**:单个敌人回合演出**总时长 ≤ 4 s**(一场合计 ≤ 20 s;若每回合演出 8 秒,一场就是 40 秒纯观看,在 45–55 分钟篇章预算下不可接受)。**该上界针对的是玩家完全无交互的整段观看**,故不对称适用于玩家回合:玩家回合的演出是玩家自己出牌的结果、有心理预期,加速手势也就在手边,**不设总时长上界**,由上面三重护栏次线性收敛。给玩家回合也设死上界,会在栈深大时撞上天花板而只剩「跳步」一条出路,与「逐步可见是硬要求」直接相抵。
- **战报(`combatLog`):收起态与展开态是同一份数据的两个视图（承重）。** 战报记的是**已经弹出、已经落账**的东西,与**栈**(等待结算的队列)是两个对象。**竖屏净增 0 个区**——收起 / 展开共用同一格。
  - **收起态(常驻)** = 固定预留高度的**单行**,显示最新一条条目。**双方回合都常驻有内容**:玩家回合里是自己打出的牌与它引发的触发链。
  - **展开态** = 点按升起的半屏面板(可上滑),内容是**本场**战报的**因果树**:按**一次结算批次**分组并缩进——一次出牌与它引发的整条触发连锁归为一组;整体**按回合分组**,默认定位到最新一条。

    ```
    第 3 回合 · 我方
      打出「叠嶂符」
        └ 触发「山岳共鸣」      对方道念 −5
        └ 削减 8(对方仅剩 5,溢出 3 未结转)
    第 3 回合 · 敌方
      打出「回风诀」
        └ 目标已不存在(未生效)
    ```

    **因果树是「栈与战场的连锁可读性」的承担者**:玩家读不懂触发连锁,是因为看不到「谁引发了谁」,而扁平列表给不出这一层。因果关系由栈条目**既有的来源引用**承载,字段面权威见 `systems/services/combat-service.md`——UX 侧不新造字段名。
  - **条目粒度 = 结算事件,不是卡牌**:卡牌结算、触发式异能、疲劳扣减各占一条,保证「我的道念为什么少了 3」有账可查。
  - **保留本场全部条目,不设条数上限。** 战报不落存档,故上限省的是内存而非存档体积;一场 `Standard` 是 10 个回合,量级不过几十条结构化条目。设上限恰好废掉战报自己的理由——「第 3 回合我的道念为什么少了 3」正是要翻回去才答得出的问题。
  - **不进战斗存档。** 退出重进后战报从空开始,**代价明写接受**:「选目标态必须自解释」这条硬要求的承担者是**选目标态的指令条**,它本就不依赖战报。依据既有先例「为一条呈现便利新增一个存档字段不划算」,以及 `ActiveCombat` 的量级护栏与「本块新增的字段只有一格」的克制取向。
  - **展开态在结算态可开,在选目标态禁用。** 结算态玩家无输入,展开态可随时开且**演出不停、不设暂停控件**,列表照常流式追加新条目。选目标态则**只保留收起态单行、禁用展开入口**:展开态是半屏面板,会压住栈层与部分合法目标,而「选目标态期间栈层必然在场且豁免压暗」「合法目标不被压暗」「暗幕只压暗决策必需信息之外的一切」三条是承重;叠加「单点即确认、不做二次确认、误触不做保护、该步已落存档」,遮挡会直接抬高误触率。
    - **判据一句话:禁用与否看的是「是否与决策面争抢屏幕或语义」。** 随身抽屉一类可能改变局面的入口争的是**语义**(点按语义与选目标态相撞);战报展开态争的是**屏幕**。**纯只读不是豁免理由。** 这是有判据的分化,不是漂移。
  - **三个消费者读同一条呈现事件流**:飘字 · 收起态单行 · 展开态因果树。三处各自去结算返回值里捞增量,迟早不一致;负载形状(类别、侧别、来源引用、增量值)的权威在 `systems/services/combat-service.md`,UX 侧不复述字段面。
  - **条目存结构化数据,渲染期才套 `res://text/` 翻译键**,不存已格式化的字符串——否则战报会成为本作最大的一处文案字面量泄漏源,且热路径上多出 `string` 拼接。
  - **占用固定预留高度(承重)。** 容器保留固定高度、内容变化不改变高度:工程形态 = `custom_minimum_size.y` 固定的 `Control`,变化的是其**子节点**(淡入 / 淡出),**容器本身不参与布局变化 ⇒ 动画不触发 `Container` 重排**。**这条纪律防的是「手牌区跳位干扰拖拽出牌的肌肉记忆」,与战报归属哪一方的回合无关**,且正是「拖出手牌区 = 打出」所依赖的。
  - **「元素上移(回收空间)」排除**:每回合两次重排,手牌区跳位已被明确点名为不可接受。
  - **落位与尺寸**:紧贴道念对比条(与道念对比、剩余回合数同属决策面板一组);尺寸 **≈ 屏高 6%** 为初值(单行文字),**写成百分比 / `SizeFlags` 比例而非像素常量**(`stretch/mode = canvas_items` + `aspect = expand` 下像素常量无意义)。**单行,永不换行**(换行会引起高度变化,与固定高度矛盾),超长文本省略并由展开态承载。
  - **动画**:本场第一条到达时淡入 **0.20 s**、战斗结束时淡出 **0.15 s**,**无高度动画**——这正是固定预留的收益。
  - **若实测排不下的压缩顺序**:先压敌方区(立绘可缩)→ 再压敌 / 我战场带 → 再压底部条;**手牌区与双方道念位不参与压缩**——前者是屏内唯一承载拖拽的区,缩小会直接抬高「拖出手牌区 = 打出」的误判率,后者是主视觉与核心决策面。**栈本就是结算期浮层,不占常驻预算,故不在压缩链上**(见下方「竖屏分区」)。
  - **不上提为跨事件类型的 `eventLog`(边界)。** 战报只属于 Combat,**不外延到 Exchange / Research / Explore / Travel**。三条理由:
    - **会制造第二权威。** `PastEventEntry`(`SelectCost` / `AppliedChange` / `EventOutcome` / `Unchosen`)已经是「一个事件里发生了什么」的事实来源,且已被剧本调制、履历、诊断三方消费。再立一份「记录事件中有意义的决策」的日志 = 同一批事实的第二份表,两份各自漂移而无机制发现。
    - **非战斗事件没有可记的时间轴。** 其余四类都是单决策点事件(择一 → 结算 → 收口一次 `TryApply`)。战报存在的两条前提——**LIFO 栈使因果链长于 1**、**敌人不作事前预告故事中呈现是唯一情报通道**——一条都不外延。
    - **非战斗事件里唯一「值得记」的东西恰好必须隐藏。** 玩家自己选了什么他知道;他不知道的是道心 / 煞气被推了多少、剧本被怎么调制——而那正是「给方向不给数字、调制是隐藏属性的主要显影通道」所要遮住的(见 `systems/adventure-event/plot-manager.md`)。诚实的 `eventLog` 会掀开这层;不诚实的只剩「你选了 A」这种零信息条目。
    > **一句话纪律:一个权威、两种寿命——事件内的过程态是纯呈现层、不落存档(战报);事件间的账目归 `PastEventEntry`、落存档。**
- **战斗屏再多两个可读对象:本场可用道具区与神通 / 法则条。** 卡牌不再只有一个来源区,呈现层要跟着补:
  - **本场可用道具区** —— 竖屏空间紧张且它不像手牌那样每回合变化,**建议默认收起为一个角标(显示可用道具数),点开为抽屉式面板**,不值得常驻占位。**措辞上不要在战斗语境里称它为「储物袋」**:储物袋是元界面里的持有物全量视图(含大量战斗外道具),战斗里出现的只是它的一个筛选视图;**敌人没有储物袋却同样有道具**,也证明这两个概念必须分开。该区**同时呈现两级持有物**(轮回级法宝 + 账号级古宝),条目上带 `AbilityScope` 标识来源——两级的规则面权威见 `systems/player-profile/player-item/_index.md`,UX 侧不复述。
  - **神通 / 法则条** —— 贴在己方战场区边缘的一排小图标。`Power` 因不可交互,**视觉权重应低于常规永久物**。**详情须长按查看** —— `ui-input-rules.md` 禁止 hover-only 可供性。**启动式异能的启动入口落在长按升起的那个弹层内**(bottom sheet,复用既有控件语言),**图标条本体保持纯只读**——详情与启动键合一,同一排图标上不并存两种手势;可发现性由图标上一个**静态启动可供性标记**补偿(形状见下方「叠加元素与二级面板」)。**只读层不列被禁用的神通 / 法则**——被禁用者根本不入场,见 `systems/character-profile/power/_index.md`。
  - **埋伏标记（必做项）** —— 对手场上「有一张埋伏」的指示(**只给计数,不给内容**);**双向对称**,玩家与 AI 读到的是同一层信息。**埋伏进入敌人卡池**,故这块指示是必做的。它**挂在战场区**(埋伏是面朝下的战场条目),不与战报混住——一个是「场上有什么」,一个是「刚刚发生了什么」。
  - **卡面须呈现类型标识(适用于会以卡面出现的类型)** —— 五类卡牌(法术 / 阵法 / 道具 / 神通·法则 / 业障)靠**卡框色 + 类型角标**区分,**不用纯文字**:竖屏卡面横向空间紧,且「法术 / 法宝」等相邻中文名共用字根,只靠文字读不开。
- **战斗内持有物面板按「可操作 / 只读」分两层。** 战斗内需要被查看或使用的持有物有四种(法宝 / 古宝 / 神通 / 法则),它们按**能否被操作**归两层,而不是按数据归属分:
  - **可操作层 = 随身**(角标 + 底部抽屉):按 `UsableScene` 筛出的本场可用道具,可直接使用;抽屉内同时呈现两级并带 `AbilityScope` 标识。派生规则 = 按 `UsableScene` 筛 + 一条禁用过滤,权威见 `systems/character-profile/item/_index.md` 与 `systems/services/combat-service.md`。
  - **只读层 = 神通 / 法则**:本身不承载操作,长按查看详情;启动式 `Power` 的启动键落在该弹层内。
    - **启动键的灰态与长按原因由服务算好交给 UI,呈现层不自行重演规则**——每条启动式异能的费用、本场剩余次数、能否启动与不能启动的原因,取自 `CombatSnapshot` 中该战场条目上的 `ActivatableAbilities`,字段面权威在 `systems/services/combat-service.md`,UX 侧不复述。**启动被拒时不弹 toast**:`Accepted == false` 时只回到原态,解释由灰态 + 长按承担——与选目标态「不做『点非法目标弹提示』」同一条纪律。拒绝文案走 `COMBAT_` 分区普通键(本地业务拒绝无后端 `code`,**不占 `ERR_` 前缀**),见 `ux/error-and-blocking-ux.md`。
  - **弹层与随身抽屉同规格禁用**(敌人回合 / 结算中 / 选目标态禁用入口)。依据上面那条判据「禁用与否看的是「是否与决策面争抢屏幕或语义」」:启动键争**语义**(它可能改变局面),半屏弹层争**屏幕**(压住栈层与合法目标),两种争抢都构成禁用理由,故不为它另立一套规格。
  - **功法与货币不进战斗 HUD。** 功法在参战方组装时已展开为卡牌、战斗内不感知功法(见 `systems/character-profile/deck/_index.md`);货币在战斗内无用途,灵石与仙玉的非战斗查看落点见 `ux/screen-flow.md`。
  - **卡组构成查询不在此收口**:不为它单开面板,复用抽牌堆信息面——抽牌堆在底部条有一个固定实体,即该信息面的宿主(见下方「竖屏分区」)。
  - **只读层的形状 = 单行图标条 + `+N` 溢出聚合格**,形态与容量见下方「叠加元素与二级面板」;本条只定分层原则。
  - **边界:启动式异能不是只读层专属。** 本条的两层划分只覆盖**持有物**(法宝 / 古宝 / 神通 / 法则);启动式异能按**载体**归类,阵法作为战场条目是它的第三个落点,宿主见下条。
- **启动式异能在阵法(`Enchantment`)上的宿主 = 战场区内该条目自身（承重）。** 启动式异能不是 `Power` 专属:阵法作为留场永久物同样可挂,而服务按**战场条目 id** 寻址、灰态预判逐条目填充,故宿主与数据同构时零映射成本。**零新增区、零新增常驻部件**——不单开「启动式异能条」,也不并进随身抽屉(随身是按 `UsableScene` 筛出的**道具**视图,阵法不是道具,`Use` 与 `Activate` 是两条来源路径)。
  - **交互链 = 长按条目 → bottom sheet →「详情 + 启动」合一。** 与 `Power` 那一半逐字同构:详情与启动键合一,同一对象上不并存两种手势;弹层复用既有 bottom sheet 控件语言。**启动键必须在弹层内、不直接挂在条目上**——竖屏战场条目塞不下满足最小触控目标尺寸的按钮,而启动扣 mana、占掉行动阶段的一个动作位、不可撤销、不做二次确认,弹层这一步正是唯一的误触门槛。**详情区的内容清单与排布沿用卡牌详情页那一份**(见待决问题),本条只定「启动区是该弹层多出来的一节」。
  - **启动区 = 逐行列表,每行逐字映射服务算好的那一格**:异能名(`LocalizedText`)· 费用(与手牌卡面 `manaCost` 同一套 mana 符号)· 剩余次数(**不限次时整格不渲染**,不显示空槽)· 启动键(不可启动时灰态,**长按灰态启动键给原因**)。数据源与灰态判定的字段面权威在 `systems/services/combat-service.md`,**UX 侧不复述**;呈现层不自行重演窗口 / mana / 配额三条规则。逐行而非单键的理由:一个条目挂多条启动式异能是常态(本场配额按**每载体条目**计,同一条异能挂两个条目即两份独立计数);行数极少,弹层内不需要滚动分页。
  - **启动被拒时不弹 toast**,只回到原态(弹层保持打开、不关闭、不提示)——与选目标态「不做『点非法目标弹提示』」同一条纪律。拒绝文案走 `COMBAT_` 分区普通键,**不占 `ERR_` 前缀**。**启动键的动词用「启动」不用「使用」**:`Use` 已被道具占用,两条来源路径在契约面已分开,UI 措辞跟着分。
  - **可发现性 = 条目上的静态启动可供性标记,与 `Power` 侧共用同一套。** 两者是同一条 API 的两个载体,标记分叉会让玩家学两遍。标记**带两态**:常态 =「此条目有启动式异能」,强调态 =「此刻至少有一条可启动」——后者服务已经算好,不显示等于逼玩家每回合逐个长按去查够不够 mana。**形状 = 图标 / 条目角上一枚不超过其 20% 面积的小标记**(落在与两级角标不争位的另一角);若实测两态在小尺寸下辨不开,退回单态是现成的退让位。
  - **需目标的启动:弹层先收起,再进入既有选目标态。** 半屏面板会压住栈层与合法目标,而「选目标态期间栈层必然在场且豁免压暗」「合法目标不被压暗」是承重。收起后按 `slotIndex` 顺序逐个问、**一次收齐**(玩家主动发起的动作,槽位在发起前收齐),指令条按同一顺序点名各槽位类别;合法目标集合大小为 1 时自动选定、不进入该态。**来源指示**由该阵法条目的上浮 + 放大 + 描边承担,与栈条目发起时同一套视觉,**不新增部件**。
  - **己方面朝下条目(埋伏)照常有启动入口;对手侧的面朝下条目不进入战斗态视图。** `faceDown` 隐藏的是**对手视角**的内容,而灰态预判只对己方条目填充;不给己方埋伏宿主,服务在这一格算出的可启动性将永无消费者。对手侧的面朝下条目在契约面已被整条剔除(不是「在列表里但不渲染」),呈现层拿不到它们,只汇总进埋伏计数——填充纪律与不变式的权威在 `systems/services/combat-service.md`,UX 侧不复述字段面。**己方埋伏在战场区逐条渲染、不折叠**——折叠后没有可寻址的战场条目宿主,启动入口即失去落点(形态见下方「叠加元素与二级面板」)。
  - **敌方阵法不渲染任何启动可供性**(标记与启动区皆无):对侧列表恒为空,敌人启动走 EnemyManager 内部路径、不经本 API;渲染它既无消费者,又是一条信息泄漏面。敌方启动的可观测性由飘字与战报承担。
  - **入口的禁用规格与 `Power` 弹层 / 随身抽屉完全同规格**(敌人回合 / 结算中 / 选目标态禁用入口,标记同步置灰)。**弹层是否只读不影响该判定**——半屏弹层争的是屏幕。选目标态下战场条目的点按 = 指定目标(该态已定「单点即确认」),该态一并禁用详情入口。**已知代价(明写接受):敌人回合与结算中无法查阅战场阵法的规则文字**;这两段的可读性由飘字与战报因果树承担(战报展开态在结算态可开)。
- **神通 / 法则的呈现气质是技能感,不是卡牌感。** 参照武将技能栏——被动常驻、身份绑定、少而精;UI 上它们**不应长得像手牌**。这与 `CardType.Power` 的机制定位一致:开局入场、受保护、不可针对、**永不入栈也不产生弃牌堆流量**(见 `systems/services/combat-service.md`)。
  - **卡面形态的适用面**:战斗内 `Power` **一律以技能条目呈现**;**卡面形态只用于图鉴 / 详情卡 / 奖励与置换选择面**。理由:它在战斗内从不以一张牌的姿态出现,卡面的类型标识对它本就是空转;而奖励 / 图鉴面需要与其他族并排,保留卡面成本最低。
  - 技能条目的**信息密度 = 只有图标,无名、无效果文字**——K 个最小触控目标并排的宽度里塞名字必然缩到不可读,可辨性由图标本身承担(同「缩略可辨」那条纪律);名称与效果文字走长按升起的详情。
- **不做「敌人状态可读」的事前补偿(已否决)。** 「以蓄力 / 凝聚 / 破绽等显式状态标记预告敌人下一步」的方案**明确否决**——那是换个名字把事前预告装回来。事前信息一律归敌人图鉴(它会做什么),事中信息一律归逐步呈现(它做了什么)。
- **敌人图鉴给静态知识,不给动态情报。** 账号级敌人图鉴(`systems/player-profile/codex/`)记录「这个敌人**会做哪些事**」;它**不揭示本回合的具体行动**。**这条边界的理由是「事前知识 / 事中情报」的分工**。**图鉴是事前知识的主通道,而事前知识的查阅与兑现集中在开打之前——全部图鉴在战斗内一律不可查阅**:战斗屏没有任何图鉴入口,战斗内的可读性完全由事中呈现(飘字 + 战报)承担。**首遇的信息差就是这场遭遇的风险定价**,战前准备的分量正来自「进场前能看到什么」与「进场后只能看它做了什么」这条切分。已解锁敌人的词条在战斗前确认页呈现,见 `ux/screen-flow.md`。
- **战后奖励面板是战斗流程的一屏(新增)。** 「获取奖励」属于战斗流程本身,故战斗结束后**在战斗流程内**呈现奖励:**强制部分自动计入**(无需玩家操作,例:`experiencePoint`),**可选部分逐项列出、由玩家逐项领取或跳过**——形态**参照 Slay the Spire** 的战后奖励面板,**不是三选一**:三项各自独立,可以全领、也可以一项不领。**推论 ①:这是战斗 UX 至今未有的一屏**,且它在返回结果之前,不是事件收口后的另一步。**推论 ②:面板须能表达每一项的三种态**(未处置 / 已领取 / 已跳过),且已处置的项**不允许反悔**——面板上没有撤销,也没有"放弃全部"按钮(一项都不领是逐项跳过的自然结果)。**推论 ③:每一次领取 / 跳过都会落存档**(决策点 `D6`,见 `systems/services/combat-service.md`),而 UI **不必**为此表达"已存档"——与选目标态同理。**候选本身预先算定,退出重进得到同一组选项**,故也没有 reroll 的表达需求。具体形态(三段结构、已处置项的视觉处置、强制段的展示、竖屏纵向堆叠)见下方「叠加元素与二级面板」。
- **回合不是交互式的:stack 保留、交互与优先权移除（承重）。** 卡牌入栈后按 LIFO 结算,但**没有响应窗口、没有优先权传递**——**"我打完换你打"的简单交替成立**,理由是交互 / 优先权**拉长时长、决策点过多、复杂度高而深度收益小**。**推论 ①:不需要"轮到你响应"这套交互**(何时提示 / 如何 pass / 自动 pass / 超时),竖屏触控上最吃紧的那一环由此消失。**推论 ②:栈仍必须进入呈现层**——虽然玩家不再为"是否响应"读栈,但**触发式能力也入栈**,故栈深可以大于 1(见 `systems/character-profile/deck/`);玩家要看懂"现在有哪些东西在等待结算、以什么顺序",否则触发连锁不可读。**推论 ③:敌人的出牌仍要呈现**(敌人也持有卡组),但只在敌方回合内呈现,不再穿插进玩家回合。
- **回合的三步结构给了 UX 一条明确的时间轴。** **开始阶段**(归属方 mana 恢复至 `manaLimit` → 触发「回合开始时」→ 抽牌)→ **行动阶段**(唯一出牌阶段)→ **结束阶段**(触发「回合结束时」→ 清理回合内状态)。**三步是回合归属方的流程,双方不同时走。** **推论 ①:每回合有三个可被呈现的节拍**——mana 刷满、抽牌、以及结束阶段的触发 / 状态消散,动画节奏可依此编排,不必自创分段。**推论 ②:手牌上限需要在 UI 上可读**——上限是**任何时刻都不得超过**的硬约束(**没有弃牌机制**),故玩家必须能随时看出"我还能拿几张";满手时抽牌的表现要能被看见(见待决问题)。**推论 ③:"轮到谁"是一个必须常驻的指示**,它现在是回合归属权的唯一表达;**由回合进度那一排小格承担**(当前格的着色即回合归属方),不新增部件——见下方「竖屏分区」。
- **结算会在中途停下来问「指谁」（承重）。** 触发式异能在栈上若需要选择目标,**那次目标选择是玩家的一次真实输入,也是一个决策点**(见 `systems/services/combat-service.md`)。**推论 ①:结算动画不能是一段不可打断的过场**——它必须能在中途停住、进入一个可交互的选目标态,再继续弹栈。**推论 ②:选目标态需要明确的进入 / 退出信号**,否则玩家会以为战斗卡住了(尤其在连锁触发中,停顿点可能出现在玩家没有预期的时刻)。**推论 ③:这不是「响应窗口」,呈现上必须区分**——玩家此刻不是在决定"要不要插手",而是在补全一个已经在结算中的效果的参数;措辞与视觉都不该暗示这是一次可放弃的机会。**推论 ④:这一步会落存档**,而 UI **不必**为此表达"已存档"(与战后奖励面板同理)。
- **战斗屏多了一个区:战场(battlefield)（承重）。** 场上**正在生效**的卡牌 / 持续状态 / 等待中的触发器落在 battlefield 上,与**栈**(等待结算的队列)是**两个不同的区**。**推论 ①:竖屏要容下三块**——战场 / 栈 / 手牌,再加上道念对比、回合计数与战报,窄高屏的分区压力显著上升(排布见下方「竖屏分区」,其中栈是结算期浮层、不占常驻预算)。**推论 ②:玩家须能区分"已经在生效"与"正在等待结算"**——二者混成一片就读不懂触发连锁。**推论 ③:回合内状态的消散有了可视对象**——结束阶段清理的是战场上标记为回合内的条目,动画有了明确的落点。
- **满手时抽牌的表现:牌抽不进(规则已定)。** 满手时抽牌**抽不进**(牌留在抽牌堆、本次抽牌无事发生),「加入手牌」类效果同理落空——**规则已定,剩下的只是表现形式**。**推论 ①:需要一个"没抽进"的可见反馈**,否则玩家会以为抽牌漏了或界面卡了;**推论 ②:手牌上限本身要常驻可读**(「我还能拿几张」),否则满手是个突然出现的意外;**推论 ③:不会有牌被弃掉或销毁的画面**——上限是纯上界,不产生弃牌堆流量,视觉上不该出现"牌被丢掉"的动作。
- **道念差是玩家可直接换算的账。** 失败时寿元的扣减量 = 道念差 × 该篇章的 `lossPerMomentum`,而**第一篇章的系数锁定为 10** ⇒ 战斗屏上的「我落后 8 点」同时就是「输了要掉 80 点寿元」——一次乘 10,玩家当场折得出来,**这条关系支撑主视觉的价值**:不需要额外教学就能读懂风险,也让「道念差是否显式呈现」这个问题的答案更倾向于「显式呈现」。**代价如实写下:折算是 ×10 而不是逐点对应**,比 1:1 多一步心算,论据强度相应下降;ch2 / ch3 各乘一个不同的已知系数,减弱更多(见待决问题)。
- **回合数不是固定的 10。** 10 回合是 **`Standard` 档的标准值**;`Practice` / `Finale` 档可改写回合数与胜负条件。**推论:「还剩几回合」的呈现必须由本场遭遇的配置驱动**,不能把 10 写死进 UI。
- **敌人等级的展示措辞。** **面向玩家一律用「境界名 + 层级」,全局序 1–22 不出现在任何 UI 上**(例:「筑基中期」「炼气十三层」)。
  - **理由(最强的一条):境界名让 `baseMomentum` 的跨度断层可读** —— 「筑基巅峰 vs 金丹初期」一眼就是跨境界,而跨境界正是起跑线的量级跳变处(32 → 45);「17 vs 18」看不出来。**起跑线就是「这场有多难」的唯一刻度**,故让它可读是等级展示的全部目的;全局序是内部比较刻度,不是玩家词汇。
  - **`EventOption` 的战斗类卡片上并列显示双方等级**(`我 · 筑基中期 ⟶ 敌 · 筑基后期`)——把比对成本降到零,而不是要求玩家记忆。
  - **战斗屏内敌人区常驻一行敌人境界名,但不并列玩家自身等级、不常驻**(玩家知道自己是谁;竖屏空间已是本作压力最大处),需要时在角色面板查看。
  - **不做方向标记**:`↑` / `=` / `↓` 一类由两个等级机械导出的符号**一律不加**——它同时把「日后被扩成三色 / 加文字 → 滑向模糊危险度档位」的风险从根上掐掉。任何主观危险度词汇(「略强」「凶险」「无从揣度」)照旧被否决。
  - **已知代价**:境界名不利于表达带内细微差(ch2 · ch3 只有四个层级名,`diff = ±1` 就是相邻两个词,玩家读得出差一档但读不出「差一档意味着 `baseMomentum` 差多少」),且比对成本回到玩家自己身上——**接受**,这正是「精确标注、不做主观解读」的直接体感。
- **选目标态的呈现形态。**
  - **规则层先削掉一半的进入次数:合法目标集合大小为 1 时自动选定,不进入该态、不产生决策点、不落存档。** 这条**一并缓解三个问题**(连锁打断次数 / 决策点密度 / 操作疲劳),是本节最有价值的一条,**且它是规则层的、不只是呈现层的**。(合法目标为 0 时按既定的效果落空规则处理,同样不进入。)
  - **进入信号** = 全屏低透明度**暗幕**(≈45%)0.15 s 淡入,压暗一切非决策必需元素;**双方道念位与栈层豁免不压暗**——前者是判断「该指谁」的依据,后者是「队列里还剩什么」的唯一来源。**选目标态期间栈层必然在场**(挂起态必发生在结算过程中,此时栈必然非空),故该豁免恒有对象。**暗幕因此是「压暗除决策必需信息外的一切」,不是字面的全屏。**
  - **来源指示**:栈上的该条目**上浮 + 放大 1.1× + 描边**,一条引导线连向指令条——**连锁中玩家必须知道「是谁在问」**,否则第三次弹出时完全失去上下文。**指令条位置绝对固定**(屏幕中部偏上,道念对比条与栈之间),每次进入同一位置、同一套视觉:**节奏可预期 = 不迷失**。
  - **合法目标**不被压暗 + **描边呼吸动画**(1.2 s 周期,静态描边在小屏易被忽略);**非法目标随暗幕压暗、点击无反馈**——压暗即答案,**不做「点非法目标弹提示」**(连锁中反复弹提示是噪音)。退出总时长 ≤ 0.4 s。
  - **指向手势 = 单点即确认**,不用拖拽连线:拖拽要求精确的起点落位与长路径,而起点(栈条目)在屏幕中上部、终点可能在顶部敌方区或底部手牌,**竖屏单手拇指跨不过去**;连锁中可能连续进入 2–4 次,**任何多余的操作都要乘以次数**。**也不做二次确认**——误触代价用「目标足够大 + 呼吸描边足够醒目」化解,而不是用二次确认换(那把每次操作翻倍)。**误触不做保护**(与「玩家主动退出静默处理」的手感取向同向);**已知代价**:一次误触在连锁中可能改变结算结果,且该步已落存档、退出重进也回到误触之后。**退让位**:若实测误触率高,退到「点选 + 确认键」,且只在合法目标 ≥ 4 个时启用。
  - **连锁中不迷失的四条**:① **连锁进度可见** —— 指令条第二行常驻 **`还有 N 项待结算`**(= 栈深,**永远可算**;不用「还有 N 项待选」——后者要求预知后续条目是否需要目标,而那依赖前面的结算结果,未必可精确预知)。**这是把「不可预期的停顿」变成「有限的、可数的停顿」,是四条里最关键的一项。** ② 位置绝对固定。③ **连续两次之间不完全淡出暗幕**(只交叉淡变来源高亮与文案,0.2 s)——避免全屏明暗闪烁,同时让「这是一段连续结算」在视觉上成立。④ **栈层保持可见且不被压暗**。
  - **措辞与「响应窗口」严格区分(三条禁令)**:文案用「选择一个目标」「指定」,**不用**「是否响应 / 跳过 / pass / 等待你的回应」;控件上**无取消键、无跳过键、无「不使用」**;**无倒计时、无超时自动选**(倒计时暗示「不选也会过去」,与「不可放弃」矛盾)。
  - **硬要求:选目标态必须自解释。** 玩家可能退出后隔几小时回来,正对着一个「请选择目标」的界面——呈现层必须交代**是哪张牌 / 哪个异能在要求选目标、它要做什么**,**不能依赖玩家的短期记忆**。恢复语义(回到该选择点、栈原样挂起、不允许反悔)见 `systems/services/combat-service.md`。
  - **道具使用后若需目标,直接进入这同一套形态,不另做一套。**
  - **整套形态与其频次相称,不因低频而削减。** 它服务的是「需要选目标的触发式异能 ≤ 10%、一场期望进入 1~2 次」的场景,而**这正是本作少数几个真正的战斗内交互时刻——密度低是它有分量的原因,不是削减它的理由**。暗幕 / 呼吸描边 / 固定指令条 / 连锁进度 / `pending` 存档形态**全部保留**。
- **战斗内的道具视图称「随身」,不称「储物袋」(形态落定)。**
  - **默认收起为角标**(小图标 + 本场可用道具数),贴在**己方战场区边缘**,与神通 / 法则条**分居两侧**——两者都是「己方的非手牌资源」,**对称落位让玩家一次学会两处**。
  - **点按 → 底部抽屉(bottom sheet)**,高约屏高 40%,其余半透明压暗:底部是竖屏拇指可达区,且抽屉是移动端母语控件、不需要教学。
  - **抽屉内 = 横向滚动的一行**(不是网格):本场可用道具通常 ≤ 8 件(`UsableScene` 筛出的子集远小于储物袋全量),一行足够;**与 EventOption 选择区的横向滑动手势一致**,玩家复用同一套肌肉记忆。
  - **不可用项灰显 + 长按给原因**(mana 不足 / 非行动阶段 / 栈非空)——**灰显即答案,不做点击弹提示**。**使用流程**:点按选中 → 抽屉自动收起 → 若需目标则**直接进入选目标态**(复用同一套形态)。
  - **敌人回合 / 结算中:角标置灰、抽屉入口禁用** —— 使用窗口是全局规则,UI 应把它表达为**可供性的有无**,而不是让玩家点了才被拒。
  - **⚠ 竖屏分区压力**:己方战场带左右两侧各让出约屏宽 8% 给法则条与随身角标 ⇒ 战场带净可用宽度约 **84%**,条目须在此宽度内满足最小触控目标尺寸,**须在实际排版时验证**。不足时的退让位见下方「叠加元素与二级面板」。
  - 元进程侧的储物袋落位与全屏面板形态见 `ux/screen-flow.md`。
- **卡面是全幅插画(full art)（承重）。** 卡牌为整图,**卡面上的文字信息只有 `manaCost`**——无规则文字、无卡名。规则描述、卡名、关键字、`Power` 的明示内容一律后置到**点按升起的详情页**。呈现哲学一句话:**卡面极简,信息后置到详情页与战报**。
  - **非文字的 UI 叠加保留并因此升格**:五类卡牌(法术 / 阵法 / 道具 / 神通·法则 / 业障)仍靠**卡框色 + 类型角标**区分(**适用于会以卡面出现的类型**),它们是呈现层 UI、与插画分开生成(UI 需要可九宫格拉伸)。在 full art 下它们是卡面上**唯一的非 `manaCost` 呈现元素**,其权重与可辨性随之升格。
  - **硬约束:插画内不得烧入任何承载可翻译语义的文字 / 字符。** 卡名 / 规则文字若烧进插画,等于把语言数焊进美术资产——切语言时静默留在中文,且失去热更通道,与「UI 文案一律走 `res://text/` 翻译键」的承重纪律相抵。(装饰性的符文 / 印章 / 书法笔触一类不承载语义的图形不在此限;判据与豁免的权威在 `art/visuals/art-direction.md`。)
  - **缩略可辨是玩家在手牌区认牌的唯一通道。** 手牌区的卡面很小,而 full art 下没有卡名可读——插画主体必须在缩略尺寸下仍能辨认,**且跨卡之间彼此可区分**(剪影 / 主色 / 构图有别),否则一手牌读不开。
- **手势分工:点按手牌 = 升起详情页,拖出手牌区 = 打出（承重）。** 卡面无文字使「点按看详情」成为刚需,故它必须与出牌手势显式分工。两者都是触控原生手势,不依赖悬停。
  - **详情入口的手势按「对象是否可拖拽」分化**:**可拖拽**的对象(手牌)用**点按**开详情;**不可拖拽**的对象(关键字定义、`Power` 详情、灰显道具的不可用原因)用**长按**。理由:长按与拖拽起手在同一根手指上争同一段时间窗,而手牌是战斗屏唯一同时承载拖拽的对象。**这条判据必须留在文档里**——否则日后读者会把两种手势并存读成漂移。判据的辖域仅限**详情入口**;「点按」在别处另有语义(随身抽屉内点按 = 选中使用、选目标态单点 = 确认),不是一张通用手势表。
  - **详情页复用既有的 bottom sheet 控件语言**,不另造控件:战斗屏内的先例是随身抽屉;库内另一处先例是战斗前确认页的功法词条(见 `ux/screen-flow.md`)。
  - **选目标态中手牌的点按语义被该态独占**:`HandCard` 槽位使手牌可成为合法目标,而该态已定「单点即确认」,故该态下点按手牌 = 指定目标,不升起详情页。
- **关键字只印名字,完整定义走长按(宿主在详情页)。** 卡面无文字,故关键字名与完整定义**一并落在详情页**:详情页印关键字名,长按展开 `KeywordData.ReminderText`——`ui-input-rules.md` 禁止 hover-only 可供性 ⇒ 触控等价物只能是长按。**永远长按,首次出现不自动展开**:「首次」这件事要记账(落哪个 Profile？跨轮回还是轮回内？),**为一条呈现便利新增一个存档字段不划算**。若实测新手看不懂,自动展开一次是现成的退让位(属实测调整)。关键字的形态见 `systems/character-profile/deck/common-properties.md`。
- **多目标槽位的询问顺序 = `slotIndex`。** 一张牌有多个目标槽位时,UI **在打出前按 `slotIndex` 顺序逐个问、一次收齐**;**各槽位的类别由选目标态的指令条按同一顺序点名**(「摧毁目标阵法」而非「摧毁目标」)——否则玩家不知道自己现在在选哪一个。指令条本就「必须自解释」、位置绝对固定、常驻连锁进度(见上),故这项告知**不新增任何部件**。
- **静默退出的告知责任落在战斗屏。** 玩家主动退出**不做二次确认弹窗**(手感优先,不在最频繁的操作上加模态);代价是「进度保留在当前决策点、成本不退还」这条规则玩家看不见——**须由战斗屏的常驻措辞或首次退出时的一次性提示承担告知,不是弹窗流程**。
- **进入战斗前的同步失败不产生任何额外提示。** 告知由**常驻的「离线 · 待同步 N」指示**承担——**该指示在战斗屏内必须可见**(这是本条成立的前提)。理由:断线期间**每一场**战斗的入口都会命中这条路径,在此弹 toast 等于把一次性的网络状态变成**逐场重复的打扰**,且时机恰是玩家最专注处。**这与「静默退出的告知责任」是同一条纪律的第二个实例**:不在最高频操作上加提示,告知由别处的常驻呈现承担。**边界**:真正需要打断玩家的情形仍由既定机制承担——缓冲超限的软阻塞模态(下一次事件选择前)与两处硬阻塞(启动 pull 失败、被挤下线)。规则侧见 `systems/services/sync-service.md`「`Immediate` flush 的失败语义」。
- **寿元余量不常驻战斗屏(已答结)。** 战斗屏只呈现道念对比与差值;余量的常驻位置是 **EventOption 选择界面**的静态标注,**不常驻战斗屏幕**、不做全局 HUD(见 `ux/screen-flow.md`)。**理由**:战斗内本就没有任何手段改变这个值,常驻显示一个战斗内不可改变的量只增噪音,还会诱导「留血打」的错误心智;而进入战斗前的确认页已给出余量。
  - **结算面板必须如实展示本次扣减量与扣后余量。** 失败代价最重的那一条不能只在数字里静悄悄地少一截——这是「不常驻」的配套条件,两者一并成立。

### 竖屏分区(主视图)

**总原则:上敌下我,中轴为共享决策面板。** 依据:玩家可操作的对象(手牌 · 己方战场条目 · 随身 · 启动式异能 · 结束回合)**全部**落在下半屏的拇指可达区;敌方全程零可操作,故占上半。

| # | 区 | 屏高 | 内容 | 常驻 |
|---|---|---|---|---|
| 0 | 顶部条 | **5%** | 左:退出入口。右:「离线 · 待同步 N」指示 | ✅ |
| 1 | 敌方区 | **20%** | 敌人立绘(紧凑半身像)· 敌人境界名一行 · 敌方 `CurrentMana/ManaLimit` · 敌方手牌张数角标 · 敌方战场带 · 敌方埋伏计数 · 敌方抽 / 弃计数 | ✅ |
| 2 | 决策面板组 | **16%** | 道念对峙条(7%)+ 回合进度(3%)+ 战报收起态单行(6%) | ✅ |
| 3 | 己方战场带 | **12%** | 己方战场条目;左缘 = 神通 / 法则只读层,右缘 = 随身角标 | ✅ |
| 4 | 手牌区 | **28%** | ≤ 7 张,水平重叠扇 | ✅ |
| 5 | 底部条 | **10%** | 左:己方 `CurrentMana/ManaLimit`。中:抽牌堆 · 弃牌堆。右:结束回合键 | ✅ |
| — | 安全区留白 | **9%** | 顶部刘海 + 底部 Home 指示条 | — |
| — | 栈层 · 飘字层 · 指令条 · bottom sheet | **0%** | 叠加层,不占布局预算 | ❌ 临时 |

- **三个百分比是初值,须在实际竖屏比例(18:9 / 19.5:9 / 平板)上实测**——`vision/scope.md` 未给目标分辨率或宽高比,故此处只能给比例、不写像素。工程形态:根 `VBoxContainer` + 各区 `SizeFlags` 比例;四类临时物挂在**根之上的独立叠加层**,与 `Container` 布局互不影响。
- **栈是结算期的临时浮层,不占常驻布局预算(承重)。** 出牌时机是「行动阶段**且栈为空**」,取其逆否即:**玩家能发起任何动作的每一刻,栈必然为空**。故栈非空的区间只有两种——结算演出(玩家无输入)与挂起态 `AwaitingChoice`(玩家只能 `ProvideTarget`),两者都是演出 / 交互时刻,不是常态;一个常驻栈区在玩家做出全部出牌决策的每一刻都恒为空,占的是屏高、给的是零信息。
  - **落位** = 屏幕中部偏上、紧贴指令条下方(指令条位置本就定在道念对比条与栈之间),不是新落点。
  - **不参与 `Container` 布局**:栈层的出现 / 消失不得挤动任何常驻区,尤其不得让手牌区跳位——与战报「容器本身不参与布局变化」同一条工程纪律。
  - **代价明写接受**:行动阶段看不到「上一次结算留下了什么」。但那已落账——持续效果落到战场(可见)、增量落进战报;栈本身在那一刻已经是空的,看不到的不是信息,是一个空容器。
  - **它依赖「无 instant / 无优先权 / 栈非空时不可出牌」这三条同时成立**;三者若有一条松动,栈须回退为常驻区。
- **栈与战场靠三条正交轴区分,不靠颜色**(色觉可及性 + full art 底色不可控):**存在性**(战场恒在 / 栈只在结算期出现,这本身就是最强的一条)· **位置**(战场是 #1 下沿与 #3 两条常驻带 / 栈是中轴浮层)· **轴向**(战场横向排列 / 栈纵向堆叠)。
  - **顺序表达**:栈顶画在最上,其左侧一个固定的「↓ 下一个结算」指示。LIFO 下后触发者先生效,自上而下的自然阅读顺序恰好就是结算顺序,无需教学。
  - **未落账气质**:栈条目半透明 + 悬浮投影 + 无底座;战场条目实心 + 贴带底 + 描边底座。「悬着 vs 落地」是两区语义的直接视觉隐喻。
  - **弹栈 = 一次可见的位移**:条目从栈层飞向它的落点(持续效果飞进战场带落座 / 一次性效果飞向弃牌堆 / `Power` 触发的异能飞回左缘的只读层)。「从等待 → 已生效」因此是一个被看见的位移,而不是一次消失加一次出现。位移**复用既定节拍、不新增任何停顿**,敌人回合 ≤ 4 s 的硬上界不受影响。
  - **敌人回合期间栈层照常出现,位置与玩家回合完全相同**——同一位置 = 节奏可预期。
- **敌方区不做己方的镜像。** 敌方在类型层没有可操作对象,故它只承载读数与观看:立绘(压缩顺位第一)· 境界名一行 · 一格 `n/5` 的敌方 mana · **敌方手牌只给一个张数角标,不渲染牌背扇形**(画扇形是把一个计数伪装成信息,且白占约 8% 屏高)· 抽 / 弃两个小计数 · 区下沿一条战场带 · 战场带上一个埋伏计数角标。**布局不得预留「翻开对手信息」的位置**——对侧手牌 / 可用道具 / 可启动异能在类型层恒空。
- **敌方出牌:在敌人立绘前方放大呈现该卡面一拍(0.35–0.5 s),再落入栈层。** 卡面是 full art、无卡名无规则文字,玩家认牌完全靠插画;若敌方出牌只是一张缩略图一闪,等于取消「敌人回合是唯一动态情报通道」这条硬要求。**给它一拍足够大的呈现,是 full art 的直接对价。** 该拍照常受 3× 加速手势约束,不是不可跳过的节拍;「它做了什么」由飘字与战报承担,不重复。
- **手牌 = 水平重叠扇,不做弧形旋转。** 旋转会让 full art 的缩略辨识更难(主体不再正立),且拖拽命中区变成不规则形;竖屏单手拇指的拖起动作也更适合水平带。
  - **重叠量动态**:≤ 4 张不重叠(稳态手牌 = 4);5–7 张按可用宽度均分重叠,**每张至少露出左侧 40% 宽度**(初值,须与美术侧「缩略可辨」阈值一并实测)。
  - **手牌区高度固定、不随张数变化**:撞上限的 7 张与稳态的 4 张占同样高度,只是重叠更密。
  - **被点按 / 被拖起的那张:上浮 + 放大 1.1× + 描边**,复用选目标态来源指示的同一套视觉,不新造视觉语言。
  - **拖拽阈值必须可见**:拖起后手牌区上沿浮现一条**释放线**(0.15 s 淡入),越过即高亮。阈值不可见时玩家无法预判「拖多远才算数」,而这是本作最高频的操作;释放线是临时浮层,不占布局。
  - **满手抽不进的反馈**:第 8 张牌从抽牌堆抬起一半后退回抽牌堆(0.3 s),手牌区上沿同步闪一次上限标记,**不出现任何「牌被丢掉」的动作**。手牌上限的常驻可读形态 = 手牌区右上角一格 `n/7`(`HandCount` / 生效上限)。上限**恒取 `CombatRulesData` 的全局常量**——任何编排面都改不动它(不进 `EncounterSpec` 覆写组、不进 `EncounterTighten` 增量面,见 `systems/services/combat-service.md`);呈现侧**仍不写死 7**,从平衡资源读,那个数可经 overlay 热更。
- **道念对峙条 = 单条双向、中点为分界,两端各挂头像与数值。**
  - **分界线位置 = `myMomentum / (my + enemy)`**:谁领先 = 分界线偏向哪边,**不读数字即可读出局势**。条的正中另有一个固定的初始中点刻度,使「分界线相对中线的偏移量」= 道念差的视觉长度。
  - **数值按三位数排版**(ch3 可达约 160);四位数是寿元的排版口径,而寿元不进战斗屏。
  - **变化反馈**:数值滚动 0.2 s + 增量段闪一次(我方增长 = 己方色向对侧推进并高亮;被削减 = 对方色侵入己方段)。数据源是既有的逐次增量,**不新增字段**。
  - **道念差显式呈现** = 分界线上方一枚小徽标 `+15` / `−15`(带方向色)。三条理由:道念差是胜负判据、胜侧奖励厚度、负侧寿元扣减**三个消费点的共同输入**,玩家真正需要的那个量就是差;ch3 战中可达三位数,要求玩家自己做三位数减法不符合「明快、单手」的基调;而「换算成寿元要先乘一个逐章系数」削弱的是「差 → 寿元」这一步,不是「差本身要不要显示」。**不在差值旁再附一层 `≈ −N 寿元` 的二级换算**——寿元不进战斗屏。
- **回合进度 = `TurnLimit` 个小格的一排点**,敌 / 我交替着色,已过的填实、当前格高亮呼吸;右侧并列文字「第 `TurnIndex` / `TurnLimit` 回合」。**格数由 `EncounterSpec.TurnLimit` 驱动,绝不写死 10**(`Practice` 8 / `Standard` 10 / `Finale` 12),格宽自适应。当前格的着色即回合归属方,另在对应一端的头像加一圈呼吸描边作冗余编码(小格在小屏可能读不出色差)。
- **回合进度与道念差是空间邻接的两行,不合成一个复合指示。** 一个「还追得回来吗」的指示需要一个每回合期望产出模型才算得出,而该模型的输入在 `systems/balance.md` 中明标为待实测校准的标定假设、不得作为承重依据;把它焊进 UI 等于让一个待校准的数字变成玩家读到的结论。**且它会替玩家算掉那本账**——「我落后 8 点、还剩 2 个回合」这本玩家自己算的账正是紧张感来源。
- **牌堆有稳定的可见面。** 抽牌堆 = 底部条中部一叠牌背朝上的牌,**厚度随剩余张数递减**(不重洗 ⇒ 单调递减 ⇒ 厚度是一个诚实且零文字的余量指示);弃牌堆与之并列,**面朝上显示最近进入的那张**(`Power` 永不产生弃牌堆流量,故这里不会出现受保护条目)。**敌方牌堆不给实体**,只在敌方区给两个计数。
  - 四条依据:抽牌堆信息面需要一个入口,而入口的自然宿主就是抽牌堆本身;抽牌动画需要一个起点(一场稳定发生 6 次);弃牌堆同理需要一个终点;且卡组与弃牌堆本就是战斗内六处位置中的两处,**给它们一个可见面是呈现既有位置,不是第七处**。
- **结束回合键 = 底部条右端的主按钮。** 行动阶段需要一个出口:「打完手上想打的牌」不是一个可被系统检测的状态(玩家可能故意留牌以免撞手牌上限、或留 mana 无用),故必须有一个玩家主动结束回合的动作。**不做二次确认**(不在最高频操作上加模态);敌人回合 / 结算中 / 选目标态置灰,与随身角标同规格。

### 叠加元素与二级面板

- **随身角标 = 胶囊形容器(一枚道具图标 + 一个数字徽章),整体满足最小触控目标尺寸。** 可用件数为 0 时**仍渲染、置灰、不隐藏**:隐藏会让玩家以为功能消失且无处解释,也会让己方战场带的可用宽度在战斗中途变化。灰态照既定纪律继续接收触控,点按升起抽屉(抽屉内为空态一行说明,走 `COMBAT_` 普通键)。
- **`AbilityScope` 两级标识 = 一枚形状化角标,不是边框色、不是文字。** 不能用文字:UI 不能靠中文名传达「这是账号级的」,且「法宝 / 古宝」共用「宝」字根;不能用边框色:卡框色已被卡牌类型占用,同一张小卡面上两套色系必然相撞。角标两个取值(`Character` = 法宝 · 轮回级 / `Player` = 古宝 · 账号级),**与只读层共用同一套形状**——同一个枚举在战斗屏只学一次。抽屉内另按 `AbilityScope` **分两段**(法宝段在前、古宝段在后,段间一道细分隔线),让角标成为确认信息而非唯一信息。长按抽屉内任一条目 = 升起卡牌详情页那一份 sheet,不可用时在其顶部追加一行原因。
- **神通 / 法则只读层 = 单行图标条 + `+N` 溢出聚合格,不折叠为角标、不做任何滚动。**
  - **不折叠为角标**:随身是可操作层,角标点开是操作入口;只读层的全部价值是**常驻可读**——`Power` 开局入场、整场不变,藏进角标等于逼玩家每回合去查。两层按「能否被操作」分层,形状不必对称。
  - **不做滚动**:横滑已被随身抽屉与事件选项占为「浏览候选」的语义,且图标条贴战场带边缘,横滑与「拖出手牌区 = 打出」的起手在同一片区域争同一根手指;滚动条本身也给不出「还有几条没看到」的常驻表达。
  - **容量**:条内最多显示 **K** 个图标,总条目数 > K 时第 K 个位置换成 `+N` 聚合格,点按 / 长按升起半屏 sheet 纵向列出全部条目。**K 是派生量**:`K = floor(可用宽度 ÷ (最小触控目标 + 间距))`,**硬下界 `K ≥ 3`**(低于 3 时聚合格吞掉的比显示的还多),**初值 5、待排版实测**。
  - **溢出格不得吞掉启动可供性**:被折进 `+N` 的条目中只要有一条此刻可启动,`+N` 格自身即带强调态——服务已经算好,不显示等于逼玩家逐个长按去查够不够 mana。
  - **固定序**:神通(`Character`)在前、法则(`Player`)在后,同段内按入场顺序;**不按稀有度排**(`RarityTier` 在战斗内没有语义)。位置稳定 = 可学习。两级角标叠在图标右下,与左上的启动可供性标记不争位。
  - **退让位**:若实测宽度容不下 3 个最小触控目标,**整条上移为战场带上沿的「己方资源条」**(左端随身角标、右端只读层图标条),**不得移出战场区**——`Power` 住在战场上,位置即语义。
- **埋伏:己方逐条渲染,对手侧是固定预留位的计数。**
  - **己方埋伏 = 战场条目的一个面朝下变体**(卡背 + 一枚埋伏次类型角标),与正面阵法条目同尺寸、同槽位排布,不另开一行、不另分区。它对己方是完全公开面(`faceDown` 隐藏的只是对手视角),逐条渲染零信息泄漏;数量天然受限(同名不可重复布置,且要占 mana 与一个出牌位)。**溢出时退让为战场带内横向滚动,绝不退让为折叠。**
  - **对手侧 = 挂敌方战场带的「图标 + 数字」计数标记**;**计数为 0 时整格淡出,容器尺寸不变**(固定预留),而不是移除该格。
  - **两侧 0 值处置不同的判据 = 它是不是一个入口**:随身角标是入口,必须可点、必须能给说明,故置灰保留;敌方埋伏计数是纯指示,无处可点,淡出即答案。两者都不改变布局,这一点没有分化。
- **卡框色 + 类型角标:颜色管「哪一类」,形状管「同一类」。**
  - **适用面**:战斗内 `Power` 一律以技能条目呈现 ⇒ 手牌与战场卡面上出现的类型只有 `Sorcery` / `Enchantment` / `Item` / `Affliction` 四类;`Power` 的卡框色与角标只在奖励 / 图鉴 / 详情面出现。**仍做一套五色**(那三个面要五类并排),但**缩略可辨性只按四类校准**。
  - **类型角标必须是形状化图标,脱色后仍两两可辨**——两个元素并存的全部意义就是冗余编码;若角标只是一块与卡框同色的色块,两者表达同一维度即是浪费。小尺寸下的颜色分辨率不足与色觉障碍是移动端的无障碍底线。
  - **卡框色 = 外缘细描边 + 一条较厚的色带,不整框着色**(整框着色吃插画面积,而缩略可辨是认牌的唯一通道)。
  - **卡面必读元素的占位由重叠扇决定**:手牌每张恒只保证露出**左侧 40% 宽度** ⇒ **`manaCost` 占左上角、类型角标紧邻其下(同在左侧可见带内)、卡框色带落左边缘;右上角在重叠扇下不可见,不得承载任何必读元素。** `manaCost` 是出牌决策的必读项、类型角标是次读项,故遮挡预算优先给前者。
  - **五色的取值归 `art/`**,本处只给三条约束:① 在 GL Compatibility 渲染器下、在手牌区缩略尺寸下两两可辨;② **灰度化后仍两两可辨**(色觉障碍的代理判据,可机械核对);③ **不与合法目标的呼吸描边、来源条目的上浮 + 放大 + 描边、灰态的降饱和三套状态视觉相撞**——状态色与类型色同处一张卡面,撞色即状态读不出。
  - **`Affliction`(业障)的角标须最醒目**:它是唯一「打出无任何正面效果」的类型,在手牌区认错它的代价高于其余四类。
- **卡牌详情页 = bottom sheet,内容自适应高度、上界屏高 60%,超出则页内纵向滚动;不分区、不分页、不加 tab。** 一张牌的详情项数只有 5–7 项,不值得分类;tab 在触控上多一次点击,而滚动是移动端母语行为。关闭 = 下滑 / 点击 sheet 外区域。内容自上而下(**缺项即整行不渲染,不留空槽**):
  1. **标题行** —— 卡名 + `manaCost` + 类型角标 + 卡框色带(与卡面呼应,使「这是刚才那张牌」零成本成立)
  2. **插画缩略** —— ≤ 屏宽 20% 的小图,只作锚点;**不重复大图**(详情页存在的全部理由是卡面无文字,把最不缺的东西放两遍会挤掉规则文字)
  3. **规则文字** —— 关键字名以可长按的内联 chip 形态嵌在句中,长按展开 `KeywordData.ReminderText`
  4. **次类型行** —— 如「阵法 · 埋伏」
  5. **目标声明摘要** —— 要选几个目标、各是什么类别;**措辞与选目标态指令条同源**,避免打出后才知道要指谁
  6. **启动区**(仅阵法 / `Power` 载体)—— 逐行列表,形态见上
  7. **不可用原因**(仅灰态入口升起时)—— 一行,`COMBAT_` 分区普通键
  - **战斗内详情页不显示 `Rarity`**(稀有度在战斗内没有消费点);奖励 / 置换 / 图鉴面的详情卡显示它。
  - **禁用档与战报展开态同档,与随身抽屉 / `Power` 弹层不同档**——判据仍是那条「争屏幕还是争语义」:手牌详情页纯只读、不可能改变局面 ⇒ 不争语义;它是半屏面板 ⇒ 争屏幕。**故敌人回合 / 结算中可开**(那段「信息与交互双零」的观看里玩家正好在规划下一回合),**选目标态下入口天然不存在**(该态独占点按手牌的语义)。三档对照:

    | 对象 | 争什么 | 敌人回合 / 结算中 | 选目标态 |
    |---|---|---|---|
    | 随身抽屉 · `Power` 弹层 · 阵法启动弹层 | 语义 + 屏幕 | 禁用 | 禁用 |
    | 战报展开态 | 只争屏幕 | 可开 | 禁用 |
    | 手牌详情页 | 只争屏幕 | 可开 | 入口天然不存在 |
- **战报与飘字的分工判据:不读也不会错过的归飘字,不读就读不懂的归战报。** 飘字 = **量与归属**(谁的道念动了多少、动在哪个对象上),不承载因果、不承载例外;战报 = **事实与例外**(谁做了什么、引发了谁、标称量与实际量之差、目标落空)。三条推论:
  - **截断量与目标落空只进战报,飘字侧不表达。** 飘字转瞬即逝、承载不了括注;更要命的是实际量为 0 时飘字本就没有数字可飘——「削减被下限 0 全部吃掉」与「目标落空」在飘字上都表现为「什么也没有」,而那正是两条硬要求要说明的那件事。
  - **飘字取实际量,战报取标称量 / 实际量一对**,两者同源同刻、**不设先后延迟**(延迟会让两个消费者对同一次结算给出错位的画面)。
  - **飘字不画因果连线、不做「由 X 触发」的附注**——因果树是展开态战报的专职。
- **战报收起态单行 = 结构化槽位,不是自由文案:`[归属方] [动作动词] [来源名] · [增量]`。**
  - 采「敌方打出「回风诀」 · 你 −5」这一档,而不是只写「敌方打出 X」:收起态是常驻的、事实上是战报的默认视图,只写动作不写结果就把「第 3 回合我的道念为什么少了 3」这个战报存在的唯一理由整个推给展开态,而玩家不会主动开日志。**与飘字的冗余是刻意接受的**——飘字转瞬即逝,收起态单行是玩家移开视线后唯一的安全网;分工判据分的是「谁必须说」,不是「谁独占」。
  - **超长时的省略顺序是一条规则:优先省略「来源名」,绝不省略「增量」。** 增量是玩家推不出来的那一半,来源名在展开态可查。不写下这条,「单行 · 永不换行 · 超长省略」会随机吃掉信息量最高的那一段。
  - 疲劳条目无来源名:`[归属方] 疲劳 · −1`。归属方用「我方 / 敌方」措辞,不用侧别代码。
- **截断与落空在单行内以符号标记表达,括注只在展开态**——在单行、永不换行、≈ 屏高 6% 的约束下,「削减 8(对方仅剩 5,溢出 3 未结转)」必然触发省略,而被省略掉的恰好就是括注本身。

  | 情形 | 判据(服务已给) | 收起态单行 | 展开态 |
  |---|---|---|---|
  | **截断** | 标称量 ≠ 实际量 | 增量后缀一枚**溢出符**:`你 −5▸` | 全文「削减 8(对方仅剩 5,溢出 3 未结转)」 |
  | **部分落空** | 有槽位落空且标称量非 0 | 来源名后一枚**落空符** | 写明是哪一半没生效 |
  | **全条落空** | 全部目标槽位落空 | 直接写「[来源名] · 目标已不存在」(无增量可显示,字数够) | 同左 + 因果树内的位置 |

  - **两枚符号必须是非数字字符,且与飘字的 `+N` / `−N` 不同源**,否则会被读成第二个数值。**符号不需要被「理解」即可用**:它只表示「这条还有话说」,语义由展开一次即得;**不做说明浮层**(无 hover 通道,且弹提示在连锁中是噪音)。具体字形归美术 / 图标集,约束只有三条:**非数字 · 单字宽 · 两枚互不相似**。
- **战报的翻译键随 `CombatFeedKind` 的成员机械对应,不建第二张手写对照表。** 分区 = `COMBAT_`,首批键见 `ux/error-and-blocking-ux.md` 的分区表。**来源名(卡名 / 异能名 / 道具名)不进翻译键**——它们是内容层 `LocalizedText`,由呈现层作格式参数插入,与「事件正文一个字也不进 `EVENT_`」是同一条边界。
- **疲劳三格。**
  - **抽牌堆剩余张数常驻**:数字叠在底部条的抽牌堆实体上,零新增区。疲劳是一条确定性的、可预算的失血曲线(抽空后每抽一张 −1,每回合抽牌数固定),玩家能且只能靠剩余张数把它算成「还有 N 个回合开始扣血」;不常驻就把一条可算的账变成突然发生的事。
  - **见底预警只给一档、纯静态**:剩余张数 `<= DrawPerTurn × 2` 时**转红字**,**不闪烁、不弹提示、不加音效、不写任何预警文案**——余量既已明文常驻且精确,预警型提示文案没有存在理由(与寿元余量的处置同构)。阈值写成 `DrawPerTurn × 2` 而非固定张数:`DrawPerTurn` 可被遭遇覆写、可被剧本收紧,固定张数在被收紧的遭遇里语义漂移;它是**派生量、不是平衡常量**,不进 `CombatRulesData`。
  - **飘字侧「疲劳扣减」与「被对手削减」按起飞点区分,不按颜色 / 字形**:被对手削减的那一条有来源对象,飘字自该对象飞向我方道念位;**疲劳没有任何来源对象**(来源三格恒空),它的飘字**自抽牌堆飞出**。判定完全由呈现事件流的类别给出,呈现层零规则重演。**颜色不参与归因**——归因维度已由起飞点承载,再叠一层颜色会与三套既有状态色争语义。
- **战后奖励面板 = 战斗流程内的全屏一屏**(不进屏幕栈、无返回键、无系统返回绕过),自上而下三段 + 底部一个全宽主按钮:

  | 段 | 内容 | 有无按钮 |
  |---|---|---|
  | **1 结果段** | 胜负 + 双方最终道念;**失败时如实展示本次寿元扣减量与扣后余量** | 无 |
  | **2 强制段** | 一行小标题 + 逐条只读行(图标 + 名称 + 数量 / 增减量) | **无** |
  | **3 可选段** | 一行小标题 + **3 行卡片,纵向堆叠** | 每行两个 |

  - **强制段必须展示**:`BaseReward` 随物化定稿,玩家不看这一屏就再也没有地方知道自己拿到了什么;更硬的一条是**失败侧的额外惩罚正是以负向条目包在 reward 内** ⇒ 不展示等于让惩罚静默发生,与「结算面板必须如实展示扣减量」是同一条诚实性要求。
  - **强制 / 可选的同屏区分靠「有没有按钮」这个结构差,不靠颜色 / 图标**——「有没有可操作」是最不可能被误读的区分,且与「按能否被操作分层」同出一辙。小标题只作确认,不作唯一区分。
  - **竖屏排布 = 纵向堆叠全宽行,绝不横滑。** 横滑正是**择一**的语汇,而「三项各自独立可领、不是三选一」恰是这块的承重语义,用错语汇即在视觉上否定它。
  - **每行 = 卡面缩略(此处 `Power` 族同样以卡面出现,五类角标齐用)+ 名称 + 一行说明 + `[领取]` `[跳过]` 两键**;点按行本体 = 升起详情 sheet(此处**显示 `Rarity`**)。两键各自独立、不做长按、不做二次确认。
  - **已处置项就地置灰保留,不消失、不移入「已领区」**:面板逐格映射 `picks`,而 `picks` 一经写入不可增删不可重排;消失或移动会让长度 / 顺序变化,与「已处置不可反悔」要传达的「这已经是事实」正好相反,也会让退出重进按 `state` 重建出的面板与处置过程看起来不一致。
  - **已领取与已跳过必须可区分,且两键移除而不是置灰**:行尾一枚状态标记(已领取 = 勾、已跳过 = 斜杠,两个非文字符号、形状可辨);两个按钮**同时移除**,不留灰键——灰态纪律要求灰格继续接收触控并给一条说明,而此处已成事实、没有任何说明可给,留一个灰键只会诱导点击(该边界句见 `ux/error-and-blocking-ux.md` 灰态判据表)。行本体本身仍可点(升详情),只是不再有处置动作。
  - **候选项数恒为 3,池不足时显式降级为实际项数;面板逐格映射 `picks`,不渲染空槽。** 空槽没有语义,且会被读成「这一项加载失败了」。`Practice` 档 `PowerData` 整族不进候选,面板形状一格不变。
  - **与事件收口两屏顺接,不合并为一屏。** 底部主按钮在**仍有 `Pending` 项时置灰**,点按给一行说明「还有 N 项待处置」(`COMBAT_` 普通键;此处是「暂时不可用」,灰格继续接收触控);按下 → 离开战斗流程 → 事件结算面板。不合并的理由:奖励面板在返回结果之前、属战斗流程,逐项处置是 `D6`;事件结算面板呈现的是收口后的一次事务结果。合并会让「**计算归战斗、施加归生命周期**」这条分工在 UI 上糊掉。**主按钮的措辞与结算面板的「继续」分开**(走 `COMBAT_` 分区自己的键),避免玩家把两次点击读成重复。
- **敌人台词落在立绘上方的非常驻浮层气泡,零新增区、零常驻部件。** 形态 = 以 anchor 挂在敌方区的 `Control` 浮层,**不进任何 `Container`** ⇒ 出现 / 消失不触发布局重排;触发时淡入、**约 1.5 s 后淡出**(初值,待实测);**不可点、不可关闭、触控事件一律穿透**——战斗屏的触控争抢是承重问题,台词绝不能吃掉任何一次点按。与飘字不争位(飘字跟随对象且短促,台词落在立绘上方的固定锚点)。**台词与既有节拍并行播放,不新增任何等待节拍**,敌人回合演出 ≤ 4 s 的硬上界原样成立——若台词要求额外停留,那条上界就被一条风味元素绕过了。
  - **硬纪律:台词永不承载规则信息。** 纯风味。台词一旦能说「我要用大招了」,它就成了「敌人的行动不作任何事前预告」这条承重纪律的旁路。槽位清单与内容侧纪律见 `systems/enemies/_index.md`。
