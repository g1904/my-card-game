# combat-ux

> 战斗手感:出牌/拖拽/指定目标、节奏。**主视觉 = 双方道念对比**;**敌人的行动不作事前预告**,可读性由敌人回合的逐步执行呈现承担(见下)。

## 意图

- **道念是战斗屏幕的主视觉。** 胜负判据是**道念(momentum)高者胜**(见 `systems/scoring.md`),因此战斗屏幕的视觉重心是**双方道念的对比**——玩家任何时刻都应一眼看出「我现在领先还是落后、差多少」。**lifeTotal 退居次要**:它在战斗过程中不变化,只在结算时按道念差被扣减,故不需要战斗内的常驻血条式强调。具体形态(对比条 / 双数值 / 天平隐喻)待战斗 UX 专场。
- **战斗是定长的 10 个回合,故进度可视。** 双方各 5 个回合、打满即比大小——**「还剩几回合」是一个必须呈现的信息**:它把「我落后 8 点、还剩 2 个回合」变成玩家可算的账,是限时积分对抗的紧张感来源。**起始道念按等级给**,故战斗一开场就可能呈现出一段明显的落差。呈现形态(回合计数器 / 进度条 / 双方轮次指示)待战斗 UX 专场。
- **敌人等级精确可见(答结「等级差是否可见」)。** 玩家**能**看到敌人的等级——**在 eventOptions 上就已精确标注**(见 `systems/services/future-event-service.md`),而非模糊的危险度档位(「同阶 / 略高 / 越阶 / 无从揣度」一类标签**否决**)。**承重理由:看到等级即看到起跑线**——等级 → `baseMomentum` → 开局领先 / 落后量,故标注的等级**就是这场遭遇的难度刻度**;「越级挑战」也因此成为可主动选择的风险 / 回报维度。
- **敌人的行动不作任何事前预告（承重）。** **意图区、三档呈现、类别符号体系、综合数值、「预估」视觉提示与偏差对照,全部从战斗屏移除。** 玩家在自己回合看不到敌人下一回合要做什么;可读性改由**事中呈现**承担(见下一条)。规则侧权威见 `systems/adventure-event/combat/_index.md`「敌人回合的可读性」。
  - **推论 ①:战斗屏少一个区**,释放约屏高 8%,且**少一个随回合归属切换而出现 / 消失的区域**——一场约 20 次的收起 / 展开动画整条消失,布局跳位的风险源随之减少一个。
  - **推论 ②:玩家回合的决策面收敛为「道念对比 + 剩余回合数 + 战场 + 埋伏计数」**。「我落后 8 点、还剩 2 个回合」这本账仍然可算,只是账里没有「它下回合要打 12」这一项。
  - **推论 ③:探查(probe)的入口不再需要在战斗屏留位置**。
  - **已知代价(明写接受):** 本作已移除交互与优先权,故敌人回合对玩家而言是**信息与交互双零**的一段观看。这正是下一条把逐步呈现升为硬要求的原因。
- **敌人回合的逐步执行呈现是硬要求（承重）。** 原理由是「快照与执行的偏差必须可解释」;偏差不再存在,但**敌人回合现在是玩家获取动态情报的唯一时刻**——看不清就完全不可读。既有形态**整体保留**:
  - **飘字为主 + 一条日志 ticker 为辅,两者都要**:飘字**注意力跟随对象**(敌人打出牌 → 牌面飞出 + 道念条上 `+5`;玩家侧被削减 → `−3`),不需要阅读但转瞬即逝;ticker 可回看。**ticker 默认显示最近一行**,点按展开本回合完整日志(半屏,可上滑)——**藏在按钮后等于取消这条硬要求**(玩家不会主动开日志)。**一条 ticker 同时解决「栈与战场的连锁可读性」那条待答。**
  - **截断量必须被说明**:一次结算的效果标称量与实际量不等时(道念下限 0 的饱和减法),ticker 给出「削减 8(对方仅剩 5,溢出 3 未结转)」。数据由 `PlayResult.MomentumDelta` 的 `Declared` / `Actual` 一对承载——**这里的 `Declared` 是效果的标称量**,见 `systems/services/combat-service.md`。
  - **节奏(原样保留)**:单个敌人回合演出**总时长 ≤ 4 s**(一场合计 ≤ 20 s;若每回合演出 8 秒,一场就是 40 秒纯观看,在 30–40 分钟篇章预算下不可接受)· 单步节拍 **0.35–0.5 s** · **超过 4 步后压到 0.2 s** 并**合并同来源、同类型、同符号的连续增量**(跨来源不合并——跨来源正是玩家需要区分的)· 点按屏幕任意处 **3× 加速**(**只能加速不能跳过**,「逐步可见」是硬要求)· 永久快速演出为设置项(默认关,开启后基线节拍 0.2 s)。
  - **删除的只有偏差那一拍**:`≈` 前置与虚线底纹、`≈12 → 8` 的对照标记、「该步额外停 0.4 s 且加速无效」整条移除——**演出中不再有不可跳过的节拍**。(节奏参数原始出处)。
- **ticker 在敌人回合常驻,占用固定预留高度(承重)。**
  - **容器保留固定高度,内容整体清空**:玩家回合该区域是**空的**(没有占位符、灰框、「敌方行动中」字样),但容器高度不变、邻居不移动。工程形态 = `custom_minimum_size.y` 固定的 `Control`,收起时其**子节点**整体淡出,**容器本身不参与布局变化 ⇒ 动画不触发 `Container` 重排**。**这条纪律防的是「手牌区跳位干扰拖拽出牌的肌肉记忆」,与意图无关,故原样保留、只是改挂 ticker。**
  - **「元素上移(回收空间)」排除**:每回合两次重排,手牌区跳位已被明确点名为不可接受。
  - **落位与尺寸**:紧贴道念对比条(与道念对比、剩余回合数同属决策面板一组);尺寸 **≈ 屏高 6%** 为初值(单行文字,比原意图区更矮),**写成百分比 / `SizeFlags` 比例而非像素常量**(`stretch/mode = canvas_items` + `aspect = expand` 下像素常量无意义)。**单行,永不换行**(换行会引起高度变化,与固定高度矛盾),超长文本省略并由展开态承载。
  - **动画**:出现 **0.20 s**(淡入)、清空 **0.15 s**(淡出),**无高度动画**——这正是固定预留的收益。
  - **若实测排不下的压缩顺序**:先压敌方区(立绘可缩)→ 再压栈 / 战场(可做浮层而非常驻)→ **道念对比条最后动**(它是主视觉与核心决策面)。
- **战斗屏再多两个可读对象:本场可用道具区与神通 / 法则条。** 卡牌不再只有一个来源区,呈现层要跟着补:
  - **本场可用道具区** —— 竖屏空间紧张且它不像手牌那样每回合变化,**建议默认收起为一个角标(显示可用道具数),点开为抽屉式面板**,不值得常驻占位。**措辞上不要在战斗语境里称它为「储物袋」**:储物袋是角色的容器(含大量战斗外道具),战斗里出现的只是它的一个筛选视图;**敌人没有储物袋却同样有道具**,也证明这两个概念必须分开。
  - **神通 / 法则条** —— 贴在己方战场区边缘的一排小图标。`Power` 因不可交互,**视觉权重应低于常规永久物**;**但带启动式异能的 `Power` 例外**,它需要一个可点击的启动入口。**详情须长按查看** —— `ui-input-rules.md` 禁止 hover-only 可供性。
  - **埋伏标记（必做项）** —— 对手场上「有一张埋伏」的指示(**只给计数,不给内容**);**双向对称**,玩家与 AI 读到的是同一层信息。**埋伏进入敌人卡池**,故这块指示是必做的。它**挂在战场区**(埋伏是面朝下的战场条目),不与结算 ticker 混住——一个是「场上有什么」,一个是「刚刚发生了什么」。
  - **卡面须呈现类型标识** —— 五类卡牌(法术 / 阵法 / 道具 / 神通·法则 / 业障)靠**卡框色 + 类型角标**区分,**不用纯文字**:竖屏卡面横向空间紧,且「法术 / 法宝」等相邻中文名共用字根,只靠文字读不开。
- **不做「敌人状态可读」的事前补偿(已否决)。** 「以蓄力 / 凝聚 / 破绽等显式状态标记预告敌人下一步」的方案**明确否决**——那是换个名字把事前预告装回来。事前信息一律归敌人图鉴(它会做什么),事中信息一律归逐步呈现(它做了什么)。
- **敌人图鉴给静态知识,不给动态情报。** 账号级敌人图鉴(`systems/player-profile/codex/`)记录「这个敌人**会做哪些事**」;它**不揭示本回合的具体行动**。**这条边界的理由是「事前知识 / 事中情报」的分工**。**图鉴是事前知识的主通道**,故战斗内的查阅入口尤其重要。**战斗内可直接查阅**(点按敌人立绘 → 半屏 bottom sheet,结算 / 选目标态禁用),见下。
- **战后奖励面板是战斗流程的一屏(新增)。** 「获取奖励」属于战斗流程本身,故战斗结束后**在战斗流程内**呈现奖励:**强制部分自动计入**(无需玩家操作,例:`experiencePoint`),**可选部分由玩家从若干候选中择一**——形态**参照 Slay the Spire** 的战后奖励面板。**推论:这是战斗 UX 至今未有的一屏**,且它在返回结果之前,不是事件收口后的另一步。**奖励预先算定,选择不是决策点**——退出重进得到同一组选项,故 UI 不必表达"已存档"。具体形态(候选项呈现、强制项的提示方式、竖屏布局)待战斗 UX 专场。
- **回合不是交互式的:stack 保留、交互与优先权移除（承重）。** 卡牌入栈后按 LIFO 结算,但**没有响应窗口、没有优先权传递**——**"我打完换你打"的简单交替成立**,理由是交互 / 优先权**拉长时长、决策点过多、复杂度高而深度收益小**。**推论 ①:不需要"轮到你响应"这套交互**(何时提示 / 如何 pass / 自动 pass / 超时),竖屏触控上最吃紧的那一环由此消失。**推论 ②:栈仍必须进入呈现层**——虽然玩家不再为"是否响应"读栈,但**触发式能力也入栈**,故栈深可以大于 1(见 `systems/character-profile/deck/`);玩家要看懂"现在有哪些东西在等待结算、以什么顺序",否则触发连锁不可读。**推论 ③:敌人的出牌仍要呈现**(敌人也持有卡组),但只在敌方回合内呈现,不再穿插进玩家回合。
- **回合的三步结构给了 UX 一条明确的时间轴。** **开始阶段**(归属方 mana 恢复至 `manaLimit` → 触发「回合开始时」→ 抽牌)→ **行动阶段**(唯一出牌阶段)→ **结束阶段**(触发「回合结束时」→ 清理回合内状态)。**三步是回合归属方的流程,双方不同时走。** **推论 ①:每回合有三个可被呈现的节拍**——mana 刷满、抽牌、以及结束阶段的触发 / 状态消散,动画节奏可依此编排,不必自创分段。**推论 ②:手牌上限需要在 UI 上可读**——上限是**任何时刻都不得超过**的硬约束(**没有弃牌机制**),故玩家必须能随时看出"我还能拿几张";满手时抽牌的表现要能被看见(见待决问题)。**推论 ③:"轮到谁"是一个必须常驻的指示**,它现在是回合归属权的唯一表达。具体形态待战斗 UX 专场。
- **结算会在中途停下来问「指谁」（承重）。** 触发式异能在栈上若需要选择目标,**那次目标选择是玩家的一次真实输入,也是一个决策点**(见 `systems/services/combat-service.md`)。**推论 ①:结算动画不能是一段不可打断的过场**——它必须能在中途停住、进入一个可交互的选目标态,再继续弹栈。**推论 ②:选目标态需要明确的进入 / 退出信号**,否则玩家会以为战斗卡住了(尤其在连锁触发中,停顿点可能出现在玩家没有预期的时刻)。**推论 ③:这不是「响应窗口」,呈现上必须区分**——玩家此刻不是在决定"要不要插手",而是在补全一个已经在结算中的效果的参数;措辞与视觉都不该暗示这是一次可放弃的机会。**推论 ④:这一步会落存档**,而 UI **不必**为此表达"已存档"(与战后奖励面板同理)。
- **战斗屏多了一个区:战场(battlefield)（承重）。** 场上**正在生效**的卡牌 / 持续状态 / 等待中的触发器落在 battlefield 上,与**栈**(等待结算的队列)是**两个不同的区**。**推论 ①:竖屏要容下三块**——战场 / 栈 / 手牌,再加上道念对比、回合计数与结算 ticker,窄高屏的分区压力显著上升(具体排布待战斗 UX 专场)。**推论 ②:玩家须能区分"已经在生效"与"正在等待结算"**——二者混成一片就读不懂触发连锁。**推论 ③:回合内状态的消散有了可视对象**——结束阶段清理的是战场上标记为回合内的条目,动画有了明确的落点。
- **满手时抽牌的表现:牌抽不进(规则已定)。** 满手时抽牌**抽不进**(牌留在抽牌堆、本次抽牌无事发生),「加入手牌」类效果同理落空——**规则已定,剩下的只是表现形式**。**推论 ①:需要一个"没抽进"的可见反馈**,否则玩家会以为抽牌漏了或界面卡了;**推论 ②:手牌上限本身要常驻可读**(「我还能拿几张」),否则满手是个突然出现的意外;**推论 ③:不会有牌被弃掉或销毁的画面**——上限是纯上界,不产生弃牌堆流量,视觉上不该出现"牌被丢掉"的动作。
- **道念差是玩家可直接换算的账。** 失败时 `lifeTotal` 的扣减量**就是道念差**(1:1),故战斗屏上的「我落后 8 点」同时就是「输了要掉 8 点 lifeTotal」——**这条 1:1 关系让主视觉的价值大增**:玩家不需要额外的教学就能读懂风险,也让「道念差是否显式呈现」这个问题的答案更倾向于「显式呈现」。
- **回合数不是固定的 10。** 10 回合是 **`Standard` 档的标准值**;`Practice` / `Finale` 档可改写回合数与胜负条件。**推论:「还剩几回合」的呈现必须由本场遭遇的配置驱动**,不能把 10 写死进 UI。
- **敌人等级的展示措辞。** **面向玩家一律用「境界名 + 层级」,全局序 1–22 不出现在任何 UI 上**(例:「筑基中期」「炼气十三层」)。
  - **理由(最强的一条):境界名让 `baseMomentum` 的跨度断层可读** —— 「筑基巅峰 vs 金丹初期」一眼就是跨境界,而跨境界正是起跑线的量级跳变处(32 → 45);「17 vs 18」看不出来。**起跑线就是「这场有多难」的唯一刻度**,故让它可读是等级展示的全部目的;全局序是内部比较刻度,不是玩家词汇。
  - **`EventOption` 的战斗类卡片上并列显示双方等级**(`我 · 筑基中期 ⟶ 敌 · 筑基后期`)——把比对成本降到零,而不是要求玩家记忆。
  - **战斗屏内敌人区常驻一行敌人境界名,但不并列玩家自身等级、不常驻**(玩家知道自己是谁;竖屏空间已是本作压力最大处),需要时在角色面板查看。
  - **不做方向标记**:`↑` / `=` / `↓` 一类由两个等级机械导出的符号**一律不加**——它同时把「日后被扩成三色 / 加文字 → 滑向模糊危险度档位」的风险从根上掐掉。任何主观危险度词汇(「略强」「凶险」「无从揣度」)照旧被否决。
  - **已知代价**:境界名不利于表达带内细微差(ch2 · ch3 只有四个层级名,`diff = ±1` 就是相邻两个词,玩家读得出差一档但读不出「差一档意味着 `baseMomentum` 差多少」),且比对成本回到玩家自己身上——**接受**,这正是「精确标注、不做主观解读」的直接体感。
- **选目标态的呈现形态。**
  - **规则层先削掉一半的进入次数:合法目标集合大小为 1 时自动选定,不进入该态、不产生决策点、不落存档。** 这条**一并缓解三个问题**(连锁打断次数 / 决策点密度 / 操作疲劳),是本节最有价值的一条,**且它是规则层的、不只是呈现层的**。(合法目标为 0 时按既定的效果落空规则处理,同样不进入。)
  - **进入信号** = 全屏低透明度**暗幕**(≈45%)0.15 s 淡入,压暗一切非决策必需元素;**道念对比条与栈区豁免不压暗**——前者是判断「该指谁」的依据,后者是「队列里还剩什么」的唯一来源。**暗幕因此是「压暗除决策必需信息外的一切」,不是字面的全屏。**
  - **来源指示**:栈上的该条目**上浮 + 放大 1.1× + 描边**,一条引导线连向指令条——**连锁中玩家必须知道「是谁在问」**,否则第三次弹出时完全失去上下文。**指令条位置绝对固定**(屏幕中部偏上,道念对比条与栈之间),每次进入同一位置、同一套视觉:**节奏可预期 = 不迷失**。
  - **合法目标**不被压暗 + **描边呼吸动画**(1.2 s 周期,静态描边在小屏易被忽略);**非法目标随暗幕压暗、点击无反馈**——压暗即答案,**不做「点非法目标弹提示」**(连锁中反复弹提示是噪音)。退出总时长 ≤ 0.4 s。
  - **指向手势 = 单点即确认**,不用拖拽连线:拖拽要求精确的起点落位与长路径,而起点(栈条目)在屏幕中上部、终点可能在顶部敌方区或底部手牌,**竖屏单手拇指跨不过去**;连锁中可能连续进入 2–4 次,**任何多余的操作都要乘以次数**。**也不做二次确认**——误触代价用「目标足够大 + 呼吸描边足够醒目」化解,而不是用二次确认换(那把每次操作翻倍)。**误触不做保护**(与「玩家主动退出静默处理」的手感取向同向);**已知代价**:一次误触在连锁中可能改变结算结果,且该步已落存档、退出重进也回到误触之后。**退让位**:若实测误触率高,退到「点选 + 确认键」,且只在合法目标 ≥ 4 个时启用。
  - **连锁中不迷失的四条**:① **连锁进度可见** —— 指令条第二行常驻 **`还有 N 项待结算`**(= 栈深,**永远可算**;不用「还有 N 项待选」——后者要求预知后续条目是否需要目标,而那依赖前面的结算结果,未必可精确预知)。**这是把「不可预期的停顿」变成「有限的、可数的停顿」,是四条里最关键的一项。** ② 位置绝对固定。③ **连续两次之间不完全淡出暗幕**(只交叉淡变来源高亮与文案,0.2 s)——避免全屏明暗闪烁,同时让「这是一段连续结算」在视觉上成立。④ **栈区保持可见且不被压暗**。
  - **措辞与「响应窗口」严格区分(三条禁令)**:文案用「选择一个目标」「指定」,**不用**「是否响应 / 跳过 / pass / 等待你的回应」;控件上**无取消键、无跳过键、无「不使用」**;**无倒计时、无超时自动选**(倒计时暗示「不选也会过去」,与「不可放弃」矛盾)。
  - **硬要求:选目标态必须自解释。** 玩家可能退出后隔几小时回来,正对着一个「请选择目标」的界面——呈现层必须交代**是哪张牌 / 哪个异能在要求选目标、它要做什么**,**不能依赖玩家的短期记忆**。恢复语义(回到该选择点、栈原样挂起、不允许反悔)见 `systems/services/combat-service.md`。
  - **道具使用后若需目标,直接进入这同一套形态,不另做一套。**
  - **整套形态与其频次相称,不因低频而削减。** 它服务的是「需要选目标的触发式异能 ≤ 10%、一场期望进入 1~2 次」的场景,而**这正是本作少数几个真正的战斗内交互时刻——密度低是它有分量的原因,不是削减它的理由**。暗幕 / 呼吸描边 / 固定指令条 / 连锁进度 / `pending` 存档形态**全部保留**。
- **战斗内的道具视图称「随身」,不称「储物袋」(形态落定)。**
  - **默认收起为角标**(小图标 + 本场可用道具数),贴在**己方战场区边缘**,与神通 / 法则条**分居两侧**——两者都是「己方的非手牌资源」,**对称落位让玩家一次学会两处**。
  - **点按 → 底部抽屉(bottom sheet)**,高约屏高 40%,其余半透明压暗:底部是竖屏拇指可达区,且抽屉是移动端母语控件、不需要教学。
  - **抽屉内 = 横向滚动的一行**(不是网格):本场可用道具通常 ≤ 8 件(`UsableScene` 筛出的子集远小于 99),一行足够;**与 EventOption 选择区的横向滑动手势一致**,玩家复用同一套肌肉记忆。
  - **不可用项灰显 + 长按给原因**(mana 不足 / 非行动阶段 / 栈非空)——**灰显即答案,不做点击弹提示**。**使用流程**:点按选中 → 抽屉自动收起 → 若需目标则**直接进入选目标态**(复用同一套形态)。
  - **敌人回合 / 结算中:角标置灰、抽屉入口禁用** —— 使用窗口是全局规则,UI 应把它表达为**可供性的有无**,而不是让玩家点了才被拒。
  - **⚠ 竖屏分区压力**:己方战场区左右两侧同时挂法则条与随身角标会挤压战场本身的可用宽度,**需在实际排版时验证**。
  - 元进程侧的储物袋落位与全屏面板形态见 `ux/screen-flow.md`。
- **战斗内可查阅敌人图鉴,入口挂敌人立绘。** 点按敌人立绘 → 半屏 bottom sheet(与「随身」抽屉**同一套控件语言**);**结算过程中 / 选目标态中禁用入口**、不暂停战斗、只读。**⚠ 点按语义冲突须在实现时明确优先级**:立绘同时可能是选目标态的合法目标——**选目标态中立绘的点按语义被该态独占**,非选目标态时点按 = 开图鉴。词条内有一条**动态页眉**「本次遭遇:筑基后期」(只在战斗内出现,只写境界名 + 层级、不写方向标记)。写作规格见 `systems/player-profile/codex/enemy-codex.md`。
- **静默退出的告知责任落在战斗屏。** 玩家主动退出**不做二次确认弹窗**(手感优先,不在最频繁的操作上加模态);代价是「进度保留在当前决策点、成本不退还」这条规则玩家看不见——**须由战斗屏的常驻措辞或首次退出时的一次性提示承担告知,不是弹窗流程**。
- **进入战斗前的同步失败不产生任何额外提示。** 告知由**常驻的「离线 · 待同步 N」指示**承担——**该指示在战斗屏内必须可见**(这是本条成立的前提)。理由:断线期间**每一场**战斗的入口都会命中这条路径,在此弹 toast 等于把一次性的网络状态变成**逐场重复的打扰**,且时机恰是玩家最专注处。**这与「静默退出的告知责任」是同一条纪律的第二个实例**:不在最高频操作上加提示,告知由别处的常驻呈现承担。**边界**:真正需要打断玩家的情形仍由既定机制承担——缓冲超限的软阻塞模态(下一次事件选择前)与两处硬阻塞(启动 pull 失败、被挤下线)。规则侧见 `systems/services/sync-service.md`「`Immediate` flush 的失败语义」。
- **寿元红字倒数不进战斗内。** 寿元告警的呈现位置已定为 **EventOption 选择界面**的静态标注,**不常驻战斗屏幕**、不做全局 HUD。见 `ux/screen-flow.md`。

## 待解问题
> _尚未解决,需要一次 handoff/决策。_

- **回合进度与道念差的组合呈现。** 「还剩几回合」与「差多少道念」共同决定紧张感;二者是同屏两个独立元素,还是合成一个「还追得回来吗」的复合指示?未定。
- **结算 ticker 的文案体系（承重）。** ticker 是**唯一**的动态情报通道,故它写什么、写多细直接决定敌人回合是否可读。仍待定:一行文案的信息量(「敌方打出 X」还是「敌方打出 X,你 −5」)、连锁触发如何在单行内表达、展开态的分组与排版、以及**它与飘字的分工边界**(哪些信息只在飘字给、哪些必须进 ticker)。排布约束已定:单行、永不换行、固定预留 ≈ 屏高 6%。
- **道具区 / 神通法则条 / 埋伏标记 / 类型标识的具体形态。** 四者的落位与视觉语言已定方向(道具 = 角标 + 抽屉、`Power` = 低权重小图标条且长按查看详情、埋伏 = 只给计数、卡牌类型 = 卡框色 + 类型角标),**具体形态未定**:竖屏已要容下战场 / 栈 / 手牌 / 道念对比 / 回合计数 / 结算 ticker 六块,再加这几项后的分区排布是本作竖屏压力最大的一处;带启动式异能的 `Power` 那个可点击入口如何与「视觉权重要低」并存亦未定。→ 待战斗 UX 专场。
- **竖屏分区整体是否过载(承重)。** 六个区 + 若干挂件已在本文件累计出现多处 `⚠ 竖屏压力最大处 / 需实际排版验证` 的标注。**根子是把 MTG 的完整分区模型搬进手机竖屏**;尤其**栈在零交互下玩家做不了任何事、只能看**,它是否必须常驻(而非结算时的临时演出层)值得重估。**→ 已排期：单开一个专门 session 答疑**,不在逐次 handoff 中零敲碎打。
- **道念对比的视觉形态。** 主视觉地位已定;**用什么形态**(左右对比条 / 双数值 / 天平隐喻)、道念变化时的反馈(数字跳动 / 特效)、以及「道念差」是否显式呈现(它决定失败时扣多少 lifeTotal,而 lifeTotal 归 0 即角色终结)均未定。→ 亦见 `systems/scoring.md`。
- **lifeTotal 在战斗屏幕上的位置。** 已定「退居次要」;但**是否仍常驻显示**(作为「失败会掉多少」的参照)还是完全移出战斗屏,未陈述。
- **战后奖励面板的形态。** 强制项与可选项如何同屏区分(自动计入的部分是否也要展示"你获得了什么")、可选候选的数量与竖屏排布、选择是否可反悔、以及它与"事件收口"之间的视觉衔接均未定。
- **栈与战场的同屏呈现(承重)。** 触发式能力入栈使**栈深可以大于 1**,故栈**必须**可见;**此外还有一个战场区**(正在生效的卡牌 / 持续状态 / 触发器)。仍待定:竖屏小尺寸上如何**同时**表达"哪些东西在等待结算、以什么顺序"与"哪些东西已经在生效"、两区如何在视觉上区分、连锁触发的结算动画如何不拖慢节奏、玩家能否在结算过程中查看条目详情。→ `systems/character-profile/deck/`、`systems/services/combat-service.md`。
- **三步结构的呈现细节。** 开始阶段的 mana 刷满与抽牌是否各有独立节拍与动画、**"没抽进"的反馈形态**(规则已定为抽不进,表现未定)、**手牌上限的常驻可读形态**、**回合内状态消散**如何被看见、以及"轮到谁"的常驻指示形态,均未定。→ `systems/services/combat-service.md`。
- **疲劳的呈现。** 抽牌堆不重洗、抽空后每抽一张 −1 道念(见 `systems/scoring.md`),故需要:**抽牌堆剩余张数是否常驻**、见底前是否给预警、以及疲劳扣减的动效如何与"被对手削减"在视觉上区分——两者都是自己的道念下跌,但归因完全不同,混淆会让玩家误判局势。
