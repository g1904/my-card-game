## 判「不是过度设计」原样保留（6 条）

- **道统残卷的可验证性** → **不简化。** 它是**分发账户级加强的核心算法**，「不给玩家任何提示」的隐藏性正是设计初衷——它要在幕后调控账户级进程，而非成为可优化的曲线。「玩家学不到 ⇒ 设计失败」这一前提不适用。三张分档表 / 五阈值 / 万分比精度全部保留，**不减档、不做任何形式的进度可感化**。（`systems/player-profile/player-power/_index.md`、`systems/balance.md`）
- **隐藏属性 12 档 + 回滞 δ 当前没有消费者** → **有消费者，且是全覆盖的。** **所有事件都有可能推拉这三个属性，不限事件类型** ⇒ 调制的分辨率需求真实，结构不是先于内容而定。**另附硬度裁定：允许携带、非强制携带**（不填 = 不推）。（`systems/services/plot-manager.md`）
- **决策点密度是否过高 / D2 是否该进清单** → **保留 D2。** 预写的「第一刀砍 D2 的 push」作废——D2 兑现的是「退出重进得到同一局面」，在强制在线 · 云端权威下这是玩家对存档的基本信任，不是可牺牲的性能余量。≈31 个决策点 / 场、≈93 KB 本地写照旧接受。（`systems/services/combat-service.md`）
- **挂起态 / 选目标态整套 UX 是否与频次相称** → **相称，全部保留。** 它服务的是本作少数几个真正的战斗内交互时刻，**密度低正是它有分量的原因**，不是削减理由。（`ux/combat-ux.md`）
- **`itemPowerRatio` 四档折价的可验证性** → **没有问题。** 它与战斗内法则的强度上沿同属**暂定平衡机制的软标准**，作用是在量纲出现前给内容侧一个相对刻度，ch1 数值标杆专场回归校准即可，**分层保留**。（`systems/balance.md`）
- **meta 层：设计密度远超实现进度** → **没有问题，无需处理。** 不中断设计去先落最小可跑的战斗回路；「设计先行」照常执行。（`vision/scope.md`）

## 判「确有问题」并当场改掉（2 条）

- **战斗内法则 ≤10% / 合计 ≤25% 闸门落在阶梯第 4 级却被当承重结论** → **降格表述。** 两个数保留但改写为**内容评审参考上沿**，删去「可执行形态」措辞与承重挂载；承重的只剩定性定位（偏体验改善与容错、不抬高道念产出上限）。**不补代理指标**（代理量与真实量的偏差同样不可验证）。（`systems/balance.md`）
- **`IgnoresProtection` ≈1% 的成本 / 收益不相称** → **两侧都动。** 编排规则 **5 条砍到 2 条**（只留 R1 仅挂 boss 档载体、R2 绝不挂玩家可主动获取的内容；原篇章配额 / 轮回内至多一次 / 加载期核对表全删）+ **目标频次 1% → ≈5%**。**连带：`CycleState` 上那个轮回级 bool 一并删除 ⇒ 该机制完全退回内容编排层、不落代码。**（`systems/balance.md`）
