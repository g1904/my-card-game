**手牌达到上限时如何处理（承重）** → **满手时抽牌抽不进**：牌留在抽牌堆，本次抽牌无事发生；「加入手牌」类效果同理落空。「抽出即弃」「直接销毁」两条路线均不采用。⇒ 手牌上限是**纯上界**，不产生弃牌堆流量、不消耗抽牌堆；弃牌堆只由「打出后进弃牌堆」与「卡牌效果显式弃牌」填充；满手的代价是 tempo 而非资源。（`20-systems/character-profile/deck/_index.md`、`20-systems/services/combat-service.md`、`20-systems/adventure-event/combat/_index.md`、`terminology.md`）
　*剩余部分仍待答：* **上限的数值**、敌人侧是否同值；以及「加入手牌」落空时**凭空生成的牌**（token / 从弃牌堆取）去哪。

**触发式效果的载体形态（承重）** → **载体开放，不专属卡牌**：牌上的触发器 / 场上的持续状态 / CharacterPower（神通）都可能承载，清单可再增。⇒ 需要统一的触发注册 / 匹配面（坐在 battlefield 上）；压栈者恒为 StackManager，与载体解耦；轮回级能力必须能被战斗内读到（参战方组装时把神通注册进战场）。（`20-systems/services/combat-service.md`、`20-systems/character-profile/deck/_index.md`、`power/_index.md`、`20-systems/adventure-event/combat/_index.md`）
　*剩余部分仍待答：* 触发条件能否跨归属方（「对手的回合开始时」）；PlayerPower（法则）能否也承载战斗内触发。

**多个削减效果同时在栈上时「道念下限 0」的截断时机（承重）** → **在每一次结算时截断**，不是全栈结算完后统一截断；溢出的削减量不结转。⇒ 更保护落后方（对方道念 5、栈上「削 8」+「+3」：逐次截断得 3，全栈后截断得 0）；**LIFO 顺序对最终结果有实际影响**；`PlayResult` 必须携带本次实际削减量。（`20-systems/scoring.md`、`20-systems/services/combat-service.md`、`20-systems/character-profile/deck/_index.md`、`terminology.md`）

**敌人赋级的等级差上界（承重 · 内容侧硬约束）** → **上界 = 比角色当前境界高一个大境界的初期**（炼气 → 最高筑基初期，筑基 → 金丹初期，金丹 → 元婴初期）。⇒ 上界按**境界**给而非按 `diff` 给；上界档必然越阶 ⇒ 必然完全黑箱（最难的遭遇即最不可读）；元婴无更高境界。（`20-systems/services/future-event-service.md`、`20-systems/balance.md`、`20-systems/adventure-event/combat/_index.md`）
　*剩余部分仍待答：* **上界与 lifeTotal 的算术冲突**（炼气一层对筑基初期 = 落后 19 > lifeTotal 10）；赋级的**分布规则**；Finale 的天劫是否同受此上界。

**战斗内「场上」缺少建模** → **引入 battlefield（战场），并新增 BattlefieldManager 与 StackManager 两个 manager**。战场记录场上全部准确数据（生效中的卡牌 / 持续状态 / 触发器注册面）；栈与战场是两个区（栈 = 等待结算的队列，战场 = 已结算并正在生效的东西）。⇒ 结算路径补全为「打出 → 入栈 → LIFO 结算 → 效果施加 →（若持续）落到战场」；「回合内 / 跨回合状态」有了承载结构；TurnManager 回落为纯粹的回合状态机；combat-service 的 manager 由三个增至五个。（`20-systems/services/combat-service.md`、`_index.md`、`20-systems/architecture.md`、`program-overview.md`、`20-systems/adventure-event/combat/_index.md`、`40-ux/combat-ux.md`、`terminology.md`）
　*剩余部分仍待答：* 战场与两个参战方 manager 的边界划线；战场 / 栈的存档形态。

**power / item 两层四个概念的中文定名** → **法则（PlayerPower）/ 古宝（PlayerItem）/ 神通（CharacterPower）/ 法宝（CharacterItem）**，取代「玩家能力 / 玩家道具 / 角色能力 / 角色道具」；**「`power` 的中文通译 = 能力」（07-30b 定）作废**。⇒ 中文名不再表达层级对称，账号级 ↔ 轮回级只在英文标识符上成立，UI 文案不能靠中文名传达层级；图鉴族五本随之改名。（`terminology.md`、`20-systems/player-profile/`（`_index.md`、`player-power/`、`player-item/`、`codex/`）、`20-systems/character-profile/`（`_index.md`、`power/`、`item/`）、`20-systems/_index.md`、`40-ux/screen-flow.md`）
　*剩余部分仍待答：* `CharacterItem` 与既有 `List<CharacterItems>` 的单复数是否统一。
