## 逐条

**flags 数据源与灰度分桶的运营形态（余下部分）——规则存在哪 / 由谁改 / 按账号计算是否需要缓存层** → **三问全部答结**。① 规则存在哪：后端主事务性存储中的一条**不可变版本化记录**（含 `bucketSalt` 与 `contentFingerprint`），高水位另存一条单行记录，插入与推进同一次事务；随发版走的配置文件与控制台自带独立存储双双出局。② 由谁改：唯一写入面是 `publish(draft, summary, scope)`，`rollback` 是它的一次调用；直连库写规则集在权限上被禁止（应用身份 `INSERT`+`SELECT`、人类身份 `SELECT`）；人机接口取 CLI / 脚本 + 文本规则草稿进版本控制；`publishedBy` 必须解析到具名人类身份；配套一条爆炸半径闸（解析结果规模较上一版新增 > 20 条即需显式确认，**后端只数 `Id` 个数、不感知内容类别**）。③ 缓存层：**不引入按账号的解析结果缓存**，改为缓存规则集本身（键 = `flagsVersion`、值不可变、永不需失效逻辑、single-flight 收敛冷启动），并写下日后引入的触发判据（p99 > 50 ms 或端点 CPU > 5% 且瓶颈确在分桶计算）与强制键形态 `(flagsVersion, accountId)`。连带定下：flags 应答逐账号签名 ⇒ 按 `(flagsVersion, accountId)` **缓存签名结果**（缓存的是 `sig` 而非 `disabledIds`）；flags 读路径不受读己所写约束，但当前拓扑取「玩家读路径全走写入区」，该自由度只留档。（归档去向：`operations/content-delivery-ops.md`「已有具体对象的运维面：内容分发」）

**签名私钥的保管与 CI 签名步骤（含 `keyId` 轮换的触发条件与节奏、「覆盖率足够」的口径）** → **全部答结**。保管形态给出五条能力判据：私钥不可导出 · 逐次签名可审计 · 原生 ECDSA P-256 + SHA-256 且能并存多把 · 签名权限授予流水线身份而非个人 · **可用性与 flags 端点同档**（草稿原写的「不在任何请求路径上、可用性低一档」不成立——flags 应答走同一密钥体系、按账号签名，该密钥在玩家读路径上；仍低于会话 token 密钥）。CI 环节定为七步 + ③b 编码归一的发布流水线，新增承重步 ⓪ 产物认证核对与 ④ 用**客户端内置公钥**自验。轮换：三类触发（计划 12 个月 / 紧急即切 standby / 客户端发版加入新公钥不构成触发）、四阶段（预置 → 等覆盖 → 切签名 → 旧 `keyId` 不主动移除）、覆盖率 = 过去 N 天有过请求的账号中 `appVersion ≥ 引入新公钥的版本` 的比例（数据源为已有的 `X-App-Version`，零新增报文），N = 7 天、阈值 95%，T2 后 48 小时观察窗口且回切安全。另两条：**首版即内置 active + standby 两把公钥**（兑现契约已写的「一组 `keyId → publicKey` 映射」，报文零改动；客户端侧承接项跨库对称落笔）· **standby 私钥 = 同一密钥服务内的独立密钥**（独立密钥 ID / 权限策略 / 审计线，签名权限平时不授予任何身份）。（归档去向：`operations/content-delivery-ops.md`；`sig` 编码补注去向 `contracts/content-manifest.md`「防篡改」）

**发布侧内容校验闸的运维形态——在哪一步跑 / 由谁触发 / 失败如何阻断 / 是否留痕 / 与签名的先后** → **五问全部答结，并新增一条实质要求**。本库那一半的正确形态不是「再跑一遍校验」（会造出第二份实现随时漂移），而是**发布流水线拒绝任何没有打包工具背书的文件集**：用产包证明与待推文件集的逐文件 hash 一一对应比对，把对侧的闸延伸到发布面。① 位置：最前，推 blob 之前。② 触发方：流水线自身、无条件、**不设跳过开关**（break-glass 若日后必需，须与 O5 同构留痕并告警）。③ 阻断：该步非零退出，①–⑦ 全不执行，无需任何补偿动作。④ 留痕：内容发布留痕八字段，与 flags 留痕同构但不合并，含单列的 `gateAttestation`。⑤ 与签名的先后：**校验先于签名**——签名即背书，先签后验会产生「已签名但不合格」的产物，它一旦离开流水线在密码学上与合法产物无法区分；推论是签名为流水线上最后一个产生可分发产物的动作。**新增要求 C6 基线漂移**：闸须对兼容矩阵内每一个 ≥ 本次 `minAppVersion` 的在架基线各跑一遍，并要求发布侧能取到每个在架版本的基线内容快照（部署侧落点归 `operations/deployment.md`）。（归档去向：`operations/content-delivery-ops.md`）
