## 内容管线 / 热更（6 条，整组移出）

- **只改不增的内容节奏代价 —— 是否预埋占位 `Id`？** → **否决预埋占位 `Id`**（与合并后强校验冲突 + 应用商店审核灰区）。改为内容随版本发布、由 overlay 翻 **`ContentEnabled: bool`（默认 `true`）** 开关放量；**过滤只在产出侧**（抽取走 `AllEnabled()`），读取侧 `Get(id)` 不过滤。能力边界如实记录：压缩的是**放量时机**而非**发版节奏**，换来灰度 / 分批放量 / 线上秒关。（`systems/services/content-service.md`、`systems/common-properties.md`、`.claude/rules/data-resource-rules.md`）
- **放弃跨版本 seed 可复现的连带影响 —— 是否记录 `contentVersion`？** → **记两个**：`StartContentVersion`（写一次不变）+ `LastContentVersion`（每个自动存档点更新）；二者不等 = 该轮回跨过内容更新，是数值突变类反馈的第一判据。push 信封同带 `contentVersion` / `appVersion` / `revision`。**不为每日种子 / 排行挑战预留冻结结构**（不在中期路线图内），仅留方向性记录。（`content-service.md`、`character-profile/_index.md`、`vision/scope.md`）
- **增量下载的粒度与失败恢复。** → **文件级粒度 + 文件级事务**（不做字节级断点续传）。`overlay/` ⁄ `overlay.manifest.json`（提交点）⁄ `overlay.staging/`（可脏）三段式；全集齐备且校验通过才搬入，最后**原子写 manifest = 提交点**；任一步失败即清空 staging、视为本次更新未发生。**永不存在半套 overlay。**（`content-service.md`）
- **overlay 防篡改。** → **做 manifest 签名**：后端私钥签、客户端内置公钥验签，逐文件完整性由已签名 manifest 内的 hash 保证。失败 → `GD.PushError` + 回退 `res://` 基线 + 上报。**边界：防误 / 防随手改，不承诺防作弊。**（`content-service.md`）
- **断线降级的具体行为。** → **总原则：绝不回退存档点。** Push 失败 → 不阻塞玩家、进 `user://cache/pending/` 待发队列重试；Pull 失败 → 硬阻塞（不提供本地缓存开局）；剧本请求失败 → 事务前置、Profile 零变更。缓冲上限**存档点 ≥ 3 或滞留 ≥ 180 s** → 软阻塞（下一次 AdventureEvent 选择前弹模态）。恢复后**先 pull 再 flush**，云端 `revision` 领先则丢弃本地缓冲并明确告知玩家；不做静默合并 / 三路合并。（`sync-service.md`）
- **RNG 状态的持久化形态。** → 子流按 `Hash64(CycleSeed, streamName)` 派生；存档 schema 挂 `CharacterProfile.Rng`（`CycleSeed` + `streams[{name, seed, state, drawCount}]`）。**`State` 是恢复权威字段**（O(1) 回填），**`DrawCount` 是诊断与迁移保险**（引擎语义变更时 fast-forward 重放）。子流清单为 `SeedManager` 常量，增删不 bump schema。**防 re-roll：** 战斗内随机每场再派生 `Hash64(combatStreamSeed, eventId, attemptIndex)`。（`systems/common-properties.md`、`character-profile/_index.md`、`life-cycle-service.md`）
