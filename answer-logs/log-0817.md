**refresh 失败的两条路径（承接自 `contracts/auth.md` §10 末段）** → `RefreshToken()` 的失败拆为两行表：**网络失败**（发不出 / 收不到 / `server.unavailable`）视同断线走 sync 缓冲通道、进行中的轮回不被打断；**收到 `auth.session_revoked` 应答**则硬阻塞重登并**暂停退避重试**（重试必然失败）。
**判据钉死为「收到了明确应答」，不是「失败了」**——弱网下「服务端拒绝」与「应答没收到」不可区分，误判成硬阻塞的代价（把只是信号差的玩家赶去重登）远大于多退避几次。同批记下 API 面**无需扩签名**：`RefreshTokenAsync` 已返回 `OpResult<Session>`，失败侧带 `OpError` 与 `code`，分流所需信息本就够——风险纯在措辞。
