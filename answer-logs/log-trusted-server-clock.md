## 移出的条目

**可信服务端时钟** —— 未成年时段判定的时间源不得依赖设备时钟；时钟源的形态（NTP 层级、跨区域一致性、时区与法定节假日表的数据源）待定
→ **五问逐条落定：**

1. **哪一个时钟** —— 基准 = 该次判定所在事务的**数据库时钟**，不取容器进程时钟。单主库是全库唯一的串行点，取库时钟即天然得到全站唯一基准；判定本就在已握账号行锁的事务里，零额外开销，且判定与写入看到同一个时刻。两处例外明写：token 的签发 / 到期时刻从会话状态派生 · JWT 验签用验签侧进程时钟。
2. **多副本一致性 / 跨区域** —— **在当前拓扑下不存在**（单区域、不做跨区域多活、只读副本不承接玩家读路径）。记为「已消解」，避免下一次重新设计一套跨区域时钟同步。
3. **如何保持准确** —— 内网 NTP 授时 + 常驻守护进程 + **只 slew 不后跳**；超出渐进修正能力即告警人工介入。**不可逆动作（注销执行）在时钟异常期间暂停一轮**，时段与 ticket 判定照常。
4. **时区口径** —— `Asia/Shanghai`，用 IANA 名不用固定偏移，**随时段规则集同版本发布**而非落单值旋钮表；镜像内置 tzdata 并作为启动断言（解析失败即拒绝启动）。时段规则集本身走昵称词表那套**不可变版本化发布**（存量审计必须能回答「这次拦截按哪一版规则做的」），零新增机制。
5. **法定节假日表** —— **人工录入、随规则集一次发布，不接第三方接口作判定输入**；日历必须有两类条目（法定节假日 / 调休上班的周末），减法排在判定顺序最前；覆盖末日距今不足 60 天即工程告警——这是日历失效唯一的机制发现面。年度录入登记为周期性运维日程项，不并入建号前置清单。

**降级语义**（原条目的第五问）：时钟异常 → 判定照常 + 告警 + 暂停不可逆动作；规则集读取失败与日历过期 → 对**未成年账号 fail-closed**，成年账号不受影响；降级路径下的解除时刻取基础周规则下的下一个允许时段起点，报文形状完整、零契约改动。

## 同批裁决（随本次移出一并定案）

- **日历过期时对未成年账号取哪个方向** → 一律拦截（fail-closed），与规则集读取失败同处置。错误拦截可回收、错误放行不可回收；日历过期已被提前 60 天告警过，是可预防的运维失职，不为它设计一条会产生合规风险的降级路径。**降级路径因此只有一条**——两条降级路径必然有一条长期没被走过，因而是坏的。「按基础周规则继续判定」被否决：每年约 6–8 天的调休工作日会被错误判为可玩，方向正是不合规的那一侧。
- 连带确立一条通则：**fail-open 是默认，例外的判据是「错误放行的代价不可回收」**——写成判据 + 实例清单（不写个数），使下一个例外出现时有据可依，不必特事特办。
