**Finale 失败后能否存活并照常完成篇章？** → 不能。失败即 `defeated`、本篇章不推进；渡劫的胜负就是篇章推进的闸门。（`systems/adventure-event/combat/_index.md`、`systems/game-progression.md`、`decisions/ADR-0004-realm-checkpoint-retry-model.md`）

**`DefeatReason` 如何表达 Finale 失败？** → 新增 `FinaleFailed`（枚举四值，只增不删、code 不复用），并在终态判定上补一条显式旁路——它不是资源触底，塞不进 `ResourceElements` 表。（`systems/architecture.md`、`systems/services/life-cycle-service.md`、`systems/character-profile/_index.md`、`systems/character-profile/life-total.md`）

**Finale 档 `0 <= d < WinMargin` 这段区间算胜还是败？** → 归入胜利侧、奖励取最低档。判定二值化为 `d >= 0` 通过 / `d < 0` 失败。（`systems/adventure-event/combat/_index.md`、`systems/services/combat-service.md`、`systems/scoring.md`）

**「奖励最低档」要不要新造一条奖励线？** → 不要。既有的线性强制奖励（`d = 0` 加成为 0）与归一化 `advantage` 三档（该区间整体落 `Tier.Narrow`）已自动兑现。（`systems/adventure-event/combat/_index.md`、`systems/balance.md`）

**`CombatOutcome.Draw` 的可达面？** → 收为**仅 `Standard` 一档可达**；`Practice` 与 `Finale` 两端各自退化。（`systems/adventure-event/combat/_index.md`、`systems/services/combat-service.md`、`systems/services/future-event-service.md`、`systems/scoring.md`）

**Finale 侧的 `WinMargin`（初值 3 / 5 / 8）如何处置？** → 删除。胜负线固定为 0 后它已成死结构。（`systems/balance.md`、`decisions/ADR-0002-adventure-event-taxonomy.md`、`systems/adventure-event/combat/_index.md`）

**Finale 失去唯一难度旋钮，补不补新旋钮？** → 不补。如实写下「Finale 的难度不再有专属旋钮」并给出三条替代校准手段（天劫赋级带位置 / 定制卡组强度 / `TurnLimit`），归 ch1 数值标杆专场。（`systems/balance.md`、`systems/services/plot-manager.md`）

**ch3 重试上限 1 是否随之放宽？** → 维持 ∞ / 3 / 1（付费 ∞ / 9 / 3），不做补偿；ADR-0004 的 Consequences 明写免费档在终局的容错次数。（`decisions/ADR-0004-realm-checkpoint-retry-model.md`）

**Finale 失败时那笔按道念差 1:1 扣的 `lifeTotal` 还扣不扣？** → 照常扣，合进 `eventEnd` 那一次 `TryApply`，只是不再是死亡判据。（`systems/adventure-event/combat/_index.md`、`systems/services/life-cycle-service.md`）

**残卷账号级写入与角色终结的先后？** → 残卷 `Accumulated` 累加必须在角色终结提交之前完成；顺序颠倒会使该机制 100% 静默失效。（`systems/services/life-cycle-service.md`、`systems/player-profile/player-power/_index.md`、`decisions/ADR-0004-realm-checkpoint-retry-model.md`）
