**阵法（`Enchantment`）上启动式异能的 UI 宿主是什么——玩家从哪里、用什么手势发起一次 `ActivateAbility`？** → 已答定：宿主 = **己方战场区内该阵法条目自身**，**长按**升起 bottom sheet、「详情 + 启动」合一；启动区逐行映射服务算好的那一格（异能名 / 费用 / 剩余次数 / 启动键，不限次时整格不渲染，灰态长按给原因），呈现层不重演规则；被拒只回原态、不弹 toast，文案走 `COMBAT_` 分区；动词取「启动」。可发现性 = 条目上的静态启动可供性标记，**与 `Power` 侧共用同一套**并带两态（有启动式异能 / 此刻至少一条可启动）。需目标时弹层收起 → 进入既有选目标态、按 `slotIndex` 一次收齐。己方面朝下条目照常有启动入口，对手侧与敌方阵法不渲染任何条目级入口或标记。**入口的禁用规格与 `Power` 弹层 / 随身抽屉完全同规格**（敌人回合 / 结算中 / 选目标态一律禁用整个弹层入口）。零服务契约改动、零 schema 改动、零存档迁移、零新增区。（归档于 `ux/combat-ux.md`「启动式异能在阵法上的宿主」一条与「持有物两层」一节末的边界句。）

**本次一并裁决、但原不在待答清单上的一项（不计入移出条数）：**

**详情弹层在敌人回合 / 结算中能否打开为纯只读？** → **不能。** 三态一律禁用整个弹层入口，阵法与 `Power` 弹层、随身抽屉完全同规格。禁用理由是**半屏弹层争屏幕**，与内容是否只读无关；「纯只读不是豁免理由」这条判据的辖域不变。被接受的代价：敌人回合与结算中无法查阅战场阵法的规则文字，可读性由飘字与战报因果树承担。
