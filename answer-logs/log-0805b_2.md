## 移出（已答定）

- **上限达成时给几个 Travel 选项（⚠ 单数措辞的歧义）** → **取宽松读法 = 多个并列的 Travel 选项**，各指向 `locationMap` 上当前 location 的一个邻接地域，**「去哪」本身是一次真实的玩家决策**。**推论：闸门是逐批择一的线性进程里唯一一个带地理含义的分岔点**，也是玩家把跨轮回地理知识变现的地方。（归档去向：`systems/game-progression.md`、`systems/adventure-event/travel/_index.md`、`systems/services/future-event-service.md`）

- **`eventCountLimit` 的计数口径** → **只计「选择进入并结算」的事件；跳过不计入，Travel 也不计入。** **推论：配额是「在这个地域做了几件事」的纯计数**——离开的动作不算做事，跳过的事情也不算做事；三条口径（不扣寿元 / 不占配额 / 计入 `pastEvent`）合起来给出跳过的完整定位：**只在行为轨迹上留痕，在任何资源与进度刻度上都不计。**（归档去向：`systems/game-progression.md`、`systems/adventure-event/travel/_index.md`）

- **location 之间的连通关系由谁承载** → **由一份独立的 `locationMap` 承载**（不挂在 Travel 内容条目上、不在运行时算）。**它是一份不变的数据，future-event-service 经常调用，三个篇章共用同一张图。** 推论：**① location 不随篇章 / 境界变化**（篇章难度差异由敌人赋级带承载，不由换图承载）；**② 熟悉度成为跨轮回的资产**（同一片世界，越玩越懂）；**③ 工程形态 = 只读静态数据、启动加载一次常驻、服务只读不写、存档只存当前 location 的 `Id`**；**④ 图对玩家不可见**，与「进程不给俯瞰地图」一致。（归档去向：`systems/game-progression.md`、`systems/services/future-event-service.md`、`terminology.md`）

- **每批必有不可跳过项 = 死锁风险？** → **否，这是设计意图。** 即便玩家打不过也得打；**没能承压就输掉这局是正常且合意的结果**，不需要产出侧的「至少一个可负担 / 可战胜选项」保证。推论：**① 与失败侧的既有建制自洽**（图鉴遭遇即记、道统残卷、失败也给经验、篇章重试模型）——**「输」是这个游戏的一个正常出口**；**② 反向约束产出侧不要过度保护**，难度的界由赋级带给出已足够。（归档去向：`systems/services/future-event-service.md`、`systems/adventure-event/common-properties.md`）

## 新增结构（非「移出」，是本轮新引入的概念）

- **`locationMap`（地域图）** —— 全局不变的连通图，玩家不可见。登记入 `terminology.md`。
- **`LocationCodex`（地域图鉴）= 图鉴族第六本** —— 「去过即记」，**是 `locationMap` 向玩家显影的唯一通道**。图鉴族由五本扩为六本（`systems/player-profile/codex/`、`player-profile/_index.md`、`systems/_index.md` 已同步）。**推论：它给「中长期规划感 / 方位感来源」这条长期待答提供了第一个具体候选**——方位感来自跨轮回积累的地理知识，而非轮回内的俯瞰视图。

## 收窄（剩余部分仍留在待答清单）
