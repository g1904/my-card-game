**stack 的借入深度：是否连响应窗口一并借入？** → **只借结算模型，不借交互与优先权。** stack 作为核心保留（打出 / 结算两时刻、LIFO）；**instant（瞬间）类牌、栈非空时出牌、优先权传递（priority passing）整体移除**——理由是它们**拉长对局时长、决策点过多、复杂度高而玩法深度收益小**。这**推翻了 08-02 的「响应窗口一并借入、回合是交互式的」**。连带答定：**所有牌都是 sorcery speed**（只能在自己回合主阶段打出）、`instant` 明确不借、EnemyManager 的代理面回落到「只在自己回合决策」。（归档：`systems/services/combat-service.md`、`systems/character-profile/deck/_index.md`、`systems/adventure-event/combat/_index.md`、`vision/references.md`、`vision/pillars.md`、`terminology.md`）

**响应窗口的规则细则（优先权轮转、哪些牌可响应、响应是否耗 mana、栈深上限、敌人 AI 在窗口中的决策）。** → **整条消解**——机制被移除，细则无从谈起。其中「响应用谁的 mana」进一步答定为：**起始步恢复的是回合归属方的 mana**，mana 的实际语义是「每次轮到我时刷满」。（归档：`systems/services/combat-service.md`、`systems/character-profile/mana.md`）

**交互式回合的移动端形态与时长约束。** → **消解。** 「轮到你响应」的提示 / pass / 超时交互不再需要；**「定长 = 每场时长可预测」恢复成立**，故**无须为战斗内交互次数另设护栏**（响应次数上限 / 计时一类）。连带：**决策点粒度不必覆盖响应窗口与优先权移交**（决策点粒度问题本身仍在，只是加压解除）。（归档：`ux/combat-ux.md`、`systems/balance.md`、`open-questions.md` 的决策点条目）

**回合的内部结构是什么？** → **三步定案：起始步 / 主阶段 / 结束步**，**去掉战斗步骤、不设双主阶段**。起始步 = 回合归属方 mana 恢复至 `manaLimit` → 触发「回合开始时」→ 抽牌；主阶段 = **唯一**出牌阶段，只有回合归属方能主动出牌；结束步 = 触发「回合结束时」→ 手牌上限弃牌 → 清理回合内状态。连带答定：**手牌上限这条规则存在**（数值未给）、**抽牌时机 = 起始步**、**「回合内状态」是一个正式的状态生命周期档位**、**没有 MTG 式的攻击阶段**（道念全部经主阶段的卡牌产出）。（归档：`systems/services/combat-service.md` 的意图与 TurnManager 表、`systems/adventure-event/combat/_index.md`、`systems/character-profile/deck/_index.md`、`systems/character-profile/mana.md`、`ux/combat-ux.md`、`terminology.md`）
