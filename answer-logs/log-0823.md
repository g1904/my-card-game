## 一、枚举形状与取值域（原 `open-questions/02-event-options.md`）

- **`HiddenStatDirection` 二值封闭、不设 `Unset = 0` 哨兵** → 维持。依据 `OutcomeRule.Direction` 全库无哨兵的先例。已知代价原样保留：内容作者漏填 `Direction` 会静默落成 `Raise`，而 `Raise` 对煞气恰是常见方向，比一般字段更难在测试中显形。（→ `systems/architecture.md`「共享核心类型」）
- **`HiddenStatGrant.Stat` 保持宽类型 `HiddenStat`、由加载期校验收窄为 `{ Faith, Bloodlust }`** → 维持。照 `OutcomeRule.PoolKind` 的既有先例，不新开 `PushableHiddenStat` 子枚举。（→ `systems/architecture.md`）
- **加载期校验 9：`HiddenStatGrants` 内 `Stat == HiddenStat.LifeSpan` → `PushError`** → 维持拒绝。堵住绕过 `lifeSpanCost` 定价表 / 回寿量表与 Travel 回寿禁令的书写出口。落笔时同批把「拒绝」的理由写进校验表那一格（原先只写了「拒绝」两字加标记）。（→ `systems/adventure-event/common-properties.md` 校验表第 9 行）
- **`lifeSpanCost` 一律非负整数定值，不带区间、不带公式** → 维持。两条否决理由确认成立：Band 0 / Band 1 不显示 `selectCost` ⇒ 方差对玩家不可感知；区间会损害「目标时长反推定价」的精度。定价表继续不设区间列。（→ `systems/adventure-event/common-properties.md`、`systems/balance.md`）

## 三、写入时机 · 凭据 · 运营通道（原 `01-combat.md`、`05-service-contracts.md`、`02-event-options.md`）

- **「非战斗四类的事件内决策点不触发第二次写入，它只是可退出点」，及其连带改写** → 口径与连带改写**均维持**：「每个决策点立即原子写本地缓存」这句全称表述降为「该时刻若产生了尚未落盘的新状态才写」。代价如实记下：一条原本无条件的存档纪律变成带前提的，实现时需逐决策点判断「有没有新状态」。（→ `systems/services/life-cycle-service.md`）
- **Exchange 面板打开不设 X0 标记** → 维持。决策点清单只有 R1 / R2 / X1 / X2 / X3 + 两条「无」；面板打开时全部状态已由既有写入覆盖（库存物化已落盘），再记一个标记无新信息。（→ `systems/services/life-cycle-service.md`）
- **不存 `refreshExpiresAtUtc`，`signin` 应答里的该字段读取即丢弃** → 维持。设备时钟不可信 ⇒ 客户端无一处可合法据它分支，存一个不许读的字段只会等着被人读。代价：无法在 UI 上提前告知「登录将过期」。（→ `systems/services/account-service.md`「refresh token 的持有与失效」）
- **明文落盘 `user://cache/refresh-token.json`，平台密钥库后置评估** → 维持。依托各平台应用沙箱 + 后端 rotation / 窗口外重放即吊销全部会话兜底；**不挂靠「不承诺防作弊」那条**（该边界的前提是「作弊者只损害自己」，而凭据泄漏的受害者是别人）。残余风险原样保留在文档：root / 越狱设备、备份提取、共享设备。平台密钥库（Android Keystore / iOS Keychain）的触发条件与四端（含 Web）行为差异**仍作为待评估项留在 `05-service-contracts.md`**——本次复核只确认「首版明文」这一取向，不关闭该评估。（→ `systems/services/account-service.md`）
- **「`eventCountLimit` 不可调制」只约束剧本层，`EventCountLimit` 仍是普通内容字段、overlay 照常可改** → 维持。保住「线上让人快点离开某个问题地域」这条唯一的运营通道（改值下次冷启动生效）。（→ `systems/game-progression.md`、`systems/services/content-service.md`）
