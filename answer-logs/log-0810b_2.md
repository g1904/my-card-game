**置换所得法则的 `SourceCode`**（原在 `open-questions/06-meta-progression.md`）
→ **置换不改变来源：换来的条目继承被换出条目的 `SourceCode`。** 目的是关死「用置换刷回高掉率」的通道——若记为新来源，换掉一条 `FinaleWin` 法则即可压低 `x`、使档位回跳。**推论：置换对 `x` 完全中性，08-09b 的「`x` 单调不减 ⇒ 档位只降不回跳」原样保住**；代价是来源记的是「最初从哪条途径进入账号」而非「上一次易手的方式」，为有意取舍。（归档去向：`systems/common-properties.md`、`systems/player-profile/player-power/_index.md`。）

**`Source` 枚举的完整成员清单**（原在 `open-questions/07-codex-monetization.md`）
→ **封闭三值：`FinaleWin` · `PremiumBundle` · `AchievementReward`**（外加防御性的 `Unknown = 0`，不是一条途径）。**不为事件 outcome 授予 / 战斗奖励 / Exchange 购买 / 置换所得 / 开局初始持有预留成员。**（归档去向：`systems/common-properties.md`。**⚠ 由此新生一条待确认项**：三值全属账号级途径，轮回级的神通 / 法宝无合法取值 —— 已作为新条目留在 `06-meta-progression.md`。）

**两版「失败但存活」补白文案的择取规则**（原在 `open-questions/06-meta-progression.md`）
→ **等概率随机二选一**，不按篇章 / 隐藏属性分化；**文案属内容层**（`res://content/` + overlay，可热更），**不随剧本服务下发**。由此在 PlotManager 内部划出一条分界：剧本正文按 key points 向云端请求、不落存档不进 ContentRegistry；而由状态转换触发的定性文案是内容条目。**推论：随机源不必带种子**（只影响呈现、不产生玩法结果，不占 `SeedManager` 子流）。（归档去向：`systems/services/plot-manager.md`、`systems/adventure-event/finale/_index.md`。）

**成就奖励能否给 PlayerPower / PlayerItem**（原在 `open-questions/07-codex-monetization.md`）
→ **可以，这是新确立的设计意图。** 成就的两档一次性奖励可发放法则 / 古宝，`Source.AchievementReward` 即其载体；**成就所得法则不计入残卷的 `x`，故不压低掉率**（与礼包同款）。**剩余部分仍待答**：具体奖励条目目录、两档各给什么、抽取是否走 `AllEnabled()` 并排除已拥有 —— 收窄后留在 `07-codex-monetization.md`。（归档去向：`systems/player-profile/achievements/_index.md`。）

**`SourceCode` 是否有 `x` 之外的消费点**（原在 `open-questions/07-codex-monetization.md`）
→ **没有。** 它存在的全部理由就是算出残卷的 `x`：**不对玩家可见**（法则列表 / 储物袋不标注来源）、**不进图鉴词条**、不参与任何其他判定。它因此是一个**纯规则字段**（严格同步 · 后端可复算）。（归档去向：`systems/common-properties.md`、各层 `common-properties.md`。）
