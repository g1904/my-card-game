**图鉴的入口与浏览形态（主菜单如何组织、列表页与词条页的竖屏排布）** → 主菜单一个「图鉴」一等入口（Achievement 之后、Settings 之前，纯标签、无角标、无门禁），下接三层结构：索引页（七格网格 + 每格 `已收录 / 总数`）→ 单本页（纵向滚动网格，窄屏 4 列 / 平板 6 列，按 `Id` 升序，未收录留灰格）→ 词条（敌人本全屏 `CodexEntryScreen`，其余五本半屏 bottom sheet）。翻译键全落 `PROFILE_` 分区，零新增存档字段、后端零配合。（归档去向：`ux/screen-flow.md`「图鉴族的三层浏览结构」、`systems/player-profile/codex/_index.md`）

**主菜单「图鉴」入口上是否显示总完成度** → 不显示，纯标签；完成度只在索引页内逐本给出。依据：图鉴靠「看着它变厚」自持、不与任何发放挂钩，主菜单上的数字是把这条动机往外部激励挪一步；且同屏 Store 明令无角标。（归档去向：`ux/screen-flow.md` 主菜单入口表）

**轮回内（EventOption 选择界面）是否给图鉴入口** → 不设，图鉴只在主菜单可达；战斗内一律锁死不变。依据：战斗前确认页会自动呈现已解锁敌人的词条，轮回内主动查图鉴的高频用途已被覆盖；角色状态条上现有入口全是轮回级。（归档去向：`ux/screen-flow.md`）

**`LocationCodex` 的词条深度与呈现形态（部分答定）** → **呈现形态那一半已定**：地域本在入口 / 索引格 / 完成度口径 / 文案分区 / 触控纪律五层套用统一形态，只有单本页的内容区不套用（它是一张逐步显影的图）；边缘态显示真实地名是全族唯一例外，不推广到其余六本。**词条深度那一半仍留在待答清单**——除连边外还写什么未定，它的单本页内容区如何画那张图与词条载体随之待定。（归档去向：`ux/screen-flow.md` · `systems/player-profile/codex/_index.md`）
