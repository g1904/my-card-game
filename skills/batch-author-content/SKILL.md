# Batch Author Content

编排规则见 `.claude/rules/batch-orchestration.md`。worker 执行的单会话技能是 **`/author-content`**——类型判定、就绪度闸门、字段校验、承重纪律、条目文档形态，全部以它为准。

批量相对逐个跑的价值：**互相引用的一组条目本就该一次写完**（功法持卡牌 `Id` 列表，逐个跑必留中间态悬空）；批内新条目之间的 `Id` 撞名与同池同稀有度重复，单会话各自跑查不到；一场 interview 答完整批的字段取向。

## 步骤

### 1. 圈定批次（用户确认，强制）
- **给了草稿清单** → 逐个读取并按 `content/_index.md` 登记表判定各自类型；判不出的照单会话技能停下询问。
- **空** → 扫 `inbox/` 顶层挑出内容条目类草稿（描述某一个具体的东西），列出（文件 + 预判类型）请用户圈选。
- 一份草稿描述多个条目 → 在此确认拆分方案（照单会话技能第 5.6 条），拆出的每个条目算批内一员。

### 2. 就绪度闸门与批内预核对（orchestrator）
- 对批内涉及的**每个类型**过一遍单会话技能第 2 步的就绪度闸门；🔴 类型的条目按其规则处理（停下或征得同意写 `⟨待定⟩` draft）。
- **预分配全部 `Id`**（按各类型 `id-form`），在整个 `content/` **加上批内其他新条目**范围内查撞名。
- **批内引用图**：条目 A 引用条目 B（B 也在本批）→ 合法，标注「批内引用」，并把 B 排在 A 之前的波次（功法先卡牌后功法）；引用批外且不存在的 → 照单会话技能判 🔴。
- 写入面分区：每个 worker 写自己的 `content/<类型>/<id>.md`（独占）；类型档案台账与 `content/_index.md` 由 orchestrator 收尾写。互相引用的一组条目可并给同一 worker。

### 3. Phase A：并行校验（worker）
按 worker 契约派单：执行 `/author-content` 第 3–4 步（只读校验：字段完备、交叉引用、Id、重复、承重纪律、自洽），产出 🔴/🟠/🔵 + 问题清单到 run 目录。批内引用按第 2 步的标注视为「将存在」。

### 4. 合并 interview ⏸️
orchestrator 去重合并全部问题（同类条目的同名字段各问各的值，**不合并**成一题；同一承重纪律冲突多条目命中 → 合并呈现），追加跨条目核对：**同 (类型, 稀有度) 同池的批内条目机制近乎等价** → 🟠 进 interview（差异化还是砍掉）。分轮问齐，未问完不落笔。

### 5. Phase B：写条目（worker，按波次）
worker 拿 `answers.md` 执行单会话技能第 6 步写条目文档（被引用者先行的波次顺序）。frontmatter `references` 含批内引用。台账行写进报告。

### 6. 收尾（orchestrator）
- 各类型档案 `_index.md` 条目台账补行（最新置顶）；类型级缺口追加进类型档案 Open questions。
- 归档来自 `inbox/` 的草稿（满足单会话技能第 7 步前置条件的才归档）。
- **不碰** `open-questions*` / `answer-logs/` / `systems/`；不评估 derive 就绪度（同单会话守则）。

```

- 闸门：<逐类型结论>；Id 预分配 <N> 个（批内撞名 0）；批内引用 <M> 条（波次：<顺序>）

### 合并 interview
- 🔴 <a> · 🟠 <b> · 🔵 <c> → 去重后 <Y> 问；逐条裁决：<字段/冲突> → <裁决>

### 条目（按类型）
- content/<类型>/<id>.md (draft) — 字段 <已答/总数> · 未定 <清单或无> · 验收断言 <n> 条

### 仍开放 / 台账 / Inbox
- <类型级缺口、未决项、归档情况、台账更新>
```
