# Remove Detail Log

**不是把日志全删光。** 按下方基线逐条判定：命中保留项的**必须留下**，其余的删。收敛目标即 `Context.md`「日志」条款的常态形态——关键状态转换处（轮回开始/结束、遭遇战开始、卡牌结算、存档/读档）有意义的日志。

**范围：只写 `game-feature-branch/`。** 四个 testing/production 快照目录只读。

## 保留基线（三类，穷举）

1. **链路最外层方法的入口/出口**：一条链路只留最外层那个方法的 start（关键入参）与 end（结果摘要）；内层方法的 start/end 属重复，删。
2. **关键状态转换与跨边界动作前后**：轮回开始/结束、遭遇战开始、卡牌结算、存档写入/读取、场景切换、边界服务（stub）调用——这些是常态基线本就要求的，留。
3. **可选数据缺失后的降级 `GD.PushWarning`**：`null-check-rules.md` 强制要求的失败语义，**不得删**——删掉就把降级变成「裸放过」。同理，必需缺失路径的 `GD.PushError` 不删。

## 应当删除

- 每次节点/资源/registry 查找后的命中回显（校验语句本身保留，只删纯回显的 `GD.Print`）。
- 分支决策点日志（「命中 xx 分支」）。
- 循环内逐条日志与前后计数（确需保留一条汇总的，在报告里说明理由）。
- 耗时统计及只为它服务的 `t0` 变量（该变量另有业务引用则只删日志）。
- 中间量回显、无信息量日志（「进入方法」「调用成功」）。
- 同一条链路逐层重复的 start/end（只留最外层）。
- 抛异常前的重复打点：`GD.PushError` + `throw` 带同样上下文时留一处即可。

## 硬边界

- **先分清新旧**：`git -C game-feature-branch diff` / `git blame` 区分本次排障新增的日志与既有常态日志——**既有日志不动**。分不清就保留并在报告里列出。
- **删日志不得改变控制流**：`if` / `else` / `catch` / 循环体删空后不得留下语法残缺;条件表达式有副作用的保留原语句结构并停下报告。
- **不得删除非日志代码**（除上面点名的、仅为日志服务且无其它引用的 `t0`）。
- 不改任何业务逻辑、不顺手修 bug。

## 步骤

1. **圈定范围**：同 `/add-detail-log` 第 1 步（有输入按输入定位并确定链路最外层方法;无输入按未提交变更枚举）。
2. **逐条判定删留**：命中保留基线 → 保留（格式不合规的顺手改成 `[System-Method]` 标签）;命中应删且不触发硬边界 → 删;触发硬边界 → 保留 + 列入报告。
3. **执行删除**：逐文件编辑,删完检查括号配对与空块残留。
4. **自检**：diff 中被删的行**全部**是日志语句（及仅服务日志的 `t0`）;每条被精简的链路仍留有最外层 start/end 与关键转换点日志（删到一条不剩即过度精简,补回）;`GD.PushWarning` / `GD.PushError` 都还在;无空块残缺。
5. **报告** ⏸️：按文件列出已删（条数 + 类别）、保留（哪几条、属哪类基线）、触发硬边界未删的（位置 + 原因,交用户决定）、顺带发现未修改的问题。提醒：改动只含日志删除,建议单独成一次提交便于误删回退。
