# Write ADR

每个设计库都攒着一批**已定方向**——它们已经在主题文档里定案了，只是还没有各自的档案。**已敲定的方向性决策**因此在库里**没有可检索的落点**：要查一条决策为什么这么定，只能在 handoff 与主题文档里翻。

本技能就干这一件事：**把那些已成事实的定案搬进 `decisions/`，做成可引用的 ADR，并把台账对齐。**它是搬运与立档，**不是裁决** —— 一条定案是否成立、成立成什么样，权威永远在主题文档与用户，不在本技能。

**范围守则：** 只写 `<LIB>/decisions/ADR-*.md`、`<LIB>/decisions/_index.md`，以及候选清单中**本次已固化的那几条**（把它们移除 —— 它们已有归宿）。**不**改任何主题文档（客户端 `vision/` · `systems/` · `art/` · `ux/`；后端 `vision/` · `contracts/` · `systems/` · `operations/`）、**不**改 handoff、**不**碰 `content/`、**不**碰候选清单以外的任何小节（尤其是 `/assess-derive-readiness` 独占的「derive 就绪度」）。发现候选与主题文档矛盾，或某条候选在主题文档里根本查无实据 —— **如实报告给用户，不建这份 ADR**。

**单写者纪律（强制）：** `decisions/` 与 `decisions/_index.md` 的**唯一写入者是本技能**。`/analyze-new-ideas` 在提炼时可以投递 ADR 候选，但**不建 ADR 文件、不动台账**；`/summarize-open-questions` 只整理待答清单，同样不碰 `decisions/`。理由与 `answer-logs/`、「derive 就绪度」一致：一份台账多个写入者，编号与顺序必然打架。

> **唯一例外（承 `rules/Context.md`「决策可被推翻」）：** 用户裁决要推翻某条既定决策时，`/analyze-new-ideas` 按根约定**直接改写那份 ADR**。那是**改写既有决定**，不是立档新决定 —— 它不新增编号、不动台账排序，与本技能的单写者纪律不冲突。

**「台账绝不领先于事实」（强制）：** 一条 ADR 只有在它所声明的决策**已经写进权威主题文档**时才可以建档。**先有事实，后有台账** —— 不许靠 handoff 里的一句话或用户口头意向就立 `Accepted` 的 ADR，那会让 `decisions/` 变成第二份、且更权威模样的设计源，与主题文档漂移。这与 ADR-0005 的副本判据同源：**本库没有任何机制能发现两份说法不一致。**查无实据的候选一律留在候选清单并在报告里点名。

## 步骤

### 0. 确定目标设计库（强制，先于一切）
按 `.claude/rules/design-library-routing.md` 解析本次作用于 `game-design-documents/` 还是 `backend-design-documents/`：显式库参数（`--lib=game` / `--lib=backend` / `客户端` / `后端` …）→ 参数中的路径前缀 → 相对路径 / `ADR-<id>` 落地探测 → 都判不出就**询问用户，绝不静默默认**。

选定后，**下文所有相对路径一律读作 `<LIB>/` 下的同名路径**。在报告开头点明本次作用的库。

**本技能不接受跨库运行，也不接受 `--lib=all`。** 依据是路由规则「仍然禁止的三件事」第 ②：**`decisions/` 编号两库各自独立，永不合并**。一次运行同时写两边极易把编号与「本次固化了哪几条」搅混。要两边都立档，跑两次。**跨库引用一律写全路径**（`game-design-documents/decisions/ADR-0003-online-cloud-authority.md`），绝不写裸 `ADR-0003` —— 两库各有一个 `ADR-0003`。

### 1. 确定范围
解析 `$ARGUMENTS`（已剔除库参数）：
- `all` 或空 → 候选清单里的**全部**条目 + 第 2 步扫出的散落定案。
- **关键词 / 条目片段**（如 `内容寻址`、`开发顺序`、`OpenAPI`）→ 只处理匹配到的条目。匹配到多条就都处理；一条都匹配不到则列出全部候选让用户挑，**不要凭猜测建档**。

条目多时**按主题成组处理**（同一次 handoff 定案下来的一族条目往往该合成一份 ADR，见第 4 步），不要机械地一行一份。

### 2. 采集候选（写之前先读）
1. `<LIB>/open-questions.md` 的 `## 下一阶段` —— **主来源**。读整节，取其中的 ADR 候选条目及其指向的权威文档路径。**保留原文措辞与它指向的文档路径**，那是第 3 步的核对入口。
2. `<LIB>/decisions/_index.md` —— 现有台账、状态词汇、**「ADR 形状」模板**（第 5 步照它写，不自创字段）、以及最大的已用编号。
   **后端库另有一张「ADR 候选（待固化为 ADR 正文）」表**，带要点与来源 handoff —— 它是该库候选的**第二个来源**，与「下一阶段」同等对待。它是过渡形态：候选被固化后从该表移除（第 7 步），表空即整节删除。
   **「已对后端构成约束的客户端决定」表不是候选**，它是跨库引用表 —— 本技能**只读不写**，任何情况下都不清空它。
3. `<LIB>/decisions/` 实际文件 —— 与台账对账：文件在而台账缺行 / 台账有行而文件不在，**都要在本次一并修好**（这是台账唯一写入者的份内事）。
4. `<LIB>/handoffs/` —— 逐份扫 `status: distilled` 的 handoff 里的 `## 决策` / 「已定案」段落。**散落在这里、却没进候选清单的定案同样是候选**，尤其是那些在同一次提炼里顺带定下的小口径。记住每条的来源 handoff 路径（ADR 的 `来源：` 字段要用）。
5. **权威主题文档** —— 各候选指向的 `vision/` · `systems/` · `art/` · `ux/`（后端：`vision/` · `contracts/` · `systems/` · `operations/`）文件。第 3 步逐条核对要用。
6. `<LIB>/answer-logs/` —— 确认某条候选不是**已被推翻**的旧方向（本项目允许直接改 ADR、允许推翻既定决策，因此旧结论会在 log 里留痕）。
7. `.claude/rules/Context.md` 的「决策可被推翻」「一切皆可改」与「活文档只保留最新设计」三条 —— 它们决定 ADR 的写法（见第 5 步的**不写考古**）。

### 3. 逐条核对「事实是否已落地」（强制，先于建档）
对每一条候选，去它指向的权威文档里找到对应的定案原文，判为三类：

- **已落地** —— 主题文档里写着同一个决定，措辞一致或更详细 → **可建档**。ADR 是它的**索引与理由留档**，不是它的替代品。
- **查无实据** —— 主题文档里找不到、或只有一句待决语气的描述 → **不建档**。留在候选清单，在报告的「未固化」区点名，并说清缺哪一段。
- **矛盾** —— 主题文档说的与候选条目不一致（典型：后续 handoff 改了口径，候选那行没跟着改） → **不建档**，在报告里并列引用两处原文，交用户裁决。

> 这一步不许省。跳过它就等于让 `decisions/` 领先于主题文档 —— 那是本项目明令禁止的台账形态。

### 4. 分组与编号
**分组：** 一份 ADR 承载**一个决定及其直接后果**。同一次定案里彼此互为前提的几条合成**一份**；彼此独立、各自可被单独推翻的，**各自一份**。判据：**能不能被单独推翻而不牵动其余** —— 能，就该分开。

**编号：** `ADR-####`，四位零填充，从现有最大编号 +1 连续递增，**两库各自独立编号、互不参照**。编号一经使用**不回收、不重排** —— 即便日后这份 ADR 被整篇改写（本项目允许直接改 ADR，见 `_index.md` 的「约定」）。

**文件名：** `<LIB>/decisions/ADR-####-<slug>.md`。`slug` 是**英文 kebab-case**、3–5 个词、描述决定的**对象**而非动作（`adventure-event-taxonomy`、`realm-checkpoint-retry-model`、`content-addressed-blob-delivery`）。与代码标识符 / 术语对齐时优先取 `game-design-documents/terminology.md` 里的词（后端库沿用客户端库的这一份）。

### 5. 写 ADR
**照 `decisions/_index.md` 的「ADR 形状」模板写**，不自创字段、不改小节顺序：标题行 `# ADR-#### — <决策标题>`，然后 `状态` / `日期` / `来源` 三行，再 `## 背景` · `## 决策` · `## 理由` · `## 备选方案` · `## 后果`。

逐节的写法：

| 小节 | 写什么 | 常见错误 |
|---|---|---|
| `状态` | 已写进主题文档的 → `Accepted`。**本技能不产出 `Proposed`** —— 未落地的候选按第 3 步根本不建档。 | 建一份 `Proposed` 占位 |
| `日期` | 该决策**在 handoff / 主题文档里定案的那一天**，不是今天建档的日期。查不到就取来源 handoff 的日期。 | 一律写今天 |
| `来源` | `handoffs/<id>.md`（多份就都列）。答定过程另有记录的，附 `answer-logs/log-<suffix>.md`。**来源写在这个头字段里**，不在正文末尾另留一行 `Source:`。 | 留空或写 `open-questions.md` |
| `## 背景` | **什么问题迫使我们必须选** —— 约束、冲突、绕不过去的边界。不复述整个系统。 | 写成功能介绍 |
| `## 决策` | **祈使句**，正面陈述选了什么，含关键取值（枚举值、字段名、上限数值、端点）。 | 写成「我们讨论了……」 |
| `## 理由` | 为什么是它。**引用主题文档的承重论证**，不新造理由 —— 新造理由等于在 ADR 里做设计。 | 现编一段论证 |
| `## 备选方案` | 每条 `<方案> — 否决理由`。**只写当时真的被权衡过的**（handoff / answer-log 里有痕迹的）。想不出就写「未权衡其他方案（当时唯一可行路径）」。 | 补一堆稻草人选项 |
| `## 后果` | 它约束了什么、放弃了什么、**哪些文档因此必须这么写**（列路径）。跨库的后果写另一库的**全路径**。 | 只写好处 |

**回链而非复述（硬红线）。** ADR 是**决策的档案**，主题文档才是**设计的正文**。细节（完整字段表、完整枚举取值域、完整流程步骤、数值旋钮表）留在主题文档，ADR 里给一句概括 + `→ systems/xxx.md` 的路径。**绝不把主题文档整段抄进 ADR** —— 那正是下一次漂移的来源，与 ADR-0005 的副本判据同源。

**不写考古。** 承 `rules/Context.md`「活文档只保留最新设计」：ADR 里不写「取代 ADR-000X / 原方案是 Y / 旧文件保留待清理」。要改一个决定，**直接改那份 ADR**，也不设 `supersedes` / `superseded-by` 字段；历史归 git。`Superseded` 状态在本库基本用不到。

语言：中文正文 + 英文代码标识符 / 路径，与全库一致。

### 6. 更新台账 `decisions/_index.md`
- 在决策表里为每份新 ADR 补一行：`| ADR-#### | <标题> | Accepted | <日期> | <影响文档，逗号分隔> |`。
- **最新置顶**（表头之下按日期降序；同日按编号降序）。首次写入时删掉占位行。
- 第 2.3 步对出的**台账 ↔ 文件不一致**在此一并修平：孤儿文件补行、悬空行删除或改指。
- **只动表格与必要的行**；「状态词汇」「约定」「ADR 形状」三节**原样保留**，不改措辞。后端库的两张附表按第 2.2 步处理。

> 写入后 `index-size-guard.ps1` 钩子可能对 `_index.md` 体积告警（阈值 20KB）。它**只告警、绝不拦截**；台账真的长到该拆时，那是一次单独的结构决定，不在本技能范围内。

### 7. 收口候选清单
在候选的来源处**删掉本次已建档的那几条** —— 它们已有归宿，留着就是第二份决策清单。

- `<LIB>/open-questions.md` 的 `## 下一阶段`：删掉已固化的条目。该小节被清空时写一行 `- 暂无。`，**不要删掉小节本身**。
- 后端库 `decisions/_index.md` 的「ADR 候选」表：删掉已固化的行；表被清空时**整节删除**（它是过渡形态，不留空表）。
- 只删本次固化的条目。**未固化的（查无实据 / 矛盾 / 不在本次范围）一律原样留下。**
- `open-questions.md` 的**其余部分一个字都不动** —— 说明段、分片导航、当前焦点、以及 `/assess-derive-readiness` 独占的「derive 就绪度」。
- 在 `<LIB>/open-questions/update-log.md` **顶部**追加一条本次摘要：固化了哪几条、落成哪几个 ADR 号。

### 8. 报告
```
## Write ADR：<范围>

- library: <game-design-documents | backend-design-documents>

### 已建档
- ADR-#### — <标题>（<日期>）
  - 事实依据：<主题文档路径>#<小节>
  - 来源：handoffs/<id>.md
  - 影响文档：<路径…>

### 未固化（留在候选清单）
- <条目原文> —— 查无实据：<主题文档路径> 里没有对应定案，缺 <什么>
- <条目原文> —— 与 <主题文档路径> 矛盾：条目称 <X>，文档称 <Y>（待用户裁决）

### 台账
- decisions/_index.md：新增 <N> 行；修平不一致 <M> 处（<说明>）
- 候选清单：<来源处> 移除 <K> 条，剩余 <R> 条
- open-questions/update-log.md：已追加
```

> 输出中**不含**任何 derive 就绪度结论，也不建议去跑 `/derive-requirements` —— 就绪度归 `/assess-derive-readiness`（用户手动调用）。
