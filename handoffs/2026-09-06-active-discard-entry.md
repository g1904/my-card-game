# 主动弃置的发起入口 = 主菜单篇章切换面上的次级动作

## Intent（distilled）

`DefeatReason.Discarded`（主动弃置）自终结三因定名起规则侧就是完整的：它走终态判定之外的一条显式旁路，落 `CycleEndScreen` 的 `Discarded` 变体（标题键 `CYCLE_END_TITLE_DISCARDED`、定性文案留空）。**但玩家怎么发起它，全库一个字都没有**——没有入口所在的屏、没有交互形态、没有确认形态、没有调用形状。它因此是一条**没有调用方**的规则路径，而 `CycleEndScreen` 的三分之一变体、`chapterRetry` 的一部分记账、以及「某篇章无可挑战角色时重新锁定」的一条触发来源都挂在它上面。

本次只答**发起侧**；轮回收尾两屏一格不动。

### 一、入口落在主菜单「切换篇章」面上，挂在该篇章那一行 `ongoing` 角色旁

弃置在规则上唯一能达成的效果，是把一个 `ongoing` 角色变成 `defeated`，从而**释放「每篇章至多一个 `ongoing`」这道闸**——角色数据本就随轮回结束被处置，弃置不额外省下任何东西。那道闸恰恰挂在主菜单的「开始新轮回」上 ⇒ **玩家读到「这一章被占着」的那一处，就该是他解除它的那一处**。入口与闸同屏，零跳转、零心智落差。

形态上**不新增屏、不新增主菜单入口**：每篇章至多一行 `ongoing` 角色 ⇒ 全游戏至多三行，不构成需要滚动或筛选的列表；弃置是这一行上与主动作「继续」并列的**次级动作**。本次只规定「弃置键挂在 `ongoing` 行上、形态如下」，不臆造一份角色管理屏，也不规定该行其余版式。

**轮回内不设第二个入口。** 三条理由，第一条是工程性的：`ct` 只在决策点被观察，而弃置要在一个没有进行中的 `AdvanceEventAsync` 的时刻提交事务 ⇒ 轮回内入口等于「取消到最近决策点 → `Immediate` flush → 弃置」，与「退出到主菜单再弃置」是**同一条链**，多的只是省玩家一次点击；全库无暂停屏，设置屏的语义是「音量 / 战斗 / 语言 + 一行只读诊断」、账号级不可逆操作已被明令挡在它之外（账号管理落 PlayerProfile 屏），没有承载它的屏；且想弃置的玩家下一步动作恒是「换个角色 / 换个篇章重开」，那一步只能在主菜单发生。代价如实写：玩家在轮回内认定这局没救时，要多一次「退出 → 主菜单」。

### 二、可弃置对象 = 仅 `ongoing` 角色

`completed` 的可挑战角色不提供弃置：它不占任何闸、不阻塞任何东西，弃置它没有可达成的效果，只有「误删一个存档角色」这一种后果；**状态机因此一格不动**，不新增 `completed → defeated` 转移。反向选项还会引出一个没有自然答案的记账问题（弃置一个还没开始那一章的角色，扣什么次数）。

**被接受的代价：** 已通关角色档没有任何清理通道，会随游玩时长在主菜单篇章切换面上持续累积——ch3 通关档更是永久保留完整档。

### 三、就地二段确认、无冷静期

第一段「放弃」→ 就地在该行内展开第二段（一行后果 + 「确认放弃」），**逐字复用本库唯一的确认语言**（解绑 / 储物袋售出 / Exchange 兑换 / 账号注销同款），不新开屏、不新增弹层、不发明第三种确认语言。

第二段的一行后果含三项事实：角色名 · 弃置**之后**该篇章的剩余重试次数 · 不可撤销。剩余次数取「记账之后」的值、与轮回结束屏同口径，不硬编码上限常量；ch1 上限无限走不含次数的另一条键，**剩余为 0 时走第三条键**改说「该篇章将不再可挑战」——那一格上这才是玩家真正需要知道的事实，「还剩 0 次」只是它的间接表达。

**无冷静期、无撤销通道。** 冷静期在这里自相矛盾：冷静期内角色仍是 `ongoing` ⇒ 闸仍占着 ⇒ 功能在整个冷静期内什么都没做成，而它的全部目的就是释放那道闸；它还要新增一个持久字段 + `schemaVersion` bump + 一个撤销入口 + 一条新口径。与账号注销的冷静期不对称的判据清楚：注销由后端定义、损失的是账号本身、发生在一条玩家可能被误导进入的合规流程里；弃置是纯本地、单角色、玩家为解除自己遇到的阻塞而主动发起，误触兜底由二段确认 + 明写后果承担，与「解绑」同级。

**弃置键恒可用、不置灰**：重试次数已耗尽不构成拒绝；待兑现购买的置灰只挂「开始新轮回」——弃置不开局、不进付费流程、不要求待发队列为空 ⇒ 不新增拦截点。

### 四、触控形态

次级键**常驻可见**：不是滑动删除、不是长按菜单——破坏性动作藏在手势后是隐藏可供性，且横滑已是角色选择与 eventOptions 的语汇，在篇章行上复用会让两个层级的操作读成同一件事。零 hover 通道；该行与两段按钮各自满足触控目标尺寸下限；次级键与主按钮在视觉层级上分开以降低误触；全部落在安全区内，篇章行区可纵向滚动时展开的第二段随行滚动、不做浮层固定。

### 五、签名、时序与文案

**`DefeatCharacter` 扩一格：`OpResult DefeatCharacter(DefeatReason reason, string characterId)`。** 现签名隐含「当前角色」，而主菜单侧恒无 active（`TryGetActiveCharacter` 的可选缺失在主菜单是正常态）。规则侧两个既有调用点传当前角色 `Id`；**不加重载、不加可空默认值**——否则两个入口会各自漂移出一份记账。被否决的替代是「主菜单侧先把目标角色设为 active 再调用」：那是为一次销毁做一次完整水合，且让「当前角色」在主菜单出现一个只为删除而存在的瞬时态。同一条推演使 `DefeatCharacter` 进入「不收 `character` 参数」那条服务级通则的显式例外表。

时序一次事务：清理之前组装只读结束摘要 → 一次 `ProfileChangeSpec` / `TryApply`（`status = defeated` + 重试记账 + `TotalCyclesDefeated +1` + 清理列）→ `Immediate` push（本就在强制立即 flush 清单内）→ `CycleEndScreen`。**主菜单发起时 `TeardownCycle()` 是空操作**（无实例化节点、无待断信号）——这是主菜单入口与轮回内入口在实现上的唯一结构差别。「无可挑战 / 可重试角色 ⇒ 该篇章重新锁定（隐藏）」的既定判定照跑，弃置该篇章唯一的角色后该篇章在同一次返回主菜单时消失。

框架文案走 `MENU_` 分区 / `menu.csv`（本就覆盖「主菜单、篇章切换」）⇒ 不新开分区、不占 `ERR_` 前缀；角色名作格式参数插入，不进 `menu.csv`。新增五条键：`MENU_DISCARD` · `MENU_DISCARD_CONFIRM` · `MENU_DISCARD_CONFIRM_DESC` · `MENU_DISCARD_CONFIRM_DESC_UNLIMITED` · `MENU_DISCARD_CONFIRM_DESC_LAST`。

**中文措辞用「放弃此角色」，不用「弃置」**——「弃置」已被功法侧占用，同词不同物；键名与代码标识符不受影响，术语分工登记进 `terminology.md`。

**存档 / 同步面：** 零新增字段 · 零新增存档点 · 零新增 flush 点 · 零 `schemaVersion` bump · 后端零配合。实现面唯一的非零成本是签名多一格与两个既有调用点各传一个 `Id`。

## Clarifications

- 是否在轮回内也设一个弃置入口？ → **只在主菜单，轮回内不设第二处**（用户裁决 A）。
- 是否允许弃置 `completed` 的可挑战角色？ → **只允许弃置 `ongoing`，不新增 `completed → defeated` 转移**（用户裁决 A）。裁决时用户已知两条本使天平偏向反向的新前提（ch3 `completed` 永久保留完整档 ⇒ 通关档会长期堆积；续章取「单记录 + 起始快照」⇒ `completed → ongoing` 已是合法转移，「终态收敛」不再能作为反对理由），在此前提下仍选 A，并接受「已通关角色档无清理通道」这一代价。
- 「弃置」一词与功法侧碰撞，角色侧用什么措辞？ → **功法侧保留「弃置」不动，角色侧 UI 文案改「放弃此角色」**，`terminology.md` 补一行区分；`DefeatReason.Discarded` 与 `MENU_DISCARD_*` 不变（用户裁决）。
- 剩余重试为 0 时第二段说什么？ → **新增第三条键 `MENU_DISCARD_CONFIRM_DESC_LAST`**，改说「该篇章将不再可挑战」；`MENU_` 分区由 4 键增为 5 键（用户裁决）。
- `DefeatCharacter` 的旧签名散落在 `decisions/ADR-0148` 与 `program-overview.md`，是否本次一并订正？ → **一并就地订正**（用户裁决）：ADR-0148 换用新签名、其登记的「主动弃置入口全库无明文」待定项本次答定后改写为已承载；结论一格不动、不新增 ADR 编号、不动 `decisions/_index.md`。
- 采纳的标准默认：第二段剩余次数取「记账之后」的投影值（= 当前 `RetriesLeft − 1`，下限 0），与轮回结束屏同口径、不硬编码上限常量；角色名走 `LocalizedText` 作格式参数，与「下一篇章显示名不进摘要、呈现层取键」同款纪律。
