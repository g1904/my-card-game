## Intent（distilled）

### 1. 三条「确有问题」的裁决与改动

#### 1.1 战斗内法则 ≤10% / 合计 ≤25% 闸门 —— **降格表述，不是承重结论**

原文自承「不可机械校验，只能作为内容评审口径」，按本库自己的**纪律可执行化四级阶梯**它落在**第 4 级（零成本、零保证）**，却被写成「25% 总闸就是『难度曲线按老账号全开校准』的**可执行形态**」——**一条零保证的条款被挂上了承重职责**，这是本次要修的全部内容。

- **改法：如实降格。** 10% / 25% 两个数**保留**，但改写为**内容评审时的参考上沿**，删掉「可执行形态」的措辞与它所承担的承重挂载。
- **真正承重的那一条单独留下**：*战斗内法则偏体验改善与容错，不抬高道念产出上限*——它是定性的，本就不需要可校验的数字来成立。
- **零新增机制。** 否决「补一条可机械校验的代理闸」（要新增字段或标注，为一条尚未有任何内容条目的纪律付结构成本）与「整条删掉两个数」（会连「老账号全开」这条已定风险的量化抓手一起丢掉）。
- **附带修正一处登记漏项**：08-15d 声明本条去向 `open-questions/07-codex-monetization.md`，但**从未真正落进该分片**，只留了 `balance.md` 的行内标记。本次一并清理该标记，问题就此答结、不再需要登记。

#### 1.2 `IgnoresProtection` ≈1% —— **两侧都动：规则砍到 2 条 + 频次抬高**

R1–R5 五条编排规则 + 一个轮回级存档 bool，换来的量级是「每 3 次完整轮回撞上 1 次」——**全库最细的编排规则服务于玩家几乎遇不到的事件**。规则密度与收益密度同时失配，故两侧同时调整。

| 规则 | 处置 | 理由 |
|---|---|---|
| **R1** 仅挂 boss 档载体（Finale 天劫 + 明确标记为精英的 `EnemyData`，不挂常规敌人） | **保留** | 硬准入。挂常规敌人则频次由遭遇频次决定，必然超标 |
| **R2** 每篇章至多 1 个载体条目、概率由目标频次反推 | **删除** | 频次抬高后配额已无约束力；「反推」是为 1% 那个极小值服务的精算装置 |
| **R3** 一次轮回内至多结算一次 + **轮回级存档 bool** | **删除** | 这是「平均 1%」与「体感 1%」之间的桥；频次抬到 ~5% 后，撞两次不再是需要被结构性排除的异常 |
| **R4** 绝不挂在玩家可主动获取的内容上 | **保留** | 硬准入。玩家一旦持有带此标记的牌，频次由他自己决定，任何配额彻底失效 |
| **R5** 加载期 `PushWarning` 逐条列举 + 人工核对表 | **删除** | 服务于配额核对；配额取消后无对象可核 |

- **目标频次 1% → ≈ 5%**（约每 6~7 场战斗一次，一次轮回内 1~2 次），采纳 `balance.md` 早已预写的调整方向。
- **承重推论：`CycleState` 少一个字段。** R3 的轮回级 bool 是 `IgnoresProtection` 在代码侧的**唯一**落点，删除后该机制**完全退回内容编排层**——「1% 的分布归内容编排，仅一个轮回级布尔位落代码」这句微调随之作废，回归最初的「不落代码」。
- **分母口径与「实际结算而非敌人持有」的定义保留**（它是频次这个数有意义的前提）。

#### 1.3 带内分布权重表 —— **三段合并为一张**

意图机制移除后 `diff` 的唯一剩余消费点只剩 `baseMomentum` 起跑线，三段（早 / 中 / 末）分辨率不再有对应的消费面；且 08-15d 已诚实记下「分段粒度在 ch2 · ch3 天然粗，右移效果被压缩」——**分段本就没兑现它承诺的效果**。

- **改法：删掉章内进度分段，保留单张 5 档权重表。**
- **保留不动的三项：`±2` 带本身**（08-15d 明确保留，消费点是起跑线）· **截断重分配**（不写就有权重和不为 1 的实现分歧）· **批内去重**（它承载「越级挑战是可主动选择的风险 / 回报维度」，与分辨率无关）· **PlotManager 的调制修正**（乘性，剧情线差异化的唯一入口）。
- **随分段一并作废的两条附注**：「分布随章内进度右移 ⇒ 篇章尾部变险由分布与规则双重承载」（现在只由**规则**承载——越阶仍只可能出现在境界末两级）· 「分段粒度在 ch2 · ch3 天然粗」这条已知代价（前提消失）。
- **否决「整个赋级降为窄带 ±1」**：那会推翻 08-15d 刚刚保留 `±2` 的裁决，以及「越阶只出现在境界末两级」等四条推论。

### 2. 七条「不是过度设计」的裁决（原样保留，登记论据）

这些条目此前的存疑点全部指向「成本 / 收益不相称」或「不可验证」。用户逐条给出的不是辩护，而是**此前未被写下的设计初衷**——写下它们之后，这些结构不再是悬空的。

| 体检项 | 裁决与论据 |
|---|---|
| **道统残卷的可验证性** | **不是过度设计。** 它是**分发账户级加强的核心算法**，「不给玩家任何提示」的隐藏性**正是设计初衷**——它要在幕后控制玩家的账户级进程，而不是成为一条玩家可优化的曲线。「玩家学不到 ⇒ 设计失败」这个前提本身不适用：**它本就不打算被学到**。三张分档表、阈值与万分比整数原样保留 |
| **隐藏属性 12 档 + 回滞 δ** | **不是过度设计。** 两件事分开成立：**① 12 档的消费者存在且是全覆盖的**——**所有事件都有可能推拉这三个属性**（不限事件类型），故调制的分辨率需求是真实的、不是先于内容而定的空结构。**② 文案只挂 4 个极值档是设计意图，不是覆盖不足**——它依赖玩家对修仙题材的基础设定认知（道心低了会入魔、煞气高了会反噬），中间档不需要旁白来教 |
| **决策点 D0–D6** | **保留 D2。**「文档已预写第一刀砍 D2」的预案作废——**D2 兑现的是「退出重进得到同一局面」，这一点很重要**。它不是可牺牲的性能余量，而是强制在线 · 云端权威下玩家对存档的基本信任。约 31 个决策点 / 场、≈93 KB 本地写的量级照旧接受 |
| **挂起态 / 选目标态整套 UX** | **不是过度设计——它是玩法精髓之一。** 暗幕 + 呼吸描边 + 固定指令条 + 连锁进度 + `pending` 存档形态全部保留。「≤10% 的触发式异能、一场期望 1~2 次」这个频次**不构成削减理由**：它服务的是本作少数几个真正的战斗内交互时刻，密度低正是它有分量的原因 |
| **`itemPowerRatio` 四档折价** | **没有问题。** 0.55/0.65/0.75/0.90 与战斗内法则的强度上沿同属**暂定平衡机制的软标准**——它们本来就不声称是精算结果，待 ch1 数值标杆定出法术基准后回归校准即可。「三个凭空系数相乘」不是缺陷，是**在没有量纲之前给内容侧一个可用的相对刻度** |
| **meta 层（设计密度远超实现进度）** | **没有问题，无需处理。**「相当一部分精算结论在第一次跑起来之前无法证伪」是**已知且接受的状态**。⇒ **节奏问题就此答结：继续深化设计，不先中断去落一个最小可跑的战斗回路** |
| **竖屏分区** | **不作本次裁决——会单开一个专门 session 答疑。** 该条**留在待答清单**并标注已排期，不再作为体检遗留项飘着 |

### 3. 手牌上限 9 → 7（与体检无关的新数值）

**这一项推翻了既有论据。** `balance.md` 原文把 7 明确写成被否决的取值：「取 7 会让上限成为常态惩罚」。用户的裁决是**改数值，并同时改写那条语义**。

- **新数值：手牌上限 = 7**（敌人侧照旧同值——参战方对称是硬纪律，意图移除后更重要）。
- **咬合验算：** 起手 4 + 每回合抽 2 → 第 2 回合即 `4 + 2×2 = 8 > 7`。**只有每回合稳定出满 2 张才不撞上限**；出牌不足即受罚。
- **承重语义改写：** 「手牌上限是逼玩家出牌腾位的**节奏约束，不是惩罚**」（08-03 推论 ③）→ 改为「手牌上限是一条**会真实咬合的紧约束**：出牌节奏跟不上抽牌节奏即开始损失牌」。**满手抽不进 / 纯上界 / 不产生弃牌堆流量**这三条规则形态**完全不变**——变的只是它咬合的频率与由此产生的压力定位。
- **连带复检一处（承重）：** 08-04b 推论 ③「道具绕开了手牌上限这条节奏约束，是**有意的松弛阀**」——**松弛阀的价值随上限收紧而上升**，故那条配套纪律「道具的强度必须比同费法术低」**变得更吃紧**，`itemPowerRatio` 的四档折价在 ch1 校准时须连同本次改动一起看。
- **不动的两项：** 每回合抽牌 2（下调到 1 会让 mana 纯浪费，推翻两条资源线等长的既定论据）· 起始手牌 4。
- **数值属性照旧：** 住在平衡资源 `CombatRulesData`、可被 `EncounterSpec` 可空覆写、属 ch1 数值标杆专场的回归对象。

## Clarifications（interview 产物）

1. **手牌上限 7 与「不是惩罚」的承重语义如何共存？** → **改数值，同时改写语义**（§3）。
   - 这**推翻了 `balance.md` 原文写下的否决论据**（「取 7 会让上限成为常态惩罚」）。否决 7 的理由不再成立的方式不是理由错了，而是**「常态惩罚」这个后果本身被接受为新的设计取向**。
   - 否决备选「同时把每回合抽牌 2 → 1 以保住原语义」：那会推翻「抽 1 则 mana 纯浪费」这条既定论据，为保住一句措辞去动另一条数值线。
   - 否决备选「7 只是暂定初值、语义不动」：文档会同时留着「7 会成为常态惩罚」的否决论据和取值 7，读起来自相矛盾。

2. **法则闸门「需要修改」改成什么？** → **降格表述，明写它只是评审口径、不是承重结论**（§1.1）。两个数保留，零新增机制。

3. **`IgnoresProtection` 精简哪一侧？** → **两侧都动：规则砍到 R1 + R4 两条 + 目标频次抬到 ≈5%**（§1.2）。附带删掉 `CycleState` 上那个轮回级 bool。

4. **敌人赋级简化到哪里？** → **只简化带内分布权重表：三段合并为一张**（§1.3）。`±2` 带、批内去重、截断重分配、调制修正全部保留。

5. **「所有事件都有可能推拉这些属性」在内容编排上的硬度？** → **可选，不强制**：任何事件类型（含 Combat / Travel / Research）都**允许**携带 `HiddenStatGrade`，取消的是「只有某几类事件才能推拉隐藏属性」这道结构性限制；**具体哪一条推哪个属性、推哪一档仍是逐条目的内容编排决策，不填 = 不推**。
   - 否决「每个事件选项都应当有非零推拉」：会把每一条内容的作者负担抬高一截，且与「不填 = 不推」这个天然默认打架。

## 被否决的备选（保留论据，防止重新提出）

- **给法则闸门补一条可机械校验的代理指标**（如「带道念数值的战斗内法则条目占比」上限）—— 能把它提到阶梯第 3 级，但要为一条**尚无任何内容条目**的纪律新增字段或标注；且代理量与真实量（道念净贡献）之间的偏差本身不可验证，等于用一个新的不可验证换掉旧的。
- **删掉 10% / 25% 两个数、只留定性定位** —— 会连「难度曲线按老账号全开校准」这条已定风险的唯一量化抓手一起丢掉。
- **`IgnoresProtection` 只砍规则、频次 1% 不动** —— 去掉 R3 后「平均 1%」与「体感 1%」之间没有桥，可能出现同一轮回撞两次，而在 1% 的量级下那是一次显著的体验异常。
- **`IgnoresProtection` 整条删除** —— 会失去「保护类效果并非绝对」这一设计面；存疑的是它的规则密度，不是它的存在。
- **赋级整体降为窄带 ±1** —— 推翻 08-15d 刚刚保留 `±2` 的裁决，以及「越阶只出现在境界末两级」「Finale 恒 `diff = +1`」等四条推论。
- **为体检 7 条「不是过度设计」的裁决另立 ADR** —— 它们是对既有设计的**论据补充**，没有一条改变决策；论据的归属地是各主题文档本身。
