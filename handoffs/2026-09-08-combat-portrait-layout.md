## Intent（distilled）

一句话：**栈不必常驻——它改为结算期的临时浮层，释放的 12–15% 屏高流向手牌区与己方战场带；六个常驻区按「上敌下我、中轴决策面板」排成一张可核对的屏高预算表；牌堆因此有了稳定可见面，卡背品类解除阻塞。**

竖屏分区被排期为一场专场的理由是「把 MTG 的完整分区模型搬进手机竖屏」，而累积的同屏容纳清单已达十余项。本次先做根因体检，再排预算表，最后逐项给出敌我分区、手牌、道念、回合进度、牌堆与结束回合键的形态。

### 1. 根因：栈不必常驻（纯规则推演，不是排版偏好）

出牌时机是「行动阶段**且栈为空**」，对双方成立。取其逆否：**玩家能发起任何动作的每一个时刻，栈必然为空。** 故栈非空的区间只有两种——结算演出（玩家无输入，单步 0.35–0.5 s、敌人回合整段 ≤ 4 s）与挂起态 `AwaitingChoice`（玩家有输入，但只能 `ProvideTarget`，一场期望进入 1~2 次）。两者都是演出 / 交互时刻，不是常态。一个常驻的栈区，在玩家做出全部约 31 个出牌决策的每一刻都恒为空——它占的是屏高，给的是零信息。

⇒ **栈改为结算期临时浮层**，不参与 `Container` 布局（与战报「容器本身不参与布局变化」同一条工程纪律）、落位在指令条下方（那本就是它的既定位置）、挂起态必然在场。**释放屏高约 12–15%。**

代价明写接受：行动阶段看不到「上一次结算留下了什么」；但那已落账（持续效果落到战场、增量落进战报），栈本身在那一刻已经是空的，看不到的不是信息，是一个空容器。反向风险已被封住——instant / 优先权 / 「栈非空时可出牌」三者已明确否决。

### 2. 屏高预算表（六个常驻区 + 四类叠加层）

顶部条 5% · 敌方区 20% · 决策面板组 16%（道念对峙条 7 + 回合进度 3 + 战报收起态 6）· 己方战场带 12% · 手牌区 28% · 底部条 10% · 安全区留白 9%。栈层 / 飘字层 / 指令条 / bottom sheet 各占 0%。

总原则「上敌下我，中轴为共享决策面板」的依据：玩家可操作的对象全部落在下半屏的拇指可达区，敌方全程零可操作。三个百分比是初值，须在 18:9 / 19.5:9 / 平板三档实测；`vision/scope.md` 未给分辨率或宽高比，故只能给比例。

**压缩顺序改写**：先压敌方立绘 → 再压两条战场带 → 再压底部条；**手牌区与双方道念位不参与压缩**（手牌区是屏内唯一承载拖拽的区，缩小直接抬高「拖出手牌区 = 打出」的误判率）。栈已浮层化，退出压缩链。

### 3. 栈与战场靠三条正交轴区分，不靠颜色

存在性（战场恒在 / 栈只在结算期出现——这本身就是最强的一条）· 位置（两条常驻横带 / 中轴浮层）· 轴向（横向排列 / 纵向堆叠）。栈顶画在最上（LIFO 下自上而下的阅读顺序恰是结算顺序）；栈条目半透明 + 悬浮投影 + 无底座，战场条目实心 + 贴带底 + 描边底座；**弹栈是一次可见的位移**，复用既定节拍、不新增停顿。

### 4. 敌方区不做己方的镜像

敌方在类型层没有可操作对象，故只承载读数与观看：立绘 · 境界名 · `n/5` mana · **手牌只给张数角标（不渲染牌背扇形）** · 抽 / 弃两个计数 · 战场带 · 埋伏计数角标。布局不得预留「翻开对手信息」的位置。

**敌方出牌在立绘前方放大呈现一拍（0.35–0.5 s）再落入栈层**——卡面是 full art、无卡名无规则文字，玩家认牌完全靠插画；若敌方出牌只是缩略图一闪，等于取消「敌人回合是唯一动态情报通道」这条硬要求。给它一拍足够大的呈现，是 full art 的直接对价；该拍照常受 3× 加速约束。

### 5. 手牌 = 水平重叠扇

不做弧形旋转（旋转让 full art 缩略辨识更难、拖拽命中区不规则）。≤ 4 张不重叠，5–7 张按可用宽度均分、每张至少露出**左侧 40% 宽度**；区高固定不随张数变化；拖起时上浮 + 放大 1.1× + 描边（复用选目标态那一套）；**拖拽阈值必须可见**——手牌区上沿浮现一条释放线；满手抽不进 = 第 8 张抬起一半后退回抽牌堆 + 上限标记闪一次，不出现任何「牌被丢掉」的动作。手牌上限常驻可读形态 = 右上角一格 `n/7`，由生效上限驱动、不写死 7。

### 6. 道念 = 对峙条 + 显式的道念差徽标

单条双向、中点为分界，两端各挂头像与数值；分界线位置 = `myMomentum / (my + enemy)` ⇒ **不读数字即可读出局势**；数值按三位数排版（四位数是寿元的口径，而寿元不进战斗屏）。

**道念差显式呈现**（分界线上方一枚 `+15` / `−15` 徽标）：它是胜负判据、奖励厚度、寿元扣减三个消费点的共同输入；ch3 战中可达三位数，要求玩家自己做减法不符合「明快、单手」的基调；而「换算成寿元要先乘逐章系数」削弱的是「差 → 寿元」这一步，不是「差本身要不要显示」。不附二级的 `≈ −N 寿元` 换算——寿元不进战斗屏。

### 7. 回合进度与道念差空间邻接，不合成复合指示

`TurnLimit` 个小格的一排点 + 并列文字；格数由遭遇配置驱动、绝不写死 10；当前格着色即回合归属方，同时给对应一端的头像一圈呼吸描边作冗余编码。

否决合成的两条理由：一个「还追得回来吗」的指示需要一个每回合期望产出模型，而该模型的输入在 `systems/balance.md` 中明标为待实测校准、不得作为承重依据；且它会**替玩家算掉那本账**，而那本账正是紧张感来源。

### 8. 牌堆有稳定可见面（答 monetization 的事实确认）

抽牌堆 = 底部条中部一叠牌背朝上的牌，厚度随剩余张数递减（不重洗 ⇒ 单调递减 ⇒ 零文字的余量指示）；弃牌堆并列，面朝上显示最近进入的那张；**敌方牌堆不给实体**。四条依据：抽牌堆信息面需要入口 · 抽牌动画需要起点 · 弃牌堆需要终点 · 卡组与弃牌堆本就是六处位置中的两处，给可见面是呈现既有位置而非第七处。

⇒ **卡背的可见面 = 玩家侧抽牌堆顶 + 己方埋伏背面**，卡背品类解除阻塞。

### 9. 结束回合键（本库此前无表述的一处缺口）

行动阶段需要一个出口：「打完手上想打的牌」不是可被系统检测的状态（玩家可能故意留牌以免撞手牌上限、或留 mana 无用）。底部条右端主按钮、不做二次确认、敌人回合 / 结算中 / 选目标态置灰。

## Clarifications（interview 产物）

- **栈是否改为结算期临时浮层？** → **A · 浮层化**（批量评审裁决）。屏高预算表按推荐值成立；连带定下「栈区保持可见且不被压暗」改写为「选目标态期间栈层必然在场且豁免压暗」，压缩顺序一并改写，栈的浮层形态由退让位提升为默认形态。
- **敌方立绘在屏高中的分量？** → **A · 紧凑半身像，敌方区 20%**（批量评审裁决）。浮层化释放的余量全部流向手牌区与己方战场带。依据：敌方区本就是压缩顺位第一，且敌人立绘在战斗前确认页已有一次充分呈现的机会。
- **神通 / 法则只读层的形状（与姊妹 handoff 的跨稿统一）** → 采用**单行图标条 + `+N` 溢出聚合格、不做任何滚动**，`K ≥ 3`、初值 5。落位仍是与随身角标分居己方战场带两侧。
- **卡面必读元素的占位**（标准默认，未出题）→ 重叠扇每张恒只保证露出左侧 40% 宽度 ⇒ `manaCost` 占左上角、类型角标紧邻其下、卡框色带落左边缘；右上角在重叠扇下不可见，不得承载任何必读元素。
- **结束回合键**（标准默认，未出题）→ 成立，属文档缺口而非取向。
- **敌人台词气泡的口径**以姊妹 handoff 为准：立绘**上方**、≈**1.5 s**。
