## Intent（distilled）

### 1. 储物袋 = 跨两个持久层的呈现视图，容量不设上限

储物袋同时呈现两级持有物：轮回级法宝（`CharacterProfile.magicPack`，`List<CharacterItem>`）与账号级古宝（`PlayerProfile` 持有的 `PlayerItem`），条目上带 `AbilityScope { Character, Player }` 标识来源——与战斗内道具区同形，元界面沿用同一形状。`magicPack` 因此只是这个视图的轮回级那一半，随轮回清理的也只是那一半；账号级古宝不受影响。

**容量不设硬上限**，界面由纵向滚动承载。满袋这一情形不再存在，随之消失的有：满袋再获得一件如何处理、满袋时能否购买道具、以及 `PROFILE_MAGICPACK_FULL` 这个文案键。

回寿法宝原有三道闸，第三道是储物袋的一格（管玩家能囤多少）。取消上限后，**回寿的总量护栏落在内容编排面**——出现频率、商店库存深度、定价——规则层不设持有上限。另两道加载期校验（`Scope == Player` 且产出 `LifeSpan` → 拒；`LifeSpan` 产出 + `UsableScene` 含 `InCombat` → 拒）管的是条目合法性，原样保留。

### 2. 出售规则：只有法宝可售，古宝不可售

法宝（轮回级）可在储物袋随时售出；古宝（账号级）不可售出，其唯一退出通道仍是置换。允许卖古宝 = 用账号级资产兑换轮回级货币，会使「开局清仓换经济」成为最优解，并与「避免第二套账号级经济」的取向相抵。

随售的准入判据**直接复用**那条代码级常量（可售出 ⟺ `ExchangeGoodsKind == CharacterItem`），不加第二个条件、不另立族白名单。

### 3. 售出有两条通道，回收率分两档

售出机制自此有两条通道：Exchange 商店内售出（权威留在 `systems/adventure-event/exchange/`），与储物袋随售（权威落 `systems/character-profile/item/`）。出售只在 Exchange 与 event selection 时可发起。

**只定「两档 + 相对关系」，绝对数值留给内容扩充后的统计校准。** 商店档 `SellRatePercent` 是逐条目字段（编排面，存在理由是让「只卖不收」的商店可编排）；随售档 `PackSellRatePercent` 是全局平衡资源单值（随售没有编排主体）。两者是独立旋钮，互不作缺省。加载期硬校验：`SellEnabled == true` 且 `SellRatePercent <= PackSellRatePercent` → `PushError`。

**两档的论证基底：** Exchange event 的形态是以物易物或资源换取道具，**大部分可随售的道具在 Exchange 中并不提供回收**。储物袋随售因此是**常态的弃置途径**——低回收率使「清仓」不构成一条经济来源，弃置的收益只是聊胜于无；少数提供回收的商店是**罕见的更优机会**，硬校验保证它恒优于随售，这正是它作为机会的全部意义。

两条通道的折算基准同为「族 × 稀有度」定价表的**基准价**，不取 `ListPrice`（随售场合没有 `ListPrice`，也读不到 `PriceOffset` / `DiscountPercent`——它们是店铺库存规则字段）。**同币回收**：币种由定价表那一格决定，落在收仙玉那一格的法宝随售即产出仙玉。仙玉的唯一**主动**获取通道仍是稀有 AdventureEvent 产出；售出与随售是同币回流，不新增获取渠道。代价正面写下：免费取得的仙玉计价法宝，其售出所得是仙玉的一条净产出，量级由「定价表哪几格填仙玉 × 该族掉率」共同决定，归统计校准。

**随售的痕迹：** 新增 `Source.PackSell`，合法子集表对 `(Item, Character)` 的 `Remove` 开 ✅，其余三格规则层封死。不复用 `Source.ExchangeSell`——`Source` 的职责是「这件东西怎么来的 / 怎么没的」，复用会让「购买次数」这类统计永远算不准，且会让痕迹指向一个不存在的事件。它是随售唯一的**来源标注**，进 `TryApply` 可追溯性日志与客服溯源，**不进存档**——随售没有 `PastEventEntry` 可挂，又不落 `SourceCode`（东西已不在），故事后不可重建。不新开 `PastEventEntry` 通道，不为「售出次数」设 `StatKey`。售出即时提交，沿用既有路径，不新增存档点类型。

### 4. 战斗内持有物面板：按「可操作 / 只读」分两层

- **可操作层 —— 随身道具角标**：点按升起底部抽屉，展示按 `UsableScene` 筛出的本场可用道具，可直接使用。抽屉内**同时呈现两级**（法宝 + 古宝）、条目带 `AbilityScope` 标识。「本场可用道具」的派生规则 = 按 `UsableScene` 筛 + 一条禁用过滤。
- **只读层 —— 神通 / 法则**：本身不承载操作，**不列被禁用的神通 / 法则**（它们根本不入场）。详情**长按**查看——沿用「可拖拽对象用点按、不可拖拽对象用长按」这条既有判据。
- **启动式 `Power` 的启动入口落在长按升起的那个弹层内**（bottom sheet，复用既有控件语言），图标条本体保持纯只读。`PowerData.Abilities` 的取值域**不收窄**（静止式 / 启动式 / 触发式皆可，至少一个）。可发现性由图标上一个静态启动可供性标记补偿。弹层与随身抽屉同规格禁用（敌人回合 / 结算中 / 选目标态）。
- **功法与货币不进战斗 HUD**：功法在组装时已展开为卡牌，战斗内不感知功法；货币在战斗内无用途，仙玉与灵石的非战斗查看归储物袋。
- **卡组构成查询不在本稿收口**：不为它单开面板，复用抽牌堆信息面，形态留待 UX 专场。
- **只读层的形状（角标 vs 常驻一排小图标）不在本稿裁定**——与已排期的竖屏分区专场高度重叠，本稿只定分层原则。

### 5. 神通 / 法则的呈现气质：技能感而非卡牌感

参照三国杀武将技能——被动常驻、身份绑定、少而精。UI 上神通 / 法则不应长得像手牌，应长得像武将技能栏；与 `CardType.Power`（开局入场、受保护、不可针对、永不入栈）的机制定位一致。

**卡面形态的适用面：** 战斗内 `Power` 一律以技能条目呈现，卡面形态只用于图鉴 / 详情卡 / 奖励与置换选择面。依据：`Power` 不被打出、永不入栈、不产生弃牌堆流量 ⇒ 它在战斗内从不以一张牌的姿态出现，卡面类型标识对它本就是空转；而奖励 / 图鉴面需要与其他族并排，保留卡面成本最低。「五类卡牌靠卡框色 + 类型角标区分」因此加限定「适用于会以卡面出现的类型」。

### 6. 账号级古宝在轮回外的查看落点

储物袋只在轮回内存在（它含轮回级持有物），入口挂在角色状态条的「袋」图标上。因此在 **PlayerProfile（玩家档案）屏内增一区「持有的古宝」**：只读列表 + 剩余 `Charges`，不可售、不可用。不新增主菜单入口。理由：古宝是付费礼包的主要交付物，付费资产的状态对玩家须恒可见。

## Clarifications（interview 产物）

- **回寿法宝的持有量护栏由谁承接** → 交给内容编排面（出现频率 / 库存深度 / 定价），规则层不设持有上限。这是原始草稿未察觉的连带后果：它只写了「取消 9 格上限」，未交代第三道软闸被一并拆掉。
- **随售产出的币种** → 同币回收，币种由定价表那一格决定。**推翻原始草稿 §1 的「换取基础货币灵石」**——该措辞与 §3 的折算机制自相矛盾。「仙玉的唯一获取通道」两处措辞相应改为「唯一**主动**获取通道」，并正面写下净产出敞口。
- **只读层的详情手势** → 长按打开弹层（详情 + 启动键合一），点按无语义。**推翻原始草稿 §4 的「点按查看详情」**——既有手势判据（可拖拽用点按 / 不可拖拽用长按）被明确标为承重、须留在文档里。
- **账号级古宝在轮回外的查看落点** → PlayerProfile 屏内增一区，不新增主菜单入口。原始草稿未提及这一缺口。
- **两档回收率的相对关系** → 加载期硬校验 `PushError`，而非内容编排口径。
- **两档回收率的论证基底** → **推翻原始草稿 §3 的「保住『跑一趟商店』的规划价值」**。Exchange event 的形态是以物易物或资源换取道具，大部分可随售的道具在其中并不提供回收 ⇒ 随售才是常态的弃置途径，商店收购是罕见的更优机会。低回收率的意义因此是「让清仓不构成经济来源」，而非「让商店更优」。
