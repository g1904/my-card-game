## Intent（distilled）

**一句话：** CDN 侧的「多区域一致性」在单区域部署下没有对象，以否定结论答结；契约里那条空悬的传播窗口 **T** 换掉主体（区域 → 实例）、取初值 **60 秒**，并配三条服务端纪律把它从「压不小就出误报」的硬约束降级为一条纯延迟 SLO。**报文零改动、客户端零义务。**

### 一、多区域一致性：结论是否定的，问题已被上游消解

服务侧是单区域部署、不做跨区域多活（`operations/environments.md`「拓扑与副本」）。对内容分发面逐条推演，「多区域」在本项目里不存在：

| 原三问 | 结论 |
|---|---|
| `contentRoot` 按区域下发是否启用 | **不启用**（自由度保留，不撤销）。单区域 ⇒ 只有一个内容源站、一个 `contentRoot` 值。CDN 的边缘节点不是「区域」——它们回源到同一个源站、由同一份 manifest 定义内容，边缘之间不存在需要协调的独立版本。启用区域化下发要先有「两套内容源」，而那只在独立部署时出现，届时它是**另一套部署的另一个 `contentRoot`** |
| 多区域间 `contentVersion` 是否必须同步推进 | **问题消解**。`contentVersion` 由单一发布动作分配、单调高水位落主存储；只有一条序列、一个分配点，「同步推进」没有对象 |
| 区域间发布的时序差如何处置 | **降格为边缘缓存传播**，已被既有条款覆盖：先推全部 blob、后推 manifest + 内容寻址 ⇒ 任何边缘一旦读到新 manifest，其列出的 blob 必然可回源取到；manifest `no-cache` ⇒ 边缘不会长期停在旧版本。只欠一条 CDN 能力要求（见第四节） |

**日后走独立部署时的形态一并写清**：那是两套独立部署，各自独立的 `accountId` 空间、独立的 `contentRoot`、**独立的 `contentVersion` / `flagsVersion` 序列**，且**不要求两套同步推进**——两套之间没有共享账号、没有共享存档、没有跨部署的客户端路由，同步推进既无收益也无兑现手段。

`contentRoot` 不进签名范围这条自由度**不撤销、也不改一个字**，只把它的理由说准：现役用途是**域名 / 厂商切换**，外加为日后独立部署留口。让它继续指向一个已被消解的场景，会误导实现方去建一个不存在的区域路由。

### 二、T 必须先被重定义：它是「跨实例」窗口，不是「跨区域」窗口

条款原文是「新批次须在窗口 T 内在**全部区域**可见」。第一节一旦成立，「全部区域」就没有指称对象，条款变成空条款——**但它要防的失效模式并没有消失，只是换了主体**：

单区域下仍有多个应用实例。`X-Flags-Version` 搭任意应答的车下发，一个设备在一次会话内会打到多个实例；各实例持有的「当前 `flagsVersion`」不会在 `publish` 事务提交的同一瞬间全部更新（版本读取的进程内缓存、连接池、flags 读路径那条尚未被用上的副本自由度）。**这就是 T 的真实主体。**

故条款主体由「全部区域」改为「**全部对外服务的实例**」：单一全局序列、良性态口径**原样成立**，只是把主体换成一个在本项目里真实存在的东西。这条改写同时让「flags 读路径不受读己所写约束」那条自由度继续有效——它日后若被用上，副本滞后天然落进同一个 T 的预算，不需要第二个窗口。

### 三、承重：偏斜是不对称的，纪律不是「把 T 压小」而是「头永不领先」

把客户端的两道单调闸对上「头与体来自不同实例」的两个方向：

| 偏斜方向 | 客户端行为 | 代价 |
|---|---|---|
| **头落后**（头 41、本实例已能兑现 42） | 等值 / 更小 → 不拉 | 只有延迟，**零告警、零上报** |
| **头领先**（头 42、flags GET 落到仍在 41 的实例） | 拉回值 ≤ 内存值 ⇒ 整批丢弃 + `PushWarning` + 按会话上报一次 | 一次**误告警 + 一次上报**，而这条通道存在的目的是发现灰度分桶串号 / 中间层缓存旧应答这类真事故 |

**推论：真正要堵的不是「T 太大」，而是「头领先于体」**——它是唯一会产生误报的方向，而误报会稀释一条只可能在线上发生的事故信号。三条服务端纪律（落为 `content-delivery-ops.md` 的 A7 / A8 / A9）：

- **A7** 应答体的 `flagsVersion` 取自它**实际使用的那条规则集记录**，绝不取自高水位（否则同版本不同结果，而客户端只比版本号、无从发现）；
- **A8** `X-Flags-Version` 下发值 = `min(高水位, 本实例当前能兑现的最大规则集版本)`，**头永不领先**；单实例内的「头领先」由此结构性不可能，跨实例只剩零告警的那一栏；
- **A9** 那个数由既有的规则集缓存自然给出（已装载的最大键）——**零新增机制、零新增存储、零报文改动**。

采纳后 T 降级为一条**纯延迟 SLO**：超了只是秒关慢一点，不产生任何错误行为、不产生任何误报。

### 四、数值、探针与一条 CDN 侧的真实残留

**T = 60 秒**，上界两侧夹出：上侧受「秒关端到端延迟是分钟级」这句承诺约束（端到端 = T + 玩家下一次上行约 60 秒 + 一次 GET ⇒ 约 2 分钟；取 5 分钟则端到端逼近 6 分钟，承诺名不副实）；下侧因偏斜已不产生误报，压到秒级换不到正确性收益，只会把一条本可宽松的 SLO 变成噪音源。预算分解：**版本读取缓存 TTL 5 秒**（主导项，**不是配置三层里那个约 30 秒的 `config_knob` 进程内缓存，两者不得混用**）· **副本滞后预算 10 秒**（当前实际 0）· 余量。**T 本身不进 `config_knob`**——它是判定阈值，不是运行时行为的输入；进旋钮表的是那两个分项。

**探针**：每个实例把 A9 那个数暴露为 gauge，告警断言 = 实例间**极差 ≠ 0 且持续超过 T**。不用「publish 时刻 → 首次出现新号」做主指标：那要跨发布侧与请求侧两个数据源，且在无发布期间失效，发现不了「某实例卡在旧版本再也不更新」这一更隐蔽的故障——而 gauge 极差就是 T 的定义本身。零新增契约面、零新增埋点。

**顺带堵一个与区域无关、与「内容寻址 + `immutable` 长缓存」有关的残留**：某边缘节点若在 blob 推上去之前对同一 URL 缓存过 404，则在负缓存 TTL 内，命中该边缘的玩家**稳定拿不到 manifest 已列出的文件**（表现为跳过更新，不崩不坏档，但症状与网络不好难以区分且只影响部分玩家）。故要求 **`/blobs/*` 关闭负缓存或 TTL ≤ 数秒**，并把**步⑤「确认 blob 可读」的探针改走 CDN 域**（A 组第 3 条的「可下载」指玩家侧可下载）。风险来自发布流水线之外的探测，低概率但高定位成本。
