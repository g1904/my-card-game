## Intent（distilled）

呈现哲学一句话：**卡面极简，信息后置到详情页与战报。**

### 1. 卡面是全幅插画（full art）

卡牌为全幅插画，卡面**只显示 `manaCost`** —— 无规则文字、无卡名。规则描述、卡牌名称、关键字的名与完整定义、`Power` 的明示内容，一律在点击后升起的详情页。

三条既有的「卡面带文字」要求**换载体不换要求**：关键字名与定义一并移入详情页（长按机制不变）；多目标槽位的类别告知责任交给选目标态的指令条（既有部件，本就要求自解释，不新增部件）；`Power` 改为详情页明示，其内容侧纪律原样成立。卡框色与类型角标是呈现层 UI 叠加、与插画分开，与 full art 相容 —— 且在无卡名可读的前提下，它们成为卡面唯一的非 `manaCost` 呈现元素，分量因此升格。

**插画内不得烧入承载可翻译语义的文字**（卡名 / 规则文字 / UI 文案 / 可读为语句的题字）：语义文字烧进美术资产等于把语言数焊进资产，切语言时静默留在中文，且失去热更通道。装饰性符文纹样、书法笔触、印章、匾额、残缺碑文**豁免** —— 受约束的是可翻译语义，不是笔画本身。该约束覆盖全部七个美术类目，不止卡面。

**缩略可辨从「看得出画的是什么」加强为「跨卡可区分」**：手牌区卡面很小且无卡名，插画是玩家辨牌的唯一通道，故同类目各卡的主体必须在剪影 / 主色 / 构图上彼此有别。

### 2. 手势分工：点按 = 详情，拖出 = 打出

卡面无文字使「点按看详情」成为刚需，必须与出牌手势显式分工：**点按手牌 = 升起详情页；拖出手牌区 = 打出**。

**详情入口的手势按对象是否可拖拽分化**：可拖拽的对象用点按开详情，不可拖拽的用长按。卡牌是手牌区唯一同时承载拖拽的对象 —— 长按与拖拽起手在同一根手指上争同一段时间窗；关键字定义、`Power` 详情、灰显道具原因三处均不可拖拽，长按无冲突。这条判据必须写在文档里，否则日后读者会把它当成漂移。详情页复用既有 bottom sheet 控件语言，不另造控件。

### 3. 结算呈现：逐层弹栈，不做滚动播报

结算 = 显示栈上的卡牌 / 效果，**逐层 LIFO 弹出，每弹一层做一次短暂的视觉强调，弹完即落账**。不可暂停、无滚动播报流，但保留因果顺序的可见性。

「不可暂停」读作**无玩家侧的暂停 / 跳过控件**；结算中途停下来问「指谁」是规则层的停顿加玩家的一次真实输入，不是暂停 —— 中途挂起进入可交互选目标态再继续弹栈，原样成立。

节奏参数复用既有那套，并提为双方回合通用：单步 0.35–0.5 s · 超过 4 步压到 0.2 s 并合并同来源 / 同类型 / 同符号的连续增量（跨来源不合并）· 点按任意处 3× 加速（只能加速不能跳过）· 永久快速演出为设置项。**「单个回合演出总时长 ≤ 4 s」这条硬上界只约束敌人回合** —— 它的论证针对完全无交互的整段观看，而玩家回合的演出是玩家自己出牌的结果、有心理预期。对称适用会在栈深大时撞天花板，届时只剩跳步一条出路，与「逐步可见是硬要求」相抵。

### 4. 战报（`combatLog`）

结算 ticker 与 stackHistory 不是两个部件，而是**同一份数据的收起 / 展开两个视图**，合并定名**战报 `combatLog`**。竖屏净增 0 个区。

- **收起态**：固定预留高度的单行，显示最新一条。**双方回合都常驻有内容**（此前只在敌人回合常驻、玩家回合清空）。固定预留高度这条纪律原样保留 —— 它的理由是防手牌区跳位干扰拖拽出牌的肌肉记忆，与战报归属哪一方的回合无关。
- **展开态**：本场战报的**因果树**，按一次结算批次分组并缩进 —— 一次出牌与它引发的整条触发连锁归为一组，按回合分组、默认定位最新一条。
- **条目粒度 = 结算事件**，不是卡牌：卡牌结算、触发式异能、疲劳扣减各占一条，保证「我的道念为什么少了 3」有账可查。目标落空是条目上的类别值加落空槽位掩码，不另立一类条目 —— 既有要求「部分槽位落空须写明是哪一半」，独立成条就写不出来。
- **保留本场全部条目，不设条数上限**。战报不进存档，故上限省的是内存而非存档体积；一场十回合量级不过几十条结构化条目。设上限恰好废掉本条自己的理由。
- **不进战斗存档**，退出重进从空开始，代价明写接受 —— 「自解释」这条硬要求的承担者是选目标态指令条，它不依赖战报。
- **展开态在结算态随时可开、演出不停**；**在选目标态禁用展开，收起态单行保留**。判据是「**是否与决策面争抢屏幕或语义**」：展开态是半屏面板，会遮挡栈区与合法目标，而栈区保持可见不被压暗、合法目标不被压暗、暗幕只压暗决策必需信息之外的一切三条是承重，叠加「单点即确认、不做二次确认、误触不做保护」会直接抬高误触率。随身抽屉一类入口争的是语义（可能改变局面），战报争的是屏幕 —— 两种争抢都构成禁用理由。
- **不上提为跨事件类型的 `eventLog`**。战报只属 Combat。三条理由各自独立：会制造第二权威（`PastEventEntry` 已是「一个事件里发生了什么」的事实来源，且被剧本调制、履历、诊断三方消费）；非战斗事件没有可记的时间轴（其余四类都是单决策点事件，而战报成立的两条前提——LIFO 栈使因果链长于 1、敌人不作事前预告故事中呈现是唯一情报通道——一条都不外延）；非战斗事件里唯一值得记的东西恰好必须隐藏（调制是隐藏属性的主要显影通道，中间档跨越对玩家完全无提示，诚实的日志会掀开这层）。
  **一句话纪律：一个权威、两种寿命 —— 事件内的过程态是纯呈现层、不落存档；事件间的账目归 `PastEventEntry`、落存档。**
- 也不用 `eventLog` 这个名字：本作已有三个 "event"（`EventBus` / `AdventureEvent` / `PastEventEntry`），第四个会让术语表无法写清。

### 4b. 工程形态：统一的呈现事件流

正确的抽象是**一条喂给呈现层的事件流**，不是「日志」这个实体。

在 combat-service 事件面定一条统一广播 **`CombatFeedEntry`**（`readonly record struct`），卡牌结算 / 触发式异能 / 疲劳扣减三类共走它，目标落空是条目上的一格。**它取代既有的 `CardResolved`** —— 一个事实只留一条广播。三个消费者读同一条流：飘字、战报收起态、战报展开态因果树；此前三处各自从出牌结果里捞，迟早不一致。

- 负载只带 `Id` 与值类型，不带 `CardInstance` 引用 —— 与既有理由同款：广播分配加 `Variant` 装箱，且不开绕过唯一写入入口的旁路。
- 条目**存结构化数据，不存已格式化的字符串**，渲染期才套 `res://text/` 翻译键。热路径不做 `string` 拼接，且否则战报会成为本作最大的一处文案字面量泄漏源。
- 因果父定名 `CauseEntryId`，与栈条目既有的 `sourceEntryId`（载体所在的战场条目）是两件事。
- UI 端持一个环形缓冲即可，容量覆盖本场。

### 5. 道念显示位：双方各随其头像

道念即本作的比分位，双方各随其头像展示。与既有的道念对比条**不互斥** —— 对比条是一条横贯元素，双方头像与数值分居其两端，合称**双方道念位**。三处以对比条为单一元素的布局纪律（结算记录紧贴其下、暗幕豁免、压缩顺序最后动）原样保留，只改指称；其中「紧贴」那处保留原指称，因为头像分居两端、改了就失去落位约束。玩家侧需要一个头像位（既有战斗屏只写了敌人立绘），它**不承担图鉴入口**，只作道念的锚点。

### 6. 疲劳改为入栈的一等条目

疲劳**以一条栈条目结算**，与触发式异能同形，且是完全一等的：**可被监听、可被响应、可被取消**。「疲劳时发动」的埋伏、「免疫下一次疲劳」的法宝由此成立。

疲劳被延后不会让对局不终止 —— `EncounterSpec.TurnLimit` 已为双方合计回合数封顶。这条判据要写下来，用来挡住日后重新提出「疲劳必须不可取消」。疲劳**不产生 `ActionResult`**（它不是玩家动作），但照常广播一条 feed 条目；它天然拥有栈条目 id，因果树因此无需为它特设空值路径。

### 7. `ActionResult`：玩家动作的统一返回类型

`PlayResult` 更名 **`ActionResult`**，按**玩家动作**产生。这是对现状的正名而非新增抽象 —— `ProvideTarget` 早已返回同一类型，该类型本就不只承载出牌。

- 新增 `UseItem` 动作签名，补上一处真实空缺：可用道具列表早已在战斗态视图里，API 面却没有任何用道具的方法。道具写入照走 `ProfileManager.TryApply`。
- `EndTurn` 由 `void` 改为返回 `ActionResult` —— 回合结束会触发结算（战场条目到期、道念变化），本就该有返回值。
- `PlayRejection` 更名 `ActionRejection` 并扩充道具相关的拒绝理由；动作主体字段泛化。
- **抓牌不纳入**：抽牌是回合开始自动发生的、以及卡牌效果的结算产物，不是玩家主动动作，没有调用方也就没有返回值可给。

**`Declared` / `Actual` 两级粒度并存**：`ActionResult` 承载一次玩家动作链路（含连锁触发）的汇总值，`CombatFeedEntry` 每条承载本次结算的增量值，呈现层只读 feed。两者不是重复 —— 状态视图无法重建 `Declared`：对方剩 5 点时打 8 与打 5，快照序列完全相同，被下限 0 吞掉的量在状态里不留痕迹。这也让敌人结算、触发式异能、疲劳三类（都拿不到任何 `*Result`）逐条都有值可显。

「每次结算是可观测事件」的适用面由敌人回合**推广到双方回合**：敌人回合的理由是它是玩家获取动态情报的唯一时刻，玩家回合的理由是 LIFO 连锁的因果需可读、且截断量必须被说明。

## Clarifications（interview 产物）

**用户主动提出的两项**（不在校验清单内，由用户在 interview 过程中提出）：

- **疲劳是否入栈** → 推翻既有的「疲劳不入栈、不产生 `PlayResult`，是抽牌流程内的一次直接扣减」，改为入栈且完全一等（可监听 / 可响应 / 可被取消）。无限对局风险由既有 `TurnLimit` 封顶，不新增机制。
- **`PlayResult` 是否应重定义为按玩家动作产生的 `ActionResult`** → 采纳，本次一并做完（含 `UseItem`、`EndTurn` 返回值、枚举扩充、字段泛化）。核实依据：`ProvideTarget` 已返回该类型，名字已名不副实；可用道具列表存在而无对应 API 方法，是真实空缺。抓牌经核不属玩家动作，不纳入。

**校验发现的裁决**：

- **战报展开态在选目标态是否可开** → 禁用展开、保留收起单行。判据由「有无可供性」改为「是否与决策面争抢屏幕或语义」。这收窄了原始输入的「随时可开」—— 原始判据漏了遮挡维度，而展开态是半屏。
- **`CombatFeedEntry` 与 `CardResolved` 的关系** → feed **取代** `CardResolved`（用户选择，非推荐项；推荐项是并存）。连带改事件面契约总表、三处热路径论证范例与 ADR-0011 的范例名 —— 论证本身不削弱反而加强，feed 覆盖四类结算、频率高于每张牌一次。
- **`Declared` / `Actual` 的载体** → 两级粒度并存。这解掉了原始输入自身的矛盾：一处写「载体不变」，另一处又把这对字段列进 feed 并把「三处各自去捞」列为待解决问题。
- **插画禁文字的判据与适用面** → 判据收窄为「承载可翻译语义的文字」并明写装饰性字符豁免，适用面提为全部七个美术类目。原始输入按字面禁「任何字符」会砍掉符箓、匾额、碑文、书法笔触、印章等中式美术核心语汇，而本作有以符箓为主体的牌；而它给的理由只对承载语义的文字成立。
- **演出总时长硬上界的适用面** → 只约束敌人回合。原始输入称三重护栏已答掉栈深失控，实则漏引了既有节奏条的第四项（唯一的硬上界）。
- **references 的「不借什么」列** → 本次顺手填：借画风与氛围，不借卡面排版。

**标准默认（自动采纳，未出题）：**

- 原始输入两处把「敌人图鉴」当作战斗屏内的既有部件 → 转述失实，战斗屏没有任何图鉴入口，bottom sheet 先例在战斗前确认页。按既有定案修正，论证不受影响。
- 原始输入称因果树「答掉了待答项『栈与战场的连锁可读性』」 → 不属实。实名是「栈与战场的同屏呈现」，且台账原话已写「已答结了连锁可读性的一半」。因果树是对已答结那半的加强，该待答项不移出，改写收窄。
- 因果父字段命名 → 经复核，栈条目既有的 `sourceEntryId` 指「载体所在的战场条目」，从不表达因果父，故 `CauseEntryId` 是真实缺口而非第二权威。
- 目标落空 → 条目上的类别值加槽位掩码，不独立成第四类条目。
- 原始输入称服务侧「已把适用面推广到双方回合」 → 不属实，服务侧三处仍写敌人回合，本次真做推广。
- art guide 的「公共约束」层在现结构中不存在 → 不新建层，用既有的权威条加类目表摘要回链的双写先例。
- guide 模板的占位是填写提示而非待定案空缺 → 只改提示词加括注，不填死（模板服务全部七类目）。
- 「缩略可辨」的两处（权威条与类目表摘要）须同改，只改一处即刻漂移。

## Open questions

- **卡牌详情页的内容清单与排布**（新增）：full art 把规则文字、卡名、关键字定义、`Power` 明示内容全部后置到详情页，一屏装哪些项、如何排布、是否需要分区或滚动、关键字定义在详情页内是否仍需长按二级展开。
- **战报条目的文案体系**（收窄）：排布与树形分组已定，仍待定收起态单行的信息量、截断量与目标落空如何在单行内表达、与飘字的分工边界。
- **启动式异能没有 API 方法**：决策点明写「一次出牌 / 启动 / 用道具结算完毕」，本次只裁决了道具动作，启动式异能是同一档的真实空缺。
- **竖屏分区过载**（既有承重待答项，已排期专场）：本次净加压为玩家侧头像位；战报因收起 / 展开共用同一格而净增 0。按该条已定的排期纪律，本次只记账、不就地裁决。
- **随身抽屉禁用态的措辞缺口**：既有写「敌人回合 / 结算中」，未点名选目标态。未经裁决，未改。
