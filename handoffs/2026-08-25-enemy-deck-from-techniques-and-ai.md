## 一行摘要

敌人与玩家**同源构筑**：敌方样本卡组由**功法 + 层数**展开（外加游离散牌），而不再是一张直接的卡牌列表。敌我共用同一套 `CultivationTechniqueData` 与同一注册表，玩家在敌人身上观察到的功法强度，就是自己习得后能拿到的强度。AI 分两层：通用兜底 + **挂在敌人模板上**的定制策略。

## Intent（distilled）

### 1. 敌方套牌也由功法组成

敌人的卡组与玩家同源：由**功法（`CultivationTechnique`）+ 层数**构成，大部分敌方功法都是玩家有机会在未来轮回中体验到的内容。

- `EnemyData` 的构筑面从「直接卡牌列表」改为 **功法引用列表（`TechniqueRef { TechniqueId, Tier }`）+ 游离散牌 `Id` 列表**。样本卡组 = 功法展开产物 ∪ 散牌。
  两段式而非纯功法列表，是为了与玩家侧的「卡组 = 功法展开的牌 ∪ 游离散牌」保持同构，并保住「卡组规模是一条疲劳编排旋钮」这条已成文的编排手段——纯功法列表会让规模只能按「功法数 × 每层卡数」整组增减。
- 战斗内照旧不感知功法：组装时展开为卡牌集合，与玩家侧同一条既有纪律。
- `KeyCardIds` 的校验基准 = 展开产物 ∪ 散牌的**并集**；「不得含 `Pool == Character`」的逐卡校验对象同样是该并集。
- 敌人图鉴词条②「功法简介」由纯风味文案升级为**指向真实功法条目**——图鉴写的运作方式即敌人实际使用的、玩家可习得的功法。

设计收益：图鉴知识可验证且可迁移；「击败后习得其招」有天然载体；敌我共用一套功法条目，内容产能减半。
被接受的代价：散牌不属任何功法，故「敌人卡组 = 玩家可习得内容」这一承诺留有一小块例外。

**敌方专用功法的过滤面。** `CultivationTechniqueData` 增一个**必填** `Pool : CardPool`（三值、无默认、缺失 `PushError`），与 `CardData.Pool` 同构同枚举。两侧对称生效：玩家侧候选取池叠一层 `Pool != Enemy`；`EnemyData` 引用的功法不得 `Pool == Character`（加载期 `PushError`，报出模板 `Id` + 功法 `Id`）。必填无默认正是为防「漏填的敌方内容悄悄进玩家池」。

### 2. 产出缩放与玩家同因，层数逐条固定

敌人各等级的道念产出缩放**不设敌方专属的隐藏数值乘区**——产出能力的决定因素与玩家完全一致。同一门功法同一层数，敌我两侧展开出的是同一批卡牌条目。

**层数在 `EnemyData` 上逐条编排为固定值，随赋级只动 `baseMomentum`。**

- 同一个敌人不因赋级变强变弱，卡组强度中立**在同一条目内**成立。
- 「强敌 = 更高层数」成立于内容层而非物化层；`EnemyLevelRange` 与层数**不建立机械对应关系**。
- 理由：卡组保持强度中立、不叠第二条强度曲线，否则 `±2` 赋级带的数值安全性推导立刻失效，而篇章耐久基线（余量系数 1.1 使炼气 10 成为公式的一个解）正建立在该前提上。层数是严格升级，按定义就是第二条强度曲线——让它随赋级浮动会使一份已成文的安全性推导当场失效，而「无隐藏乘数、观察即所得」这个核心诉求不需要靠层数浮动来兑现。
- 连带收益：层数固定 ⇒ 展开在加载期即唯一确定 ⇒ `KeyCardIds` 的加载期校验与图鉴的静态性一字不改。

**条目之间的层数散布须有护栏。** 层数固定只解决了同一条目内的浮动；条目**之间**的散布仍是一条与 `diff` 同量纲的旋钮（一档 `TechniqueTier` 差 ≈ 一档 `diff` 的 `baseMomentum` 落差），而 `lifeTotal` 境界基线的 1.1 余量没有为它留量。故：敌人功法层数按**篇章给一个基准档**（对齐玩家在该阶段的典型层数），逐条目偏离 **≤ ±1 档**；`lifeTotal` 基线段明写「1.1 余量的成立前提 = 敌我卡组层数相当」。这是**内容编排口径**，落 `/audit-content` 汇总（只报告不阻断），不进加载期校验。

**样本卡组的物化改写整条取消。** 原「赋级对齐 / 风味替换」被「按功法 + 层数展开」取代——保留一条作用于展开产物的二次改写会同时保留两条强度旋钮。随之 **`OverridesDeck` 字段删除**：物化改写不再发生，「关键卡牌不得被物化改写」这条检查恒真，豁免格恒无对象；天劫等条目的定制性改由 `Pool == Enemy` 的敌方专用功法承担，不为它开第二条构筑通道。

### 3. 敌人 AI：通用兜底 + 策略挂敌人模板

AI 结构两层：

- **通用兜底策略**：任何套牌都能跑的保底出牌逻辑，实现在 EnemyManager 内。
- **敌人模板级定制策略**：出牌策略挂在 `EnemyData` 上（「这个敌人该怎么打」），**不挂功法**。字段可空，空即走兜底。

策略经 `EnemyInstance.EnemyId` → `ContentRegistry.Get<EnemyData>()` 读取，**`EnemyInstance` 六字段不变**——模板常量不是物化产物。战斗内因此不需要认识功法，「功法是战斗外的构筑层，战斗内完全不感知它」这条纪律一字不动。

**定制策略只表达打法风格，不作强度 / 难度旋钮。** 难度仍只由 `baseMomentum` 与内容编排承担——同一批定案里一边否掉层数浮动、一边开 AI 强度通道会自相矛盾。「策略不得强于兜底多少」是不可机械校验的编排口径（软约束），不设校验。

**确定性约束：** AI 决策必须是「局面 + `combat` 子流」的纯函数；随机只取 `combat` 子流，不再派生新流；跨回合记忆必须可重算，否则必须落存档。

## Clarifications（interview 产物）

- **敌人层数是否随赋级浮动** → 逐条固定，赋级只动 `baseMomentum`；`EnemyLevelRange` 与层数不建立机械对应。推翻原稿「`EnemyLevelRange` 与功法层数的对应关系成为敌方强度的唯一表达面」一句。
- **AI 如何在战斗内取到功法策略** → 推翻原稿「AI 策略挂功法」：没有功法策略，策略跟随敌人模板定制。原稿收益「新增功法时 AI 自动获得对应打法」随之失效——策略逐敌人模板编写；`deck/_index.md` 不再需要为功法条目登记 AI 策略附属定义。
- **`OverridesDeck` 在物化改写取消后如何处理** → 删除字段；天劫的定制性改由 `Pool == Enemy` 的敌方专用功法承担。细化了原稿「`OverridesDeck` 语义不受影响」一句——语义确实没变，但已指向空集合。
- **敌人构筑面是否保留游离散牌一格** → 保留，与玩家侧同构。细化了原稿只写「功法 `Id` + `TechniqueTier` 列表」的构筑面。
- **条目之间的层数散布是否要护栏** → 立编排护栏（篇章基准档 ± 1）+ 在基线段明写前提；三条基线数字与两句承重文不动。这是原稿「条目之间的强度差异归内容编排」一句未交代的缺口。
- **定制 AI 策略是否算强度 / 难度旋钮** → 只表达打法风格，不作旋钮。
- **图鉴词条②手写正文是否仍写功法名** → 去掉功法名，只写一句路数；名字由引用字段在呈现层渲染。推翻 `enemy-codex.md` 原写作规格「功法名 + 一句概括其路数」——手写一份名字会与功法条目的 `LocalizedText` 构成第二权威，多语言 + overlay 热更下无法机械比对。
- **词条②的功法引用字段是单个还是列表** → 单个「主功法」、必填，加载期校验「须 ∈ 该敌人的功法列表」。细化了原稿的单数措辞；其余功法在敌人词条里无入口，一屏纪律优先。

**标准默认（自动采纳，未出题）：**

- 敌人引用功法加 `technique.Pool != Character` 的加载期闸 → 加。依据：`CardData.Pool` 在卡牌层本就是两侧各一条闸，功法层是它的同构上移；「敌方套牌不过滤」讲的是取池，不覆盖加载期编排校验。
- `Pool` 的定义落点 → 留在 `deck/_index.md`「卡池划分」节，不上移到 `deck/common-properties.md`。依据：该节的三条论证与枚举定义是同一条推理的两半；不搬迁仍只有一份权威。
- 敌我共用同一 `CultivationTechniqueData` 类型与同一注册表；展开产物不写回 `EnemyData`（共享只读单例），派生索引落 ContentRegistry。
- 被引用功法 `ContentEnabled == false` 不做连带过滤（读取侧不过滤纪律）；同一功法在一份 `EnemyData` 中重复列出 → `PushError`（层数是严格升级），但展开后卡牌重复仍合法。
- 词条②的引用字段只带 `Id`、不带 `TechniqueTier`（词条正文绝不写等级、不含阿拉伯数字）；悬空 → `PushError`。
- 图鉴静态性三句（「物化改写必须保留这 3 张」「词条文案挂模板且是静态的」「慷慨度 3 张关键卡」）一字不改。

## Open questions

- `EnemyData` 上「行为脚本的表达形态」（独立 `Resource` 还是内联字段）——归属已定（敌人模板），形态未定。
- AI 的具体算法、决策粒度（一次性 vs 逐张）、多回合行为倾向、难度旋钮的落点。
- `Pool == Enemy` 的敌方专用功法在功法图鉴中如何呈现——玩家永远学不到，却被敌人词条②的引用字段指向。写入面在功法图鉴一侧。
- `combat` 子流的三句互相矛盾（先于本次存在）：「敌人抽牌走与玩家抽牌不同的子流」 vs 「战斗内随机不在 combat 子流上再派生一层」 vs 子流常量清单只有 map/combat/shop/reward 四条。本次一律按「取 `combat` 子流、不新增子流」落笔。
- 一门功法含几张牌、层数上限 `MaxTier` 是几、每层的替换幅度多大——留待内容扩充后的统计校准。
