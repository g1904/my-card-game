## Intent（distilled）

refresh token 首版明文落 `user://cache/refresh-token.json` 已经定下，并把「平台密钥库是**后置评估项而非否决项**」写进了 `systems/services/account-service.md`。本次把「后置」两个字变成兑现物——它此前没有任何可判定的内容，而这类留口的失败模式是已知的：它不会在某天被想起来，只会在下一次「顺便看看还有什么没做」时被再次记为后置。

### 一、四端能力矩阵

按「有无 OS 级凭据机制 / Godot 侧有无内置绑定 / `user://` 的实际落点 / 消掉哪几条已登记残余风险 / 升级后新增的坏路径 / 边际成本」六行铺开 Android · iOS · 桌面 · Web。

矩阵读出两条结论，它们是后两件交付物的依据：

- **收益集中在移动双端，且只覆盖三条已登记残余风险中的「备份提取」一条半。** root / 越狱这条——三条里唯一被主动攻击者利用的——密钥库消不掉。升级的定性因此从「补上安全短板」降为「关掉备份提取这一条被动泄漏面」。
- **桌面与 Web 的升级收益是零，不是「小」。** 桌面是威胁模型使然（能读 OS 凭据库的进程与能读 `user://` 的是同一批），Web 是机制缺失。

矩阵中凡涉及 Godot 侧绑定与具体平台 API 行为的格子一律带 `[待核实]` 标注落笔——本机无法验证任何平台 SDK 行为，且 `game-feature-branch/` 尚无 `.csproj`。三项核实（Godot 4.7 有无内置安全存储绑定 · Web 导出 `user://` 的持久化后端 · Android Keystore 密钥失效的具体异常与触发面）并入已登记的「`.csproj` 生成后实测」批次，不单独排一次验证。**格子不删**：`[待核实]` 标注本身就是「此格非断言」的显式声明，而删格子会让矩阵不可读；两条结论均不依赖任何待核实格子。

### 二、升级触发条件穷举五条（T1–T5）+ 四条明确非触发

判据取两条轴：**明文的依据是否仍成立**、**升级的边际成本是否已被别的事付掉**。每条都是可机械判定的事件。

| # | 触发事件 | 轴 |
|---|---|---|
| T1 | 后端契约 `auth.md` §4 的 rotation 或「窗口外重放即吊销全部会话」任一条被改写 / 削弱 / 取消 | 依据失效 |
| T2 | 客户端出现第二份落盘的鉴权 / 支付材料 | 依据失效 |
| T3 | 首次为 Android 或 iOS 引入任何自有原生插件 | 成本已被付掉 |
| T4 | 出现一例经确认的凭据泄漏 / 盗号工单，路径落在三条已登记残余风险内（>0 即触发，不设阈值） | 依据失效 |
| T5 | 上架渠道 / 合规审核以条款形式要求凭据受 OS 级保护 | 外部硬约束 |

命中任一条 ⇒ 从后置项转为**必须在当次同批裁决**的工作项。**裁决可以是「仍不升级」，但必须给出结论，不得再记为后置。**

**明确不构成触发条件**（写下来是为了防日后被「补全」）：「有空了」· root 设备占比的统计数字 · 竞品做了 · 「安全总是好的」。

这组条件的形状取自本库既有的同型清单（失效路径穷举六条、条件编译清单穷举五处不得扩张），**穷举 + 明写反例**是本库处理这类留口的既定形态。

### 三、升级不引入平台分支（结论 + 三条理由）

1. **能力差异不落在 API 面上，落在一处实现内。** 落盘点已收敛为 `AuthManager` 私有的一处且无公开取值方法；升级 = 换掉这一处的读写实现，服务 API 面 / `Session` / 六条失效路径 / 三条读写失败处置一格不动。
2. **Web / 桌面不是「降级分支」，而是同一个默认实现。** 明文实现不被移除，它是四端共同缺省；移动双端在插件可用时替换。判据是「这一端有没有可用的凭据存储实现」（运行期一次探测），不是「我在哪个平台」——与 `BackendSelector` 的「唯一选择点 + 换实现而非插 `if`」同一条纪律。
3. **因此也不碰条件编译清单。** 平台实现的有无是构建产物层面的事，不是 `#if` 分支；清单仍是五处。

推论：`ui-input-rules.md` 的「仅在某项能力确有本质差异处分支」在此用不上——根本没有分支。

### 配套两条

- **现在不预留 `ICredentialStore` 之类的抽象。** 只有一处落盘点、一个实现、API 面已隔离，此刻抽接口正命中架构文档的抽象反判据；替换成本已经最低。
- **升级真发生时的落地形态**已备好（同一份 JSON 串换载体 · 一次性搬迁 · 失败语义落回既有的 `PushWarning` + 内存持有那一格 · iOS 必须显式选不随备份 / 不随 iCloud 同步的可访问性且必须明写 Keychain 条目卸载后存活 · 密钥库条目不适用原子写纪律故 `AtomicJsonFile` 调用方清单须同批复核），**不构成现在就做的建议**。

### 跨库承接（后端侧）

本次交付物全部由客户端实现，**后端零改动、零新增义务**。但 **T1 反向成立**：客户端明文取向的全部辩护挂在后端 `contracts/auth.md` §4 的 rotation / 吊销语义上，而后端侧此前零登记，其文末反而宣称本域「两侧无遗留欠账」。故在后端契约 §4 追加**一句只回链、不复述**的下游依赖登记，并把文末那句措辞调整为不与新增登记打架——两侧对称留痕，改写 §4 的人必然读到。

## Clarifications

- **T3 是「必须给出结论」还是「必须升级」？** → **必须给出结论**（草稿选项 A）。插件工程存在后强制重估一次，可裁决为「仍不升级」；由「必须在当次同批裁决、不得再记为后置」这句兜住。理由：密钥库消掉的是三条残余风险中的备份提取一条半，而内购本身并不放大凭据泄漏的后果（bundle 是一次性权益，兑现走后端验票），硬绑会把一件收益未变的事塞进本就最重的一批里。
- **T1 的反向承接项是否写进后端库、落在哪份文件？** → **写进 `backend-design-documents/contracts/auth.md` §4**，只回链不复述，并同批调整文末「两侧无遗留欠账」的措辞。这推翻了草稿「本草稿不写对侧文件，仅作建议交回」那一句。**不**写进后端 `open-questions/cross-boundary.md`——它不是待答问题，而是已成立的下游依赖事实，属契约正文；写进待答清单会成为一条永不答结的僵尸条目。

### 本次采纳的标准默认（未出题）

- **T1 的前置依赖成立，T1 原文照落。** 后端 `auth.md` §4 §5b 均标「承重」且已成文（rotation · 60 秒宽限窗口 · 求值顺序 · 绝对寿命上限 · `TokenReuseDetected` / `SessionExpired`）⇒ 草稿「若未定稿则改写 T1」的备选分支不触发。
- **矩阵中的 `[待核实]` 标注原样落笔，不删格子**（落笔后共 4 处标注，覆盖三项待核实事实——移动双端的 Godot 绑定合为一项）（属事实待查而非用户取向，且不改变机制形状）；三项核实并入既有的 `.csproj` 后实测批次。
- **两件交付物落在 `account-service.md`「refresh token 的持有与失效」既有小节内**，与该节的其余穷举表同形；不新建文档、不新增小节层级。
- **`ADR-0080` 加一行指向触发条件的回链**，决定本身一字不动（ADR 后果段已有「明文落盘 + 平台密钥库后置评估」一句，读者会在此止步而不知触发条件存在）。
- **T4 的判定主体在运营 / 客服侧**，不要求客户端提供任何上报机制，落笔时不为它新增客户端机制。
- **`AtomicJsonFile` 写入方清单本次不改**——它以「升级真的发生」为前提，现在没有任何写入方变化，只作为触发后的配套动作一句带过。
