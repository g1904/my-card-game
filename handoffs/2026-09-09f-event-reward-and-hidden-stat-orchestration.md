## Intent（distilled）

**一句话：** Combat 三档的奖励厚薄轴 = **换池**（篇章 × `combatTier` 九个具名池，每池五档全非空、厚薄由族与价位构成表达）；隐藏属性的逐条目推拉收敛为**一张语义判据表 + 一张可复算的供给对账表**；两条隐藏属性剧情线定形为 `SideStory` / 3–4 节点 / boss 走 `PlotModulation` 六字段。**零字段、零校验、零 schema、后端零参与。**

### 1. 厚薄轴 = 换池，不换权重表、不换抽数

三条候选路径逐条按既有结构检验，只有一条不引入新轴：

- **换池** —— 三档共用同一条生成路径，差异只在 `RewardPoolId` 与优势档 `Tier` 两格；换池正是既有结构**唯一已经预留**的档位差异旋钮。✅
- **换权重（按 `combatTier` 选不同稀有度权重表）** —— 权重表的分表维度是「按用途」，`combatTier` 是「由哪条路径给出」而非「什么用途」，加这一维与该分表判据同形相抵。❌
- **换抽数（`Practice` 抽 2 / `Finale` 抽 4）** —— 与「优势档只影响候选池的稀有度权重、不影响候选数量（恒 3）」直接冲突，且牵动战后奖励屏的三项逐项领取布局。❌

**厚薄落在「池里有什么」，不落在「怎么抽」。** 这与 `Practice` 档对神通的整族排除是同一条轴上的两个刻度（族排除 = 池成分的极端形态），故不引入第二条机制。

### 2. 池的编排维度 = 篇章 × `combatTier`（九个具名池）

- **池是一份逐条编排的具名成员清单**（`.tres` 编排面），不是一组过滤器；同一个内容条目可以同时属于多个池。这样池在加载期是可数出条数的确定集合，取池不足的三道闸才有对象可断言。
- **池 id 形态** `reward.<chN>.<tier>`：`reward.ch1.practice` · `reward.ch1.standard` · `reward.ch1.finale` · …… 共九个，与既有点分小写内容 id 同构。
- **每个池的成员覆盖 `Tier1`–`Tier5` 全五档、任一档非空。** 池不表达「哪些档可达」，只表达**族成分与具体条目**。
- **承重的机制事实：** 混合池上只按 `RarityTier` 加权抽 ⇒ **某一档的抽中概率就是权重表给的那个数，与该档在池里有几条条目无关**（只要非空）。故稀有度的**分布**完全由权重表承担，篇章差异必须落在权重表的篇章位移上；池只承担「抽中某一档时，玩家拿到的是哪一族、什么价位的条目」。
- **`Practice` 池不再在成分上重复表达神通排除** —— 生成侧的族级排除已机械兜底，池里写不写都不影响结果，写了即两处真值。
- **`ItemData` 族一律不含回寿法宝子集**（战后奖励池是免费通道，取池侧过滤）。

**三档厚薄的三个承担者（V 值口径）：**

| 承担者 | 形态 |
|---|---|
| ① 挂池率 | `Finale` 恒挂 · `Standard` 约三成 · `Practice` 偏低 |
| ② 同一档位上池里放什么条目 | 族构成与价位构成（同一 `RarityTier` 内，功法 / 神通族的定价族系数高于卡牌 / 道具） |
| ③ `Practice` 池的神通族排除 | 高价族整族不进候选 |

V 是**书写口径（可复算算式），不进 `.tres`**：

```
V(池, 篇章, 优势档) = Σ_i w_i × BasePrice(RarityTier_i) × k(族_i) / Σ_i w_i
  w_i        = 该篇章 × 该优势档的权重表在 RarityTier_i 上的取值
  BasePrice  = 定价表的稀有度基价向量
  k(族)      = 定价表的族系数
每场战斗的可选奖励期望厚度 = 挂池率 × 候选数量 3 × V(池)
```

**厚度比的目标形状**：与基础奖励灵石量的三档偏置**同向**（`Practice` 薄 · `Standard` 基准 · `Finale` 显著厚）；`Finale` 一格因「每章一次 + 恒挂池」而比灵石那一半更厚，这是被接受的取向。**三档 V 的具体数值待内容铺开后按上式核算**——在池成员与权重表两侧都还只有初值时给出精确比值，只会得到一个不可复算的数字。

### 3. `BaseReward` 中「其余 element 的量」= 恒空

这一格的答案不是一个待填的数字，是「结构上没有第二格」：灵石是唯一一格；仙玉走稀有事件通道；经验有模板侧独立的书写位，再装一份即与「物化后可出现的 key ≠ 模板可声明的 key」相抵；回寿只走 outcome 侧的三条通道；`ManaLimit` 量值恒 1 由 outcome 侧展开；四族内容走 `RewardPoolId`。**唯一的例外是少数条目的额外惩罚（`Spoils` 内的负向 `ChangeElement`），属逐条目编排，不是档位默认值。**

### 4. Combat 三档的默认 `HiddenStatGrade` 阶梯

| 档位 | 道心 | 煞气 |
|---|---|---|
| `Practice` | `Raise` · `Minor`(2) | 不填 |
| `Standard` | 逐条目（方向随语义）· 基准 `Standard`(5) | 杀伐类 `Raise` · `Major`(10) |
| `Finale` | 胜负同施 `Raise` · `Major`(10) | 首批不填（天劫是天道 / 自然，杀伐语义不成立） |

- `Standard` 档取 `Standard`(5) 是反推口径的直接读出；`Practice` 的「对位低一档」在基准 5 之下机械得出 `Minor`(2)；`Finale` 取 `Major`(10) 与它在灵石与寿元成本两张表上的最高档偏置同向，且恰为道心档宽的一半 ⇒ 渡劫必留印记，但单次不足以跨档。
- **煞气默认档比道心高一档**，依据是两张档位表的几何：煞气从 0 起须走满 75 点才到极值档，道心从 50 起只须走 30 点到 `+2`。两者取同档则煞气结构上到不了极值档，煞气反噬与它唯一的跨档文案双双零触发。

### 5. 语义 → `(Stat, Direction, Grade)` 的编排判据表

一张覆盖五类事件的**编排口径表**（不是校验），配三条编排纪律：一个条目至多两条 grant、默认动作是不填；`Travel` 一律不填（换图没有道德内容，且它已因不占事件位而少一道软闸，再开一条隐藏属性通道即开出来回横跳刷道心的口子）；`Explore` 壳不填、真身填。**`Travel` 那条以审计汇总项看住，不立加载期校验**——允许面对五类无一例外开放是结构结论，加硬校验即在结构上推翻它。

### 6. 行程口径：`Σ|Δ|`，方向不参与

隐藏属性的验收带（每属性每篇章跨档含往返 2–4 次 ⇒ 道心一章行程 40–80 点）里的**「行程」是沿路径累计的绝对量，不是净位移**。这是该处三个数字（40–80、平均单次幅度、「基准映射值略高于上沿」）唯一逐格自洽的读法，须写死在权威处以防再被读成净位移。可复算式：`跨档次数 ≈ 行程 ÷ 档宽`。

**推论：内容池的方向配比对行程零影响**（行程不看方向），它影响的是净位移与饱和形态。

### 7. 饱和才是跨档次数的真正约束

行程只有在**不撞值域端点**时才等价于跨档次数。道心 `[0,100]`、起点 50、档宽 20 ⇒ 单向至多两次 outward 跨档，此后行程被端点吸收；煞气 `[0,100]`、起点 0、档宽 25 ⇒ 单向至多三次。而验收带要求 6–12 次 / 轮回。

⇒ **反向供给面（道心的 `Lower`、煞气的净化 / 忏悔 / 疗愈）是达成验收带的必要条件，不是可选点缀。** 缺了它，行程被端点吸收，跨档次数塌到单向上限。这条从煞气一侧扩到两侧。

### 8. 道心的默认叙事 = 「修行本身即精进」

逐条目内容池取字面对称 `Raise` : `Lower` = 5 : 5，但 `Practice` 与 `Finale` 的道心推拉是**档位默认恒 `Raise`、不进内容池配比** ⇒ 一个篇章的结构性 `Raise` ≈ +20。**不刻意选择的玩家每章净上漂约 20 点**：道心通明（Band `+2`）在第二篇章近乎必达；**心魔滋生退化为主动选择型剧情线**，被动触发率不足一成，要触发须持续在带道心推拉的条目上选 `Lower`。

### 9. 两条剧情线的结构形态

两条同形：`SideStory` · `ChapterScope` 空 · `PlotTriggerId` 对接两个极值档 · 同 `ExclusiveGroup` · 3–4 节点 · 入口叙事 → 1–2 调制 → 剧情线 boss（`EnemyPoolScope` + `LevelBias` + `Tighten`，零新结构）→ 终止 · 至少一处 `ChooseBranch`。`ChapterScope` 恒空的理由须写进文档（否则会被顺手填上）；3–4 节点既是下界（少于三节点就没有 boss 节点，而 boss 是这条线唯一的高潮落点）也是上界（第三篇章触发时须能在剩余事件位内跑完）。**两条线的触发通路不对称**——煞气反噬在默认路径上，心魔滋生是主动选择型——编排密度据此分配，但**节点规模不因触发率下调而缩水**。

### 10. 审计落点：审计汇总项三条（只报告不阻断）

1. 逐篇章 × 逐属性的 `Σ|Δ|` 与 `Raise` / `Lower` 构成，对目标带比对；单列「`Travel` 条目携带推拉」「`Explore` 壳条目携带推拉」两项异常。**道心携带面的目标带 = 18–20 个事件 / 篇章。**
2. **煞气的反向条目配额 ≈9 条 / 篇章**（净化 / 忏悔 / 疗愈 / 放生类）。
3. 逐 `RewardPoolId` 池的族与价位构成、五档是否全非空、V 值比。池**深度**已由取池不足的三道闸看住，本项不重复造闸。

## Clarifications（interview 产物）

- **`reward.<chN>.practice` 池的稀有度上界（`Tier1`–`Tier2` 还是仅 `Tier1`）** → 该问法本身作废：**每个池五档全非空**，池不再用档幅上下界表达厚薄。用户原话「让每个 Tier 都有一定可能性，只是碾压给更好东西的概率更大点」。⇒ 草稿 §B 的九池成分表（ch1 `Tier1–2` / `Tier1–3` / `Tier2–4`、ch2 / ch3 逐章上移）整表不落笔。
- **既然每档非空，篇章差异落在哪里** → 落在**权重表的篇章位移**（三张按优势档分的权重表各配一个篇章乘数），不落在池成分。承重的机制事实（混合池只按 `RarityTier` 加权 ⇒ 某档抽中概率与该档在池里有几条条目无关）随之写进权威处。位移的取值与上界（有效递减比必须 < 1，否则分布单调上升、最稀有档成为最常见档）落在分片 A 的写入面。
- **奖励池的数据载体** → **具名成员清单**（`.tres` 编排面），一个条目可同时属于多个池。⇒ 九个具名池成立；「载体形态待定」不作为待答项留存。
- **道心内容池的方向配比** → **维持字面对称 5 : 5**，但草稿记下的两条后果（「净方向完全由玩家选择决定」「随大流的玩家可能整章不跨一次档」）**经核算不成立，不予沿用**：档位默认恒 `Raise` 不进内容池配比，结构性 `Raise` ≈ +20 / 章 ⇒ 默认叙事是「修行本身即精进」，道心通明第二篇章近乎必达，心魔滋生退化为主动选择型（被动触发率 < 10%）。**档位默认不动**（不改 `Practice` 不推 / `Finale` 胜负同推的既有口径）。
- **草稿引入的「净比 η」** → **不存在**，是对验收口径中「行程」一词的误读。权威口径是 `Σ|Δ|`、方向不参与；该处三个数字只有在这个读法下逐格自洽。⇒ 草稿 §F 的 η 一节整节不落笔。
- **道心行程超上沿后的收口方向** → **缩**携带面到 **18–20 个事件 / 篇章**（不是扩）。行程 102 超验收带上沿 27%，收到 18–20 后回到 ≈85，与已成文并被接受的「略高于上沿」对齐。退让阶梯照守：携带面是第一顺位旋钮，映射值 2/5/10 不动，档数永远不动。
- **煞气的反向配额** → 从「每篇章 ≥3 条」提到 **≈9 条 / 篇章**。代价已接受：每篇章要写 9 条净化 / 忏悔 / 疗愈类条目，占 35 个事件的约四分之一。
- **两条剧情线的编排投入是否随心魔滋生触发率下调而缩** → **不缩，维持 3–4 节点**。3–4 是 arc 的最小可用规模，砍到两个节点就没有 boss 节点。
- **战后奖励池排除含寿元产出的道具** → 采纳，九池成分中 `ItemData` 族一律不含回寿法宝子集；草稿刻意留的那个口就此填上。
- **奖励厚薄的九池维度与「战后奖励面板不是每场都开（约三成 Combat 条目挂池、`Finale` 恒挂）」是否冲突** → 不冲突，是正交两层：**挂不挂池**是频率轴，**挂哪个池**是厚薄轴，两者都落在 `RewardPoolId` 这一格里、互不覆盖。**连带的措辞订正：** `Practice` 池须写成条件口径（「`Practice` 档条目**若**挂池，取该篇章的 `practice` 池」），而不是「`Practice` 档的战斗从这个池抽」。
- **标准默认（自动采纳）：** 两条 arc 取 `SideStory` 不取 `SideChapter`（跨篇章不重置 + 触发时点不可预知）· 同 `ExclusiveGroup`（既杀伐又背信的角色会同时满足两条触发条件）· boss 节点走 `PlotModulation` 六字段（零新结构）· 两条线都不给干净的好结局（grimdark 基调）· `Travel` 一律不填且不立加载期校验（改以审计汇总项看住）· `Explore` 壳不填真身填 · `Finale` 煞气首批不填 · 池 id 形态 `reward.<chN>.<tier>` · 道心对账表补齐 `Explore` 真身一行（煞气表已含该行，两半口径须一致）· 道心侧改写成与煞气侧同款的带符号求和形态。

## Open questions

- **`HiddenStatGrade` 三个映射值（2 / 5 / 10）的统计校准** —— 反推验收项，不是死数字；本次已解除它对「增减触发未定」的依赖，但标定本身仍待内容扩充后实测。它约束的是标定，不阻塞任何结构。
- **第二、三篇章的逐类型事件构成表尚未补齐** ⇒ 两张推拉供给对账表**只有第一篇章可复算**；后两章须待构成表补齐后按同一条式子算出，不在本次臆造。
- **战后奖励池权重表的篇章乘数取值**与卡牌产 / 削道念的量纲基准，落在另两份并行意图的写入面上；V 值的绝对取值依赖前者，玩家实际拿到的稀有度分布依赖两者共同决定。
