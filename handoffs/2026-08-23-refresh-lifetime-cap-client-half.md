## Intent（distilled）

**一句话：** 后端给 refresh token 链加了一个绝对寿命上限（机制、旋钮、报文全归对侧），落到本库只有两件事——一条二级文案，和一个软信号的反应形态。**API 面 / `Session` / 存档 schema / 四处阻塞点清单全部零改动。**

> 机制本身——上限是什么、取几天、报文长什么样、`reasonKey` 叫什么、软信号如何判定——权威在 `backend-design-documents/contracts/auth.md` §5b，**本库不复述，只回链**。

### 1. 新 `reasonKey` 的落地 = 一条翻译条目，零代码改动

本库的二级文案键是**机械变换**的产物（`ErrorText.For(code, reasonKey, error)` 已吃三个参数、已有未知回落、反向审计已放宽为前缀匹配），故后端新增取值时本库需要且只需要在 `res://text/` 的 `ERR_` 分区加一条条目：`ERR_AUTH_SESSION_REVOKED_SESSION_EXPIRED`。

**措辞取最平淡的例行口吻，且不附原因句。** 登录链到期是一次完全正常的例行事件——玩家没有做错任何事，也没有第二台设备在动他的账号，与「被挤下线」在情绪上必须明确区分。只说要做什么（「登录状态已过期，请重新登录」），不解释为什么：一句「为保障账号安全，登录状态会定期过期」读起来更安抚，却把一个**后端可调旋钮**写进了翻译条目，改值时两处不同步即静默失准，而没有任何机制会报错。

**本项不阻塞任何发版**：未知 `reasonKey` 回落一级键已定，两侧发版顺序任意。

### 2. 软信号 `reauthRecommended` 的反应形态（三条）

- **只在内存里持有，绝不落盘。** 它是本次进程内的一次性提示；落盘就变成一个「过期了还在生效」的本地状态，且破坏 `refresh-token.json`「只放鉴权材料」的字段集判据。
- **不做任何时间判断。** 收到即为真、未收到即为假；不推算、不折算、不与任何本地时钟比较。这是「设备时钟不可信」在本项上的直接兑现，也是后端把它做成布尔而非时间戳的原因。
- **反应 = 在下一个自然时机主动走一次 `signin`，不是任何阻塞。** 自然时机取**启动期**：静默续期成功且收到该信号 → 直接呈现登录屏（会话仍有效，故它是可跳过的）。启动期是唯一一个必然经过、必然空闲、且已有现成屏幕的时刻，**零新增屏幕、零新增触发接线**。**失败即忽略**——玩家取消或登录失败时当前会话照常有效；它是一次邀请，不是一道门。

**归属 = `AuthManager` 私有，API 面零改动**——与 `deviceId` / refresh token 同款：一个公开取值口就把「挂个本地判断」变成一行代码的距离。

### 3. 明确不做的三件事（写进文档，防日后被「补全」）

- **不新增阻塞点。** 到期重登复用既有的 `auth.session_revoked` 硬阻塞路径，软信号则完全不阻塞；四处阻塞点的穷举清单一字不改。
- **不持有、不推算、不展示任何「还有几天到期」。** 没有一处 UI 需要它，而持有它就等着被拿去做本地判断。
- **软信号不使任何 token 失效**——它不是 `refresh-token.json` 六条失效路径的第七条，只是提前去换一条新链。

### 4. 顺带消除的计数副本

`ux/error-and-blocking-ux.md` 原在回链后端取值表时写死了条数（`session_revoked` 七值 · `nickname_rejected` 三值）。**条数同样是一份会漂移的副本**，与本节自己那条「取值集合由后端契约给出、本库不维护第二份清单」同向——改为不带数目的回链。对侧同批消除同形写法。

## Clarifications（interview 产物）

两项取向已于 08-23 批量评审裁决，本次照裁决落笔：

- 到期重登的玩家措辞基调 → **最平淡的例行口吻，不附原因句**（理由与本库既定的「`message` 不给玩家看、文案按 `code` 取」同源：玩家需要知道要做什么，不需要知道机制）。
- 软信号的「自然时机」取哪一档 → **启动期续期成功即呈现可跳过的登录屏**。备选「仅在无进行中轮回的主菜单触发」永不打断任何流程，但需要一个「有没有进行中轮回」的判断点与一处新的触发接线，而软信号的提前量足以覆盖至少一次冷启动，增量覆盖面很小。

## Notes / triage

**本方案不推翻本库任何一条既定纪律**：阻塞点清单不变、时钟纪律不变、`refresh-token.json` 的六条失效路径不变、API 面不变。`account-service.md` 末段「收口手段全在后端侧、本库不代为决定」是一句**指向待办的占位**，收口定案后本就该改写为回链——这不是张力。

「客户端自行按距上次 `signin` 的天数强制回登录屏」照旧否决（撞「设备时钟不可信」：一台时钟偏了的设备会凭空强制重登或永不重登）；「把后端下发的到期时刻存进 `refresh-token.json`」照旧否决（撞「不存过期时刻」）。
