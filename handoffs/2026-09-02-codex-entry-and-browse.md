## Intent（distilled）

图鉴族共**七本**（Enemy / CharacterPower / PlayerPower / CharacterItem / PlayerItem / Location / Technique），存档面已就绪，但**呈现面整块空缺**：主菜单入口表里没有图鉴，七本在游戏里没有任何可达路径。意图机制移除后，敌人图鉴是**事前敌人知识的唯一通道**，故浏览形态不是装饰面——读不到就等于那条通道不存在。

### 入口 = 主菜单一个「图鉴」一等入口

主菜单入口表新增一行 `Codex（图鉴）`，位于 Achievement 之后、Settings 之前；Store 恒在末位。三条依据：

1. **一族的立论就是「七本差别只在收录对象」**；在最显眼的一层拆成七个平行入口等于在 UI 上否掉自己的抽象，且收益为零（七个入口不比一个入口更快到达任何一本）。
2. **主菜单是账号级视图的落点**，图鉴是账号级的；三条元进程积累线里另两条（PlayerPower / Achievement）都持一等入口。
3. **竖屏容量**：六行按钮仍在单手可及区内；十二行会把 Store 推到需滚动才可见的位置。

入口是**纯标签**——不带红点 / 角标 / 动效，沿用 Store 那条呈现纪律；**无条件可见、无门禁**（首玩时七本全空，空图鉴本身就是「有东西可收集」的呈现）。总完成度不上主菜单。

### 三层结构：索引页 → 单本页 → 词条

```
主菜单 ──▶ CodexIndexScreen（七格索引）──▶ CodexBookScreen（单本）──▶ 词条
                                                                  ├ 敌人本：CodexEntryScreen（全屏页）
                                                                  └ 其余各本：半屏 bottom sheet
```

净增 3 屏 + 复用 1 个既有控件（bottom sheet = 「随身」抽屉同款控件语言）。**不做一屏七页签**：七个页签在窄屏溢出成可滑动页签条、标签被截断，且页签栏吃掉的纵向空间正是索引页最该放完成度的地方。

- **索引页** = 七格网格（窄屏 2 列 / 平板 3 列），顺序恒定按 `CodexKind` 成员序，不按完成度 / 最近解锁排序——位置恒定是收集面的一部分。每格一条完成度 `已收录 / 总数`（两个整数，不是百分比条；分母口径 = `AllIncludingDisabled()`，地域本只计已解锁顶点）。
- **单本页** = 纵向滚动网格（窄屏 4 列 / 平板 6 列，`GridContainer.columns` 随宽度调整），不分页——逐字复用储物袋已定的网格语汇。条目按 `Id` 升序（稳定序），不按解锁时间；不新增 `SortOrder` 字段。首批不做筛选 chip、不做排序切换（图鉴只有二值解锁态）。
- **格内容**：已收录格 = `Artwork` + 名称。`Artwork` 挂在七类内容定义上，`EnemyData` 在列 ⇒ **敌人本的格用 `EnemyData.Artwork`**；**只有功法本恒无视觉资产**，用统一占位图 + 名称。
- **未收录 = 灰态占位格，只有通用锁形图标**：不给名、不给剪影。不给名是因为首遇的信息差是首遇的风险定价；不做剪影是因为剪影要为每个条目另出一份美术资产。点按给一条「尚未收录」提示（触控等价，非 hover）。
- **词条载体按词条深度分野**：敌人本全屏 `CodexEntryScreen`（五项结构化文案，第⑤项即关键卡 3 张，另有可点入的功法词条入口）；其余五本半屏 bottom sheet；地域本的词条载体随其词条深度定，本次不裁决。
- **图鉴屏内的敌人词条页没有等级页眉**——词条挂模板、跨轮回持久，图鉴屏没有「本次实例」可标。

### 地域本：只有单本页的内容区不套用

入口 / 索引格与完成度口径 / 文案分区 / 触控纪律四层全部套用统一形态；**只有单本页的内容区不套用**（其余六本是滚动网格，它是一张逐步显影的图）。**地域本边缘态显示真实地名是全族唯一例外，不推广到其余六本**——地名之外什么都不给，而敌人名 / 功法名一给出去就把首遇的风险定价泄掉。

### 工程面：零新增存档字段、零后端配合

两个 ViewModel 随屏出生 / 随屏消亡，开屏组装一次并缓存至离屏，不进 `_Process`；订阅翻译变更重组装一次。不新增存档字段 / `ProfileChangeSpec` 列 / 提交点 / 缓存文件；Codex 不进透明路径白名单 ⇒ 后端零配合。条目解析不到 → `PushWarning` + 跳过该格、不阻断本屏。

翻译键全部落 `PROFILE_` 分区 / `profile.csv`，不新开 `CODEX_` 分区；敌人词条五项的项目标签与战斗前确认页共用同一批既有键。词条正文 / 条目名 / 风味文案不走翻译键——内容层 `LocalizedText`。

## Clarifications

- **主菜单入口是否显示总完成度 → 不显示，纯标签。** 完成度只在索引页内逐本给出。依据：图鉴靠「看着它变厚」自持、不与任何发放挂钩，主菜单上的数字是把这条动机往外部激励挪一步；且同屏 Store 明令无角标。
- **轮回内（EventOption 选择界面）是否给图鉴入口 → 不设，图鉴只在主菜单可达。** 战斗内一律锁死这一条不变。依据：战斗前确认页会自动呈现已解锁敌人的词条，轮回内主动查图鉴的高频用途已被覆盖；且角色状态条上现有入口全是轮回级。
- **主菜单「五项」的写死计数 → 改写为「Store 恒排末位」**（标准默认）。Store 的四条承重纪律一字不动；角色选择屏那句改为「不新增主菜单入口」。
- **灰占位在两处判据相反 → 在图鉴屏与战斗前确认页两侧各写一句边界**（标准默认）。确认页的空槽是每场战斗重复一次的提醒；图鉴屏的灰格是收集面的分母框，而分母已由完成度公开。
- **草稿的一处事实错误已在提炼时修正：** 草稿称 `Artwork` 仅 `PowerData` / `ItemData` 两类有，系误读；`EnemyData` 有立绘。⇒ 敌人本格用 `EnemyData.Artwork`，只有功法本需要统一占位图。「内容侧为敌人本 / 功法本各准备一张占位图」相应收窄为只有功法本。

## Open questions
