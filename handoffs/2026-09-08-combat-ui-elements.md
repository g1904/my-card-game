## Intent（distilled）

一句话：**战斗屏九项叠加元素与二级面板一次落形——随身角标与两级标识 · 只读层的单行图标条 + `+N` 溢出 · 埋伏两侧形态 · 卡框色与类型角标 · 详情页清单与禁用档 · 战报文案体系 · 疲劳三格 · 战后奖励面板 · 敌人台词落点与 `LineSlot` 五成员；零新增字段、零 schema、零后端配合。**

方向此前已定得很密（道具 = 角标 + 抽屉 · `Power` = 低权重小图标条 · 埋伏只给计数 · 卡牌类型 = 卡框色 + 类型角标 · full art 把一切文字后置到详情页 · 战报收起 / 展开共用一格），但九项的**具体形态**一项都没落。它们卡住三件事：`LineSlot` 空枚举使 `Lines` 只能是空数组；战报的两条硬要求（截断量必须被说明、目标落空必须被说明）在「单行、永不换行、≈ 屏高 6%」下尚无可执行的表达形态；只读层因「神通不设持有数量硬上限」而条目数无上限，形状必须能容纳 N 条。

### 1. 随身：角标形态与 `AbilityScope` 两级标识

胶囊形容器（道具图标 + 数字徽章），可用件数为 0 时**置灰保留不隐藏**（隐藏会让玩家以为功能消失，也会让战场带宽度在战斗中途变化）。两级标识 = **一枚形状化角标**，不用文字（UI 不能靠中文名传达「这是账号级的」，且「法宝 / 古宝」共用字根）、不用边框色（已被卡牌类型占用，两套色系必然相撞）；与只读层共用同一套形状，同一个枚举在战斗屏只学一次。抽屉内按两级分段（法宝在前、古宝在后），让角标成为确认信息而非唯一信息。长按 = 升起详情页那一份 sheet，不可用时顶部追加一行原因。

### 2. 只读层：单行图标条 + `+N` 溢出聚合格

**不折叠为角标**（随身是可操作层，角标点开是操作入口；只读层的价值是常驻可读——`Power` 开局入场整场不变，藏进角标等于逼玩家每回合去查）；**不做滚动**（横滑已被随身抽屉与事件选项占为「浏览候选」的语义，且与「拖出手牌区 = 打出」在同一片区域争同一根手指；滚动条也给不出「还有几条没看到」的常驻表达）。

条内最多 K 个图标，超出时第 K 格换成 `+N` 聚合格，点按升起半屏 sheet。**K 是派生量**：`K = floor(可用宽度 ÷ (最小触控目标 + 间距))`，硬下界 `K ≥ 3`，初值 5。**溢出格不得吞掉启动可供性**——折进去的条目中只要有一条此刻可启动，`+N` 格自身即带强调态。固定序：神通在前、法则在后，同段按入场顺序，不按稀有度。宽度不足 3 个最小触控目标时，整条上移为战场带上沿的「己方资源条」，**不得移出战场区**（`Power` 住在战场上，位置即语义）。

### 3. 埋伏：己方逐条渲染，对手侧固定预留位的计数

己方埋伏折叠会**没有可寻址的战场条目宿主**，服务逐条目填充的启动可供性将永无消费者；要救就得再造一层展开列表，撞「零新增常驻部件」。故己方埋伏 = 战场条目的面朝下变体，与正面阵法同尺寸同槽位；溢出退让为带内横滚，**绝不退让为折叠**。

对手侧 = 「图标 + 数字」计数标记，**计数为 0 时整格淡出、容器尺寸不变**。两侧 0 值处置不同的判据：**它是不是一个入口**——入口必须可点、必须能给说明，故置灰；纯指示无处可点，淡出即答案。

### 4. 卡框色 + 类型角标

手牌与战场卡面上只会出现四类（`Power` 在战斗内一律以技能条目呈现），仍做一套五色但缩略可辨性只按四类校准。**颜色管「哪一类」，形状管「同一类」**——类型角标必须脱色后仍两两可辨，否则两个元素表达同一维度即是浪费。卡框色 = 外缘细描边 + 一条较厚色带，不整框着色（吃插画面积）。`Affliction` 的角标须最醒目——它是唯一「打出无任何正面效果」的类型，认错的代价高于其余四类。色相三条约束：缩略尺寸两两可辨 · 灰度化后仍两两可辨 · 不与三套状态视觉相撞。

### 5. 卡牌详情页：一屏清单与禁用档

bottom sheet、内容自适应、上界屏高 60%、超出页内滚动，**不分区、不分页、不加 tab**（详情项只有 5–7 项，tab 多一次点击，滚动是移动端母语行为）。七项自上而下、缺项整行不渲染；战斗内不显示 `Rarity`；关键字仍走长按二级展开，宿主换成详情页。

**禁用档与战报展开态同档**：判据仍是「争屏幕还是争语义」——手牌详情页纯只读不争语义、是半屏面板故争屏幕 ⇒ 敌人回合 / 结算中**可开**（那段观看里玩家正好在规划下一回合），选目标态下入口天然不存在。三行对照表须写进文档，否则后来者会读成禁用规格不一致。

### 6. 战报的文案体系（承重）

**分工判据一句话：不读也不会错过的归飘字，不读就读不懂的归战报。** 飘字 = 量与归属，不承载因果与例外；战报 = 事实与例外。三条推论：截断量与落空只进战报（实际量为 0 时飘字本就没有数字可飘，而那正是两条硬要求要说明的那件事）· 飘字取实际量、战报取标称 / 实际一对且不设延迟 · 飘字不表达因果。

**收起态单行 = 结构化槽位**：`[归属方] [动作动词] [来源名] · [增量]`。取「敌方打出「回风诀」 · 你 −5」这一档——只写动作不写结果，就把「我的道念为什么少了 3」这个战报存在的唯一理由整个推给展开态，而玩家不会主动开日志。**省略顺序是一条规则：优先省略来源名，绝不省略增量。**

**截断与落空在单行内以符号标记表达，括注只在展开态**——在单行 + 永不换行 + 超长省略下，被省略掉的恰好就是括注本身。两枚符号须非数字、单字宽、互不相似，且与飘字的 `+N` / `−N` 不同源；不做说明浮层。翻译键随 `CombatFeedKind` 成员机械对应，来源名作格式参数插入、不进翻译键。

### 7. 疲劳三格

剩余张数**常驻**（叠在抽牌堆实体上，零新增区）——疲劳是一条确定性可预算的失血曲线，不常驻就把一条可算的账变成突然发生的事。见底预警**只给一档、纯静态**（`<= DrawPerTurn × 2` 转红字，不闪烁、不弹提示、不加音效、不写预警文案），与寿元余量的处置逐字同构；阈值写成派生量而非固定张数，因 `DrawPerTurn` 可被覆写 / 收紧。飘字侧「疲劳」与「被削减」**按起飞点区分**——疲劳没有任何来源对象，飘字自抽牌堆飞出；**颜色不参与归因**，否则会与三套状态色争语义。

### 8. 战后奖励面板

战斗流程内的全屏一屏，三段（结果 / 强制 / 可选）+ 底部全宽主按钮。强制段必须展示——玩家不看这一屏就再也没有地方知道拿到了什么，且**失败侧的额外惩罚正是以负向条目包在 reward 内**，不展示等于让惩罚静默发生。强制 / 可选靠「有没有按钮」这个结构差区分。竖屏纵向堆叠全宽行、**绝不横滑**——横滑正是「择一」的语汇，而「三项各自独立可领」是这块的承重语义。已处置项就地置灰保留（面板逐格映射 `picks`，而 `picks` 不可增删不可重排），**但两个按钮移除而不是置灰**——灰态要求继续接收触控并给说明，而此处已成事实、无说明可给。主按钮在仍有 `Pending` 时置灰并给一行说明；与事件结算面板两屏顺接不合并，否则「计算归战斗、施加归生命周期」的分工在 UI 上糊掉。

### 9. 敌人台词：落点 + `LineSlot` 五成员

落点 = 敌人立绘**上方**的非常驻浮层气泡，不进任何 `Container`（出现 / 消失不触发重排）、约 1.5 s 淡出、不可点不可关闭、触控穿透；**与既有节拍并行播放，不新增等待节拍** ⇒ 敌人回合 ≤ 4 s 的硬上界原样成立。

`LineSlot` 首批五成员全部落在既有可观测时刻上，不新造时刻：`OnCombatStart` · `OnFirstEnemyTurn` · `OnEnemyMomentumLead`（一场至多一次）· `OnEnemyDefeat` · `OnCharacterDefeat`。新增成员一律追加末尾，**声明顺序不表达时间轴**；**绝不给 `EnemyLine` 加权重 / 条件 / 概率**（那会变成第二套触发系统，而触发式异能已经是那个系统）。**硬纪律：台词永不承载规则信息**——否则它就是「敌人的行动不作任何事前预告」的旁路。

## Clarifications（interview 产物）

- **抽牌堆剩余张数是否常驻战斗屏？** → **A · 常驻**（批量评审裁决）。数字叠在底部条的抽牌堆实体上（该实体由姊妹 handoff 确认存在）⇒ 见底预警与飘字起飞点两条随之成立，两个退让位不再需要。
- **敌人台词是否进战斗屏（它决定 `LineSlot` 成员本身）？** → **A · 进战斗屏**（批量评审裁决）。五成员按上表落笔；立绘**上方**气泡、≈**1.5 s**、不进 `Container`、与既有节拍并行；硬纪律「台词永不承载规则信息」一并采纳。
- **只读层形状（跨稿统一）** → 本稿的「单行图标条 + `+N` 溢出格、不滚动、`K ≥ 3` 初值 5」获采纳；姊妹 handoff 的槽位契约按此对齐。
- **卡面必读元素占位**（标准默认，未出题）→ `manaCost` 占左上角、类型角标紧邻其下、卡框色带落左边缘；右上角在重叠扇下不可见，不承载任何必读元素。
- **「面板长度恒为 3」的措辞松动**（标准默认，未出题）→ 改为「候选项数恒为 3，池不足时显式降级为实际项数；面板逐格映射 `picks`，不渲染空槽」。既定处置本就允许显式降级、不静默给 2 项；空槽占位反会被读成加载失败。
- **灰态判据表补一行边界句**（标准默认，未出题）→「暂时不可用 → 置灰并保留触控；已成事实、永不恢复 → 移除控件」。原表每一行的判据都是「暂时不可用但仍是入口」，本条是补齐而非推翻。
