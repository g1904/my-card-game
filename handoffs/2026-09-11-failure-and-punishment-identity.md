## Intent（distilled）

**一句话：** 失败在本作里是**代价，不是学费**——游戏不评价、只记账；惩罚的绝对值随境界层层放大而**体感恒定**；全作唯一一处角色用自己的声音说话的地方，是它死的那一刻。

### 一、失败的性格：代价，不是学费

游戏对玩家的失败不作任何评价——不安慰、不鼓励、不总结教训，只如实记账。整个轮回**没有「失败画面」**，只有寿元在变少。

- **失败侧产出的定性口径改写。** 经验 50% / 图鉴遭遇即记 / Finale 失败累积残卷，这三条读作**「你走过就留下了痕迹」**，不是「游戏补偿你」。
- **全部失败相关文案一律陈述句**：无鼓励语、无「再试一次！」、无教训总结。内容侧撰写这批文案时，凡出现劝慰或总结教训的语气即为违规。
- **与 Balatro / Slay the Spire 的分别**：那两作的失败是**局的终点**，重开是默认动作；本作的失败是**账上的一笔扣款**，而账户只有一个、余额不回头。
- **ch1 的死就该这么轻，这是有意的、不是待修的缺陷。** ch1 是教学期，死了换个角色再来（新建随机角色 · 旧角色化为墓碑 · snapshot 回收，原样维持，不为它加软代价）；真正的重量从 ch2（重试 3）开始、ch3（重试 1）到顶。后续任何「给 ch1 也加一条惩罚」的提议须先推翻本条。

### 二、惩罚强度的走向：恒定占比

**`lossPerMomentum` = 10 / 5 / 10**（ch1 已锁定 10，本次定 ch2 = 5、ch3 = 10）。

- 形状即「一次**带内最坏落差**的失败恒占本章可用预算 8–12%」，逐格校验 9% / 10.0% / 11.3% 全部通过。
- 修为越高、输得绝对值越大，但「疼的程度」三章一致——**境界提升表达为数字量纲的整体上移，而不是难度的层层加码**。
- **非单调的 10 → 5 → 10 不是笔误**，是 ch3 预算跳 3 倍而最坏落差只跳 1.5 倍的算术结果。
- 零连带改动：N = 2 容错、21 格 `lifeSpanCost` 定价表、λ 反推台账全部不动。

### 三、归因：信息差只在首次遭遇时收费

输掉一场，玩家**应当总能说出自己哪一步错了**；错法一般是牌组构建或出牌顺序。同一个敌人**第二次遇到就该能打赢**。

- 支柱 9 说的是**首遇**的信息差即首遇的风险定价，不是一直收费。图鉴因此成为真正的元进程。
- **承重后果：敌人 AI 必须是可描述的固定行为模式，而非自由决策。** 敌人行动零事前预告是硬边界，AI 若不可描述，这条承诺当场落空。现有 AI（1-ply 加权效用评分 + 确定性 argmax、全流程零随机、零记忆）已满足它，无需改动——但这条承诺此后是那些性质的**消费者**，给 AI 掷骰或加私有记忆等于推翻本条。
- **遇量的意外性不放宽**：维持敌人赋级带 `±2` 与层数散布 `±1 档`，可控性优先。遇到超纲敌人而输不属于「你哪步错了」。

### 四、「已知」存在哪里：图鉴是可预测性的唯一载体

敌人行动零事前预告 + 图鉴战斗中一律不可查 ⇒ 「第二次遇到就该能打赢」只能靠**战前查阅 + 战中记忆**兑现。图鉴因此必须写到**招式与行为模式级**。

落地形态（**推翻了两条既有的慷慨度收口**）：

- **敌人词条由五项变四项**：撤销「关键卡牌」一格，词条②由「主功法」单引用改为**核心功法引用列表**（多门、不含层数），玩家点入功法图鉴自行展开。
- **功法图鉴词条列出该功法逐层的卡牌清单。** 「敌人词条 → 功法图鉴 → 反查其样本卡组」这条通道**由被封堵改为设计目标**——它正是「第二次就该打赢」最强的兑现形式。
- **③「运作方式」与 ④「特点与弱点」加厚到行为模式级**：会出哪几路牌、什么节奏、何时发力、怕什么打法。
- **一屏纪律让路**：词条页允许纵向滚动，总长上限撤销。
- **`EnemyData.KeyCardIds` 字段保留但职能收窄为「仅供 AI」**：它不再是图鉴数据源，只告诉 `KeyCardBias` 这几张是该敌人的打法重心。
- 不变的三条：图鉴**战斗中一律不可查**、词条**不含动态情报**、词条正文**绝不写等级**。层数不进任何词条 ⇒ 反查仍停在「这门功法大致长什么样」，而层数提升是整组替换。

**代价明写：** 敌人条目的内容量显著上升（每个敌人须写清会出什么牌、什么节奏），且首遇之外的信息劣势被大幅削平——这是为「主要可归因于决策」付的对价，是取向不是副作用。

### 五、「从这里开始不一样了」要明示

进入 ch2 / ch3 时**如实告知本篇章的剩余重试次数**。与全库既有的透明纪律同向（置灰 + 一行说明不隐藏、失败就地内联、购买流付款前如实标注），且**告知规则不等于威胁**——这正是「不评价」的正确形态。算式已存在（`ChapterRetryLimitsData[HasPremiumBundle 选行][N] − chapterRetry.ChN`），零新增存档字段。

### 六、声音：素语包裹下的一句人声

**除角色终结台词外，全库框架文案一律纯数据陈述**（「寿元 −80。剩余 3 次重试。」）。台词之所以凿得进去，正因为四周全是冷的——这是三国杀阵亡台词的生效机制（周围全是牌面与数字）。

**角色终结台词**（对标三国杀武将阵亡台词：纯文本、无配音、逐角色定制）：

| 项 | 裁决 |
|---|---|
| 射程 | **只在角色终结时。** 普通战斗失败零台词，仍是纯数据结算——一个角色一辈子只说这么一次 |
| 分句 | **三因各一句**（主动弃置 / 寿元耗尽 / 渡劫失败）。首批五角共 15 句 |
| 延伸 | **只给死亡。** 角色选择、突破境界、篇章通关、抵达元婴一律不给台词 |
| 视角 | 第一人称 |
| 呈现 | `CycleEndScreen` 上**结果三行与主按钮之间**的一处呈现位 |

- **稀缺即分量**，与「输一场只是付账、不值得仪式感」严格一致。三因情境差别极大（玩家主动放弃 / 大限将至 / 死于天劫），一句通用台词在「主动弃置」时会明显不对劲。
- **它大幅强化角色辨识度**——首批五角刻意压平在同一复杂度档，辨识度只能从别处来。
- 「角色唯一开口的时刻就是它完蛋的时刻」成为本作的一条明写表态。

## Clarifications（interview 产物）

- **轴 6 的词条深度落到哪一级？** → **词条只列核心功法（多门、不含层数），玩家点入功法图鉴自行展开；移除「关键卡 3 张」这一设定。** 这推翻了 `enemy-codex.md` 的承重决策「慷慨度维持『关键卡 3 张、不给样本卡组完整列表』」及其退让阶梯——草稿「张力」区自陈「无推翻」，与事实不符，已据裁决改写。
- **「点入功法图鉴自行展开」展开到哪一层？** → **功法图鉴列出卡表**，`ADR-0095` 就地改写。原 ADR 的承重理由（封住「敌人词条 → 功法图鉴」的反查通道）随之作废：该通道现在是兑现「第二次就该打赢」的主路径。
- **`EnemyData.KeyCardIds` 怎么处置？** → **字段保留，仅供 AI 使用**（`KeyCardBias` 的数据源），图鉴词条⑤ 整格撤销。`ADR-0113` / `ADR-0090` 零改动，两处「它是图鉴数据源」的理由句改写。
- **敌人词条的一屏纪律是否让路？** → **让路，允许纵向滚动**；总长 150–280 字的上限撤销，`common-properties.md` 里「敌人词条昂贵」那句的量级描述随之改写。

自动采纳的标准默认（未出题）：

- **`CharacterData` 上新增终结台词字段，形态 = 稀疏覆写数组 + 内嵌 `Resource` + 两个具名字段**（`DefeatLines : DefeatLine[]`，元素 = `Reason : DefeatReason` + `Text : LocalizedText`），类型写 `LocalizedText` 不写裸 `string`。依据：`EnemyData.Lines` / `RealmArtworks` 的同族先例（`ADR-0120`），以及 `data-resource-rules.md` 的显示字符串硬约束。
- **缺项 → `PushWarning` + 呈现层省略台词位**（不 `PushError`）。依据：一句缺失不阻断开局，而 `CharacterData` 现有 `PushError` 各条的对象都是「开不了局」的缺陷；覆盖率由 `/audit-content` 汇总。
- **台词不落存档、不进云端负载。** 结束摘要已含 `DefeatReason`、角色身份有 `characterDataId`，台词由这两者在展示层查表得出——属 ViewModel 的呈现期对象。零存档增量、不 bump `schemaVersion`、后端零配合。
- **首批 15 句属内容层**，写进 `content/` 侧的角色条目；字段定义留在 `systems/`。依据：`content/_index.md` 的「只填值 + 权威回链」纪律。
- **轴 7 不新增屏。** 剩余重试的常驻展示落在**篇章切换面的 `ongoing` 篇章行**（该面已展示弃置后剩余次数，同口径同键族），零新增屏、零新增存档字段；上限不得硬编码，须读 `ChapterRetryLimitsData` 按 `HasPremiumBundle` 选行。
- **`EnemyCodex` 的加厚不开战斗内查询入口**——「战斗中一律不可查」不因深度加大而松动。
- **素语基调不改 `ERR_*` 键的机械变换规则**（键由后端 `code` 变换而来、不得手写），只约束键对应的中文文案写法。
- **素语的射程限于框架文案**（`CYCLE_` / `COMBAT_` 战报 / `ERR_*` 与四条兜底），**不覆盖内容层叙事文案**（事件正文、跨档叙事、定性文案、敌人台词）。不写清这条射程，内容侧会把全部风味一并剥掉。
- **「全作唯一开口处」精确到可玩角色侧。** `EnemyData.Lines`（敌人五 slot 台词）是敌人侧既有的纯风味通道，不受本次影响。
- **`CycleEndScreen` 的 `Discarded` 定性文案仍留空。** 留空的理由是「写挽留 / 惋惜文案像在评价玩家的选择」，而台词是**角色自己的声音**不是游戏的评价——两格并存不矛盾。
