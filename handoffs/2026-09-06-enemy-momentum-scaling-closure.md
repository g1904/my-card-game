## Intent（distilled）

**一句话：** 敌人侧**不存在**独立的道念（momentum）产出缩放曲线——产出能力由卡组决定、决定因素与玩家完全一致，等级只经 `baseMomentum` 决定起跑线；三份主题文档 `## 待决问题` 里登记的「缩放曲线未定」是同一次落笔漏清的残留，本次整条删除，`systems/balance.md` 的对应条补一句指向 `ADR-0090` 的档案回链。

### 1. 矛盾不在文档之间，而在每份文档的正文 ↔ 它自己的待决问题小节之间

`open-questions/01-combat.md` 曾登记「敌人各等级的道念产出缩放曲线」并标注「⚠ 带一处主题文档间的矛盾」。直读四份文档后，这个「文档间矛盾」的描述本身不成立：

| 文档 | `## 意图` 正文 | `## 待决问题` |
|---|---|---|
| `systems/enemies/_index.md` | 产出缩放与玩家同因，不设敌方专属的隐藏数值乘区；卡组保持强度中立，不叠第二条强度曲线 | 「产出能力的缩放曲线未定」 |
| `systems/enemies/common-properties.md` | 敌人侧的战斗内量与玩家侧对称，共用同一个 `DeckModule`，疲劳规则一视同仁 | 「缩放参数未定义」 |
| `systems/adventure-event/combat/_index.md` | 敌人是对称的参战方；强度以 `baseMomentum` 为主刻度；AI 的定制策略不作强度 / 难度旋钮 | 「随境界 / 篇章缩放未定」 |

三条「未定」登记**各自都只有一句转发**（「→ `systems/balance.md`」），无论据、无日期、无溯源；而转发终点 `systems/balance.md` 写的正是相反结论。转发链的终点否定了转发本身——这是残留文本的形态，不是有效的对立主张。

### 2. 结论侧有四份彼此独立的证据

- **用户拍板**：`inbox/archive/draft-0823b.md:29` 明标 `[用户拍板]`——「不设敌方专属的隐藏数值乘区，产出能力的决定因素与玩家完全一致」。
- **已正式答结并归档**：`answer-logs/log-0823b.md:11` 用的正是该待答项的标题原文，且明写残余量纲「已由既有的『卡组规模的实际取值 / 功法的规模参数』两条承载，**不重复登记**」——它预先回答了「删掉会不会丢东西」。⇒ 清单上那条是一次**回归登记**，不是一条新问题。
- **两份 Accepted ADR 构成结构性封死**：`ADR-0090`（层数逐条固定、赋级只动一条曲线）与 `ADR-0044`（`±2` 赋级带）。一条敌方专属产出曲线与层数浮动在因果上是同一件事——都在唯一可见的难度刻度之外再开一条不可见的强度轴。补回它需要先推翻两份 Accepted ADR。
- **`systems/balance.md` 的「越级追分的形状锚点」整段**（该文件最数值化的一段）是在敌我同因的前提下写就的：它把追分能力唯一地归给卡组层数差，并明写锚点比的是同一角色的卡组在两种层数状态下的差异，不是「玩家功法 vs 敌人功法」。若存在敌方专属产出曲线，这段标定推导当场失效。

### 3. 三个「仍待定的缩放维度」全部已有登记，删除零信息损失

`combat/_index.md` 那条里有一个其余两处没有的维度（「随境界 / 篇章缩放」）。逐维核对其着落：

| 维度 | 承载 | 状态 |
|---|---|---|
| 等级 / 境界 → 起跑线 | `baseMomentum` 表 | **已定**（22 个全局等级各有一个值，表已完整） |
| 篇章 → 敌人产出 | 敌人功法层数的篇章基准档 | 取值待定，已登记在 `open-questions/01-combat.md`「功法的规模参数」 |
| 产出的绝对量纲 | 各卡牌 / 行为的道念产 / 削量 | 取值待定，已登记在 `01-combat.md`、`combat/_index.md`、`balance.md` |
| 卡组规模 → 后期失血 | 敌人样本卡组张数 | 取值待定，已登记在 `01-combat.md`「卡组规模的实际取值」 |

**结构与取值是两件事**：三条取值待定项都是**敌我共用**的量纲，它们的待定状态不影响「敌人侧不另有专属曲线」这一结构性结论。

### 4. 落笔面

- 三处残留**整条删除，不留墓碑**（不写「原为未定 / 已由 ADR-0090 答定」之类）——三份文档的 `## 意图` 正文已正面承载结论，`Source:` 行也已列有对应 handoff，无须新增溯源。`systems/enemies/_index.md` 的 `## 待决问题` 小节随之为空，写 `- 无。`。
- `systems/balance.md` 的道念数值条中，在「不存在独立于卡牌数值的敌方隐藏乘区」之后插入一句档案回链指向 `ADR-0090`。放在这里是因为它是三条转发路径的**共同终点**，一处即覆盖全部三条路径；而 `ADR-0090` 的标题（「敌方套牌由功法 + 层数展开」）看不出它同时裁决了产出缩放——这正是本条被绕过多次的原因。

### 5. 对内容编排的实际指示

内容侧不得为敌人条目寻找 / 期待任何「敌方倍率」字段。要让某个敌人更强，唯二的通道是**赋级**（`baseMomentum`）与**内容编排**（功法选择 / 层数 / 卡组规模 / 道具 / power）。这一条本已成立，本次只是让它在三份文档里不再被「未定」的措辞动摇。

## Clarifications

- **裁决方向（balance 侧成立 vs 三处「未定」侧成立）** → 用户裁定：**balance 侧成立，按该侧收口**。敌人侧不存在独立的道念产出缩放曲线，产出决定因素与玩家完全一致。
- **是否在 `systems/enemies/_index.md` 的层数散布护栏条末追加「基准档的逐篇章取值即敌人侧唯一的产出缩放旋钮」** → 用户裁定：**不落笔这句**。理由是它有两处与本次收口相抵：同一份文档已明写「不叠第二条强度曲线」「不设敌方专属的隐藏数值乘区」，紧接着称某物为「敌人侧唯一的产出缩放旋钮」会把刚被消灭的读法在同一份文件里重新种回去；且句尾的「取值待定 →」等于在主题文档里再登记一次已被承载的待定项。防重复登记的职责改由 `systems/balance.md` 的 `ADR-0090` 回链承担——覆盖面更好，且不制造新的「敌方旋钮」读法。
- **回链措辞** → 采纳标准默认：写「该结论的档案见 …」，**不写「已固化 / 已定案」**（活文档里的每一句默认就是当前定案，加戳等于没加戳）。
- **回链的插入位置** → 采纳标准默认：插在「敌方隐藏乘区」句之后，**不是行末**——该行末句讲的是「一张牌该产多少」的基准框定，与本回链无关。
- **空小节写法** → 采纳标准默认 `- 无。`（本库四种写法并存，取与 `systems/character-profile/currency.md` 同款的最简一种）。
- **是否新建 answer log** → 不建。该问题已于 08-25 答结并归档（`answer-logs/log-0823b.md`），本次是清理一次误重复登记而非首次答结；为它另建一份会在归档台账里制造同一问题的第二条答结记录。
