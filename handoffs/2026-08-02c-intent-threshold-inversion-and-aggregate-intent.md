## Intent（distilled）

一句话：**意图三档的同阶阈值整体下移——只有把敌人压低若干级才给完整意图，`diff` 在同级附近的一大段一律只给类别；篇章分档保留（ch2 · ch3 两端各收紧一级）；且意图（类型与数值）都是**本回合的综合描述**，因为对手一个回合可以打出多张牌。**

### 1. 同阶阈值改写（推翻 08-01b 的分档取值，保留篇章分档）

`diff` 的定义不变：**`diff` = 敌人全局等级 − 角色全局等级**（全局等级序 1–22，见 `systems/game-progression.md`）。

| 情形 | 玩家看到 |
|---|---|
| **越阶**（敌人境界高于角色） | **完全无信息**，不给任何替代线索 —— 不论 `diff` 多小（**硬门，不变**） |
| 同阶 · 第一篇章、`diff ≤ -3` | **完整意图**：综合类型 + 综合数值 |
| 同阶 · 第一篇章、`-2 ≤ diff ≤ 2` | **仅类别**：攻击 / 防御 / 增益 / 特殊，不带数值 |
| 同阶 · 第一篇章、`diff ≥ 3` | **完全无信息** |
| 同阶 · 第二 / 第三篇章、`diff ≤ -2` | **完整意图** |
| 同阶 · 第二 / 第三篇章、`-1 ≤ diff ≤ 1` | **仅类别** |
| 同阶 · 第二 / 第三篇章、`diff ≥ 2` | **完全无信息** |

- **篇章分档保留。** ch2 · ch3 相对 ch1 **两端各收紧一级**：完整意图的门槛放宽一级（`-2` 即可），黑箱的门槛也提前一级（`+2` 即黑箱）。
- **推论：后期境界内，等级差在信息面上的权重更大。** 同样一级之差在 ch2 · ch3 更容易改变档位——境界越高，等级序上每一步都更「值钱」，与 `baseMomentum` 跨度随境界放大的方向一致。
- **越阶硬门保留。** 新表述以「同阶」限定，越阶部分未被触及：敌人境界更高即彻底黑箱，不论 `diff`。
- **不做「敌人状态可读」的补偿**（不变）。

### 2. 语义翻转：完整意图从「默认」变成「碾压才有的奖励」

旧规则是「**默认揭示，越级才降级**」；新阈值下**默认变成了「仅类别」**：

- **同级对局（`diff = 0`）只给类别，不给数值——这是有意为之（已确认）。** 标准 Combat 的常态因此是第二档，而不是第一档；**不为此做任何可读性补偿**。
- **完整意图只在明显压制时出现**（ch1 低 3 级、ch2 · ch3 低 2 级及以上），它是**碾压弱敌的即时反馈**，不再是玩家每场都能拿到的基础信息。
- **轻微越级与轻微压制被合并进同一档**——「略强 / 略弱」在信息上不做区分，只有**碾压**与**被拉开**才改变档位。
- **推论 ①：第二档「仅类别」的视觉语言从边缘情形升为承重项。** 它现在是玩家看得最多的一档，其符号体系直接决定战斗可读性（此前它只在越级时出现，可以粗做）。
- **推论 ②：探查（probe）的价值显著上升。** 常态既然只有类别，「主动付代价买当回合完整意图」就从一个边角能力变成有稳定需求的信息通道——形态仍归内容横向扩展阶段，本阶段不设计。
- **推论 ③：意图揭示不再承担「教玩家读战斗」的职能。** 新手在同级对局里也拿不到数值，教学与可读性必须由别处承担（图鉴的静态知识、卡牌自身文本、道念对比主视觉）。

### 3. 意图 = 回合级的综合描述（新定案）

**理由：一个回合对手可以打出多张牌。** 因此意图不是「下一张牌是什么」，而是**对本回合全部出牌的汇总表述**：

- **综合数值（第一档）= 计算后合并的最终结果。** 给的是**一个结果值**（例：削减 12），不是各张牌的分解，也不是未经合并的多条明细——多张牌的效果先算完再合并成一条。
- **综合类别（第二档）= 主类别并行陈列。** 一回合若跨类别（攻击 + 增益），**并列陈列各个主类别**，不压缩成单一类别、也不归入「特殊」。
- **推论 ①：不暴露张数与逐张分解。** 综合描述天然把「打几张、各是什么」藏起来——即使在第一档，玩家得到的也是最终结果而非牌序。
- **推论 ②：EnemyManager 的 AI 是回合级一次性规划，不是逐张即时决策。** 要给出综合意图，敌人必须在**呈现意图之时就已定好本回合的整套出牌**并算出合并结果；否则无从汇总。这是对 `systems/services/combat-service.md` 的 AI 面的一条硬约束。
- **推论 ③：意图值与实际结算量必然可能不等。** 道念削减是下限 0 的饱和减法、且触发式能力也入栈，故「综合意图数值」是**声明的量**，实际结算结果可能更小或被改写——与既有的「`PlayResult` 需区分意图削减量 vs 实际削减量」一条正好合流。

### 4. 呈现时点：仅在玩家回合显示下一回合的意图（已定案）

- **意图只在玩家自己的回合内呈现**，内容是**敌人下一个回合**要做的事。**敌人回合内不呈现意图**——那时它正在执行，呈现的是出牌本身。
- **推论 ①：意图的用途是「为我这一回合的决策提供依据」。** 玩家在主阶段出牌时就知道对手接下来的合计动作，出牌选择因此有据可依；这也解释了为什么综合成一条结果值就够用——玩家要的是「我该防多少 / 追多少」，不是牌序。
- **推论 ②：敌人 AI 的规划时点前移到玩家回合开始之前。** 结合推论「回合级一次性规划」，敌人下一回合的整套出牌在玩家回合开始时就已定案。
- **推论 ③：UI 上意图是玩家回合内的常驻信息**，随回合归属切换而出现 / 消失，不是逐次出牌的飘字。**敌人回合内意图区直接收起**（不留占位、不换成「对手行动中」一类指示）。

### 5. 意图即承诺：公布后不因玩家行动重算（已定案）

- 敌人的下一回合计划在玩家回合开始时定案，**玩家在主阶段做什么都不改写它，也不刷新显示**。
- **推论 ①：玩家可以据它布局**——「它要打 12，我这回合防住 12」；屏上意图数字在整个玩家回合内不跳动，与「道念差 = lifeTotal 损失」的 1:1 换算合流，**战斗屏的算术完全可算**。
- **推论 ②：EnemyManager 不走响应式 AI 路径。** 决策发生在一个明确时点，不必挂钩玩家的出牌事件重算；难度旋钮因此落在**规划算法与卡组**，而非临场调整。
- **推论 ③：UI 无需表达「意图已变更」**——没有重算就没有刷新动画 / 变更高亮。
- **推论 ④：承诺与执行可能不一致**——玩家行动可能让计划中的某张牌在敌人回合无法照原样执行，见 Open questions。

## Open questions
