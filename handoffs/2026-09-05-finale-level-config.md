## Intent（distilled）

**问题：`balance.md` 自陈的「三条 Finale 校准手段」里，手段 ① 是一条死手段。** 同一份文件一处写「校准 Finale 难度只有三条替代手段…① 天劫的赋级带位置（`±2` 带内的权重偏移）」，另一处写「Finale 不掷骰（天劫是指派，恒为 `diff = +1`）」——**不掷骰就没有权重可偏移**。两处并存使实际可用手段只剩两条（定制卡组强度、`TurnLimit`），而后者一动就要连带重估「12 回合是给 build 表达自己的窗口」那条论据。Finale 是全作压迫顶点、又是篇章推进的唯一闸门，却是三档里校准余地最小的一档。

**做法：把天劫的指派值从硬编码常数换成配置格。**

1. **在 `EnemyLevelingData` 的既有行类型 `EnemyLevelRange` 上增一格 `FinaleDiff : int`** —— 本篇章天劫的**指派 `diff`**（相对角色等级）。物化 Finale 时以 `角色等级 + FinaleDiff` 得出天劫等级，取代硬编码的「`+1`」。
   - 落点是推演不是选择：平衡资源是本库唯一配置层（`ADR-0074`），且 `FinaleDiff` 与同行的 `Upper` 之间有跨字段不变式（`FinaleDiff <= Upper`），按「有跨字段不变式的同住一份」判据不容拆成第二份资源。
   - **通道不变**：Finale 本就是指派、不掷骰；`FinaleDiff` 不是传给赋级函数的区间覆盖参数，而是这条既有指派通道自己的取值来源。`ADR-0044` 的「赋级函数不接受任何区间覆盖参数」逐字成立。
2. **存储形态是相对 `diff`，不是绝对等级。** 三章初值恒 `+1`，推导出的天劫等级仍是 14 / 18 / 22 —— **行为零变化、玩家侧零可感知、平衡侧零重算**：装上旋钮，不拧它。
3. **取值域由加载期校验锁死（三条新增校验，均 `PushError` + 抛，带篇章号与取值）：**
   - `1 <= FinaleDiff <= Upper` —— 下界常量 `1` 由「天劫必然越阶」定死，上界读同一行的 `Upper`；
   - `该篇章末级 + FinaleDiff <= 22` —— 全局序上界；
   - 缺值 / 未赋值（读作 `0`）即违规 —— `0` 意味着不越阶。
4. **顺带消解 `balance.md` 的内部不一致：** 手段 ① 改述为「调本篇章的 `FinaleDiff`」，它从此是一条真手段；「Finale 不掷骰」保持成立（本方案不引入掷骰），两处不再互相抵消。

**实际收益如实写下（不粉饰）：** 上界受 `Upper = +2` 与全局序 22 双重截断 ⇒ **ch1 `[14,15]` · ch2 `[18,19]` · ch3 `[22,22]`**。**`FinaleDiff` 在第三篇章只有一个合法取值，旋钮不可拧。** ch3 的 Finale 校准仍只能走定制卡组强度与 `TurnLimit`。这是在知悉该限制的前提下选择的取向：ch1 / ch2 各 2 档已足以消解「手段 ① 是死手段」这一缺口；为 ch3 争取余量需要放宽 `±2` 带本身，那是一次要有实测数据支撑的独立决策。

**补写的承重前提（原始草稿未写出）：角色进入 Finale 时恒在本境界末级。** Finale 的出现条件就是角色已达本境界巅峰，且它以 `Priority = 1` 封锁同批其余选项。校验按「本境界末级」而非「角色当前等级」算，正因为二者在 Finale 时刻恒相等——不写出这条，校验基准看起来像是凭空取的。

**明确不需要的：** `CharacterProfile` 新字段 / 存档 schema bump · 存档迁移 · 新内容条目 · `eventPriority` 抬升清单变更 · `ADR-0044` / `ADR-0018` / `ADR-0074` 正文订正 · 平衡数值重算 · `terminology.md` 登记（`FinaleDiff` 是代码标识符，非领域术语）。

## Clarifications（interview 产物）

**① 「与既有决策的张力：无」这一句不成立 → 张力存在，裁决为收窄两处承重原话的作用域。**
原始草稿断言本次改动「纯结构性、与既有决策零张力」。实际有两处承重原话被本方案打成假命题：
`balance.md`「天劫的特殊性全部落在定制卡组与遭遇参数上，『绝境感』永远不由等级差表达」与
`combat/_index.md`「推论 ②：天劫…特殊性不落在等级上」。
→ **裁决：两句的作用域收窄为「剧本 / 内容侧不得用等级差表达 Finale 的特殊性；平衡面独占一个 Finale 等级旋钮，取值受同一条带纪律约束」，两处同改。**
依据：`ADR-0077` 的理由原话——「Finale 是篇章的能力检查点，**它的难度必须由平衡面独占决定**；允许剧本加压等于让某些剧本线不可通关」。平衡资源正是「平衡面」，而被撞两句的上下文都指向剧本 / 内容侧。**这是与既有论证一致的读法，不是网开一面。**
`ADR-0044` 后果行「剧本加压 Finale 只能走敌人侧的两个字段，不能走赋级带」约束的是剧本，已复核，不必改。

**② 取值域 `[末级 − 2, 末级 + 2]` → 收窄为 `[末级 + 1, 末级 + Upper]`。**
草稿取值域的下半段（天劫等级 ≤ 角色等级）与「天劫必然越阶」「渡劫 = 突破到下一境界」正面相抵；草稿只验证了初值处的自洽，没验证旋钮可达的其余取值——而旋钮的全部意义就是被拧。
→ **裁决：下界定为常量 `1`。** 既有承重链一字不动（必然越阶 · 渡劫叙事 · 经验供需推论 ① · 剧情线不转入 Finale 的第二条理由 · Finale 的抬升条件）。
**代价当面告知并接受：ch1 / ch2 各 2 档，ch3 恒为单值。**
全局序上界 22 的截断仍需一条独立校验——相对形态下 ch3 的 `+2` 会算出 23。

**③ 字段形态由绝对 `FinaleLevel` 改为相对 `FinaleDiff`。**
草稿直接落笔绝对全局等级（ch1 14 / ch2 18 / ch3 22），未考虑相对形态。
→ **裁决：取相对 `FinaleDiff`，初值三章恒 `+1`；绝对等级 14 / 18 / 22 只作为推导结果并列展示，不是存储形态。**
依据全部来自既有设计：同行其余字段本就定义为「相对 `diff` 的闭区间 + 逐档权重」，塞一个绝对值是同页两义；绝对形态的校验须外借「篇章末级」这个住在境界枚举里的常量，而本库已否决跨文件不变式（「要么无人校验、要么校验代码得加载两份资源猜对应关系」）；`ADR-0074` 的同住判据（「权重表的定义域就是边界区间」）在相对形态下才逐字成立。相对形态下校验退化为纯本地断言。

**④ 改动面由草稿宣称的 3 处扩到 8 处。**
草稿漏列：`balance.md` 的 `±2` 无例外硬规则段 · `combat/_index.md` 的推论 ② · `combat/_index.md` 的「退让位清单」（其中「天劫的赋级带位置」是同一条死手段的第二个引用点）。

**⑤ 草稿点名的一处落地面不存在。**
草稿写「`future-event-service.md` 中 Finale 的赋级措辞由『恒为 `diff = +1`』改为…」——**该串不在该文件中**（全库仅 `balance.md` 有）。正确落点是该文件的「赋级的合法区间」一节与十步管线伪码的 ② 赋级行。

**⑥ 机械订正（自动采纳，未出题）：**
- 草稿把下界写成「末级 − `Upper`」——应为 `Lower`（负数），且本次由 ② 定为常量 `1`。草稿在此犯了它自己批判的那个错（「写死 `2` 会在日后调整带宽时静默失配」）。**落笔时明写：上界读 `Upper`，下界写常量 `1` 且刻意不读 `Lower`**——后者表达的是「必然越阶」，跟着 `Lower` 走会让一次带宽调整顺手把不越阶的天劫放进来。
- `EnemyLevelingData` 的代码块补标 `ISingletonContent`（同文件正文已明写它是，代码块漏标；本次正好改到该块，顺手修）。
- `balance.md` 的「加载期校验（五条）」计数随之改为八条。
- 「通过 Finale 所需追回的道念点数 ch1 5 / ch2 13 / ch3 25」标明为 `FinaleDiff` 初值下的推导值，随旋钮变动。
