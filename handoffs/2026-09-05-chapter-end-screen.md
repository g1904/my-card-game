## Intent（distilled）

一次轮回走到尽头有两条出口。失败侧（`defeated` 三因）已有 `CycleEndScreen`；**成功侧（`completed`）全库无明文**，而元婴界面（整轮回通关的终局展示面）只定了「是一块类似通关证书的终局界面、是寿元 `+5000` 这次最终更新的读者、统计区落两个数」，字段与形态未定。本次把成功侧一次定完。

### 轮回收尾族 = 两屏，不是一屏、也不是三屏

| 屏 | 承载 | 变体轴 | 变体数 |
|---|---|---|---|
| `CycleEndScreen`（既有，一格不动） | 角色离场（`defeated`） | `DefeatReason` | 3 |
| **`ChapterEndScreen`（新增）** | 篇章通关（`completed`） | `chapter`（1 / 2 / 3） | 3（ch1 突破筑基 · ch2 突破金丹 · **ch3 = 元婴通关证书**） |

**不是一屏五变体。** 拿 `CycleEndScreen` 自己写下的收敛门槛去量（「三变体的差异恰是两格，出路 / 信息行 / 按钮全同」）：成功侧与失败侧的差异不止两格，且其中两处是**互相否定的承重纪律**——失败侧「本屏不呈现本轮回的账号级收获」vs 元婴**必须**有统计区。同一张变体表内同时写「零呈现」与「必须呈现」，读者无从判断哪一条是这张表的纪律。另两处：剩余重试行在成功侧**没有可显示的事实**（通关不消耗重试次数）；演出口径相反（失败侧的克制不推广到全游戏唯一的胜利时刻）。

**不是三屏。** 元婴就是 ch3 的 `CompleteChapter()`——同方法、同状态、同收尾链、同一套触控与安全区约束；三份等价布局各自维护必然漂移成三种不一致的观感。元婴独有的东西恰好可表达为变体表里的两格开关（解锁行 / 统计区）。

### `ChapterEndScreen` 的形态

一屏全屏（安全区内）· 不进屏幕栈 · 无返回 · 非弹层。触发 = `CompleteChapter()` 提交完成之后。数据源 = `CompleteChapter` 内组装的只读值摘要。结果三行（境界 + 篇章 · `pastEvent.Count` · `Status.lifeSpan`）与失败侧摘要字段面同构；解锁行 ch3 不出现；统计区仅 ch3 出现。商业化零入口零文字、残卷零呈现、成就零呈现（结算在主按钮之后才跑）、图鉴零呈现、常驻同步指示可见。唯一主按钮「返回主菜单」。零存档写入、零新增存档字段。

**出口不放「继续下一篇章」。** 逐字复用结束屏否掉「再试一次」的理由：主菜单是既定唯一开局入口，三道闸全挂在「开始新轮回」上，第二个开局入口要么复制三道闸（必然漂移）要么绕过它们。附带一条独立理由：`completed` 之后角色进入下一篇章的可挑战角色池，起手是读档续章，而「哪个角色、哪个篇章」的选择面本就在主菜单侧。

**允许一次入场演出，但复用既有语汇。** 逐字复用 Explore 揭示转场那一套：标题淡入 ≈ 1.2s（待实测初值）+ 一次短音效 + 全屏任意触点即跳过 + 无震动。演出只覆盖标题与定性文案的入场，结果行 / 解锁行 / 统计区不做逐行动画。

### 三变体表

差异恰是四格（标题键 · 定性文案条目 · 解锁行有无 · 统计区有无），出路 / 布局骨架 / 主按钮 / 结果三行全同。变体轴取 `chapter` 而不是「是不是最后一章」——前者是摘要里本就有的一格、可机械判定，后者要在呈现层再写一次「3 是最后一章」的常量。三条定性文案是内容层条目（与 `DefeatReason` 的定性文案同族），不进 `cycle.csv`。

### 结束摘要（`ChapterEndSummary`）

`CompleteChapter()` 组装一份只读摘要交给呈现层，与 `DefeatCharacter` 的摘要逐条同纪律（只含值类型 + 内容 `Id` + 文案条目 `Id`、不持 `CharacterProfile` 引用、不落存档、不进 `PlayerProfile`）。**零新增存档字段、零新增存档点、零 schema bump、后端零配合**——字段全部是已定字段的读取或已定判定的结果。

**时点两条硬要求：** 在境界寿元增量施加之后（元婴界面正是 `+5000` 这次最终更新的读者）；且在 `TeardownCycle()` 与任何角色数据处置之前组装。

### 翻译键：`CYCLE_` 分区扩容，不新开 `CHAPTER_`

分区表是开放表、分区划的是界面；轮回结束屏与篇章结束屏是同一个界面族（同一条收尾链、同一套骨架、共用结果行标签与主按钮）。为八个键单开一个 CSV，分工与 diff 的收益为零，代价是结果行标签与主按钮要么跨文件引用要么复制两份。

## Clarifications

- **元婴通关证书的展示深度 → 只用已定字段（用户裁决，原选项 A）。** 两行账号级统计（`FinaleWinOrdinal` + `TotalCyclesCompleted`）+ 与 ch1 / ch2 同一套结果三行。连带闭合：零新增字段、零 schema bump 成立；`PlayerStatistics` 首批清单不成为硬前置。
- **通关证书是否可跨会话回看 → 不做独立回看（用户裁决，原选项 A）。** 两个账号级数字在玩家档案屏常驻可读即为回看通道；零新增账号级字段、零新增屏、零 `user://` 文件。
- **「通关」二字的口径分离 → 采纳（用户裁决）。** ch1 / ch2 变体一律用「突破」，「通关」只留给 ch3 变体与统计区。状态机的 `completed` 是**篇章**通关，而统计侧的「通关」是完成整个轮回，本屏是唯一同时呈现两者的界面。
- **`completed` 是否清理角色数据 → 本次不裁定（用户裁决）。** 摘要的时点写成「在 `TeardownCycle()` 与任何角色数据处置之前」，该要求在两种读法下都成立；库内两处措辞的矛盾另立待答项跟踪。
- **`ChapterEndKind` 与变体轴 `Chapter` 不作两个真值**（标准默认）：变体表按 `Chapter` 索引，`Kind` 只是 `Chapter` 的派生标签。
- **解锁行的下一篇章显示名不进摘要**（标准默认）：以 `Chapter + 1` 为格式参数取篇章名，复用主菜单「切换篇章」既有的 `MENU_` 分区键。
- **结果三行标签键优先复用结束屏既有键**（标准默认）；三条定性文案不做多版随机（一次轮回内各至多出现一次，随机没有对象）。
