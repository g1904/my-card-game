## Intent（distilled）

`open-questions/04-content-delivery.md` 余下三条不是协议问题而是运维形态。它们悬着的名义原因是「共同前置栈选型」，但其中相当一部分由已定的契约条款与 ADR 逻辑上推得出，只是从未被写下来。本次把这部分推完并落笔。

### 一、flags 规则集的存储形态与变更通道

- **存储形态**：规则集是后端主事务性存储中的一条**不可变版本化记录**（`flagsVersion` · `rules` · `bucketSalt` · `derivedFrom` · `publishedBy` · `publishedAtUtc` · `summary`/`scope` · `contentFingerprint`），高水位另存一条单行记录，**插入与推进同一次事务**。这一条单独就把候选砍到只剩一类，并排除了「随发版走的配置文件」（改一次规则发一次版，秒关延迟退回发版级）与「控制台自带独立存储」（天然是一条原地编辑路径）。
- **分桶盐随版本冻结**（承重）：盐放部署配置即「改配置改变全体解析结果而版本不动」。推论是分桶函数天然成为 `(accountId, 规则集版本)` 的纯函数——把契约条款做成结构上不可能违反，而非实现时记得遵守。
- **唯一写入面** `publish(draft, summary, scope)`；`rollback` 是它的一次调用，不是第二条路径。**直连库写规则集在权限上被禁止**（应用身份 `INSERT`+`SELECT`，人类身份 `SELECT`）。人机接口取 CLI / 脚本，规则草稿以文本形式进版本控制。
- **`publishedBy` 必须是具名人类身份**；不设强制第二人审批。配套一条**爆炸半径闸**：解析结果规模较上一版新增 > 20 条即需显式确认。
- **O7 的内容指纹自检直接开启**。
- **缓存的对象是规则集本身**（键 = `flagsVersion`、值不可变、永不需失效逻辑、single-flight 收敛冷启动），不引入按账号的解析结果缓存；引入的触发判据与键形态一并写下。

### 二、ES256 私钥的保管、CI 签名步骤与 `keyId` 轮换

- **五条能力判据**（私钥不可导出 · 逐次签名可审计 · 原生 P-256 且能并存多把 · 签名权限授予流水线身份而非个人 · 可用性与 flags 端点同档），它们**反向约束托管选型**，不能等选型落定再谈。
- **发布流水线七步 + ③b**：产物认证核对 → 推 blob → 生成 manifest → 签名 → 编码归一 → 自验 → 探针 → 原子发布 → 留痕。新增的承重步是 ⓪ 与 ④；④ 必须用**客户端内置的那份公钥**验，验的才是「玩家手里那把钥匙能不能验通」。
- **首版即内置 active + standby 两把公钥**，把紧急轮换从「跨发版周期 + 强更全体玩家」降到「服务端切一个字符串」。standby 私钥是同一密钥服务内的独立密钥（独立密钥 ID / 权限策略 / 审计线，签名权限平时不授予任何身份）。
- **轮换三类触发 · 四阶段 · 覆盖率口径**：覆盖率由已有的 `X-App-Version` 派生（零新增报文），N = 7 天、阈值 95%，阈值推导挂在「轮换的爆炸半径是暂时收不到热更，不是玩不了」上。T2 后 48 小时观察窗口，异常即回切——**`keyId` 的回切是安全的**，单调纪律不适用于它。

### 三、发布侧内容校验闸（只写本库那一半）

分工的准确切法：客户端保证「凡是打包工具产出的包，都过了闸」，它无力保证「凡是被发布出去的文件集，都是打包工具产出的」——**后者是本库的义务，是这条链上唯一还敞着的口子**。故本库那一半不是「再跑一遍校验」（那会造出第二份实现随时漂移），而是**发布流水线拒绝任何没有打包工具背书的文件集**：用一次逐文件 hash 比对（产物认证核对）把对侧的闸延伸到发布面。位置最前、无跳过开关、校验先于签名（签名即背书）、失败即非零退出且无需补偿、留痕八字段含 `gateAttestation`。另有一条本库对发布运维提出的实质新要求：**基线漂移**——闸须对兼容矩阵内每一个 ≥ 本次 `minAppVersion` 的在架基线各跑一遍。

## Clarifications

- **flags 应答也走同一密钥体系 ⇒ 内容签名私钥就在 flags 读路径上**（与草稿 B1-5 逐字写的「不在任何请求路径上」相抵） → **承认逐账号签名，并按 `(flagsVersion, accountId)` 缓存签名结果**。B1-5 改写为「在 flags 读路径上，但不在写路径的关键区」，可用性档位提到与 flags 端点同档（仍低于会话 token 密钥）。连带修正：A6 的单次成本分析补上签名这一步、紧急轮换的止血范围补上 flags 通道那一半。缓存的是 `sig` 而非 `disabledIds`，「同一 `(flagsVersion, 账号)` 解析结果恒定」不受影响；键含版本使 B 组硬约束结构性满足。
- **爆炸半径闸的「> 该类型可抽取池的 5%」要求后端感知内容类别与池规模**（与契约「服务端不区分内容类别」相抵） → **退化为纯计数：新增 > 20 条**。按类型池规模缩放写进正文作为内容规模长大后的优化路径，并注明它需要产包证明供数、会扩大客户端承接面。
- **草稿 A7 的拓扑主张「flags 端点可由只读副本 / 多区域实例承接」与同批裁决的「玩家读路径全走写入区」相抵** → **删掉拓扑主张，只留语义结论**：flags 的读路径不受读己所写约束，是一条被保留但当前未被使用的自由度；当前拓扑取「玩家读路径全走写入区」，flags 随之。不引入读路径分档表，不设例外。
- **「首版即内置 active + standby 两把公钥」是一项无人承接的跨库义务** → **首版即内置两把**，本库写服务端侧本体，客户端侧承接项在 `game-design-documents/` 侧对称落笔。它兑现的是契约里已经写着的「一组 `keyId → publicKey` 映射」，**报文零改动**。
- **standby 私钥放哪**（草稿写「另一处独立保管」） → **同一密钥服务内的独立密钥**：独立密钥 ID、独立权限策略、独立审计线，signing 权限平时不授予任何身份。依据是威胁模型逐字只到「防误 / 防随手改」，跨保管方隔离防的那一档不在模型内，而离线保管几乎必然引入 B4 要堵的「人可直接签」旁路。
- **flags 规则集的作者入口** → **CLI / 脚本 + 文本形式的规则草稿进版本控制**（用户在批量评审中裁决）。控制台日后加上去时不动存储、不动纪律、不需迁移。
- **「发布流水线不设跳过开关」这条口径收紧** → **采纳**。若日后确需 break-glass，须与 O5 同构留痕并触发告警，而不是一个静默的命令行参数。
- **`sig` 编码澄清（P1363 而非 DER）** → **采纳**，补进 `contracts/content-manifest.md`「防篡改」。澄清而非变更：报文零改动、`manifestSchema` 不提升。

**本次自动采纳的标准默认**（有通行做法或可由既有设计推出，未占裁决）：规则集与高水位同事务 · 分桶盐进规则集 · `rollback` 复用 `publish` · 直连库写入的权限禁令 · O7 指纹直接开启 · 缓存对象取规则集本身 · `contentVersion` 与 `flagsVersion` 两条序列不合并 · `contentVersion` 也用高水位 + 备份恢复强制跳号 · 步 ④ 自验用客户端内置公钥 · ③b 编码归一 · 数值初值（12 个月 / N = 7 天 / 95% / 48 小时）· 覆盖率复用 `X-App-Version` · `keyId` 回切安全且不套用单调纪律 · 不设强制第二人审批 · 闸放最前 / 无跳过开关 / 校验先于签名 · 内容留痕与 flags 留痕不合并 · 对每个在架基线各跑一遍 · 留痕落主存储而非 CI 产物 · `contentVersion` 分配由受权限保护的发布动作承担。

## Open questions

- **多区域一致性与传播窗口 T 的数值上界**（留在 `open-questions/04-content-delivery.md`）：flags 「传播时延而非独立计数」的口径依赖 T；规则集缓存在多区域下的行为也随它定稿。
- **「更高版本客户端基线是否为更低版本基线的超集」**：这是客户端侧的内容纪律问题，答定后可把「每个在架基线各跑一遍」简化为「只跑最新」。本次已取安全默认，不依赖它。

## 客户端侧影响

本 handoff **不改动**客户端 ↔ 后端边界的报文语义：`manifestSchema` / `flagsSchema` 均不提升，`sig` 编码是澄清而非变更。但它带来**三项客户端承接义务**，须与本方案同批落地，单侧采纳即校验闸有洞：

1. **产包证明的字段形态与产出时机**（工具版本 · 所用基线 `appVersion` · 断言项计数 · 逐文件 `path` + `sha256`）——发布流水线步 ⓪ 的输入。
2. **基线内容快照的归档形态**——须随客户端发版归档到发布侧可达处，否则闸对老基线跑不了。
3. **首版即内置 active + standby 两把公钥**——兑现契约已写的「一组 `keyId → publicKey` 映射」，它的全部价值在「首版就做」。

受影响的客户端成分是 **content-service**（验签与合并期校验）与打包 / 发版流程；对侧同步文档见 `game-design-documents/systems/services/content-service.md` 与 `game-design-documents/` 侧的承接记录。
