**一行摘要：** 敌人赋级由「按境界给的绝对上界」改为**相对当前等级的 ±2 对称带**（连带天劫也受同一条约束），栈**必须落存档**（栈上的目标选择本身就是决策点），埋伏**进入敌人卡池但不计入意图**，`IgnoresProtection` 配额定为 **≈1% 的游戏场景**，并确立一条全局硬约束：**本作没有凭空生成的牌**。

## Intent（distilled）

### 一、对手等级上下限重定义 = 当前等级 ±2

> **物化赋级的合法区间 = `[角色全局等级 − 2, 角色全局等级 + 2]`**，在全局序 1–22 上截断。这是一条**相对 `diff` 的对称带**，**取代** 08-03 的「上界 = 高一个大境界的初期」（那是一条按境界给的绝对天花板）。

参照的全局等级序（不变，见 `systems/game-progression.md`）：

```
炼气 1层..13层  →  全局 1..13
筑基 初期..巅峰 →  全局 14..17
金丹 初期..巅峰 →  全局 18..21
元婴 初期       →  全局 22
```

**这条重定义改了三件事：**

| 项 | 08-03 旧规则 | 本次 |
|---|---|---|
| 形态 | 按**境界**给的绝对天花板 | 按 **`diff`** 给的相对带 |
| 下界 | **无**（可以遇到任意低的敌人） | **有**：`角色 − 2` |
| 最坏开局差 | 炼气一层 vs 筑基初期 = **19** | 境界边界处最大 **9** |

- **推论 ①（承重 · 答结 08-03 的算术冲突）：`lifeTotal` 的「一次惨败打穿耐久」风险从内容侧纪律升格为规则层保证。** 旧规则下炼气一层可遇筑基初期（`baseMomentum` 1 vs 20，开局落后 19 > `lifeTotal` 10）；`±2` 带下最坏情形是**境界边界的跨越**——炼气十二层（12）遇筑基初期（20）落后 8、炼气十三层（15）遇筑基中期（24）落后 9，均在 10/10 之内。**先前记在 `life-total.md` / `scoring.md` 上的「由内容设计侧规避」这句话不再是唯一防线**，规则层自己就给了界。
- **推论 ②（结构性 · 未被明说但必然）：越阶遭遇只可能出现在每个境界的最后两级。** `±2` 带下要跨过境界边界，角色必须已在本境界的倒数第一 / 第二级（12、13 → 筑基；16、17 → 金丹；20、21 → 元婴）。**越阶压迫感因此自动向篇章尾部集中**，与 Finale 落在篇章边界同向——这不是另加的编排，是规则的必然结果。
- **推论 ③：08-03 的「上界档必然越阶 ⇒ 最难遭遇必然完全黑箱」作废。** 上界档现在是 `diff = +2`，它**只在境界末两级才是越阶**；境界中段的 `+2` 是同阶，照常按 `diff` 门槛给信息。「最难的即最不可读」不再普遍成立，只在篇章尾部成立。
- **推论 ④：下界是新增的约束面。** 此前没有下界，「碾压弱敌」在规则上是可能的；现在 `diff ≥ −2`，**碾压的深度被封顶**。这直接撞上意图揭示的第一档（见「与既有决策的张力」第 1 条）。
- **推论 ⑤：赋级规则的表达形式变简单了。** 旧规则要先查角色所在境界、再查该境界的下一境界初期对应的全局序；新规则是全局序上的一次加减 + 截断，**不需要境界表**。境界边界的特殊性由 `baseMomentum` 的跨度放大自然承载，与「全局等级序保持为一把简单的直尺」的既定分工一致。
- **推论 ⑥：元婴（22）仍是终点。** 角色 21 时带为 `[19, 22]`（22 为截断后的上界）；抵达 22 即轮回终点，不再产生遭遇。
- **`±2` 只约束「能出到几级」，不约束分布。** 带内五个档位各以什么权重出现、依什么决定这次给几级，仍是待答（分布规则未变，只是可选范围换了）。

### 二、栈必须落存档：决策点并不总落在栈为空的时刻

> **触发式异能在栈上若需要选择目标，那次目标选择本身就是一个决策点。** 故「任何可退出的时刻栈都是空的」这条假设**不成立**，**栈必须落存档**。

- **推论 ①（承重 · 答结 08-03 推论 ⑤ 的未确认项）：栈条目须可序列化**——与战场条目同级的存档要求：来源 `Id`、已选定的目标、以及「正等待选择目标」这一挂起态。
- **推论 ②（承重 · 代码面）：结算不是一个原子的同步过程。** LIFO 弹栈结算的中途可以停下来等玩家输入，`RunCombatAsync` 的结算循环因此必须是**可挂起、可从中途恢复**的状态机，而不是一个跑到底的 `for` 循环。这是本条对 combat-service 的实际要求。
- **推论 ③：决策点粒度的清单多了一类。** 08-02b 曾把回合内的可退出时刻「回落到回合 / 出牌这一级」——本条**把它推回去一层**：除回合 / 出牌边界外，**结算过程中的目标选择**也是决策点。粒度问题本身仍未答定，但已知它至少要覆盖这一类。
- **推论 ④：这不重新引入交互。** 目标选择是**结算自身的一部分**（这张牌 / 这个触发要指向谁），不是「在对手窗口插手」的响应机会。08-02b 移除交互与优先权的定案不被松动——玩家仍然只在自己回合出牌，只是**自己压进去的东西在结算时可能回头问一句「指谁」**。
- **推论 ⑤：目标选择的归属方可以是敌人。** 敌人的触发式异能同样可能需要选目标，那由 EnemyManager 在执行时自行决定，**不产生决策点**（不需要玩家输入即无需挂起）。决策点只在**需要玩家输入**时产生。
- **仍未落定（不在本次范围）：** 战斗内道具的运行态（本场已用掉哪些、剩余次数）与 `Power` 的战斗内运行态（「本场已触发 N 次」这类计数器）的存档字段形态。

### 三、埋伏进入敌人卡池，但不计入意图

两问一并答定：

| 问 | 答 |
|---|---|
| 敌人侧是否也布置埋伏 | **是**，埋伏进入敌人卡池 |
| 埋伏是否计入敌人意图的呈现 | **否** |

- **推论 ①：玩家侧的对称指示从「若是则需要」升为必需。** `ux/combat-ux.md` 已登记的**埋伏标记**（对手场上「有一张埋伏」，只给计数不给内容）现在是**必做项**，不再是条件项。双向对称的信息规则由此真正落地——玩家与敌人 AI 读到的是同一层信息（都只看到计数）。
- **推论 ②：埋伏是意图之外的第二个不确定源，且性质与快照偏差不同。** 意图偏差是「说了但没做到」（快照与执行不一致，见 08-04b）；埋伏是「根本没说」——它在**玩家回合**触发，而意图只描述敌人**自己回合**的行动，二者的时间归属就不重叠。**它是一个被公开计数的「已知未知」**：玩家知道有，不知道是什么、什么时候炸。
- **推论 ③：意图的定义边界因此更清晰了。** 意图 = 敌人**自己回合**行动的汇总快照。凡不在敌人自己回合发生的东西，一律不进意图——这条判据同时预先答了同类问题（例如敌人的静止式异能也不进意图）。
- **推论 ④：埋伏的既有规则对敌人侧同样适用**——同名不可重复布置、触发后进弃牌堆、面朝下、对手只见计数。**不为敌人侧另立一套。**
- **推论 ⑤：`EnemyTemplate` 的样本卡组可含埋伏。** 「物化时改写样本卡组」因此又多一个旋钮：这一场的敌人带不带埋伏、带几张。

### 四、`IgnoresProtection` 的内容配额 ≈ 1% 的游戏场景

> **带 `IgnoresProtection` 的效果应出现在约 **1%** 的游戏场景中。** 这是 08-04b「稀缺性归内容侧纪律」那条纪律的量化口径。

- **推论 ①：1% 是「出现频次」口径，不是「条目占比」口径。** 它约束的是**玩家实际撞上这类效果的频率**（量级上「百场遭遇遇一次」），不是内容库里带这个标记的条目数除以总条目数。**两者可以差很远**——一条挂在稀有 boss 上的效果，条目占比可能是 1/500 而出现频次是 1/50。
- **推论 ②：因此它无法被加载时校验机械化。** 加载时只能数条目、数不了出现频次；**08-04b 定下的 `PushWarning` 逐条列举保持不变**（它的作用是让这份清单始终可见、可人工审阅），1% 是**编排与抽取权重侧的口径**，落在内容设计与遭遇编排上，不落在代码上。
- **推论 ③：这个量级坐实了「法则会不会被拆」的实际体感。** 1% 意味着绝大多数对局中 `Power` 的保护是**事实上的绝对保证**；被拆是一个足够罕见、值得记住的事件，而不是需要每场都防的常规威胁——这正是 08-04b 明确接受的那个代价的具体大小。

### 五、不会有凭空生成的牌（全局硬约束）

> **本作不存在凭空生成的牌。** 「加入手牌」类效果的牌**一律来自既有的区**（抽牌堆 / 弃牌堆 / 卡组），**没有 token、没有运行时新造的卡牌实体**。

这条以**否定前提**的方式答结了 08-03 的「『加入手牌』落空时凭空生成的牌去哪」——问题里那两种情形（生成 token 类新牌 / 从牌库外取牌）**都不会发生**。

- **推论 ①：满手落空的规则已完备，无需第二条。** 既定的「牌留在原处、这次抽牌无事发生」覆盖全部情形：从抽牌堆来的留在抽牌堆，从弃牌堆来的留在弃牌堆。**不需要「产生后进弃牌堆」这条补充规则。**
- **推论 ②（承重 · 存档面净减）：一场战斗内的卡牌集合是闭集。** 战斗中卡牌只在区之间流转（卡组 ⇄ 手牌 ⇄ 弃牌堆 ⇄ 战场 ⇄ 栈），**总量不增不减**。故决策点存档只需记录**各区的 `Id` 序列 + 各 `CardInstance` 的运行态**，**不需要为运行时新造的匿名卡分配 id、也不需要序列化「这张牌是怎么被造出来的」**。这与既定的「存档只记 `Id`，`CardType` / `Subtypes` 是静态字段」完全合流。
- **推论 ③：不借入 MTG 的 token 概念，`CardType` 六分不需要第七类。** 与已否决的「引入放逐区」同源——现有六处位置与六个类型已能表达全部已定案的流转。
- **推论 ④：灵宠不受影响。** 灵宠是**从手牌打出后落到战场**的永久物，不是凭空生成的实体——它自始至终是卡组里那张牌。「场上的实体」与「凭空生成的牌」是两回事。
- **推论 ⑤：卡组增删只发生在战斗外。** 业障由事件的负向奖励塞进卡组、卡牌由奖励加入卡组，这些都是**轮回级**的卡组变更，走 `ProfileChangeSpec` → `TryApply`；**战斗内没有任何一条增删卡牌总量的通道。**

### 六、Finale 的天劫同受赋级约束

> **天劫只是 Enemy 的一种，遵循同一套境界与赋级规则**——它同样受 `±2` 带约束，**不享有任何等级规则上的例外**。

- **推论 ①（自洽性验证）：叙事与规则天然吻合，无需特例。** 篇章末角色处在境界巅峰（13 / 17 / 21），下一境界的初期是 14 / 18 / 22 —— **`diff` 恰为 +1，稳稳落在 `±2` 带内**。「渡劫 = 突破到下一境界」这句叙事因此**不需要为它开任何规则口子**就能成立。
- **推论 ②（承重）：Finale 的信息压迫感完整保留。** 天劫落在下一境界 ⇒ **越阶** ⇒ 按越阶硬门 **完全无意图信息**。这答定了「天劫是否天然属于大幅越级」这条待答问题：**天劫不是大幅越级（最多 +2），但天然越阶**——**信息面的结果与「大幅越级」完全相同，而数值面不至于失控**。两个目标同时达成。
- **推论 ③：天劫走同一条物化路径。** `EnemyTemplate` → 充实 / 改写 → 指派，与常规敌人无异；它的特殊性全部落在**定制卡组**与**遭遇参数**（回合数 / 胜负门槛可拧紧）上，**不落在等级上**。
- **推论 ④：Practice 同受此约束。** 「天劫只是 enemy 的一种」这句话的逆命题同样成立——**赋级规则挂在 Enemy 上，不挂在事件类型上**，故 Combat / Practice / Finale 三者一视同仁。Practice 的「低风险」由回合数与胜负门槛承担，**不由「派个更弱的对手」承担**。

## 与既有决策的张力

1. **⚠ `±2` 带与意图揭示阈值发生算术冲突（承重 · 需用户裁决）。** 既定阈值（`diff` = 敌人 − 角色）：**ch1** `≤ −3` 完整 / `−2 ~ 2` 仅类别 / `≥ 3` 无信息；**ch2 · ch3** `≤ −2` 完整 / `−1 ~ 1` 仅类别 / `≥ 2` 无信息。把 `diff ∈ [−2, +2]` 代进去：

   | 篇章 | 完整意图 | 仅类别 | 完全无信息 |
   |---|---|---|---|
   | **ch1** | **不可达**（需 `≤ −3`） | `−2 ~ +2` = **全部** | **仅靠越阶**（`≥ 3` 不可达） |
   | **ch2 · ch3** | 仅 `diff = −2` 一档 | `−1 ~ +1` | `diff = +2` 或越阶 |

   即：**第一篇章的意图揭示退化为单档**——除境界末两级的越阶遭遇外，**永远是「仅类别」**，完整意图在整个 ch1 不可能出现。而 08-02c 的定案是「完整意图 = 碾压专属、是碾压弱敌的即时反馈」——**`±2` 的下界把「碾压」这件事本身封掉了**，这一档在 ch1 变成死档、在 ch2 · ch3 只剩一个取值。**两条规则都是用户明确定下的，本次不擅自裁决**，三条可能的收口方向见 Open questions。
2. **08-03 的「赋级上界 = 高一个大境界的初期」被整条取代。** 其三条推论中，**推论 ①（上界档必然越阶 ⇒ 最难即最不可读）作废**、**推论 ②（元婴无更高境界）由「1–22 截断」自然承接**、**推论 ③（只约束上限不约束分布）继续成立**。
3. **`life-total.md` / `scoring.md` 的「由内容设计侧规避」措辞被降级。** 它不再是唯一防线——`±2` 是规则层的界，内容侧纪律退为第二道。**1:1 换算与「不设上限截断」本身不变。**
4. **08-03 推论 ⑤「栈可能不必落存档」被推翻。** 其依据是「栈非空时双方都不能出牌 ⇒ 可退出时刻栈必为空」；本次给出的反例（栈上的目标选择）证明该推理的前提漏了一类需要玩家输入的时刻。**「出牌时机唯一」这条规则本身没错，错的是把它等同于「唯一的玩家输入时刻」。**
5. **08-02b「决策点回落到回合 / 出牌这一级」被部分推回。** 该减压当时的依据是响应窗口与优先权移除；本次证明**结算内部仍有需要玩家输入的点**。减压的大部分仍成立（没有响应窗口），但粒度下界比当时估计的低一层。

## Open questions

- **⚠ `±2` 带下意图揭示阈值如何收口（承重 · 需用户裁决）。** ch1 的完整意图档不可达、无信息档只能靠越阶；ch2 · ch3 的完整档只剩 `diff = −2` 一个取值。三条方向：① **调阈值**（把完整档上移到 `≤ −1` 或 `≤ −2`，让它在带内可达）；② **接受退化**（ch1 就是恒定「仅类别」，把它当作篇章一的有意设定——新手期信息一律模糊）；③ **放宽下界**（`±2` 只约束上界，下界另给或不设，恢复碾压的可能）。三者对可读性、教学曲线与「完整意图 = 碾压反馈」的定位影响完全不同。
- **`±2` 是硬规则还是默认带、能否被剧本调制突破。** 隐藏属性 / 剧本调制（PlotManager）是否有权把某场遭遇推出带外（例如「大限将至」线上的绝境遭遇）？若可，突破的幅度与触发条件未定；若不可，则它是一条无例外的硬约束。
- **`±2` 带内五档的分布权重。** 上界档（`+2`）多久出现一次、依什么决定这次给几级——**分布问题本身未变**，只是可选范围从「境界天花板以下全部」收窄为五个档位，故权重表现在只有五个格子要填。
- **境界边界处 `diff = +2` 的残余量纲。** 炼气十三层（`baseMomentum` 15）遇筑基中期（24）= 开局落后 9，对 `lifeTotal` 10/10 仍是「一次惨败几乎打穿」。它已在规则界内（不是矛盾），但**它是 `lifeTotal` 更高境界基线的一个具体输入**——筑基巅峰（32）遇金丹中期（55）落后 23，故筑基 / 金丹的 `lifeTotalLimit` 基线不能停在 10 这个量级。→ 归 ch1 数值标杆专场与 `life-total.md` 的「更高境界基线」。
- **「1% 的游戏场景」的分母口径。** 本次解读为**玩家实际撞上的战斗遭遇数**（约百场遇一次）；若用户本意是「内容条目占比 1%」或「带此效果的敌人占敌人库 1%」，量级会差一个数量级以上，需确认。
- **栈的存档字段形态。** 栈条目要落哪些字段（来源 `Id`、已选目标的 `TargetRef` 列表、挂起态标记、栈内位置），以及它与战场条目、道具运行态、`Power` 运行态如何组成一份完整的战斗决策点存档 schema。
- **挂起态的取消语义。** 若玩家正卡在「选目标」这一步时退出 / 断线 / 应用挂起，恢复后是回到该选择点（栈原样挂起），还是回退到上一个更粗的边界？这与「`AdvanceEventAsync` 的取消触发方」是同一组问题。
- **需要选目标的触发式异能的频度。** 若这类异能很常见，决策点会显著变密（写入频率与 push 防抖压力上升）；若极稀少，则可作为例外路径处理。这是内容侧的密度问题，直接影响存档粒度的实现取舍。
