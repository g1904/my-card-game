## Intent（distilled）

两条各自悬着的待答项——**事件选择区的呈现与导航手感**、**闭关构筑面板的竖屏呈现与风险档标注**——要的是同一样东西：本库至今没有一套成文的「一批候选项在竖屏怎么摆、怎么标、怎么解释」的通用语言。每新增一个决策面（战后奖励、置换、构筑槽、剧本分支、Exchange、储物袋）都要重裁一次，而这正是「不发明第二种选择语言」所要防的漂移。故本次**先立一套可复用的候选项列表语言，再把它落到这两个场景**。

### 一、候选项列表语言（横切所有决策面）

1. **两条排布轴的分工判据**（把已经在事实上生效的做法写成明文纪律）：
   **推进进程的择一 → 横滑等宽 carousel；面板内 / 事件内的择一与列举 → 纵向堆叠或网格。**
   六处既有落点逐一核对后自洽：eventOptions 选择区与角色选择屏在横滑侧；Exchange 网格、剧本分支按钮、储物袋 / 图鉴网格、战后奖励 / 置换 / 构筑槽在纵向侧。
   推论：两个待答场景各落在轴的两侧，它们**共用的不是轴，而是条目构件与标注语言**——这让「构筑面板与战后奖励面板同构」这句约束落在一个可独立成立的层上。

2. **统一的「候选条目」构件 = 六个位**（顶带类型标识 / 顶带标注带 / 中带视觉 / 名称 / 一行副文本 / 数值行）。两条轴共用同一构件，只有外框比例不同。
   六个位全部可空，**缺位整格不渲染、不留空占位**；**长文本永不截断成省略号**（超出归长按详情）；**触控目标 = 整个条目**。

3. **标注层分三类，位置与优先序固定**：资源数值标注（数值行，恒精确、成本 / 产出两侧对称）· 状态 / 风险标注（顶带标注带，静态常驻、每条目至多 2 枚）· 实例信息标注（数值行独立一行，同屏只标一次）。
   **三条禁则**：不加由已展示数字机械导出的符号（推论：不给卡片级致死标记）· 不显示隐藏的映射量 · 不做灰态表达「不划算」。

4. **统一的说明通道（无 hover 的等价物）**，三层深度全库共用：恒常可见 → **长按**半屏 bottom sheet → 再叠一层 bottom sheet。**绝不用悬停、绝不用「ⓘ」小图标。**

### 二、事件选择区

- **1–5 的自适应七条规则（R1–R7）**：卡宽 / 卡高跨批恒定不随 N 缩放 · 标定基准 = 常态 3 项恰好同屏 + 左右 peek · N ≤ 3 不可滚动（回弹）· N = 4 / 5 逐项吸附 · N ≥ 4 给 N 枚位置点 · N = 1 与多项批完全同形且不加说明文案 · 闸门批复用同一选择区零特殊形态。
- **进入手势 = 焦点制**：点非焦点卡 = 居中导航、不支付；点焦点卡 = 支付并进入。零新增控件、不改 Explore 既有流程图。
- **卡面六个位逐位落定**；**标注带在事件选项卡上恒为空是结论，不是遗漏**（三条禁则逐条排除了全部候选）。
- **寿元告警只落角色状态条的 `❤` 位，不下沉到卡片层**（三条独立依据：既定落点本就在选择区正上方 · 卡片级告警撞禁则 1 · 它会取消「明知是死路仍然走」这条承重取向）。
- **六个手感参数给待实测初值**（卡宽 ≈ 屏宽 28% · 卡高 : 卡宽 ≈ 1.45 : 1 · 间距 ≈ 16 px · peek ≈ 36 px · 翻页阈值 25% · 吸附 ≈ 180 ms），**旋钮位置 = 呈现层常量的 `[Export]` 字段，不进数据资源 / 存档 / 内容条目**（它们不是平衡数值，改它们不改任何玩法结果）。
- **角色选择屏与本区共用同一卡宽基准** ⇒ 该屏 5 张角色卡照常滑动、不追求同屏。

### 三、闭关（Research）构筑面板

- **P1–P7**：全部槽同屏共用一个纵向滚动容器、不做分步向导 · 确认键固定底部 · 未选满置灰 + 一行说明 · 「什么都不做」是候选列平等的最后一行 · 选中态即时反馈且改选零代价无二次确认 · 候选短缺不做呈现区分 · 顶部不显示 `lifeSpanCost`。
- **风险档标注 = 中性色标记 + 常驻一行「成功 法力上限 +1 · 失败 −1」**。明写规则而非藏起来（`manaLimit` 是明面资源，`+1 / −1` 是规则不是隐藏映射；既定的「不预先展示」保护的是已掷定的**结果**）；不用告警色（告警色的专属语义「寿元见底」值得保护，且警示色读起来像系统在劝阻，与「风险是被选择的」相抵）；不做二次确认、槽级不预告、标注静态无动效。
- **与战后奖励面板的同构只落在三层**：条目构件 + 标注层 + 说明通道；交互层不同构（一次确认提交 vs 逐项即时处置）。

### 四、落地面

**数据与存档零增量**：存档 schema 零改动零 bump · `EventOption` / `ResearchCandidate` 零新增字段 · 批次规模读 `Options.Count` 而非 `BatchSizeWeights` · 内容条目零新增字段 · 六个手感参数不受 overlay 管辖。

## Clarifications（interview 产物）

- **事件选项的进入手势** → **焦点制**（点非焦点卡居中导航不支付，点焦点卡支付并进入）。推翻了「单击即进」与「选中 + 底部确认按钮」两个备选：前者在竖屏窄栏下边缘卡只露一部分，误触不可逆且可能致死；后者在全游戏最高频路径上每次多一次点击，且要改写 Explore 既有流程图。
- **走火入魔风险档的标注强度** → **中性标记 + 明写规则**。推翻了「警示色 + 明写规则」（稀释告警色的专属语义）与「只给定性文案不写 `+1 / −1`」（`manaLimit` 是明面资源，藏起一条纯规则会让玩家无法为赌注定价）。
- **卡宽标定基准 vs 角色选择屏「5 张卡同屏」** → **两处共用同一卡宽基准**（常态 3 项同屏 + peek）。这推翻了角色选择屏原留的一句「5 张卡的同屏容纳度待实测」所隐含的期待；该句已改写为已答：不追求同屏，滑动即可。理由：坚持 5 张同屏须把卡宽压到屏宽 ≈ 18%，事件卡的副文本与数值行在该宽度下不可读，实际后果是两处横滑区各用一套卡宽，「同款手感」当场退化为「同一种手势、不同的排版」。

## Open questions

- **寿元余量转红字时是否伴随音效 / 震动**（既有的独立待答项）。本次只定视觉形态，与它互不预设。
- **走火入魔候选的出现权重**（既有待答项）。只影响风险候选出现的频率，不影响标注形态。
- 六个手感参数与吸附 / 翻页阈值是**待实测初值**，只能在真机上调；它是实测校准，不是待裁决的取向。
