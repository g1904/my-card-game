## Intent（distilled）

**一句话：** 胜侧道念差的经验加成（`rewardPerMomentum[experiencePoint]`）此前在单价表里有一列、逐章有取值，却从未进过经验供给账 `G_c`；本次把它计入，并把单价下调、存储形态改为整数 `K`，供需带的管辖对象一并归一 —— A3 三章因此落带，而这属于**调构成**，阈值曲线一格不动。

### 1. 正面认账：这是账目缺口，不是设计选择

「应当计入」有三条各自独立成立的依据：① 同一条式子的两条账取了相反口径 —— 灵石侧 `I(c)` 计入道念差加成，经验侧 `G_c` 不计，而没有任何一处文档给过这个差别的理由；② 失败代价 ⑤「胜侧加厚归零」已是定案，若经验不吃加成，⑤ 在经验一列上就是空的；③ 单价表有 `experiencePoint` 一列且逐章给了值 —— 不计入等于让一列已定案的数据在账上不存在。

### 2. 根因：一条带被同时施加在两个相差 6–8% 的量上

`1.15–1.20` 这条带此前同时卡两个分子：全胜路线的 `G_c`，与扣掉 `N = 2` 次典型失败后的 `G_c − 2X_c`。两者相差 `2X_c / D_c` ≈ 7.6% / 7.3% / 6.1%，**算术上不可能同时落在同一条带里**。A3 三章不达标的根因是这处口径撞车，不是数值没校准 —— 无论怎么实测都不可能同时满足两条。

**裁定：带只管辖「扣 N 后的比」（A3 口径）。** 全胜比降级为**导出量**，带不管辖它。理由：带的两条边界（更高 ⇒ 玩家提前满级、后半章奖励变废纸；更低 ⇒ 跳过几个事件就卡在境界末级进不了 Finale）描述的都是实际游玩路线的失衡，而全胜是上界情形、不是典型路线；且 A3 是写进表侧核对清单的机械可校验断言，比一句书写口径更承重。**已接受的代价：** 全胜路线的经验冗余上移到 25–30%，熟练玩家在篇章后半段会更早看到经验奖励变废纸。

### 3. 计入 + 单价下调，存储形态统一为整数 `K`

`element 量 = baseReward 中该 element 的量 + floor(道念差 / MomentumPerUnit[element][篇章])`。**`floor` 语义必须明写** —— 否则「四舍五入还是截断」会在文档与实现处各取一半（与 21 格定价表「半值一律四舍五入向上」同款处置）。`K` 为正整数、逐章不下降；`K == 0` 无意义 ⇒ 加载期 `PushError`（带篇章与 element 名）。不引入浮点、不设上限截断、平局给 0 加成。

| 量 | ch1 炼气 | ch2 筑基 | ch3 金丹 |
|---|---|---|---|
| `K`（`MomentumPerUnit[experiencePoint]`） | **5** | **6** | **9** |
| `p_c` = 一场胜局的道念差经验加成 = `floor(E[道念差] / K)` | **1** | **2** | **2** |
| 战斗场数 `n_c` | 11 | 11.9 | 14.0 |
| 道念差加成合计 `n_c × p_c` | **+11** | **+25** | **+28** |
| `G_c`（计入后） | **103** | **314** | **488** |
| 需求 `D_c` | 79 | 247 | 391 |
| `X_c`（一次典型失败的经验损失，三笔合并） | **4** | **11** | **14** |
| **A3 = `(G_c − 2X_c) / D_c`** | **1.203** | **1.181** | **1.176** |
| 经验侧 `N` 上界 `(G − D) / X` | 6.00 | 6.09 | 6.93 |
| `N_c`（软 · 三章均取寿元侧） | 5.30 | 4.97 | **2.69** |
| 全胜比（**导出量 · 带不管辖它**） | 1.30 | 1.27 | 1.25 |

- **`K` 取值使 `K` 整除 `E[道念差]`**（5|5 · 6|12 · 9|18），于是 `floor(E/K) = E/K`，两种估计口径重合、文档内的口径分歧结构性消除。
- **诚实边界：** `K | E` 只消除**文档内**的口径分歧；`E[floor(d / K)] ≤ E[d] / K` 这个估计偏差仍然存在。本次沿用点估计代入（与整份台账既有做法一致），实测拿到道念差分布后须按分布复算期望，届时 `K` 可能移动一档。
- 灵石列 `K` = 1 / 2 / 4，与现值等价、零改动。
- 单价逐章下调的形状保住（`K` 递增 5 → 6 → 9），与「吸收 `baseMomentum` 百倍量纲膨胀」同向。

### 4. 失败代价由两笔变三笔；三章一律由寿元侧封顶

一次典型失败的代价：寿元 `L_c` = 50 / 60 / 180（不变）· 经验档位折半 3 / 9 / 12（不变）· **胜侧加成归零 `p_c` = 1 / 2 / 2（新增）** ⇒ 合并经验损失 `X_c` = 4 / 11 / 14（占本章阈值合计 5.1% / 4.5% / 3.6%）。

**`N = 2、三章统一` 的定案与三条依据的结构一字不变**；依据①的三个数由经验侧改为寿元侧的 5.30 / 4.97 / 2.69。计入后**三章一律由寿元侧封顶**，经验侧上界（6.00 / 6.09 / 6.93）全程宽松、退出竞争。**ch3 仍是全轮回容错最薄的一章（2.69）**，这是已登记的实测复核点，不为它加旋钮。

### 5. 新增断言 A4，补运行期的空白

既有断言「单次给予量 ≤ 该境界最小阈值」的对象是 `ExperienceGrade` **映射值**（加载期），管不到含道念差加成的运行期总量。补一条同档断言：

```
A4   Major 映射值 + E[道念差]_c × 单价_c  <  2 × 该境界最小阈值
```

本次取值下 ch1 `6 + 1 = 7 < 12` · ch2 `18 + 2 = 20 < 138` · ch3 `24 + 2 = 26 < 216`，三章通过；**该断言实际只咬 ch1**，ch2 / ch3 余量极大。**A4 不进 `.tres`、不进加载期校验** —— 它含 `E[道念差]` 这个 ⚠ 待实测标定格。

### 6. 影响面与不动面

- **`.tres` / schema 零改动、无迁移。** 单价表本就是既有平衡资源的一格，改的是取值与记法（分数 → 整数 `K`）；`G_c` / `X_c` / A1–A4 全是书写口径与标定台账，不进任何 `Resource`、不进存档。
- **玩家侧可感知变化很小。** ch1 一场典型胜局多拿 1 点经验，碾压局多拿 2–3 点；越级挑战在经验侧也有回报，与「道念差是双向刻度」同向。
- **`Spoils` 物化后会出现一格 `experiencePoint`**（其 `baseReward` 分量恒 0、只有道念差加成）—— 这正是「物化后可出现的 key ≠ 模板可声明的 key」的字面情形，与 `BaseReward`「element 面 = 灵石一格、其余恒空」不相抵，但须在该条补一句澄清。
- **`ExperiencePoint` 的物化来源面多了第二条：** 「只能由物化组装从平衡表映射展开」的**来源**放宽为「档位映射 `ExperienceGrade` / `HiddenStatGrade`，或胜侧单价 `rewardPerMomentum`」；承重的那一半（模板不可声明 · 内容侧不落裸数字 · 物化后可出现的 key ≠ 模板可声明的 key）不受影响。
- **不动：** 覆盖率 ≈55%（计入加成不改变「哪些事件带经验」，ch1 参考构成实算仍是 54.3% = 19 / 35）· 缩放曲线登记表第 5 行的状态 · `systems/scoring.md` 与战斗侧只写「单价逐篇章下调」形状的两处 · 五格「典型失败」口径表 · 阈值曲线 · 21 格 `lifeSpanCost` 定价表。
- **验收仍是两层**：表侧断言 A1–A4 + 编辑器侧固定 seed 三读数。

### 已否决的路线（理由承重，留着以免被重新提出）

- **按现价（1 / 2 / 4）原样计入、超出部分靠提高阈值曲线吸收** —— 收口方向明写「调这条曲线或调构成，不是提高阈值」；且吸收 ch1 的 +38% 需把阈值合计从 79 抬到 ≈114。
- **给经验侧的线性加成加一个上限截断** —— 胜负两侧均明写不设截断：截断会让「一次惨败 / 一次碾压」失去分量，正确的旋钮是系数本身。
- **只让部分 `combatTier` 吃加成** —— 单价表只有篇章一维；按档分档与「三档共用同一系数，一个篇章之内玩家的心算账本只有一本」正面相抵。
- **删掉 `experiencePoint` 列（裁定经验不吃道念差加成）** —— 与带管辖 A3 口径不自洽（需要 `p > 0`），且等于删掉一列已定案数据。
- **把 `Explore` 真身为 Combat 的那部分也计进加成** —— 供给侧把 `Explore` 计成扁平的 `Standard` 档、不区分真身；加成侧单独区分会造成两半口径不一致。ch1 影响量约 2 点（≈2%），保守不计。
- **`K` 取 ch1 = 6** —— `floor(5 / 6) = 0`，典型胜局的结算屏会显示「道念差加成 +0」，而结算屏要求显式陈列算式。取 `K = 5`，接受 A3 ch1 落在 1.203 的那个 ε。

## Clarifications（interview 产物）

**用户裁决（2026-09-10 批量评审合并 interview）：**

- **经验单价 `K` 的取值与 `floor` 口径** → **`K = 5 / 6 / 9`**（令 `K` 整除 `E[道念差]`）。它**推翻**草稿子项 4 / 子项 5 与「具体形态 ①」写的 `K = 5 / 8 / 12`，以及草稿 `p_c` 列填的 `1 / 1.5 / 1.5`：草稿表头写 `p_c = floor(E/K)` 而 ch2 / ch3 的取值 1.5 未取 floor，两处对同一个量取了相反口径；取 floor 则 A3 ch2 / ch3 = 1.141 / 1.146 跌出下沿，`K = 8 / 12` 当场失效。随之改写的还有：草稿 Q1 裁决文复述的全胜比 ch2 / ch3 由 1.25 / 1.23 改为 **1.27 / 1.25**（冗余 23–30% → 25–30%，量级不变，Q1 已接受的反方论据不因此翻转）；`X_c` 由 4 / 10.5 / 13.5 改为 **4 / 11 / 14**；`G_c` 由 103 / 308 / 481 改为 **103 / 314 / 488**；A4 的 ch2 / ch3 代入由 19.5 / 25.5 改为 **20 / 26**。ch1 一列完全不动。**同时锁定：** 诚实边界（`E[floor(d/K)] ≤ E[d]/K` 的估计偏差仍在、实测须复算、`K` 可能移动一档）必须写进正文。
- **`ADR-0176` 与本次落笔的正面冲突** → **直接改写该 ADR，不新开取代 ADR**（根约定「决策可被推翻 → 改那份 ADR」）。草稿的「与既有决策的张力」列了四条，**没有一条是 `ADR-0176`** —— 而该 ADR 的决策原文「A3 三章均不达标的事实如实记录……台账不得写成『三条全过』」与后果「台账里会长期留着三个『✗』」在 A3 落带后当场作废。改写面：标题 · 决策 · 备选方案第二条（改为正面陈述：判据的边界值不因结果调整，本次改的是带管辖哪一个量，且由口径撞车驱动而非结果驱动）· 后果（删去三个「✗」那条）· 理由第四条（「实测才是这条的正确出口」重指向 ch3 余下的 2.69）。**保留：** ch3 最薄不加旋钮那条（三章改由寿元侧封顶后 ch3 仍是 2.69，这条加强而非削弱）· 两层验收那条。

**已按标准默认采纳（未占 interview，依据随附）：**

- **失败侧是否同时吃 ④ 与 ⑤ 两笔** → 是，且两笔不重叠。依据：④ 出自模板侧 `ExperienceGrade` × `FailureRatio`，⑤ 作用于道念差加成，书写位不同、量不同源。
- **⑤ 的「失败只发 `baseReward`」是否需要限定语** → 需要。依据：计入后经验的 `baseReward` 分量恒 0（`BaseReward` 的默认 element 面只有灵石一格），⑤ 的字面读法会导出「失败零经验」，与 ④ 直接打架 ⇒ 限定语写作「作用域限于线性加厚这一路，经验的档位产出走独立书写位、不受本条约束」。
- **`game-progression.md` 的「三者能同时成立」措辞** → 按 A3 读法重述中间那一项为「扣掉 N 次典型失败后的供需比落 1.15–1.20」即恢复成立。依据：带改为管辖扣 N 后的比后该口径全落带。
- **覆盖率 ≈55% 是否随之下调** → 不动。依据：计入道念差加成不改变「哪些事件带经验」，ch1 参考构成实算 54.3%（19 / 35）不变；且全胜路线的经验冗余已是 Q1 一并权衡并接受的代价，不借覆盖率的壳重新出题。
- **失败代价表 ④ 的「供需比仅 1.15–1.20 ⇒ 反复失败真实导致卡级」是否被削弱** → 不削弱，反而更直接成立（扣 2 次失败后正好压在 1.176–1.203）；只需把它指明为扣 N 后的口径。
- **`ExperiencePoint` 的「只能从 `ExperienceGrade` 展开」如何处置** → 来源面放宽一档（新增胜侧单价 `rewardPerMomentum` 这条同样是平衡表映射的来源），承重的三句一字不动。依据：新增的来源同样是「平衡资源映射、内容侧不落裸数字」。
- **A4 是否三章都写** → 三章照写，并明写 ch2 / ch3 余量极大、该断言实际只咬 ch1。依据：与 `lossPerMomentum` 的「形状锚三章逐格校验」同形。
- **A4 是否进 `.tres` / 加载期校验** → 不进。依据：它含 `E[道念差]` 这个 ⚠ 待实测格，此类量既定处置是不进任何 `Resource`。
- **单价存储改整数 `K` + `floor` 明写** → 属通行做法。依据：既有纪律「沿用分数记法、不引入浮点」与 21 格定价表「不写死方向，文档与实现会各取一半」；`K == 0` ⇒ 加载期 `PushError` 照必需项的空值校验语义。
- **ch1 战斗场数取 11 还是 11.5** → 取 11（35 批次参考构成的显式 Combat 行 5 + 5 + 1）。依据：`G_c` = 92 的构成本身就是这套参考构成，加成侧必须与供给侧同分母；差异 −4%，不移动任何 `K`。
- **缩放曲线登记表第 5 行（胜侧 `rewardPerMomentum`）是否改** → 不改。依据：该表明写「只指路与记状态，不复制数字」，状态仍是「已定」。
- **只写「单价逐篇章下调」形状的两处（`systems/scoring.md` 与战斗侧）是否改** → 不改，它们不含取值。
- **`itemPowerRatio` 的 1.15–1.20** → 与本条无关，纯同形数字巧合，复扫时不得误改。

## Open questions

- **`E[道念差]` = 5 / 12 / 18 与熟练玩家败率 20% 仍是两个 ⚠ 待实测标定格**，不得引为承重依据。本次 `p_c` 与 `K` 全部由前者派生 ⇒ 该格一改，`K` 须按同一条式子重算（改的是数，不是形状）。
- **`E[道念差]` ch3 的 35% 偏高**（`open-questions/01-combat.md` 在办）与本条强耦合：若 `E_3` 下调，`K_3` 须同步重算并保住 `K | E` 的整除性质。**先后已明确：本条先落（`K` 是从属量），`E_3` 实测改写时由同一条式子自动重算** —— 与「任一反推输入格被实测改写时 `N` 由反推式自动重算」同款处置。
- **`E[floor(d / K)] ≤ E[d] / K` 的估计偏差**：实测拿到道念差分布后须按分布复算期望，`K` 可能移动一档。
- **ch2 / ch3 的逐类型事件构成表尚未补齐。** `G_2` / `G_3` 与战斗场数 11.9 / 14.0 同为按权重外推；构成表落定后 ch2 / ch3 两列须整列重算。ch1 是三章中唯一可复算的一列。
- **`lossPerMomentum` ch2 / ch3 仍是候选值**（5 / 10）。它只影响寿元侧封顶值，不影响经验侧算术；但 `N` 的 `min` 取自寿元侧 ⇒ 它一改，`N` 由反推式自动重算（既定处置）。
- **两条账的分母口径并未统一。** `G_c` 是全胜口径（不含败率），灵石侧 `I(c)` 含败率 20% —— 本次统一的只是「胜侧道念差加成是否入账」这一点，不是分母。
- **`systems/balance.md` 的 `I(ch1) ≈ 127` 账目缺口**：其中道念差加成分量按同一格输入复算不出（应为全胜 55 或按 20% 败率折的 44，而不是 32），⇒ `I(ch1)` 应为 ≈150 或 ≈139，`I_cum` 与定价表购买力对账随之要复核。本次不改数，登记待答。
- **战斗场数在库内有三个并存读数**（参考构成 11 · 灵石侧约 11.5 / 11.9 / 14 · `0.35 × P + 1` 的公式解），最大相差 20%。本次按理由取 11，不去统一它们。
