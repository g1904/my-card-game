## Intent（distilled）

剧本树的数据挂点已定（`PlotEdge.BranchLabel` 非空 = 对玩家可见的分支边、`PlotCondition.Kind == BranchChosen` 是它专用的推进条件、`PlotSegment.Branches` 是产出载体、`ChooseBranch(branchId)` 经 `ProfileManager` 写入一条 `PlotKeyPointAssignment`）。悬着的是呈现侧三问：**何时** · **哪一屏** · **可见 / 不可见的边界**。

### 触发点 = `eventEnd` 那一次 `TryApply` 提交之后

这不是取舍，是被既定纪律逼出的唯一位置：

- **不能落在 `eventEnd` 组装之内**——五步组装里插一次玩家等待，等于在⑤提交之前引入一个可退出点 ⇒ 需持久化中间态，与「中间态永不需要持久化」「取消点与存档点永远重合」正面冲突。
- **不能落在事件推进之外的独立时机**（例如每 N 个事件弹一次）——剧本推进的唯一时点是 `eventEnd`，另设时机就是给剧本层开第二个出口。

故落点唯一：`eventEnd` 提交完成 → 该 arc 的 key point 已停在分支节点上 → 结算面板呈现该节点的正文与分支 → 玩家点选 → `ChooseBranch` 一次 `TryApply` → 面板收起。**分支呈现在 arc 抵达该节点的同一次结算面板上，不延后一次收口**——延后只会让分支正文与产生它的那个事件脱节。

### 屏 = 事件结算面板内追加一段「剧本段」

跨档叙事已确立先例：由状态转换触发的定性文案播在事件结算面板内，不是独立弹层。剧本分支是同族的东西，没有理由为它选一个跨档叙事被明确否决过的形态。

- **剧本段 = 正文（可空）+ 分支（可空）。** 有分支时**分支按钮取代「继续」**——玩家本就要点一次「继续」离开面板，分支节点上那一次点击变成「选哪一条」，**零额外点击**；无分支时正文 + 既有的「继续」。纯叙事节点（`Body` 非空、无分支）因此与分支节点共用同一落点，这顺带填上了「剧本正文落哪一屏」这个至今无明文的空位。
- **纵向堆叠全宽按钮**，每条一行、承载 `BranchLabel` 全文不截断；满足触控目标尺寸下限、落在拇指可达区与安全区内。**不复用横滑区语汇**——横滑是 eventOptions 与角色选择的语言。
- 正文过长时面板内纵向滚动，按钮不随之移出视野；零 hover 通道。
- **不做二次确认**（不损失资源，与储物袋「使用」不做二段确认同判据）、**无跳过、无默认选中、无超时自动选**（该节点出边全是 `BranchChosen`，不选即无出边可走）。
- **未选完退出 = arc 停在该节点**，key point 已提交，下次收口的结算面板照常再呈现；该等待时刻**不是新的存档点**。
- **分支段不带「这是一次剧情抉择」的显式标识**：与结算面板其余部分同一视觉层级，剧本层继续保持隐匿。玩家读到的是「有人问了我一句话」，不是「系统给了我一个剧情选择」。
- **一次收口至多呈现一条 arc 的分支**，其余 arc 停在各自节点、下次收口再呈现。固定优先序：`Tier` 序 `Story → Chapter → SideChapter → SideStory`，同 `Tier` 按 `ArcId` 字典序。确定性是硬要求（同一存档恢复后必须问同一条），字典序是零成本的确定性来源。这同时填上 `TryResolvePlot` 单数产出在「多条 `Active` arc」下取哪一条的空白。
- **与跨档叙事同屏时：跨档叙事行在上、剧本段在下**——前者是刚发生的事的回响，后者是要玩家做的下一个动作。
- **终态时不呈现分支**：终态判定 ① 命中时 `eventEnd` 根本没跑；判定 ② 命中时整段不渲染，直接走轮回结束屏，arc 停在原节点随角色数据一并拆解。
- 文案：面板框架走 `EVENT_` / `event.csv`；`Body` 与 `BranchLabel` 一个字都不进 `res://text/`——内容层 `LocalizedText`。

### 可见 / 不可见的边界

**结构判据（可机械检查）：** 把 `BranchLabel` 非空与 `Condition.Kind == BranchChosen` **焊成充要关系**，边界不再依赖内容作者的自觉。异或成立即 `PushError`（带 arc `Id` + 节点 `Id` + `ToNodeId`）——一条摆给玩家看却由后台条件推进的边，玩家点了不生效；一条等玩家选却没有标签可呈现的边，该 arc 死锁。

**内容编排判据：** 三条同时成立才写成可见分支——① 它是一次**当下可理解的承诺**（答应 / 拒绝、走哪条路、收不收下某物），玩家不需要任何隐藏信息就能判断自己在选什么；② 两条分支在**调制上真的分岔**，而不是两句措辞不同、汇回同一节点的文案；③ **不依赖玩家读出隐藏量**才能做出选择。**其余一律写成自动边**——由 `HiddenStatBand` / `EventResolved` / `EventCount` / `ChapterAdvanced` 驱动的推进正是隐藏属性显影纪律要求静默的部分。

**禁令：分支不得成为隐藏属性的读数口。** `BranchLabel` 是玩家能读到、由剧本节点触发的文案 ⇒ 它是隐藏属性泄露的一条新通道。既有的软检查扩用到它：正文含属性名 / 阿拉伯数字 / 档位序号 → `PushWarning` 逐条列出。

### 频次

每条 Story / Chapter arc 每篇章 0–2 个分支节点，一次轮回合计个位数；单节点 2–3 条分支，> 3 条 → 加载期 `PushWarning`。它是**内容编排目标值，不入结构**，与跨档叙事「≈2–4 条 / 轮回」同量级、同「稀缺才有分量」。

### `ChooseBranch` 那一次写入的定位

它是**批次层的一次独立即时提交**，与储物袋道具使用同族，**不新增存档点清单条目**。三条连带纪律逐条核过、不开例外：不触发 `RefreshAfterEvent`（成立且必须——重算会消耗 `map` 子流，并开出「用一次分支选择刷新这一批事件」的通道）· 照跑终态判定（**恒为 no-op**，`PlotKeyPointAssignment` 不动任何资源 element）· 不计软阻塞闸门（闸门只数事件级存档点）。push policy `Debounced`。

**不把分支选择记进 key point 的已走路径数组**（既定：判据「重算不出来且有消费方」当前无消费方；日后落点是 `PastEventEntry`）。存档 schema 零改动、零迁移。

## Clarifications

- **分支段是否带显式标识 → 不标识。** 承重的「隐藏剧本层 + 调制才是显影通道」是本作区别于 Reigns 的核心路径；标识的代价（把刻意隐藏的剧本层在 UI 上显形一次）大于收益，而「一时不确定」由分支按钮本身的文案自然消解（按钮上写的是「答应他」而不是「继续」）。
- **纯叙事节点（`Body` 非空、无分支）是否也落在事件结算面板 → 一并定，落同一落点。** 这推翻了草稿 §3 末尾「若评审认为应单独裁决，可把本节收窄为『仅分支节点的正文落结算面板』」那句保留。依据三条：分支必然需要正文作语境，两者分落两处则一次选择要跨两个呈现面；另开一层全屏剧本层已被否决（与「叙事是点缀不是载体」相抵），除结算面板外没有第二个候选落点；跨档叙事已确立「定性文案播在结算面板内」的先例，剧本正文与它同族。
- **「一次 `eventEnd`，每条 arc 至多前进一个节点」重述为「一次 `eventEnd` 之内至多前进一个节点」**（标准默认）：行为零改动，只把作用域写明。防自动连跳的承重理由未被削弱——两步之间无 eventOptions 重算，且第二步是玩家亲手做的而非自动连跳。
