# flags 零装载失败刻意不给专属错误码

- id: 2026-09-09-flags-zero-load-no-dedicated-code
- date: 2026-09-09
- topic: contracts/envelope（§6「台账的承重项」）· contracts/content-manifest（B 组）· systems/content-delivery（回源失败的降级）· operations/observability（零装载失败计数器）
- status: distilled
- distilled-to: `contracts/envelope.md`、`contracts/content-manifest.md`、`systems/content-delivery.md`、`operations/observability.md`

## Intent（distilled）

**一句话：** `GET /v1/content/flags` 在「本实例零装载 + 回源失败」这一失败面上**不新增专属 `code`**，沿用兜底的 `server.unavailable`（`Retryable`）；把「需要看见这个失败面」这件事从契约挪到服务端自有指标，并同批把那条指标真的落下来。

### 判据：什么样的失败面才值得一条专属 `code`

`envelope.md` §6 台账的「承重项」小节已经把每一次拆 / 并的理由写在纸面上，从中可归纳出实际在用的判据（满足其一即值得独立成码）：

| # | 判据 | 本题 |
|---|---|---|
| J1 | **客户端处置不同**（第一判据） | **不成立** |
| J2 | 玩家可见的措辞分叉（本身不构成理由，一律同码 + `reasonKey`） | **不成立，且玩家面为空** |
| J3 | `class` 不同，或混入会污染某一档的静态推理 | **不成立** |
| J4 | `detail` 须携带客户端必须消费的字段 | **不成立** |
| J5 | 线上两条曲线运维处置不同，**且区分所需的事实由对端持有、指标层自己分不出来** | **前半成立，两个限定均不成立 ⇒ 整条不成立** |
| J6 | 台账四要素都产得出（必要条件，不是理由） | 勉强成立，但只是入场券 |
| J7 | 端点错误清单的封闭性本身是资产 | **反向成立 ⇒ 支持不新增** |

**J5 的两个限定是本题的关键。** `purchase.receipt_pending` 必须独立成码，不是因为「运维想看两条曲线」，而是因为区分它的事实**只有支付渠道知道**、我方指标层自己产不出这个维度。而 `sync.conflict`（CAS 冲突与回声拒绝共用一码、指标层分开计数）与 refresh 的滥用面（只记账告警、不返回限流码）合起来证明：**当区分所需的事实就在我方进程内时，本库的既定做法是打点，不是开码。**「本实例已装载的键集是否为空」正是这样一个数——它已经在供两条 gauge 用。

### 承重推论：「绝不把空 `disabledIds` 持久化为降级值」不靠 `code` 成立

悬项的原始动机是「空集合会被客户端当作一批合法 flags 持久化下来」。这条风险由两条**结构事实**堵死，与 `code` 取什么值无关：① 错误应答的 body 只有 `{ error: { code, class, message, detail?, requestId } }` 这一个形状，根本不含 flags 报文的五字段，服务端保证 F7 已把这一点写成可验收的断言 ⇒ 客户端解析不出一批 flags，不存在「拿到一个空集合」这个中间态；② 客户端缓存的写入时点唯一 = 一批 flags 通过单调闸并被应用之后，拉取失败一律不写。**一条专属码在这里不增加任何保障。**

### 留痕：把「刻意不给」写下来，而不是留空

同 refresh 刻意不给 `rate.limited`、理由落在网关纪律里的既有做法。三处落笔：`envelope.md` §6 承重项追加一条（**台账表本身不加行**，守 P-1）· `content-delivery.md`「回源失败的降级」末行由「归 §6 台账裁决」改写为取兜底码 · `content-manifest.md` B 组补一句「flags 端点不引入任何 flags 域专属错误码」（这句同时保住机检断言②——它扫的是六份契约正文，而 `content-delivery.md` 是 `systems/` 文档、不在扫描面内）。

### 配套：服务端侧的零装载指标

把风险从契约转移到指标，就必须真的把指标落下来，否则等于把风险抹掉而不是转移。一条**零装载失败计数器**，维度含实例标识，触发条件与服务端保证 **F7** 的输入逐字对齐；阈值 = 任何非零持续超过「当前版本读取缓存 TTL + 装载耗时」即告警（该窗口已由 F5 定义，**不另立新窗口**）。它补的是既有两条 flags gauge 结构性看不见的那一块：零装载的实例根本没有「本实例可兑现的最大版本」这个数，两条 gauge 在它身上都无值，而「gauge 无值」极易被读成「零落后」。

### 对 derive 的影响

`open-questions.md` 此前写的是「derive `/v1/content/flags` 时按兜底码落笔**并标注该条可能后续替换**」。**那半句注记随本条销号一并删去**——FR 的验收标准直接按 `server.unavailable`（`Retryable`）写。理由：那句注记是**悬项状态**的产物，不是结论的一部分；留着会让验收标准无法机械核对（核对者不知道该按哪个码判）。日后若判据真的变化，那是一次正常的契约变更，走完成判据六条即可——契约本来就允许被改，靠的是变更流程，不是预先埋一句免责。
