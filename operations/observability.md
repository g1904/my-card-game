# observability —— 日志 · 指标 · 追踪 · 探针与告警

「怎么看它是否健康」，以及**契约语义的哪些性质必须在线上可见**。探针口径由契约的语义决定，不能等服务上线后再补。

## 基座

- **结构化 JSON 日志 + OpenTelemetry**（指标与追踪，栈中立）。
- **`X-Request-Id` ↔ 错误体 `requestId` ↔ 服务端 `trace_id` 三者贯通**——它是跨进程边界唯一的定位标识符（`contracts/envelope.md` §5）。任何一条服务端日志都必须能由玩家上报的 `requestId` 反查到。
- 指标标签只用**低基数**维度。`accountId` 一律不作标签，账号维度落日志。

## 五条契约语义探针

| 探针 | 指标形态 | 告警口径 | 为什么是这个口径 |
|---|---|---|---|
| **本地领先** `sync.revision_ahead` | 计数器，标签 `app_version` | **阈值 = 0，任一次即告警** | 契约明写它的服务端含义是「客户端信封被改写**或后端发生过回滚**」，后者是我方自己的事故信号。它是不可能态，不该有基线 |
| **`pushId` 去重命中率** | 幂等命中的 push / 总 push，滑动 1 小时 | 相对基线突增（3×）即告警 | 它度量的是应答丢失率；突增 = 客户端重试风暴或链路劣化 |
| **复算不一致率** | 分子**按校验类型拆成三条**：① 掷骰逐位比对 · ② 单向蕴含（未命中却新增）· ③ 结构不变式；分母 = 掷骰序号递增的 push 次数 | ① / ③ 的全局率突增 ⇒ 工程告警（疑似我方差一位或客户端 bug）；② 的**长尾单账号累计** ⇒ 风控入口 | 不拆类型这条指标就没用：①③ 与 ② 的**处置完全不同**。契约已把三条校验分列，指标逐条对位 |
| **透明路径缺失** | 计数器，标签 `path`（白名单十三条，低基数可安全作标签）+ `app_version` | 某条 `path` 的缺失率由近零跳到显著非零、且集中在某个 `app_version` ⇒ 告警 | 契约明写后端对缺失的透明路径**只记账、不拒绝上行**，这条告警是路径漂移唯一的可见面 |
| **未知 `schemaVersion`** `sync.payload_schema_unsupported` | 计数器，标签 `schema_version` + `app_version`（均低基数） | **阈值 = 0，任一次即告警**，并**按与已登记集合的大小关系二分**：值 **>** 已登记最大值 ⇒ 工程告警叫人（登记漏了，改旋钮即修复）；值 **<** 已登记最小值 ⇒ 信息级、只上看板（旧客户端，是既定下线纪律的预期产物） | 它是漏登唯一的机制发现面——没有它，漏登的表现是一批玩家安静地上不去进度、客户端只出一条非模态提示，**后端侧零信号**。二分而非一律工程级：正常下线之后存量旧客户端会持续制造以周计的预期告警，那是把整张探针表训练成「可以忽略」的最快途径，与透明路径缺失那行「带前提才告警」同一手法 |

**⚠ 透明路径缺失的判定必须带前提，否则告警会被噪声淹没。** 上行 diff 是顶层键粒度的浅合并，**常常不含**某些顶层键。**只有当某个顶层键出现在本次 diff 中时，才检查该键下的白名单路径是否缺失**——这正是「该顶层键出现 ⟺ 这些透明字段本次有新值」这条推论的直接用法。不带这个前提，每一次普通 push 都会误报。

**复算不一致 ② 与回声校验拒绝的事件出口**是风控的事件流：结构化事件 + 累计计数 + 工单，账号 `status` 的任何变更须人工确认，**热路径不做裁决**。

## 其余最小集合

- **RED 三件套**：每端点的请求率 / 错误率 / 时延分位（p50 / p95 / p99）。
- **按 `code` 的错误分布**——错误码台账的每个 `code` 各一条时间序列。**新增一个未登记的 `code` 会在这里显形**，这是台账 ⇔ 实现一致性的一条廉价旁证（正式的机检断言见 `deployment.md`）。
- **CAS 冲突率与回声校验拒绝率必须分开计数。** 两者共用同一个 `code` 是契约的刻意选择（前者是正常的多设备 / 弱网现象，后者是客户端 bug 或改包），但**指标层必须能分辨**——否则回声校验那一节的可观测性设计落空。
- **会话面**：活跃会话数 · 挤下线率 · **泄漏判定计数（任一次即值得看）** · 各吊销原因的分布。
- **聚合维度的孤儿取值告警**：零判定权字段的取值清单不是校验闸，拼错的成员名只会在聚合维度里多出一个孤儿取值、靠看板发现（`decisions/ADR-0017-*`）。**这条告警就是那个看板的兑现**——缺了它，该决策接受的代价就无人承接。
- **数据面**：复制延迟 · 连接池饱和度 · 最长事务时长 · profile 文档体积分布与超阈值账号数 gauge。**体积是软告警，绝不拒绝上行。**
- **refresh 端点的滥用记账**：请求率与单账号频次分布，只告警、不返回限流码（`deployment.md` G-1）。

## 日志脱敏：中间件统一实施

一处白名单式序列化，而不是各处自觉：

- `message` 必填且必须写到能定位问题，同时**不得含 token / 完整凭据 / 密钥**。
- 账号标识与 `pushId` 一类标识按前缀截断。
- 手机号 / 邮箱一律以 `identifier_mac` 或掩码出现，**明文绝不落日志**。
- 密钥解包事件单独成一条审计线（谁、哪个环境、何时），见 `environments.md`。
