# environments —— 环境实体 · 配置分层 · 区域与合规 · 密钥保管

后端的运行时底座：有哪几套环境、什么东西算配置、数据放在哪、密钥怎么保管。发布动作本身见 `deployment.md`，监控口径见 `observability.md`。

## 环境实体：两套云上 + 一套本地

| 分支 | 环境实体 | 用途 |
|---|---|---|
| `backend-feature` | **本地 docker-compose**（Postgres + Redis + 服务进程） | 开发期验证，起停快、成本为零 |
| `backend-testing` | **云上测试环境** | 与生产同构的验证场；集成、迁移演练、上线核对 |
| `backend-production` | **云上生产环境** | — |

**必须与生产同构的是 testing，不是 feature。** 「本地跑得通、云上跑不通」的环境差异在 testing 暴露，这是被接受的代价：它换来固定成本减少约三分之一，而 feature 环境的利用率本就最低。日后需要第三块地（团队扩大、迁移演练）时补一套是纯增量，不改任何形态。

**三处跑同一个 artifact，只有配置不同**（镜像形态见 `deployment.md`）。

## 配置三层：判据是「改它要不要发版」

| 层 | 内容 | 落点 |
|---|---|---|
| 编译期常量 | 协议不变式、SplitMix64 常量、判定顺序 | 代码 |
| 环境配置 | 连接串、区域、bucket、KMS 密钥别名、日志级别 | 环境变量 + 云 Secrets |
| **运行期可调旋钮** | 契约里全部标注「初值 / 待实测校准 / 落后端配置而非代码常量」的数值 | `config_knob` 表（`key` 主键 + `value` + 更新者与时间）+ 进程内缓存约 30 秒 TTL，**改值不发版** |

**密钥永不进环境变量明文、不进镜像、不进 git**——环境配置里出现的只有 KMS 密钥别名，见下方「密钥保管」。

## 限流的实现分层

- **push 滥用阈值走 Redis 计数器**（`INCR` + `EXPIRE`），**键是账号维度、不是 IP**——移动网络 NAT 下 IP 维度会误伤整个小区。触发时的 `code` 与 `class` 见错误码台账；应答须**同时**给 `Retry-After` 头与 `detail.retryAfterSeconds`（台账已把 `detail` 形状写死）。
- **Redis 不可用 → 放行并告警**，不阻断玩家：限流是防滥用，不是正确性的一部分。
- **验证码 / 短信计数是例外，不沿用上面这条 fail-open。** 短信是有成本且被刷的通道，一旦放行代价是真金白银。它的计数落 Postgres；若实现上仍走 Redis，则 Redis 不可用时对该端点 fail-closed 返回限流码。
- **`/v1/auth/refresh` 上不得存在任何返回限流码的限流**——这是契约刻意留的形状，实现与网关两侧都要守，作为上线核对项过闸（见 `deployment.md`）。

## 区域与合规

- **主区在中国大陆境内。** 面向国内渠道（登录 / 支付 / 实名 / 防沉迷）反向约束存放地，且身份主体自建这条决策的理由之一正是境外托管与国内数据存放要求冲突（`decisions/ADR-0010-*`）。
- **个人信息不出境**（手机号 / 邮箱 / 实名信息 / 验证码记录）。**任何副本因此仍在境内**——跨区域不等于跨境。
- **`identity` 与 `profile` 分表分权限**，使注销与数据导出能按数据类别定位，且日常玩法路径不需要触达个人信息表。
- **手机号 / 邮箱以 `identifier_mac = HMAC(identifierSecret, identifier)` 参与索引，明文绝不落库落日志**；日志侧的统一脱敏见 `observability.md`。
- **域名备案与国内发行资质是上线时序的前置**，不是技术选型的自由度；它与发布前置清单同批推进（`deployment.md`）。

## 拓扑与副本

**单区域部署，不做跨区域多活**——账号级严格单调计数器在多主下无法维持，这是契约层面的排除，不是规模判断。跨区域延迟由客户端的非阻塞上行通道吸收。

**玩家读路径全部走写入区**（读己所写的最简兑现，见 `systems/profile-store.md`）。**只读副本只承担灾备与离线分析，不承接任何玩家读路径。**

> flags 的读路径**不受读己所写约束**——这是一条被保留但当前未被使用的自由度；当前拓扑取「玩家读路径全走写入区」，flags 随之。规模到需要时可无额外一致性代价地把 flags 读移出写入区。

**灾备只写能力要求，不写副本数。** 部署形态须满足 `decisions/ADR-0009-*` O3 的**可演练恢复**——「版本号未倒退」是数据库恢复演练的必检项，一个没有可演练恢复流程的部署形态不满足它。副本数、可用区分布与备份保留期是成本模型的输出，在 DAU 预期落定之前不写死（`open-questions/06-platform-stack.md`）。

**海外扩展是另一套独立部署 + 独立 `accountId` 空间**，不是本套的跨境拉伸。

## 容量形状

契约已把写入频率钉死（稳态每账号约 1 次上行 / 分钟）。设峰值同时在线账号数为 `C`：

```
push    ≈ C / 60    req/s
refresh ≈ C / 900   req/s
pull    ≈ 启动一次 + 购后一次
verify  ≈ 每账号个位数 / 年
```

每次 push 是一个小事务（更新一行 `jsonb` + 插入一行幂等记录）。在这个形状下，一台中等规格的单主关系库到**同时在线万人量级都不需要分片**——这是「不引入分片 / 多主 / 读写分离」这条结论的定量依据（`systems/_index.md`）。

**实例规格不在此定稿**：DAU 预期是本库范围外的产品输入，写死一个规格会在成本模型到来时立刻过时。

## 密钥保管

### 会话 token 签名密钥

- **KMS 只保管被包裹的私钥，签名在进程内完成。** 进程启动时向 KMS 解包一次，私钥只在内存：不落盘、不进环境变量、不进镜像。
- **KMS 因此不在签发热路径上**——它停机不影响登录。把全站登录能力的可用性押给一个外部托管服务，是用一次审计换一个单点。
- **代价如实记下**：失去逐次签名审计，降级为**解包事件审计**（谁、在哪个环境、什么时候解包过）。这是被接受的取舍。
- **轮换**：JWT header 带 `kid`；旧 `kid` 只需保留 ≥ access token TTL + 时钟偏移余量，建议 1 小时后退役。轮换**纯服务端、零客户端义务、不需要发版**。例行 90 天轮换 + 疑似泄漏时立即轮换（立即轮换的代价上限 = 一个 access token TTL 内的在途请求）。
- **`refreshSecret`** 同处 KMS、带自己的 `kid`（落会话行的 `refresh_key_id`），轮换时旧 secret 保留至最长 refresh 链自然到期（绝对寿命上限）。

### 与内容签名密钥的关系

两把密钥**同处一个 KMS、是两个独立密钥、两套权限与两条审计线**，绝不共用一把、也不共用一套轮换流程。

| | 会话 token 密钥 | 内容签名密钥 |
|---|---|---|
| 算法 | EdDSA | ES256 |
| 是否在请求路径上 | **是**（每次签发 token） | **是**（flags 应答逐账号签名） |
| 可用性档位 | 最高——停机即全体无法登录 | 与 flags 端点同档——停机时 flags 降级到客户端本地缓存 |
| 轮换窗口 | 分钟级，纯服务端 | 跨一个完整客户端发版周期 |
| 是否牵动客户端发版 | 否 | 是 |

内容签名密钥的保管、CI 签名步骤与 `keyId` 轮换形态的权威在 `_index.md` 的内容分发运维面，本文件不复述。

### 本地 feature 环境

本地不接 KMS，用**开发专用密钥与开发专用 `kid`**，与线上 `kid` 空间**隔离、永不共用**。轮换演练在非生产环境用新 `keyId` 走完整条流水线后再上生产。

## 定时任务出口

当前只有两个轻量周期任务：幂等记录的分区滚动、profile 体积扫描。托管容器形态天然能承接它们。**合规侧的注销冷静期是一条跨天长时状态机**，会追加对可靠调度的要求——出口已预留，形态待合规侧落定（`open-questions/06-platform-stack.md`）。
