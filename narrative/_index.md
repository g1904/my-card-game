# narrative —— 世界观与叙事事实源（内部）

> **这是写内容时要查的上游事实源，不是玩家可见面。** 本分区服务的是**内容作者之间的一致性**——避免两个角色的事件互相矛盾、避免同一个地名在两条剧本线里是两回事。玩家永远看不到这里的任何一份文档，本作**不做设定集、不做 lore 图鉴、不做任何可回看的档案面**。

## 为什么它是一个顶层分区

它既不是机制类定义（`systems/`）也不是条目实例（`content/`），而是二者共同的**上游**：写一条剧本 arc、一个事件、一个角色背景时先来这里查世界观事实。叙事会随内容持续变长，给它自己的分区不会挤压其他区；`vision/` 的三份是「保持简短稳定」的裁决基准文档，性格与持续变长的 lore 台账相反。

## 承载什么

- **世界观设定** —— 地域、宗门、势力、修行体系中与机制无关的那一层设定事实。
- **时间线** —— 世界事件的先后与因果，供「A 的故事与 B 的故事在暗处相交」有一份可核对的底稿。
- **人物关系** —— 角色之间、角色与世界事件之间的关系图；**它是编排义务的兑现面**：写第二个角色的事件时要能查到第一个角色的事件写了什么。
- **碎片台账** —— 哪一条 lore 碎片撒在哪个事件 / 剧本节点上，用于反查与去重。

**内部结构与文档清单尚未定**：本分区目前只定了「建它、放什么类东西」，切成几份文档留给首次建区时按实际底稿量决定。

## 叙事纪律（承重）

- **碎片 lore 只撒在轮回内，不留存。** 它活在事件描述与剧本节点正文（`PlotNodeData.Body`）里，读过即过：**不进图鉴、不做可回看的档案面**，图鉴族不因 lore 扩张。玩家读到什么取决于他遭遇了什么。
- **与支柱 9 的边界。** 支柱 9「信息靠遭遇获得、图鉴即元进程奖励」管的是**关于敌人 / 未来 / 世界的可用情报**；lore 碎片**不是**那种意义上的信息——它不可换取、不影响决策、不进图鉴。两者不冲突，但这条边界要写出来，否则内容侧会把 lore 误当作图鉴该收录的东西。
- **冷的残缺文献体。** 碑文、卷宗、手札残页、旁人记述；叙事性强但情绪冷，**不解释、不总结、不动用第一人称**。全作唯一一处角色用自己的声音说话的地方，是它终结的那三句台词——lore 用第三人称文献体写，正是让那三句话仍能凿进去的前提。
- **允许文学质地，但不许温度。** 素语纪律的射程是**框架 / 系统文案**（纯数据陈述）；lore 与剧本正文是另一档，允许语调与暗示——Elden Ring 式 lore 的可深挖性恰恰来自残缺句子里那点语调，全抽成极简陈述就没有可挖的东西了。**这不是给 lore 开修辞的口子**：划的是「冷的叙事」与「冷的记账」两种冷。
- **体裁纪律照旧压顶。** 本作是 deck builder，不是 visual novel；文案「多写几句」与「少写几句」存疑时**一律取少**。
- **交叉纯隐式，游戏从不点破。** 一个角色故事里出现的无名者正是另一个角色，但**不给提示、不给成就、不做任何「你发现了」的确认**；成就系统不为 lore 串联开条目。被接受的后果：绝大多数玩家永远不会发现，串联主要发生在玩家社区而非游戏内。
- **角色系列是世界观的切片，不是难度的梯队。** 一个系列有一个与世界观兼容的有意境名称（地域、宗门一类）与一段简要概述，**对成员角色没有任何规则上的强制要求**；名与概述的承载是内容条目 `CharacterSeriesData`（见 `content/_index.md`）。
- **叙事待遇不分付费轨道。** 每个角色都可能带一条专属剧情线，铺不铺取决于内容排期而非付费与否；剧情**不是付费面**。

## 与其他分区的关系

| 方向 | 关系 |
|---|---|
| → `content/` | 条目文档写正文时来这里查事实；条目**不复述**世界观设定，需要时回链本分区 |
| → `systems/services/plot-manager.md` | 剧本的**机制**（arc / node、激活、调制、校验）归那里；本分区只管**写什么**，不管**怎么跑** |
| → `vision/pillars.md` | 基调（grimdark、素语包裹下的一句人声）是本分区的上位约束 |
| → `art/` | 视觉与音频方向另有分区；本分区不写 prompt、不登记资产 |
